# PC-GPD-005: 版號是單調計數器不表達分叉，兩個 consumer 各自前進一步即撞號

## 症狀

一份共用資產（skill、方法論、範本）由多個 consumer 各自維護副本，某個時點兩邊都從同一個版本 X.Y.0 前進一步，各自標為 X.(Y+1).0。兩份 X.(Y+1).0 的內容完全不同，各自都是對方沒有的真實工作。

同步工具的報告在這種情況下不會示警：版本字串只顯示不比較，內容雜湊只證明兩份不同、不證明誰新。靠版號肉眼掃過去會直接放行，把其中一邊的工作靜默覆蓋掉。覆蓋後兩邊的版號一致、內容一致，事後從版號看不出曾經有過分叉。

## 根因

| 層級 | 機制 |
|------|------|
| L1 版號的語意 | 版本號是單調計數器，表達「在某條時間軸上前進了幾步」。它沒有欄位可以表達「這一步是從哪個分支長出來的」，兩條獨立時間軸的第 N 步在版號上長得一模一樣 |
| L2 工具的判準 | 內容雜湊比對的輸出是二元的「相同或不同」。要判方向需要第三個點（上次同步的基準），沒有基準記錄時任何雜湊差異都只能報「分歧、方向未知」 |
| L3 覆蓋的預設 | 同步工具的單向操作（pull 或 push）預設是取代而非合併。分歧警示多為 WARNING 不阻擋，強制旗標照樣覆蓋，所以警示能提示分叉、不能防止覆蓋 |

## 案例

兩個專案共用同一個地基設計 skill，canonical 上是 6.0.0。A 專案為它補了一段反向路由（指向新建的契約程序 skill），標 6.1.0 並推上 canonical。B 專案在本地為同一份檔案補了一欄「適用條件」與非 SaaS 專案的處置段，也標 6.1.0。

A 給 B 的同步通知裡直接寫了「執行 `skill-sync pull foundation-design`」。B 若照做，它那段非 SaaS 處置會被靜默覆蓋——而同一封通知裡 A 才剛提醒過 B「索引檔請合併不要覆蓋」，只是不知道這條也命中了。

B 沒有照指令做，而是 clone canonical 後逐檔**雙向** diff，發現兩筆 6.1.0 內容不同，把自己那筆順延為 6.2.0，以 canonical 為共用時間軸合併後推回。事後 A 拉下來的是含雙方內容的 6.2.0。

B 的判定不是靠工具的分歧警示。同步工具在該次 push 確實印出了「both sides changed independently since last sync」，但那是 WARNING、不阻擋，強制旗標照樣覆蓋。

## 防護

**Why**：版號能排序不能定位分支。多 consumer 共用一份資產時，「版號比較大」不蘊含「包含對方的內容」，兩者是獨立的事實，必須分別查證。

**Consequence**：把版號當作合併判準，會在兩邊同步前進時靜默刪掉一邊的工作。損失在版號上不留痕跡——覆蓋後版號單調、內容一致，看起來像正常同步，要到有人回頭找那段內容才會發現。

**Action**：

| 情境 | 做法 |
|------|------|
| 收到「執行 pull X」或「執行 push X」的同步指令 | 先 clone 對方的權威來源，對該資產做**雙向** diff，再決定拉或推。只跑單向（例如只看 `grep '^>'`）會誤判：「被對方改寫掉的舊版」與「對方沒有的真實工作」在單向 diff 下同形 |
| 雙向 diff 顯示兩邊各有對方沒有的內容 | 這是分叉不是落後。以共用時間軸（canonical）為準，把本地那筆順延一號，合併後推回；順延的那筆在變更紀錄裡寫明原編號與撞號對象，讓事後看得出曾有分叉 |
| 同步工具印出「both sides changed」類警示 | 當作提示不當作閘門。該類警示多為不阻擋級別，強制旗標照樣覆蓋，它能告訴你去查、不能替你擋 |
| 通知其他 consumer 更新 | 通知裡給資產清單與變更摘要，不直接給 pull / push 指令。指令蘊含了「你那邊沒有分叉」這個發送方查不到的前提 |
