# PC-GPD-019: 形狀相符終止查證——附近有個東西長得像答案，於是不再往下讀

| 項目 | 值 |

| 類別 | process-compliance |

## 症狀

查證某個事實時，在目標**附近**看到一個外觀符合預期答案的東西，於是停止查證並以它作答。該東西真實存在、內容也沒有被誤讀，錯的只是「它與待答問題的關係」從未被驗證。

**識別特徵**：

- 被引用的證據**確實存在**，重讀時仍在原處，所以事後檢視找不到「看錯」
- 停止查證的那一刻沒有可疑感——形狀相符本身就是停止訊號，它不會同時發出「還沒驗完」的訊號
- 結論的形式是關於**關係**的斷言（「它接在那條路徑上」「這個數字就是那個計數」「這段輸出就是那次執行的結果」），而證據只支持**存在**
- 據此產出的往往不是模糊意見，而是一條**具體且可執行的線索**（修法方向、計數、成敗判定），因此下游會直接照辦
- 補做一步查證（誰呼叫它 / 全量計數 / exit code）後，結論整個翻轉

## 根因

**形狀相符是廉價的，關係查證是昂貴的，而兩者產生同一種「找到了」的感覺。**

待答問題幾乎總是關於關係——「這個函式**有沒有被**那條路徑呼叫」「這個數字**是不是**全量」「這段輸出**是不是**成功的那次」。而在目標附近能找到的東西，只能證明存在。存在與關係之間有一步推論，這一步在形狀相符時會被靜默略過，因為推論的結論與觀測到的形狀一致，沒有任何矛盾可供察覺。

**與 `PC-GPD-011`（過濾產物活得比它的問題久）的關係**：`PC-GPD-011` 是本模式的一個子類——過濾是「製造出形狀相符之物」的手段之一，而共處一室（同模組、同目錄、同輸出區塊）是另一種。兩者的根因不同：`PC-GPD-011` 談的是產物的**生命週期**（子集被搬到新脈絡仍以全量身分被讀），本模式談的是查證的**停止規則**（形狀相符即停手）。同一起事件可能兩者皆命中。

**與 `tool-output-trust-rules` 規則 3 的關係**：規則 3 要求關鍵事實用無法腦補的固定值交叉驗證。本模式是規則 3 失效的具體機制——不是忘了驗證，是**誤以為已經驗過了**，因為手上確實有一份真實的觀測。

## 實例

| 待答的關係 | 附近那個形狀相符的東西 | 略過的那一步 | 後果 |
|-----------|---------------------|------------|------|
| `get_active_dispatches()` 的回傳路徑上有沒有過濾 | 同一模組內確實有 `_is_dispatch_expired()` | 查誰呼叫它（實際只有 `cleanup_expired()`） | 把「修法只是加一個條件」當線索交給另一個 session 去開票，而該函式全文是 `return state["dispatches"]`，零過濾 |
| 某檔案的變更**總數**是多少 | `git log -N` 的輸出恰好有 N 筆 | 用 `\| wc -l` 取全量 | 兩個 session 各自持一個錯誤計數，且因數字相同而互相佐證 |
| 剛才那次寫入**成功了嗎** | `\| tail -5` 顯示的內容正是剛送出的那段文字 | 讀 exit code | 判定寫入成功，實際 `rc=2` 參數錯誤、檔案未動；靠後續 `grep -c` 回 0 才發現 |

三例的共通形態：**觀測是真的，關係是假的。**

## 解決方案

發現後：補做被略過的那一步關係查證（誰呼叫、全量計數、exit code），並回頭檢查該結論是否已被下游採用——本模式的產物常是具體線索，會被立即照辦。

## 預防措施

**問法要從「有沒有」換成「憑什麼」。** 在附近找到形狀相符之物時，強制多問一句：

| 觀測到 | 錯誤的下一步 | 正確的下一步 |
|-------|------------|------------|
| 同模組／同目錄有個名字對得上的函式 | 推定它在那條路徑上 | 查呼叫端（`grep` 函式名，排除定義處） |
| 一段輸出的筆數等於預期的筆數 | 採信該筆數 | 移除全部 `-N`／`head`／`tail`，改 `\| wc -l` |
| 輸出裡有剛送出的內容 | 判定送出成功 | 讀 exit code：`out=$(...); rc=$?` |
| 文件某節標題與待查主題相符 | 引用該節作答 | 讀該節全文，確認它回答的是同一個問題 |

**自陳「我沒查完」不構成免責。** 給出線索的一方若在同一段話裡註明未讀完，該註記對接收方沒有作用——接收方拿到的仍是一條具體線索，並會照它行動。**沒查完就只給座標，不給方向**：說「`is_file_under_dispatch` 不過濾且無註解」（實讀）是有效的，說「修法可能只是加一個條件」（推定）不是。
