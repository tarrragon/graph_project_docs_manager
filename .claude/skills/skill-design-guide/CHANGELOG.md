# skill-design-guide 版本紀錄

新到舊。版號規則與兩個住址（本檔與 `SKILL.md` frontmatter 的 `metadata.version`）見專案的 skill 同步規範。

**本檔只記變更本身**：版號、改了什麼、落在哪一節。多輪審查的 finding 分類、逐 frame 敘事、
被推翻的判定與其推導過程屬設計過程紀錄，依 `writing-the-body.md`〈嚴禁清單〉該列的處置放在
**專案的 worklog 系統**，不放這裡。此約定自 v1.7.1 起生效；此前各版已回溯壓縮。

**Version**: 1.7.1 — 修 Round 3 多輪審查（七個 frame）的嚴重必修中可機械執行者。〈外部引用〉的例外 1 由具名清單改為判準（成員自述會與清單脫節），並補「skill 內相對路徑與外部路徑同形時一律補足前綴」；`patterns-and-troubleshooting.md`〈測試方法〉與〈常見問題排除〉首表補適用邊界（兩者預設經上傳分發，走 git 同步的專案三層中兩層無管道）；〈發布前檢查清單〉補一列指向 `skill-cli-sync-check` 規則（該清單不涵蓋 CLI 行為變更的同步，走完全綠不代表那件事被問過），該規則同步補回指。本檔壓縮為只記變更。

**Version**: 1.7.0 — 修 Round 2 多輪審查的三類可機械驗證缺陷。**指標**：〈按需讀取〉路由表的涵蓋章節欄六列全部改為與目標檔 `##` 逐字相同並要求雙向齊全（原有兩個全死名、兩個只命中 H1 的半死名、一個漏列），跨檔指涉補檔名，兩份 reference 補「亦由此進入」。**條文未套回自身**：〈外部引用〉起手句的計數與其下實際項數不符、〈拆分特有的必查項〉補第 5 列（H1 與檔名）、節界檢查改為排除 fenced block 的 awk 版（裸 `grep -c '^## '` 在含 markdown 範例的檔上實測高估 2.7 倍且前後同等高估）、五份 100+ 行 reference 補章節清單。**節界**：〈一則完整走查〉提為獨立 `##`，〈觸發控制矩陣〉由 `###` 提為 `##`，兩處 stale footer 移除。

**一項被本輪推翻的判定（歷史記錄，非現行判準）**：先前把 `patterns-and-troubleshooting.md` 的 6,876 字元判為超標，該判定把繁中係數 6,500 無條件套用於一份 77.1% ASCII 的檔案。重判時用的「6500 + ascii_ratio × 13500」內插式**不在本 skill 任何一份檔案內，是重判者當下自造的**；文件內的方法（「混合內容取兩者之間」）在這些檔案上判不出來。後續審查另證分段加總（ASCII 段除以 4、非 ASCII 段除以 1.3）才是形狀正確的算法。現行判準以 `SKILL.md`〈Progressive Disclosure — 三層載入〉為準。

**Version**: 1.6.0 — 依 Round 1 的拆分方案執行拆分。SKILL.md 由 17,962 字元／578 行降至 6,482／169，兩個官方門檻皆通過；references 由三份增為六份，切分判準為「一次工作會不會同時用到」。入口檔留路由與判準（核心心法、三類 bundled resource 的分工、按需讀取、發布前檢查清單）。

**拆分前最關鍵的前置是 17 處內部 `§N` 編號指涉全部改為章節名**——編號式指涉失效的方式與名稱式不同：重編號後不是「找不到」而是「指到別的節」，讀者不會察覺。全庫章節編號一併移除（32 處）。行覆蓋驗證 578/578，無重複無遺漏。章節數由 13 增為 14 屬設計決定（原〈Anatomy〉下只剩一個子節隨外移升為 `##`），依程序明文記錄以免下一個人照「搬移前後各數一次」判為異常。

**Version**: 1.5.0 — 修多輪審查 Round 1 的嚴重項並補三節範例。

**兩項對外查證推翻了既有寫法，其中一項是 v1.3.0 自己寫錯的**：其一，v1.3.0 寫「官方全篇未給任何行數限制」，**此句為誤**——官方文件有兩頁，v1.3.0 只讀了 overview，而 best-practices 頁三處寫 "Keep SKILL.md body under 500 lines"。**兩個門檻都是官方值**。此錯誤與「截斷後下全稱結論」同型，而截斷至少留下線索，「只讀了兩頁中的一頁」沒有。其二，6,500 字元門檻沿用的 `CHARS_PER_TOKEN = 1.3` 其註解逐字寫「繁中為主集合」，v1.3.0 引用它卻未問適用條件——已改為附語言換算表並明令不可無條件套用。

**額外檔案禁令查證後大幅收窄**：官方 best-practices 未禁止任何額外檔案且立場相反。原條理由「每多一個檔案就增加讀檔判斷成本」是本地發明。已改寫為本地判斷、理由改為目錄辨識成本、範圍收窄至「AI 不會讀到的檔案」，`CHANGELOG.md` 移出禁止之列（它是跨 consumer 版號協定的載體）。

**Version**: 1.4.0 — 新增〈拆分既有 skill〉與 `references/splitting-an-existing-skill.md`。原本只說「超標就外移」，沒說怎麼外移才不會壞。

**動因是一次實測**：一份 15,015 字元的 skill 拆為八份，行覆蓋 245/245、各新檔與原區間位元相同、無重複無遺漏，**而該次拆分仍引入四項嚴重缺陷**。壞掉的不是位元，是位元之間的關係——節界、跨檔指涉、共置關係、外部引用，逐行比對對這四類全部無鑑別力。reference 另收兩類拆分特有的高頻缺陷（內嵌計數不會跟上結構改動、位置性指涉的判準卡在失效條件而非形態）、檔頭三段式、路由表的涵蓋章節欄、以及收尾兩步。

**Version**: 1.3.0 — 第 2 層體量判準由行數改為字元數。原表列兩個判準而 Action 只綁行數，於是實際生效的是括號裡那個代理指標。行數對繁中散文失效，因每行字元數無上界：一份實測 skill 為 245 行（通過行數門檻）但 15,015 字元，最長單行 548 字。新門檻 6,500 字元 = 5k tokens × 框架既有校準係數 1.3 chars/token（`file-size-guardian-hook.py` 的 `CHARS_PER_TOKEN`，2026-06-12 以 `/context` 實測校準）。條文另載明本層零執法的事實。

**Version**: 1.2.0 — 新增〈外部引用：指名身分，不用檔案路徑〉（skill 用名字走 Skill 工具載入、方法論與規則用標題檢索），含判別問句「讀者是要去讀它學東西，還是要寫進它讓別的東西動起來」與正當例外。實證：框架改版移動 hook 位置使舊路徑註冊全數失效；`skill-sync` 可攜性閘門把兩份 skill 的 25 處路徑判為指名他專案的檔案而中止 push。

**Version**: 1.1.0 — 新增 Opinionated Defaults 設計心法。
