# 弱觀察者 UX 試水溫結果（0.5.0-W1-466）

## 結論

**不通過，結論為「不做」。** 通過條件 (a) 為 0/9：沒有任何一題出現「壞版失敗、原版通過」，條件 (b) 因此也不成立。依 466 AC 4，0.5.0-W1-466.3 以 requirement_vanished 關閉，不修改變體重跑。

Haiku 在單 token、4×4 格線的設定下，沒有把注入的語意破壞反映為作答失敗。九題中壞版沒有一格判為失敗；能判定的題目裡，壞版的作答表現大多與原版相同或更好。

| 條件 | 要求 | 結果 | 判定 |

| (a) | 至少 4/9 題「壞版失敗、原版通過」，反向 0 題 | 正向 0 題，反向 0 題 | 不通過 |

## 「找不到」選取率

原版 8.9%（4/45），壞版 4.4%（2/45）。壞版沒有讓模型更常回報「找不到」。

## 限制

- **循環論證**：試水溫的正解由構造定義（注入前的元件位置與計數），只能檢驗模型是否對注入的破壞有反應，不能檢驗破壞是否真的造成人類使用者的困難。
- **評估器邊界**：評估器的鑑別力已由 0.5.0-W1-466.7 證明，但 Flutter `MinimumTapTargetGuideline` 會略過貼著視窗邊緣的節點，minTapTarget28 對貼邊元件不構成檢查。壞版只改語意層，不影響原版與壞版的比較。
- **C' 為弱破壞**：只換顏色。
- **A2 只有 K-A 一列**：且 K-A 兩版皆不可判，對 A2 沒有任何結論。
- **單 token 取樣協定**：數字題與區域題以單 token 代碼作答。25/90 無法解析，使 6 格不可判，降低了判定力。這是協定本身的成本，依規則不重跑。
- **不可判的格集中在 K 畫面**：Ticket 清單的三題中，K-A 與 K-B 共 4 格不可判，K 畫面實際只剩 K-C' 一題可判。
