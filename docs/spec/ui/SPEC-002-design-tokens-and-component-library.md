# Design token 與元件庫：所有顏色、尺寸、元件皆具名

## 唯一硬規則

**程式碼中不得出現裸的色碼、尺寸數字或字級數字。** 每一個值都必須先被命名，
畫面只引用名字。

```dart
// 禁止
Container(color: Color(0xFF2E6F6A), padding: EdgeInsets.all(8))
Text('...', style: TextStyle(fontSize: 13))

// 要求
Container(color: AppColors.accent, padding: EdgeInsets.all(Space.sm))
Text('...', style: AppText.body)
```

**這條規則優先於 Flutter 的 `Theme`。** `Theme` 是分發機制，不是決策位置——
它讓值傳到 widget，但它不回答「這個值是什麼、為什麼是這個」。本規格定的是
決策層：先命名，再由 `Theme` 分發。

## 為什麼在 Theme 之外先決定

| 只用 Theme | 先定 token 再進 Theme |
|-----------|---------------------|
| 值散在各個 `ThemeData` 欄位，語意由 Material 的欄位名決定（`primary`／`surface`／`onSurfaceVariant`） | 值有專案自己的語意名（`accent`／`gapEdge`／`damagedDetail`），Material 欄位只是其中一個消費端 |
| 新增一個 Material 沒有對應欄位的語意（例如「邊損壞」與「詳情損壞」兩種標記）時無處可放 | 語意先存在，需要時再決定要不要映射到 Material 欄位 |
| 換色只能整組換 seed | 可單獨調整某個語意角色 |

本 App 有數個 Material 沒有對應欄位的語意角色——破洞四類的分類色、
`severity` 兩級的標記強度、`flow 未結構化` 的引導態——它們必須有名字才存在。

## 值的來源

**token 自 `design/` 的九份 artboard 萃取，不重新發明。** 那九份是 0.1 版型
定案的產物，經過比較後選定；重新發明等於丟掉那次比較。

但**萃取不等於照抄**：artboard 的間距出現 1／2／7／8／9／10／12 七種值，
那是產生器的輸出而非設計過的尺度。token 化時須歸納出一個尺度並吸收噪音，
否則等於把雜訊固化成規格。

四階，是本規格要回答的問題之一。

## 命名層次

三層，各自回答不同問題：

| 層 | 回答 | 例 |
|----|------|-----|
| **原始值** | 這個值是多少 | `teal600 = #2E6F6A` |
| **語意** | 這個值代表什麼 | `accent = teal600` |
| **元件** | 這個元件用什麼 | `NavItem.selectedBg = accent` |

畫面只引用**語意層與元件層**，不得引用原始值層。原始值層的存在是為了讓
「同一個顏色被兩個語意共用」這件事顯性化——若 `accent` 與 `linkText` 都是
`teal600`，換色時才知道要不要一起換。

## 元件庫的範圍

**各畫面的材料一律取自元件庫，不自行組裝。** SPEC-001 的 29 個狀態橫跨七個
畫面，若各畫面自行拼裝，同一個概念會長出七種樣子。

從 SPEC-001 的狀態表與 artboard 歸納，至少需要下列元件（**本清單不宣稱窮盡**，
實作中發現的補入並回填本節）：

| 元件 | 出現在 |
|------|--------|
| 空狀態（訊息 + 前進動作） | 空圖、無 UC、無提案、無 ticket、無破洞、無最近專案 |
| 阻擋狀態（訊息 + 版本值 + 出口） | 不是框架專案、無可消費的型別表、schema 不相容 |
| 載入態（骨架 + 進度 + 取消） | Domain 視圖載入中、Ticket 載入中、破洞掃描中 |
| 損壞標記（兩級） | 節點詳情部分損壞、Ticket 含損壞、FR-05 的邊損壞／詳情損壞 |
| 導覽項 | 側欄六項 |
| 專案切換浮層 | 側欄頂端 |
| 節點卡 | 矩陣格、泳道步驟、追溯樹節點、破洞項 |
| 徽章（計數／狀態／健康） | 損壞計數、主題節票數、專案健康 |

**空狀態與阻擋狀態必須是兩個元件，不是一個。** 空狀態說「這裡目前沒有東西」，
阻擋狀態說「這個專案不適用本 App」——退出路徑與語氣皆不同，合併會讓
FR-03 與 FR-07 的驗收互相污染。

## 功能需求

### FR-01: 程式碼中無裸值

| 項目 | 值 |
|------|-----|
| 優先級 | P0 |
| 驗收 | `lib/` 下（`lib/tokens/` 除外）grep 不到 `Color(0x`、`#[0-9A-Fa-f]{6}`、以及 `fontSize:`／`borderRadius:`／`EdgeInsets` 後方接字面數字。此檢查可機械化，應納入 CI |

### FR-02: 每個 token 有語意名

| 項目 | 值 |
|------|-----|
| 優先級 | P0 |
| 驗收 | 顏色、字級、間距、圓角四類皆有具名常數表；語意層的每個名字可回溯到原始值層的某個名字 |

### FR-03: 畫面只用元件庫

| 項目 | 值 |
|------|-----|
| 優先級 | P1 |
| 驗收 | SPEC-001 §1–§7 的每個狀態，其顯示欄的內容皆由元件庫元件組成；新增元件須先進元件庫再被畫面引用 |

### FR-04: 間距與字級為離散尺度

| 項目 | 值 |
|------|-----|
| 優先級 | P1 |
| 驗收 | 間距與字級各自為一組有限的具名階（如 `Space.xs/sm/md/lg`），不接受任意數字；artboard 的七種間距值須歸納為階並記錄映射 |

## 設計約束

- token 定義集中於 `lib/tokens/`，該目錄是唯一允許出現裸值的位置
- `Theme` 由 token 建構，不反向——不得先設 `ThemeData` 再從中取值命名
- 本規格是 `design/` artboard 的下游：artboard 是視覺決策的產物，
  本規格是它的結構化表達。兩者不符時**以 artboard 為準並更新本規格**
- 元件庫清單不宣稱窮盡，實作中補入者須回填本規格
