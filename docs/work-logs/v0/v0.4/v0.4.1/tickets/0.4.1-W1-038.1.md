## Solution
<!-- Schema[IMP/Solution]: 選填（.claude/pm-rules/ticket-body-schema.md） -->
新增 testpaths_coverage_warning.py（hooks 與 ticket 包各一份相同副本，獨立運作），以 pytest_terminal_summary 比對 config.args 與 ini testpaths；全量數由 rootdir 子程序 collect-only 取得（env 守衛防遞迴），實際數由 trylast modifyitems 記錄。hooks 新建 conftest.py、ticket 擴充既有 conftest.py。限制：hooks 包若只帶 ../lib/tests（不經 hooks 目錄），rootdir conftest 不會載入，不警告。commit f5b41592e

### 已知限制（PM 記錄）

- 只帶 hooks 包的第二個 testpath（`../lib/tests`）執行時，`.claude/hooks/conftest.py` 不會被載入，因此不會出現警告。主要情境（只帶 `tests`）會警告。
- 搭配 `-k`／`-m` 篩選時，警告中的「實際收集」是篩選後的數字，「全量」是預設選項下的數字，兩者的差距包含篩選掉的部分。
- 僅在命令帶有部分路徑時，才會多執行一次 `--collect-only` 子程序來取得全量數；不帶路徑或單檔呼叫時沒有這筆額外開銷。
- 兩份副本（hooks 包、ticket 包）以位元組比對測試維持一致；consumer 只同步其中一包時，該測試會 skip。
- Python 3.9：新檔以 3.9 py_compile 通過；實際在 3.9 執行受 0.4.1-W1-039 阻擋（ticket 包既有程式碼使用 3.10 語法）。
### 自檢結果（PM）

- 合併 04e96605e。PM 審查共退件兩輪：
  - 第一輪：兩個非 hook 模組補進 hook-exclude-list.json，SessionStart 註冊檢查實跑為 0 個未註冊；另以 3.9 做 py_compile 驗證。
  - 第二輪：兩份副本的一致性改由位元組比對測試守住（附 E2 改一字元的正向對照）；`_count_full_collection` 三條失敗路徑原本靜默回傳 None，改為先寫一行 stderr 再回傳。
- 合併時 bare-commit guard 擋下一次，原因是 where.files 少列了兩份外掛模組與排除清單。已用 set-where 補成實際範圍，未拆開合併提交。
- 本票的外掛已隨 canonical v2.73.0 推送；推送內容經 hooks、ticket 兩個完整套件覆核，皆全綠。
- 執行者回報的「ticket 既有失敗」，是因為其 worktree 基底早於 0.4.1-W1-037 的修復。合併到 main 之後，該項失敗已不存在。
