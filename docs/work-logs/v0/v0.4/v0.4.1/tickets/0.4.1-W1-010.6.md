## Problem Analysis
### 問題根因

version-shift 與 migrate 是兩套各自維護的「改票號＋改引用」實作，前者自 2026-08-26 框架導入後未再演進（git log 只有導入與 sync 兩筆），後者經 W1-010.1～.5 已補齊自動提交、previous_ids、topic 承接、hierarchical 掃描與 discovered_during／closed_by／chain 改寫。version-shift 的缺陷都來自「沒有跟上框架不變式」：

- 路徑：`_validate_versions` 等七處寫死扁平 `docs/work-logs/v{version}`，不經 `paths.get_tickets_dir_under_root`。框架不變式 W14-052 規定新版本一律三層，故 version-shift 對任何依預設建立的版本都在前置驗證 exit 1（X1 重現）；即使在扁平舊結構下能跑，產出的目標目錄也是扁平，違反同一不變式。
- todolist：`yaml.safe_dump` 整檔重寫；只改 `current_version`／`previous_version`／`tech_debt` 三鍵，`versions[]` 不動。
- 引用：以「版本前綴替換」改 6 個欄位，與 migrate 的「精確 ID 比對」語意不同，且漏 discovered_during、closed_by；跨版本掃描只看 `v*/tickets`（扁平）。
- 其餘缺口：不記 previous_ids、不承接 topic、不改 worklog 主檔名、不提交；所有 except 皆靜默（`_shift_single_ticket`、`_process_ticket_for_cross_refs`、`_rename_worklog_dir`、`_update_todolist_yaml`、`execute` 的 RuntimeError），這正是 IMP-025 收錄的案例本身；`_find_auxiliary_files` 在檔案改名之後才執行，計數恆為 0。
- 測試未發現的原因：test_version_shift.py 的 22 個案例全部使用扁平 fixture，沒有一個案例落在框架預設的三層結構上。

## 重現實驗結果
### 實驗方法

全部在 session scratchpad 的 tmp git repo 執行，主 repo 無任何 git 寫入（量測環境：macOS，git 2.50.1，2026-10-01）。tmp repo 內容為主 repo 的 `.claude/skills/ticket`（現行碼，含 W1-010.1～.5 已完成的修改）、`docs/work-logs` 全部（1246 張票）與 `docs/todolist.yaml`，經 `ticket` shim 以真實 CLI 執行。結構引用以自寫掃描器統計：解析每張票 frontmatter 的 blockedBy、relatedTo、children、parent_id、source_ticket、spawned_tickets、discovered_during、closed_by、chain.root／chain.parent，計算以指定版本前綴開頭的引用數。

- X1：三層結構（原樣），`ticket version-shift 0.4.1 0.4.2` 的 dry-run 與實跑。
- X2：把 0.4.1 目錄改為扁平 `docs/work-logs/v0.4.1`（其餘版本維持三層，模擬混合結構），實跑 version-shift。
- X3：三層結構，先以字串插入在 todolist 登記 0.4.2 並提交（模擬人工登記），再以 `ticket migrate --config <39 筆 0.4.1-X → 0.4.2-X> --version 0.4.1` 搬移整版。

### 實驗發現

已驗證：
- version-shift 在框架預設的三層結構下不可用（X1）；在扁平結構下可執行，但產出至少五類錯誤狀態：註解全刪、versions[] 不更新、三層目錄的他版本引用全漏、topic 遺失、不提交（X2）。修復它等於重寫 migrate 已具備的能力。
- 現行 migrate --config 已能承擔整版搬移的票面部分，且結果滿足 W1-010 (1) 對提交語意的建議：單一 commit、porcelain 為空、引用零殘留、topic 與 previous_ids 完整（X3）。
- 整版搬移在 migrate 之外只剩三件事未處理：todolist 版本條目、worklog 主檔、舊目錄清理。
- 新版本缺 worklog 主檔時，`worklog_appender.append_worklog_progress` 會印 `[WARNING] worklog 檔案不存在，跳過進度追加` 並略過——X3 之後若不手動處理主檔，該版每次 complete 都會缺進度行（程式碼確認，未實跑 complete）。

未驗證：
- 大版本耗時：本 repo 最大版本 0.1.0 有 866 張。migrate 每張票都掃描全庫一次 frontmatter（程式碼確認），X3 為每張約 2.5 s；耗時主要來自全庫掃描屬推論，未做剖析。
- 其他 consumer 是否使用 version-shift。
