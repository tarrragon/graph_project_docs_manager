## Problem Analysis
### 問題根因

version-shift 與 migrate 是兩套各自維護的「改票號＋改引用」實作，前者自 2026-08-26 框架導入後未再演進（git log 只有導入與 sync 兩筆），後者經 W1-010.1～.5 已補齊自動提交、previous_ids、topic 承接、hierarchical 掃描與 discovered_during／closed_by／chain 改寫。version-shift 的缺陷都來自「沒有跟上框架不變式」：

- 路徑：`_validate_versions` 等七處寫死扁平 `docs/work-logs/v{version}`，不經 `paths.get_tickets_dir_under_root`。框架不變式 W14-052 規定新版本一律三層，故 version-shift 對任何依預設建立的版本都在前置驗證 exit 1（X1 重現）；即使在扁平舊結構下能跑，產出的目標目錄也是扁平，違反同一不變式。
- todolist：`yaml.safe_dump` 整檔重寫；只改 `current_version`／`previous_version`／`tech_debt` 三鍵，`versions[]` 不動。
- 引用：以「版本前綴替換」改 6 個欄位，與 migrate 的「精確 ID 比對」語意不同，且漏 discovered_during、closed_by；跨版本掃描只看 `v*/tickets`（扁平）。
- 其餘缺口：不記 previous_ids、不承接 topic、不改 worklog 主檔名、不提交；所有 except 皆靜默（`_shift_single_ticket`、`_process_ticket_for_cross_refs`、`_rename_worklog_dir`、`_update_todolist_yaml`、`execute` 的 RuntimeError），這正是 IMP-025 收錄的案例本身；`_find_auxiliary_files` 在檔案改名之後才執行，計數恆為 0。
- 測試未發現的原因：test_version_shift.py 的 22 個案例全部使用扁平 fixture，沒有一個案例落在框架預設的三層結構上。
