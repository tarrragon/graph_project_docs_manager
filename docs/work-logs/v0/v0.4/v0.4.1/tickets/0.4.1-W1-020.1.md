## Solution
<!-- Schema[IMP/Solution]: 選填（.claude/pm-rules/ticket-body-schema.md） -->
migrate.py: 遷移前記錄原 parent_id；chain_info 存在時 parent_id 一律設為 chain.parent（根票為 null）。遷移與交叉引用完成後，若父票改變呼叫 _sync_parent_children：舊父 children 移除 old/new ID（字串與 dict），新父 children 加入新 ID（不重複），新父缺檔只輸出 [WARNING]。異動父票併入 _MigrationRecord.referrers，沿用單一隔離提交。dry-run 於前段 return，不寫入。SKILL.md／CHANGELOG 版號寫為 2.44.x（待合併取號）。Phase 4：無需重構，品質 A。commit 24d6bd3d4。

### 自檢結果（PM）

- 合併 8e38ddb4c，取號 ticket 2.44.24。合併後完整套件出現 1 項回歸：新父 children 中的 dict 形式被改成字串。由 incident-responder 開立 0.4.1-W1-037（P1），已於 ac0c68f00 修復，取號 2.44.25。
- 回歸當初沒有在合併前被抓到，原因有二：執行者回報的「全套件」只跑了 tests/（TEST-BAL-006 情境）；PM 合併前也沒有重跑完整套件。流程改善由 0.4.1-W1-038 系列承接。
- 「新 ID 為根時清空 parent_id」的影響範圍：已掃描真實資料，沒有任何根 ID 票以 set-parent 掛到非前綴父票，因此不會切斷既有的父子關係。
- 實地觸發：真實資料中沒有天然的觸發配對。案例 B 與 C 由真實 tmp git repo 測試驗證 commit 內容。

### Phase 4 重構評估

- 重構需要：否（新父分支的先刪後加已由 W1-037 改為 guard clause）
- 技術債務：無新增
- 程式碼品質：A
- 結論：同步邏輯拆成三個小函式（剔除、載入、寫回）加上一個協調函式，每個都只做一件事。
