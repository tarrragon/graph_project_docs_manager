### 錯判方向實測（PM，2026-10-01，scratchpad tmp repo：main checkout 加 feat/x worktree）

直接呼叫 `commit_content_guards._resolve_branch_context(False)`，cwd 為寫入目標，CLAUDE_PROJECT_DIR 分別設定：

| 情境 | 寫入目標（cwd） | CLAUDE_PROJECT_DIR | 結果 | 意義 |
|---|---|---|---|---|
| A | worktree（feat/x） | main checkout | ACTIVE，branch=main | 誤擋：feature 分支上非豁免路徑的合法提交會被當作寫入 main 而 deny |
| B | main checkout（main） | worktree（feat/x） | SKIPPED | 誤放：受保護分支上的違規提交不檢查 branch-verify |
| C | main checkout | 未設 | ACTIVE，branch=main | 對照：正確 |
| D | worktree | 未設 | SKIPPED | 對照：正確 |

**結論：兩個方向都會錯判，含誤放。** B 情境的實際路徑：環境指向自身 worktree 的代理人或行程，對主 repo 的受保護分支寫入（commit-tree、update-ref 等不經 Bash 層 PreToolUse 守衛的路徑）。reference-transaction guard 正是這類路徑的最後防線，因此依 e1 分診判準升為 P1。

驗收已含 B 的正向對照（第 1 項）與 A 的反向對照（第 2 項）。

e1 合併前要求（2026-10-01；SendMessage 兩次送達失敗，改寫票面）：
1. gate 擋下的處置同意：不繞過、不放寬上限；負載降後跑全套件、gate 方式取樣並記 load 再提交。低負載仍超過 60 秒時，改排 W1-019 第二輪在前，通知 e1 改契約。
2. 附帶行為變更（commit-stage-guard-gate 的 PreToolUse 路徑改用呼叫端傳入的 root、不再優先讀 CLAUDE_PROJECT_DIR）擴大了影響面：Solution 須列出受影響的呼叫端；該路徑須有自己的 worktree 情境測試（合法放行、違規被擋兩側），不以 hook 層測試間接覆蓋。
## Solution
<!-- Schema[IMP/Solution]: 選填（.claude/pm-rules/ticket-body-schema.md） -->
### 修法
_resolve_branch_context(is_merge_commit, project_root=None, branch=None) 與 _run_all_checks(..., branch=None)：呼叫端傳入的 project_root 直接作為分支判定的根與 host_root，不在內部重新解析 CLAUDE_PROJECT_DIR；branch 有值時以之為準，None（含 detached HEAD 寫入）退回讀 project_root 的 HEAD。

### 受影響呼叫端（grep _run_all_checks／_resolve_branch_context 為準，共兩個 hook 與 lib 本體）
| 呼叫端 | root 來源 | branch 來源 |
|---|---|---|
| commit-stage-guard-gate-hook.py（PreToolUse） | 修正後：git rev-parse --show-toplevel（提交發生處 cwd），失敗退回 get_project_root() | 不傳，讀該根的 HEAD 分支 |
| git-ref-transaction-content-guard.py（reference-transaction） | 修正後：同上 | stdin 第一個 refs/heads/* 的分支名；ref 為 HEAD（detached）不帶分支，退回讀 HEAD |
| _resolve_branch_context 單檔呼叫（_check_branch_verify 無 ctx） | 未傳 root 時維持舊行為（get_project_root，env 優先） | 同上 |
實測發現：PreToolUse hook 的 staged 清單本身也取自 env 根，僅改 lib 無法修好 B 情境，故 commit-stage-guard-gate-hook.py 同步改根解析（原 where.files 未列此檔）。

### 驗證
- reference-transaction：TestWorktreeBranchResolution（真實 update-ref 路徑 + lib 層）
- PreToolUse：test_commit_stage_guard_gate_hook.py TestWorktreeBranchResolution 4 測試，hook 根修正前 2 紅（A：feature worktree 合法提交被 env 指向的 main 的 staged 違規誤擋；B：main 上違規被放行）2 綠（對照）。
