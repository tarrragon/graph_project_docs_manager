## Solution

### 派發決策（PM）

- **不可變的範圍**：事件、邊、缺陷、查詢結果的集合，在建構時包成 `List`／`Set`／`Map.unmodifiable`。
- **frontmatter 只包第一層**：`TicketDetail` 回傳的 frontmatter map 包成 unmodifiable。巢狀的值（清單、子 map）不做深層凍結；這個缺口寫進 Spawn Requests，由 PM 回報 e1 決定是否另開票。
- **計數**：計數 getter 改為只走訪一次，可用 `late final` 或在建構時算好；選哪種由實作決定。類別若是 const 建構子，不能用 `late`，改在建構時計算。0.4.1-W1-003 交過來的「GraphBuiltEvent 混用存欄位與推導計數」由本票一併處理。
- **不碰 `buildGraph` 的簽章**：W1-002 正在並行處理。
- **契約基線**（docs/todolist.yaml 0.4.1 第 2 欄）：測試數只增不減，基線為 main 77e061427 合併後的通過數（W1-003 覆核值）；0.4.0 IT-1～3 凍結值、G9 計數與建圖日誌事件的欄位和值都不變。
- **排程**：W1-002 與 W1-004 並行（兩者沒有共用檔），W1-005 在 W1-004 合併之後派。
