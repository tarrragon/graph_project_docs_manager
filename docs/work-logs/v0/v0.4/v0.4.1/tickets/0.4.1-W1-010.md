### 實驗發現

已驗證：
- commit_files_isolated 的 staging（`git add -- <paths>`，在以 HEAD read-tree 的隔離 index 上）能正確處理刪除與改名；提交後共用 index 同步會 force-remove 舊路徑，porcelain 為空。
- 唯一的阻礙是提交範圍自我驗證：`git diff --name-only old_head commit` 受 diff.renames（git 預設開啟）影響，改名只列新路徑，因此一律誤判為範圍不符而放棄提交。加 `--no-renames` 即可。這是安全方向的失敗：不 update-ref，不會寫壞 HEAD。
- 只接受逐檔列舉，不接受目錄路徑。
- worklog 是中段插入，現行 append_lines 會把行放錯位置；W1-014 的投影在工作區為超集時正確，非超集時需要「在 HEAD 上重放插入」的回退，否則行仍落在檔尾。
- 路徑 (2)(3)(4) 的現行寫入集合與程式碼盤點一致；路徑 (1) 在本 repo 的階層式目錄下無法執行。

未驗證：
- 大量檔案（整版搬移數百檔）時 commit_files_isolated 的 `git add` 參數長度與耗時（E4 只有 3 檔）。
- 被解鎖票併入同一 commit 時，若另一 session 正對該票做 CLI 寫入，鎖競爭的實際頻率。

## Solution
### 結論摘要

四條路徑都應改為「一個邏輯操作 = 一筆隔離提交」，沿用 commit_files_isolated／commit_ticket_mds_reporting。不採 git mv：它經共用 index，違反隔離提交要件 1–2，並行時會吸入他人 staged 內容。前置條件只有一項，就是讓自我驗證不受 rename 偵測影響（加 `--no-renames`）。加上後，現有多路徑提交即可處理刪除與改名，不需要新的提交機制。worklog 這類多寫入者、中段插入的檔案，要以行為單位提交，依賴 W1-014 的投影，並另需「在 HEAD 上重放插入」的回退。
