### 盤點中發現的既有缺陷（與提交語意相關，列入 Solution 擬建票或 spawn）

- version-shift 只解析扁平路徑 `docs/work-logs/v{version}`，本 repo 為階層式 `v0/v0.4/v0.4.1`：`--dry-run` 與實跑皆在前置驗證以 exit 1 結束（tmp repo 實測）。現階段無法在本 repo 執行，故目前不會造成損害。
- version-shift 的 todolist 步驟只改 `current_version`／`previous_version`／`tech_debt`，本 repo todolist 三鍵皆無；但無論改動數是否為 0 都以 `yaml.safe_dump` 整檔重寫：實測 569 行變 291 行，38 行註解全數消失，`versions[].version`／`worklog` 也不會更新。另有三處未處理：worklog 主檔名 `v{from}-main.md` 未改名、topic-assignments 未處理、跨版本引用掃描只掃 `v*/tickets`（扁平）。
- migrate 結構欄位漏改：`discovered_during`、`closed_by`、被遷移票子孫的 `chain.root`／`chain.parent`。topic-assignments 無任何處理，新 ID 的 `list_assignments()` 回傳 None，主題實際遺失。本 repo 實例：0.4.1-W1-010 在 topic-assignments.txt 無登記；舊行 0.4.0-W1-077 登記為「0.1 App 地基」，與 todolist notes 的「框架修復」也不一致。
- migrate 父票時子票不連帶遷移：子票 ID 仍為舊前綴，但 parent_id 已指向新 ID。
- complete 的 worklog 以整檔提交：工作區 worklog 含他人未提交修改時，該修改會被一併提交（E5-A）。
- batch-complete 不執行 cascade 與反向 blockedBy 解鎖，只有單票 complete 會執行（程式碼確認，未見註明是否刻意）。

### WRAP 三問
- W：各路徑皆評估至少兩個方案（見 Solution）；「git mv 加單一提交」不採用：git mv 經共用 index，違反隔離提交要件，且並行時吸入他人 staged 內容。
- A：本票為分析票，不擠壓 Graph topic；實作票與 W1-014 共用 git_ops，須排序。
- P：最可能的失敗是把 commit_files_isolated 能否處理刪除與改名當成假設而未實測。已用 tmp repo E1–E4 驗證：刪除可行，改名在預設 git 設定下被自我驗證誤擋。
