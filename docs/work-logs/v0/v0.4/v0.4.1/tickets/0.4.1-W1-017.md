## Solution
### 變更摘要

實作於 bad00714c，測試修正 8870c0262，合併為 main 上的 merge commit。檔案均在 .claude/skills/version-release/：scripts/version_release.py、tests/test_release_git_write_failure.py（新增）、SKILL.md（2.10.0 改為 2.10.1）、CHANGELOG.md。

- 新增 run_git_with_lock_retry：偵測 .lock 與 File exists 時固定間隔重試，預設 5 次、每次 2 秒，不刪鎖。沒有沿用 ticket 側的重試函式，因為跨 skill import 違反 skill 隔離。
- commit_changes：git add 或 git commit 在重試用盡或遇到其他失敗時回傳 False。rename 舊路徑側出現 pathspec 不匹配時視為正常（路徑已不存在）。
- git_merge_and_push：任一 git 寫入失敗都在打 tag 之前中止，main() 以 1 退出。stderr 會帶出失敗命令、exit code、git 原始錯誤、已完成步驟與補救指令。git checkout main 失敗原本被忽略，這次一併修正。

### git 寫入點盤點

| 寫入點 | 原行為 | 現行為 |
|---|---|---|
| git add（逐檔、相容路徑） | 只 WARN 就繼續（本缺陷） | 重試，用盡即中止 |
| git commit | 回傳 False，無錯誤詳情 | 重試，並輸出 stderr |
| git checkout main | 失敗被忽略 | 失敗即中止 |
| git pull / merge | 回傳 False，無 stderr | 補 stderr 與中止訊息；merge 對 unrelated histories 的既有容忍維持 |
| git tag -a | 回傳 False | 改走重試並補 stderr |
| git push main / tag | 回傳 False | 補 stderr 與補救指令（含「tag 已在本地建立」狀態） |
| git branch -d / push --delete | 僅警告 | 維持。這兩步在 tag 與推送之後，只做清理 |

### 自檢結果（PM 審查）

- 代理人回報：暫時鎖測試在修正前就是綠的。PM 以 fbb5a5fec 的程式碼取樣 5 次，3 次紅、2 次綠，判定為計時器造成的偽綠。原因是 git 啟動慢於 0.3 秒時，第一次 add 已經看不到鎖。
- 處置：改為在第一次 add CHANGELOG.md 返回後才釋放鎖，並斷言 add 至少被呼叫兩次（8870c0262）。取樣結果：修正前 5/5 紅，修正後 5/5 綠。
- 新發現：git commit 與 git tag 仍帶 timeout=10。逾時被殺的 git 可能殘留鎖。現行行為是可見失敗，會在打 tag 前中止。已建 0.4.1-W1-018（待 0.4.1 分診確認）。
- 既有設計未動：git_ok 為 False 時，main() 會先寫 todolist completed，再 return 1。

### Phase 4 重構評估

- 重構需要：否
- 技術債務：發現一項，即固定 10 秒逾時，承接票 0.4.1-W1-018
