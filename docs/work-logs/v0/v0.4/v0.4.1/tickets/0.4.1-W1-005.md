# Execution Log

## Task Summary

W4-001 審查（linux #7、#8，parsley #7）：AdjacencyUnavailable 的 cause 與 edgeTypeReason 組合有一組不合法（buildNotCompleted 帶 reason），僅靠建構邏輯保證；「圖不可用只記一次」以實例旗標實作，同一 buildResult 建多個實例會重複記錄；query 每次線性掃描 edges（O(E)），逐節點查詢時為 O(N·E)

## Solution
<!-- Schema[IMP/Solution]: 選填（.claude/pm-rules/ticket-body-schema.md） -->

### 派發決策（PM）

- **sealed 化**：`AdjacencyUnavailable` 拆成兩個子類，「建圖不可用」帶 `EdgeTypeUnavailableReason`，「尚未完成建圖」不帶原因。`reasonCode` 的輸出值不變，L3 的 payload 也不變。
- **「只記一次」的單位**：以 buildResult 為單位（版本契約第 5 欄，e1 已定），做法由實作決定，例如以 `Expando` 掛在 buildResult 上。不可用全域可變旗標，否則測試之間會互相污染。
- **尚未完成建圖（buildResult 為 null）**：記錄單位待 e1 裁決，見 NeedsContext NC-1。裁決前不派發。
- **端點索引**：`AdjacencyQuery` 建構時依端點建立索引，查詢不再線性掃描全部邊；G7 的回傳順序須與現行相同。
- **排程**：W1-004 已合併，本票接在之後。
- **契約基線**：測試數只增不減，以 main 94ff913a3 的覆核值為準；0.4.0 IT-1～3、G9 與建圖日誌事件不變。

### NC-1（PM，派發前）：尚未完成建圖時「只記一次」的單位

- **缺失項**：版本契約第 5 欄規定「圖不可用」以 buildResult 為單位只記一次。尚未完成建圖時 buildResult 是 null，沒有物件可以當作單位。
- **觸發位置**：`AdjacencyQuery` 的 `buildResult == null` 分支（`AdjacencyUnavailableCause.buildNotCompleted`）。
- **影響**：L3 的新案例只涵蓋建圖不可用；null 分支的行為需要先定案，實作才能寫測試。
- **建議補料**：由 e1 裁決，三個選項：
  - (a) null 時維持以實例為單位只記一次（現行行為）。
  - (b) null 時不記日誌：尚未完成屬於暫態，不是不可用。
  - (c) null 時每次查詢都記。
