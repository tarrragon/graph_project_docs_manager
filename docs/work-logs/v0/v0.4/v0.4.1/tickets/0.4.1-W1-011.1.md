### 動工前多視角審查（2026-10-01，linux 架構與一致性、clove 錯誤命中與繞過）

兩份審查結論皆為「需修改後動工」。

| 編號 | 來源 | 嚴重度 | 問題 | 處置 |
|---|---|---|---|---|
| R1 | linux F1、clove F1/F2 | 高 | 命中條件沒有綁定 ref 名稱。殘留項可在受保護分支 tip 等於 parent 時被 ff merge 或 update-ref 錯誤命中；預驗證之後切換到 tip 相同的分支，也會命中 | 綁定 ref 全名（預驗證以 symbolic-ref HEAD 取得，hook 比對 stdin 的 ref） |
| R2 | linux F2、clove F3/F4 | 高 | `_resolve_branch_context` 內部以 CLAUDE_PROJECT_DIR 重新解析專案根，同一 hook 內有兩套根。「預驗證不用 CLAUDE_PROJECT_DIR」與「兩邊 findings 相等」在現行程式下互相矛盾，而且現行 hook 在 worktree 內本身就會判錯 | 前置修復另建 0.4.1-W1-028（blockedBy）；本票的等價性驗收加入絕對判準 |
| R3 | clove F5 | 高 | shim 為了判斷行數讀過 stdin，未命中時若不原樣交給 python，guard 讀到空輸入，多 ref 交易會被放行 | shim 先存整段 stdin，未命中時原樣管線給 python |
| R4 | linux F3 | 設計 | 快取檔帶來位置、原子寫入、單次使用、清掃、跨 worktree 共用與殘留項等成本 | 改用環境變數：commit_files_isolated 只在該次 update-ref 的 env 帶 `<new>:<old>:<ref>`，shim 以 sh 比對 stdin。沒有檔案，因此 clove F6～F8、F10 與 linux F4、F5、F8 一併消失 |
| R5 | linux F6 | 中 | 合併進行中兩端都豁免 branch-verify；單 parent 提交本不該豁免（既有缺陷） | 預驗證遇到 MERGE_HEAD 一律不設 env；既有缺陷另建 0.4.1-W1-029 |
| R6 | linux F7 | 中 | wrap 一致性檢查讀工作區磁碟，不由 commit sha 決定 | 預驗證只要產生任何 finding（含 WARN）就不設 env，退回完整掃描 |
| R7 | linux F9、clove F8、F9 | 低 | 預驗證載入失敗；sh 解析邊界；版本綁定 | 載入失敗不設 env，並且 stderr 與日誌都要可見；sh 以 `read -r` 加 hex 格式檢查，所有比較加引號。採用環境變數形態後，預驗證與 hook 讀同一份 repo_root 下的 .claude/，版本綁定可以拿掉 |

繞過面：兩份審查都確認沒有新增蓄意繞過途徑（能設環境變數或寫 .git 的行程，本來就能用 core.hooksPath 繞過 guard）；新增的只有意外錯誤命中，由 R1～R3、R5、R6 封住。
