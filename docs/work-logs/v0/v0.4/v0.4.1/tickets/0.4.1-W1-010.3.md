## Solution
### 變更摘要（實作 75553f548，合併 b72afebd7）

- `_cascade_unblock_children`、`_reverse_unblock_blockedby`、`_post_complete_cascade` 新增選用參數 `saved_paths`。只有 save 成功時才 append 路徑，回傳值形狀不變。
- `complete()` 把被解鎖票的路徑併入 `modified_paths`。`_auto_commit_completion_files` 新增 `unblocked_paths`，commit body 加「被解鎖的票：<id>、…」。
- 移除兩處過期的範圍註解。ticket skill 版號 2.44.15，CHANGELOG 記錄範圍變更的理由。
- 行為描述同步（PM，於合併 commit 內）：`references/track-command.md`「排除 children/siblings」改為「被解鎖的票併入同一 commit」；`pm-rules/ticket-lifecycle.md` 6.5.0 的範圍說明同步改寫。依 skill-cli-sync 規則，與程式碼放在同一個 commit。

### 自檢結果（PM）

- 程式審查：只收本次 save 成功的被解鎖票。save 失敗者不列入，原 WARNING 照常輸出。跨版本路徑由 git 自行解析所屬 repo（W1-010 的 E4 已驗證）。
- 合併衝突：與 W1-010.1 的版號衝突，CHANGELOG 保留 2.44.15 與 2.44.14 兩則，frontmatter 取 2.44.15。
- 合併前以 set-where 把 SKILL.md、CHANGELOG.md、track-command.md、ticket-lifecycle.md 補進 where.files。
- 執行者提出的疑點：
  - 同版本 child 的解鎖只在 `--force` 路徑可達，測試因此加了 `--force`；反向 blockedBy 不需要。
  - complete 產生的 handoff 是 untracked 檔，porcelain 斷言以 `--untracked-files=no` 排除。兩者都與本票範圍無關。
- 實地觸發：目前沒有票 blockedBy 本票，本票的 complete 不會解鎖任何票。第一次真實觸發是 0.4.1-W1-010.4 complete 時解鎖 0.4.1-W1-010.5，屆時檢查被解鎖票是否在同一個 commit、工作區是否乾淨。
