## Solution

### 派發決策（PM）

- **依賴方向不變**：Graph 不得 import Diagnostics；Diagnostics 不得 import Schema（SPEC-007 v1.5 FR-09，test-design §1.3）。Diagnostics 可以 import Graph 的型別。
- **編譯期守護**：保留 sealed 窮舉。新增一種缺陷時，`_toGap` 之類的 switch 必須在編譯期就報錯，不能退化成 runtime default 分支。
- **去重方式由實作決定**：可以合併 wrapper 與 detail、讓 Gap 直接承載 Graph 的 detail，或改用其他方式，但要守住上面兩條。Solution 須列出「新增一個缺陷子類要改的位置」前後對照，列出檔案與符號。
- **不碰計數**：「GraphBuiltEvent 混用存欄位與推導計數」由 0.4.1-W1-004 處理，本票不改計數 getter，避免兩票同時改同一區塊。
- **建圖日誌事件**：欄位與值不得改變（版本契約第 2 欄）。
- **排程**：W1-001、W1-006、W1-007、W1-008 合併後派發（main cab4374c7）。本票合併後，再並行派發 W1-002 與 W1-004。

### 新增一個缺陷子類需改的位置：前後對照

前（6 處、4 層型別）：
1. lib/graph/graph_built_event.dart：GraphDefect 子類（wrapper，含 detail）
2. lib/graph/light_node.dart 或 reference_classification.dart：detail 型別（DuplicateIdDefect／DanglingRef／MalformedRef）
3. lib/graph/graph_builder.dart：包 wrapper 的建構
4. lib/diagnostics/graph_defect_gap.dart：GraphDefectKind 列舉值
5. 同檔：GraphDefectGap 子類
6. 同檔：_toGap 的 case

後（3 處）：
1. lib/graph/graph_built_event.dart：新增 GraphDefect 子類（欄位直接承載，無 detail wrapper）
2. lib/graph/graph_builder.dart（或分類函式）：產生該缺陷
3. lib/diagnostics/graph_defect_gap.dart：GraphDefectGap.kind 的 switch 加一 case 與 GraphDefectKind 列舉值（sealed 窮舉，漏寫編譯期報錯）

做法：DanglingRef／MalformedRef／DuplicateIdDefect 刪除，欄位併入 *GraphDefect 子類；RefGraphDefectGap／DuplicateIdGraphDefectGap／MultiSourceGraphDefectGap 合為單一 GraphDefectGap(defect)；_toGap 刪除。依賴方向不變（Diagnostics import Graph，Graph 不 import Diagnostics／Schema 新增）。GraphBuiltEvent 計數 getter 未動。
