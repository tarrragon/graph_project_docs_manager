# Execution Log

## Task Summary

W1-070 實測：現行 shim（由 git-ref-transaction-guard-install-hook 產生、以 exec uv run --quiet 啟動 guard）在 uv 無法解析依賴（離線且快取冷，rc=1）或 uv 不存在（rc=127）時，git 以 fatal: ref updates aborted by hook 中止所有 ref 寫入（update-ref rc=128），與 guard 宣告的 fail-open 設計相反。guard 阻擋時也回 rc=1，shim 無法分辨是 guard 判定阻擋，還是 uv 啟動失敗。

## Solution
<!-- Schema[IMP/Solution]: 選填（.claude/pm-rules/ticket-body-schema.md） -->
### PM 複核與合併（2026-09-30，83）

- 合併 b6ef08630。guard 判定阻擋改用專用離開碼 87，避開 1、2、101、126、127、128+N 與 sysexits 64-78 等常見錯誤碼。shim 收到 87 才中止 ref 寫入，其他非 0 一律寫警告後放行。
- **實地觸發時發現的瑕疵，由 PM 修正**：shim 警告寫成 `rc=$rc）`。bash 在 C locale 下會把緊接的全形標點位元組併入變數名，展開結果為空，輸出變成 `rc=��`，看不到實際的離開碼。
  - PM 改為 `rc=${{rc}}`：模板是 Python f-string，大括號必須跳脫。
  - SHIM_VERSION 升為 3，讓已安裝的 v2 shim 也會被更新。
  - 補回歸測試 `TestShimWarningRcExpansion`（commit bd9d24e91）。
- **部署順序**：舊 shim 搭配新 guard 時，guard 回 87 仍是非 0，照樣中止，不會漏擋。新 shim 搭配舊 guard 時，判定阻擋會被當成啟動失敗而放行；但 shim 與 guard 位於同一個 `.claude/`，會隨同一次 sync 一起更新，install hook 在 SessionStart 才改寫 shim，所以這個組合的窗口可以忽略。

### 自檢結果

- **本 session 實地觸發**：在 scratch repo 安裝主 repo 實際產出的 shim，guard 為複本，分支為非保護分支。
  - E1：PATH 不含 uv 時 commit 成功，stderr 為「guard 啟動失敗（rc=127），已放行本次 ref 寫入，內容掃描未生效」。v2 時這裡是亂碼，v3 顯示正確。
  - E2：PATH 中的假 uv 回 87 時，出現 `fatal: ref updates aborted by hook`，HEAD 沒有前進。
- **liveness**：
  - 在主 repo 執行 install hook 後，`.git/hooks/reference-transaction` 由無版本標記的舊 shim，依序更新為 `shim-version: 2`、`3`。
  - guard 日誌在 23:43:40 記錄 PM 那次 commit 的「新 commit 內容無發現，放行：new_commits=1」，證明正常路徑經 v3 shim 照常運作。
- **測試**：install hook 測試檔 15 passed。代理人跑 hooks 全套件時只有 1 項失敗，原因是舊的 rc=1 斷言，已改為 87 並重跑相關的三個測試檔，全部通過。

### Phase 4 評估

- 重構需要：否。
- 技術債務：無。
