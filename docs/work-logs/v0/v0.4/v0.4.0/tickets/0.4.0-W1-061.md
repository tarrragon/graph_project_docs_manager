## Solution
<!-- Schema[IMP/Solution]: 選填（.claude/pm-rules/ticket-body-schema.md） -->
### PM 複核與合併（2026-09-30，83）

- **第一輪 blocker（PM 直接呼叫解析函式實測）**：子 shell 的 cd 洩漏到括號閉合之後。`(cd <sp> && ls) ; git reset --hard` 等三種寫法被判為「目標皆為他 repo」，主工作區的清空操作因此被放行。已退回修正。
- **第二輪**：
  - 只有整個命令恰為單一 `( cd X && … )` 時才採用 cd 推導的目標。
  - `cd -` 與相對 cd 視為無法解析。
  - 新增 `_space_parens`：修掉原本就存在的偵測盲點，即括號黏在 token 上時，括號後的 git 呼叫不被偵測。
  - 補 E2 共 6 案，紅燈與綠燈證據見代理人回報。
- **合併**：worktree 分支合併進 main。合併前確認 index 與 HEAD 一致、工作區乾淨。
- **共用層**：盲點其實在共用的 `lib/git_command_parse`，其他 6 個守衛同樣可被繞過。另建 0.4.0-W1-065（P1）處理，並由它移除本守衛內的局部 `_space_parens`。
