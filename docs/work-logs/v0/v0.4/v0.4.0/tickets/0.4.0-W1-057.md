# Execution Log

## Task Summary

flutter_balance 0.3.0-W4-001：where.files 只有 .claude/skills/verify/SKILL.md 的票被 PORTABLE_ISSUE_UNDEDUPED 擋下（where.files 全在 .claude/ 下即判定可攜問題），但 verify 在 .claude/sync-skills.yaml 已宣告 private，屬專案特化、不推送的 skill。

---

## Problem Analysis
### 問題根因

`ticket create` 的可攜問題分流閘門（PORTABLE_ISSUE_UNDEDUPED）用路徑前綴判斷：where.files 全部在 `.claude/` 底下，就當作可攜問題，要求先查重 framework issue。這個判斷沒有讀 `sync-skills.yaml` 的 private 宣告。宣告為 private 的 skill 不會被 sync-push 推到 canonical，屬於專案特化，卻一樣被要求查重。

### 既有共用函式（PM 讀碼確認，2026-09-30）

`.claude/lib/sync_exclude_manifest.py` 已經提供可直接重用的函式：
- `load_sync_skills_config(claude_dir)`：回傳 mode、include、private 三項設定
- `should_exclude_skill(skill_name, config, direction)`：push 方向時，排除 private skill，以及 mode=select 下不在 include 清單的 skill
- `should_exclude(path)`：非 skill 路徑的同步排除清單

sync-claude-push／pull 用的就是這組函式。建議閘門改問「這條路徑會不會被 sync-push 推到 canonical」，直接重用這組函式，不另寫一份 private 判斷，否則閘門和推送範圍會再次分岐。

### 框架問題判準（兩條 AND）

1. 抽象可攜：是。任何有 private skill 的 consumer，替該 skill 建票時都會被誤擋。
2. 根源在 `.claude/` 通用資產：是，根源在 `.claude/skills/ticket/ticket_system/commands/create.py`。

### 查重

e1 已查重，命中 #55（ticket CLI 契約缺口叢集），關係為引用。完成後在 #55 附加觀測。

### 版號

ticket skill 2.44.2（W1-052、W1-053）正在等待推送授權。本票改用 2.44.3：不論 2.44.2 是否已推送，都不會撞號。

## Solution
<!-- Schema[IMP/Solution]: 選填（.claude/pm-rules/ticket-body-schema.md） -->
### 採用的判準與接法

閘門判準由「where.files 全在 .claude/ 下」改為「全在 .claude/ 下，且至少一條路徑會被 sync-push 推到 canonical」。修改處為 field_validators.py 的 is_portable_where_files（新增 _is_pushed_to_canonical），create.py 呼叫端不需改。

每條 .claude/ 路徑（去掉 .claude/ 前綴後）依序判定：
- manifest.should_exclude(rel)：同步排除清單命中，不推送
- 路徑為 skills/<name>/...：manifest.should_exclude_skill(name, config, "push")，涵蓋 private、mode=select 下不在 include、mode=none
- 其餘視為推送

全部路徑皆不推送才回 False（不觸發閘門）。含任一會推送的路徑仍觸發（E2）。未另寫 private 判斷。

### import 路徑接法

ticket CLI 的 sys.path 不含 .claude/lib，但 ticket_system/lib/claude_lib_loader.py 已提供 load_claude_lib / find_claude_dir（identity_guard 等既有模組同一做法）。閘門用 load_claude_lib("sync_exclude_manifest") lazy 載入，claude_dir 由 find_claude_dir 取得（CLAUDE_PROJECT_DIR，其次 cwd 向上，再其次開發環境 fallback）。不新增 sys.path 操作。manifest 或 claude_dir 取不到、或 sync-skills.yaml 解析拋 ValueError 時，退回原行為（視為會推送），並寫 stderr，寧可多擋不漏擋。

### 修改檔案

create.py 未改，改動在 field_validators.py（where.files 已用 set-where 補登）、tests/test_create_portable_issue_gate.py、SKILL.md（2.44.3）、CHANGELOG.md。

### 自檢結果

- 函式長度：_is_pushed_to_canonical 約 28 行，is_portable_where_files 約 17 行，皆 <= 30
- 巢狀深度 <= 2，無魔法數字（前綴 ".claude/" 沿用既有字面）
- 例外處理：ValueError 分支寫 stderr 並說明退回保守判定
- 認知負擔指數估計 <= 10

### Phase 4 評估

- 重構需要：否
- 技術債務：無新增。既有 is_portable_where_files 的路徑前綴判斷保留，新增判準疊加其上
- 程式碼品質：A
- 結論：無需重構。已知限制：本專案 .claude/ 下無 sync-skills.yaml，config 取預設 mode=all、private 空，故本專案自身行為不變；只有宣告 private 的 consumer 受益
