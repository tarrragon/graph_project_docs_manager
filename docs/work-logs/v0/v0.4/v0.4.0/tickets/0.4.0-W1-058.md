### PM 初步查證（2026-09-30，83）

- e1 提供的線索 39bee0711（15:16:43）是本 session W1-056 代理人的 append-log CAS 提交，只含 `0.4.0-W1-056.md`，該提交與其親代的 `.claude/VERSION` 都是 2.65.0。
- `git_ops._sync_shared_index_after_commit` 只以 `ls-tree <tree> -- <paths>` 取出本次提交的路徑，再用 `update-index --index-info` 寫回，不做全量 read-tree；VERSION 不在該次的 paths 內，理論上不會被這條路徑改動。
- 已知時序：
  - 15:16：sync-push 回寫 2.66.0 到主工作區
  - 15:16:43：CAS 提交 39bee0711
  - 15:17:11：e1 以 git add + 裸 commit 產生 1e8091846（VERSION 2.66.0）

  - 15:18:36：PM 以 restore 對齊後合併 bd74d6ae3
- 待查方向：15:17:11 之後有誰同時「寫回檔案內容」並且「stage」。候選包括 SubagentStop／Stop 類 hook（agent-commit-verification、worktree-auto-commit、ticket-md-auto-commit）在代理人結束時對主 repo 的操作，以及代理人在主 repo 執行的任何 git 指令。可交叉比對各 hook 的 hook-log 在 15:17–15:19 的紀錄。

### 排除項（逐條有證據）

1. `git_ops._sync_shared_index_after_commit`：只以 `ls-tree` 取本次 paths 再 `update-index --index-info`，且 CAS 全程不寫工作區檔案（git_ops.py 檔頭 docstring 與函式本體）。本次 CAS 39bee0711 只含 W1-056 ticket md，與 1e8091846 之間 `git diff --name-only` 僅 `.claude/VERSION`。無法把 VERSION 檔案內容改回 2.65.0。
2. `sync-claude-push.py`：`write_local_version`（約 L246–L270）只寫檔、不 stage、值為本次推送版本；全檔無 checkout／restore／stash／reset／read-tree 呼叫，無 rollback 路徑。
3. `sync-claude-pull.py`：VERSION 走 `VERSION_FILES_TAKE_UPSTREAM` 只 `_atomic_write` 工作區檔，不 stage；且採 upstream（新版），不會寫回舊版。
4. Stop 類 hook：worktree-auto-commit 於主 repo 直接跳過（其唯一寫入路徑是 worktree 內 `git add -A`／commit）；ticket-md-auto-commit 判定無未提交 ticket md；SubagentStop 兩條 hook（dispatch-cleanup、agent-commit-verification）在該窗口無 git 寫入紀錄（agent-commit-verification 15:xx 無 log 行；dispatch-cleanup 只做狀態標記）。
5. PostToolUse(Bash) 類 hook 與 PreToolUse guard：全為唯讀檢查／提醒；hook-logs 於窗口內無任何 VERSION／restore／reset／checkout／stash／read-tree／update-index 字樣。
6. 合併語意：b59ffd1d9 與其 merge-base 的 VERSION 皆 2.65.0（theirs==base），merge 本身不會把 VERSION 改成 2.65.0；「would be overwritten」是既存的 index≠HEAD 狀態所致，是結果而非成因。

### 證據缺口

- hook-logs 不記錄 Bash 指令全文，無法還原 15:17:11–15:18:36 各 session 實際下過的 git 指令。
- 無 shell history／transcript 可對應到 e1、83、W1-056/057 代理人 session。
- 檔案 mtime 已於 15:18:04 被 83 的對齊改寫，原始寫入時間不可得。
