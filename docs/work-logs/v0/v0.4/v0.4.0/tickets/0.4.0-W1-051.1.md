# Execution Log

## Task Summary

hook 對 owned 登記檔（目前 25 張）每張串行呼叫一次 section_comment.py check 子程序，每張 2.1–3.4 秒、無快取無並行，整體牆鐘中位約 88 秒（N=6），每個 session 啟動都要等。settings.json 對本 hook 的 timeout 為 152 秒，約 43 張時會被平台中止（SessionStart 逾時 non-blocking，觀測提醒整批遺失）

---

## Problem Analysis
### 問題根因

hook 對 `.claude/state/framework-issue-owned.json` 內的 25 張 owned issue，逐張串行呼叫 `section_comment.py check` 子程序。每張內部有 2 次以上 gh API 呼叫，其中一次是 `--paginate` 讀取全部 comments；整個流程沒有快取，也沒有並行。量測與分階段耗時見 0.4.0-W1-051。

### 框架問題判準（兩條 AND）

1. 抽象可攜：是。任何 consumer 只要 owned issue 數增加，啟動耗時就線性增長，不依賴專案名稱或路徑。
2. 根源在 `.claude/` 通用資產：是，位於 `.claude/hooks/session-start-issue-check-hook.py`。

### 查重（2026-09-30）

以關鍵字 session-start-issue-check／owned／SessionStart 查詢，命中 10 則。其中 #95（framework-issue skill 2.0.0）只提到本 hook 的 owner 前綴比對，#81、#77 等只列出 hook 名稱，沒有任何一則涉及耗時或串行擴展性。判定未命中，與 #95 為引用關係。依流程回報 e1，不新開 issue。

### Hook 票必填

- Session 觸發確認：SessionStart 於 session 啟動時觸發，註冊見 settings.json（W1-047 設定 timeout 152 秒）。
- 活性驗證：PM 合入後以正式啟動方式（uv run，餵 SessionStart JSON）實測牆鐘時間 N>=3，並讀 hook log 確認各張都有結果。
- 失敗語意：hook 自身屬 fail-open，逾時或例外都不阻擋 session 啟動。單張 check 失敗時，該張在輸出中標示失敗、其餘張照常輸出；逾時由平台中止（non-blocking），但耗時須遠低於 152 秒。

### 產生路徑盤點（會讓本 hook 跑 check 的來源）

| 產生路徑 | 是否覆蓋 | 未覆蓋原因 |
|---------|---------|-----------|
| owned 登記檔存在且非空（快速路徑） | 是 | 本票主場景 |
| 登記檔不存在，改以 owner 前綴推導 | 是 | 同一個 `_run_check` 迴圈，一併並行 |
| 已關閉的 issue 仍留在登記檔 | 是 | 本票略過 |

## Solution
<!-- Schema[IMP/Solution]: 選填（.claude/pm-rules/ticket-body-schema.md） -->
修改 .claude/hooks/session-start-issue-check-hook.py 與同名測試檔（commit f43a6997c，分支 worktree-agent-a8011882b39212e1e）。
- _collect_registry_hits：先以 _closed_issue_numbers 單次 gh issue list --state closed 批次取得已關閉集合並略過（登記檔無狀態欄，不逐張多打 API；批次失敗 fail-open 不略過）；其餘依編號排序，ThreadPoolExecutor(max_workers=5) 並行 _safe_check，pool.map 保序，輸出順序與串行版一致。
- worker 上限 5 的依據：每張 check 約 2-3 次 gh REST 讀取；GitHub 限制為並行請求 <=100、REST 5000/小時。25 張約 75 次呼叫遠低於主限額，5 workers 約 10-15 個並行請求，保留約 7 倍餘裕。
- 失敗可見：_run_check 逾時／非 0 改回傳 [check 失敗] 標記字串並寫 log；_safe_check 攔截 worker 例外轉同樣標記，不影響其餘張。
- 實測（uv run 正式啟動，25 張，N=3）：修前 70.8/58.3/55.1 秒；修後 14.9/19.6/15.8 秒；輸出長度修前修後一致（25493）。
- E1 修前：假 check 0.3 秒 x 12 張串行 3.66 秒（修後測試門檻 <2.0，實測約 0.9）；E2 修前：單張例外會使 _collect_registry_hits 整個拋出。

### 自檢結果
E1/E2/已關閉略過/批次單次呼叫共 5 個新測試，修前 5 紅（缺 _closed_issue_numbers、CHECK_FAILED_PREFIX），修後全綠。全套件 uv run --directory .claude/hooks pytest -q：5159 passed, 48 skipped。

### Phase 4 評估
重構需要：否。技術債務：無新增；註：已關閉略過的實際效果取決於登記檔內是否含已關閉 issue，本 repo 實測輸出不變。程式碼品質：A。結論：無需重構。
