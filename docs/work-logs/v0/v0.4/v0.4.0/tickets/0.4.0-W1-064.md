## Solution
<!-- Schema[IMP/Solution]: 選填（.claude/pm-rules/ticket-body-schema.md） -->
commit 7b6a232f4（worktree 分支）。ticket skill 2.44.6。
### 吞掉失敗的位置
- lib/git_ops.py commit_files_isolated：失敗以 {status:failed,error} 回傳，錯誤文字含 [殘骸診斷]。
- lib/git_utils.py _auto_commit_ticket_md：只回傳 status 字串，error 被丟棄（第一層吞）。
- commands/create.py execute 的 auto-commit 區塊：git_failed 只印 "auto-commit skipped（git_failed，非致命）" 無原因、無 [WARNING]，rc 維持 0（第二層吞）。
### 根因（PM 提供的現場證據 + 重現）
update-ref 持 HEAD.lock/main.lock 期間執行 reference-transaction hook；高負載下超過 _GIT_TIMEOUT=10，subprocess.run 逾時殺掉 git，鎖殘留，其後每次提交撞鎖。RED 以 sleep 3 的 hook + timeout=1 重現：修正前 ref 未推進；修正後推進且無殘鎖。
### 修法
1. update-ref 不設 timeout（timeout=None）。git_ops._run_git 預設 timeout 改哨兵 _DEFAULT_TIMEOUT，呼叫當下讀 _GIT_TIMEOUT（原為定義當下綁定，測試無法覆寫）。其餘持鎖步驟評估：read-tree/add/write-tree 作用於私有臨時 index，無共用鎖；_sync_shared_index_after_commit 持 index.lock 但毫秒級、不觸發 hook，維持預設 timeout，不同型。
2. git_utils.auto_commit_ticket_md_with_retry：git_failed 且為鎖競爭、且無 [殘骸診斷] 標記才重試；退避 0.5/1/2 秒，等待總和上限 5 秒。_auto_commit_ticket_md 新增 result_out 帶回 error；非 git repo 回 not_git_repo（維持 rc 0）。
3. create 最終失敗：stderr [WARNING] 含原因、鎖檔路徑、補救指令（git add + git commit）與「確認無 git 行程再手動移除鎖」；rc=75。絕不刪鎖。
### exit code 選定
75（sysexits EX_TEMPFAIL，暫時性失敗、稍後可重試）。與建票失敗 1、用法錯誤 2 區分；為 sysexits 慣例值，不與 ticket CLI 既有 0/1/2 衝突。記於 references/create-command.md。
### 未擴大範圍
reference-transaction hook 本身高負載下耗時 10 秒以上的原因未處理（不改 hook）。
