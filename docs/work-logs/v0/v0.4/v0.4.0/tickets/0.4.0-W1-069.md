## Solution
<!-- Schema[IMP/Solution]: 選填（.claude/pm-rules/ticket-body-schema.md） -->
### PM 複核與合併（2026-09-30，83）

- **根因**：`track.execute()` 只從 `args.ticket_id` 解析版本。set-parent（`child_id`）、add-child（`parent_id`）、batch-claim 與 batch-complete（`ticket_ids`）的位置參數名稱不同，都落入只看 active 版本的自動偵測。修正方式是新增 `_ticket_id_arg_version` 依序讀取這四個名稱，`--version` 顯式值仍最優先。合併 b2f7a8e6d，ticket 2.44.8。
- **子命令盤點**：共 4 個子命令有缺口，全部已修；其餘接受 `ticket_id` 的子命令走同一段解析，沒有缺口。盤點表見代理人回報。已知限制：batch 系列只取第一個 ID 的版本，跨版本混合清單仍須顯式給 `--version`，已寫進 CHANGELOG。

### 自檢結果

- **紅燈與綠燈**：真實 CLI 路徑的 fixture（active 0.2.0、planned 0.3.0）。修正前 set-parent 與 add-child 不給 `--version` 時回報「找不到 Ticket」（3 failed）；修正後 5 passed。
- **live**：本 repo 找不到可以安全操作的 planned 版本票（set-parent 與 add-child 都是寫入），因此沒有另做 live 驗證，由上述走真實 CLI 路徑的 fixture 承擔。
- **全套件**：合併後在 main 重跑 `uv run --directory .claude/skills/ticket pytest -q`，4236 passed、5 deselected。

### Phase 4 評估

- 重構需要：否。
- 技術債務：位置參數命名不一致，用 helper 收斂，沒有改參數名稱，以免破壞 CLI 介面。
- 品質：A。
