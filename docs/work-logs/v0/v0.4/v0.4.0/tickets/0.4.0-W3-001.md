### Panel `default` 呼叫處現況（決定 slot 形狀）

子件順序實測：`[Toolbar, Expanded, SplitRow.footer]`、`[Expanded, _legendBadgeRow]`、`[EmptyState, Expanded]`、`[AppText, Expanded, BadgeRow]`、`[Expanded]`；另有三處無任何填滿子件：domain_view `[AppText, EmptyState]`、uc_flow `[EmptyState]`、`[ListRow.meta, AppText, EmptyState]`——與 SPEC-004 §4.30「子件中恰一個填滿」不一致。
形狀：前段 0..n ＋ 填滿區恰 1 ＋ 後段 0..n。三處無填滿者的 `EmptyState.section` 靠上對齊、`mainAxisSize.min`，放入填滿區後仍貼上緣，渲染不變，故填滿區可定為必填，「恰一個」由型別保證。

## NeedsContext
- **缺失項**：`SizedBox.shrink()`（零尺寸、無子件）是否屬路徑 C 步驟 3 (b)「單子件佈局輔助」。判準定義為「僅改空間分配、內距、對齊或尺寸，不含第二子件的**包裝節點**」，shrink 不包任何子件；框架對應表的 `SizedBox` 分列只有「兄弟間無子件＝間距」與「包住一個元件＝固定尺寸」兩種，零尺寸空白兩者皆非
- **觸發位置**：掃描表 #9–15；兩種用法：(i) `build` 在狀態不符時 `return const SizedBox.shrink()`（4 處，不渲染）；(ii) `AppTableRow.header` 的 `cells:` 中無標題欄的空白格（3 處）
- **影響**：acceptance 1「計數為 0（或逐處列豁免理由）」的分母是 8 或 15
- **建議補料**：候選 A：兩種皆不計入（非包裝節點），逐處列豁免理由；候選 B：(i) 不計、(ii) 計為元件層缺口（`TableColumnHeader` 缺空白格變體）；候選 C：兩種皆計入。本專案為該 skill 上游，裁決後判準措辭可能需補一句
- **重派成本**：不擋 #1–8 的實作；#9–15 依裁決另補
