## Solution
<!-- Schema[DOC/Solution]: 免填（DOC 類型以變更摘要取代）（.claude/pm-rules/ticket-body-schema.md） -->
三份皆判 `evaluation_level: heavy`，依 `.claude/pm-rules/proposal-evaluation-gate.md` 規則 1 分級判定表「架構層級改動」條件：

| PROP | 判定依據 |
|------|---------|
| PROP-001 交付形態與發布通路 | 關閉 App Sandbox、改走 Developer ID，決定整個 App 的執行權限模型（架構層級） |
| PROP-002 schema 消費方式 | App 與框架 CLI／JSON 之間的契約形態（架構層級，且跨 APP 與框架兩端） |
| PROP-003 工作資料夾存取與資料來源 | 檔案存取模型與資料來源範圍（架構層級） |

三份 status 皆為 confirmed，補欄位屬維護編輯，不觸發升級閘門的章節檢查（規則 2.-1）。與 PROP-004（同為 heavy，W1-048 補）一致。
