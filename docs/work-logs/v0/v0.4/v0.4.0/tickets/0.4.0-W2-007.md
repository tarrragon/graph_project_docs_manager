## NeedsContext
- **缺失項**: 建圖不可用原因碼（D3-4）在 Diagnostics 端的承載型別裁決。
- **觸發位置**: `lib/graph/graph_built_event.dart` 的 `GraphBuildUnavailable.reason` 型別為 `EdgeTypeUnavailableReason`（定義於 `lib/schema/edge_type.dart`，值：versionOutOfKnownRange、missingForwardCardinality）。
- **影響**: §1.3 禁止 `lib/diagnostics/` 與 `test/unit/diagnostics/` import `lib/schema/`。(a) 收 `GraphBuildUnavailable`：測試無法建構該物件（需命名 schema enum）；(b) 沿用 W4-001 先例，以 Diagnostics 自有 `UndeterminedGapReason` 接收、由編排層映射：該 enum 只有 projectVersionOutOfKnownRange／noPathPattern，無 missingForwardCardinality 對應值，須新增列舉值（改既有公開 enum，可能影響 UI 的 exhaustive switch）或裁定該原因映射到既有值；(c) 以 dart:core `Enum` 不透明承載：型別可行但測試仍需一個 schema enum 值。三者皆為選邊，故未動工。
- **建議補料**: PM 裁決 (b) 是否新增 `UndeterminedGapReason.missingForwardCardinality`（建議：SPEC-006 FR-08 原因碼與 SPEC-007 FR-01 為同一套，補值最小），並同步 SPEC-004 l10n key 需求；裁決後 `detectGraphDefectGaps({required GraphBuiltEvent? event, required UndeterminedGapReason? unavailableReason})` 回傳沿用 `Undetermined`，可直接實作。
- **重派成本**: 低；紅燈測試與實作約 2 檔，資料已讀畢。
