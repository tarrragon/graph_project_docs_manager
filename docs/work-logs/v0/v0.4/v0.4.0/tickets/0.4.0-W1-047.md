# Execution Log

## Task Summary

settings.json 有 77 個 hook 的 timeout（5000 到 30000）以毫秒數值寫成，平台單位為秒，實際等於 83 分鐘以上。直接除以 1000 會讓 26 支 hook 的實測最大耗時超過或逼近新值，被平台終止時為 non-blocking，守衛會靜默失效。改為依 hook log 實測分佈逐支設定秒數，並更正 hook-specs 文件的單位說明

---

## Problem Analysis
### 問題根因

`.claude/hook-specs/claude-code-hooks-official-standards.md` 以毫秒示範 hook timeout，而平台單位為秒。settings.json 共 77 筆註冊照此文件填寫，實際上限變成 83 分鐘到 8.3 小時。查證紀錄見 0.4.0-W1-044 Solution。

### 框架問題判準（兩條 AND）

1. 抽象可攜：是。settings.json 經 sync 散佈（只排除 settings.local.json），錯誤示範文件也隨框架散佈。
2. 根源在 `.claude/` 通用資產：是。

### 查重與 canonical

用戶已授權開 canonical issue：tarrragon/claude#112（2026-09-30，由 e1 開立）。本票完成後在 #112 附加觀測。

### 修法約束

不可直接除以 1000。hook-logs 實測中，26 支 hook 的最大耗時超過原意值的一半。PreToolUse 逾時不會阻擋工具呼叫，timeout 設得過窄，守衛會在負載下靜默失效，比現狀更差。

## Solution
<!-- Schema[IMP/Solution]: 選填（.claude/pm-rules/ticket-body-schema.md） -->
### 公式與啟動開銷

timeout = ceil(max(p99 x 3, 最大值 x 1.5) + 啟動開銷)，下限 10 秒。無 log 資料者移除 timeout 欄位（平台預設 command 600；UserPromptSubmit 30，本批無 UserPromptSubmit 者）。

啟動開銷量測（3 支 hook 各 5 次，牆鐘 vs hook log 的程序內計時）：agent-prompt-length-guard 牆鐘 0.81-2.8s / log 0.24-0.83s（差約 2.3s）；dispatch-staging-phrase-guard 牆鐘 1.43-3.19s / log 0.13-0.7s（差約 2.5s）；language-guard 首次冷啟動 14.48s（uv 建環境，離群），暖啟動 0.8-4.25s。取暖啟動最大差 2.5s，進位為 3s 作為啟動開銷；冷啟動一次性成本不計入。

### 校正結果

76 筆註冊（>=1000）：71 筆改為秒、5 筆移除 timeout。hooks-test-gate（120，W1-043 已依秒設定）保留。樣本數為 log 內含同 hook 於不同事件的合計（log 不分事件），故同 hook 多事件註冊共用同組樣本與新值。

### 修訂（PM 覆核）：下限 10 秒改為 30 秒

公式改為 ceil(max(p99 x 3, 最大值 x 1.5) + 3)，下限 30 秒。依據：冷啟動量測到 14.48 秒（uv 建環境），sync-pull 改到 hook 依賴或 uv 快取失效後的第一次呼叫必然重現，不是離群值；下限 10 秒會讓該次呼叫被平台中止並靜默放行。代價是真正卡住的 hook 最多卡 30 秒。

新值欄修訂：上方逐支表中原新值 10 至 29 的 63 筆一律改為 30；原新值 >=30 者（152、595、54、40、39 等）與 hooks-test-gate 的 120 不變。settings.json 為準。
