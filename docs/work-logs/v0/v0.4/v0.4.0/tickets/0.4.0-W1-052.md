## Problem Analysis
### 問題根因

`create.py` 在 rc==0 之後才呼叫 `append_assignment` 追加主題行，而 `_auto_commit_ticket_md` 只提交新票的 md 一個路徑。建票時產生的旁路寫入不在提交範圍內，一律留在工作區。

### 影響範圍（本票建立時當場重現，2026-09-30）

建立本票後 `git status` 顯示兩個未提交修改：
1. `docs/work-logs/topic-assignments.txt`：`+0.4.0-W1-052	框架 skill 撰寫`
2. `0.4.0-W1-051.md`（`--source-ticket` 指定的來源票）：`spawned_tickets` 回填 `0.4.0-W1-052`

第 2 項是同一機制的另一個旁路寫入：`--source-ticket` 雙向回填改到來源票，但來源票也不在 auto-commit 範圍內。本 session 先前建 W1-044、W1-046、W1-050、W1-051 時也出現過同形的來源票殘留，當時皆以手動提交收尾。兩項都已手動補提交。

### 框架問題判準（兩條 AND）

1. 抽象可攜：是。任何 consumer 只要以帶主題或帶 `--source-ticket` 的方式建票就會觸發，不依賴專案名稱或路徑。
2. 根源在 `.claude/` 通用資產：是，根源在 `.claude/skills/ticket/ticket_system/commands/create.py`。

### 查重

以關鍵字 `topic-assignments` 查重，命中 #55（ticket CLI 契約缺口叢集，含「auto-commit 範圍不一致」）。關係判定為重複：屬同家族新成員，#55 既有條目涵蓋 check-acceptance／set-acceptance 與 append-log 等命令對，未涵蓋 create 的旁路寫入。處置：在 #55 附加觀測，不新開 issue。

## Solution
<!-- Schema[IMP/Solution]: 選填（.claude/pm-rules/ticket-body-schema.md） -->
### 做法
- git_ops.commit_files_isolated 新增 append_lines（路徑 -> 追加文字）：該檔在隔離 index 內以「old_head 版本 + 追加文字」組 blob（git show old_head:path -> hash-object -> update-index --cacheinfo），不整檔 add。多寫入者 append-only 檔因此不會帶入工作區他人未提交的行；HEAD 版末尾無換行時先補換行，與寫入端一致。提交範圍自我驗證與共用 index 同步改用 expected_changes（整檔路徑 + 追加路徑）。
- git_utils._auto_commit_ticket_md 新增 extra_paths / append_lines（預設 None；僅在有值時才傳 append_lines，既有呼叫端與其測試替身簽章不變）。
- create.py：append_assignment 回傳 True 時記下「ticket_id<TAB>topic」行；auto-commit 時帶入。來源票由 _source_backfill_paths 解析，僅在來源票內容含新票 ID 時納入（回填失敗則檔案無變更，納入會使自我驗證失敗、整批放棄）。
- 選擇理由：整檔提交會吸入他人未提交的行；「HEAD + 本次一行」使提交內容只由本次呼叫決定，與隔離索引的設計前提一致。來源票是 ticket md，單一寫入者語意，整檔納入即可。

### where.files 補登
以 set-where 補登 git_ops.py、SKILL.md、CHANGELOG.md：append_lines 的組 blob 與範圍驗證只能在 commit_files_isolated 內實作；版號與 CHANGELOG 為 acceptance 第 4 項要求。

### 自檢結果
- E1 修前紅：topic 殘留 " M docs/work-logs/topic-assignments.txt"；來源票殘留 " M tickets/...md"；修後皆乾淨且同一提交（變更檔恰為新票 md + topic 檔 + 來源票）。
- E2：--no-topic 提交不含 topic 檔（修前後皆綠，屬對照組）。
- 他人未提交行：修前 HEAD 內容缺本次行（測試紅）；修後 HEAD blob 不含他人行、工作區保留、仍為未提交修改。
