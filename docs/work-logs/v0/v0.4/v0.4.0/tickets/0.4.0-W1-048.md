## Solution
<!-- Schema[ANA/Solution]: 必填（.claude/pm-rules/ticket-body-schema.md） -->
### 裁決（2026-09-30 用戶 AUQ；缺口 1 經 WRAP）

| 缺口 | 裁決 | 判準 |
|---|---|---|
| 2 計數範圍 | 多子件一律計 | 頁面層任何多子件佈局都是一個排列關係，不論子件是元件庫元件或原生葉節點。原生葉節點本身另由方法論〈原生元件禁用對照表〉在元件層處理；兩者分工：葉節點違規屬元件層，其所在排列屬容器層 |
| 3 定義方式 | 結構定義 | 接受子件清單的節點即多子件佈局（Flutter：帶 children 參數或以 builder 產生多子件者）；列舉降為例示，補疊層（Stack／IndexedStack）、捲動列表（ListView／GridView／CustomScrollView／Sliver）、Table |
| 1 單子件佈局輔助 | 一律計入並依屬性歸屬轉置 | 填滿／空間分配（Expanded／Flexible）→ 容器具名 slot；間距／對齊／畫面邊距（Padding／Align／Center／當間隔的 SizedBox）→ 容器負責或容器參數；單一元件固定尺寸 → 元件尺寸變體（記元件契約缺口） |

### 缺口 1 的 WRAP 摘要

- **R**：(a) 本專案 Panel 契約（SPEC-004 §4.30）「子件中恰一個填滿剩餘高」由呼叫端以 Expanded 表達，容器無法驗證「恰一個」；(b) Expanded 是 ParentDataWidget，須為 Flex 直接子件，中間夾 render object widget 即執行期拋 `Incorrect use of ParentDataWidget`——頁面因此依賴容器內部為 Flex 且不再包層，容器改內部結構時頁面壞而編譯期無訊號；(c) 前例：Flutter Scaffold 以具名 slot（body）承載填滿區，不要求呼叫端包 Expanded。
- **結論**：有必要讓容器提供參數，理由不是 API 大小，而是把不變式從慣例移到型別、切斷頁面對容器內部實作的依賴。
- **被放棄選項的優點**：留 Expanded 最貼 Flutter 慣例、改動最小。
- **代價與絆腳索**：兩個 consumer 的容器都要加 slot、頁面層佈局輔助全數轉置；單一容器排列參數或變體超過 3 個時改拆具名容器。

### 兩個 consumer 實例的判定

| 實例 | 舊判準 | 新判準 |
|---|---|---|
| flutter_balance `_TrendContent` 的 `Row(原生 Text, ChangePill)` | 不計（僅 1 個元件庫元件） | 計入（多子件），原生 Text 另計元件層 |
| flutter_balance `app_shell.dart` 的 `IndexedStack` | 漏計（清單未列） | 計入（接受子件清單） |
| flutter_balance 頁面邊距 Padding、圖表 SizedBox | 無判準 | Padding → 頁面框架容器邊距；SizedBox 固定高 → 圖表元件尺寸變體 |
| 本專案 Panel children 內 Expanded 6 處 | 不計（夾在容器內） | 計入，轉 Panel 具名填滿 slot |
| 本專案 router 佔位頁 `Center(child: Text)` | 無判準 | 計入（對齊輔助）＋原生 Text 元件層 |

「殘留只報告、不擋發版」屬 consumer 的守衛強度，不寫進 skill 判準。
