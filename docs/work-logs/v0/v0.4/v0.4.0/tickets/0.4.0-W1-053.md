## Problem Analysis
### 問題根因

`dispatch_skeleton.py` 的 `CLOSING_BY_ISOLATION["worktree"]` 收尾句寫「commit（`ticket track commit`，於 worktree 路徑）」，但沒有說明提交範圍。依 root 分離設計，票面由主 repo CLI 寫入，main 會自動提交。代理人照字面在 worktree 提交時，若把票面一併帶上，只能先把主倉庫的票面 cp 到 worktree，於是分支留下比 main 舊的票面，合回 main 時票面狀態會倒退（flutter_balance 0.2.3-W3-454 實例）。

### 本 session 的對照證據

本 session 以 worktree 派發了 6 張票（W1-042、W1-043、W1-046、W1-047、W1-051.1、W1-052）。PM 自寫的派發 prompt 都明寫兩點：「在 worktree 內 commit，只 add 精確路徑」，以及「用主 repo CLI 回填票面」。6 次合入都沒有出現票面副本或狀態倒退。這表示「worktree 只提交產品檔、票面走主 repo」的分工實際可行，衝突點只在骨架文字。

### 框架問題判準（兩條 AND）

1. 抽象可攜：是。任何 consumer 以 `ticket track dispatch --isolation worktree` 產生骨架並照做時都會觸發，不依賴專案名稱或路徑。
2. 根源在 `.claude/` 通用資產：是，根源在 `.claude/skills/ticket/ticket_system/lib/dispatch_skeleton.py` 與 `.claude/references/agent-dispatch-template.md`。

由 e1 以 #101（保護分支守衛只擋得住已分歧的合併：worktree 交付無合法落地路徑）查重，判定關係為引用：兩者同屬 worktree 交付家族，本票機制是骨架文字與 root 分離設計互相矛盾。完成後在 #101 附加觀測。
