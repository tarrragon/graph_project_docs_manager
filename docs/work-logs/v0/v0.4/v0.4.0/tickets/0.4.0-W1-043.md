# Execution Log

## Task Summary

hooks-test-gate 把本次提交改到的 hook 之對應測試合成一次 pytest 執行，逾時固定 PYTEST_TIMEOUT=30 秒且無覆寫方式。flutter_balance sync-pull canonical v2.64.1 改到 10 支 hook，合併執行 333 passed 耗時 45.2 秒，被判「測試逾時」阻擋提交；逐檔耗時 bare-commit-guard 17s、bash-git-protected-branch-guard 9s、git-ref-transaction-content-guard 7s、commit-stage-guard-gate 5s，其餘 <1s。consumer 被迫把一次 pull 拆成 3 個 commit，與 sync-pull『一次 pull 集中為單一 commit』規範衝突。

---

## Problem Analysis
### 問題根因

`PYTEST_TIMEOUT = 30` 的註解依據是「單一目標測試檔基準 0.21s（W3-188 實測）」，但 `_run_pytest` 把本次提交觸及的全部 hook 的對應測試合成**一次** pytest 呼叫，套用同一個 30 秒上限。單檔基準的前提在合併執行下不成立：總耗時隨觸及 hook 數線性增長，逾時與「測試檔本身卡住」不再同義。gate 在 `TimeoutExpired` 時保守判定失敗並阻擋，綠燈被報為紅燈。

### 影響範圍

- 任何 consumer 一次 sync-pull 觸及的 hook 數達到一定量即必撞，與 sync-pull「一次 pull 集中為單一 commit」規範衝突。
- 修法的外部約束（PM 讀碼確認，執行者須實測核對）：settings.json 對本 hook 的註冊**未設 `timeout`**，依賴平台預設值；平台層 hook 逾時的結果是 non-blocking（commit 放行、gate 形同未跑）。因此任何會拉長 gate 總耗時的修法（逐檔執行、縮放逾時）都可能把「誤擋」換成「靜默放行」。修法必須同時界定 gate 總耗時上界，並讓它落在明示的平台 timeout 之內。

### 框架問題判準（兩條 AND，逐條套用）

1. 抽象可攜：是。敘述不依賴任何 consumer 名稱或路徑——「固定逾時套用於隨觸及檔數增長的合併測試執行」在任何 consumer 單次提交觸及夠多 hook 時必然觸發。
2. 根源在 `.claude/` 通用資產：是。根因常數與合併執行邏輯都在 `.claude/hooks/hooks-test-gate-hook.py`，隨 sync 散佈至所有 consumer。

關鍵字 `hooks-test-gate`／`PYTEST_TIMEOUT`／`逾時`／`timeout`。PYTEST_TIMEOUT 零命中；#54、#67、#97、#58 留言中皆無本逾時的既有觀測。

## Solution

擇定方向：(b) 逐檔執行（每測試檔各跑一次 pytest，單檔逾時才判失敗）+ 總預算硬上限。
否決：(a) 依檔數縮放逾時：仍是單一合併呼叫，無法指名是哪個檔逾時，違反硬約束 2；總耗時上界隨檔數增長，需另加 cap，複雜度不低於 (b)。(c) 辨識 sync-pull 提交豁免：commit 訊息／檔案集皆可由一般提交複製偽裝，未能說明不可偽裝，依硬約束 3 不選。
量測（N=5，負載下，秒）：bare-commit-guard 5.3/5.2/4.6/6.6/6.8；bash-git-protected-branch-guard 15.2/37.5/10.4/9.2/17.2；git-ref-transaction-content-guard 12.5/16.7/15.8/8.2/13.3；commit-stage-guard-gate 13.2/10.9/7.9/11.1/9.6。含 uv 啟動；最大 37.5s 為負載尖峰，故單檔上限取 60s（PER_FILE_TIMEOUT）而非 30s，否則單檔即誤擋。
總耗時上界：每檔 timeout = min(60, 剩餘預算)，預算 TOTAL_BUDGET=100s，耗盡後其餘檔案標記未執行並 deny（保守）。最壞 = 100s + 進入測試前 git diff 開銷（<5s）約 105s < settings.json timeout 120。
平台 timeout 單位：專案 .claude/references/hook-architect-technical-reference.md 記為「秒數」，Claude Code 官方 hooks 文件同為 seconds（預設 60）；本環境無 context7 工具，官方文件未能當場重驗，出處為前述專案 reference。settings.json 明示 "timeout": 120（秒）。
發現（需另票）：settings.json 他處 timeout 值為 5000/15000/30000，且 .claude/hook-specs/claude-code-hooks-official-standards.md 寫毫秒；若單位為秒則這些值實為 5000 秒以上（等於無逾時保護），與 reference 矛盾，需 PM 建票查證。
deny 訊息區分 紅燈／單檔逾時／總預算耗盡未執行，並列出檔名。改動：hooks-test-gate-hook.py、test_hooks_test_gate_hook.py、settings.json。
