### 派發決策（PM）

- **原因碼**：新增 `EdgeTypeUnavailableReason.invalidEdgeTypeEntry`（SPEC-007 v1.8，e1 裁決 d09c37df0）。命名沿用 W4-015 改名後的風格。
- **排程**：派發順序為 W4-003、W4-004、W4-005 合併，接著 W4-015 合併，最後才派本票。本票與 W4-015 都會改 `edge_type.dart` 的同一個 enum，而本票又會改 W4-005 改過的 IT-2 呼叫端，所以放在最後。
- **Diagnostics 端**：不改。三個原因碼在編排層一律映射為 `projectVersionOutOfKnownRange`（FR-09）。
- **一併收斂（W4-004 Phase 4）**：`_parseEdgeTypes` 目前重複判斷 `map is Map` 四次，另有一次 `(map as Map)` 強轉。本票重寫該函式時改為先判型、非 map 即拒收的單一分支。
- **codec 對外介面**：codec 須交出被拒收的邊型名，供 `resolveEdgeTypes` 補回或判定不可用；形狀由實作決定。§1.3 不變：Schema 不 import graph。
- **判定優先序**：版本高於內建時，若同時缺 `edge_types`，照原規則處理，因為沒有條目可拒收。若同時有壞條目與缺正向基數的條目，只回報 `invalidEdgeTypeEntry`：解碼階段的拒收發生在基數補值判定之前（SPEC-007 v1.9，e1 裁決 c5c250999）。
