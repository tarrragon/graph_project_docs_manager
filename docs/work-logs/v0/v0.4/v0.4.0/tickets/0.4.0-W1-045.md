### 修正（2026-09-30，與 SPEC-007 登記同批）

以各 SPEC／UC／EVT 的 `source_proposal`（正向）為準，比對 PROP frontmatter `outputs` 與 `proposals-tracking.yaml`：

| 位置 | 修正前 | 修正後 |
|---|---|---|
| PROP-004 `outputs.spec_refs` | [SPEC-001] | [SPEC-001, SPEC-002, SPEC-003, SPEC-004] |
| PROP-005 `outputs.spec_refs` | [] | [SPEC-006, SPEC-007] |
| tracking PROP-004 `spec_refs` | [SPEC-001] | 同上四份 |
| tracking PROP-005 `spec_refs` | [SPEC-001]（錯誤：SPEC-001 來源為 PROP-004） | [SPEC-006, SPEC-007] |
| tracking `specs:` 清單 | 缺 SPEC-006 | 補 SPEC-006、SPEC-007 |

SPEC-007 為本日新建（0.4.0 建圖規格），一併登記，故 PROP-005 的值多出 SPEC-007，超出 acceptance 原文所列。

**比對後一致**：PROP→SPEC 三份資料一致；`usecase_refs`、`event_refs` 除下列一筆外皆一致。

**未修、交用戶判斷**：PROP-002 `outputs.usecase_refs` 列 UC-01，但 UC-01 的 `source_proposal` 為 PROP-003（PROP-003 的 `outputs` 亦列 UC-01）。依聯集規則，UC-01 會有兩個來源提案並產生一筆 `multiSource`。這筆可能是反向資料過期，也可能 UC-01 確實同時是 PROP-002 的產出（UC-01 含 schema 關卡），屬內容判斷，不由比對腳本決定。
