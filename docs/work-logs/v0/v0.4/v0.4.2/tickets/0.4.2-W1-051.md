## Solution
### 歸屬

- 觸發寫入的是 `ticket_system/tests/test_git_ops.py::TestPrevalidateEndToEnd::test_worktree_protected_branch_violation_blocked_despite_env_project_dir`。票面 where.files 原本列的 `test_create_auto_commit_failure_visible.py` 不是觸發源，它的 hook 是測試自己寫的 sleep 腳本，不是 guard。
- 解析路徑如下：
  1. 該測試刻意把 `CLAUDE_PROJECT_DIR` 設成 tmp repo `primary`。
  2. `guard_world.make_repo` 把 `primary/.claude` 整個 symlink 到真實的 `.claude`。
  3. guard 的 `setup_hook_logging` 經 `get_project_root`（以 `CLAUDE_PROJECT_DIR` 為第一優先）解析到 `primary/.claude/hook-logs`。
  4. 這個路徑穿過 symlink，實際寫進真實的 hook-logs。

### 修復方式（候選 b：fixture 自身隔離）

- `guard_world` 新增 `link_claude`：建立真實的 `.claude` 目錄，裡面逐項 symlink 到真實資產，但排除 `hook-logs`。`make_repo` 與 worktree 情境都改用它，guard 的日誌因此留在 tmp repo 內。
- 候選 (a)（在 conftest 設 `CLAUDE_PROJECT_DIR`）無效，因為該測試會主動覆寫這個變數。
- guard 本體與 `lib.hook_logging` 都沒有修改。
- 新增測試 `test_guard_logs_stay_inside_tmp_repo`。
- ticket skill 升到 2.44.35。實作 commit 92ade5eca（thyme-python-developer，worktree），由 PM 合併。

- PM 審查：新增行的規則 8 grep 結果為 0。
