## Solution
### 修復方式

- `lifecycle.py` 新增 `_find_non_terminal_by_id(ticket_ids, version)`，`_collect_pending_children` 與 `_collect_non_terminal_spawned` 改為共用它。
- 查詢順序：
  1. 用既有的 `extract_version_from_ticket_id` 從 ID 前綴推出版本，以 `load_ticket` 載入。
  2. 載入不到就退回父票版本再試。
  3. 兩處都沒有才記為 not_found。
- 兩個函式的簽名不變。
- ticket skill 版本 2.44.32，SKILL.md 與 CHANGELOG 同步更新。
- 實作 commit 為 bda579a0e（thyme-python-developer，在 worktree 完成），由 PM 合併。
- `test_track_lifecycle.py` 有兩組既有 fixture 原本只 mock `list_tickets`，這次補上 `load_ticket` 的 monkeypatch，讓它從同一份資料取值。測試斷言沒有修改。

### 盤點（執行者）

| 位置 | 是否同型 | 處置 |
|---|---|---|
| `_collect_pending_children`、`_collect_non_terminal_spawned` | 是 | 已修 |
| hooks `acceptance_checkers/children_checker.py` | 否 | 已用 `find_ticket_file` 跨版本找檔，不改 |
| chain 分析、階段前置、next-steps 的 `list_tickets` | 否 | 這幾處是同版本的任務鏈分析，不改 |
| `_post_complete_cascade`（未傳入 `ticket_map` 時）及其他 `list_tickets(version)` 呼叫點 | 疑似，未驗證 | 另開 0.4.2-W1-048（ANA P3）追蹤 |

### 自檢結果

- PM 審查 diff：
  - 跨版本載入沿用既有的 ID→版本推導，沒有新增一套路徑解析。
  - 「不存在」的判定沒有放寬，仍是兩處都載入不到才記 not_found。
  - 舊版本中非終態的票照常回報實際狀態並阻擋，E2 已涵蓋。
- 實地觸發：合併後在 main 對母票 0.4.2-W1-038 執行正常 complete，不帶 --force，rc=0。修正前，同一張票被「0.4.1-W1-038.1: not_found」擋下。

### Phase 4 評估

- 需要重構：否
- 技術債務：已識別、尚未驗證的同型位置由 W1-048 承接
- 程式碼品質：A
- 結論：兩份幾乎相同的實作收斂成一個函式，重複程式碼減少，無需再重構。
