## Problem Analysis
<!-- Schema[IMP/Problem Analysis]: 選填（小型 IMP 可留 placeholder；大型 IMP 建議填寫）（.claude/pm-rules/ticket-body-schema.md） -->
根因：main() 的 Step: Commit Version Activation 於 Step 3 推送之後建立提交，無對應推送；print_summary 寫死「已推送」。修法：publish_activation_commit（HEAD 前進才推送，失敗列未推送 hash、rc=1）；print_summary 新增 activation_pushed。測試 test_finish_activation_commit.py 新增 3 項，修前 3 failed，修後全綠。version-release 2.10.3。

## Solution
### 修復方式

- `version_release.py` 新增 `publish_activation_commit(root, head_before)`：Commit Version Activation 之後，若 HEAD 前進則 `git push origin main`；HEAD 未前進（無啟用提交）視為無需推送。推送失敗時 stderr 輸出 git 原始錯誤、`[ABORT] 啟用提交未推送：<完整 hash> <subject>` 與補救指令，回傳 False。
- `main()` 記錄啟用前 HEAD；dry-run 不推送；推送失敗時摘要後 `return 1`。
- `print_summary` 新增 `activation_pushed`（預設 True，唯一呼叫端為 `main()`），「[DONE] 版本已推送到 main 分支」只在實際推送成功時輸出，否則輸出警告。
- version-release 2.10.3（SKILL.md frontmatter 與 CHANGELOG 同步）。
- 實作 commit 9650f77da（thyme-python-developer，worktree），PM 合併於 main。

### 自檢結果

PM 審查 diff：推送只在 HEAD 前進時發生、dry-run 不觸發、commit_changes 失敗時 HEAD 不前進故不誤推、推送失敗的 hash 由 `head_before..HEAD` 列出而非寫死。推送發生在 exit 前殘留守衛之前，殘留守衛 return 1 時未推送清單已輸出於 stderr，失敗語意不被遮蔽。

已知限制：`main()` 的接線（記錄 head_before、呼叫推送、rc=1）無端到端測試，因 finish 路徑需通過 preflight 與 migrate，不得在 worktree 執行真實 finish（PC-GPD-030）。函式層由 E1 對照覆蓋，接線以 diff 審查加本版 finish 實地驗證承接（版本契約第 3 欄：finish 後比對 HEAD 與 origin/main）。

### Phase 4 評估

- 重構需要：否
- 技術債務：無新增（main() finish 收尾區塊可抽成可單測函式，屬既有結構，非本票引入；本版不另開票，finish 實地驗證已承接接線行為）
- 程式碼品質：A
- 結論：修改集中於單一新函式與兩處接線，邊界條件（無新提交、dry-run、推送失敗）各有明確分支，無需重構。
