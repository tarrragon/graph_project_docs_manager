## Problem Analysis
<!-- Schema[ANA/Problem Analysis]: 必填（.claude/pm-rules/ticket-body-schema.md） -->
### 問題根因
pytest 命令列帶任一路徑即整條忽略 testpaths（TEST-BAL-006）。文字預防（基線留票面、pyproject 加註）依賴執行者記得，同日兩次失效。
再現：(1) W1-020.1 跑 `pytest tests` = 2520，漏 ticket_system/tests（全量 4372），回歸進 main；(2) PM 對 hooks 帶路徑，收進 archived 且漏 ../lib/tests。

### 盤點（uv run --directory <pkg> pytest --collect-only -q，僅收集；2026-10-01 實測）
| pyproject | testpaths | 全量收集 | 常見縮小寫法與數量 |
|---|---|---|---|
| .claude/hooks | tests, ../lib/tests | 5351 | `pytest tests` = 5093（漏 lib 258） |
| .claude/skills/ticket | tests, ticket_system/tests | 4372（另 5 deselected，addopts -m 'not perf'） | `pytest tests` = 2520（漏 1852） |
| .claude/scripts | tests | 單筆，不受影響 | - |
| skills/doc、mermaid-ascii、project-init | tests | 單筆，不受影響 | - |
只有 hooks 與 ticket 兩包有風險。注意收集摘要格式不一：`N tests collected` 與 `N/M tests collected (K deselected)`，任何解析須兩者皆支援。

### 方案比較
| 案 | 機制 | 誤報情境 | 漏報情境 | consumer 可攜性 |
|---|---|---|---|---|
| A PreToolUse(Bash) hook | 解析命令（pytest / uv run pytest / python -m pytest）、定位 pyproject、比對 testpaths | 刻意局部執行（單檔、-k）；跨包命令、wrapper 腳本、cwd 推斷錯誤 | 命令被包在腳本/make；子代理人未載入 hook；解析命令的脆弱性 | 隨 .claude/hooks 同步；邏輯不含專案常數，但需 settings 註冊；consumer 無多筆 testpaths 時靜默 |
| B 零工具：各包單一全套件入口 | 派發範本固定 `uv run --directory <pkg> pytest`（無路徑） | 無（不偵測） | 完全依賴範本被照抄；執行者自行加路徑即失效（W1-020.1 正是此型） | 最高，純文件 |
| C 驗收附 `--collect-only -q` 全量數對照 | 票面 Test Results 要求「passed 數 = 全量收集數 + 差異說明」 | 無 | 事後才發現（complete 前可擋，執行中擋不住）；人工比對 | 高，純 SOP；可由 ticket CLI 欄位化但那是另一支工具 |
| D（新增）包內 conftest 外掛 | `pytest_terminal_summary` 於 config.args 非空且未涵蓋全部 testpaths 時印 WARNING 與未涵蓋清單 | 單檔/`::`/-k 刻意局部（可用「參數含檔案或 :: 時不警告」收斂） | 無（任何呼叫方式皆經 pytest） | 隨該 skill/包同步，不依賴 settings 註冊，所有呼叫端（agent、CI、人）皆生效；hooks 與 ticket 兩包各一份，邏輯可抽共用 |
D 實驗（tmp，雙 testpaths，4 種呼叫）：`pytest tests` 警告 inner/tests；無參數、`.`、同時列兩路徑皆不警告；單檔 `::` 亦警告（需收斂）。陷阱：用 pytest_report_header 時 `-q` 會隱藏，須改 pytest_terminal_summary 驗證（未驗，列入子票驗收）。

### 結論（建議組合 D + C，A 不採）
- A 不採：解析命令字串脆弱、需 settings 註冊才生效（consumer 與子代理人覆蓋不一致），且 PreToolUse 無法便宜取得收集數（全量收集 9-10 秒），只能給靜態提示。
- D 為主：訊號出現在測試輸出本身，覆蓋所有呼叫路徑。
- C 為輔：complete 前的人/CLI 關卡，補 D 看不到的「執行者只貼 passed 數」情形。
- B 併入派發範本修訂（零成本）：範本寫明完整指令不得加路徑。
- 子票以 `ticket create --parent 0.4.1-W1-038` 落地。

### 子票草稿（不自行建票）
1. 標題：hooks 與 ticket 包加入 testpaths 覆蓋警告 conftest 外掛。驗收：(a) 對兩包各以 `pytest tests` 執行時輸出含未涵蓋清單（含 -q）；(b) 無參數、列全部路徑、單檔 `::` 三種不警告；(c) 附 test 以正向對照輸入斷言警告出現（E2）；(d) 全量收集數不變（hooks 5351、ticket 4372，以 --collect-only 對照）；(e) Python 3.9 相容。
2. 標題：ANA/IMP 驗收與派發範本加入全量收集數對照。驗收：(a) agent-dispatch-template 與 ticket Test Results 慣例明列「passed 數對照 `--collect-only -q` 全量數，差異需解釋」及無路徑指令；(b) 格式涵蓋 deselected 摘要；(c) 結論引用 TEST-BAL-006。
3. （選）標題：評估把全量收集對照做成 ticket complete 檢查。驗收：判定可行性與誤報，結論有無皆寫入票面。

### TEST-BAL-006 預防措施補寫草稿（未改檔）
> **工具層**：多筆 testpaths 的包提供 conftest 外掛，命令列路徑未涵蓋全部 testpaths 時於測試輸出尾端警告並列出未涵蓋項；派發範本與驗收一律使用無路徑指令，並附 `--collect-only -q` 全量數對照（注意 `N/M collected (K deselected)` 格式）。
