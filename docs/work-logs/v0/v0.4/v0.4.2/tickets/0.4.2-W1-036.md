### 例外呼叫點盤點

gate 分兩階段，階段決定失敗語意該怎麼選：偵測階段（payload 解析到 touched 判定）對**每個 Bash 呼叫**執行；驗證階段（touched 非空之後）只在 commit 觸及 hooks 目錄時執行。任一階段拋例外，皆由 run_hook_safely 預設（fail_closed=False）回 exit 1；PreToolUse 只有 exit 2 才 deny，故結果為放行，外觀為 stderr 一段 CRITICAL，無 stdout。

關鍵觀察：(a) 例外機率整體極低，但去向全部同形：外觀與測試通過相同，僅 stderr 有 CRITICAL；(b) 驗證階段例外的後果最重，因為此時已確知「有 hook 檔被改」，例外使本該 deny 的紅燈放行（實測 E5）；(c) P5 不經例外卻是同類 fail-open，且只有 warning 日誌，違反 quality-baseline 規則 4；(d) PM 補充的 _log_segment_timing 結論：機率極低，但位於驗證階段的熱路徑，且屬純觀測，不應與驗證結果同命運。

### 盤點補充（PM，W1-035.2 合併時）

- `_log_segment_timing`（W1-035.2 新增）只在讀取 load 時有 try，其餘部分（regex、float 轉換、日誌格式化）沒有。若在其中拋出意外例外，會經 `run_hook_safely` 預設的 fail-open 放行。這裡實際會拋錯的機率很低，但應列入本票的「主流程可拋例外的呼叫點」清單。

### 問題根因

hooks-test-gate 主流程的例外全部由 run_hook_safely 接住，預設 fail_closed=False，最後以 exit 1 結束。PreToolUse 只有在 exit 2 時才會 deny，所以 gate 自己拋例外時，即使已經測出紅燈也會被放行，壞掉的 hook 因此可以進 main（實測 E5 重現）。

### 影響範圍

- 驗證階段（確認觸及 hook 檔之後）：_resolve_test_paths、_run_all_tests、_build_deny_message、emit_hook_output。由 W1-036.1 處理。
- 偵測階段：payload 型別、Path.resolve 例外。由 W1-036.3 處理。
- git diff --cached 失敗時只寫 warning，使用者看不到，staged 清單漏判也不會被察覺。由 W1-036.2 處理。
- 共同語意：run_hook_safely 預設 fail-open，114 支 hook 都受影響。由 0.4.2-W1-052 處理。

### 結論

採方案 B 的收斂形：**以階段為界，驗證階段 fail-closed、偵測階段維持 fail-open**；「逐點」不是每個呼叫點各包一個 try，而是在驗證階段入口設單一邊界，因為驗證階段所有呼叫點的語意相同（無法驗證等於未通過）。另補兩個鄰近缺口（P5 不可見、偵測階段 crash 噪音）。

### 三案比較

| 面向 | A 整體 fail-closed（run_hook_safely fail_closed=True） | B 逐點判 red（本結論取驗證階段邊界） | C 維持現狀 |
|------|------|------|------|
| 紅燈被例外遮蔽（E5） | 擋下 | 擋下（驗證階段） | 放行（已實測） |
| gate 缺陷的爆炸半徑 | **每個 Bash 呼叫**，因偵測階段對所有命令執行；含修復指令（git checkout、編輯後驗證） | 只有觸及 .claude/hooks/*.py 的 commit | 無 |
| 逃生路徑 | 在 Claude Bash 工具內無（所有 Bash 被 deny）；只剩使用者終端機，或 Edit 改 settings 停用 gate | 使用者終端機執行該 commit（gate 只攔 Claude Bash 工具）；deny 訊息明寫此路徑。修 gate 自身的 commit 同樣走此路徑，無死鎖 | 不需要 |
| consumer 可攜性 | 差：consumer 的 Python 版本、符號連結、權限差異造成的 gate 缺陷會使整個 Bash 工具失靈，且修法在上游，須等 sync-pull | 中：缺陷只影響觸及 hooks 的 commit；訊息與逃生路徑為通用語，不含專案識別 | 好但靜默：缺陷存在於每個 consumer 而無人察覺 |
| 誤判代價 | 極高（全面停擺） | 低（單次 commit 改走終端機） | 無誤擋；漏擋代價為壞 hook 進 main |
| 實作面積 | 一個參數，但語意過寬 | 一個邊界 try + 計時日誌隔離 | 0 |

為何不加環境變數 bypass：常設後門會被依賴，且 gate 本意就是不可被 agent 隨手繞過；終端機路徑零新增表面。代價是無終端機的無人值守 subagent 遇此情況須回報 NeedsContext，屬可接受的罕見路徑。

### 附帶決策

- 計時日誌 _log_segment_timing 為純觀測，隔離為 swallow-and-warn，其例外不得把綠燈轉 deny（邊界內若不隔離，B 會讓日誌缺陷擋下正常 commit，比現狀更糟）。
- P5（git diff 失敗）維持放行，但由僅日誌改為使用者可見提醒：git 壞掉時 commit 本就失敗，逾時屬負載尖峰，阻擋會誤擋。
- 偵測階段不改 fail-closed；E1-E4 屬可預期輸入，改為記日誌後 exit 0，去除 hook error 噪音。
