## Solution
### 修復方式

- `test_lease.py` 新增 `_utcnow()` 接縫，每次呼叫都取當下時間。`_fresh_ts` 與 `_stale_ts` 改為使用它。
- 新增 autouse fixture `_refresh_now`，每個測試開始時把 `NOW` 重設為當下時間。原有約 50 處的 `now=NOW` 注入不必修改，種子與真實時鐘的差距只剩單一測試的耗時，不再隨套件總長累積。
- 不採用固定時鐘：`claim_lease` 等入口讀的是真實時鐘，固定時鐘無法與它們對齊。
- STALE 種子仍以 `_STALE_THRESHOLD + _STALE_MARGIN` 推導，門檻沒有放寬。
- ticket skill 升為 2.44.33。實作 commit 09fcedea6（thyme-python-developer，worktree），由 PM 合併。

### 自檢結果

PM 審查 diff：
- E1 測試把 `pm_registry` 與本檔的 `datetime.now` 一起撥快 31 分鐘。修前 `_fresh_ts` 回傳 import 時刻，會被判定為 STALE；修後種子取自撥快後的當下，判定為 FRESH。修前與修後結果不同，測試有鑑別力。
- 另有一個 STALE 對照組，確認時鐘前移後 STALE 種子仍判定為 STALE，修正沒有把所有種子都變成 FRESH。

同型盤點：
- test_track_sessions（高風險）與 test_track_stale_list_in_progress（中風險）尚未實測，另開 0.4.2-W1-050 處理。
- test_track_onboard 與 test_track_conflicts 只把 NOW 當注入基準，風險低。
