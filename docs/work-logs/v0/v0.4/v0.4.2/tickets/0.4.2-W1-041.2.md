## Solution
### 修復方式

- `.claude/skills/ticket/conftest.py` 新增 autouse `_isolate_hook_logs_dir`，把 `HOOK_LOGS_DIR` 指向 tmp，並設 `HOOK_TEST_ISOLATION=1`，兩棵 testpath（`tests/`、`ticket_system/tests/`）共用。
- `ticket_system/tests/conftest.py` 原有一個同名的 autouse，已移除並整合到上述位置，不再重複。
- 新增 `tests/test_hook_logs_isolation.py`，含 2 項測試，修前紅、修後綠。
- ticket skill 版號 2.44.34。實作 commit 25d309ced（thyme-python-developer，worktree），由 PM 合併為 e1c0c735f。
- 產品碼未改，`identity_guard` 的根目錄解析維持原樣。

### 自檢結果

- 規則 8：新測試檔的 docstring 寫有專案 ticket ID。PM 合併後在 10238b1ef 改為描述性文字，對合併範圍的新增行重跑 grep，0 命中。
- 合併過程：第一次 merge 在提交階段遇到短暫的 index.lock，失敗時已 stage 本次合併的 5 個檔案，但沒有 MERGE_HEAD。PM 先確認 index 裡只有這 5 個檔案，以 `git restore --staged --worktree` 還原到 HEAD，再重新合併。過程中沒有動到其他 session 的變更。
- 執行者回報「票 md 在 worktree 內未提交」，經查不成立。票務 CLI 的寫入會導回主倉庫（PC-GPD-030），append-log 已自動提交到 main（6b0e869b9、ca49094cb），worktree 與 main 都是乾淨狀態。

### 驗收第 1 項的殘留

- 修正後，乾淨 clone 與 clone 內的 linked worktree 跑完 ticket 全套件，hook-logs 只多出一項：`git-ref-transaction-content-guard`。
- 這項的機制和本票不同：測試把真實的 guard 安裝到 tmp repo，guard 由 git 以 subprocess 執行，透過 `lib.hook_logging` 解析專案根，而這條路徑不讀 `HOOK_LOGS_DIR`。修前（E1）也存在。
- 已另開 0.4.2-W1-051 處理。

### 實地觸發（PM，main 10238b1ef）

- 在主 repo 跑 ticket 全套件，`CLAUDE_PROJECT_DIR` 未設，時段為 13:22:19 至 13:34:50。
- 這段時間內，真實 `identity-guard/usage.log` 新增 0 筆。修前同一套件會寫 19 行，E1 對照為 82 行。
- 同一時段 hook-logs 其他目錄也有寫入，但那段期間 PM 與其他 session 正在執行真實工具呼叫（ticket create、git push 等），這些目錄不能拿來判斷測試是否洩漏。
