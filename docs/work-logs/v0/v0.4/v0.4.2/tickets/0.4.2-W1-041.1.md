## Solution
### 修復方式

- `.claude/hooks/tests/conftest.py` 新增 `pytest_configure` 與 `pytest_unconfigure`。
  - 在 collection 之前，把 `CLAUDE_PROJECT_DIR` 指向含 CLAUDE.md 的 tmp 目錄，並設 `HOOK_TEST_ISOLATION=1`。
  - 結束時還原這兩個變數，並刪除 tmp 目錄。
  - session fixture `isolate_project_root` 只回傳這個隔離根目錄。
- 新增 opt-out fixture `real_project_root`，給斷言真實專案根的 5 項測試使用（`@pytest.mark.usefixtures("real_project_root")`），斷言內容不改。這 5 項是：
  - test_agent_dispatch_validation_hook：2 項
  - test_branch_verify_cross_repo：2 項
  - test_hook_base_get_project_root：1 項
- 新增契約測試 `test_conftest_session_isolation.py`，共 3 項。
- `isolate_hook_logs` docstring 原本寫「改 CLAUDE_PROJECT_DIR 會大量誤傷」，與實測不符，已改寫。
- 實作 commit：f6bc4bdf4、8f89b6f87、64b491c55（thyme-python-developer，worktree），由 PM 合併。
- 沒有改 hook 本體，也沒有改 hook-exclude-list 或任何 gate 上限。

### 偏離派發做法：改用 pytest_configure

- 派發時指定的是 session fixture。
- 乾淨 clone 第一輪實測，`agent-dispatch-validation/events/events.jsonl` 仍洩漏 9 行。
- 原因：該 hook 在模組層用 `get_project_root()` 計算 `_EVENTS_JSONL_PATH`；測試檔 import 這個模組發生在 collection 階段，早於任何 fixture。
- 因此改在 `pytest_configure` 設定環境變數。產生路徑盤點表見 how.strategy。

### 自檢結果

- 第一輪：PM 審查發現新增行有 4 處專案 ticket ID，違反規則 8，退回修改。
- 第二輪：合併後對 diff 新增行 grep，0 命中。conftest 其他位置的舊 ID 是既有行，不在本次範圍。

### 實地觸發（PM，main 748cfb8df）

- 在主 repo 跑 hooks 全套件，`CLAUDE_PROJECT_DIR` 未設，執行時段 12:52:43 到 12:54:53。
- 這段時間真實 `hook-logs` 只有兩處變動：
  - `_liveness`：2 筆 `subagent-stop-dispatch-cleanup`，是真實的代理人停止事件。
  - `subagent-stop-dispatch-cleanup`：3 個檔案。
- 修正前同一套件會寫入約 20 個目錄、48 行 `_liveness`。這次 askuserquestion-charset-guard、comment-qa 等只有測試會產生的目錄都沒有出現。

### Phase 4 評估

- 需要重構：否
- 技術債務：無新增。session id 前綴與洩漏哨兵由 W1-041.3 承接。
- 程式碼品質：A
- 結論：隔離邏輯集中在 conftest 的設定階段，opt-out 是明確標記，不需要重構。
