## Solution
### 修復方式

git 命令依「本地寫入」與「網路」分兩類（version-release 2.10.4，實作 commit 37a727a76、7657a1e93，thyme-python-developer，PM 合併）：

| 類別 | 命令 | 逾時 | 理由 |
|---|---|---|---|
| 本地寫入 | add、commit、tag -a、checkout main、merge --no-ff、merge --no-edit FETCH_HEAD、branch -d（含經 run_git_with_lock_retry 的呼叫） | `GIT_WRITE_TIMEOUT = None` | 建立或刪除 ref、持有 index／HEAD 鎖，會觸發 reference-transaction hook；被殺會殘留鎖 |
| 網路 | fetch origin main、push origin main（Step 3 與啟用提交）、push origin <tag>、push origin --delete | `GIT_NETWORK_TIMEOUT = 300`，`GIT_TERMINAL_PROMPT=0` | 傳輸期間被殺不留本地鎖；不設逾時時，網路卡住或認證提示會讓 finish 無限期掛住且無輸出 |
| 唯讀 | status、log、describe、branch --show-current、rev-parse --show-toplevel | 不變 | 不寫 ref |

- pull 拆成 fetch（網路逾時）加 merge --no-edit FETCH_HEAD（本地，不設逾時）。保留原 pull 在分歧時產生合併提交的語意，未改 --ff-only。
- `run_git_network` 逾時不拋例外，回傳 rc=124 與可見的 stderr，走既有的失敗中止路徑。逾時後以 `find_git_lock_files` 列出 git 目錄下所有 `*.lock`，逐一印出並附「確認沒有其他 git 程序後再手動刪除」。工具不自動刪鎖，因為鎖可能屬於其他 session 正在進行的寫入（e1 裁決）。

### 自檢結果

PM 審查兩輪：
- 第一輪退回兩項：網路命令也拿掉了逾時；套件耗時從 28.8s 變成 244s 原因未明。e1 追加一項：網路逾時後要報出殘留鎖。
- 第二輪全數處理。

耗時歸因：PM 在相同負載下，以 main（215 tests）與 W1-018（220 tests）交替各跑兩次。
- 第一輪：39.5s 對 35.7s。
- 第二輪：15.5s 對 38.4s。
- main 自身就在 15 到 40s 之間擺盪。W1-018 新增的測試約有 8s 是刻意 sleep（慢速 hook 3 次各 2s、網路逾時 seam 1s）。
- 結論：244s 由機器負載造成（量測時 load average 約 100），沒有測試是靠 10 秒逾時快速失敗的。

已知限制：`find_git_lock_files` 會列出 git 目錄下全部鎖檔，包括其他 session 持有的鎖。訊息已明示「可能屬於其他 session」，這是報告用途，不是歸屬判斷。
