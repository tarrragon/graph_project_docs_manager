## Solution
### 修復方式（方案 a）

- `test_real_pytest_subprocess_writes_ordered_marks` 加上 `@pytest.mark.wallclock`。`.claude/hooks/pyproject.toml` 新增 `addopts = "-m 'not wallclock'"` 並註冊這個 marker，所以主套件預設會排除它。要執行時跑 `uv run pytest -q -rf -m wallclock tests/test_hooks_test_gate_hook.py`，命令列的 `-m` 會覆蓋 addopts 的設定。
- 子程序呼叫抽成 seam `_run_child(cmd, env, cwd, timeout)`。wallclock 套件的逾時上限放寬為 120 秒，用來偵測子程序卡死，逾時就拋 `TimeoutExpired` 判紅，沒有任何 skip 或 pass 分支。
- 新增 `test_real_pytest_hung_child_is_red_not_skipped`（同樣標 wallclock）：注入 `sleep 3600` 的子程序並設 2 秒逾時，斷言會拋 `TimeoutExpired`；同時把 `pytest.skip.Exception` 轉成 `pytest.fail`。
- 計時外掛原本就在主套件中的 in-process 功能斷言不受影響，例如 plugin 載入／未載入、寫入失敗只輸出 stderr。
- 實作 commit ed4ae0b17（thyme-python-developer，worktree），PM 合併。

不採方案 b 的理由：牆鐘上界本身就是負載的函數。拿掉上界，子程序卡死時主套件會無限掛住；保留但放寬，只是把觸發門檻往後推，不可靠的斷言依然存在。

### 自檢結果

- 突變驗證（執行者）：在 seam 加入 `except TimeoutExpired: pytest.skip` 後，初版 E2 只變成 skip，沒有抓到；補上 skip→fail 轉換後，突變版 E2 變紅。突變已還原，不在提交內容中。這個結果證明 e1 禁止的「逾時改 skip」確實會被 E2 攔下。
- PM 審查：新增行的規則 8 grep 結果為 0。審查時發現 wallclock 標記被預設排除後，目前沒有固定的執行點，已建 0.4.2-W1-059（P3）承接。

### 實地觸發（PM，main 309020b9b）

- 預設套件：collect 5398/5400（2 deselected），結果 5350 passed、48 skipped、2 deselected。
- `-m wallclock`：在 load1 約 29.6 下 2 passed、57 deselected，耗時 36.34s。

### Phase 4 評估

- 重構需要：否
- 技術債務：wallclock 的執行點由 W1-059 承接
- 程式碼品質：A
- 結論：改動限於測試與 pytest 設定，seam 抽取很單純，不需要重構。
