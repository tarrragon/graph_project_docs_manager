## Solution
### 結論：實測不紅，無需修改

依 e1 裁決（先實測，實測為紅才列為 finish 必要並修正）跑了 AC1，兩個檔都是綠的，因此不修改，也不設 scope_blocker。

| 檔案 | 時鐘前移 211 分鐘後 | 原因 |
|---|---|---|
| ticket_system/tests/test_track_sessions.py | 16 passed | 判定入口全部注入 `_now=NOW`，`_build_rows` 也用 `now=NOW`，種子與判定共用同一個基準 |
| ticket_system/tests/test_track_stale_list_in_progress.py | 9 passed | 同上 |

實驗方法：
- 用暫時性 pytest plugin（放在 scratchpad，不進 repo）把 `ticket_system.*`、`pm_registry` 與測試模組的 `datetime.now` 撥快 211 分鐘，超過 STALE_THRESHOLD_MINUTES 與 STALE_IN_PROGRESS_HOURS。模組層 `NOW` 維持 import 時刻的值。
- 正向對照：另寫一個暫時測試，斷言模組層 `NOW` 與 `datetime.now` 的差距大於 1800 秒，在同一個 plugin 下通過，證明前移確實生效（E2 型對照）。

與 W1-049 的差別：test_lease 的 `claim_lease` 等入口讀的是真實時鐘，種子卻是 import 時刻，兩邊基準不一致才會誤判。本票兩個檔的入口全部改由注入的 NOW 判定，兩邊基準一致，所以不會誤判。

### 自檢結果

PM 核對報告：檔案路徑落在 ticket_system/tests（票面 where.files 寫的是 tests/，屬路徑誤記，不影響結論）。正向對照證明這個實驗確實能偵測到時間差，「綠」不是因為前移沒生效而產生的假陰性。

AC2 的前提「實測為紅者」不成立，所以 AC2 無適用對象。AC3 以 main 現值的全套件結果承接：本票沒有修改，最近一次在 main 10238b1ef 執行為 4437 passed。
