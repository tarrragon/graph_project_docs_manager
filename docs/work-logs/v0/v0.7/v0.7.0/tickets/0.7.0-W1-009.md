## 重現實驗結果
### 實驗紀錄（L53，2026-11-09）

**方法**：讀現行實作 `lib/screens/preferences/preferences_panel.dart` 的 `_choose`，以及 `lib/workspace/editor_preference.dart` 的 `EditorPreferenceStore.write`；對照 SPEC-003 v1.83 §3.8、§4 第 47、48 列與 SPEC-001 v1.80 §9。用戶實機回饋來源為 0.6.0-W1-170。

**執行**：
- `_choose(editorId)`：`setState(() => _chosenId = editorId)` 後呼叫 `write(editorId)`。不關閉面板、不顯示提示，也不比對持久化值，點選相同值也會寫入。
- `EditorPreferenceStore.write` 回傳 `Future<void>`；失敗時只記 level 900 日誌、不拋出，呼叫端無從得知成敗。
- SPEC-003 v1.83 §3.8 寫「不顯示 SnackBar（選取標示即結果，§2.13 判準 T2）」；§4 第 47 列與 SPEC-001 §9 退出路徑都寫「點選後留在本狀態」。實作與規格一致，缺口在規格。

**發現**：
- 已驗證：選後無回饋是規格明定的行為。根因是 T2 把「選取標示改變」算成「狀態轉換即結果」，但效果要到下次開啟原始檔才出現，當下畫面看不到；0.7.0-W1-008 的分析成立。
- 已驗證：新增「已改用」提示後，寫入失敗時若照常提示，就會告知一件沒發生的事。現行 `write` 不回報成敗，實作必須改介面。
- 裁決未涵蓋：點選與持久化值相同的選項時是否提示。比照 FilterDropdown「選取值相同 → 收合回原態」，定為只關閉、不提示（PM 處置，待用戶覆核）。

## Solution
<!-- Schema[ANA/Solution]: 必填（.claude/pm-rules/ticket-body-schema.md） -->
### 結論（L53，2026-11-09）

採用 0.7.0-W1-008 的用戶裁決，偏好設定面板選取即關閉並提示。規格落地在 `b63f918604`：

| 規格 | 改動 |
|------|------|
| SPEC-003 v1.84 §3.8 編輯器選項列 | 以點選值與持久化值比對來分流：不同且寫入成功 → 面板消失，顯示 `preferencesEditorAppliedMessage`（`AppSnackBar.plain`，「已改用 {editor}，下次開啟原始檔時生效」）；寫入失敗 → 只關閉；相同 → 只關閉、不寫入 |
| SPEC-003 §2.13 對照表列 20 | T1 是、T2 否、T3 否、T4 否 → `plain` |
| SPEC-003 §2.14 指派表列 21 | 等待型、可棄，標定點為寫入呼叫發出當下 |
| SPEC-003 §4 第 47、48 列 | 出口改為面板消失 |
| SPEC-001 v1.81 §9 | 兩列退出路徑；離開方式改為點選選項與關閉面板兩種 |

**PM 處置，待用戶覆核**：寫入失敗、點選相同值兩個分支都只關閉、不提示。理由是提示不能告知一件沒發生的事。

**與 SPEC-004 的對齊**：與 v1.129 4.40〈套用時點〉偏好設定欄一致，008.1 文字審查列為高嚴重度的不一致已消除。
