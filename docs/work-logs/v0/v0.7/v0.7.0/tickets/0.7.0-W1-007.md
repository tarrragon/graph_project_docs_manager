## Problem Analysis
<!-- Schema[ANA/Problem Analysis]: 必填（.claude/pm-rules/ticket-body-schema.md） -->
### 事實盤點（L53，2026-11-09）

- **設定入口**：只有 macOS 選單列一處（`macos/Runner/Base.lproj/MainMenu.xib` 的 `Preferences…`，keyEquivalent `,`）。經 `AppDelegate.openPreferences` → MethodChannel `openPreferences` → `lib/assembly/shell.dart` 開啟面板。主視窗內沒有任何可點的入口。
- **選單在地化**：`MainMenu.xib` 共 61 個 `menuItem`，全是 Flutter macOS 範本的英文標題；`macos/Runner/` 下只有 `Base.lproj`，沒有其他 `.lproj`。SPEC-001 §9 與 SPEC-003 §3.8 寫入口是「偏好設定…」，與實作不一致。不一致的範圍是整份選單，不只 Preferences…。
- **App 自身的鍵盤操作**（`lib/` 的 `SingleActivator` 與 SPEC-003 §2.10）：⌘,（開啟偏好設定）；Esc（收合浮層、篩選選單、schema 詳情面板，清除矩陣選格，關閉偏好設定面板）；Tab／Shift+Tab（三區段焦點順序）；Enter／Space（啟動已聚焦的元件）；↓（展開篩選選單）；↑／↓／Home／End（在篩選選項間移動）。選單中的 ⌘Q、⌘H、⌘M、⌘F 等是範本的系統項，是否在本 App 有作用未逐一實測。

### 框架問題判定（驗收第 5 項）

- **判準一（抽象可攜）**：成立。「功能只能靠快捷鍵或選單列到達，畫面上沒有可見入口」換掉專案名稱與路徑後仍成立，任何桌面 App 都可能出現。
- **判準二（根源在 `.claude/` 通用資產）**：成立。`ux-design-evaluation` 的 `references/navigation-patterns.md` 只有行動裝置的模式（push/pop、router、tab、drawer、deep link），沒有桌面選單列與快捷鍵可達性的檢查；本專案依該 skill 評估 §9 時無從發現此缺口。
