### 現況（2026-11-10，main 29dc173072 之後）
- `lib/screens/history/history_event_list.dart` 的 `HistoryEventList.build` 回傳 `Panel.scrollable(key: ValueKey(filterKey), scrollKey: scroll-history-events, children: [表頭, 所有列])`，所有列一次建構完。
- 呼叫端只有 `history_screen.dart` 的 `_ResultView`（git grep 確認），放在 `Column` → `Expanded` 裡。
- `AppDataTable`（`lib/components/app_data_table.dart`）的 virtual 變體：表頭固定在頂部，列交給 `ListView.builder` 建構，`itemExtent` 為 `LayoutSize.rowHeightRelaxed`。`AppTableRow.historyEvent` 的列高也是 `rowHeightRelaxed`，兩者一致。範本是 `ticket_list_screen.dart` 的 `fill: AppDataTable(variant: virtual, ...)`。
- 會用到列錨點或捲動錨點的測試：history_event_row_test、history_jump_test、history_filter_test（以 scroll-history-events 為祖先查找），以及 integration_test/uc07_history_test（只點第 0 列）。

### 範圍
- 只改事件清單的承載方式：從 Panel.scrollable 全量建構，改為 AppDataTable 虛擬捲動。
- 篩選改變時捲動歸零：保留現行做法，以 key 重建，或改由頁面層持有 ScrollController 並重設。兩種擇一。
- SPEC-004 §10 正常列的其他組合差異（例如淺層徽章與篩選列是否放在 Panel.default 內）不在本票範圍。實作時若發現，寫進 Solution，由 PM 另行建票。
- 不改 SPEC 與元件。如果 AppDataTable 不能滿足需求（例如需要 historyEvent 以外的列型別），停手並回報。
