## Problem Analysis
<!-- Schema[ANA/Problem Analysis]: 必填（.claude/pm-rules/ticket-body-schema.md） -->
### 主控初步分析（2026-11-09，待基本率核對後定案）

**現行判準怎麼得出「不顯示提示」**：step-3-fill-contract.md〈回饋契約的填寫順序〉關卡二第 2 問是「事件是否已在該可見畫面上產生可見的狀態轉換？答是 → 不用暫態提示，狀態轉換本身即結果」。SPEC-003 §3.8 據此（§2.13 判準 T2）判定偏好設定面板不顯示 SnackBar，因為選取標示改變就算可見的狀態轉換。

**用戶實機遇到的落差**：選取標示只回答「選了哪一個」，沒有回答兩件事：
- 是否已經生效、已經儲存
- 現在可不可以關掉

這個設定的效果要到下次開檔才出現，當下畫面看不到。

**假設的缺口**：「選取態改變」與「選取已提交且生效」是兩件事，第 2 問把兩者當成同一件。選擇類元件在進回饋契約之前，應先回答兩題：
1. 套用時點：選取是立即提交，還是等確認後才提交？
2. 生效是否當下可見：提交後的效果在當下畫面看得到嗎？

**候選結局**（待基本率決定各自的觸發條件）：
- 確認按鈕：適用於後果大或難以復原、多個欄位要一起設定、需要預覽或比較後才決定。
- 立即套用加提示：效果不在當下畫面時，提示寫明生效範圍，例如「下次開啟原始檔時生效」。
- 自動關閉加提示：單一選擇、選完就沒有其他可做的事。

**基本率**：背景代理人正在查 macOS HIG、Material、Windows 的原文，結果回來後補進本票再定案。

**各來源用來決定的條件**：
1. 容器是 modeless 或 modal
2. 多個欄位是否必須同時套用
3. 套用是否耗時（約 1 到 2 秒）
4. 是否需要先預覽或評估
5. 可逆性與後果（能復原時，優先提供復原而不是確認）
6. 單選或多選（決定是否自動關閉）
7. 所在容器本身是否需儲存（不混用兩種模式）
8. 使用者意圖
9. 是設定還是動作

## Solution
<!-- Schema[ANA/Solution]: 必填（.claude/pm-rules/ticket-body-schema.md） -->
### 判準草案（主控，2026-11-09，待用戶確認）

選擇類元件（選項清單、單選、下拉、選單、選擇器）在填回饋契約之前，依序回答下列四問。四問的答案寫進元件契約的新欄位「套用時點」。

| # | 問句 | 結論 | 依據 |
|---|------|------|------|
| 1 | 是設定還是動作：選取會不會執行命令或開新視窗？ | 會 → 這不是選擇類元件，改用按鈕 | Win32 Radio／Drop-down、NN/g |
| 2 | 套用時點：以下任一成立嗎？(a) 多個欄位必須同時套用；(b) 套用約超過 1 秒；(c) 使用者要先預覽或比較才決定；(d) 難以復原或後果重大；(e) 所在容器本身是需要儲存的表單 | 任一成立 → 延後提交，要有確認按鈕，並配「取消」。(d) 若能提供復原，優先用「立即套用＋復原」，不用確認。全不成立 → 立即提交（預設） | GNOME 2/3、Win32、Apple 2015、M2/M3、WinUI、NN/g |
| 3 | 容器何時關閉（只在立即提交時問）：容器裡是否只有這一個單選，選完就沒有其他可做的事？ | 是 → 選取即關閉。否（多選或還有其他設定）→ 保持開啟，關閉鈕叫「關閉」或「完成」，不叫「取消」，用名稱表示已經生效 | Apple Popovers、M2 simple dialog、Win32 Cancel 改名 Close |
| 4 | 生效是否當下可見：提交後的效果，有沒有出現在使用者當下看得到的畫面上？ | 有 → 狀態轉換即結果，照現行關卡二第 2 問。沒有（效果在別處或之後才出現，畫面上只有選取標示改變）→ 選取標示不算「已生效」，要告知「已套用」與生效範圍。容器關閉時用暫態提示，例如「已改用 X，下次開啟原始檔時生效」；容器不關時在選項旁顯示「已儲存」 | NN/g「要讓使用者看到結果」、Apple Feedback（完成確認只留給重要的動作；效果看不到時這則提示才是資訊，不算干擾） |

**對現行 skill 的修改點**：
- 在 step-3-fill-contract.md 的元件契約欄位表新增「套用時點」欄，只適用選擇類元件，內容即上表四問。
- 關卡二第 2 問補一句：「選取標示的改變只說明選了哪一個；只有提交的效果本身出現在可見畫面上，才算狀態轉換即結果。」

**與 SPEC-003 §2.13 的分工**：本判準決定何時提交、何時關閉、要不要告知生效。§2.13 只決定告知時用哪一種載體。

**套用到偏好設定面板（供 0.7.0-W1-009 參考）**：面板目前只有編輯器一項單選，效果要到下次開檔才出現。第 2 問全不成立，所以立即提交。第 3 問答是，所以選取即關閉。第 4 問答「沒有」，所以要提示「已改用 X，下次開啟原始檔時生效」。之後面板若加入其他設定，第 3 問改答否，改為面板保持開啟、選項旁顯示「已儲存」、關閉鈕叫「完成」。

### 用戶裁決（2026-11-09，AUQ）

- 判準的形式：在元件契約欄位表新增「套用時點」欄，只適用選擇類元件，內容即判準草案的四問。同時在關卡二第 2 問補一句：「選取標示的改變只說明選了哪一個；只有提交的效果本身出現在可見畫面上，才算狀態轉換即結果。」
