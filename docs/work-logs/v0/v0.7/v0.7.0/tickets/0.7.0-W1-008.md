## Problem Analysis
<!-- Schema[ANA/Problem Analysis]: 必填（.claude/pm-rules/ticket-body-schema.md） -->
### 主控初步分析（2026-11-09，待基本率核對後定案）

**現行判準怎麼得出「不顯示提示」**：step-3-fill-contract.md〈回饋契約的填寫順序〉關卡二第 2 問是「事件是否已在該可見畫面上產生可見的狀態轉換？答是 → 不用暫態提示，狀態轉換本身即結果」。SPEC-003 §3.8 據此（§2.13 判準 T2）判定偏好設定面板不顯示 SnackBar，因為選取標示改變就算可見的狀態轉換。

**用戶實機遇到的落差**：選取標示只回答「選了哪一個」，沒有回答兩件事：
- 是否已經生效、已經儲存
- 現在可不可以關掉

這個設定的效果要到下次開檔才出現，當下畫面看不到。

**假設的缺口**：「選取態改變」與「選取已提交且生效」是兩件事，第 2 問把兩者當成同一件。選擇類元件在進回饋契約之前，應先回答兩題：
1. 套用時點：選取是立即提交，還是等確認後才提交？
2. 生效是否當下可見：提交後的效果在當下畫面看得到嗎？

**候選結局**（待基本率決定各自的觸發條件）：
- 確認按鈕：適用於後果大或難以復原、多個欄位要一起設定、需要預覽或比較後才決定。
- 立即套用加提示：效果不在當下畫面時，提示寫明生效範圍，例如「下次開啟原始檔時生效」。
- 自動關閉加提示：單一選擇、選完就沒有其他可做的事。

**基本率**：背景代理人正在查 macOS HIG、Material、Windows 的原文，結果回來後補進本票再定案。
