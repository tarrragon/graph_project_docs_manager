## Problem Analysis
<!-- Schema[IMP/Problem Analysis]: 選填（小型 IMP 可留 placeholder；大型 IMP 建議填寫）（.claude/pm-rules/ticket-body-schema.md） -->
實機觀測（L52，2026-11-10，量測環境：作者本機 macOS，main 5f4a2cfa5d 之後的 debug build，以 vm_log 收 developer.log）：
- 本 repo：preflightResult 為 ready（git 2.50.1）。scanFinished 為 commitCount 26761、outputBytes 96261382。scanParseReported 為 eventCount 0、desyncs 0、yamlParses 18508、filesWithoutId 6。
- App 啟動約 35 秒後再按重新整理，第二次掃描（commitCount 26762）eventCount 仍為 0。所以「builtinTrackingSchemaJsonProvider 第一次 read 時尚未載入完成」這個推測不足以解釋，或者不是唯一原因。
- 淺層 clone（scratchpad 內 --depth 200，586 commit）eventCount 同樣為 0。
- yamlParses 有一萬多次，表示 frontmatter 有被解析。疑點在事件建構器的使用中邊型清單或宣告抽取：lib/app/history_providers.dart 的 _newBuilder 取 `ref.read(builtinTrackingSchemaJsonProvider).value`，再以實際型別表宣告的邊型限縮。
- 整合測試 uc07_history_test 以測試輸入覆寫 historyScanInputsProvider（012.12 Solution〈偏離與注意〉第 2 點），因此沒有走過這條接線。

根因（incident-responder 唯讀分析，PM 已讀碼確認，2026-11-10）：
- lib/app/history_providers.dart 的 _newBuilder 以 `resolveEdgeTypes(projectSchemaJson: null, builtinSchemaJson: builtin)` 決議使用中邊型。
- 在 resolveEdgeTypes（lib/schema/edge_type.dart）裡，schemaVersionOf(null) 為 null，classifySchemaVersion 遇到 null 時回傳 Unreadable，因此 inRange 為 false。
- project == null 且 !inRange 時，回傳 edgeTypes 空表（projectVersionOutOfKnownRange）。
- activeEdgeTypes 因此恆為空，DeclarationExtractor 對每份 frontmatter 都得到空宣告，eventCount 恆為 0。這與內建表是否已載入無關。
- 證據等級：控制流為讀碼推論（純函式，分支無歧義）；內建表 asset 確實含 19 個 edge_types，為唯讀實測。
- 現有測試沒抓到的原因：
  - uc07_history_test 覆寫了 historyScanInputsProvider，_newBuilder 未被執行。
  - history_wiring_test 的 WR-1～WR-5 沒有斷言事件數，事件為 0 與有事件在這些斷言下結果相同（違反 E2）。
  - test/unit/history/events 直接以手工邊型建構抽取器。
- 次要問題：`ref.read(builtinTrackingSchemaJsonProvider).value` 在 AsyncLoading 時同樣得到空清單，而且沒有日誌（違反可觀測性規則 1）。gap_report_provider 的 _nonDomainPathsKeyOf 也有同樣的 `.value` 寫法，但不影響本票，由 012.14 Phase 4 彙整處置。

PM 定的修法（方向 a，符合 SPEC-008「使用中邊型取實際型別表」）：
- 讓 History 使用與建圖同一份決議結果，不另外以 null 呼叫 resolveEdgeTypes。
- 在 ScanRoundResult（lib/app/scan_round.dart）新增欄位，保存本輪建圖用的 EdgeTypeResolution，或建圖時的專案型別表 JSON，二擇一，由實作者依現有資料流判斷並在 Solution 說明理由。
- 新欄位設為可選或附預設值，不改 4 個既有建構 ScanRoundResult 的測試檔（已列為 ::read）。若無法避免，就停手回報。
- _newBuilder 改用本輪決議結果；再以實際型別表宣告的邊型限縮，這部分維持原樣。
- 降級時（以內建表當專案表），使用同一份降級決議結果。
- 使用中邊型為空時，以 developer.log 記 warning，內容含原因碼與元件名。
- 測試：在 test/widget/app/history_wiring_test.dart 新增一案，走真實 app root。只以 fake historyProcessRunnerProvider 回放含 blockedBy 增刪的合成 git log，不覆寫 historyScanInputsProvider 與 builtinTrackingSchemaJsonProvider，斷言事件數大於 0。修正前先實跑並貼紅燈輸出。
