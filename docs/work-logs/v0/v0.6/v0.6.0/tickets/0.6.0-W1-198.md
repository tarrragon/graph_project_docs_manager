## Problem Analysis
### 問題根因

193.2 只對部分 widget 改用 select；五處仍 watch 整個值（_ReadyListView、_ReadyTopicView、DomainViewScreen 頂層、_MatrixBody、domainSwimlaneProvider），理由「用到大部分欄位」未逐欄核對。裁決 A：五處全部要改。

### 影響範圍

- `lib/screens/ticket_list/ticket_list_screen.dart`：_ReadyListView、_ReadyTopicView
- `lib/screens/domain_view/domain_view_screen.dart`：DomainViewScreen 頂層、_MatrixBody
- `lib/screens/domain_view/domain_view_providers.dart`：domainSwimlaneProvider

### 修改順序（依 193.3 Profiler 數據，只決定順序）

1. _ReadyListView（2584 列排序首幀 BUILD 37.2ms，與整值 watch 的重建範圍相關，未驗證）
2. _ReadyTopicView（同畫面同型）
3. DomainViewScreen 頂層
4. _MatrixBody
5. domainSwimlaneProvider

3–5 未量測。修改後的效果由 0.6.0-W1-193.3.1 以 `integration_test/perf/ticket_list_perf_test.dart` 重量測，本票不跑 drive。

### 相關 Error Pattern

PC-SCLK-008 反方向：不得依數據自行縮小範圍；若某處改了反而需要讀更多欄位（select 回傳整個值等於沒改），停手回報。

## Solution
<!-- Schema[IMP/Solution]: 選填（.claude/pm-rules/ticket-body-schema.md） -->
五處改為 select，逐處欄位：
1. _ReadyListView：record(tickets, searchQuery, statusFilter, priorityFilter, sortKey, sortOrder, targetTicketId, targetFiltersAutoCleared, targetNotFoundNotified)；未用 mode、expandedTopics、noTopicFilesNotice。
2. _ReadyTopicView：record(tickets, expandedTopics, targetTicketId, noTopicFilesNotice)；toggle 改以 ref.read 目前值為基底。
3. DomainViewScreen 頂層：select(s is DomainReady ? null : s)，Ready 內部欄位不重建頂層；_ReadyBody 改 select mode，不再接 state 參數。
4. _MatrixBody：select record(selectedDomainId, selectedCell)；寫回以 ref.read 為基底；_CellDetailPanel 移除 state 參數，tap 時讀目前值。domainMatrixProvider 的 watch 保留（rows/columns 逐欄渲染，select 回傳整值等於沒改，且該值僅隨輪次變）。
5. domainSwimlaneProvider：lastCompletedRoundProvider.select -> record(event, failedEvents)。
附帶：_SwimlaneBody 為讓 _ReadyBody 不持有整個 state，改自行 select record(selectedDomainId, swimlaneFocus.column)（同檔，在 where.files 內）。

### 自檢結果與 Phase 4 評估

重構需要：否；技術債務：無；程式碼品質：A；record 內 tickets 為 List 參考相等，copyWith 保留同一 list 時視為未變。
