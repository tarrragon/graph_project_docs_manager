## Context Bundle

證據來源：0.6.0-W1-141 Solution（根因與「ready 在 fseventsd 卡住時仍會完成」的觀測）、0.6.0-W1-140 Problem Analysis（卡住期間與重啟後的對照）。
已知事實：
- fseventsd 卡住期間，DirectoryWatcher.ready 正常完成，watch started 之後首輪照常開始，但之後完全沒有即時事件，App 端沒有任何訊號。
- FR-11 規則 10 的就緒逾時（5 s）與串流錯誤都不會觸發。
- B10 已在 DirectoryWatchSource、_onChange、去抖送出三處加 log（目前 level 500），可作為存活判斷的觀測點。
- 恢復手段只有用戶手動執行 sudo killall fseventsd，App 無法自行修復，所以「偵測到之後要怎麼呈現給使用者」是這張票的核心。
- 相關裁定：W6 規定監看失敗時畫面不顯示「自動更新已停止」，只留 warning。存活檢查若要在畫面上提示，等於變更 W6，須用戶重新裁定。
