## Problem Analysis
### PM 派發前前提核對與盤點（2026-11-04，L50）

| 項目 | 實測 | 判定 |
|------|------|------|
| star-anise 的 tools 沒有 zhtw | `.claude/agents/` 下 tools 含 Write／Edit 的 14 個定義檔（含範本 language-agent-template），全部沒有 `mcp__zhtw-mcp__zhtw`；全專案只有 basil-writing-critic（唯讀審查）有這個工具 | 成立，而且不限 star-anise |
| 派發模板有沒有提到 zhtw | `agent-dispatch-template.md`、`pm-rules/`：0 命中 | 模板沒有約定 |
| 有沒有不經 MCP 的執行管道 | `zhtw-mcp lint <path>` 可以直接在 Bash 執行（實測對 `docs/spec/corpus/domain-map.md` 輸出 13 issue，帶行號、類別與建議）；**有 issue 時 rc 仍為 0**，判定結果要讀 `N issue(s) found` 這一行，不能看結束碼 | 有 Bash 的代理人都能跑 |
| where.files | 只列 018.1 票檔，不是要修改的對象；落地檔案應為 `.claude/references/agent-dispatch-template.md` | 失準，落地時改列 |

根因：派發 prompt 要求的檢查依賴 MCP 工具，接收方工具清單沒有這個工具時，檢查不會報錯，只是沒有執行。同型問題已在 125（hook 類票的盤點格式沒有傳到代理人，#92）出現過：派發 prompt 的要求和代理人的能力之間沒有核對。

### 相關 Error Pattern

PC-112（代理人工具清單限制導致自行停手）同屬「工具清單與任務要求不一致」，但方向相反：這次是檢查默默不做，不是停手。

### 框架問題兩條 AND 判準（curator 逐條套用，2026-11-04）

| 判準 | 套用 | 判定 |
|------|------|------|
| 抽象可攜性 | 替換專案名與路徑後：「派發 prompt 要求的檢查依賴某 MCP 工具，接收代理人的 tools 欄沒有該工具時，檢查不報錯、只是不執行；派發模板未約定替代管道」。不依賴本專案任何檔案或領域 | 成立 |
| 資產範圍 | 根源在 `.claude/agents/*.md` 的 tools 欄（14 個可寫代理人皆無 zhtw 工具）與 `.claude/references/agent-dispatch-template.md`（0 命中 zhtw 約定），皆為通用資產；修改點為後者 | 成立 |

結論：兩條皆成立，屬框架問題，進入 dedup。
## Solution
### 決定：不補工具，改派發模板（PM 裁決，2026-11-04）

| 方案 | 利 | 弊 | 裁定 |
|------|----|----|------|
| A 給會改規格的代理人補 `mcp__zhtw-mcp__zhtw` | 代理人可以直接呼叫 | 要改 14 個定義檔；`.claude/agents` 會 sync 到所有 consumer，沒裝 zhtw-mcp server 的 consumer 拿到的是失效工具名；新代理人仍會漏 | 不採 |
| B 派發模板約定以 Bash 跑 `zhtw-mcp lint <path>`，用 `N issue(s) found` 判定 | 不改任何代理人定義；有 Bash 的代理人都能用；CLI 可用性已有 SessionStart hook 檢查 | 結束碼不反映結果，必須讀輸出行；模板需寫明這一點 | **採用** |
| C 模板註明由 PM 在合併前補跑 | 不依賴代理人 | 每次都佔 PM，而且要等到合併前才發現問題 | 不採；只作為代理人沒有 Bash 時的退路 |
