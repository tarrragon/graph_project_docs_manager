## Problem Analysis
### 問題根因

用戶待辦（U1）的配對狀態只在看板一處可見，而且只在寫入時可被糾正。三個缺口都源自同一點：寫入端、主控每輪讀的檢視端、結案端，都不讀配對狀態。

1. 寫入端：主控記錄裁定時寫的是「主控查證」段，與完成行是兩種書寫形態；寫入協調票時，`coordination-queue-line-check-hook.py` 只檢查現行佇列行（docstring 三項檢查皆為 LANE_LINE），不看 U1。寫了前者，不會被提醒後者。
2. 檢視端：`line-board/hooks/lineStatus.ts` 以 `readLaneLines` 讀協調票，只取佇列行，不取 `parseUserTodos`；`continuity.ts` `formatLineStatus` 的「等用戶」段只列 `lanesWaiting`（U2：S1/S2/S3）。主控每輪呼叫 line_status，看不到 U1。看板走 `readLanes`，有 todos，所以兩邊不一致。
3. 結案端：`.claude/hooks/`、`.claude/skills/ticket/hooks/`、`ticket_system/` 都沒有讀「用戶待辦」的程式（grep 無命中），協調票 complete 不檢查 U1。

### 影響範圍

- 已驗證：349 的 307 完成行已在 2026-11-02 補寫（第 3752 行），目前 349 沒有未配對的待辦。099 現有 2 項未配對：`L48-compact執行`、`L51-關閉session`（以 userTodos.ts 規則的 Python 等價實作計算，fence 內與 Solution 段外的行不算）。這兩項是否已實際完成未查證；line_status 不會列出它們。
- 受影響檔案：`line-board/hooks/lineStatus.ts`、`continuity.ts`、`userTodos.ts`（規則權威）、`coordination-queue-line-check-hook.py`、`acceptance-gate-hook.py`、`multi-session-orchestration/references/line-continuity.md` §2〈用戶待辦〉。

規則已寫在 line-continuity.md §2〈列入時機〉（「主控在同一輪寫完成行」），但仍漏寫，屬 opinionated-default 主張 1：文件規範與工具預設不一致時，工具會贏。不另建 error-pattern。
