### 實作

- `hooks/lanes.ts` 新增 `isQueueWithoutTicket(tokens: readonly QueueToken[])`：沒有 ticket token 且有 text token 時為 true。看板與 line_status 共用，定義只有這一份。
- `hooks/continuity.ts` 的 `liveLaneStale` 改呼叫 `isQueueWithoutTicket`（原為內聯的 `ids.length === 0 && tokens.some(kind === text)`，語意相同）；no-ticket 過期項的 detail 由「看板該線只剩線標題」改為「看板該線只剩標了［佇列無票號］的線標題」，與新行為一致。
- `hooks/lanesView.tsx` 新增匯出常數 `QUEUE_NO_TICKET_LABEL = ［佇列無票號］`；`groupTitle` 在 `［狀態］` 之後、context 標記之前接上。`isQueueWithoutTicket` 經 `./parse` 匯入（沿用檔案慣例）。`layout.ts` 未改。
- `references/board-screens.md`：〈版面〉的線群組標題格式加 `[［佇列無票號］]` 與說明段；〈協調票現行佇列行的格式〉的佇列無票號條目同步改寫。
- 版號 0.12.0 → 0.12.1（`CHANGELOG.md`、`SKILL.md` metadata.version）。

### 失敗語意

- 觸發條件：協調票某條線的最後一行現行佇列行，票序經 `parseQueue` 後沒有任何票號 token、且至少有一個文字 token（如 `（結束了）`、`等主控通知`）。結果：看板該線標題列顯示 `［佇列無票號］`，line_status 同時列過期項「佇列無票號」；兩者由同一函式判定，不會一端有一端無。
- 觸發條件：票序含任何票號（含票號夾說明文字、W 寫法、完整票號）。結果：不標示、不列過期項。
- 觸發條件：收線附說明寫法（`無（…）`、`（無）— 說明`）。結果：看板仍顯示該線且標 `［佇列無票號］`（票序確實不含票號）；line_status 列為「收線寫法」而非 no-ticket，因 lineStatusReport 對收線寫法先行分流。此差異已寫入 board-screens.md，屬 PM 派發前前提核對所述「with-note 不屬本票範圍」的既有分流，未改。
- 判定為純函式，無 I/O、無例外路徑；標示失效的唯一方式是判定函式本身錯誤，由 lanes.test.ts 與 board.test.ts 的 E1/E2 對照覆蓋。
