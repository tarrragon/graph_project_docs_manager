## Solution
<!-- Schema[DOC/Solution]: 免填（DOC 類型以變更摘要取代）（.claude/pm-rules/ticket-body-schema.md） -->
**判定：不是漏填，`source_specs: []` 維持不動。**

**判準**：其他 bundle 填的 `source_specs`，都是「有 FR 的驗收對象落在本 bundle 公開面」的 spec。各 bundle 的 FR 歸屬見各 domain map §7，以及 `docs/system-layer.md` §8〈FR → Bundle 覆蓋對照〉。例外是 workspace：它的 domain spec SPEC-005 雖無 FR 編號，仍列入。

| 來源 | 結果 |
|------|------|
| SPEC-006、SPEC-007 | layout domain map §7 明載「無 FR 歸屬」 |
| SPEC-001 | 功能需求只有 FR-01～FR-08，system-layer §8 SPEC-001 表中沒有任何一列的 Bundle 欄是 Layout |
| SPEC-002、SPEC-003 | system-layer §8 對應表中沒有 Layout 列；SPEC-003 FR-08 的備註反而明寫「不以 Layout 座標計算為驗收對象」 |
| domain spec | 沒有任何 SPEC 的 frontmatter `domain` 是 `layout` |

所以 072 量到的 domain_coverage 出邊為 0，是依現行慣例的正確值。history bundle 情況相同。

**另外發現的缺口（已另建票）**：SPEC-001 §1〈泳道布局規則〉與 layout domain map §3 公開面描述的是 Layout 的行為，但沒有任何 FR 承接，layout 的測試無法回溯到 FR。要不要補 FR 或調整 `source_specs` 慣例，交給新票分析，本票不擴大範圍。
