## Problem Analysis
<!-- Schema[ANA/Problem Analysis]: 必填（.claude/pm-rules/ticket-body-schema.md） -->
驗證方式改定（2026-11-02，用戶問「能否自行驗證」）：原判斷「需要用戶操作 GUI」不精確。riverpod 3 的暫停條件是 widget 所在子樹的 TickerMode 關閉；Shell 以 IndexedStack 承載六頁，非選取頁在 widget／integration 測試中同樣處於該狀態，可用 macOS integration_test 驅動真實 App 重現。視窗縮小可用 `tester.binding.handleAppLifecycleStateChanged` 模擬生命週期。改為派 parsley 撰寫自動化驗證，結果同時成為回歸防護。
驗證情境：
1. 掃描進行中切到其他頁、完成後切回破洞報告：顯示完成結果，不停在掃描中或舊結果。
2. Domain 視圖在背景時掃描輪次完成，切回後矩陣反映最新輪次。
3. 在其他頁時掃描完成，掃描完成通知照常觸發（ScanNotificationController 以 shell 層 listenManual 監聽）。
4. 生命週期 hidden／paused → resumed 期間完成掃描，通知與破洞報告結果正確。
既有基礎：integration_test/app_test.dart、domain_view_v050.dart、test/widget/app/shell_test.dart。
