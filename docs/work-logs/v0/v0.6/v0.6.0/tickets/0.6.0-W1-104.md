### 入選判準（PM 定案，2026-11-03，L48）

追溯視圖第四層要回答的是「這個 UC 由哪些票做成」（PROP → SPEC → UC → Ticket 實作鏈，SPEC-001 §3〈四層樹由掃描輪次衍生〉第三跳）。所以入選的票必須做出該 UC 場景中使用者會碰到的行為，只是提到該 UC 的票不算。

一張票列入某份 UC 的 `ticket_refs`，須四項全部成立：

1. **類型是 IMP。** DOC、ANA 只分析或改文件，不做出行為。
2. **產物在產品程式碼。** `where.files` 至少有一個路徑落在 `lib/` 或 `integration_test/`。只改 `.claude/`、`docs/`、`test/` 的不算。
3. **票面明確對應該 UC。** `what`、`why`、`acceptance` 或 Problem Analysis 其中一處，寫了該 UC 的 ID（`UC-0N`），或寫了該 UC flow 區塊的步驟 ID，而且對應的段落描述的是該 UC 場景中的行為。只看標題不算；只在背景、引用或「相關」清單中提到也不算。
4. **沒有以不做收場。** status 為 completed、in_progress 或 pending 都收。closed 且 Solution 或 closed_by 寫明撤銷、重複、不做的不收。

實測基準：tickets 目錄本文提到 UC-01～06 的票各有 28～79 張，沒有任何票用 frontmatter 欄位記錄 UC。所以第 3 項要讀內文判斷，不能只靠 grep 計數。

填寫規則：值為裸 ticket ID，依 ID 排序。每份 UC 若有欄位變動，version 加一版並在〈變更歷史〉補一列。逐 UC 的候選票、入選或排除理由寫在本票 Completion Info，排除理由要寫明不符哪一項。
