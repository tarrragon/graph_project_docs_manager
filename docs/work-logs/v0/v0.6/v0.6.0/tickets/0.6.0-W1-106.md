## Solution
<!-- Schema[IMP/Solution]: 選填（.claude/pm-rules/ticket-body-schema.md） -->
L49 實作（parsley，分支 worktree-agent-a10bf60c7cf5d7932）：
- 新增 lib/state/state_holder.dart：StateHolder<T> extends Notifier<T>（public state getter/setter，沿用 .notifier.state 呼叫）、stateHolderProvider<T>、autoDisposeStateHolderProvider<T>、擴充 StateHolderOverride.overrideWithInitial((ref) => v)（沿用舊 overrideWith 呼叫形狀；3.x 的 overrideWith 改收 Notifier 工廠）。
- lib 15 檔全由 StateProvider 改為 stateHolderProvider（lib 內原無 StateNotifier）；lib 不再 import flutter_riverpod/legacy.dart。11 個宣告 provider 的檔案 export StateHolderOverride（show），既有 test 的 import 形狀不變。
- test 2 檔（gap_report_provider_test、state_injection_demo_test）legacy import 一併改為 stateHolderProvider；另 33 個 test／integration_test 檔因 overrideWith 簽章改為 overrideWithInitial（機械替換，無邏輯變動）。
- == 過濾逐 provider 評估（3.x Notifier 以 == 過濾，legacy 以 identical 過濾）：
  - bool／int／String?／enum（switcherOpen、degradedSchema、projectGeneration、inferredVersion、selectedUc、selectedDestination、returnTo、jump targets、ticketSearchInput、pendingLocateGapItem、appLifecycleState）：同值寫入不再通知，監聽者輸出僅依值，無可觀測差異。
  - DomainViewState 家族：只有 SwimlaneFocus 覆寫 ==，各 state 類別維持 identity，行為不變。
  - TicketListState／TraceabilityScreenState／NodeDetailState／WorkspaceState／UcFlowFocus／DegradedSchemaVersions／RecentProject：未覆寫 ==，行為不變。
  - Set／List／Map 狀態（visitedDestinations、expandedTraceNodes、recentProjects、switcherUnavailableProjects）：集合 == 為 identity；所有寫入點皆寫入新複本，無就地突變，行為不變。
  - 結論：15 檔皆無需產品判斷，無 NeedsContext。
