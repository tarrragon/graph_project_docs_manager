### 問題根因
`WorkspaceRepository` 類別本體約 605 行（檔案 1006 行），recent projects 讀寫（`loadRecentProjects`／`addRecentProject`／`saveRecentProjectCounts` 及 `_readRecentProjects`／`_readRecentProjectsForWrite`／`_readForCounts` 類 helper、`_writeCounts`、`_parseRecentProjects`）是可分離次職責，來源 0.6.0-W1-195 方案 C。

### 影響範圍（耦合點盤點，已驗證）
| 耦合點 | 位置（符號） | 判定 |
|---|---|---|
| 共用欄位 | `WorkspaceRepository._preferencesPort`（`WorkspacePreferencesPort`） | 共用，抽出需注入同一 port |
| 共用欄位 | `WorkspaceRepository._log`（`WorkspaceLogSink`） | 共用，抽出需注入同一 sink |
| preferences key | `_recentProjectsKey`='workspace.recentProjects'；`_pathKey`、`_schemaVersionKey` 僅被選取/restore/migration 使用 | 不共用 key |
| schema migration | `_migrateSchema`／`_parseSchemaVersion`／`_writeSchemaVersion` 內無 recentProjects 引用 | 195 所述「migration 與 recent 寫入耦合」未在程式碼中查到 |
| 錯誤處理 | 三個公開方法各自 open handle、catch 後記 log 回預設值 | 各自獨立，無共用 helper |
| 日誌事件 | `WorkspaceLogEvent` enum 的 `recentProjects*`／`recentProjectCountsInvalid`／counts 系列成員與其他事件同 enum | 共用 enum，抽出後可留原 enum |
| 日誌標籤 | `_defaultLogSink` 以 `name: 'WorkspaceRepository'` | 共用；抽出後保留同標籤或另立需決定 |
| 純解析 | `parseRecentProjectsPure`／`ParsedRecentProjects`／`_parseCounts` 已在類別外 | 無耦合 |
| 內部呼叫 | `chooseFolder`／`_persistAndInspect`／`restore` 不呼叫 recent 方法（`addRecentProject` 由 lib/app/workspace_selection.dart 呼叫） | 無類內呼叫耦合 |
