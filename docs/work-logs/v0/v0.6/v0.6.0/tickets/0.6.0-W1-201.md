### 問題根因
`WorkspaceRepository` 類別本體約 605 行（檔案 1006 行），recent projects 讀寫（`loadRecentProjects`／`addRecentProject`／`saveRecentProjectCounts` 及 `_readRecentProjects`／`_readRecentProjectsForWrite`／`_readForCounts` 類 helper、`_writeCounts`、`_parseRecentProjects`）是可分離次職責，來源 0.6.0-W1-195 方案 C。

### 影響範圍（耦合點盤點，已驗證）
| 耦合點 | 位置（符號） | 判定 |
|---|---|---|
| 共用欄位 | `WorkspaceRepository._preferencesPort`（`WorkspacePreferencesPort`） | 共用，抽出需注入同一 port |
| 共用欄位 | `WorkspaceRepository._log`（`WorkspaceLogSink`） | 共用，抽出需注入同一 sink |
| preferences key | `_recentProjectsKey`='workspace.recentProjects'；`_pathKey`、`_schemaVersionKey` 僅被選取/restore/migration 使用 | 不共用 key |
| schema migration | `_migrateSchema`／`_parseSchemaVersion`／`_writeSchemaVersion` 內無 recentProjects 引用 | 195 所述「migration 與 recent 寫入耦合」未在程式碼中查到 |
| 錯誤處理 | 三個公開方法各自 open handle、catch 後記 log 回預設值 | 各自獨立，無共用 helper |
| 日誌事件 | `WorkspaceLogEvent` enum 的 `recentProjects*`／`recentProjectCountsInvalid`／counts 系列成員與其他事件同 enum | 共用 enum，抽出後可留原 enum |

## Solution
<!-- Schema[ANA/Solution]: 必填（.claude/pm-rules/ticket-body-schema.md） -->
### 結論
抽出可行。recent projects 讀寫與類別其他職責只共用兩個注入物（`WorkspacePreferencesPort`、`WorkspaceLogSink`），另共用 `WorkspaceLogEvent` enum 與日誌標籤 'WorkspaceRepository'；無共用 preferences key、無類內互相呼叫、錯誤處理各自獨立。0.6.0-W1-195 所述 schema migration 耦合在程式碼中未查到。

### 候選方案
| 方案 | 內容 | 承載處現況（PC-GPD-083） | 利 | 弊 |
|---|---|---|---|---|
| A 維持現狀 | 不動 | 全部已存在 | 零風險、零測試改動 | 類別本體約 605 行持續存在 |
| C1 內部委派 | 新建 `RecentProjectsStore`（注入同一 port 與 sink），`WorkspaceRepository` 三個 recent 方法轉呼該 store | 介面 `WorkspacePreferencesPort`／`WorkspaceLogSink` 已存在；`RecentProjectsStore` 不存在（0 處）；無需新 provider；測試替身不需改 | 類別本體約減 250 行；lib 呼叫端 5 處、provider、9 個替身全不改；workspace_repository_test 29 處呼叫經委派仍成立 | 公開介面未縮小，替身仍須實作 recent 方法；store 可另外測試但非必需 |
| C2 完整分離 | recent 方法移出 `WorkspaceRepository`，新增 `recentProjectsStoreProvider`，呼叫端改讀新 provider | `recentProjectsStoreProvider` 不存在；新替身不存在 | 介面真正縮小，替身變小 | 影響 lib 4 檔 5 處、main.dart override 接線、9 個替身檔、3 個直呼測試檔（39 處）；共約 17 檔 |
