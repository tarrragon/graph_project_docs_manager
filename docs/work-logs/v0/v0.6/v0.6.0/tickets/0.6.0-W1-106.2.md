## Solution
<!-- Schema[ANA/Solution]: 必填（.claude/pm-rules/ticket-body-schema.md） -->
結論：三支 provider 無原地修改，無正確性缺口（非高優先級）。父票「所有寫入點皆寫入新複本」經獨立複核成立。

| 方案 | 利 | 弊 |
|---|---|---|
| A 維持 StateHolder，不改 | 零變更；寫入點少（Set 1、List 3、Map 1）且全為複本寫入 | 防線靠呼叫端紀律，未來新增寫入點若原地修改仍會靜默不通知 |
| B 改領域 Notifier（markVisited／replaceAll＋syncCounts／markUnavailable），不公開 state setter | 結構上排除原地修改，寫入語意集中 | 5 處呼叫端改寫、新增 3 個類別；收益僅為防未來誤用 |
| C 維持 StateHolder，狀態改不可變集合（Set.unmodifiable 等） | 原地修改改為執行期拋錯，不再靜默 | 錯誤延至 runtime；初值與每個寫入點都需包裝 |

建議：採 A。現況無缺陷，B/C 屬預防性改寫，價值低於變更成本。

Spawn 落地確認：
| 項目 | 處置 |
|---|---|
| 三支 provider 改領域 Notifier | 無需建 ticket：結論採方案 A，現況無缺陷 |
| autoDispose 版 overrideWithInitial 無測試覆蓋 | 已建 0.6.0-W1-106.2.1（P3，--parent 本票） |

PM 收尾判定（2026-11-04）：分析結論已完成，三支 provider 共 5 個寫入點都寫入新集合，沒有原地修改。本票屬防護性 ANA，落地票 0.6.0-W1-106.2.1（autoDispose 版 overrideWithInitial 覆寫測試）以 --parent 建立，依 ticket-lifecycle〈防護性 ANA〉，本票維持 in_progress，待 106.2.1 完成後 complete，不以 --force 收尾。重現實驗結果章節不適用：結論為無缺陷，沒有可重現的問題。
