**虛擬碼要點**
- isScanInputPath(path, location?)：
  - path 等於 location 時為 true。
  - 不在 docs/ 底下時為 false；任一路徑段是 .git 時為 false。
  - 兩個主題檔為 true。
  - 其餘以 endsWith(".md") 判定，大小寫敏感。
- WatchDebouncer：
  - pending 是有序表，每筆為 路徑→kind：先 created 後 deleted 就刪除該筆；先 created 後 modified 仍保留 created；其餘以後到的覆寫。
  - quietTimer 每次 add 都重排；maxTimer 只排一次。
  - flush 時若 pending 為空就不送。clearPending 與 dispose 會清空 pending 並取消兩個計時器。
- CorpusWatcher：
  - start(root) 時遞增 session 號，只把通過過濾的事件交給 debouncer。
  - onError，或非主動停止的 onDone：記 warning(900)，然後 _halt。
  - stop 不寫 warning。_halt 取消訂閱並清空 debouncer。callback 須核對 session 號。
- ScanScheduler：
  - 狀態為 running、pendingTrigger、generation。
  - manual 觸發時先清空監看累積的事件；running 期間收到觸發，以後到的覆寫 pending。
  - _run 完成時先核對 generation，再接著跑 pending；runRound 的錯誤只記日誌。
  - cancel 會讓 generation 加一並清除 pending。
- GapsWatchPresentation：
  - watch 觸發的輪次不轉 scanning。
  - 手動重掃時：scanning=true、awaitManual=true。
  - 輪次完成時，若 awaitManual 且 rerunPending，維持 scanning、不替換結果；其餘情況替換結果。
  - shouldAutoScanOnVisible 等於 shown==null。
- watch_round_notification：
  - prev 為 null 時視為空集合。
  - changed 的條件是兩向差集任一非空。
  - shouldSend 的條件是 changed 且 not(前景 且 在破洞頁)。
  - 先撤回舊通知（失敗只記 warning）再發送。
- DirectoryWatchSource：
  - 監看 <root>/docs。
  - 事件路徑以 p.relative 轉相對路徑，分隔符統一為 `/`。
  - ADD/MODIFY/REMOVE 分別對應 created/modified/deleted。
  - 錯誤原樣傳出。

**接線點**（實際符號）：scanRoundProvider（ScanRoundNotifier：rescan、discard、ensureRound）、lastCompletedRoundProvider（D1 的 prev 來源）、currentWorkspaceStateProvider（WorkspaceReady 時 start，其餘狀態 stop）、GapReportNotifier（目前的 rescan、_projectRound、cancelScan 都直接呼叫輪次，要改經 ScanScheduler）、ScanNotifier.show/withdraw、ScanNotificationController（在 lib/assembly/shell.dart 建立）。
