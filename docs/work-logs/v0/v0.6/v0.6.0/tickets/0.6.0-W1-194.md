## Problem Analysis
### 問題根因

兩張票都是改號，不是刪除。`ticket migrate` 只改寫票檔內的結構欄位，不回寫 `docs/` 下的引用，所以規格裡的舊號變成查不到的票號。

| 規格引用 | 改號鏈（`git log --name-status -M`） | 現況 |
|---|---|---|
| `0.3.0-W1-086`（SPEC-006 D9） | 4cd0db798a（2026-09-25，0.3.0 發布準備）`0.3.0-W1-086 → 0.3.1-W1-086` | `0.3.1-W1-086` 已關閉 |
| `0.1.0-W3-135`（SPEC-005 §三 G-1） | 0196f26fad（09-23）→ 32b9063b5b（09-24）→ 4cd0db798a（09-25）→ 60613c65c1（09-29），`0.1.0 → 0.1.1 → 0.3.0 → 0.3.1 → 1.0.0-W3-135` | `1.0.0-W3-135` 待處理 |

語意確認：SPEC-005 在 21bbe0ce9c（2026-09-09）引用 `0.1.0-W3-135` 時，該票的標題就是「宣告 WorkspaceDirectoryProbePort 的例外契約……」，與現在的 `1.0.0-W3-135` 是同一張。SPEC-006 的引用在 2cc0aea5ad 加入，主題為 ASCII 語意的方言說明，與 `0.3.1-W1-086` 的標題一致。

`previous_ids` 查不到這兩張，原因是曾用 ID 記錄由 0.4.1-W1-010.2（525419eb07，2026-10-01）才加入 migrate，這兩張的改號都在那之前。

### 影響範圍

- 已驗證：四次改號 commit 改到 `docs/work-logs/` 以外的檔只有 `docs/todolist.yaml` 與 `CHANGELOG.md`，沒有 `docs/spec/`。
- 已驗證：`migrate.py` 的引用改寫範圍為 `work_logs_root.glob("v*/tickets")` 與 `glob("v*/v*/v*/tickets")` 下的票檔。
- 已驗證：兩份規格已被改寫為「原票號已不在票庫」（SPEC-005 v1.8 G-1 列、SPEC-006 v1.37 修訂列）。這個敘述不正確。
- 影響面量測，見〈重現實驗結果〉：`docs/`（排除 work-logs）有 34 個票號不在票庫。
