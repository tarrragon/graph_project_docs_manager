## Problem Analysis
### 問題根因

兩張票都是改號，不是刪除。`ticket migrate` 只改寫票檔內的結構欄位，不回寫 `docs/` 下的引用，所以規格裡的舊號變成查不到的票號。

| 規格引用 | 改號鏈（`git log --name-status -M`） | 現況 |
|---|---|---|
| `0.3.0-W1-086`（SPEC-006 D9） | 4cd0db798a（2026-09-25，0.3.0 發布準備）`0.3.0-W1-086 → 0.3.1-W1-086` | `0.3.1-W1-086` 已關閉 |
| `0.1.0-W3-135`（SPEC-005 §三 G-1） | 0196f26fad（09-23）→ 32b9063b5b（09-24）→ 4cd0db798a（09-25）→ 60613c65c1（09-29），`0.1.0 → 0.1.1 → 0.3.0 → 0.3.1 → 1.0.0-W3-135` | `1.0.0-W3-135` 待處理 |

語意確認：SPEC-005 在 21bbe0ce9c（2026-09-09）引用 `0.1.0-W3-135` 時，該票的標題就是「宣告 WorkspaceDirectoryProbePort 的例外契約……」，與現在的 `1.0.0-W3-135` 是同一張。SPEC-006 的引用在 2cc0aea5ad 加入，主題為 ASCII 語意的方言說明，與 `0.3.1-W1-086` 的標題一致。

`previous_ids` 查不到這兩張，原因是曾用 ID 記錄由 0.4.1-W1-010.2（525419eb07，2026-10-01）才加入 migrate，這兩張的改號都在那之前。

### 影響範圍

- 已驗證：四次改號 commit 改到 `docs/work-logs/` 以外的檔只有 `docs/todolist.yaml` 與 `CHANGELOG.md`，沒有 `docs/spec/`。
- 已驗證：`migrate.py` 的引用改寫範圍為 `work_logs_root.glob("v*/tickets")` 與 `glob("v*/v*/v*/tickets")` 下的票檔。
- 已驗證：兩份規格已被改寫為「原票號已不在票庫」（SPEC-005 v1.8 G-1 列、SPEC-006 v1.37 修訂列）。這個敘述不正確。
- 影響面量測，見〈重現實驗結果〉：`docs/`（排除 work-logs）有 34 個票號不在票庫。

### 相關 Error Pattern

無對應的 error-pattern。框架層的根源是 tarrragon/claude#110 症狀 1（Ticket ID 內嵌版本，搬移即改名、文件引用失效）。

### 查重紀錄

`section_comment.py dedup --keywords "migrate 改號 引用 docs" "migrate previous_ids spec 回寫"`，rc=0。#110 症狀 1 已涵蓋，關係判為「引用」，以 observe 附加實測。

## 重現實驗結果
### 實驗方法

1. 對兩張票的檔名追遷移鏈：`git log --format='%h %ad' --date=short --name-status -M -- '*W1-086.md'`（`'*W3-135.md'` 同法），再用 `git show <commit>:<path>` 讀引用當時的票標題，確認語意相同。
2. 查四個改號 commit 改到的非 work-logs 檔：`git show --name-only --format= <commit> | grep -v '^docs/work-logs/'`。
3. 讀 `migrate.py` 的引用改寫函式（`_update_cross_references_collecting`、`_rewrite_external_refs`、`_iter_all_ticket_files`）的掃描範圍。
4. 影響面：以 python 收集全部票的 id 與 `previous_ids`（52 筆），掃描 `docs/` 排除 `work-logs/` 的 `.md`／`.yaml`／`.json`，列出票庫已無此 ID 的票號。

### 實驗發現

- 已驗證：0.3.0-W1-086、0.1.0-W3-135 都是改號，新 ID 分別為 0.3.1-W1-086、1.0.0-W3-135。
- 已驗證：migrate 不回寫 `docs/` 的引用。
- 已驗證：改號不保證保留序號（`0.5.0-W1-104 → 0.6.0-W1-081`），「同後綴換版本」的候選不可靠。其餘 30 個須逐一以 git rename 鏈判定，已交由 194.1 處理。
- 未驗證：30 個舊號各自是改號、刪除還是打錯字。

## Solution
### 分析結論

- `0.3.0-W1-086`：改號，新 ID 為 `0.3.1-W1-086`（已關閉）。
- `0.1.0-W3-135`：改號，新 ID 為 `1.0.0-W3-135`（待處理）。
- `ticket migrate` 不回寫 `docs/` 的引用，這是框架缺口，屬 tarrragon/claude#110 症狀 1。
- 這兩次改號早於 `previous_ids` 的引入日（2026-10-01），所以只能用 git rename 鏈解析。

### 候選方案

| 方案 | 內容 | 利 | 弊 |
|---|---|---|---|
| A 觀測進 #110，專案層更正交給子票 | 框架面附加實測到 #110；本 consumer 的錯誤敘述與殘留舊號由 194.1 處理 | 符合修補節奏（P3）；實測數字留在 canonical | 框架缺口不會因此關閉，下次改號仍會失效 |
| B 本地修 migrate，改為同批回寫 docs/ | 改寫範圍擴及 `docs/` | 直接止血 | 誤改風險（決策記錄是 append-only、歷史引用不應改）未評估；#110 方向是改用穩定 ID，本地修補可能白做；不是 P0／P1 |

採 A。
