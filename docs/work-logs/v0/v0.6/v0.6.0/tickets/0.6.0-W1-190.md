## Problem Analysis
### 問題根因

擋下命令的不是專案 hook，是 Claude Code 平台對 `isolation: worktree` 代理人的 Bash 靜態檢查。證據取自 187.1 代理人的 transcript：`~/.claude/projects/<proj>/a3148b43-.../subagents/agent-a093c864be16fa428.jsonl`。

三種拒絕訊息的原文（worktree 路徑以 `<wt>` 代替）：

- `This agent is isolated in the worktree <wt>, but this command names git in a form too complex to verify that it stays inside the worktree. Refusing to run it — a worktree-isolated agent's git operations must target its own worktree. Split it into plain, separate commands and run them from <wt>.`（heredoc 加 `; ec...`，內文含 `git diff --cached`）
- `... but this command runs ticket with a value computed at runtime (command output) inside a construct too complex to verify, so what it runs cannot be shown not to be git. Refusing to run it ...`（heredoc 命令替換加 `; echo rc=$?`）
- `... but this command runs ticket with the text merge-gate.yaml 新增三個套件：tool-spec006-sel… inside a construct too complex to verify ...`（單引號多行參數加 `; echo rc=$?`）

被擋的命令都帶 `; echo rc=$?` 串接。代理人去掉串接、把內容壓成單行之後才通過（transcript 時間戳 08:11:16Z）。183 代理人的情況相同：`out=$(...); rc=$?; ...; git rev-parse` 被擋，訊息為 `names git in a form too complex to verify`。
