## Solution
### 分析結論

主控提問的兩個可能（守衛誤擋、代理人迴避）都不成立。

1. 不是專案守衛誤擋。拒絕來自 Claude Code 平台的 worktree 隔離檢查，屬非專案來源。專案 hook 在同一時段全為 allow，見 how.strategy 盤點表。
2. 代理人的做法沒有違反禁止事項。平台訊息要求 `Split it into plain, separate commands`，屬於 tool-selection 規則 2 的「too complex to verify」例外。代理人去掉串接、改成單一命令，是例外允許的拆分；它沒有改用 `python -c` 之類的寫法藏起實際操作。不過，把 markdown 壓成單行是 PC-GPD-003 L2 明列的錯誤降級。合規路徑 `append-log --content-file` 沒有出現在手寫 prompt 裡，代理人也沒有讀到 PC-GPD-003（該檔不自動載入）。
3. 根因在上游：PM 手寫 worktree 派發 prompt，沒有經過 `ticket track dispatch --isolation worktree`，骨架中的多行內容指引因此遺失。這與 tarrragon/claude#92 第二節同型。
4. 附帶修正：PC-GPD-003 L1 寫的判準是「含換行即拒」，與實測不符。實際條件是「多行或命令替換內容」加上「`;` 串接」的組合。另外，bash 規則五（長文字用 heredoc）與統一檢查清單的 `out=$(...); rc=$?` 在主線程仍然成立；在隔離代理人內，兩者合用就是會被拒的形態。
