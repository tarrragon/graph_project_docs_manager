## Problem Analysis
<!-- Schema[ANA/Problem Analysis]: 必填（.claude/pm-rules/ticket-body-schema.md） -->
### 問題根因

票面前提「App 規格對 bundle `path_patterns` 沒有元素格式規則」只部分成立：

- 已明載：UC-02〈ticket 定位〉比對語意條「不以 `/` 結尾的值是單一檔案」寫明上游判為格式違規的值（空字串、`/` 或 `./` 開頭、含 `..` 段、含 glob 字元）不命中任何路徑（C3′）。該條不分 bundle 側或非 domain 側，bundle 側「靜默不命中」已有規格依據。
- 未明載（缺口三項）：
  1. bundle 的 `path_patterns` 值不是清單（例如純量字串）：`_bundlePathPatterns` 回 `null`，等於「未宣告」，該 bundle 計入「domain 未宣告」。UC-02 只寫「欄位缺席為未宣告，`[]` 為已宣告」，非清單值的歸類無規格。
  2. bundle 清單內非字串元素：`whereType<String>()` 靜默略過。非 domain 側同情形有 `elementNotString` 子原因並發 EVT-CORPUS-005；bundle 側無對應規格、無事件。
  3. 「glob 字元」字元集與上游不一致：App `_globChars = [*?\[\]{}]`；上游 `_PATH_PATTERN_FORBIDDEN_CHARS = *?[\`（反斜線）。差集：App 多擋 `]` `{` `}`；上游多擋反斜線。規格只寫「含 glob 字元」，未列字元集。

### 影響範圍

- 程式：`lib/graph/project_path_declaration.dart` 的 `_bundlePathPatterns`；`lib/graph/path_declaration_state.dart` 的 `_isMatchable`、`_matches`、`_globChars`。
- 規格：UC-02〈ticket 定位〉；SPEC-006 FR-10 與 EVT-CORPUS-005 只管非 domain 清單；graph domain-map 不變式表與 SPEC-007 無 `path_patterns` 條目。
- 讀這個欄位的是 Graph（`lib/graph/`），Corpus 只把 frontmatter 原樣放進 `rawNodes`。
- 已驗證（讀碼）：上述三項缺口。未驗證：被觀測專案實際出現壞值的頻率（本專案 8 份 domain-map 的 `path_patterns` 皆為合法清單）。

### 相關 Error Pattern

- PC-GPD-075（改規格須同步檢查以路徑字面引用規格的契約測試，Context Bundle 已列）。
- 字元集差異屬建立端與下游清單不同步（PC-BAL-001 同型），上游 `check_path_pattern_format` 為權威。
