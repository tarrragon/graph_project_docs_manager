### 問題根因

**一句話**：`multi_view_status` 的值域與修正路徑只出現在「寫錯之後的阻擋訊息」與 PM 側文件；代理人寫入 Solution 時能看到的載體（票面 placeholder、派發骨架、代理人定義、append-log 回饋）都沒有值域。阻擋訊息附的修正指令又缺少多行情境需要的 `--match`，所以 PM 照著訊息也修不好。

已驗證（取證見〈重現實驗結果〉）：

1. **寫入時點沒有值域**。新 ANA 票的 Solution placeholder 來自 `ticket_builder.py` 的 `_TYPE_PLACEHOLDERS["ANA"]["solution"]`，字面是「（必填：分析結論、至少 2 個候選方案含利弊、Spawn 規劃表）」，沒有欄位名、值域，也沒有修正命令。旁邊的 Schema 註解只寫「必填」，並指向 `ticket-body-schema.md` 整份檔案。值域在該檔〈Validator 層級規則〉表格的第一列。
2. **派發與代理人載體 0 命中**：`agent-dispatch-template.md`、`agent-dispatch-closeout.md`、`AGENT_PRELOAD.md`、`.claude/agents/*.md` 都沒有出現 `multi_view_status`。
3. **第一個主動送出值域的時點是 complete**：只有 acceptance-gate-hook 步驟 2.6 會檢查。append-log 與 check-acceptance 都不檢查值（`.claude/hooks`、`ticket/hooks`、`ticket_system` 中只有 checker、gate 和 fix 命令三組檔案提到 multi_view）。092.2 的 gate log 只在 PM 收尾時觸發一次（2026-11-04 12:41:28 判為非法），代理人執行期間從來沒有收到值域。
4. **修正路徑缺 `--match`**：`fix-multi-view-status` 的 parser 有 `--match`，help 寫明用途是「既有非法值行 + 事後補正行並存」，也就是 092／092.2 的情況。但 gate 非法值訊息的修正指令沒有它（實驗 a1），fix 多行拒寫訊息只列出候選行、也沒提它（實驗 b1），ticket skill 的四份 references 同樣沒有記載。〈補充觀測〉寫「必須在 Solution 只有 1 行時才能用」，是因為兩則錯誤訊息都沒指出 `--match` 而造成的誤讀；實驗 b2 證實帶 `--match` 可以一次修好。
5. **gate 只讀第一行**：`multi_view_checker._parse_field` 用 `re.search`，只取 Solution 中第一行 `multi_view_status:`。所以在後面追加合法值無法覆蓋前面的非法值（a1）；順序反過來，合法值在前、非法值在後，則會靜默通過（a2）。
