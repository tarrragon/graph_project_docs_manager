## Solution
### 分析結論

根因：盤點表的格式只寫在 gate 擋下訊息與 schema 文件裡。執行期間會到達代理人的兩個傳達點（建票驗收佔位、派發骨架）都只寫「寫入 how.strategy」，格式本身沒有傳達到。四個失敗實例全是 gate 的 absent，而且分別違反三項不同的格式限制（須為表格、表頭須含字面「產生路徑」、半形 `|` 逐列換行並帶分隔列）。這說明缺的是格式本身，不是代理人漏看某一條限制。實驗細節見「重現實驗結果」。

### 處置結論

**採 C：僅觀測進 tarrragon/claude#92。** 修法方向記為 A，交給清理線。

理由：
1. 〈修復時點〉表規定 P2／P3 走路徑 A。本票 P3，四個實例都由 PM 改寫後 complete，沒有阻擋專案工作。不屬於「P0／P1 且阻擋」，也沒有用戶要求。
2. PM 端有已驗證的暫行做法：派發 prompt 或 `--note` 直接帶半形表格字面（表頭含「產生路徑」、帶分隔列、逐列換行），對照樣本 123、129 都一次寫對。在清理線修好之前，風險可以由派發端吸收。
3. 修法方向已能定案（A 優於 B），留在觀測內容中，清理線開線時不必重做分析。A 優於 B 的關鍵是覆蓋面：佔位對所有派發途徑都有效，骨架只對 dispatch CLI 有效，而且 126.1 正是骨架之外的途徑出錯。
