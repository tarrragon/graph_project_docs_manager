### 實機驗證（PM，2026-11-04，macOS 25.5.0，本機 main @ 318a7670f6 之後）

**第 1 輪：原配方**：執行 `WV_KEEP_LOG=<scratchpad>/161-vm.log bash .claude/skills/verify/watch-verify.sh`，rc=0。

```
GATE fseventsd_cpu=1 limit=50 sample=1
GATE canary=CANARY_EVENT
RESULT total=72 seq_gaps=0 exp_add=1 exp_remove=1
PASS
CLEANUP app_pid=30475 exp_file_removed=yes
```

- 訊息本體超過 128 字的 log 有 9 行，最長 222 字；`[TRUNCATED` 標註 0 行。
- 72 行的 seq 每行都比前一行 +1，0 處不連續。
- 原始輸出範例（seq=21，訊息本體 222 字）：
  `+3.42s seq=21 [GraphBuilder] L0 [buildCompleted] graph build completed {nodeCount: 2572, edgeCount: 3676, danglingRefCount: 3, malformedRefCount: 1, duplicateIdCount: 0, multiSourceCount: 9, flowDefectCount: 0, resolvedCount: 5789, totalReferences: 5793}`

**第 2 輪：對照組，證明 getObject 確實有被走到**

只看第 1 輪分不出兩種情況：一是 VM 有截斷、getObject 也成功還原；二是 VM 根本沒截斷。所以在 scratchpad 複製整個 verify 目錄，只在 `vm_log.mjs` 的輸出行加上 `PROBE_truncated=<valueAsStringIsTruncated>` 和 `rawlen=<截斷值長度>` 兩個欄位，同一配方再跑一次，rc=0，PASS。

| 原始截斷值長度 | 還原後長度 | 行數 |
|---|---|---|
| 128 | 165 | 1 |
| 128 | 168 | 2 |
| 128 | 171 | 2 |
| 128 | 222 | 4 |

- `PROBE_truncated=true` 有 9 行，`[TRUNCATED` 標註 0 行，seq 不連續 0 處。
- 結論：VM service 對這 9 筆把訊息截到 128 字，`getObject` 以事件中的 isolateId 取回全文，回應由 pending map 攔截，WebSocket 接線端對端成立。
- 探針複本只放在 scratchpad，沒有進 repo。
