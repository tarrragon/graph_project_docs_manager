## Problem Analysis
### PM 派發前前提核對（2026-11-03，L50）

以程式碼核實（票面原 where 寫 statusColor.ts／statusColor.test.ts，經查不需改）：

- 誤配來源：`dispatch.ts` 的 `dispatchRows` 組 `DispatchRow.task`：有 ticketId 時為 `shortTicketId(...)`，沒有時退回 `record.description || NO_DESCRIPTION`。`DispatchRow` 型別定義在 `types/index.d.ts`，目前沒有完整票號欄位。
- 比對點兩處，同一模式：
  - `lanesView.tsx` 的 `queueColorOf`：`allRows.filter(row => row.task === serial)` 決定佇列票顏色（票面所述）。
  - `layout.ts` 的 `laneGateTickets`：`dispatches.filter(row => row.stage === '閘門').map(row => row.task)` 再與 `token.serial` 比對，決定閘門票列是否重複列。同樣會被 description 誤配，一併改。
- `statusColor.ts` 的 `queueTicketState` 只吃 status 與 stages，不碰比對，不改。
- 測試檔：`tests/boardDispatch.test.ts`（〈五色狀態〉以 queueSegmentsOf 讀佇列票顏色，E2 對照放這裡：description 等於某短票號的無票號派發不得讓該票上色）、`tests/dispatch.test.ts`（dispatchRows 產出帶完整票號，無票號時為 null）、`tests/layout.test.ts`（以字面建 DispatchRow，加欄位後須同步）、`tests/fixtures.ts`（需新 dispatch 紀錄時）。
- 文件：`references/board-screens.md`〈五色狀態〉「以短票號比對任務欄」改為以完整票號比對；`CHANGELOG.md` 與 `SKILL.md` metadata.version（現 0.12.1）。
- 檔數：程式 4 檔，其餘為測試與文件，同一比對改動的伴隨範圍，不拆票。
