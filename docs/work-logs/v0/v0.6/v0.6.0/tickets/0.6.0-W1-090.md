## Problem Analysis
### PM 派發前前提核對（2026-11-03，L50）

以程式碼核實（票面原 where 寫 statusColor.ts／statusColor.test.ts，經查不需改）：

- 誤配來源：`dispatch.ts` 的 `dispatchRows` 組 `DispatchRow.task`：有 ticketId 時為 `shortTicketId(...)`，沒有時退回 `record.description || NO_DESCRIPTION`。`DispatchRow` 型別定義在 `types/index.d.ts`，目前沒有完整票號欄位。
- 比對點兩處，同一模式：
  - `lanesView.tsx` 的 `queueColorOf`：`allRows.filter(row => row.task === serial)` 決定佇列票顏色（票面所述）。
  - `layout.ts` 的 `laneGateTickets`：`dispatches.filter(row => row.stage === '閘門').map(row => row.task)` 再與 `token.serial` 比對，決定閘門票列是否重複列。同樣會被 description 誤配，一併改。
- `statusColor.ts` 的 `queueTicketState` 只吃 status 與 stages，不碰比對，不改。
- 測試檔：`tests/boardDispatch.test.ts`（〈五色狀態〉以 queueSegmentsOf 讀佇列票顏色，E2 對照放這裡：description 等於某短票號的無票號派發不得讓該票上色）、`tests/dispatch.test.ts`（dispatchRows 產出帶完整票號，無票號時為 null）、`tests/layout.test.ts`（以字面建 DispatchRow，加欄位後須同步）、`tests/fixtures.ts`（需新 dispatch 紀錄時）。
- 文件：`references/board-screens.md`〈五色狀態〉「以短票號比對任務欄」改為以完整票號比對；`CHANGELOG.md` 與 `SKILL.md` metadata.version（現 0.12.1）。
- 檔數：程式 4 檔，其餘為測試與文件，同一比對改動的伴隨範圍，不拆票。

## Solution
### 實作

- `types/index.d.ts`：`DispatchRow` 新增 `ticketId: string | null`（派發沒有票號時為 null，不參與佇列票比對）。
- `hooks/dispatch.ts`：`dispatchRows` 填入 `record.ticketId`（`nonEmptyString(ticket_id)`，空字串與缺欄皆為 null）；`task` 組法不變。
- `hooks/lanesView.tsx` `queueColorOf`：`row.task === serial` 改為 `row.ticketId === id`（id 為佇列 token 的完整票號）。
- `hooks/layout.ts` `laneGateTickets`：閘門派發列去重由 `task` 對 `token.serial` 改為 `ticketId` 對 `token.id`。
- `statusColor.ts` 未改（`queueTicketState` 只吃 status 與 stages）。
- 文件：`references/board-screens.md`〈五色狀態〉佇列票比對描述、閘門票列不重複列的描述改寫為完整票號比對；`CHANGELOG.md` 新增 0.12.2；`SKILL.md` metadata.version 0.12.1 → 0.12.2。

### 失敗語意

本改動屬顯示判定，不放行也不阻擋任何操作。觸發條件：派發紀錄的 `ticket_id` 為空字串或缺欄時，該派發列 `ticketId` 為 null，不參與佇列票上色與閘門票去重——佇列票改依主 checkout 狀態上色（pending 灰、in_progress 綠），持有閘門的佇列票照常列閘門票列；派發列本身照常列出並顯示描述原文。修正前同條件下，描述剛好等於某短票號時該票會被上色為派發階段色，或閘門票列被誤判為已由派發列表達而不列。

### Phase 4 評估

- 重構需要：否。
- 技術債務：無新增。`task` 欄現只剩顯示用途（`formatGroupDispatchRow`），比對與顯示已分離。
- 程式碼品質：A。
- 結論：兩個比對點改為同一鍵（完整票號），與 `laneGateTickets` 內 holder 比對（`shortBranch(...) === token.id`）一致；無需重構。
