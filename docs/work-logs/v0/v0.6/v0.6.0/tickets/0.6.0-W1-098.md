- 期間：2026-10-08（合併前審查成為常規）至 2026-11-05。

- 分類（每則訊息一類，依序判定）：衝突併 main／資訊請求／接新票／測試失敗（閘門或測試紅燈）／linux 審查退回（linux、Phase 4、合併前審查、寫作審查）／PM 或主控審查退回（覆核、審閱、驗收退回、追修、補修、回歸）／範圍或規格（where.files、裁示、裁決、新增驗收、約束補充）／收尾（complete、自檢、通過而無修正要求）／其他。

## 重現實驗結果
### 實驗方法

以 Python 讀上述兩個來源：對話紀錄中，Agent tool_use 的 input（subagent_type、prompt）以 tool_use_id 對到 tool_result 的 agentId；SendMessage 的 `to` 對 agentId 或代理人 name，即可得到每則續做訊息所屬的票與代理人。訊息以關鍵字規則分類（類別順序見 Problem Analysis〈口徑〉），票級彙總：一張票只要有一則計入類訊息，就計為有該類重派。

### 實驗執行

- SendMessage 給實作代理人的 413 則，分類結果：範圍或規格 95、PM 或主控審查退回 83、收尾 80、linux 審查退回 76、其他 35、衝突 23、測試失敗 17、接新票 2、資訊請求 2。

- Agent 重派：632 張票中有 37 張出現 2 次以上實作層派發。扣除收尾派發 16 張、PM 規劃的分階段 3 張（0.6.0-W1-080、0.5.0-W1-465、0.5.0-W1-164.6 系列子票已各自成票）後，描述為重派、重做或重試的約 8 張。
