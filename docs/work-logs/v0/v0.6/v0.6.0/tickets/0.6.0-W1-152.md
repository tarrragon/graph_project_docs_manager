## Solution
<!-- Schema[ANA/Solution]: 必填（.claude/pm-rules/ticket-body-schema.md） -->
### 結論：改集合比對（單向：§4.0.6 表 ⊆ ARB 且值逐字相等）

**範圍驗證方法**：rg regex 法＋Python set 差集（全表列舉，非抽樣）。
**驗證指令**：見〈重現實驗結果／實驗方法〉第 2 點（regex `^\| \`key\` \|`，範圍 `#### 4.0.6` 至 `#### 4.0.7`）。
**已知盲區**：列首非反引號 key 的表列、或一列多 key 的寫法不會被抽到；ARB→表方向只檢查 SPEC-004 全文字串出現，未驗證出現處是否為 i18n 表。
**盲區影響評估**：§4.0.6 範圍內 `| key |` 表頭以外的表列皆為反引號 key 起首（逐子表目視）；ARB→表方向不納入契約，盲區不影響結論。

理由：點名比對只涵蓋新票點到的 key，§4.0.6 的其餘列沒有任何守衛；本次實測在全綠的 main 上找到 6 處文案漂移與 3 個規格無記載的 ARB key，與 probingReason 同型。gap* 子集已用集合比對且運作（gap_report_projection_test），證明表格解析可行。

### 候選方案

| 方案 | 利 | 弊 |
|------|----|----|
| A 單向集合比對（採用） | 整張表一次覆蓋；新增表列自動受守衛；誤報面只剩可具名列舉的豁免 | 需維護兩份具名豁免；落地前須先清 6 處漂移 |
| B 雙向集合比對（ARB 亦須在表內） | 能抓 ARB 新增但未登記 | 93 個表外 key 中 90 個合法登記在元件條目 i18n 表，豁免清單近百項，等同點名 |
| C 維持點名比對 | 無遷移成本 | 已實證漂移無訊號，主控要求的「漂移由契約抓到」不成立 |

### 比對規則（交 0.6.0-W1-152.2）

1. 抽取：SPEC-004 `#### 4.0.6` 至 `#### 4.0.7` 之間，以 `| \`key\` |` 起首的列；拆欄沿用 gap_report_projection_test 的跳脫豎線處理。版次子表不需區分，整段合併抽。淘汰 key 以引言區塊敘述、非表列，天然排除，殘留守衛維持 arb_key_sync_test。
2. 斷言：表內無重複 key；列數下界（防解析抽到 0 列空轉）；表列 key 扣「待加入豁免」後全數存在於 zh／en ARB；扣「非字面豁免」後 zh、en 值逐字相等。
3. 豁免以兩個具名常數表達，各條附理由與來源版次：
   - 待加入豁免（表有、ARB 尚無）：初始為 1.113 三個 nodeDetail key。斷言豁免成員必須仍在表中、且尚不在 ARB——ARB 一加入即紅，迫使移除豁免並進入值比對。不用子表標頭「待建」字樣判定（已實證過期）。
   - 非字面豁免（儲存格是描述而非字面）：初始為 healthBadgeA11yLabel 的 en；只豁免值比對，不豁免存在性。
4. 不做 ARB→表方向（理由見方案 B）。ARB 中不屬 §4.0.6 的 key 不受本契約約束；其「全文無記載」的 3 個由 152.1 補登。
5. E2 正向對照：竄改一個表列 key 的 ARB 值須紅；合成一個表有 ARB 無的 key 須紅。
6. 既有點名比對保留（F6、K4 另驗證硬編碼期望值，能抓規格與 ARB 同步改錯的情況），是否併入由 152.2 判斷並寫明。
