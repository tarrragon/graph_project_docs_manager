### 自檢結果與 Phase 4 評估（linux 審查）

**範圍**：`coordination_ticket.py`（179 行）、`test_coordination_ticket.py`（92 行，8 個測試）。實測：用現行 `docs/todolist.yaml` 對照本模組 `active_version_worklogs` 與 PyYAML `safe_load`，兩邊結果相同，都是 `[('0.6.0', 'docs/work-logs/v0/v0.6/v0.6.0/')]`。

- **重構需要**：否（本票範圍內）。重複的程式碼在 100.2 刪除。
- **技術債務**：發現 5 項
  1. `TICKET_ID`／`ticket_file_candidates`／`resolve_ticket_file` 與 `statusline_lane.py` 逐字重複。100.2 改為 import 時須同批刪掉 statusline_lane.py 那一份，並把對齊 line-board `hooks/shared.ts` 的註解移到本模組。
  2. todolist 以逐行 regex 解析，下列輸入會和 PyYAML 結果不同：縮排、鍵的順序、flow style、巢狀鍵撞名、值含 `#`、多行字串、錨點。regex 失效時安靜回 `none`，與本模組「不靜默」的主張矛盾。
  3. frontmatter 的 `coordination` 只認 `true`（不分大小寫），PyYAML 會把 `yes`／`on` 也當成 true，判準字面需要寫進規格。
  4. 測試缺正向對照（E2）：沒有「regex 漏抓」的輸入；也沒有測「completed 版本底下的 coordination 票不會被掃到」。
  5. `test_cli_json_fields` 漏斷言 `reason` 欄位。
- **程式碼品質**：A。函式長度只有兩個略超 15 行，都是線性流程；巢狀深度最多 3 層；3 處 except 都經 `_warn` 寫 stderr；另外兩處靜默降級屬正常語意，docstring 已寫明。
- **結論**：資料結構正確，流程扁平，錯誤都有出口。扣分在兩處：整段複製，以及手刻 regex。不用 PyYAML 是有意的取捨（執行環境可能沒有 PyYAML），但取捨沒有寫進程式碼。
