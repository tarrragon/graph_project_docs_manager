## Problem Analysis
### 問題根因

`closed_by` 有三個寫入者、一個讀取端，值域不一致：`close` 對 `superseded_by`／`duplicate` 驗 Ticket ID 格式加存在性，其餘四種 reason 對 `resolved_by` 零驗證；`set-closed-by`（`track_set_closed_by.py` 的 `_validate_new_closed_by`）一律要求 Ticket ID 格式加存在性。所以 close 寫得進的 `tarrragon/claude#N`，修正路徑寫不進。

### 影響範圍

- 已驗證：set-closed-by 對 `tarrragon/claude#102` 以 rc=1 拒收（實跑）；本 consumer 95 張 issue ref 形態的 closed 票，`close_reason` 全為 `not_executable_knowledge_captured`（票庫統計）。
- 讀 code 結論、未實跑：close 在 `goal_achieved`／`not_executable_knowledge_captured` 兩種 reason 下對 resolved_by 與 note 皆不檢查。

### 框架問題兩條 AND 判準

1. 抽象可攜：替換專案名與路徑後成立——任何 consumer 走 framework-issue 收束流程關票後，若需修正 closed_by，都撞同一個拒收。成立。
2. 根源在 `.claude/` 通用資產：`.claude/skills/ticket/ticket_system/commands/track_set_closed_by.py` 與 `lifecycle.py`，隨 sync 分發。成立。

### 相關 Error Pattern

PC-MON-002（必填不等於有效）；同領域既有 issue #60。

### 查重紀錄

`dedup --keywords set-closed-by closed_by`。關係判定：#60 重複領域（closed_by 值域與框架關閉路徑脫節），以 observe 附加；#55 僅在 auto-commit 修正清單中列出命令名，引用關係，不處置；其餘命中為全文雜訊。
