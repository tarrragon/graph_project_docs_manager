## 重現實驗結果
### 實驗方法

唯讀查詢，不啟動編輯器、不改系統預設。量測環境：macOS 26.5（25F71），本機 mac-eric，2026-11-04。
- `ls /Applications` 列已安裝編輯器
- `lsregister -dump` 計數已註冊 scheme 綁定
- `swift -e` 呼叫 `NSWorkspace.shared.urlForApplication(toOpen:)`：對 `<scheme>://x` 查 handler；對 `CLAUDE.md` 的 file URL 查 .md 預設 app

### 實驗執行

| 查詢 | 結果 |
|------|------|
| vscode:// | /Applications/Visual Studio Code.app |
| vscode-insiders:// | /Applications/Visual Studio Code - Insiders.app |
| cursor:// | /Applications/Cursor.app |
| zed:// | /Applications/Zed.app |
| idea:// | /Applications/Android Studio.app（非 IntelliJ，scheme 被其他 JetBrains 系 app 佔用） |
| subl:// / txmt:// / x-bbedit:// / jetbrains:// | nil（未安裝） |
| .md 預設 app | /Applications/Xcode.app |

### 實驗發現

已驗證：
1. scheme 可唯讀查得 handler；未安裝者回 nil，可作為「scheme 未註冊」的判斷依據
2. .md 預設 app 為 Xcode，不在任何 scheme 對照表內（Xcode 無公開行號 URL scheme）——自動偵測方案在本機即落入失敗退路
3. 一台機器可同時裝多個 scheme 編輯器（本機 4 個），自動偵測無法從 .md 預設 app 推出使用者偏好
4. 同一 scheme 可被非預期 app 佔用（idea:// → Android Studio）

行號語法（官方文件）：
- VS Code：`vscode://file/{絕對路徑}:{line}:{column}`（code.visualstudio.com/docs/configure/command-line「Opening VS Code with URLs」）；Insiders 為 `vscode-insiders://`；Cursor 沿用同格式 `cursor://file/...`（VS Code fork，未見獨立官方文件，屬推斷）
- Sublime Text：無內建 URL scheme；官方 CLI `subl {path}:{line}`（sublimetext.com/docs/command_line.html），`subl://` 需第三方 handler
- TextMate：`txmt://open?url=file://{path}&line={n}&column={m}`（macromates.com/manual/en/using_textmate_from_terminal「url scheme」）
- Zed：`zed://file/{path}:{line}:{column}`（zed.dev/docs，Zed CLI / URL 文件）
- JetBrains：`idea://open?file={path}&line={n}`（jetbrains.com/help/idea/opening-files-from-command-line）

未驗證：上述 scheme 的實際跳轉行為（約束禁止啟動編輯器）；路徑含空白/中文時的 URL 編碼表現。

## Solution
<!-- Schema[ANA/Solution]: 必填（.claude/pm-rules/ticket-body-schema.md） -->
### 方案比較

| 方案 | 使用者行為 | 失敗退路 | 新增面 |
|------|-----------|---------|-------|
| A 設定頁選編輯器 | 設定頁選一次（下拉僅列 handler 查得非 nil 的對照表項 + 「系統預設（不定位）」）；之後點「開啟原始檔」直接跳到行 | 所選 scheme 被移除（handler 變 nil）→ 退回 `/usr/bin/open` 不定位，同列提示「編輯器不可用」；無行號 → 不帶行號 | 設定持久化 1 鍵（編輯器 id）、設定頁 1 列、i18n：選項標籤 + 不可用提示；`ExternalOpener.open(path, {line})` + scheme 對照表 |
| B 自動偵測 .md 預設 app 對應 scheme | 零設定；預設 app 在對照表內才定位 | 預設 app 不在表內（本機實測即為 Xcode）→ 退回 open 不定位，使用者無從得知為何不定位 | 無持久化；需 bundle id→scheme 對照表；不定位原因需常駐說明 i18n |
| C 維持 open 不定位 | 現行行為：開檔，使用者看行號欄自行跳轉 | 無 | 無；SPEC-001 §5「附行號」維持顯示用途 |

建議 A（可預設為「系統預設（不定位）」，等同 C，零設定者行為不變）。理由：實測 B 在本機首例即失效且多編輯器並存時猜不出偏好；A 只在使用者明示時才換行為，失敗退路即 C。

### 事件類行號來源

不採「引用該 EVT 的 FlowStep 所在行」：一個 EVT 可被多個 FlowStep 引用，仍非單一行號；且該行在 UC 檔而非 EVT 原始檔，開的會是另一份檔。建議事件類維持無行號、開啟 EVT 原始檔不定位（SPEC-001 §5 現行「無值時不顯示」不變）；此重評結論待用戶一併裁定。
