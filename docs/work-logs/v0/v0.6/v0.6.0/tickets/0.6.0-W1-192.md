### PM 派發前補料（2026-11-05）

**預設設計方向**（Phase 1 若有更好方案，於 Solution 說明偏離理由）：
- adapter 不直呼 `developer.log`，改經建構子接收既有的 `WorkspaceLogSink`（預設 `_defaultLogSink`）。理由：測試可注入 sink 捕捉日誌，並與既有日誌走同一條投影路徑。

## Solution
<!-- Schema[IMP/Solution]: 選填（.claude/pm-rules/ticket-body-schema.md） -->
三個私有 adapter（`_DefaultWorkspacePreferencesHandle`、`_DefaultWorkspacePreferencesPort`、`_DefaultWorkspaceDirectoryProbePort`）的建構子改為接收 `WorkspaceLogSink`；`WorkspaceRepository` 建構時傳入 `logSink ?? _defaultLogSink`，日誌隨 adapter 實作移動，並沿用既有的 sink 投影路徑。`WorkspaceLogEvent` 新增 5 個值：`adapterProbeExistsResult`、`adapterProbeReadFirstEntryResult`、`adapterPreferencesOpenResult`、`adapterPreferencesReadResult`、`adapterPreferencesWriteResult`。例外以 level 900 附 error 記錄後 rethrow；`writeString` 回 false 時也記 level 900。既有 event 沒有改名或移除。與〈PM 派發前補料〉的設計方向一致，未偏離。

SPEC-005 升為 1.9：§三 G-1、G-2 改記為已修並附測試路徑；§2.3 `exists` 回 false 結果列的 adapter 欄 N 改為 Y；§2.5 對應列同步。
