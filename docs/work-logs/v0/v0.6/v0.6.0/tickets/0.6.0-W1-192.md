### PM 派發前補料（2026-11-05）

**位置**：`lib/workspace/workspace_repository.dart` 的 `_DefaultWorkspacePreferencesHandle`、`_DefaultWorkspacePreferencesPort`、`_DefaultWorkspaceDirectoryProbePort` 三個私有 adapter；全檔唯一的 `developer.log` 呼叫在 `_defaultLogSink`。缺口原文見 `docs/spec/workspace/SPEC-005-workspace-driven-ports.md` §三 G-1、G-2 兩列。

**預設設計方向**（Phase 1 若有更好方案，於 Solution 說明偏離理由）：
- adapter 不直呼 `developer.log`，改經建構子接收既有的 `WorkspaceLogSink`（預設 `_defaultLogSink`）。理由：測試可注入 sink 捕捉日誌，並與既有日誌走同一條投影路徑。
- 新增的日誌點各自對應新的 `WorkspaceLogEvent` 值。測試只斷言 event，不斷言 message，沿用該 enum doc comment 的既有契約。
- 需要記錄的點：probe 的 `exists` 結果、`readFirstEntry` 的結果或例外；Preferences 的 `open`、`readString`、`writeString` 的結果。依觀測性規則 5，平台互動要記 check 入口加結果，例外要附 error。
- 不可讓呼叫端既有的日誌事件消失或改名，因為既有測試綁定這些 event。

**範圍外**：檔案 920 行、超過 300 行閾值，本票不拆分；如需拆分，以 spawn request 回報。

**SPEC 回寫**：§三 G-1、G-2 改記為已修並附測試路徑，§2.3 表格第 199 列 adapter 欄的 N 同步改為 Y，修訂紀錄加一列。docs/spec/ 在 flutter 套件 prefixes 內，合併時會觸發全套件測試。
