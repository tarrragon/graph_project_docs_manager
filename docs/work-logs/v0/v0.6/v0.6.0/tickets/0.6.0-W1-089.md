## Solution
### 變更摘要

- `hooks/layout.ts`：`formatGroupTitle(parts, isOpen)` 改為 `formatGroupToggle(title, isOpen)`，回傳 `▾ <標題>`／`▸ <標題>`；多段以「｜」相接、空段略過的分支移除。
- `hooks/lanesView.tsx`：兩個呼叫端（群組標題列 `frame.title`、佇列細節按鍵 `QUEUE_DETAIL_LABEL`）改呼叫 `formatGroupToggle`，原本包成單一元素陣列的寫法拿掉。輸出字串與改前逐字相同（單一元素陣列 join 後即該元素本身）。
- `tests/layout.test.ts`：鎖多段相接的兩則斷言改為單一標題的展開（`▾ L7 s［busy］`）與收合（`▸ 佇列細節`）兩種輸出，仍是同一則 test。
- `tests/paneHarness.ts`：新增匯出 `Ui`、`Described` 型別與 `childrenOf`、`textOf`、`textsOf`、`headerOf`、`titleOf`；`board.test.ts` 與 `boardDispatch.test.ts` 改為匯入，原檔的對應定義刪除。只有單檔使用的 `bodyOf`、`queueSegmentsOf`、`allDispatchRows`（boardDispatch）與 `displayWidth`、`callLineStatus`、`detailOf`（board）留在原檔。
- 版號：`CHANGELOG.md` 新增 0.12.3 條目，`SKILL.md` metadata.version 0.12.2 → 0.12.3。

### formatQueueRow 的去留（PM 補充，421 審查）

保留。產品碼改由 `queueRowSegments` 分段上色，`formatQueueRow` 只剩 `layout.test.ts` 使用；它定義佇列列整行文字的契約（completed 的票不列、分隔符合併後的整行字串），且 `queueRowSegments` 的測試以「各段相接即 formatQueueRow 的票序」驗證兩者一致。移除它就得把這組整行文字斷言改寫成分段相接，契約失去單一的權威表達。已在其 JSDoc 補一句寫明「產品碼不呼叫、保留作為整行文字契約、layout.test.ts 以它鎖定」。

### 兩份實作的差異與選擇

| 函式 | board.test.ts 版本 | boardDispatch.test.ts 版本 | 選用 |
|------|------------------|--------------------------|------|
| 抽文字 | `textLines`：Text 只取陣列形態子節點中的字串，內嵌 Text 的文字略過；子節點為單一字串（非陣列）時取得空字串 | `textsOf`（搭配 `textOf`／`childrenOf`）：單一字串子節點也包成陣列，內嵌 Text（佇列列各票分段）的文字遞迴相接 | `textsOf` |
| `titleOf` | 直接 `ui.find` Button 取 `.text`，標題 Box 以 `textLines` 抽文字 | 經 `headerOf` 取 Button `.text`，標題 Box 以 `textsOf` 抽文字 | boardDispatch 版 |

選 boardDispatch 版的理由：它是 board 版的超集合，board 版能取得的文字它都取得；差異只在內嵌 Text 與單一字串子節點，board.test.ts 的斷言對象（標題 Box 的目標、活動計數各行，佇列細節各行）在改前已以 board 版取得完整文字，改用超集合後兩檔既有測試全數通過（338 pass，見 Test Results），證實 board.test.ts 斷言的節點不含這兩種形態。
