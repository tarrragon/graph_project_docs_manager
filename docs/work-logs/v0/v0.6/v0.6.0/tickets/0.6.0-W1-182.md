# Execution Log

## Task Summary

append-log 的 H2→H3 自動降級跳過 fenced code block 內的行

---

## Problem Analysis
### 問題根因

`track_acceptance.py` 的 append-log 以 `re.sub(r'(?m)^## ', '### ', content)` 降級，不認 fenced code block，fence 內的 markdown 範本被改壞。

### 影響範圍

票面 why 的前提「程式碼區塊內的行不會被解析為章節」實測不成立：`section_locator.find_section` 與 acceptance checker 的 `^## Solution\s*\n(.*?)(?=^## |\Z)` 皆在 fence 內的 `## ` 處截斷 Solution。降級因此是讀取端缺陷的補償；票面 strategy（只讓降級跳過 fence）單獨落地會使 Solution 必填驗證與 acceptance checker 讀到截斷內容。讀取端另有十餘處各自的 `^## ` regex（validator、context_bundle_extractor、handoff、track_dispatch、acceptance_checkers 等）。

### 框架問題兩條 AND 判準

1. 抽象可攜：任何 consumer 以 append-log 寫入含 fenced `## ` 的內容皆重現，與專案內容無關。成立。
2. 根源在 `.claude/` 通用資產：`.claude/skills/ticket/ticket_system/` 與 `.claude/hooks/acceptance_checkers/`。成立。

### 相關 Error Pattern

無直接對應；同領域既有觀測 tarrragon/claude#55 issuecomment-6543093317（find_section 不認 fence）。

### 查重紀錄

`dedup --keywords append-log section_locator fenced 降級`。關係判定：#55 重複領域（同一缺陷的讀取端已觀測於該 issue），以 observe 附加；#33／#61／#80 為 append-log 其他缺陷，引用關係不處置；其餘為全文雜訊。
