## 重現實驗結果
### 實驗方法

- 指令：`claude plugin test <dir>`，`<dir>` 為 repo 內 `.claude/skills/line-board`（in）或 scratchpad `092/line-board`（out，同一份 HEAD 的 git archive）
- 每輪記錄：開始與結束時的 load1（`sysctl -n vm.loadavg`）、結束碼、耗時、`(fail)` 測試名與所在檔；每個 Pane 測試的耗時取自測試輸出的 `[N ms]`
- 順序：每組 5 對，前 3 對 in→out、後 2 對 out→in
- 三組：baseline 不加壓；加壓一 16 個 `yes > /dev/null`；加壓二 32 個（8 核機）。加壓程序以 PID 記錄並以 `kill <PID>` 結束，結束後以 `pgrep -l yes` 確認
- Pane 測試範圍：board、boardDispatch、boardQueue、boardUserTodos、boardLaneContext、boardContextUsage 共 6 檔、65 個測試（每輪輸出 73 筆含 describe 前置的專案設定測試）

### 實驗執行

- baseline 07:45–07:47，load1 22–27（其他 session 的背景負載），10/10 綠
- 加壓一 07:47:43–07:53:40，load1 33–48，10/10 綠，Pane 單測最大值 3907 ms
- 加壓二 07:54:05–08:03:00，load1 57–119（加壓再疊上其他 session 負載），9/10 綠；07:59:16 起的 out 輪 2 fail：
  - `board.test.ts`「Pane > 各 session：只列本 repo（含 worktree）且 pid 存活者…」5157 ms，`timed out after 5000 ms`
  - `boardQueue.test.ts`「Pane > 佇列細節：有佇列列的線群組各有一個細節按鍵…」5080 ms，`timed out after 5000 ms`
- 其餘 9 輪的 Pane 單測最大值 2476–4315 ms，距 5000 ms 只差 15–50%

### 實驗發現

已驗證：
1. 逾時的成因是負載：Pane 單測平均耗時從 baseline 約 375 ms（非首測）上升到加壓二的約 1231 ms，約 3 倍；最大值從約 1.6–3.3 s 升到 4–5.2 s。只有加壓二重現逾時，與 10-28 觀測（load 約 60 時 5 輪中 3 輪紅）的方向一致
2. 每檔首個 Pane 測試有固定的冷啟動成本：首測平均 1277／1849／2727 ms，非首測平均 375／826／1231 ms（baseline／加壓一／加壓二），首測約為非首測的 2.2–3.4 倍。本次 2 個逾時都是該檔的首測；但 10-28 觀測有非首測逾時，所以首測只是最先撞線，不是逾時的唯一落點
3. 位置（`.claude/` 內外）不影響結果，見 Problem Analysis〈位置對照結論〉
4. 主要耗時步驟：每個 Pane 測試都呼叫一次 `startBoard`，依序執行 `session.start`、`clock.advance(1)` 觸發第一次 refresh，再 `ui.mount` 渲染。refresh 期間走 test 端 hook 的 `process.run`（git worktree list、協調票 CLI、每個 pid 一次 `ps`）與 `fs.list`／`fs.read`（7 個狀態檔、票檔），每一次都是 engine 與 hook 的往返。harness 沒有自訂等待條件，`ui.find` 直接查描述樹。所以耗時隨往返次數與 CPU 排程延遲成正比。帶 `sessionStub` 的測試（約 1 s 起跳）明顯比不掛狀態檔的專案設定測試（約 140–180 ms）慢

未驗證：
- 首測冷啟動成本的具體構成（模組載入或 engine 首次初始化）沒有拆開量測
- 逾時的確切 load 門檻：介於 48（無逾時）與 88（重現）之間，沒有更細的取樣
