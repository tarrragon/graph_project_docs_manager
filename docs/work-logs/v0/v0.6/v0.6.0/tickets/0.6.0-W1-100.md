## Problem Analysis
### 問題根因

讀協調票的消費者全部從單一手寫狀態取票號：`.claude/project-integration/multi-session.json` 的 `coordinationTicket`，statusline 另在 `settings.local.json` 的命令列寫死 `--coord-ticket <票檔路徑>`。協調票的生命週期（版本開工建立、版本收尾結案）沒有任何機制回寫這兩處，所以換版時兩處都停在舊票，直到有人手動修改。實測 2026-11-02：設定仍為 `0.5.0-W1-349`（status: completed），現行協調票為 `0.6.0-W1-099`（status: in_progress）。

### 影響範圍

消費者清單（主 checkout，排除 `.claude/worktrees/` 副本），grep `coordinationTicket|coord-ticket|multi-session\.json`：

| 消費者 | 讀取點 | 現況後果（實測） |
|--------|--------|------------------|
| line-board 看板 | `hooks/readers.ts` `readProjectConfig`／`readLanes`，`hooks/shared.ts` `parseProjectConfig`，`hooks/register.tsx` refresh | 看板分群讀 349，0.6.0 的線與用戶待辦不顯示 |
| line-board `line_status` | `hooks/lineStatus.ts` 經 `readLaneLines` | L48–L51 不列，各線查不到 ctx 段（主控補充） |
| line-board 接續流程 | `hooks/resumeFlow.ts` | 接續時讀 349 的線 |
| 看板設定錯誤畫面 | `hooks/lanesView.tsx` `PROJECT_CONFIG_FORMAT` | 只提示手動填設定 |
| statusline 線號 | `multi-session-orchestration/scripts/statusline_lane.py`（`--coord-ticket` 或 `coord_ticket_from_config`），命令寫在 `.claude/settings.local.json` | 名稱「協調票解析」對 349 只印名稱；對 099 印 `L50 │ 協調票解析` |
| 主控接續提示 | `multi-session-orchestration/scripts/master_resume_hint.py` `coordination_ticket` | 指示主控讀 349 |
| 佇列行檢查 hook | `.claude/hooks/coordination-queue-line-check-hook.py` `read_coordination_ticket` | 寫入 099 時 hook 靜默不檢查（rc=0、無輸出） |

文件端同步點：`line-board/SKILL.md`、`line-board/references/board-screens.md`、`multi-session-orchestration/references/session-naming.md`、`references/line-continuity.md`。測試：`line-board/tests/{shared,board,continuity,boardDispatch}.test.ts`、`paneHarness.ts`、`multi-session-orchestration/tests/test_{statusline_lane,master_resume_hint}.py`、`hooks/tests/test_coordination_queue_line_check_hook.py`。

### 相關 Error Pattern

同型：手寫狀態與實際生命週期無同步邊（設定值不隨源頭變動而失效）。本票不另建 error-pattern，修法即移除該手寫狀態。

### 標記穩定性查證

標題不是穩定標記：349 標題為「盤點 0.5.0 進行中與待辦票的任務線，分配給兩個同儕 session」，099 為「協調 0.6.0 任務線分配與多 session 協調」。全票庫無既有的 `coordination`／`tags`／`role` frontmatter 欄位。`ticket_system/lib/parser.py` `save_ticket` 以 `yaml.dump` 全量序列化，自訂欄位會保留。

### 框架問題判準

(1) 抽象可攜：任何使用 line-board／multi-session-orchestration 的 consumer 換版時都要手改同兩處，替換專案名後仍成立。成立。(2) 根源在 `.claude/` 通用資產：全部消費者在 line-board skill、multi-session-orchestration skill 與通用 hook。成立。屬框架問題；本專案為主控方，就地修。查重見下節，無同主題 issue；新開 issue 須逐次授權，未開。
