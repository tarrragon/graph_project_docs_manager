### 做法與取捨

採建議做法：acceptance-gate 在原 fast-path（非 complete 命令）改為進 `_handle_close_command`，以 `find_ticket_track_invocations(command, ("close",))` 辨識 close，只對這些票執行 `check_unpaired_user_todos(..., action="close")`，不套用 complete 的其他步驟。未採 lifecycle.close 內呼叫 checker：會讓 ticket CLI 依賴 multi-session-orchestration scripts，耦合較重。checker 新增 `action` 參數（預設 complete，既有訊息不變）。

改動檔案：`.claude/hooks/acceptance_checkers/coordination_todo_checker.py`、`.claude/skills/ticket/hooks/acceptance-gate-hook.py`、新增 `.claude/hooks/tests/test_acceptance_gate_close_coordination.py`。

### 失敗語意

fail-open（放行）。觸發條件：close 命令無法解析（未閉合引號、管線或 here-string 餵 stdin shell、巢狀過深）；close 的目標票檔找不到或讀取失敗（寫 logger 與 stderr）；coordination_ticket 匯入或 parse_user_todos 拋例外（既有 checker 語意）。close 非危險操作，誤擋所有無法解析的 Bash 代價高於漏擋。
