## Problem Analysis
### 問題根因

0.5.0-W1-338.3 判定（見該票 Solution）：worktree_manager.py 的同檔競爭集中在隔離索引 CAS 引擎（238、231 兩棵票樹改過），且待辦的 328 需要其中的 `_compute_merge_tree`。本票把 CAS 引擎搬到 `scripts/merge_cas.py`，只做純搬移。

### 影響範圍

- 搬移範圍：`worktree_manager.py` 的〈隔離索引 CAS 合併〉段落，從段首註解到 `merge_branch_cas` 結尾（約 283 行），包含 `CheckResult`、`PreMergeCheck`、`MergeOutcome`、`_git_raw` 到 `merge_branch_cas`，以及 `_sleep`／`_clock` 接縫與 `_RETRY_*` 常數
- 留在 worktree_manager：`cmd_merge`、`_compose_merge_message`、`_merge_through_gate`、`_print_merge_outcome`（呼叫 merge_cas 的 `_verify_three_planes`）
- 搬出段落的外部依賴：`DEFAULT_BASE_BRANCH`、`get_project_root`、`MergeMessages`。新模組沿用 `try: from .x` / `except ImportError: from x` 的雙路 import
- 位置鎖定的 patch（必須改指 merge_cas）：
  - `tests/test_merge_gate.py` 的 `repo` fixture：`wm._sleep`
  - `instrument`：`wm._prepare_candidate`、`wm._git_raw`
  - `tests/test_worktree_merge_entry.py`、`tests/test_worktree_merge_cas.py` 的 fixture：`wm._sleep`
- `_sleep`／`_clock` 不 re-export（file-split-by-contention §3.3：可變的注入點只留在單一模組，否則 patch 舊名稱照樣成功卻沒生效）
- `merge_branch_cas` 在 repo=None 時呼叫 `get_project_root`，搬移後由 merge_cas 的命名空間查找，patch `wm.get_project_root` 對它無效。二擇一，並在 Solution 寫明選哪一種：呼叫端一律明確傳 repo，或測試改 patch merge_cas
- 文件：`merge_gate.py` 模組 docstring 與 `GateVerdict` docstring、`references/subcommands.md` 的程式入口，都要改寫為 `merge_cas.merge_branch_cas`
- 不在範圍內：GateVerdict 收斂為 CheckResult（另開 0.5.0-W1-351）
