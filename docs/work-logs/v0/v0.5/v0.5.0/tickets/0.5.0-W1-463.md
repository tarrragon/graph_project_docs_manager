## Problem Analysis
<!-- Schema[ANA/Problem Analysis]: 必填（.claude/pm-rules/ticket-body-schema.md） -->

### 問題根因

`.claude/skills/error-pattern/lib/allocator.py` 的 `_max_num_in_ticket_references` 掃 `docs/work-logs/**/tickets/*.md` **全部**票（不分狀態）中本專案精確前綴 `<CAT>-<PROJ>-NNN` 的字面，取最大號併入配號（設計來源：防 ticket 預留編號與 allocator 競爭，見該模組 docstring）。掃描不區分「預留編號」與「歷史記錄中出現的字面」。

本例：已完成票 0.5.0-W1-306.8 的驗收條件與 Solution 記錄了觸發驗證用的探針檔 `TEST-GPD-999-live-trigger-probe.md`（暫置後刪除）。L18 配號時 TEST-GPD 檔案最大為 006，但票面字面 999 被計入，配出 TEST-GPD-1000（d627a5209，已在 origin/main，README 已有索引列）。

### 影響範圍

- 已驗證：TEST-GPD 類下一號為 1001；306.8 的 999 字面仍在，即使把 1000 改回 007，下一次配號仍會得到 1000。
- 已驗證：306.8 的字面是實地觸發驗證的事實記錄（含日誌行引用），不是佔位或舉例，不改寫。
- 機制推論：任何 consumer 在票面記錄探針、範例或大號佔位的同前綴字面，都會使該類編號永久跳升；跳升只影響編號連續性，不造成撞號或配號失敗。

### 主控裁定（2026-10-21）

| 問題 | 裁定 | 理由 |
|---|---|---|
| 觀測進 issue | 是，observe 進 #52 | 符合兩條判準（下節）；非 P0/P1 阻擋，依節奏裁示不派修 |
| TEST-GPD-1000 改回 007 | 不改 | 編號是識別符，跳號無功能損害；改號要動 `.claude/` 檔名與 README 並走 worktree，且 allocator 未修前下一號仍會再跳到 1000，改了也擋不住再發生 |
| 306.8 字面改寫或加豁免 | 不改 | 屬事實記錄；修正點在 allocator 的掃描判準，不在票面 |

### 框架問題兩條判準（逐條套用）

1. **抽象可攜**：成立。換掉專案名與票號後，「配號掃描把票面歷史字面當預留編號，導致編號跳升」在任何以本框架票系統記錄 error-pattern 驗證過程的 consumer 都可重現。
2. **根源在 `.claude/` 通用資產**：成立。根因在 `.claude/skills/error-pattern/lib/allocator.py` 的掃描判準，隨 sync 傳到所有 consumer。
