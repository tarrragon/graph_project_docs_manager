### 實例（E 線，2026-10-15）：ticket_command_parse.py

- 通知標題：「Commit security review found: fail-open / security check bypass in .claude/lib/ticket_command_parse.py」。內文只有 connector 停用警告，沒有位置與觸發方式。相關 commit：0.5.0-W1-286.1（3da647b85，已合併）與 0.5.0-W1-302（956b153a4，通知當時在閘門排隊，之後合併為 f0c6606dd）。
- 狀態：已自查、未取得原文、未判誤報。
- PM 自查的三條路徑與結論：
  1. 0.5.0-W1-294 的 -h／--help 排除（is_help_only）：token 須完全等於 -h 或 --help 且在單獨的 -- 之前；`--as --help` 會被 argparse 報錯不執行 complete；`--` 之後的 --help 不排除；`--help=foo` 與 `-hv` 不等於兩者，仍辨識為 complete。未找到繞過。
  2. 解析失敗回 None：實測「ticket track complete X # it's done」與換行後的註解含引號，解析器皆回 True（註解處理正確）；真正未閉合的引號回 None，但 shell 本身也會因語法錯誤不執行。acceptance-gate 收到 None 時退回原文字面比對（_legacy_complete_substring 與 _RAW_COMPLETE_VERB_RE），屬 fail-closed，只會多擋。未找到繞過。
  3. 286.1 與 302 的 is_invocation_masked：只用於完成類 hook 的成功判定，不是安全檢查；設計方向是無法判定時保守判為遮蔽或回 None 退回標記判定。不屬安全檢查範圍。

### 第 5 例：276.4 的 parser-differential / gate bypass（F 線，2026-10-15）

- 收到內容：推送後背景安全審查只送達標題「parser-differential / gate bypass in .claude/hooks/acceptance_checkers/hook_protection_acceptance_checker.py」，由 D 線轉來，歸屬 276.4（fa4dd7e83）。
- 假設（D 線推測）：tests 排除只比對前綴，可能用 `tests/../`、`./` 前綴、symlink 繞過。
- 查證方式：比照 120.7.9.5.10，在 276.4 合併前的 detached worktree（fa4dd7e83^1）與現行 main 上，以同一組 8 筆路徑呼叫 touches_hook_protection_scope 比對結果。
- 結果：**命中，且是 276.4 引入的 regression**。`.claude/hooks/tests/../foo-hook.py`、`.claude/hooks/tests/../../hooks/foo-hook.py`、`.claude/skills/ticket/hooks/tests/../agent-dispatch-validation-hook.py` 三筆，在舊版為 True、現行為 False。成因是 PurePosixPath 不解析「..」。`./` 前綴與 `//` 兩種寫法現行判 False 是正確的，因為它們確實是測試檔。symlink 屬純路徑判斷無法偵測的另一形態，尚未實測。
- 處置：建 P1 子票 0.5.0-W1-276.7（先 normpath，再處理 realpath 與 symlink，跳出專案根時 fail-closed）。
- 成本觀察：假設在第一輪即命中，查證約 5 個命令。若審查細節有送達，本例可以省去「推測繞過形態」這一步。
### 第 6 例：284.2 的 redos-guard-bypass（F 線，2026-10-15 19:5x）

- 收到內容：推送 284.2（44b0b193d）後，背景安全審查只送達標題「redos-guard-bypass in .claude/hooks/bash-write-boundary-guard-hook.py」。
- 假設：新加入的 sed 正則在特製長輸入上回溯過量，hook 逾時後放行。
- 查證：
  - 對新版 `_extract_candidate_paths` 量測 4 種重複形態（短段反覆），都沒有指數爆炸。
  - 改測「大量 sed 字樣」形態，耗時呈平方級：128KB 27.9s、192KB 43.4s。
  - 從 git 取出 284.2 之前的版本，同兩組輸入只要 0.004s、0.008s。
  - 這支 hook 沒有宣告 fail_closed，分派器逾時時回 exit 1，也就是放行。
- 結果：命中，且是 284.2 引入的 regression。已建 P1 子票 0.5.0-W1-284.3 並派發。
- 成本觀察：第一輪假設（指數回溯）落空，第二輪（逐位置前瞻造成平方級）才命中。共 4 個量測命令，加上確認逾時語意。如果審查細節有送達，第一輪就能直接打中。
