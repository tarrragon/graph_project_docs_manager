## Problem Analysis
<!-- Schema[ANA/Problem Analysis]: 必填（.claude/pm-rules/ticket-body-schema.md） -->
### 問題根因

同一個畫面層在不同載體有四種寫法：目錄 `ui`、SPEC 的 `domain: ui`、EVT 保留字 `presentation`、system-layer 的「L4 畫面狀態」。其中兩個名稱有行為意義：
- `ui`：spec 覆蓋檢查據此判定層級 SPEC。
- `presentation`：lib 的事件類破洞判定據此分流。

兩者都只靠「目前沒有同名的已宣告 domain」才成立，沒有守衛。

### 影響範圍

- SPEC-001～004 的覆蓋判定。
- EVT-LAYOUT-001、EVT-SCHEMA-002、EVT-DIAGNOSTICS-001 的 consumers 判定。
- `lib/diagnostics/event_gap.dart`。
- `.claude/skills/spec/scripts/domain_coverage/map_locate.py`。

逐項位置見 Solution〈盤點結果〉。

## Solution
<!-- Schema[ANA/Solution]: 必填（.claude/pm-rules/ticket-body-schema.md） -->
### 盤點結果（2026-10-31，L34）

#### 一、四個名稱的出現位置與消費端

| 名稱 | 出現位置 | 消費端 | 值是否有行為意義 |
|---|---|---|---|
| 目錄 `ui` | `docs/spec/ui/`（SPEC-001～004 與 audit/） | 人工導航；doc CLI 依路徑讀取，不依目錄名分流 | 否 |
| SPEC frontmatter `domain: "ui"` | SPEC-001、002、003、004，共 4 份 | `.claude/skills/spec/scripts/domain_coverage/map_locate.py` 的 `is_layer_spec`：domain 欄不在已宣告 DomainBundle 集合內時，判為層級 SPEC，改以 `docs/system-layer.md` 判定覆蓋。`layer_banner` 會把這個值印出 | 有。只看「是否等於某個已宣告 domain」，不看字面是否為 `ui` |
| 保留字 `presentation` | EVT consumers：EVT-LAYOUT-001、EVT-SCHEMA-002、EVT-DIAGNOSTICS-001；規格 SPEC-003〈`presentation` 本地保留字〉、SPEC-001 §2／§5 鏡像、SPEC-004 4.0.6；`docs/spec/layout/domain-map.md`、`docs/spec/diagnostics/domain-map.md`、`docs/system-layer.md` §6 | `lib/diagnostics/event_gap.dart` 的常數 `presentationReservedWord`，以精確比對判定 consumers 是否改比對 `traverses == []` 的步驟。上游 doc validate 只檢查 consumers 是否為空，不檢查值 | 有。字面寫死在 lib 與規格 |
| L4 畫面狀態 | `docs/system-layer.md` §2（L4 圖與 2.1）、§3 仲裁點表、§7 FR 歸屬表（「L4 畫面狀態（非 domain）」）；lib 對應 `components/`、`app/`、`screens/`、`assembly/` | 人工閱讀，以及 domain 覆蓋檢查讀系統層的 FR 歸屬表（以 FR 號比對，不比對「L4」字面） | 否 |

補充：
- 泳道「畫面」列在 lib 是 `ScreenLane`（`lib/layout/lane_order.dart`）與 `DomainLaneKind`（`lib/app/domain_view_state.dart`）。顯示名走 i18n key `swimlaneScreenLaneName`（zh 畫面／en Screen），lib 不使用 `presentation` 字面。
- 現有已宣告 domain 共 8 個：corpus、diagnostics、graph、history、layout、schema、ticketdetail、workspace。`ui` 與 `presentation` 都不在其中，現況沒有衝突。

#### 二、可能出錯的條件

兩個保留值都靠「不等於任何已宣告 domain」才成立，但沒有任何守衛擋住同名宣告：
- 若日後新增名為 `ui` 的 DomainBundle：SPEC-001～004 會從層級 SPEC 改判為 domain SPEC，覆蓋檢查改走該 map，輸出不會有任何提示。
- 若日後新增名為 `presentation` 的 DomainBundle：event_gap 的保留字分支先於 domain 比對，該 domain 在 consumers 的值永遠走保留字路徑。

#### 三、候選與改動面

| 候選 | 作法 | 改動面 |
|---|---|---|
| K1 維持四名，補守衛 | 四個名稱不改。doc validate（或 spec 覆蓋檢查）拒絕宣告名為 `ui`、`presentation` 的 DomainBundle，並在 system-layer §2 寫明四者的對應關係 | 框架：doc 或 spec 腳本加一條檢查與測試，屬 `.claude/` 資產，依框架修補節奏處理。專案：system-layer 加一段 |
| K2 SPEC domain 欄改為 `presentation` | 4 份 SPEC 的 `domain:` 改為 `presentation`，與 EVT 保留字統一；目錄 `ui` 不動 | 4 份 SPEC frontmatter；覆蓋檢查行為不變（仍不在宣告集合內）；不需改 lib |
| K3 全部統一為 `presentation` | 同 K2，另把目錄 `docs/spec/ui/` 改名為 `docs/spec/presentation/` | 目錄改名會牽動全專案對 `docs/spec/ui/` 的引用（CLAUDE.md、tech-decisions、traceability、票面、ARB description 等），引用穩定成本高 |
| K4 不處理 | 維持現況，不加守衛 | 無；上節兩個出錯條件繼續存在，且出錯時沒有訊號 |

傾向：K1。四個名稱各有消費端，語意層次也不同（目錄、SPEC 分類、資料保留字、架構層），統一寫法無法消除實際風險；實際風險是同名宣告時靜默改判，加守衛才擋得住。K2 可以和 K1 並行做，但只帶來寫法一致，不降低風險。
