### 實驗發現

已驗證的事實：
- 改名入口有兩個：啟動旗標 `claude -n/--name <name>`，以及 session 內的 `/rename <name>`（別名 `/name`）。後者只能由用戶輸入。
- `/rename` 之後，sessions 檔的 name 立即改寫、`nameSource=user`，ListAgents 改用新名，ref（136408）不變。
- 新名可以立即定址。舊名立即失效：SendMessage 回錯誤，建議清單也不含新名，所以送訊方無法從錯誤訊息找到改名後的 session。

## Solution

### 分析結論（L14／session-naming，2026-10-20）

1. **改名機制可行，但只能由用戶或啟動參數做**：入口有兩個，`claude -n <名稱>` 和 `/rename <名稱>`，模型無法自行改名。改名後新名立即可以定址；舊名立即失效，錯誤訊息也不提示新名。衍生名稱跟著行程走，同一行程內 `/clear` 不換名。實測見〈重現實驗結果〉。
2. **規則草案**：已寫在 `feat/0.5.0-W1-411` 分支，c9f4a9937，尚未合併，等主控審閱。
   - 新增 `references/session-naming.md`：規則三條，改名方法，改名後的同步位置（告知主控、更新現行佇列行、轉知有往來的線），換 session 的步驟，升版後的確認方式。
   - SKILL.md：分線表、按需讀取、檢查清單各加一列，版本升到 1.6.0。
3. **協調票格式的對應調整**：現行佇列行的格式不變，括號內改填線主題名即可。解析規則 `（([^）]*)）` 接受任意名稱，但看板是以名稱精確比對線與 session，所以改名當下主控必須追加一行新的現行佇列行。
4. **狀態列方案定案為候選 A**：見下方比較，實作交 0.5.0-W1-411.1。
