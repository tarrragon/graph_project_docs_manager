## Problem Analysis
<!-- Schema[IMP/Problem Analysis]: 選填（小型 IMP 可留 placeholder；大型 IMP 建議填寫）（.claude/pm-rules/ticket-body-schema.md） -->
### 經驗萃取評估（PM，2026-10-19）

可抽象的模式：守衛以「執行者所在位置」（cwd 所屬 checkout）推導判定範圍，而非以「目標所在位置」推導；測試 fixture 只用守衛預設的版面（cwd=worktree、.claude/worktrees/），與實際派發版面（主 checkout cwd + 同層 worktree 絕對路徑）不同，故全綠仍無鑑別力。與 IMP-GPD-006（以某條路徑的副產物判定）同屬「守衛只在自己假設的路徑上被驗證」家族。處置：本票 Phase 4 判定是新增 error-pattern 或併為 IMP-GPD-006 的變體，結論寫入 Solution；不在本票以外另行建檔。

### error-pattern 候選（主控 2026-10-19）

候選模式：守衛的保護範圍由實作者推定的部署版面決定（此處 cwd 所在 checkout 與 `.claude/worktrees/`），單元測試與合併後實測都在同一個推定版面上進行，綠燈只證明「守衛擋得住它認得的路徑」，未證明「它認得的路徑涵蓋實際工作位置」；實際派發工具的預設版面（主 checkout 同層 `<repo>-<ticket>`）不在範圍內，且放行不留紀錄，缺口只靠執行者自行回報才被發現。收尾時判定是否跨專案可重現，成立則 `/error-pattern add`，先查重 IMP-GPD-006（守衛依產生路徑的副產物判定）是否同族
### 設計輸入（PM，2026-10-19，派發前）

- 反方向同樣缺口：cwd 在 sibling worktree、以絕對路徑寫主 checkout 的 lib/、test/、.claude/** 時，_scope_roots 只含該 worktree，同樣放行。修法以「目標路徑自身所屬 checkout」判定即可同時涵蓋兩方向，需各有一筆 E2 測試。
- 目標檔可能尚未存在：自 dirname 向上找第一個存在的祖先，再找含 .git（目錄或 gitlink 檔）的 checkout 根；先 realpath 解析 symlink。
- 同 repo 判定：比對兩個 checkout 的 git common dir（gitlink 檔指向 <main>/.git/worktrees/<name>，其 commondir 回到 <main>/.git），不呼叫 git 子行程（守衛在 PreToolUse 熱路徑，且 fail_closed）。解析失敗時的取向寫入 Solution。
- 用戶裁定的合併條件（經主控，2026-10-19）：屬收緊方向，合併前回報主控即可；若會連帶擋到 worktree create、合併閘門建快照（.claude/worktrees/merge-gate-*）等例行作業，合併前先回報。兩者都要有放行測試鎖住（E1）。
Phase 4 error-pattern 判定時，一併比對 IMP-GPD-006（以路徑副產物判定）與 IMP-GPD-008（git 全域選項使正則比對失效，b2c44e5b2），判定是否同類後決定新增或併為變體（主控轉知，2026-10-19）。
