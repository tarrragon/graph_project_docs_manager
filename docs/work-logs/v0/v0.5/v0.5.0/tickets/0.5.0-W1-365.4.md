## Solution
<!-- Schema[IMP/Solution]: 選填（.claude/pm-rules/ticket-body-schema.md） -->
資料結構：env 為 name -> frozenset(Optional[str])，None 代表可能無法判定。必然執行賦值取代集合；不確定賦值（子殼、管線、&&／||、背景、複合命令內）併入既有集合（原未知併入 None）。複合命令以陳述開頭的 if／while／until／for／select／case／{ 開啟、fi／done／esac／} 結束的深度計數判定，then／else／elif／do 等子句字先剝除再辨識賦值（涵蓋換行分隔與同行 then F=x）。值內 $VAR、~、HOME、CLAUDE_PROJECT_DIR 於賦值當下依當時集合展開；HOME／CLAUDE_PROJECT_DIR 另保留展開前形式（真實值檢查維持）。使用處（重導向目標、命令 token、python argv）以 _expand_all 對所有組合展開；組合上限 _MAX_COMBINATIONS=16，超限（或集合大小超限）以替身候選 lib/_bash_guard_combination_overflow 取代，必然命中受限範圍。
E2：F=lib/a; false && F=/tmp/x、||、管線、子殼、背景變形；HOME=<repo>; D=~/lib; HOME=/tmp、$HOME 版；換行 if／while／case／函式本體／for 與同行 then 變形；python argv 變形，修正後皆 deny。E1：F=lib/a; F=/tmp/x 放行；複合命令結束後的賦值仍為必然；CLAUDE_PROJECT_DIR 換行 if 維持擋；組合數 27 擋下、4 放行。
既有測試調整一筆：test_uncertain_plain_assignment_is_unresolvable 原斷言「(F=lib/a); echo x > $F 放行並記 unresolvable」，依新規格改為 deny lib/a。
文件反查（381）：SKILL、references、pm-rules 內 grep 「&&／||／管線後賦值接寫入」「賦值; 寫入受限路徑」「HOME／CLAUDE_PROJECT_DIR=...;」三式，結果：無。
