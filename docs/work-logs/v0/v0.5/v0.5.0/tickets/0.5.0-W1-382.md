## Problem Analysis
<!-- Schema[IMP/Problem Analysis]: 選填（小型 IMP 可留 placeholder；大型 IMP 建議填寫）（.claude/pm-rules/ticket-body-schema.md） -->
經驗萃取評估（L9 PM，2026-10-20）：本缺陷與 IMP-GPD-006「變體：以執行者的位置推導判定範圍」同族——守衛的前提假設了一種 worktree 版面（repo 外 /tmp），框架標準版面（主 checkout 同層 <repo>-<ticket>）不符該假設。Phase 4 判定時與 IMP-GPD-006 該變體比對，傾向補為同一變體的第二例，而非新建。

第二次重現（PM，2026-10-20）：派發本票時，prompt 以文字列出測試範例（家目錄佔位路徑與系統暫存目錄下 worktree 的 .claude 路徑）即被本 hook 以 ARCH-015 阻擋，改為不列字面路徑、指向票面 how.strategy 後派發成功。本缺陷會阻擋其自身修正的派發，E1 測試應涵蓋「prompt 文字中描述範例路徑」的情境。
## Solution
<!-- Schema[IMP/Solution]: 選填（.claude/pm-rules/ticket-body-schema.md） -->
共用模組：.claude/lib/checkout_identity.py（common_dir／same_repo／owning_checkout_root，自 bash-write-boundary-guard-hook 搬出，該 hook 以別名 import，行為零變更）。
agent-dispatch-validation-hook：佔位字樣（三點、省略號、角括號）略過；同 repo 且與目前 checkout 同父目錄的 checkout 視為非外部。同 repo 但在 repo 外（系統暫存目錄）的 worktree 照擋（ARCH-015 runtime 拒絕該位置）。
判定失敗落擋下側：owning_checkout_root 回 None、common_dir 解析失敗（gitlink 指向不存在）、project root 不可解析，皆回 False，維持 external；對應測試 test_nonexistent_path_stays_external、test_unresolvable_common_dir_stays_external、test_project_root_unresolvable_stays_external。
E2：test_worktree_outside_repo_still_external（同 repo repo 外 worktree）、test_unrelated_repo_claude_still_external。
