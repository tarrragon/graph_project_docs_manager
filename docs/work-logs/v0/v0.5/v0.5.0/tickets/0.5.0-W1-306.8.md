## Solution
<!-- Schema[IMP/Solution]: 選填（.claude/pm-rules/ticket-body-schema.md） -->
### 受眾裁定與輸出管道

| hook | 裁定 | 理由 | 管道 |
|------|------|------|------|
| error-patterns-index-consistency-check | 模型可見（僅可行動發現） | 索引缺漏、過時條目、未登記碰撞、README 重複列可由模型直接修。原輸出 2644 位元組，內容多為已登記碰撞 INFO 與 81 組 related 單向引用建議（存量、非可行動），每次開 session 注入不值得；改只注入可行動類，其餘進日誌 | stdout JSON additionalContext（SessionStart） |
| skill-body-size-check | 僅用戶可見，維持現狀 | 13 支 SKILL.md 超標是長期維護待辦，單一 session 無可行動修正，每次注入約 150 token 屬純雜訊 | 不變（stderr） |
| spec-version-consistency-check | 模型可見 | 版號漂移是明確缺陷，模型可直接對齊；一致時零輸出，平時零成本 | additionalContext |
| memory-dir-audit | 模型可見 | 訊息本文即「需要你主動處理」搬遷指示，受眾本就是模型 | additionalContext，event 取自 input（SessionStart/Stop） |

### 原輸出紀錄（改寫前，本 worktree 實跑，SessionStart）
- error-patterns-index: stdout 0 位元組，stderr 2644 位元組（INFO 6 組已登記碰撞 + WARNING 81 組 related 單向），exit 0，無決策欄位
- skill-body-size: stdout 0，stderr 約 330 位元組（SkillBodySize 13 支超標，列前 5），exit 0
- spec-version: stdout 0、stderr 0（現況一致）
- memory-dir-audit: 原為 print(AUDIT_MESSAGE, file=stderr)，exit 0，無決策欄位
改寫後每次最多輸出一份 JSON（emit_model_reminder 單次呼叫）；例外路徑「檢查異常」仍走 stderr（hook 失敗須對用戶可見，規則 4）。

### Stop 註冊處理（memory-dir-audit）
Stop 事件的 additionalContext 會讓模型續跑。此處為預期行為：訊息要求模型搬遷 memory 內容；marker 無條件更新，同一變化不重複觸發，不會迴圈。已記錄，不拆分 hook。

### 實地觸發方式與要避開的提早返回
- error-patterns-index: 在 .claude/error-patterns/ 新增未入 README 的檔案（或改 README 留過時 ID），重啟 session。避開：get_project_root 為空、error-patterns 或 README.md 不存在、凍結表失敗僅影響碰撞分流
- spec-version: 將 docs/spec 任一檔 frontmatter version 與變更歷史最大版號改成不一致，重啟。避開：缺 frontmatter，或變更歷史與正文版號行皆缺
- memory-dir-audit: 在本專案對應的 ~/.claude/projects/<slug>/memory 放一個檔案，重啟 session（SessionStart）或 Stop。避開：stdin 為空或非 JSON、hook_event_name 非 SessionStart/Stop、零候選（比對鍵未命中）、內容與 marker 快照相同（marker 位於 .claude/hooks/hook-logs/memory-dir-audit-marker.json，可刪除以重置）
- skill-body-size: 未改，無需觸發

### 讀取來源觀察
