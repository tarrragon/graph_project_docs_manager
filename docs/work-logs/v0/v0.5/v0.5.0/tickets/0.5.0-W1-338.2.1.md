## Solution
<!-- Schema[IMP/Solution]: 選填（.claude/pm-rules/ticket-body-schema.md） -->
拆分前後行數：hook_ticket.py 939->1006（+67，單一實作 + 後綴剝除/去重/佔位符）；ticket_parser.py 274->226（-48）；bare-commit-guard-hook.py 1251->1241（-10）。
移除的重複實作：2 份（ticket_parser 的 _extract_where_file_intents 與佔位符常數、bare-commit-guard 的票檔定位+解析流程）。agent-dispatch-validation 已是 lib.extract_where_files 的一行包裝，未改。
未完成：parallel-dispatch-verification-hook.py 的後綴剝除（parse_file_intent 迴圈）尚未搬入 lib。原因：tests/test_parallel_dispatch_verification_hook.py 的 TestIntentSuffixStripping 4 例 patch 掉 hook 的 extract_where_files 並回傳帶後綴原始值，釘住「剝除發生在 hook 內」的接縫；改呼叫 intent="write" 後這 4 例紅。該測試檔不在本票 where.files，ticket track commit 的範圍檢查不允許，故還原該 hook 改動。需 PM 以 set-where 補宣告該測試檔，或另票處理（把測試改為 patch lib 層或走真實票檔）。lib 端 intent="write" 已有測試。
陷阱：(1) 範圍檢查以 where.files 為界，測試檔若不在宣告內，重構會被釘住接縫的測試卡住；盤點 where.files 時應含「釘住被搬走邏輯的測試」。(2) 四處行為差異看似多（拋例外/回空、寬鬆/嚴格型別、去重/不去重、是否剝後綴），收斂成 intent/canonical/raise_on_missing 三個參數；canonical 把嚴格型別、去重、去佔位符綁成一組，因它們在原實作恆同時出現。(3) lib 不可在匯入期依賴 skills/ticket，parse_file_intent 改延遲載入。(4) rule8 hook 擋在 .claude/ 檔案新增文字含專案 ticket ID（註解中的舊票號需刪）。
