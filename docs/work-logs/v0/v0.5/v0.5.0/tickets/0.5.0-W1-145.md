## Solution
<!-- Schema[IMP/Solution]: 選填（.claude/pm-rules/ticket-body-schema.md） -->
### 實作（thyme-python-developer，worktree commits 8e50deaac、f29950692）

- 兩支 hook 的「保留變更並落地 main」建議，由 `git -C <wt> add <paths> && git -C <wt> commit -m "<message>" -- <paths>` 改為三行：`git -C <wt> add <exact-path>` → `git -C <wt> diff --cached --name-only   # 確認只含目標檔` → `git -C <wt> commit -m "<message>"`。無 pathspec、無 --only／-o／-a、無 && 串接
- 獨立 index 實測（真實 git）：主 checkout 暫存 f 後 `git worktree add`，worktree 內 `diff --cached --name-only` 0 行、主 checkout 輸出 f；`rev-parse --git-path index` 分別為 `.git/worktrees/wt/index` 與 `.git/index`。結論：linked worktree 各有獨立 index；仍保留核對步驟，因 worktree 自身 index 可能殘留先前暫存，且與規則七一致
- f29950692：測試名 `..._path_limited_commit` 改 `..._exact_add_bare_commit`，docstring 同步（規則 3 命名一致）

### 範圍外發現

- 建議指令收尾的 `git merge <branch> --no-edit`（及 remove-deliverable 的 `git checkout main && git merge`）繞過合併閘門：建 0.5.0-W1-371（blockedBy 本票）
- `session-start-merged-worktree-audit-hook.py`、`worktree-commit-before-dispatch-hook.py` 印 `git add <..> && git commit -m ...`：無需建 ticket，規則三明文允許 add 與 commit 串接，且無 pathspec
