## Solution
<!-- Schema[IMP/Solution]: 選填（.claude/pm-rules/ticket-body-schema.md） -->
純搬移 commit ad0eb6bb4（無行為修改）。行數：拆分前 check_domain_coverage.py 920 行 / 58 函式；拆分後入口 207、fr_extract 279、map_locate 271、attribution 146、event_flow 82、__init__ 1（共 6 檔，4 個職責模組）。
模組職責：
- fr_extract（底層，無套件內依賴）：FR token 展開、圍欄/行內程式碼/HTML 註解遮罩、FR 標題與形似行抽取、frontmatter 區塊、extract_spec_id、has_functional_requirements 宣告讀取。
- map_locate：source_specs 解析、定位鏈、層級 SPEC 判定（domain 欄）、各類診斷訊息、路徑常數、_read_maps。依賴 fr_extract。
- attribution：FR->SPEC 歸屬解析、_ParsedMap、未覆蓋計算、層級覆蓋、補法說明。依賴 fr_extract、map_locate（SYSTEM_LAYER_PATH）。
- event_flow：事件流訊號詞、通道章節/到達級別子表定位、標定檢核。依賴 fr_extract、check_api_surface。
- 入口：CLI main、judge_fr_declaration、兩個 _report_*，並 re-export 全部原頂層名稱（含底線名稱；僅 _FR_LEAD/_FR_NUMBERING/_FR_CORE 三個正規式片段不 re-export，無外部使用）。依賴方向單向無循環。
分群微調：票面未列的 FR 宣告讀取與 frontmatter/spec id 歸 fr_extract（被 map_locate 與 attribution 共用，放底層避免循環）；judge_fr_declaration 與報告函式含輸出副作用，留入口。
陷阱：
1. 既有測試 test_both_consumers_use_shared_fr_like_judgment 用 monkeypatch.setattr(cdc, "fr_like_lines") 鎖位置而非行為：find_unextracted_fr_lines 搬到 fr_extract 後，patch 入口檔的名稱對它無效，測試紅（261 過 1 敗）。re-export 不會讓 patch 穿透到來源模組。處置：測試改為對 fr_extract 與 cdc 兩處各 patch 哨兵（兩消費端分居兩模組），斷言不變；該測試檔已在 where.files。其餘測試皆走公開函式與 main + chdir，無位置鎖定。
2. 路徑常數（SYSTEM_LAYER_PATH 等）若被測試 patch 同樣不穿透；本檔無此類測試，但日後 patch 須指向 map_locate。
3. 新套件以絕對名 domain_coverage 匯入、套件內用相對匯入；直接執行腳本時 scripts 目錄在 sys.path，故可行（已實跑 --help）。套件名不與標準庫同名。
