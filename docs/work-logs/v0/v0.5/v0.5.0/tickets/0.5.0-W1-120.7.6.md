## Solution
<!-- Schema[IMP/Solution]: 選填（.claude/pm-rules/ticket-body-schema.md） -->
改法：changelog-update、commit-handoff、post-git-commit、skill-cli-sync-check、variable-count-literal-guard 五支的 git commit 子字串判定改為 match_git_commit(...) is True（commit 3c900e922）。原本排除 amend 的三支（commit-handoff、skill-cli-sync-check、variable-count-literal-guard）及 post-git-commit 的子邏輯判定用預設 exclude_amend=True；原本不排除 amend 的 changelog-update 與 post-git-commit 外層閘門傳 exclude_amend=False。None 一律視為未命中（fail-open，只少一則提示）。原 EXCLUDED_COMMAND_PATTERNS 中 git log、show、diff、status 項不會被判為 commit 呼叫，由解析器自然排除，判定函式不再引用該常數。
實地觸發：scratchpad 暫存 repo（git init），以 settings 註冊的啟動方式 uv run --quiet hook-dispatcher.py --group PostToolUse:Bash，CLAUDE_PROJECT_DIR 指向暫存 repo，餵 payload 給 post-git-commit-hook。git -C x commit 的 payload：暫存 repo 的 hook-logs/post-git-commit-hook 日誌出現 INFO 偵測到 git commit 命令，開始執行子邏輯；echo git commit 的 payload：該日誌無此 INFO（計數 1），兩者 rc=0。liveness 驗證方式：兩次 payload 的日誌差異比對。失敗語意：無法解析（None）視為未命中，fail-open。
Phase 4：重構需要 否；技術債務 無；程式碼品質 A；結論：無需重構。
