## Problem Analysis
<!-- Schema[ANA/Problem Analysis]: 必填（.claude/pm-rules/ticket-body-schema.md） -->

### 問題根因

lease 的 ghost forensics 以分支名比對票號找殘留工作；cc runtime 隔離派發建立的分支名為 `worktree-agent-<hash>`，不含票號，375 前後的分支比對都不會命中。代理人分支上仍有未合併工作時，鑑識看不到，reclaim 可能判為乾淨而放行接管——漏判方向，不可接受。屬既有缺口，375 審查發現，非 375 引入。

### 影響範圍

- 受影響：`ticket track reclaim` 的鑑識（lib/lease.py 的 run_ghost_forensics）。
- 已驗證（2026-10-20 實地查證，見 Solution 候選訊號表）：當下 4 條 worktree-agent 分支名皆不含票號；dispatch-active 每筆含 ticket_id 與 agent_id，分支名可由 agent_id 推得，紀錄保留至該票 complete。
- 已驗證：391.1 以 dispatch-active 為主訊號、commit 主旨為輔訊號補命中；391.2 修正主訊號的兩種誤擋（prunable worktree、無關未追蹤檔）與 worktree list 失敗落點。兩張子票皆已合併。
- 殘餘漏判：派發 hook 未記錄且分支無帶票號 commit 的情形，分支無可歸屬資訊，不另設訊號（見 Solution 結論）。

## Solution
<!-- Schema[ANA/Solution]: 必填（.claude/pm-rules/ticket-body-schema.md） -->
### 候選訊號（2026-10-20 實地查證）

| 訊號 | 取得方式 | 涵蓋範圍 | 誤判方向 |
|------|---------|---------|---------|
| A. commit 主旨前綴 `type(<ticket-id>):` | 對未合併的 worktree-agent-* 分支 `git log --format=%s`，以 375 的票號邊界規則比對 | 有 commit 的分支；當下 4 條 agent 分支的最新 commit 皆帶票號 | `ticket track commit` 的 -m 原樣使用（只附加 trailer），前綴靠慣例非工具保證；無 commit 的分支（代理人仍在改、未提交）漏判 → 只能當輔訊號 |
| B. `.claude/dispatch-active.json` | 每筆含 ticket_id、agent_id、work_checkout；分支名為 `worktree-agent-<agent_id>`（branch_name 欄只記 `worktree`，以 agent_id 推得） | 自派發起到該票 complete：代理人結束只標 `turn_ended_at`，紀錄由 lifecycle.py 的 `clear_dispatch_by_ticket_id` 於 complete 時才移除（實查：387、354.1 代理人已結束，紀錄仍在；379、361 已 complete，紀錄已移除） | reclaim 只發生在票未 complete 時，正好落在涵蓋區間內；派發 hook 未記錄（hook 失效）時漏判 |
| C. 派發日誌（票面） | `ticket track dispatch` 寫入 | — | 派發時 agent_id 尚未產生，無法對到分支，不可用 |

### 結論：以 children 建實作票

- 0.5.0-W1-391.1：B 為主訊號（ticket_id 全等比對，推得分支後判未合併或 worktree 有未提交變更），A 為輔訊號；dispatch-active 讀取失敗（不存在除外）時判 unknown、拒絕接管
- 兩訊號都只增加命中、不減少，屬收緊方向，不會讓原本拒絕接管的情況改為放行
- 殘餘漏判：派發 hook 未記錄且分支無帶票號 commit 的情形。此時分支無任何可歸屬的資訊，不另設訊號
