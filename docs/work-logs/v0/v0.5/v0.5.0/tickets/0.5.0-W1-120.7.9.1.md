<!-- Schema[IMP/Solution]: 選填（.claude/pm-rules/ticket-body-schema.md） -->
### 實作（thyme-python-developer 於 worktree，PM 依流程 B 代寫，2026-10-14）

提交 a89aae0a6，以 worktree merge 的隔離索引 CAS 合併為 2d17c7b3d。

- 介面：`find_git_invocations(command, subcommands, base_dir=None, scan=False)`、`match_git_commit(command, exclude_amend=True, base_dir=None, scan=False)`。`GitInvocation.via_scan: bool = False` 放在 dataclass 尾端。回傳形狀與 None、[] 的語意都不變。
- 判定順序：每個語句先用命令位置判定，命中就 via_scan=False；位置判定沒命中才進入掃描，掃描命中一律標 via_scan=True。
- 掃描方式：逐 token 檢查，git token（絕對路徑也算）交給既有的呼叫解析；遇到巢狀腳本載體（shell -c、eval、env -S、flock -c、watch）就遞迴解析；eval 與 watch 處理完即停止掃描，避免同一語句重複計數。
- 例外：echo、printf 之後的參數不掃描；`command -v`、`-V` 不掃描；heredoc、引號內文字、註解交由既有管線處理（建立在 strip_line_comments 之後）；位置判定會拋 _Unparseable 的情形，掃描路徑同樣會拋，不會靜默放行。
- 「只靠掃描命中，比照無法解析處理」的語意不在 lib 實作，由守衛端（120.7.9.2、120.7.9.3）依 via_scan 決定處置。

### 量化

- 56 項正向輸入：scan=True 命中 52 項，scan=False 命中 31 項。漏掉的 4 項與分析預期一致：echo 引號內的命令替換、su -c、script -c、sg -c，已用「已知漏判」測試鎖定。
- 反向輸入：本票測試的 14 項誤判 0。對抗式壓力輸入 39 項誤判 23 項，全部是「git 作為其他命令的參數」這一類（查文字類命令、其他命令的參數、遠端或容器內執行），屬封閉集合，已寫入 docstring 並以測試鎖定。
- 真實語料（正式實作重跑）：12,821 筆含 git 字樣的命令中，僅 scan 命中的 2 筆經逐筆裁定都是真實呼叫（xargs -0 git add），scan 誤判 0。hook 日誌語料 1,350 筆，僅 scan 命中 0 筆。兩份語料中，scan 的解析結果（命中、未命中、None）與位置判定逐筆一致，沒有新增解析失敗。
