### 相關 Error Pattern

- 本缺陷已記為 `.claude/error-patterns/process-compliance/PC-GPD-034-suggested-command-not-validated-by-own-parser.md`（commit c8899f9ac，2026-10-19）。修正時依其主防線補測試：以掃描端實際產出的分支名渲染建議指令，餵回 cleanup 的參數解析並斷言不報格式錯誤
- 該 pattern 撰寫時未讀 compositional-writing（commit 時 framework-rule-edit-skill-trigger WARN），文字審查另行處理

### 修法選擇（PM，2026-10-19，已事前回報主控）

採 A：cleanup 新增 `--branch <name>`（比照 merge 的 --branch，與 ticket_id 擇一）；掃描報告對非 ticket 分支改印 `/worktree cleanup --branch <name>`（--force 版同理）。

不採 B（掃描報告改印裸 `git worktree remove` + `git branch -D`）：B 的建議指令繞過 cleanup 的 Level 1 未 commit 閘門，且不經 cleanup 的 parser，PC-GPD-034 主防線（把建議指令餵回自家 parser 斷言可解析）無從套用。

實作要點：
- 掃描端 `safe_to_clean.append(ticket_id or branch)` 與 warnings 清單已混入分支名，渲染時須依「是否為 ticket ID」選樣板，不可只換一個樣板
- 測試主防線：取掃描端實際產出的 worktree-agent-<id> 分支名渲染建議指令，拆成 argv 餵回 main() 的 parser，斷言不報格式錯誤且定位到該 worktree（E2 正向對照：亂寫的分支名仍須報找不到）
- agent worktree 在代理人存活時為 locked，cleanup 失敗屬預期，不處理
- 相鄰缺陷 Level 3 合併判定恆誤報另開 0.5.0-W1-363，本票不修
