## Solution
<!-- Schema[IMP/Solution]: 選填（.claude/pm-rules/ticket-body-schema.md） -->
**做法**（thyme-python-developer，worktree commit ff5cd629c）
- `pixel_diff.decode_png` 接受 depth 8 或 16、color type 2 或 6、非交錯。bpp 改為「通道數 × 每樣本位元組數」，沿用原 `_unfilter`。
- depth 16 時每通道取高位元組（`r[0::2]`）縮成 8-bit，再走既有的 RGBA 丟 alpha 路徑；`tol` 仍以 8-bit 通道值計。8-bit 路徑未改。
- `test_ui_checks.py` 新增 `png16` 16-bit 編碼器（低位元組固定 0x55）與 `PixelDiff16BitTest` 三個測試。

### 自檢結果

| AC | 證據 |
|---|---|
| 1 解 16-bit RGB／RGBA | `PixelDiff16BitTest` 解碼結果等於原 8-bit 影像（RGB 與 RGBA 各一） |
| 2 16-bit 正向對照 | 兩張已知有差異的 16-bit 圖：`skip` 為 False，區塊位置正確 |
| 3 16-bit 負向對照 | 同一張 16-bit 圖自比：`skip` 為 True |
| 4 8-bit 不變 | `python3 -m unittest test_ui_checks`：20 tests OK（含既有 8-bit 測試） |
| 5 實際擷取產物 | 見 Test Results：兩次不同的 HEAD 擷取直接比對，結果 skip，未用轉換腳本 |

掃描手段：PM 在 worktree 內重跑 `python3 -m unittest test_ui_checks`（20 tests OK），並以修補後的 `pixel_diff.py` 實跑 AC5 比對。
