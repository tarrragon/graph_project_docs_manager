## Solution
<!-- Schema[IMP/Solution]: 選填（.claude/pm-rules/ticket-body-schema.md） -->
### 設計

守衛語意取得方式：分派層以 regex 掃描 hook 檔 `fail_closed=True`（is_fail_closed）；registry 讀不到時用內建 FALLBACK_FAIL_CLOSED_GUARDS，漂移測試比對兩者。

PreToolUse:Bash 27 支中 fail_closed 為 2 支：bash-git-protected-branch-guard-hook、workspace-wipe-guard-hook；其餘 25 支與 PostToolUse:Bash 16 支皆 fail_open（崩潰 exit 1，守衛的主動 deny 仍走 exit 2 / permissionDecision）。

| 故障情境 | fail_closed 守衛 | fail_open hook |
|---|---|---|
| 群組預算用盡 | 不略過，進尾段子程序並行，完整自身逾時，守衛自行 deny | 同左，照常執行 |
| 單支逾時（含 HookTimeout 穿過 run_hook_safely） | 分派層回 2 | 回 1，stderr 可見 |
| 載入期例外 / 分派機制失敗 | 回 2（in-process 失敗先退子程序） | 回 1 |
| registry 讀取失敗 / run_group 拋例外 | 內建清單逐支子程序執行，擋下回 2；未擋下回 1 且 stderr 可見（不鎖死修復用 Bash） | 不執行，exit 1 可見（與改動前一致，fail_open 本身語意） |

### 延遲上限

| 項目 | 改動前 | 改動後 |
|---|---|---|
| 預設單支逾時 | 30s | 60s（註冊值不變） |
| Pre 群組序列預算 / settings | 600 / 620 | 380 / 995 |
| Post 群組序列預算 / settings | 120 / 140 | 120 / 200 |
| 預算用盡時剩餘 hook | 略過 | 尾段並行，上限 = budget + 最大單支逾時（Pre 380+595，Post 120+60） |

Pre 預算下調的原因：settings 逾時須 < 1000（單位守衛測試），budget + 最大逾時 595 + 餘裕 20 <= 995。副作用：逾時 595 的 tracking-schema-json-staleness-guard 因剩餘預算恆小於 595，固定走尾段子程序（多一次直譯器啟動，與序列段並非並行）。正常路徑（預算充裕）延遲不變。

hook_output_validator 改經 merge_dispatch_registry 取清單（驗證 98 筆全過）。
