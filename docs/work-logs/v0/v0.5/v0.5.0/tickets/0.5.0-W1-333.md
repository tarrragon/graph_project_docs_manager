## Task Summary

hook-dependency-isolation-check 反覆對 commit-stage-guard-gate-hook.py 報 import doc_system 未被 PEP 723 涵蓋；需判定屬 (a) 遞移 import 確實拉進 doc_system 而 PEP 723 只宣告 pyyaml、(b) isolation-check 把 docstring 文字當 import、(c) 全量掃描時報出的檔案歸錯

## Problem Analysis
<!-- Schema[ANA/Problem Analysis]: 必填（.claude/pm-rules/ticket-body-schema.md） -->
### 問題根因
判定：三個候選 (a)(b)(c) 皆不精確，實際為第四種 (d)：isolation-check 的 lib 遞移掃描對本地掛載套件 doc_system 誤判為外部依賴（誤報）。
- 非 (b)：extract_external_imports（hook-dependency-isolation-check-hook.py，函式 extract_external_imports）以 ast.parse + ast.walk 取 Import/ImportFrom 節點，docstring 為 Constant 節點不會被當 import。commit-stage-guard-gate-hook.py 第 70 行 docstring 的 doc_system 無關。
- 非 (c)：單檔觸發與全量掃描都經 check_file_consistency 以 rel_path 為鍵，報出的檔案歸屬正確；該檔確實經 lib 觸及 doc_system。
- 非純 (a)：真實 import 位於 .claude/lib/commit_content_guards.py 第 127 行（_check_uc_reference 內，try/except ImportError 降級回傳 []，第 124-125 行先 sys.path.insert skills/doc）。1cc61bb3c 前已抽出至 lib，hook 本體自身 import 無 doc_system。doc_system 是 skills/doc 下本地套件、非 PyPI，補 PEP 723 宣告無效也不正確。
- 真因：build_lib_dependency_index 呼叫 extract_external_imports 時 local_names 只傳 lib 子模組 stem 加 lib（約 470 行附近），未用 build_local_module_index 的全域索引；hook 直接 import 時 local_names 為全域索引（含 doc_system）故不報，經 lib 遞移時才報。
### 影響範圍
單一檔案 commit-stage-guard-gate-hook.py（及任何經 lib 遞移觸及本地 skill 套件的 hook，目前僅此 1 筆，日誌 157 檔 1 筆問題）。執行期無影響：uv 隔離環境實測匯入該 hook 成功，載入時 doc_system 不在 sys.modules，需要時才 sys.path 掛載，失敗降級。
### 相關 Error Pattern
tarrragon/claude#97 為引用關係（dedup 關鍵字 isolation / PEP723 / doc_system 無重複或切分）。

## 重現實驗結果
### 實驗方法
(1) 直接執行 isolation-check hook 對該檔 stdin 觸發；(2) 腳本 probe 載入 isolation-check 模組，對 lib/commit_content_guards.py 與 hook 本體分別以 lib 式 local_names 與全域 local_names 呼叫 extract_external_imports；(3) uv run --no-project --with pyyaml 隔離環境匯入 hook。
### 實驗執行
- (1) 輸出 WARNING：['doc_system'] 未被涵蓋，1 筆。
- (2) doc_system in 全域本地索引: True；lib 式 local_names 下結果 {'doc_system'}；全域 local_names 下 set()；hook 本體直接 import 結果 set()。
- (3) 匯入鏈成功，doc_system loaded at import: False；uv 隔離環境 find_spec('doc_system') 為 None（確認非 PyPI 可得，僅靠 sys.path 掛載）。
### 實驗發現
已驗證：誤報成因為 local_names 取值差異；AST 偵測不受 docstring 影響。未驗證：其他 hook 是否同型（現有日誌僅 1 筆）。

## Solution
<!-- Schema[ANA/Solution]: 必填（.claude/pm-rules/ticket-body-schema.md） -->
結論：(d) isolation-check 誤報，修 checker，不改 hook。
候選方案：
- 方案 1（採用）：build_lib_dependency_index 接受全域 local_names，scan_all 傳入 build_local_module_index 結果。利：與直接 import 判定一致、根治同型；弊：本地索引含同名 stem 時可能遮蔽同名 PyPI 套件（既有行為）。
- 方案 2：commit_content_guards 以 importlib 動態載入避開 AST。利：checker 不動；弊：為迎合 checker 扭曲產品碼，且動態 import 本即 checker 盲區。
- 方案 3：在 hook PEP 723 宣告 doc_system。弊：非 PyPI 套件，uv 解析失敗，破壞 hook。
Spawn 規劃：0.5.0-W1-333.1（IMP，修 checker，acceptance 含 E2：正向對照 lib 子模組真漏宣告 PyPI 套件仍報、反向對照 docstring 提及 doc_system 與本地掛載不報）。dedup：framework-issue dedup 關鍵字 isolation PEP723 doc_system，無重複或切分，#97 引用。
