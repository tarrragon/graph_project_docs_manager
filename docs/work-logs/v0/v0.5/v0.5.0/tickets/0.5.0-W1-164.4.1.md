### Commit 規範

Recommended: commit via isolated index (files must be a subset of this
ticket's where.files; never touches the shared index):
  ticket track commit <ticket-id> -m "..." -- {exact files}
In a linked worktree (files changed under a worktree dir, not the main repo):
add `--worktree <abs-worktree-path>` to the command above.
Fallback (not recommended; only if `ticket track commit` fails or is
unavailable) — use precise staging + verified bare commit only (no pathspec):
  git add {exact files}
  git diff --cached --name-only   # confirm index contains ONLY {exact files}
  git commit -m "..."             # bare commit; no -- <paths> / --only / -o / -a
Forbidden: git add . / git add -A; git commit -- <paths> / --only / -o / -a
  (pathspec-style commit discards the index and rebuilds it from working-tree
   content for the given paths — it silently absorbs unstaged edits other
   sessions may have on the same path, not just already-staged ones)
Before fallback commit: git diff --cached --name-only to check staged scope; git restore --staged <path> for any non-owned file
If bare `git commit` fallback is DENYed by bare-commit-guard-hook (another
dispatch active), stop and escalate to PM; never switch to pathspec /
--only / -o / -a to get around it.
If a commit is later found to have swept in out-of-scope content (e.g. a
peer session's staged changes):
Forbidden recovery actions: git revert; git reset --soft; git commit
--amend; any "reverse apply"/reapply of the diff. None of these may be
used to undo or rewrite the commit.
The ONLY permitted actions are: stop, record the commit SHA and file
list in the ticket, report to PM.
Reason: swept-in content is diff-indistinguishable from a peer's
legitimate concurrent write in the same window, so any of the forbidden
actions above would also undo the peer's legitimate work.

### 第一階段設計（待 PM 確認；尚未寫任何程式）

#### D1 觸發與流程
每次 Bash 呼叫皆進入，不依子命令。順序：取目標集合 -> 對每個目標上溯鎖路徑 -> 逐一走既有四項刪除條件。fail-open：main 內任何例外寫 stderr 加日誌，輸出 approve。
- 前置濾除：tool_name 非 Bash 直接 approve。
- 命令不含 git 字樣（沿用 lib git_command_parse 的 contains_git_word 語意，但以內聯子字串判斷 "git" 與 "ticket"）且不含 "ticket"：目標集合只有 cwd，不 import git_command_parse（延遲 import 放在需要的分支內）。

#### D2 目標集合解析（有序去重，上限 8 個）
1. payload cwd（無則退回 get_project_root() 並留日誌，維持現行行為）。
2. find_git_invocations(command, 全子命令) 的每個 dash_c_path：絕對路徑原值；相對路徑以 cwd 為基準 os.path.normpath(join(cwd, p))；展開 ~。不存在的目錄略過並寫 debug 日誌。「全子命令」以 git_command_parse 既有的萬用或空篩選方式為準，實作時先確認 API；若 API 要求明列子命令，則改以 parse_command_statements 取 dash_c_path，不自行寫 tokenizer。
3. ticket track commit 的 --worktree 值（--worktree X 與 --worktree=X 兩形）：同一 tokenization 掃描，語句首兩 token 為 ticket track 且含 commit 子命令時才取。相對路徑同樣以 cwd 為基準。
4. 解析失敗（tokenize 回 None）：只用 cwd，寫日誌，不報錯。
未列入：git --git-dir/--work-tree、GIT_DIR 環境變數（不在票面範圍；列為已知未覆蓋，結案閘門表註明）。

#### D3 鎖路徑上溯（純檔案系統，不起子程序）
從目標目錄起逐層向上找 ".git"（上限 64 層，到根停止）：
- 是目錄 -> 鎖為 <該目錄>/index.lock。
- 是檔案 -> 讀首行 "gitdir: <path>"（相對路徑以該檔所在目錄為基準）-> 鎖為 <gitdir>/index.lock（linked worktree 的 gitdir 即 .git/worktrees/<name>，index 在其下，與 rev-parse --git-path index.lock 一致）。
- 找不到或解析失敗：退回現行 resolve_lock_path 的 rev-parse，並日誌註明 "fallback=rev-parse reason=..."；rev-parse 再失敗則沿用現行 <root>/.git/index.lock 退路與 WARNING。
同一鎖路徑由多個目標解到時以 realpath 去重，只處理一次。

#### D4 刪除條件（不變）
0 位元組、鎖齡大於 STALE_THRESHOLD_SECONDS(5)、lsof 無持有、刪除前以 (ino, mtime_ns, size) 複核。lsof 只在前兩項成立後才起，故新鎖與無鎖路徑零 lsof 成本。非 0 位元組舊鎖與有持有者沿用現行 WARNING（已超閾值的異常狀態仍輸出 stderr）。
新增靜默規則：鎖存在但未達閾值，只寫日誌（info），不寫 stderr、不放進 hook 輸出訊息。PC-139 排查提示文字移到日誌行，不再輸出。

#### D5 線索記錄（先記後刪，D4 全部條件通過、複核通過之後、os.remove 之前）
單行、key=value、空白分隔，值含空白或等號者以 json.dumps 引號包裹，前綴 "IDXLOCK-EVIDENCE"。欄位：
ts（ISO 本地時間含時區）、lock_path、size、lock_mtime（ISO）、lock_age_s、hook_cwd、trigger_cmd（去除換行、截 200 字元；機密遮罩：KEY=VALUE 形且 KEY 含 TOKEN/SECRET/PASSWORD/KEY/AUTH 者值換成 ***；Authorization/Bearer 後 token 換成 ***）、index_mtime（同目錄 index 的 mtime，不存在填 none）、reflog_new（鎖 mtime 之後該 checkout 的 reflog 是否有新項：讀 <gitdir>/logs/HEAD 最後一行的 committer 時間戳，大於鎖 mtime 為 yes，否則 no，讀不到 unknown；純檔案讀取，不起 git）、common_dir_resolved（yes/no，見 D6）。
一筆記錄對應一次刪除；僅在「實際走到刪除」時寫，非刪除的警告路徑不寫線索行。
