## Problem Analysis
<!-- Schema[ANA/Problem Analysis]: 必填（.claude/pm-rules/ticket-body-schema.md） -->

### 問題根因

390 讓 track commit 與 move-lines 共用 lib/write_scope.py 的 `unsafe_paths`（symlink 或解析後落在 repo 外即拒絕）。審查提出兩點：(1) commit 路徑上 git 本身不跟隨 symlink，islink 拒絕的必要性低；(2) `execute_commit` 只對 `args.files`（目錄展開前）呼叫 `unsafe_paths`，`_expand_directories` 展開出來的個別檔不再檢查，兩層判準不一致。

### 影響範圍

- 已驗證（/tmp 拋棄式 repo 實測，2026-10-20）：`git add linkdir/f.txt`（linkdir 為指向 repo 外的 symlink 目錄）回 `fatal: pathspec ... is beyond a symbolic link`；`git add linkfile`（指向 repo 外檔案）以 mode 120000 存入，blob 內容為目標路徑字串，不讀入 repo 外內容；`git status --porcelain -z` 會列出 `linkfile` 與 `?? linkdir`。故 commit 路徑不存在「寫到或讀入 repo 外」的漏洞，但目錄展開確實可能帶出 symlink 項目而繞過展開前的 islink 檢查。
- 已驗證：本 repo 目前追蹤的 symlink 數為 0（390 審查實測）；references/track-command-commit.md 退出碼表已寫明「目標本身是 symlink……拒絕」且與 move-lines 共用同一判準。
- 受影響檔案：commands/track_commit.py（execute_commit 的檢查時點）。write_scope.py 不需改。

### 相關 Error Pattern

- IMP-007（非對稱邊界更新）：同一判準在兩個入口只套用一邊，本案為展開前後兩層的同型不一致。

## Solution
<!-- Schema[ANA/Solution]: 必填（.claude/pm-rules/ticket-body-schema.md） -->
### 結論：採方案 B（維持 commit 拒絕 symlink），補目錄展開後的二次檢查

| 方案 | 代價 | 風險 |
|---|---|---|
| A：commit 只保留「逸出 repo」判定、移除 islink | write_scope.unsafe_paths 須加參數區分 commit 與 move-lines，共用判準一分為二；文件退出碼表與 move-lines 說明要改 | 低：git 不跟隨 symlink（實測 mode 120000、blob 為路徑字串；穿越 symlink 目錄的路徑被 git 拒絕），commit 不會寫到或讀入 repo 外 |
| B：維持拒絕 symlink | 日後若要提交合法 symlink 會被擋，須另開票放寬 | 無安全風險；本 repo 追蹤 symlink 數為 0，當下代價為零 |

取 B：兩個命令共用單一判準比放寬一個入口簡單，且文件（track-command-commit.md 退出碼表）已載明，不需改動。日後確有需提交的 symlink，由該需求的實作票處理放寬，屆時判準拆分的代價才有對應的價值。

目錄展開後的二次檢查：需要。/tmp 實測 `git status --porcelain -z` 會列出 symlink 項目，目錄型宣告展開後的 symlink 檔不經 islink 檢查即進入提交，與文件所述判準不一致。不構成安全漏洞（git 只記錄連結），屬判準一致性缺口，由 0.5.0-W1-398.1 承接（--parent）。
