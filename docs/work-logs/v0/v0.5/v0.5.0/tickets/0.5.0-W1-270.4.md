## Task Summary

check-acceptance --all 輸出「index 全部 (n/m) 已勾選」時 n 是本次新勾數，改為能區分本次新勾與目前總勾選數的措辭

---

## Problem Analysis
<!-- Schema[IMP/Problem Analysis]: 選填（小型 IMP 可留 placeholder；大型 IMP 建議填寫）（.claude/pm-rules/ticket-body-schema.md） -->
### 根因

兩個入口都把「本次變更數」放進 `(n/m)` 的分子，讀者會讀成「目前已勾 n 項，共 m 項」：
- `commands/track_acceptance.py` 的 check-acceptance `--all` 分支：`index=f"全部 ({count}/{total_count})"` 與 `BATCH_CHECK_SUMMARY_FORMAT`（「已勾選 {checked_count}/{total_count} 項」），`count` 為本次由未勾變已勾的數量；`--uncheck` 分支同型（`BATCH_UNCHECK_SUMMARY_FORMAT`）。
- `commands/track_set_acceptance.py` 的 `all_check`／`all_uncheck`：`scope = f"全部 ({changed}/{total})"`。

實例：0.5.0-W1-270.1 先勾第 1 項，再 `check-acceptance --all`，主倉庫兩項皆勾（51fb450ac），輸出「index 全部 (1/2) 已勾選」「已勾選 1/2 項」，實驗代理人回報為口徑不一致。

### 修法

輸出改為同時呈現兩個量：本次變更數，以及寫入後目前的已勾選數／總數。例如：`[OK] <id> 全部已勾選：本次變更 1 項，目前 2/2`。訊息字串集中在 `command_tracking_messages.py`；`set-acceptance` 的 all 模式同步改。現有測試無依賴這些字串（grep 確認）。

### 測試（E1／E2）

補測試：(1) 部分已勾的票執行 `--all`，斷言輸出含本次變更數 1 與目前 2/2；(2) 全未勾的票執行 `--all`，兩數相同。(1) 在修正前必須為紅。
