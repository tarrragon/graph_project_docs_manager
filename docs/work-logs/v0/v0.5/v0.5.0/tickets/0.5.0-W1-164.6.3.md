### 輸入彙整（PM 89，2026-10-13，來自 0.5.0-W1-164.5、0.5.0-W1-164.6 與 164.3／164.6.1 的合併審查）

**已排除（在各自的實驗條件下）**

| 路徑 | 結果 | 出處 |
|------|------|------|
| git status 被 SIGKILL 或 SIGTERM 終止（帶與不帶 --no-optional-locks） | 終止 42 次，留鎖 0 次 | 0.5.0-W1-164.6〈重現實驗結果〉 |
| harness 逾時終止 hook（先 SIGTERM，不退出者後續被強制終止），hook 內 git 正持鎖 | 6 次，留鎖 0 次，無殘留行程 | 0.5.0-W1-164.5〈重現實驗結果〉B 段 |

**本票應涵蓋的候選（皆未實測）**

1. 持鎖的寫入類 git（add、commit、update-index 等）被 SIGKILL 直接終止。164.5 的代理人指出此為已知的 git 行為但未量測；本票以它作為正向對照的首選，先確認 fixture 能產生 0 位元組殘留鎖，再測其他候選。
2. 不帶設定的工作樹側 git diff：其 index 回寫不受 --no-optional-locks 抑制（實測表見 0.5.0-W1-164.6 Solution〈盤點分類更正〉），164.6 的實驗未測到它，164.5 只取樣 1 輪。
3. uv 多層啟動鏈：hook 經 uv 啟動 python 再啟動 git 時，逾時訊號是否逐層傳到 git，或只有外層被終止而 git 成為孤兒後被另行 SIGKILL。
4. worktree 內執行的 hook 與 CLI 來自哪個 checkout（自身的舊版或主 checkout 的新版）：0.5.0-W1-164.5 中 ae035706 一例的兩種解讀靠這一點區分。

**PM 的推測（未查證，僅供排序）**：上列之外，另有一類行程會對執行中的 git 送出訊號而不經任何 hook——Bash 工具呼叫本身逾時、使用者中斷、代理人或 session 被結束時，其下正在執行的 git 寫入。0.5.0-W1-164.5 的兩個殘留鎖出現時，該 worktree 的 index 與 reflog 皆無寫入痕跡，與「寫入進行到一半被終止」不完全相符，故此項列為待驗而非主張。

**方法提醒**：先建立會留鎖的正向對照再測其他候選，否則全為 0 的結果無從解讀；取樣不少於 5 次並記錄 load；只在 scratchpad 的拋棄式 repo 進行。

### 執行約束與實驗設計要求（PM 89，2026-10-14；派發 prompt 不重述，以此為準）

實驗設計：
- 順序：先做驗收第二項（寫入類 git 於持鎖期間被 SIGKILL）建立正向對照。確認 fixture 能產生 0 位元組且無行程持有的 index.lock 之後，才測其他候選；正向對照若建立不起來，先停下回報，不要接著跑其他組（全為 0 的結果無從解讀）。
- 可靠的持鎖方式（0.5.0-W1-164.5 已採用）：git add 搭配 clean filter，filter 內等待；git 先取 index.lock 再執行 filter，鎖於 filter 期間持續存在。終止的對象是 git 本身的 PID，不是 filter。
- 每一組記錄：命令、終止訊號、終止時鎖是否已存在（終止前先確認）、終止後鎖是否殘留、殘留鎖的大小、是否仍有行程持有、取樣數與分佈、當時的 load。
- 殘留鎖的形態要與 0.5.0-W1-164.5 所記的兩個實例比對：0 位元組、無行程持有、該 worktree 的 index 與 reflog 於鎖出現前後無變動。寫入類被 SIGKILL 若留下的是非 0 位元組的鎖，或會連帶改動 index，須明寫與實例不符之處。
- 唯讀類（status、工作樹側 diff）沿用同一套量測，並設法在回寫 index 的窗口內終止（例如以大量 stat-dirty 檔案拉長窗口、或以追蹤輸出定位取鎖時點）；做不到就說明做了什麼、為何打不中。
- uv 多層鏈：以拋棄式 hook 腳本經 uv run 啟動、其內再啟動持鎖的 git，由外層施加逾時與終止，觀察訊號是否到達 git、git 是否成為孤兒後仍持鎖或留鎖。不啟動額外的 Claude Code 行程；若此項必須啟動才能測，改為說明並列為未測。
- hook 載入來源：唯讀查證。於一個既有的代理人 worktree 內（不寫入、不提交）確認 settings 中 hook 指令所用的專案目錄變數在該情境下指向主 checkout 或該 worktree，並以檔案路徑與內容差異為依據。只讀不改。

位置：
- 所有實驗只在 scratchpad 的拋棄式 repo 進行。git -C 的目標寫字面絕對路徑。
- 不動專案的任何 worktree、分支、index.lock、settings、hook。不啟動或終止不屬於本實驗的行程。
- 終止只針對本實驗啟動、以 PID 指名的行程；不用 pkill、killall。實驗結束後刪除拋棄式 repo，並以 PID 逐一確認無殘留行程。
