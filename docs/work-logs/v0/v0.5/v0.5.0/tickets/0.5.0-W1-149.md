## Problem Analysis
### 問題根因

票面把問題框成「補 source_specs 或載明不適用」。實測兩邊都不成立，缺口在工具定位鏈的設計前提：0.5.0-W1-086 方案 C 假設每份 SPEC 至少被一份 domain map 的 source_specs 列入，docs/system-layer.md 只當聯集成員、從不單獨使用。純畫面層的 SPEC 不滿足這個前提。

### 影響範圍

實測（c6，2026-10-12，main）：

| 事證 | 內容 |
|------|------|
| 不帶旗標 | SPEC-001～004 四份皆 rc=1，訊息「有 domain map 但無一份的 source_specs 列入本 SPEC」 |
| 帶 --domain-map docs/system-layer.md | 四份皆 rc=0；系統層 §8 已列 SPEC-001（8 FR）、SPEC-002（4 FR）、SPEC-003（17 FR）的歸屬，SPEC-004 無 FR |
| 暫存副本補 source_specs 後 | SPEC-001、003 rc=0 但各多 2～3 行「未歸屬的 FR 且 source_specs 非單一值，未計入」；SPEC-002 仍 rc=1（4 個 FR 全屬畫面層，無 domain 可列） |
| source_specs 的語意 | 上游邊型 domain_coverage（DomainBundle→SPEC，established），補值即在真實圖上新增邊 |
| 呼叫端 | .claude/ 內無 hook 或流程自動執行本檢查；失敗自 2026-10-07 拆檔起即存在，非 0.5.0-W1-086.1 引入 |
| 四份 SPEC 的 frontmatter | domain 皆為 "ui"；depends_on_domains 已填（SPEC-001、003 七個 domain，002、004 為 [layout]） |

### 相關 Error Pattern

### X5 的範圍解讀（c6 PM，2026-10-13；回覆 13 對 0.5.0-W1-149.1 的提問）

13 的實作初版把「domain 欄值不在已宣告 domain 集合內即走系統層」排在原定位鏈之前，審查實測會蓋過正面證據（SPEC 已被 map 的 source_specs 列入、有同目錄 map 或舊式 map 時仍被拉去系統層），造成假紅。

c6 裁決：走系統層的條件為「原定位鏈找不到任何 map」且「domain 欄值不在已宣告 domain 集合內」兩者同時成立。依據：送用戶時的問題是四份 ui SPEC 找不到任何 map，X5 解的是無 map 可看時的去處；只憑「找不到 map」即退回系統層是當時的候選 X2，用戶未採，故已宣告 domain 且無 map 的 SPEC 仍須報錯（漏登記），並列為工具的對照測試。
性質：工具內部判定順序，對現有七份 SPEC 的結果無差異，屬 PM 裁決項。若實作後有 SPEC 的結果因此改變，改送用戶。
