## Solution
<!-- Schema[IMP/Solution]: 選填（.claude/pm-rules/ticket-body-schema.md） -->
`_staged_files(target, logger)` 在 `git diff --cached` 回非零時寫 `logger.warning` 加 stderr（含 returncode 與 git stderr），仍回空清單維持 fail-open。新增模組常數 `_GIT_TIMEOUT_SECONDS = 10` 供 `_run_git` 使用；既有 `test_e2_dash_c_merge_denied_when_staged` 以 monkeypatch 放寬為 60，降低負載敏感度。docstring 的失敗語意改寫為三條路徑皆 fail-open，並列出理由：放行後 merge 可復原，且 hook 自身故障不得使全域卡死。維持 `fail_closed=False`。commit a80607be1，合併 738832e19。

### 自檢結果

- RED：單檔 18 個測試，修改前 2 failed（diff 非零無訊號、逾時常數不存在），16 passed。逾時注入測試修改前已綠：該路徑原本就由頂層 except-all 寫 stderr，屬 E1 對照的另一半。GREEN：18 passed。
- 產生路徑盤點表在 how.strategy：diff 逾時、diff 非零、自身例外三列為「是」。rev-parse 與 merge-base 非零兩列為「否」，理由是這兩處非零時回 False，結果偏向 deny，不構成靜默放行。
- 規則 8 grep 0 命中。
- 實地觸發（本 session 實地觸發確認）：在 scratchpad 的臨時 repo 讓 index 有 staged 檔，兩分支以 commit-tree 構成非快轉。index 正常時，修正前後皆 rc=2（擋下）。把 `.git/index` 寫壞使 `git diff --cached` 回 128：修正前 rc=0 且 stderr 空白（靜默放行）；修正後 rc=0，stderr 為「diff --cached 回傳 128，無法判定 index 狀態，已放行」。

### Phase 4 評估

- 重構需要：否。
- 技術債務：無新增。
- 程式碼品質：A。
- 結論：改動限於一個函式的錯誤分支與一個常數，訊號格式與同檔既有的自身例外訊息一致。
