## Problem Analysis
<!-- Schema[ANA/Problem Analysis]: 必填（.claude/pm-rules/ticket-body-schema.md） -->
PM 觀察（2026-10-15 12:16:51）：執行「cat /nonexistent-probe-28131.txt; true」，畫面上可見 cat 的錯誤訊息，但 cli-error-feedback 的日誌在同一時間記錄「general-cli: 無 stderr，命令成功，跳過」，表示 PostToolUse 的 tool_response.stderr 為空，stderr 疑似被併入 stdout。若屬實，所有以 tool_response.stderr 判斷失敗的 PostToolUse hook 都會失效（cli-error-feedback 的 general-cli 分支即是一例；舊 cli-failure-help-reminder 8 天觸發 0 次也與此相符）。盤點時請以實際 payload 確認 Bash 的 PostToolUse tool_response 中 stdout 與 stderr 的分流方式，並列入可見性對照表。

### 實測方法（本 session，2026-10-15）

以 `claude -p --settings <暫存設定> --setting-sources ""` 在 scratchpad 的空專案跑真實 session，各事件註冊多支探針 hook，每支以不同管道輸出唯一標記 `QZX7_<事件>_<管道>`，再請模型列出 context 中所有 QZX7 標記及出處。每支探針另寫 `ran.log`，以 `RAN` 行確認該分支實際執行（PC-GPD-032）；未改任何專案 hook、規則或設定。Pre 的 exit 2 stderr 與 additionalContext 另有本 session 內自然觀測：bash-edit-guard 的裸 cd 攔截，stderr 與 additionalContext 皆原樣出現在本代理人 context。

### 實測發現

1. 模型可見的管道只有四條：exit 2 的 stderr、decision block 的 reason、hookSpecificOutput.additionalContext、以及 UserPromptSubmit／SessionStart 的純文字 stdout。exit 0 的 stderr、systemMessage、非標準欄位（message、reason 無 decision、suppressOutput）對模型一律不可見。
2. Stop 事件：exit 2、decision block、additionalContext 三者皆使模型續跑並引用標記；exit 0 stderr 無任何效果（模型只回 ok）。
3. Bash PostToolUse payload：`tool_response` 為 `{"stdout":"OUTMARK\nERRMARK","stderr":"",...}`，stderr 併入 stdout，恆為空字串。PM 觀察成立。
4. Bash PostToolUseFailure payload：無 `tool_response`，改帶 `error`，內容為 `Exit code 3\nOUTMARK\nERRMARK`（交錯 stdout 與 stderr）。`lib/bash_tool_response.py` 已依此處理失敗事件。
5. 未實測：SubagentStop、PreToolUse 的 exit 2 專屬探針（以自然觀測代替）、Notification 等事件；用戶欄位在 `-p` 模式無 UI，未實測，僅引專案紀錄。

### 規則 4 判定

結論：需要補。規則 4 現文「Hook 異常必須寫入 stderr（用戶端可見）」只定義用戶可見，且是 IMP-048 與 IMP-003 的正確對應；問題在於它是 hook 作者唯一讀到的輸出規則，提醒類輸出照字面寫 stderr 加 exit 0，對模型零可見，wrap-decision-tripwire（305）即此例，本盤點再找出 24 支同型。

候選方案：

| 方案 | 利 | 弊 |
|------|----|----|
| A 規則 4 補一段受眾宣告：輸出須標明受眾，模型為受眾時走 additionalContext 或 exit 2；對照表放 references | 自動載入層只增一段；與 IMP-055 方向互補 | 仍依作者自律，需配 helper 降低遺漏 |
| B 不改規則，只在 hook-architect 技術參考加表 | 零自動載入成本 | 作者讀不到（305 即在 basil 定義下發生） |
| C 加 Hook 守門：偵測 exit 0 且僅 stderr 的提醒類 hook | 強制 | 受眾無法機械判定，誤報率高，且 hook 數量已多 |

採 A 加 helper（.2）：規則補一段、表與 error-pattern 放 references（.1）；C 不採，理由是受眾為語意判斷。
