### 補充 context（c6，2026-10-13；來源 0.5.0-W1-156.1 獨立審查 M3、S5）

1. 可達性已有產生端證據（審查者靜態閱讀，未實機）：workspace_repository 的 _persistAndInspect 於偏好寫入失敗時無條件回傳 ChooseFolderNotRemembered，其 state 可為 WorkspaceUnavailable；project_switcher_overlay 的 _handleChooseFolderResult 在該分支先走 _handleChosenState（不可用即維持展開）再呼叫 AppSnackBar.show（workspaceNotRemembered）。浮層可由阻擋狀態出口展開，故為可棄請求於不可棄持有期間到達。尚未追 _inspect 何時回 WorkspaceUnavailable。SPEC-003 §3.7 無此組合的列；其可見行為未裁決，本票列候選交 PM 送用戶。
2. 顯示時點會翻轉用戶裁決的結果：用戶 2026-10-12 裁決「未能記住」提示在阻擋狀態到達時保留到停留時間到，並註明與現行程式相同。規格 v1.60 只寫「提示先、阻擋後」的順序；現行程式是 gate 判定套用、浮層收合之後才顯示，即阻擋狀態已在、提示隨後出現。若本票判以實作時點為準，§2.17 拒絕動作（等待型被更高級別持有即不顯示且留痕）會得出不顯示，與裁決意旨相反。本票結論須明寫兩種時點下裁決如何維持，不得只對齊其中一側。
3. 0.5.0-W1-167 會改同一檔的浮層內失敗回饋（SnackBar 改常駐文字），開工前先看該票狀態。
