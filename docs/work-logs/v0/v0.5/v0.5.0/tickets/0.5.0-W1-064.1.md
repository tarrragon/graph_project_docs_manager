## Solution
<!-- Schema[IMP/Solution]: 選填（.claude/pm-rules/ticket-body-schema.md） -->
在 `.claude/hooks/tests/conftest.py` 新增 autouse、function 級 fixture `clear_caller_effort`，以 `monkeypatch.delenv("CLAUDE_EFFORT", raising=False)` 清除繼承自呼叫者的值，放在 `real_project_root` 之前，不碰 `pytest_configure` 與 HOOK_TEST_ISOLATION。測 effort 行為的測試原本即以 setenv、os.environ 賦值或 payload 顯式設定，不受影響。phase4 測試 helper 原有的逐檔 delenv 移除，由 conftest 統一負責，避免兩處維護同一件事。commit 79584cb05，合併 7f47898e1。

### 自檢結果

- 反事實 RED：只移除 phase4 helper 的逐檔 delenv、以 CLAUDE_EFFORT=low 跑該檔，2 failed（int_3、int_4），206 passed。加上 fixture 後同條件 208 passed。
- 三種環境（low、high、未設）hooks 全套件皆 5405 passed、48 skipped、4 deselected；`-m wallclock` 4 passed（本次改到 conftest，提交時 hooks-test-gate 會觸發）。
- 規則 8 grep 0 命中。
- 執行者自承 high 那次未等待他方套件即開跑，結果仍與基線一致；該流程問題由 0.5.0-W1-081 追蹤。

### Phase 4 評估

- 重構需要：否。
- 技術債務：無新增。逐檔隔離已收斂為單一 fixture。
- 程式碼品質：A。
- 結論：fixture 只移除繼承值，不改寫顯式設定，影響面限於呼叫者環境。
