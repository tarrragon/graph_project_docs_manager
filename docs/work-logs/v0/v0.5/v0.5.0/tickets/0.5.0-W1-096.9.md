### WRAP 評估（2026-10-08）

範圍：NeedsContext 1～3。不選定方案。

**事證**
- 本專案 8 個 bundle 目前 0 個宣告 path_patterns，也沒有 `docs/non-domain-paths.yaml`；096.4 會一次補齊兩者。
- flutter_balance 只有 1 個 bundle，不可能部分宣告；部分宣告只會出現在有兩個以上 bundle 的專案、補宣告的過渡期。
- 依 7a，兩種未宣告都不進破洞報告，所以 E 的標籤只影響矩陣與票列表的逐路徑顯示。
- SPEC-001 §5 的掃描後狀態有三列：無破洞、有破洞、無法判定破洞。SPEC-004 沒有專供「頁面層級說明一行」的元件，現有可用的是 AppText、Badge（tag／category）、Section。

**E：部分宣告 path_patterns，且非 domain 清單也缺席**

| 候選 | 標籤 | 代價 |
|---|---|---|
| E1 | 「domain 未宣告」（沿用 5c 的寫法） | 該路徑也可能屬非 domain 層，標籤只說對一半 |
| E2 | 「非 domain 未宣告」（沿用「只有 path_patterns」那一列） | 該路徑也可能屬未宣告的 bundle |
| E3 | 新增合併標籤「未宣告」 | 顯示狀態從五種變六種 |
| E4 | 規格不定義 | 096.7 與 096.5 寫不出預期值 |

**F＋G（建議合併裁決）：報告頁專案層級宣告狀態一行**

| 面向 | 候選 |
|---|---|
| 出現的狀態 | F1 只在掃描完成的三個狀態（無破洞、有破洞、無法判定）／F2 加上掃描中 |
| 何時顯示 | F3 只在有任何宣告缺口時顯示，完整宣告時隱藏／F4 常駐 |
| 內容 | F5 列出缺哪一側（path_patterns 已宣告 n／m 個 bundle；非 domain 清單有或無），加上受影響路徑數／F6 一句總述，不列細項 |
| 元件 | F7 AppText 次要字級置於頁首說明區（不新增元件）／F8 Badge.category tone warning／F9 新元件 |
| 文案與 key | 由規格撰寫者依 §4.0.6 慣例提案，經用戶確認 |
| G：整體「未宣告路徑」 | G1 同一行顯示（宣告狀態只有一個位置）／G2 不在此行，只在矩陣與票列表 |

**傾向**：E1（規則最少，與 5c 同句即可涵蓋；不新增狀態）；F1＋F3＋F5＋F7；G1。
**盲點**：
- 沒有查破洞報告頁目前的頁首結構能否容納一行說明。
- F5 的「受影響路徑數」需要 Graph 或 Diagnostics 提供計數，介面歸屬沒有查。
