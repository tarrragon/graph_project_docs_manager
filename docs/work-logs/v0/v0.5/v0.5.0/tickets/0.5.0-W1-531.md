### 實驗發現

已驗證的事實（以本探測的外層 `Semantics(container: true)` 為畫面容器替身）：

| 元件 | liveRegion 節點 | 併入外層 | label 混入 | 子樹含按鈕 |
|------|----------------|---------|-----------|-----------|
| MissingSourceState | #4 = 全畫面 960x640 | 是 | 路徑行（`lastKnownPathLabel`） | 是 |
| LoadPrompt | #4 = 全畫面 | 是 | 無（label 只有訊息；計數是訊息本身的一部分，本狀態內不更新） | 是 |
| BlockedState（4 變體） | #4 = 全畫面 | 是 | 版本值、explanation；withDetail 展開時再加詳情面板文字（3c→3d label 由 2 行變 4 行）；3c/3d 另併入 isFocusable／focus action | 是（2 顆） |
| LoadingState（4 變體） | #4 = 全畫面 | 是 | 訊息 `domainLoading`；skeleton 另含骨架朗讀「載入中」；progressBar 另併入 value「進度 45 / 100」或 role loadingSpinner | 是 |
| SwitcherOverlay | #12 獨立節點 236x13 | 否 | 無（只有失敗原因） | 否 |

- 四個元件的成因與 530 (b) 相同：`Semantics(liveRegion: true)` 未設 `container`，旗標往上併入最近的語意邊界（此處為畫面容器替身），併入後節點 label 為整個容器內非按鈕文字的串接。
- 程式碼層：MissingSourceState、LoadPrompt、LoadingState 的 liveRegion 只包訊息／計數一個 Text，包覆範圍本身正確，偏離全來自併入；BlockedState 的 `_buildMessageBlock` 以 `header + liveRegion` 包整個 Column（訊息 + 版本），包覆範圍本身就大於訊息。
- SwitcherOverlay 同樣未設 `container`，本次未併入，取得獨立節點的原因是其父節點 #5（`scopesRoute`）內兄弟節點各自成節點，非元件自身保證。
- 未驗證：真實畫面的語意邊界是否與替身相同（530 已在 domain_view 實測同型，其他畫面未逐一實測）；macOS VoiceOver 實際播報行為（label 變化是否重播）未實機驗證。

## Solution
### 結論（主控裁示 2026-10-30，見 0.5.0-W1-349 Solution）

依 IMP-GPD-019 與 SPEC-004 §4.22～4.25、§4.42 無障礙子節判定：

| 元件 | 判定 | 偏離點（對照條文） |
|------|------|-------------------|
| MissingSourceState | 偏離 §4.22 | liveRegion 併入外層，label 混入路徑行；條文為「訊息以 liveRegion 播報一次」，路徑為接續朗讀 |
| LoadPrompt | 偏離 §4.25（輕） | liveRegion 併入外層，label 內容正確，但按鈕落入 live 子樹，真實畫面其他文字可能一併併入 |
| LoadingState | 偏離 §4.24 | 條文「計數文字為 liveRegion」，計數每次更新重播屬規格本意；偏離點是 label 混入訊息、骨架朗讀、進度 value，每次重播唸整段 |
| BlockedState | 偏離 §4.23 | 條文 header 與 liveRegion 對象只限訊息、版本值接續、面板展開由 expanded 旗標播報；程式以 header + liveRegion 包「訊息 + 版本」整個 Column，併入後再含 explanation，展開詳情時 live label 變動。條文清楚，屬對齊既有規格，不轉問用戶（主控裁示） |
| SwitcherOverlay | 符合 §4.42 | 現有獨立節點，但成因是父層兄弟結構偶然成立，元件本身無保證；併入 531.2 補 container（主控裁示） |

未驗證（照實列）：真實畫面的語意邊界只有 domain_view 於 530 實測；macOS VoiceOver 實際播報行為未實機驗證。
