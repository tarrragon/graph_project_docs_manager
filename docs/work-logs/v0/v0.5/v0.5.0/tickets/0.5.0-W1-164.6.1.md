### 派發 context（PM 89，2026-10-13）

**與 0.5.0-W1-164.3 的關係**：同型修改，緊接其後執行。164.3 已落地（提交 394f6b057 與 909db4b96），本票沿用它的寫法與測試形態，執行前先讀那兩筆提交。

**本票的呼叫點**（以 0.5.0-W1-164.6 盤點為準，接手者仍須自行核對）

| 檔案 | 函式 | git 子命令 | 現況 |
|------|------|-----------|------|
| .claude/skills/worktree/hooks/worktree-zombie-cleanup-hook.py | is_worktree_dirty | git -C <worktree> status --porcelain | subprocess.run 直接呼叫，無旗標 |
| .claude/skills/worktree/hooks/worktree-branch-check-hook.py | get_uncommitted_count | status --short | 經該檔本地的 run_git_command（不是 lib 的帶旗標版） |
| .claude/skills/ticket/hooks/stop-worklog-handoff-sync-check-hook.py | _extract_session_incremental_content | diff --unified=0 <base> -- <path> | subprocess.run 直接呼叫，無旗標 |

**做法**
- 旗標為 git 的全域選項，置於子命令之前；與 -C 並用時寫作 git -C <path> --no-optional-locks status。
- worktree-branch-check-hook 的本地 run_git_command 同時服務其他三個不取鎖的呼叫（worktree list、branch --no-merged、symbolic-ref）。二擇一並在 Solution 寫明理由：(a) 只在 get_uncommitted_count 的引數補旗標；(b) 在本地 run_git_command 固定帶旗標。採 (b) 時須確認其餘三個呼叫的既有測試不受影響。不要為此改走 lib 的 helper 而變動錯誤處理與逾時語意。
- 本票不處理逾時終止方式、逾時日誌、is_worktree_dirty 的靜默 except（皆屬 0.5.0-W1-164.6.2）。

**測試要求**
- 每個呼叫點一則測試，斷言實際送出的 argv 含旗標且位於子命令之前；先寫測試確認修改前為紅，再實作。形態比照 909db4b96。
- 既有測試檔：.claude/hooks/tests/test_worktree_zombie_cleanup_hook.py、.claude/skills/worktree/tests/test_worktree_branch_check_hook.py、.claude/hooks/tests/test_stop_worklog_handoff_sync_check_hook.py，已列入 where.files，可用 ticket track commit 提交。另有 .claude/skills/ticket/tests/test_stop_worklog_handoff_sync_check_cell7.py，若需改動它須先回報，不在範圍內。
- 只跑上列測試檔，不跑全套件。跑測試前先看 uptime 並把 load 記進 Test Results。執行方式比照：uv run --quiet --directory .claude/hooks pytest tests/<檔名> -q；worktree 的測試則以 .claude/skills/worktree 為目錄。

**預期效果的界線**：0.5.0-W1-164.6 的重現實驗中 git status 被終止 42 次、留鎖 0 次，正向對照未成立。本票目的為降低取鎖面與統一慣例，不在 Solution 宣稱可消除殘留鎖。

**避開**：.claude/hooks/post-test-hook.py、.claude/scripts 下的 orphan-test-procs.py 與兩者的測試（另一 session 正在修改，工作區可能有其未提交的變更）；不得以 --kill 執行 orphan-test-procs.py；不動任何 worktree、分支或 index.lock。

## Solution
<!-- Schema[IMP/Solution]: 選填（.claude/pm-rules/ticket-body-schema.md） -->
三處唯讀 git 呼叫補 --no-optional-locks（置於子命令前）：
- worktree-zombie-cleanup-hook.is_worktree_dirty：argv 改為 git -C <path> --no-optional-locks status --porcelain。
- stop-worklog-handoff-sync-check-hook._extract_session_incremental_content：git -C <root> --no-optional-locks diff --unified=0。
- worktree-branch-check-hook.get_uncommitted_count：採 (a)，僅在該呼叫引數補旗標。理由：本地 run_git_command 另服務 worktree list、branch --no-merged、symbolic-ref 三個不取鎖的呼叫，(a) 不擴大影響面，不動錯誤處理與逾時語意。
既有測試 test_worktree_branch_check_hook.py 的 fake 以 args[:2]==["status","--short"] 比對，因旗標前置而失配，改為 args[-2:]（僅比對方式，斷言契約不變）。
不宣稱可消除殘留鎖（164.6 重現實驗正向對照未成立），目的為降低取鎖面與統一慣例。
