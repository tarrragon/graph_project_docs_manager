### 門檻分母的選擇規則（主控裁定，2026-10-31）

- `autoCompactThreshold` 有值（auto-compact 開啟）：用 `compactPercent`。理由：何時壓縮是由 compaction window 決定；line-board 是框架的通用工具，其他 consumer 可能開著 auto-compact
- `autoCompactThreshold` 為 null（auto-compact 關閉）：用 `percent`（模型 window，和狀態列的數字一致）
- 選中的值為 null（compact 剛完成、tokens 缺席）：不判定，不標待 compact 或待 clear
- 本機實測：使用者層設定 `autoCompactEnabled: false`（`~/.claude/settings.json`、`~/.claude.json`），型別寫明 `autoCompactThreshold` 在 auto-compact 關閉時缺席；compaction window 退回模型 window，兩份樣本的 `compactWindow` 都等於 `window`（1,000,000），`percent` 等於 `compactPercent`。這條規則在本機的結果和只用 percent 相同
- 判定函式由 583.2 實作並附正反對照測試（要求已寫進 583.2 Problem Analysis）；583.1 已在用量檔寫齊選擇所需的三個欄位，不再改程式
### 主控裁定：門檻（2026-10-31）

- 一般的線採 A：T_compact=45、T_clear=30。依據 583 盤點到的兩次實際 compact，壓縮前分別在 45% 與 33%；原本的 60 永遠晚於實際 compact 的時間點。
- 主控另設一個門檻：T_compact=60，不判定待 clear。理由是主控長駐（multi-session-orchestration §6），/compact 屬於例外處理；套用 45 會讓主控在正常運作時就一直被標記。
