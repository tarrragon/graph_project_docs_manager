#### 現況（main）
- `project_switcher_overlay.dart` 的 `_handleChooseFolderResult`：`ChooseFolderUnavailable` 走 `AppSnackBar`（`chooseFolderUnavailableMessage`）；`_handleChosenState` 的 `WorkspaceUnavailable` 走 `AppSnackBar`（`folderUnavailableMessage(reason)`）。最近專案項一律 `enabled: true`、`reason: null`。
- `SwitcherOverlay` 尚無 `chooseOtherFailureReason`；ARB 尚無兩個新 key。`RecentProjectItem` 已支援 `enabled: false` + `reason`。

#### 本票範圍
1. `SwitcherOverlay` 新增 `chooseOtherFailureReason`（`String?`，`AppText.caption`，最多 2 行末行截斷；null 時不渲染、不佔高度），位於 `chooseOther` 下方相鄰處，兩種變體（expanded／no-recent）皆適用。
2. ARB zh／en 新增 `switcherChooseFolderUnavailableReason`、`switcherFolderUnavailableReason`（placeholder `reason`），值依 SPEC-004 §4.0.6〈1.88 新增〉表。
3. 失敗狀態由畫面級 provider 持有（不放元件內部）：選擇其他的失敗原因、本次展開內判定不可用的最近專案項（路徑 → reason）。浮層收合時清空。
4. 選擇其他：`ChooseFolderUnavailable` → 原因文字 `switcherChooseFolderUnavailableReason`；`ChooseFolderSelected(WorkspaceUnavailable)` → `switcherFolderUnavailableReason(reason)`。兩者皆不呼叫 `AppSnackBar`。
5. 最近專案項：`openPath` 得 `ChooseFolderSelected(WorkspaceUnavailable)` → 該項 `enabled: false`、`reason` 為 `projectUnavailableReasonLabel(reason)`，本次展開期間維持；其他項不受影響；不呼叫 `AppSnackBar`。
6. 清除：失敗文字顯示中，點 `action-switcher-choose-folder` 或任一 enabled 最近專案項時，點擊當下（結果回來前）清除；選擇器取消後不再顯示前一次原因。
- 不含：`ChooseFolderNotRemembered` 路徑（含其 state 為 `WorkspaceUnavailable` 的組合）維持 main 現況、不改不加測試，歸 0.5.0-W1-169；§3.1 內容區 `action-domain-choose-folder` 維持 SnackBar；無障礙播報（規格標提案，非驗收）；展開時的可用性探測（既有範圍外）。
