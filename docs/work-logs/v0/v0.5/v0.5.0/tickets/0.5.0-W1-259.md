## Problem Analysis
<!-- Schema[IMP/Problem Analysis]: 選填（小型 IMP 可留 placeholder；大型 IMP 建議填寫）（.claude/pm-rules/ticket-body-schema.md） -->
### 現況與可重用機制（PM 前台調查，2026-10-14）

- `track_commit.execute_commit` 把輸入檔全部交給 `commit_files_isolated(normalized_input, message, cwd=repo_root)` 整檔提交。`_cli_managed_paths` 會把票所屬版本的工作日誌與 topic-assignments.txt 列為隱含可寫，所以這兩個檔案也會整檔進入提交，他票尚未提交的行會一起被帶進去。
- 可重用機制：`git_ops.commit_files_isolated` 已經有 `append_lines: Dict[path, str | AppendSpec]` 參數。這類檔案不整檔 stage，提交內容是「HEAD 各行 + 本次追加各行」，不帶入工作區裡他人未提交的內容。complete（lifecycle.py）與 track_batch 已經用 `worklog_append_spec` 走這條路徑提交工作日誌進度行，可以參照。
- 修法方向：在 track_commit 裡，對輸入中屬於 append-only 共用檔的路徑（topic-assignments.txt、版本工作日誌），先算出「工作區相對 HEAD 新增、且含本票 ID 的行」，以 append_lines 傳入，同時從 paths 移除。原因是 docstring 寫明與 paths 重疊時以整檔為準。
- 要確認的邊界：
  - 輸入只有共用檔、paths 變空時，commit_files_isolated 要求 paths 第一個是存在的檔案。要確認 paths 為空時的行為，必要時以本票票面或其他既有檔作主路徑，或在呼叫端擋下並給出清楚的錯誤。
  - 共用檔沒有本票的行時，不提交該檔，並輸出提示。
- 約束：`git_ops.py` 屬 D 線，不得修改，只能使用既有的 `append_lines`／`AppendSpec` 介面。
- 查重：#55 的 topic-backfill-assign 行層級提交待辦採用同一手法，關係為引用。

## Solution
<!-- Schema[IMP/Solution]: 選填（.claude/pm-rules/ticket-body-schema.md） -->
修法：track_commit.py 新增 _split_shared_append_files；topic-assignments 與版本工作日誌自 paths 移除，改以 AppendSpec 經 append_lines 提交「HEAD + 本票新增行」。本票行：topic 首欄等於票 ID；工作日誌整詞含票 ID；只取工作區相對 HEAD 新增的行。共用檔無本票行：不提交並輸出 [INFO]。
paths 變空的處置：commit_files_isolated 在 paths 為空時於函式開頭直接回 empty，不處理 append_lines（已查 git_ops.py）。故 paths 空且有 append 時以票自身 md 作主路徑（淨變更為零屬合法）；票面不存在於 repo root（--worktree）則報錯 exit 1；兩者皆空則 exit 0 並提示。
副作用：共用檔對 HEAD 既有行的修改或刪除不會被提交。舊測試 test_remedy_with_worklog_and_topics_commits 改為共用檔含本票行。
同步：references/track-command.md〈track commit 子命令〉新增段落；SKILL.md 僅一行索引，行為描述不變。
