### 前序變更須注意（0.5.0-W1-231.7，commit c30b17510）

slot_gate 在每次 heavy 命令取得名額後、啟動前，以子程序執行 orphan-test-procs.py 的列出模式（不帶 --kill），並解析其末行摘要「符合 N 略過 M 疑似殘留 K」與「登記可終止」行數。修改本腳本時須確認：(1) 列出模式會移除過期登記，這已成為每次 heavy 啟動的副作用，改動後此行為是否仍合預期；(2) 摘要文字格式為 slot_gate 的解析依據，改動格式須同步修改 slot_gate.count_orphans 與其測試。

## Solution
<!-- Schema[IMP/Solution]: 選填（.claude/pm-rules/ticket-body-schema.md） -->
### 目錄位置定案
改到 HOME 底下：預設 ~/.cache/claude-proc-registry（與名額鎖 ~/.cache/claude-slot 同處）。理由：系統暫存目錄在 Linux 為全機共用且名稱可預測，改位置後即不受他人預建同名目錄影響；HOME 與名額鎖共用同一信任邊界與驗證手法。CLAUDE_PROC_REGISTRY_DIR 覆寫仍有效且同樣經驗證。舊位置的殘留登記不遷移（被 SIGKILL 的舊登記屬短期殘留，可接受）。

### 實作
- run-with-timeout.py：registry_dir 預設改位置；_prepare_registry_dir 以 lstat 驗證非 symlink、為目錄、擁有者為本人、無 0o077 權限位，不符拋 PermissionError，register_group 既有 except 路徑寫 stderr 一行並回 None，命令照常執行。暫存檔改以 O_CREAT|O_EXCL|O_NOFOLLOW、0o600 建立再 os.replace。
- orphan-test-procs.py：registry_dir 同值；registry_dir_problem 在讀取前以同樣條件檢查（不建立目錄），不安全則印「登記目錄不安全，略過」且不讀、不終止。新增契約行 `ORPHAN_SUMMARY matched=N skipped=N suspects=N registered=N`（registered = 判為可終止的登記數）。
- slot_gate.py：_ORPHAN_SUMMARY_RE 只認契約行；registered 取自契約行，不再掃「登記可終止」前綴。
- 測試：run-with-timeout 側新增他人擁有／群組可寫／其他人可寫／symlink 四情境、命令不被擋、O_NOFOLLOW 旗標、預設位置兩端一致、覆寫兩端一致；orphan 側新增不安全目錄不讀、symlink 不讀、契約行與人讀行一致、registered 計數；slot_gate 側新增人讀行改字不影響計數、僅人讀行無契約視為查詢失敗。既有替身與手建登記目錄改為 0o700／契約行。

### 舊碼紅燈證據
修改前跑新增測試：scripts 側 11 failed 3 passed（紅：四情境、兩個 does_not_block、default_registry 位置、orphan 不安全目錄／symlink／契約行／registered；綠 3 項為 O_NOFOLLOW、private、override，因 tempfile.mkstemp 本就帶 O_NOFOLLOW，該測試鎖住旗標而非翻紅）；slot_gate 側 3 failed（registered 契約、改字不少算、僅人讀行）。

### 測試結果
scripts 兩檔 182 passed；slot_gate + merge_gate 128 passed。

### Phase 4 結論
重構需要：否。技術債務：registry_dir 與驗證邏輯在寫入端與讀取端各一份（兩支獨立腳本無共用 import 路徑），以測試鎖兩端位置一致；驗證條件與 slot_gate._prepare_dir 重複，後續可評估收斂進 lib。程式碼品質：A。結論：無需重構，重複項已記錄。
