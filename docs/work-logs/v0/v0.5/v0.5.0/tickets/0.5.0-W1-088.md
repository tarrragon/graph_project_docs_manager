## Solution
<!-- Schema[DOC/Solution]: 免填（DOC 類型以變更摘要取代）（.claude/pm-rules/ticket-body-schema.md） -->
commit 88db0b0cd：`docs/system-layer.md` §8 新增「SPEC-001」「SPEC-002」兩子節。`docs/spec/ui/` 沒有 domain map（系統層 §1.3：畫面狀態是 layer 不是 domain），所以兩份 SPEC 都比照 SPEC-003 的先例寫在系統層。歸屬判準沿用 §8 開頭：看驗收對象落在哪個 bundle 的公開面。

| FR | 歸屬 | 依據 |
|----|------|------|
| SPEC-001 FR-01 | L4（非 domain） | 驗收對象是 §1–7 每列的退出路徑欄 |
| SPEC-001 FR-02 | L4；Corpus、Diagnostics | 驗收寫的是「Domain 視圖載入、Ticket 載入、破洞掃描三處長時操作」；比照 SPEC-003 FR-02 列：載入由 Corpus 解析，掃描由 Diagnostics |
| SPEC-001 FR-03 | L4（非 domain） | 驗收對象是空狀態「至少一個非返回的動作」 |
| SPEC-001 FR-04 | Schema；L4 | 「schema 版本超出已知範圍」對應 Schema domain map §3 公開面「版本相容判定」；顯示版本值、不繪製屬 L4 |
| SPEC-001 FR-05 | L4（非 domain） | 驗收寫的是「以視覺差異呈現（虛線框／降低不透明度）」 |
| SPEC-001 FR-06 | L4（非 domain） | 驗收寫的是顯示 UC 資訊、說明與開啟原始檔動作；比照 SPEC-003 FR-06 列，開啟原始檔只算 Workspace 的呼叫端觀測 |
| SPEC-001 FR-07 | Schema；L4 | `tracking_schema.json` 缺席與 `.claude/VERSION` 對應 Schema domain map §3 的公開面「型別表」與內部面「.claude/VERSION 讀取」；兩個狀態的說明與切換出口屬 L4 |
| SPEC-001 FR-08 | L4（非 domain） | 驗收對象是 §8.1 表與 `find.byType(SnackBar)` |
| SPEC-002 FR-01 | L4（非 domain） | 驗收是對 `lib/` 跑 grep 找裸值 |
| SPEC-002 FR-02 | L4（非 domain） | 驗收是 `lib/tokens/` 的具名常數表 |
| SPEC-002 FR-03 | L4（非 domain） | 驗收是 SPEC-001 各狀態顯示欄由元件庫元件組成 |
| SPEC-002 FR-04 | L4（非 domain） | 驗收是間距與字級的具名階 |

- 對 SPEC-002 下同一條指令，結果為通過，rc=0

- 只改了 docs/system-layer.md。SPEC、.claude、lib、test 都沒有動
