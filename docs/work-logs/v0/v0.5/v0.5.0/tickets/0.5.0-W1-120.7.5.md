## Solution
<!-- Schema[IMP/Solution]: 選填（.claude/pm-rules/ticket-body-schema.md） -->
### 實作（thyme-python-developer 於 worktree，PM 依流程 B 代寫，2026-10-14）

提交：0a9f0a467（主體）、c918986ac（追修），以 worktree merge 隔離索引 CAS 合併為 b1f257015。

- `&` 加入語句分隔符；控制結構 if、then、else、elif、do、while、until、`{ }`、`!`、coproc、`function NAME {` 的語句頭會被略過。`for` 的語句頭不略過，避免 `for git in ...` 被誤判。
- 前綴白名單：nice、timeout（含 DURATION 與長選項）、stdbuf、caffeinate、sudo 與 env 帶選項、builtin、time -p、doas、chronic、flock（略過鎖檔、-w、-E）。
- `git -C<path>` 黏寫、`-c alias.X=值` 行內別名（優先於設定檔，不覆蓋內建子命令）、`-c<k=v>` 黏寫。
- 反引號：`extract_backtick_bodies` 另取本體掃描，雙引號內算、單引號內不算；原命令字串不改，`git -C \`pwd\`/repo commit` 既有測試不受影響。
- env -S、watch、flock -c：以 `_wrapper_script` 取出字串後比照 bash -c 遞迴解析。
- stdin shell（`| bash`、`bash <<< 字串`、`cat s | bash -s`）回 None。
- `skip_prefix_wrapper_count` 新增 `extended=False` 參數，只有 git 定位傳 True；lib/test_command_parse 的既有行為不變。第一版直接改預設行為，曾讓 test_test_command_parse 2 項失敗，改成旗標後恢復。
- `find_git_invocations`、`parse_command_statements`、`match_git_commit` 的回傳形狀不變。

### PM 驗收

- 阻擋型守衛對新增 None 情形的處置逐支核對：add-broad-guard 對 None fail-open；phase4 用 parse_command_statements（未改）；其餘守衛先過 contains_git_word。與 git 無關的 `| bash` 不會被誤擋。
- worktree 內重跑 8 個檔 951 passed（rc=0），追修後 6 個檔 936 passed（rc=0）；合併後在 main 重跑 13 個檔 1205 passed（rc=0）。
- 背景安全審查：0a9f0a467 報 4 項，PM 實測出 10 種漏判寫法，由 c918986ac 補上；合併後又報 3 項 parser-differential，未再追修。名單擴充沒有收斂終點，改由 0.5.0-W1-120.7.9（ANA）做模型取捨。
- 仍未涵蓋：xargs -I{}、find -exec、變數與命令替換組出的命令，列入 0.5.0-W1-120.7.4 殘留清單。

### Phase 4

重構需要：否。技術債務：有。`skip_prefix_wrapper_count` 以旗標切開兩套語意，根因是 test_command_parse 有自己的 launcher 剝除，長期應合併，歸 0.5.0-W1-120.7.9 的方案比較一併處理。程式碼品質：A。
