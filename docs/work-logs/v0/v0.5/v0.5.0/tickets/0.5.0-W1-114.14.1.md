## Solution

### 用戶裁決（2026-10-12，AUQ）

載入時掃描發生非預期錯誤（不是資料夾不可讀，也不是三個阻擋狀態的判定），Domain 視圖新增「載入失敗」狀態，提供重新載入與切換專案。另兩個選項不採：退回未選專案（沒有重試，其他畫面看不出失敗）、維持停在載入中（使用者無從得知失敗，違反 W1-013「錯誤的載體是畫面」）。

### PM 處置（e1，2026-10-12；文案、key、識別字與既有規則的直接後果）

| 項目 | 處置 |
|------|------|
| 狀態名與 id | §1「載入失敗」，`state-domain-load-failed`（比照 `state-domain-not-framework` 等阻擋狀態命名） |
| 顯示 | 4.23 `BlockedState`，message `domainLoadFailedMessage`：zh「掃描此專案時發生非預期錯誤，無法載入圖譜」／en「An unexpected error occurred while scanning this project, so the graph could not be loaded.」。message 只寫結果與原因，操作由按鈕承載（4.26 訊息設計要求） |
| 可用操作 | 重新載入（`reloadAction`：zh「重新載入」／en「Reload」，`action-domain-reload`）、切換專案（內容區 `action-domain-switch-project`，渲染條件由三個阻擋狀態擴為四個） |
| 進入條件 | 載入中，且載入輪次拋出非預期例外（不落入未選專案與三個阻擋狀態的判定者）；經「以 App 內建型別表檢視」進入的載入同樣適用 |
| 退出路徑 | 重新載入 → 載入中（同一資料夾、同一模式：失敗的載入若是降級檢視，重試仍為降級檢視）；切換專案；導覽（殼層通則） |
| 已存路徑與最近清單 | 不變。資料夾可存取，失敗不屬於存取問題；下次啟動照常還原並重新載入，若仍失敗再落本狀態 |
| §2–§6 專案未就緒 | 原因由三選一改為四選一，新增 `projectUnreadyReasonLoadFailed`：zh「圖譜載入失敗」／en「Graph failed to load」；進入條件加入「載入失敗」 |
| 提示需求（§8.1） | 否。T2：阻擋狀態占滿內容區，轉換可見；不另發 SnackBar 或通知（FR-08 不重複告知） |
| 狀態總數 | §1 由 11 列改為 12 列，總數 40 → 41，第 41 列為 §1「載入失敗」；SPEC-003 §0／§4／FR-01、SPEC-004 §3.6 依此同步 |
| 日誌 | 沿用 level 900 錯誤日誌（觀測性規則 1），本狀態不另定日誌 |
