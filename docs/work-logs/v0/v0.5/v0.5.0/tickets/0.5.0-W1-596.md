### 重現（L45，2026-10-31，以合成 PreToolUse payload 直接餵給 hook，未實際寫檔）

hook 版本：.claude/hooks/bash-write-boundary-guard-hook.py，最後修改 a3d97a69e（2026-10-20）。
代理人當時的原始命令取自 worktree 自己的 hook 日誌（代理人的 hook 以 worktree 為 CLAUDE_PROJECT_DIR，記錄寫在 worktree 的 .claude/hook-logs，主 checkout 的日誌查不到）：
`for f in integration_test/app_test.dart integration_test/real_font_layout_test.dart; do python3 - "$f" <<'EOF' ... p=sys.argv[1]; open(p,'w') ...`
日誌判定：`decision=allow reason=subagent_no_scope_hit targets=['$f'] skipped=['$f:unresolvable']`

| 輸入 | 決策 |
|---|---|
| 路徑經 shell 迴圈變數 `"$f"` 傳成 argv，heredoc 內 `open(sys.argv[1],'w')`（正向對照） | **allow** |
| 同一寫法，argv 改為字面路徑 `integration_test/app_test.dart` | deny |
| `python3 -c "open('integration_test/...','w')"`、pathlib、絕對路徑、`cd` 進 worktree 後寫入、字串拼接、os.path.join、`sed -i` | 全部 deny |

結論：hook 把無法靜態解析的路徑（shell 變數）歸為 unresolvable 並放行。守衛的失效方向是放行，放行時沒有任何提示。
