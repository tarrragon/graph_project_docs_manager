## Problem Analysis
<!-- Schema[ANA/Problem Analysis]: 必填（.claude/pm-rules/ticket-body-schema.md） -->
### 發現者補充（L18，2026-10-27）

- 啟動方式：486.1 的閘門由 L18 以 Bash 工具 `run_in_background: true` 執行 `worktree merge --branch ... | grep -v ... | tail -30`。也就是背景任務，外層多了一段管線，管線的 `tail` 讓輸出直到結束才寫入輸出檔。
- 本次沒有取得實測資料：閘門在 20:20 開始，約 17 分鐘後由同一個 session 收到完成通知（flutter 綠燈，合併 326347aad）。用戶選擇 /compact 之前閘門已經結束，所以「關閉 session 時閘門是否隨之終止」這次沒有被測到，也沒有反例。
- 更正：L18 稍早告訴用戶「閘門程序是獨立程序，應該會繼續跑完」，這是未經查證的推定，與主控「會連帶終止」的推定相反。兩者都沒有實測，應以本票的實驗為準。
- 實驗可沿用同樣的形態：在一個可丟棄的 session 中以 run_in_background 啟動長時間子程序（不必是真閘門），關閉 session 後查該 pid 與其子程序是否存活，並與 /compact 對照。
