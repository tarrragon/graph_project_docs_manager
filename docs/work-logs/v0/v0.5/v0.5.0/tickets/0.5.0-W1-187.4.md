### 設計輸入：檢查項目與強制層（他專案 session 回報，2026-10-13）

來源為 flutter_balance 的 session 回報，非本票執行者親自量測。

- 代理人三次開跑測試前的 load 為 64.74／29.15／43.79，皆高於派發 prompt 所寫的門檻 24，三次都照常執行。寫在 prompt 的資源門檻沒有產生約束力。
- 同一時段孤兒測試程序為 0 個而 load 仍約 48，交換空間 18432M 已用 18015M。負載高的原因當時是記憶體換頁，只看 load 與孤兒數會看不到。

對本票的影響：輸出項目除每核負載與孤兒數外，應評估納入記憶體壓力與交換空間用量。上層分析已否決「超過門檻時阻擋測試」，理由是高負載可能來自與測試無關的程序且無從解除；上述實測正是該情形，阻擋與否的結論不因此改變，但警告內容須讓讀者分得出負載來自孤兒還是來自換頁。
