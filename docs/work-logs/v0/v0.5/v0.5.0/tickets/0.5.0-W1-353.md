### PM 定位成因（-3e，2026-10-19 16:10）：測試執行環境缺 pyyaml

代理人 31 次取樣全綠後，PM 比對各代理人跑測試的指令，發現有人用 `uv --directory .claude/hooks run pytest`，有人用 `uv run --with pytest python -m pytest`，並據此實測：

1. `uv run --no-project --with pytest` 建的臨時環境疊在「目前目錄找到的 interpreter」上。在 `.claude/hooks/` 下執行時繼承 `.claude/hooks/.venv`，`yaml` 從 `.claude/hooks/.venv/lib/python3.12/site-packages/yaml/` 載入；換到沒有 `.venv` 的目錄（實測 `docs/`）執行，結果為 `No module named 'yaml'`
2. 用沒有 yaml 的環境跑 `.claude/hooks/tests/test_bare_commit_guard_hook.py`，結果 `3 failed, 141 passed`。失敗的正是這三項：`TestDeclaredScopeReadsLiveTicket::test_e1_renamed_path_on_ticket_is_declared`、`TestDeclaredScopeReadsLiveTicket::test_deny_mapping_uses_ticket_files`、`TestLiveScopeFallbackToSnapshot::test_readable_ticket_replaces_snapshot_without_warning`。斷言為 `['snap.py'] == ['live.py']`，即讀票面 frontmatter 失敗後退回派發快照

**機制**：剛建立的 linked worktree 沒有 `.claude/hooks/.venv`（gitignore，不隨 worktree 建立），這時用不建立 project 環境的指令跑測試就缺 pyyaml。`.claude/lib/dispatch_scope.py` 的 `_with_live_declared_files` 捕捉讀票失敗、寫 warning 後退回快照，所以這三項會紅，其他測試不受影響。之後只要有人在同一個 worktree 用 `uv --directory <wt>/.claude/hooks run pytest`，就會建立 `.venv`，同一份程式就轉綠。這解釋了「同一 worktree 先紅後綠」，也解釋了取樣代理人為何全綠：它用的是會建立 project 環境的指令

**假說一到四的結論維持代理人判定**（全部排除）；成因與 root 解析、派發記錄、跨檔順序都無關
