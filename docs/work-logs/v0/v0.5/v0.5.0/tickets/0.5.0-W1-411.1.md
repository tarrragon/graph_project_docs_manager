## Context Bundle

### 實作所需事實（L14／session-naming 整理，2026-10-20）

**stdin 契約**（Claude Code statusLine 內建說明，2.1.304 binary）：JSON 欄位包括 `session_id`、`session_name`（選填，只在 /rename 或 -n 設定後出現）、`transcript_path`、`cwd`、`workspace.project_dir`、`context_window.{total_input_tokens,context_window_size,used_percentage}`。

**名稱 fallback**：`session_name` 缺席時，掃 `~/.claude/sessions/*.json`，找出 `sessionId == stdin.session_id` 的那筆，取其 `name`。只讀 `*.json`，不讀 `*.key`；讀檔失敗就視為沒有名稱。

**線號解析**：必須與看板規則一致，看板實作在 `tools/line-board/hooks/lanes.ts`。
- 掃描範圍：協調票 `## Solution` 二級標題到下一個二級標題之前。
- 行首比對正則 `^\*\*L(\d+) 現行佇列\*\*(?:（([^）]*)）)?：(.*)$`，清單項、表格內、反引號範本內的行都不算。
- 同一條線只取最後一行；票序為 `（結束）` 的線視為結束。
- 括號內的名稱與 session 名稱做精確比對。
- 一個名稱可能對到多條線，此時全部列出，例如 `L6·L13`。

**輸出**：
- 先印一行前綴 `L<n> │ <名稱>`；沒有對到線時只印 `<名稱>`；名稱也沒有時不印前綴。
- 接著以同一份 stdin 執行內層命令，原樣輸出它的 stdout。

**參數**：
- `--coord-ticket <路徑>`：相對路徑以 `workspace.project_dir` 為基準；未給或檔案缺席時，不顯示線號。
- `--inner <命令>`：未給時讀 `~/.claude/settings.json` 的 `statusLine.command`。若讀到的命令就是本腳本，不得遞迴，此時不執行內層。

**失敗語意**：任何解析失敗只省略前綴，內層狀態列必須照常輸出；內層命令失敗時保留前綴。不得印 traceback 到 stdout。

**實作位置與測試**：
- 腳本：`.claude/skills/multi-session-orchestration/scripts/statusline_lane.py`，只用 stdlib，python3 shebang。
- 測試：`.claude/skills/multi-session-orchestration/tests/`。skill 有 tests/ 時，合併閘門會跑 `skill:multi-session-orchestration` 套件。
- 測試須含 E2 正向對照：給一份該顯示線號的協調票 fixture，斷言前綴有線號；另一份 fixture 中同名的線已寫 `（結束）`，斷言不顯示線號。

**文件**：`references/session-naming.md` 補〈狀態列〉一段，寫明啟用方式（專案 `.claude/settings.local.json` 的 `statusLine.command` 指向本腳本並帶 `--coord-ticket`）。不得寫死本專案的票號或使用者路徑。

**不在範圍內**：
- 寫入 settings.local.json：由 PM 在合併後向用戶確認才寫。
- acceptance 1 的實測 stdin 擷取：由 PM 在啟用時做。
