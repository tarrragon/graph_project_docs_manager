## Solution

### 逐支改寫結果（commit bb0ee57e8）

| hook | 事件 | 原警告路徑 stdout 決策欄位 | 受眾裁定 | 改寫 | 分派器 |
|------|------|--------------------------|---------|------|--------|
| dart-style-guardian | PostToolUse Edit/Write | 違規時 stdout 為 {continue:true, message}，無 decision/permissionDecision；無需合成 | 模型可見（all）：樣式違規需模型修正 | 移除 message 欄位，改 emit_model_reminder | 否（非 Bash group） |
| settings-registration-exec-guard | PostToolUse Edit/Write/MultiEdit | 無輸出（已降級為僅日誌，無 stderr、無 stdout） | 僅日誌（無提醒可遷移），維持現狀 | 不改碼；測試補 stdout 空斷言 | 否 |
| hook-dependency-isolation-check | SessionStart + PostToolUse | 原 stderr 加 exit 0，stdout 無任何輸出，無決策欄位 | 模型可見（all）：框架維護者與模型需據以修宣告 | SessionStart 用事件名 SessionStart，PostToolUse 用 PostToolUse | 否（SessionStart 與 Edit/Write/MultiEdit 註冊於 settings.json） |
| ana-ticket-metadata-validation | PostToolUse Write | stderr 加 exit 0，stdout 無輸出，無決策欄位 | 模型可見但 pm_only（訊息內文「PM 派發前請複檢」） | emit_model_reminder audience=pm_only 並傳 input_data | 否 |
| ticket-creation-validation | PostToolUse Write | stderr 加 exit 0，stdout 無輸出，無決策欄位 | 模型可見但 pm_only（decision_tree_path 為 PM 決策樹概念） | 同上 | 否 |

### 讀取來源記錄（只記錄不修）

- dart-style-guardian 讀 sys.argv[1]（settings.json 傳 $CLAUDE_FILE_PATH），該環境變數非平台 hook 文件化提供，真實環境下極可能為空，則走「No files to check」提早返回，永不觸發違規分支。需實測確認，若成立應改讀 stdin tool_input.file_path。
- ticket-creation-validation 原 sys.path 只加 .claude/hooks，`from lib import get_effort_level` 恆 ImportError 走 fallback（effort 恆 medium）。本次為取得 emit_model_reminder 補加 .claude 路徑，副作用是 get_effort_level 現在真正載入。
- ana-ticket-metadata-validation docstring 稱「已停用註冊」，但 settings.json PostToolUse Write 仍註冊（裸路徑 shebang 執行）。
- hook-dependency-isolation 於 settings.json 註冊在 SessionStart 與 PostToolUse 的 Edit/Write/MultiEdit。

### 實地觸發方式與須避開的提早返回

- dart-style-guardian：編輯 lib/presentation/*.dart 並含 TextButton( 之類；避開：argv 為空、路徑不含 /lib/presentation/、.g.dart/test/l10n 等跳過、檔案不存在。注意上列 argv 來源疑慮。
- hook-dependency-isolation：SessionStart 觸發需存量有不一致（目前專案若 0 筆則無輸出）；PostToolUse 需編輯 .claude/settings.json 或 .claude/hooks|skills/*/hooks/*.py 且 scan_all 有 issue。避開：tool_name 非 Edit/Write/MultiEdit、路徑不相關、無 issue。
- ana-ticket-metadata：Write docs/work-logs/*/tickets/*.md，frontmatter 含 source_ticket 非空或 who.current 為 ANA 類，且 acceptance 含「;」。避開：非 ticket 路徑、非 ANA 來源、subagent 觸發（pm_only 丟棄）。ticket-file-access-guard 可能擋直接 Write。
- ticket-creation-validation：Write 新 ticket md，無 parent_id、type 非 DOC、缺 decision_tree_path。避開：子任務、DOC、frontmatter 解析失敗、subagent（pm_only）。
- settings-registration-exec-guard：無輸出，無需實地觸發。
