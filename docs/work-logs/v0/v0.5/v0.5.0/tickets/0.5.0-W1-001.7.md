### PM 處置與 WRAP（e1，2026-10-09）：4a 審查回報 D1／D2

D2（版本超出已知範圍又缺 direction）——PM 處置，採 (a)：resolveEdgeTypes 在此情況回報 unavailable，與缺正向基數一致。依據：FR-01 明文「不可把缺欄一律當 directed」，且同函式缺基數已回報 unavailable；此路徑由 SPEC-001 §1 關卡擋住、使用者不可見，(a) 只讓程式與條文一致。補一條測試：版本超出範圍＋缺 direction → unavailable（E2）。

D1 WRAP（快速+）：direction 值不合法或非字串（例 "undirect"）
事證：FR-01 對「單一邊型條目不合法」（值不是 map；class、forward_field、layer 缺席或不是字串；reverse_field 存在但不是字串）已定為「整筆拒收並寫日誌，視同該邊型缺席，依缺欄位規則處置——版本在已知範圍時取內建表定義」；direction 是後加欄位，未列入。執行者現行選擇「當缺欄處理」（只補 direction，其餘欄位照用）。語料 0 筆。
| 候選 | 規則 | 致命風險 |
|---|---|---|
| Q1 | 比照既有不合法條目規則：整筆拒收、寫日誌、視同該邊型缺席，版本在範圍內取內建表整筆定義 | 一個打錯的 direction 讓該邊型其他自訂欄位也被內建表覆蓋 |
| Q2 | 當 direction 缺欄：只補 direction（取內建表；內建表沒有則「預設（有向）」），其餘欄位照用，寫日誌（現行實作加 log） | 與其他欄位不合法的處置不一致，規則多一條例外 |
| Q3 | 另報缺陷（graphDefect 或新原因碼） | 需新缺陷類別，範圍擴大 |
傾向 Q1，信心中：與既有「條目不合法」規則同一條路，FR-01 只需把 direction 加進列舉；代價是覆蓋範圍較大，但語料 0 筆、上游匯出不會產生此值。

用戶裁決（2026-10-09）：D1 取 Q1，direction 不合法列入整筆拒收；D2 PM 處置 (a)。皆寫入 SPEC-007 v1.21 FR-01 與兩條驗收。
