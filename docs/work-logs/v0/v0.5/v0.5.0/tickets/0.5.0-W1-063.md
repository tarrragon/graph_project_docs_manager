### 實驗協定（開工前寫定，執行中不改判準）

#### 1. 基準（200K 時期）

- 母體：對話紀錄中有實作代理人派發、且同票派發 ≥2 次的 92 張票（量測條件：Agent 呼叫的 subagent_type 屬實作層、prompt 含票號）
- 抽樣：依派發次數分層，至少 20 張；記錄抽樣種子與清單
- 分類：context 觸頂／回合上限／審查退回／測試失敗／中斷（用戶或 session 結束）／其他；每張附判定依據的紀錄位置
- 基準值：重派率 15%（92／604），以及 context 類重派占比

#### 2. 0.5.0 逐次記錄

每次實作層派發完成時，PM 於本票 Test Results 追加一列：票、代理人、模型、subagent_tokens、tool_uses、duration_ms、首次回報測試是否全綠、是否重派與原因、審查發現數（高／中／低）。

#### 3. 成對對照

- 組數：至少 5 組（PC-168：N ≥ 5）；優先取 Layout 產品實作票，不足時以框架 P3 實作票補
- 方法：同票、同基準 commit，各自 worktree；一份派 parsley（sonnet[1m]），一份派臨時對照定義（內容相同、model 為 opus[1m]）
- 臨時對照定義：`.claude/agents/` 下不進版控的檔案，name 與正式代理人不同；新增後須開新 session 才載入（代理人定義不會在 session 中途重新載入）
- 盲審：兩份 diff 以 A／B 標記交 linux 審查，審查者不知道哪份是哪個模型；合併審查發現較少的一份，另一份 worktree 丟棄
- 比較：審查發現數依嚴重度、首次回報是否全綠、重工次數、subagent_tokens

#### 4. 預寫 tripwire（任一成立即建調整票）

| 編號 | 條件 | 調整票的方向 |
|------|------|-------------|
| T1 | 0.5.0 實作層重派率高於基準 15% | 檢查重派原因分布，判定是否為模型問題 |
| T2 | 成對實驗中 sonnet 份的高嚴重度審查發現多於 opus 份的組數 ≥ 3／5 | 評估實作層改回 opus[1m] 或按代理人分別設定 |
| T3 | 0.5.0 出現 context 類中途失敗（含 Prompt too long） | 檢查 1M 是否實際生效及任務拆分 |

皆不成立：結論為維持現行分層，於 agent-model-selection.md〈沿革〉補記評估結果。

**判讀**

- context 觸頂 0／35；只計代理人實際跑過之後的 11 次重派，也是 0／11。本專案 200K 時期沒有 context 類重派，「1M 降低 context 類重派」這一問在本專案沒有可改善的基準量。
