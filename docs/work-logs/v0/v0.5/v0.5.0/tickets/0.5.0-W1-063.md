### 實驗協定（開工前寫定，執行中不改判準）

#### 1. 基準（200K 時期）

- 母體：對話紀錄中有實作代理人派發、且同票派發 ≥2 次的 92 張票（量測條件：Agent 呼叫的 subagent_type 屬實作層、prompt 含票號）
- 抽樣：依派發次數分層，至少 20 張；記錄抽樣種子與清單
- 分類：context 觸頂／回合上限／審查退回／測試失敗／中斷（用戶或 session 結束）／其他；每張附判定依據的紀錄位置
- 基準值：重派率 15%（92／604），以及 context 類重派占比

#### 2. 0.5.0 逐次記錄

每次實作層派發完成時，PM 於本票 Test Results 追加一列：票、代理人、模型、subagent_tokens、tool_uses、duration_ms、首次回報測試是否全綠、是否重派與原因、審查發現數（高／中／低）。

#### 3. 成對對照

- 組數：至少 5 組（PC-168：N ≥ 5）；優先取 Layout 產品實作票，不足時以框架 P3 實作票補
- 方法：同票、同基準 commit，各自 worktree；一份派 parsley（sonnet[1m]），一份派臨時對照定義（內容相同、model 為 opus[1m]）
- 臨時對照定義：`.claude/agents/` 下不進版控的檔案，name 與正式代理人不同；新增後須開新 session 才載入（代理人定義不會在 session 中途重新載入）
- 盲審：兩份 diff 以 A／B 標記交 linux 審查，審查者不知道哪份是哪個模型；合併審查發現較少的一份，另一份 worktree 丟棄
- 比較：審查發現數依嚴重度、首次回報是否全綠、重工次數、subagent_tokens

### T1 修訂（2026-10-07，用戶裁決「只計啟動後的非規劃重派」）

**修訂理由**：基準 35 次重派中 24 次發生在代理人啟動前（守衛擋下、參數錯誤、worktree 被拒），與模型無關；且 0.5.0 前段 Ticket ID 守衛因殘留 handoff 檔失效（W1-067），守衛擋下在 0.5.0 不會出現。照原判準比較，0.5.0 的重派率會被系統性低估，偏向對 sonnet 有利。

**原判準（保留供對照）**：T1 = 0.5.0 實作層重派率高於基準 15%（92／604）。

**修訂後 T1**：

- 計入：代理人實際執行之後、非原本規劃的重派或退回，原因可歸於實作——審查退回（實作缺陷）、測試失敗、context 觸頂、回合上限、提前交回。含以 SendMessage 讓同一代理人續做的退回（基準期此類未被計入，故本口徑對 sonnet 偏嚴）。
- 不計入：啟動前被擋、原本規劃的分階段、根因在規格或 prompt 的重派（例：W1-056 根因為票面規格）、環境因素（例：W3-001 全套測試掛住，W1-072 查證中）。不計入者仍逐列記錄原因。
- 基準（同口徑，由已分類樣本估算）：20 張樣本中 5 張有此類重派（W1-067、W2-007、W1-068、W3-550、W1-006）；樣本取自重派票（母體 15%），母體估計值約 15% × 5／20 ≈ 3.75%。樣本小、信賴區間寬。
- 觸發：0.5.0 實作層派發的票中，有此類重派的票占比 > 7.5%（基準 2 倍），且張數 ≥ 2。兩條件並列，避免小樣本單一事件觸發。
