## Context Bundle

### 派發前定稿（4a，2026-10-09）
規格：SPEC-001 v1.40 §1〈泳道布局規則〉「列集合與列序」「`traverses` 異常的步驟」（「未定位」列）、「畫面」列例外段；SPEC-007 v1.20 FR-13「回傳形狀」條。測試設計：docs/test-design/SPEC-001-test-design.md §1.3、§1.4、§1.5、§3.1 L1-4、L2-5、L2-6、L8（L1-1～L1-3、L2-1～L2-4 已移 G13，本票不做）。

#### FR-13 介面的處置（PM 決定，114.7 尚未落地）
- Layout 不呼叫 Graph 內部，也不等 114.7：列序組裝寫成純函式，FR-13 的回傳值作為**輸入參數**傳入，形狀依 SPEC-007 FR-13「排序後的 bundle 清單，每項附層號，推不出層者為 null」，用 Dart record `List<({String domain, int? layer})>` 表達（不在 lib/graph 新增型別，不佔用 114.7 的命名權）。
- L8 的「替身」即測試直接構造此清單；L8-2 以刻意不同於分層推導的排序證明 Layout 照單使用。
- 114.7 定介面識別名時，回傳值須能無損轉成此 record 清單；轉接放在呼叫端（domain_view／provider），不在 Layout。

#### 期望（main 現況：lib/layout 不存在，全部為新增）
| # | Given | Then |
|---|-------|------|
| L8-1 | FR-13 清單為本專案快照排序（G13-1 期望值） | 列序：「畫面」、schema、workspace、corpus、history、diagnostics、graph、ticketdetail、layout，共 9 列 |
| L8-2（E1） | 同一組 bundle 與依賴邊，FR-13 清單刻意改為 layout、schema、其餘原序 | Layout 的 bundle 列序逐值等於輸入清單，且與 L8-1 不同 |
| L8-3 | L8-1 輸入另有一個 traverses 缺鍵的步驟 | 「畫面」、FR-13 排序、「未定位」；排序段不增不減 |
| L8-4（E1） | FR-13 清單末兩項為層號 null 的 X、Y | 照原樣放排序段末尾、「未定位」之前；Layout 不自行判斷環 |
| L1-4 | 單一 bundle、無邊（flutter_balance 形狀，以 builder 構造） | 無異常步驟時 2 列；有缺鍵步驟時 3 列 |
| L2-5 | X 的 depends_on_bundles 含未宣告 ghost | 不產生 ghost 列；指向 ghost 的依賴邊不畫；X 其餘依賴邊照畫 |
| L2-6 | 同一 FR-13 清單，六個不同的選定 UC | 六次列序逐值相同 |

- 測資以 §1.5 的 `test/helpers/spec001/bundle_graph_builder.dart` 構造（本票建立；flow_builder 屬 114.10，本票如需最小步驟輸入可先建，114.10 沿用）；不依賴 114.6 快照。
