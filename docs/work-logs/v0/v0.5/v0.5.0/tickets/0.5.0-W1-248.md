## Problem Analysis
<!-- Schema[ANA/Problem Analysis]: 必填（.claude/pm-rules/ticket-body-schema.md） -->
### 問題根因

直接原因：integration_test/app_test.dart 的「DomainReady（內建矩陣）」群組只替換了 gate 的探測埠（`_ReadyFrameworkSignalProbe` 回報 VERSION 與 JSON 版本皆等於內建版本），工作區為 `WorkspaceReady('/fixture/ready-project')`；但 0.5.0-W1-114.14（commit 092afe4ee，2026-10-12）讓 `GateDetectionNotifier.detect` 通過後改走 `DomainViewLoader.load` → `ScanRound._runRound`，該處以 `_readProjectSchemaJson` 從真實檔案系統讀 `/fixture/ready-project/.claude/skills/doc/doc_system/core/tracking_schema.json`。路徑不存在 → `projectJson = null` → `resolveEdgeTypes` 中 `project == null` 且 `isWithinKnownSchemaRange(null, builtin)` 為 false（`classifySchemaVersion(null)` = Unreadable）→ `EdgeTypeUnavailableReason.projectVersionOutOfKnownRange` → `DomainViewLoader._stateOfRound` → `_unavailableGraph` 的 `assert(false)`。

gate 沒有「漏擋」：gate 看到的是替身回報的版本（InKnownRange），建圖看到的是真實磁碟（無 JSON）。兩條讀取路徑來源不同，測試只替換了其一。測試寫於 W3-383（2026-09-29，當時矩陣來自內建 fixtures），群組註解「矩陣內容來自 App 內建 fixtures」在 W1-114.14 後已失真。

### 影響範圍

- 已驗證：4 個 DomainReady 尺寸測試失敗；「首頁啟動煙霧測試」第一項的 failed after test completion 是同一 assert 的非同步錯誤被歸到 integration binding 的首個測試（CI log 中每次出現在 DomainReady 測試之後）。
- 已驗證：.claude/VERSION（2.81.1）不參與任何一條路徑——gate 用替身，建圖讀 /fixture 路徑；與 SharedPreferences、工作資料夾還原無關（repository 為 `_StubWorkspaceRepository`）。
- 推論（未實機）：路徑 /fixture/ready-project 在任何機器都不存在，本機同樣失敗，非 CI 特有。

### 相關 Error Pattern

部分替身（partial fake）：測試替換上游判定埠，下游重構新增對真實 I/O 的第二條讀取路徑後替身不再足夠。與 PC-165（綠燈不等於 runtime 正確）同族，未另建 error-pattern。
