## Solution
<!-- Schema[IMP/Solution]: 選填（.claude/pm-rules/ticket-body-schema.md） -->
- worktree_manager.py：新增 WORKTREE_REMOVE_TIMEOUT_SECONDS=300；_timed_git_remove 以該常數執行 remove 並經 emit_gate_line 寫入耗時行；_cleanup_recover 在 remove 失敗後僅當 status 全為 " D" 且 HEAD 為 main 祖先才 remove --force + prune，否則列出不成立項並非 0；_cleanup_handle_lock 讀 worktree list --porcelain 的 locked，有鎖停手回報原因與 pid 存活，--unlock 才解鎖；unlock 貫穿 cmd_cleanup／_cleanup_single／argparse。
- A4 rc=0 路徑：_cleanup_execute 在 worktree 已移除、git branch -d 失敗時回 (True, 提示)，rc=0 但分支殘留。改回 False（rc 1）；原測試斷言 rc==0 已改為 1。此為程式碼中唯一「清理未完成卻 rc=0」的路徑；是否即第一例實際路徑僅憑讀碼，無現場證據。
- messages.py 增 REMOVE_LOCKED／UNLOCK_FAILED／RECOVER_REFUSED；SKILL.md cleanup 條目同步。
- Phase 4：重構需要=否；技術債務=發現（get_worktree_uncommitted_count 在 status 失敗時回 0 使 Level 1 誤放行，範圍外未改）；品質=A；新增函式皆 <=20 行、巢狀<=2。
