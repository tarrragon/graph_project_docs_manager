## Problem Analysis
<!-- Schema[IMP/Problem Analysis]: 選填（小型 IMP 可留 placeholder；大型 IMP 建議填寫）（.claude/pm-rules/ticket-body-schema.md） -->
PM 補充實例（2026-10-15 17:4x～17:5x）：imp-306-5 與 imp-309 的 Subagent hand-back 報告送達時，UserPromptSubmit 的 tripwire 皆注入「[WRAP 絆腳索] 偵測到限制性結論（關鍵字：無法）」，兩份報告中的「無法」均為代理人描述既有行為或已知限制的用語，非 PM 結論。兩次 prompt 的開頭皆為 agent-message 框架（含「[Subagent hand-back]」標記行）。另一形態：cross-session-message（他 session 訊息）同樣以使用者回合送入。

## Solution
<!-- Schema[IMP/Solution]: 選填（.claude/pm-rules/ticket-body-schema.md） -->
### 辨識方式與理由
- 方案：前綴比對。YAML restrictive_keywords 新增 skip_prompt_prefixes（agent-message、cross-session-message 的角括號與裸形態，以及 [Subagent hand-back]）；prompt 去除前導空白後以任一前綴開頭，RestrictiveKeywordsStrategy 整個跳過，log_reason=framework_message。
- 理由：(1) 標記清單放 YAML，符合 hook 檔「禁止硬編碼 triggers」約束；(2) 前綴而非全文子字串，使用者在句中提到 agent-message 字樣不被誤跳過；(3) 整個跳過而非只比對標記外區段，因報告本文全在標記之內，切分規則需依未知的結尾格式，易錯。
- 已知漏判：標記不在 prompt 開頭（前面另有文字）的回合仍會比對；實際 agent-message 精確開頭字串以票面描述推定，未見原始樣本，若實際形態不同需補前綴。S4 reflection 訊號未套用（僅 restrictive_keywords 設定）。
- 失敗語意：標記判定拋例外時 fail-open，視為使用者回合照常比對，寫 stderr 並記日誌，不阻擋。
