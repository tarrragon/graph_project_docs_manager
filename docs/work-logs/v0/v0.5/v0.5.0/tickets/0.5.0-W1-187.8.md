### 起點證據（他專案 session 回報，2026-10-13 15:29）

- 孤兒測試程序清空後（flutter_tester 0 個），load average 仍為 47.94／52.40／48.96。
- 回報方的過渡逾時寫法（程序群組終止）兩次使用皆未逾時、未留孤兒；逾時路徑尚未在實際工作中被觸發過。

這兩點指向「孤兒程序是負載來源之一而非主因」，定位仍待本票以實測值寫定。完整數值見 0.5.0-W1-188 的 Problem Analysis。

## Solution
<!-- Schema[ANA/Solution]: 必填（.claude/pm-rules/ticket-body-schema.md） -->
### 定位結論
孤兒程序對 CPU 過載為「無關（現況）」：主因是記憶體交換空間（188），本次取樣孤兒 0 個、殭屍 2 至 3 個且無資源佔用。但孤兒的機制成立，故它是「潛在的偶發放大因素」，並非過載成因；上層分析把它當成因寫入的說法需更正。依據：load 27 以上且 swap 18.5G/19.4G 的狀態下，符合條件的孤兒為 0。

### 六項措施複核
| 子票 | 措施 | 現況 | 判定 | 理由 |
|---|---|---|---|---|
| 187.1 | 逾時包裝腳本 | completed | 維持 | 修的是工具缺口（macOS 無 timeout），與過載佔比無關；已完成 |
| 187.2 | 移除 hook 的全機 pkill | pending | 維持，建議升為最高優先 | 風險是波及他 session，與過載佔比無關，正確性問題；過載時他 session 被誤殺代價更高 |
| 187.3 | 限本專案孤兒清理指令 | pending | 維持，優先級降低 | 現況孤兒 0，補充性工具；仍是 187.4 與 187.5 的依賴 |
| 187.4 | 測試前 hook 輸出負載與孤兒提示 | pending | 調整：範圍改為以負載與 swap 用量為主，孤兒為輔 | 188 證明 prompt 門檻無約束力，真正訊號是 swap；建議只警告不阻擋（原決策維持）；與 188 候選 C 合併考量 |
| 187.5 | 全機 pkill/killall 守衛 | pending | 維持 | 與 187.2 同理，防的是代理人自行清理造成的波及，與佔比無關 |
