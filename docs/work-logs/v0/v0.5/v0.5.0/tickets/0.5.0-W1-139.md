### WRAP（完整模式，e1，2026-10-12）：FR-12「排除經直接 domain 的路徑」的套用時機

**錨點**：讀者是用 UC-02 評估變更影響的維護者；詳情卡要回答「Y 為什麼會影響這個 UC」，每行一條依賴路徑。評估單位：一條路徑集合規則，套用到全部間接依賴格。

**Step 0**：資料足夠。規則全文在 SPEC-001 §1〈間接依賴格的詳情卡：依賴路徑〉；排除列附了理由：「較短的那條已由該中間 domain 為來源列出」。現有語料兩種讀法結果相同（10 格間接依賴）。

**R：規則條文的理由指向哪一邊**
- 排除的理由是**冗餘**：路徑 X→…→Z→…→Y 經過直接 domain Z，而 Z 自己作為來源已列出更短的 Z→…→Y，所以這條是重複資訊
- 若 X 另有一條**不經任何直接 domain** 的較長路徑 X→A→B→Y，它不是冗餘：它揭示 X 對 Y 有一條獨立於 Z 的影響途徑。理由排除不了它
- E-A 下這種 X 整列消失（最短路徑全被判冗餘，但 X 的獨立途徑也一起不見）；E-B 下 X 列出那條獨立途徑
- 保證性：兩種讀法下每個間接依賴格都至少有一行（沿冗餘鏈往下，必有一個直接 domain 的最短路徑不經其他直接 domain），「在泳道中檢視」的跳轉目標兩者皆有定義
- 演算法：E-B 等同「中間節點不得為直接 domain 的子圖上取最短路徑」，單次 BFS 即可，不比 E-A 複雜

**W：選項**（反向框架：排除是否根本不需要？——不需要即 E-F，與已裁決的 UC-06 期望值衝突，列出僅供對照）
| 候選 | 規則 | 讀者看到的 |
|---|---|---|
| E-A | 先取每個來源的最短路徑，再剔除經直接 domain 者（現行實作） | 只有「最短即不冗餘」的來源出現；有獨立長途徑的來源不出現 |
| E-B | 每個來源只在「中間節點不經直接 domain」的路徑中取最短 | 每個有獨立途徑的來源各一行（可能較長） |
| E-E | 不分來源，只列全格最短的路徑 | 最精簡，但「每個來源一條」的既有規則要改 |
| E-F | 不排除 | 與 UC-06 × schema 期望值（不列 diagnostics → corpus → schema）衝突 |

**A：代價與 10/10/10**
- E-B 需改 114.7 已合併的實作（W1-139 本就承接）；詳情卡在罕見情形會多一行較長路徑
- E-A 不改程式，但遇到該情形時，讀者看不出 X 有一條不經 Z 的獨立影響途徑，評估變更影響時會漏看
- 十個月後若依賴圖變密，E-A 與 E-B 的差異會出現；E-B 的資訊量隨之增加，E-A 則隨之遺漏

**P：E-B 的行前預想**
1. 詳情卡出現很長的路徑，讀者覺得雜訊——早期警訊：出現 4 跳以上的路徑行
2. 實作把「中間節點」誤判為含端點，排掉了來源本身——由 UC-04／UC-06 既有期望值測試擋下

**傾向**：E-B，信心中。快速模式時我傾向 E-A；完整檢驗規則條文的理由後改變——理由只支持排除冗餘路徑，不支持連帶丟掉一個來源的獨立途徑。盲點：未訪談實際讀者是否在乎長途徑。
