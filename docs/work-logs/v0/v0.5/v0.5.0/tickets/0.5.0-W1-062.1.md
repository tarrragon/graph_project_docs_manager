## Solution
<!-- Schema[IMP/Solution]: 選填（.claude/pm-rules/ticket-body-schema.md） -->
SubagentStop 的標記全數失敗時（含狀態檔尚不存在），呼叫 `leave_turn_ended_tombstone` 留下 agent_id 墓碑。`record_dispatch` 寫入記錄時，若 agent_id 或 agent_handle 匹配墓碑，直接帶入 `turn_ended_at` 並刪除墓碑。清理條件為消費即刪，加 `TOMBSTONE_TTL_SECONDS=600`，每次狀態寫入時剪除過期墓碑。沿用 `_state_lock` 與 `_write_state` 的鎖與原子寫入。tracker hook 不改。commit 03ca73649，合併 cd50735ce。

### 自檢結果

- 前提：背景派發的記錄先於 SubagentStop，精準標記會命中，不留墓碑，行為不變，由 `test_background_order_leaves_no_tombstone` 驗證。
- RED：修改前 4 failed、3 passed（3 個對照組）。E2 斷言不用墓碑且 Stop 先到時，條目殘留 null。
- GREEN：新增 8 個測試；兩個目標測試檔 83 passed。規則 8 grep 0 命中。
- 實地觸發（本 session 實地觸發確認）：在 `git clone --no-hardlinks` 的 clone 內以 `claude -p` 同步派發一次（主 repo 未執行）。SubagentStop 22:14:19 留墓碑，PostToolUse 22:14:22 寫入記錄，`turn_ended_at`=14:14:19Z（即 22:14:19 本地），墓碑已消費、無殘留。修改前同實驗（0.5.0-W1-062）的 turn_ended_at 為 null。

### Phase 4 評估

- 重構需要：否。
- 技術債務：無新增。執行者指出的 FIFO 後援誤標風險在修改前即存在，由 0.5.0-W1-069 追蹤。
- 程式碼品質：A。
- 墓碑寫入失敗只記 info、不寫 stderr：裁決維持。失敗時退回修改前行為（條目由既有 TTL 回收），屬功能降級而非 hook 故障，不另建票。
- 結論：三個小函式各司其職，消費點放在既有寫入鎖內，不需重構。
