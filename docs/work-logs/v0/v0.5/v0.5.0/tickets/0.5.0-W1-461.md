## Problem Analysis
<!-- Schema[IMP/Problem Analysis]: 選填（小型 IMP 可留 placeholder；大型 IMP 建議填寫）（.claude/pm-rules/ticket-body-schema.md） -->
### 問題根因

460 查證 lib import 時發現：`lib/diagnostics/event_gap.dart`（114.22.1 引入）import `lib/schema/edge_type.dart`，`EventGapsUndetermined` 帶 `EdgeTypeUnavailableReason reason`。違反 SPEC-007 FR-09「Diagnostics 不依賴 Schema 的原因型別」與 `lib/diagnostics/gap_detector.dart` 檔頭約束。

### 影響範圍

- `reason` 無消費者：lib 內沒有讀取點；`lib/screens/gap_report/gap_report_round_state.dart` 只取 `detectEventGaps(...).report`。只有 `test/unit/diagnostics/event_gap_test.dart` 以 isA 斷言型別。
- 同類設計已遵守的參照：`graph_defect_gap.dart` 的 Undetermined 帶 Diagnostics 自己的 `UndeterminedGapReason`，Schema 原因碼由編排層 `undeterminedReasonFromGraph` 轉換。本票採「直接移除欄位」而非改型別，因為沒有讀者。

### 守衛測試樣板

既有同型守衛：`test/unit/layout/layout_import_direction_test.dart`、`test/unit/graph/graph_import_direction_test.dart`。新守衛沿用其掃描與正向對照輸入寫法，放 `test/unit/diagnostics/`，判準：`lib/diagnostics/` 下任何檔案不得 import `package:graph_project_docs_manager/schema/` 或相對路徑指向 `lib/schema/`。正向對照輸入（E2）：一段含 schema import 的字串必須被判為違規。

### 相關 Error Pattern

無匹配既有模式。

## Solution
<!-- Schema[IMP/Solution]: 選填（.claude/pm-rules/ticket-body-schema.md） -->
EventGapsUndetermined 移除 reason 欄位與 schema import；detectEventGaps 對 GraphBuildUnavailable 回 const EventGapsUndetermined()。新增 test/unit/diagnostics/diagnostics_import_direction_test.dart（含 E2 正向對照與遞迴掃描對照）。

Phase 4 評估：重構需要=否；技術債務=無；程式碼品質=A；結論=無需重構，改動為欄位移除加守衛測試。
### 自檢結果

- [x] lib/diagnostics 下無 schema import（守衛測試實際掃描＋PM 檢視 diff）
- [x] EventGapsUndetermined 無欄位，建圖不可用時 report 為空，型別判別不變（event_gap_test isA 斷言保留）
- [x] 守衛含兩則正向對照（package 與相對路徑字串、子目錄遞迴），符合 E2
- [x] 收尾：worktree 隔離派發，合併後由 PM 在主 checkout complete
