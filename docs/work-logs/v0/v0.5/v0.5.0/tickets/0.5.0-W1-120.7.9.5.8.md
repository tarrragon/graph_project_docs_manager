## Solution
<!-- Schema[IMP/Solution]: 選填（.claude/pm-rules/ticket-body-schema.md） -->
修改 .claude/skills/ticket/hooks/acceptance-gate-hook.py：新增 extract_ticket_ids_from_command（收集全部完成類呼叫的 ID，batch-complete 逗號清單拆開、空白分隔本為多 token；原文後備與 legacy 後備同樣收集全部 ID，保序去重）；extract_ticket_id_from_command 保留為取第一個的相容介面；main 改為逐一 check_acceptance_status，任一張 should_block 即以該張結果輸出 deny 並回 2。
失敗語意：解析失敗維持 fail-closed（原文後備，誤判只會多擋）；hook 例外時行為不變（輸出 allow、回 EXIT_ERROR）。
不覆蓋：以變數或命令替換帶入 ID（命令文字看不到，沿 120.7.2 裁定靠自律）。

### 自檢結果
- 4 種多 ID 寫法皆抽到兩個 ID；單一 ID 行為不變；原文後備收集全部 ID，皆有測試。
- 第二張 ID 有未完成 children 時 check_acceptance_status 回 should_block=True（測試鎖定）。
- 改檔僅用 Edit；hook 維持 Python 3.9 相容語法與 logger 傳參規範。

### Phase 4 結論
重構需要：否。技術債務：無（main 內逐票迴圈為最小變更；輸出僅呈現第一張應擋票，多張同時應擋時其餘見日誌，可接受）。程式碼品質：A。結論：無需重構。
