### WRAP（快速+，e1，2026-10-09）：branch_from 指向「欄序無法輸出」步驟的步驟

事證：SPEC-001 §1〈泳道布局規則〉「欄序無法輸出的步驟」只定義 (a) branch_from 懸空、(b) 沿 branch_from 追溯回到自身的循環；步驟 C 的 branch_from 指向 (a)／(b) 步驟 X 時，C 也到不了主線，但不符合 (a)（X 存在）也不符合 (b)（不回到 C 自身）。既有原則「結構異常一律接在最後顯示」（列序推不出層、traverses 異常同一原則）。6 個 UC 現況 0 筆（092 Solution §1 不變式）。

| 候選 | 規則 | 代價 |
|---|---|---|
| V1 | 凡沿 branch_from 追溯到不了主線的步驟，一律依檔內順序 i 接在最後一欄之後（擴大「欄序無法輸出」的定義） | C 與 X 可能不相鄰，父子關係只靠邊表達 |
| V2 | 尾段先依檔內順序輸出 (a)／(b) 步驟，每個之後遞迴輸出其分支（比照欄序的巢狀規則） | 循環內各步互為父子，誰先輸出需再定一條規則；實作較複雜 |
傾向 V1，信心中：一條規則涵蓋所有到不了主線的情形，與「結構異常接在最後」同一原則；V2 的循環起點需要額外裁定。

用戶裁決（2026-10-09）：V1。凡沿 branch_from 到不了主線的步驟（含指向懸空或循環步驟者，新增 (c) 依附異常）一律依檔內順序平鋪接在最後一欄之後，尾段不套巢狀；(b)、(c) 的 branch_from 邊照常畫。已寫入 SPEC-001 v1.43〈泳道布局規則〉。案例補強依 4a 規劃以小票承接。
### WRAP（快速+，e1，2026-10-09）：主線 next 的解析歸屬（兩位審查者皆提出）

事證：SPEC-007 FR-10「主線順序取清單順序，不沿主線 next 推導；主線 next 與清單一致性由上游 doc validate 檢查，Graph 不重複檢查」，且主線 next 不解析、不產生缺陷；SPEC-001〈泳道布局規則〉「邊的來源」要求主線與分支 next 各值畫一條邊。兩份實作都在 Layout 以 step id 自行解析主線 next，審查評為把 Graph 的工作搬進 Layout。先例：O1（domain × UC 關係由 Graph 判定，畫面只顯示）、R1（列序歸 Graph，Layout 向 Graph 取）——規則與解析一律放 Graph。
