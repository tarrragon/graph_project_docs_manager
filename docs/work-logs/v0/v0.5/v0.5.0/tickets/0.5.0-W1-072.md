# Execution Log

## Task Summary

W3-001 成對實驗兩份的首次全套 flutter test 皆掛住（CPU 0%，停在不同檔），單獨重跑皆綠；加 < /dev/null 後通過，但當時負載也較低，無法區分 stdin 與負載

---

## Problem Analysis
### 問題根因

stdin 未重導不是成因：Claude Code 的 Bash 工具在主線程與子代理人、前景與背景都已把 stdin 接到 `/dev/null`。10-06 的兩次掛住與高負載（15 分鐘平均 67）同時出現，負載是目前唯一的候選成因，但沒有經過對照實驗。

### 影響範圍

W1-063 之後，有 42 張 0.5.0 票的約束寫了「全套 flutter test 一律 `< /dev/null`」。這條約束沒有作用，但也無害。負載面的控管由 0.5.0-W1-231（名額閘門、執行前負載檢查）承接，已落地。

### 相關 Error Pattern

PC-168（少量綠燈不等於 always 綠燈）：10-06 之後加了 `< /dev/null` 的全套測試都沒有掛住，這種連續綠燈不能當作重導有效的證據。實際上兩種條件相同，綠燈期間負載也已受名額閘門控管。


## 重現實驗結果
### 實驗方法

不跑全套 flutter test（不佔 heavy 名額）。改為直接量測 Bash 工具 shell 的 stdin 指向：`lsof -a -p $$ -d 0` 與 `[ -t 0 ]`。若 stdin 本來就是 `/dev/null`，「有／無 `< /dev/null`」兩種條件就沒有差別，N>=5 的交替實驗也就失去鑑別對象。另查合併閘門歷史紀錄作為旁證。

### 實驗執行

2026-10-30，Claude Code 2.1.314：

| 執行環境 | stdin | tty |
|---------|-------|-----|
| 主線程前景 Bash | `/dev/null`（CHR 3,2） | 否 |
| 主線程背景 Bash（run_in_background） | `/dev/null` | 否 |
| 子代理人前景 Bash（唯讀探測代理人） | `/dev/null` | 否 |
| 子代理人背景 Bash | `/dev/null` | 否 |

旁證：
- 合併閘門經 `run-with-timeout.py` 以 `subprocess.Popen` 繼承 stdin 執行 flutter test，呼叫端沒有加 `stdin=DEVNULL`。`worktree-merge.log` 記錄 flutter 套件綠燈 170 次，僅見名額等待逾時，沒有掛住造成的逾時。最長 2849s，最後也正常結束。
- W1-063 記錄 10-06 兩次掛住時，15 分鐘平均負載曾到 67。

### 實驗發現

已驗證：四種 Bash 執行環境的 stdin 本來就是 `/dev/null`，`< /dev/null` 加了也沒差，stdin 假設不成立。未驗證：10-06 當時的 Claude Code 版本是否也如此（無法回溯）；掛住的實際成因（負載是唯一與掛住同時出現的條件，但沒有做對照實驗）。


## Solution
### 結論

stdin 假設不成立（四種 Bash 執行環境的 stdin 皆已是 `/dev/null`）。派發範本不需要加 stdin 重導約束，不建派發範本修正票。

### 兩條 AND 判準

1. 抽象可攜：「Bash 工具 stdin 已是 `/dev/null`」這項事實可攜，但它不是缺陷。
2. 根源在 `.claude/` 通用資產：不成立。沒有任何框架資產少了 stdin 重導。負載成因由 0.5.0-W1-231 的名額閘門承接，對應 tarrragon/claude#115 既有觀測。

判定：不是框架缺口，不 observe，也不 dedup 新主題。查重仍有跑：stdin、dev/null、掛住、flutter test、hang、卡住，沒有任何 issue 處理 stdin 成因；#115 與負載、殘留程序相關，屬引用關係。

### 候選方案

| 方案 | 利 | 弊 |
|------|----|----|
| A：不改，往後的派發約束自然不再寫 `< /dev/null` | 零成本；這條約束無害 | 過渡期仍有人照舊複製 |
| B：申請 heavy 時段，在高負載下做 N>=5 的對照實驗，確認負載是否為成因 | 可確定成因 | 佔用名額；名額閘門已控管負載，結論不改變現行做法 |

採 A。

### Spawn 落地確認

| 項目 | 落地 |
|------|------|
| 派發範本 stdin 修正票（原 strategy 的條件分支） | 無需建 ticket：成因不是 stdin |
| 負載成因對照實驗 | 無需建 ticket：負載控管已由 0.5.0-W1-231 落地，實驗結論不改變處置 |
| 42 張票的無效約束文字 | 無需建 ticket：無害，屬已結束票的歷史文字 |
