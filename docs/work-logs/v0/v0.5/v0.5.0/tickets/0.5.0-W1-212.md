### Context Bundle（L23，2026-10-30，HEAD 1c182c1b4）

**AC1 現況確認（PM 已查，代理人照錄至 Solution 並自行重驗 `ls docs/usecases/`）**：本專案 docs/usecases 下 6 個 UC 檔名全部帶描述字尾（例：`UC-02-assess-change-impact-by-domain.md`），**「docs/usecases/<UC id>.md」樣式對 6 個 UC 全不成立**——在本專案資料下，泳道未結構化態的「開啟原始檔」恆走 notFound 分支，向使用者報告「原始檔已消失」。

**現況程式**：`_SwimlaneBody._openSource`（`lib/screens/domain_view/domain_view_screen.dart`）以 `'docs/usecases/$ucId.md'` 呼叫 `resolveOpenPath`，並帶 `// i18n-exempt: fixture 路徑字面` 標註；其文件註解仍寫假資料時代的敘述。

**既有前例（照做，不另創機制）**
- UC Flow：`lib/screens/uc_flow/uc_flow_providers.dart` 投影 `UcFlowUcItem(filePath: node.path)`，`uc_flow_screen.dart` 的 `_openSource` 傳 `uc.filePath`。
- 節點詳情：`node_detail_providers.dart` 以 `node.filePath` 解析。
- 節點路徑欄位：`lib/graph/light_node.dart` 的 `path`。

**實作方向**：Domain 視圖由投影層（`domain_view_providers.dart`／`domain_view_projection.dart`）提供「UC id → 該 UC 節點的 path」，畫面不再自行組路徑；查無節點時沿用既有 notFound 分支。刪除寫死樣式與過期註解中關於 opened 不可達的敘述（只限 `_openSource` 本身；同檔其他過期註解屬 0.5.0-W1-211）。

**測試**：E1 對照——同一 fixture 下，UC 節點 path 為帶描述字尾的檔名（與 id 不等）時，開啟呼叫收到的路徑等於節點 path（以 fake `externalOpenerProvider` 記錄收到的路徑）；對照案例：舊樣式路徑不會被傳出。兩條斷言各自獨立案例。改碼前先實跑新測試取得紅燈。

**局部測試範圍**：test/unit/screens/domain_view_test.dart、test/unit/screens/domain_view/domain_view_state_driven_test.dart、test/unit/screens/external_opener_wiring_test.dart、test/unit/screens/domain_view/swimlane_parse_failure_test.dart、test/unit/schema；新增測試所在檔若不在此列，於回報說明。

**約束**：一律 fvm；SynchronousFuture 模擬已載入；需改的測試檔不在 where.files 時停手回報（PM 補 where）。
