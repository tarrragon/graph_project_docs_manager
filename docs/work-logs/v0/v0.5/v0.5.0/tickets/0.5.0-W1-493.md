### 候選方案（待用戶裁定）

前提：平台型別只能由互動式 `--plugin-dir` 啟動產生，閘門（無頭、worktree 快照）無法自行取得。

| 方案 | 做法 | 利 | 弊 |
|------|------|----|----|
| A 型別快照入庫 | 把平台型別（約 956K）複製進 `.claude/skills/line-board/` 下的入庫目錄並記來源 Claude Code 版號；tsconfig 改指向快照；merge-gate.yaml line-board 套件加 `tsc --noEmit` | 閘門可機械執行，漏寫 prompt 也擋得住 | 快照隨 sync 擴散到所有 consumer；平台升版後快照過期須人工更新（需另設版號比對提醒），過期時閘門檢查的是舊 API |
| B 維持手動，改由流程固化（建議） | 不入庫型別；在主 checkout 以互動式 `claude --plugin-dir .claude/skills/line-board` 啟動一次產生新位置 types；手動配方（臨時 tsconfig 指向主 checkout 新位置 types、include worktree hooks）寫進 worktree skill 合併前清單與 line-board SKILL.md，由 PM 合併前執行並讀 rc | 型別永遠與本機平台同版；不增加 sync 體量 | 仍靠人執行，只是從 prompt 提醒移到固定清單；主 checkout 須先有人互動式 --plugin-dir 啟動過 |
| C 閘門機會式檢查 | 閘門偵測主 checkout 有 types 才跑 tsc，沒有則印 WARNING 放行 | 有 types 時自動 | 沒 types 時退化成 B 且只是警告；「有時檢查」使綠燈語意不一 |

不論選哪個方案都要處理：
1. 新位置 `.claude/skills/line-board/.claude-plugin/types/` 補 gitignore（舊位置的 `.gitignore`（`*`）沒帶過來）
2. 孤兒 `tools/line-board/.claude-plugin/types/` 清除時點：在新位置 types 產生並跑過一次配方之後（B 現行配方仍依賴孤兒）；選 A 則於快照入庫後清除

B 的弱點是仍靠人執行。若選 B，這條規則應掛在 PM 合併收尾的固定清單上，不靠派發 prompt；這樣就不會重演 485.7.1「prompt 沒寫，就沒人檢查」的缺口。

### 用戶裁定（2026-10-28）：方案 B

落地拆兩張子票（--parent 493）：
- 493.1：新位置 `.claude-plugin/types/` 補 gitignore；手動型別檢查配方（臨時 tsconfig 指向主 checkout 新位置 types、include worktree hooks、`npx --no-install tsc -p` 讀 rc 與 `error TS` 計數）寫入 line-board SKILL.md，並在 worktree skill 合併前清單加一列「改到 line-board 時 PM 合併前執行並讀 rc」。改 worktree skill 前先回報主控
- 493.2：用戶在主 checkout 以互動式 `claude --plugin-dir .claude/skills/line-board` 啟動一次，產生新位置 types；以配方跑一次確認 rc=0 後，清除孤兒 `tools/line-board/`
### 三種情境的行為比較（AC1）

| 情境 | A 型別快照入庫 | B 手動配方（採用） | C 閘門機會式 |
|------|---------------|-------------------|-------------|
| types 缺席（主 checkout 未曾以互動式 `--plugin-dir` 啟動） | 不受影響，快照在庫內 | 配方 rc=2（TS5083 讀不到 tsconfig），依判準屬「未執行」，PM 須先互動啟動一次（493.1 實測） | 印 WARNING 後放行，綠燈不代表檢查過 |
| types 過期（平台升版，但本機型別仍是舊版產物） | 檢查的是快照的舊 API，須人工更新快照 | 以舊型別仍可能 rc=0：493.1 以過期的孤兒型別跑出 rc=0、errors=0，所以 API 漂移偵測不到。重新以互動式 `--plugin-dir` 啟動即更新 | 同 B，且只在有型別時才跑 |
| 新 consumer（sync 後首次使用） | 隨 sync 取得約 956K 快照，可立即檢查 | 沒有型別，先互動啟動一次 | 沒有型別，WARNING 放行 |

B 的弱點集中在「過期」：配方不比對型別的來源版本。目前沒有實例造成誤判，不另建票。若日後平台型別有破壞性變更，症狀會是 worktree 程式通過配方，在主 checkout 實際載入時才報錯。
