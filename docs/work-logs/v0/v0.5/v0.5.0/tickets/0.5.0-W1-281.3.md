## Problem Analysis
<!-- Schema[ANA/Problem Analysis]: 必填（.claude/pm-rules/ticket-body-schema.md） -->
問題根因：cli-error-feedback 的 docstring 寫明已合併 cli-failure-help-reminder，但上游合併時漏刪後者的註冊；189.1 把註冊搬進 hook-dispatch-registry.json 時兩支都照搬，造成兩支在 PostToolUse:Bash 共存，偵測條件與輸出訊息相同。

影響範圍：遮蔽的失敗命令若帶 stderr，同一次 PostToolUse 會輸出兩則相同提醒（IMP-020 所述的共存碰撞）。實際觸發次數兩支皆為 0。

調查方式：逐項比對兩支的觸發、排除條件與輸出；查兩支在本專案的引入提交；以各自的日誌字串計數觸發次數。結論與比對表見 Solution。

## Solution
<!-- Schema[ANA/Solution]: 必填（.claude/pm-rules/ticket-body-schema.md） -->
### 重疊比對

| 項目 | cli-failure-help-reminder（.claude/hooks/） | cli-error-feedback 的 check_general_cli_failure（.claude/skills/ticket/hooks/） |
|------|-------------------------------------------|---------------------------------------------------------------------------|
| 觸發條件 | PostToolUse 且 tool_response.stderr 非空 | 同左；另外在 PostToolUseFailure 改讀 error 欄位 |
| 排除條件 | is_handled_by_other_hooks、is_expected_stderr（含 GIT_INFO_STDERR_PATTERNS） | 同名函式，邏輯相同 |
| 輸出 | WorkflowMessages.CLI_FAILURE_HELP_REMINDER | 同一則訊息 |
| registry 群組 | PostToolUse:Bash | PostToolUse:Bash 與 PostToolUseFailure:Bash |

- cli-error-feedback 的 docstring 寫明「合併自 cli-failure-help-reminder-hook.py」，邏輯是完整的超集。
- 合併提交：兩支在本專案都是隨 cffdda1df（框架初次導入）一起進來，合併發生在上游 canonical 的歷史；canonical 的 settings.json 至今仍註冊 cli-failure-help-reminder，屬上游合併時漏刪的註冊。189.1（b7c7e0452）把註冊搬進 hook-dispatch-registry.json 時兩支都照搬。
- 實際觸發：兩支的日誌都寫到 DEBUG 等級，8 天內「偵測到 CLI 失敗」皆為 0 次。原因是未遮蔽的失敗命令只會到 PostToolUseFailure，那裡只註冊了 cli-error-feedback；PostToolUse 中的命令結束碼為 0，stderr 非空多半是資訊性輸出，已被排除條件濾掉。
- 風險：若命令被遮蔽且 stderr 帶失敗文字，兩支會在同一次 PostToolUse 各輸出一次相同提醒（IMP-020 描述的共存碰撞）。

### 選定：刪除 cli-failure-help-reminder

- 不改掛失敗事件：cli-error-feedback 已經註冊在 PostToolUseFailure，改掛等於讓重複發生在兩個群組。
- 不保留：保留只會留下重複輸出的風險，沒有任何它獨有的偵測條件。
- 落地：0.5.0-W1-281.3.1。
