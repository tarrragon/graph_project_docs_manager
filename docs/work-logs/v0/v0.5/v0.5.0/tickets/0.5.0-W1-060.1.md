## Solution
<!-- Schema[IMP/Solution]: 選填（.claude/pm-rules/ticket-body-schema.md） -->
新增 `_resolve_subtree_root_target`：根票目標撞號時，沿用單票路徑的 `_resolve_available_target_id` 取下一個可用序號，`_migrate_subtree` 以新根重算 mapping，並在根票寫入 `migrated_from`。dry-run 撞號時判 FAIL 並印出改號預覽，與單票路徑一致；改成 rc=0 預覽由 0.5.0-W1-060.2 處理。`--force-overwrite` 不改號。只有根票撞號會改號；成員撞號仍由 preflight 整體拒絕。目標正是子樹成員自己的 ID（根遷到自己的子位）時不算撞號。ticket skill 2.44.40，migrate-command.md 子樹「碰撞處理」列同步改寫。commit af324f251，合併 ec3171b95。

### 自檢結果

- RED：新增 5 案，修改前 3 failed（preflight「目標已存在」）、2 passed（兩個對照：不撞號的 E1、force-overwrite 不改號）。
- GREEN：migrate 兩個測試檔共 30 passed。E2 斷言 previous_ids、子票與孫票 parent_id、根票 children、外部票 blockedBy／relatedTo、migrated_from，以及被佔用的既有票未被觸碰。
- CLI 同步 grep：只有 migrate-command.md 子樹表的「碰撞處理」列與新行為不一致，已同 commit 更新。規則 8 grep 0 命中（測試裡的 0.0.0-W0-* 是合成 fixture）。
- 實地觸發：在 `git clone --no-hardlinks` 的 clone 裡，把有兩張子票的票遷移到一個已存在的目標 ID。dry-run rc=1 並印出改號預覽；正式執行 rc=0，改號到下一個可用序號（含子孫共 3 張）。新根帶 migrated_from 與 previous_ids，子票 parent_id 指向新根，兄弟票的 blockedBy 已改寫，被撞號的票未變。

### Phase 4 評估

- 重構需要：否。
- 技術債務：無新增。單票與子樹兩條路徑的 dry-run 回傳值統一，由 0.5.0-W1-060.2 承接。
- 程式碼品質：A。
- 結論：新函式重用單票路徑的既有改號函式，沒有另寫平行邏輯；巢狀一層，不需重構。
