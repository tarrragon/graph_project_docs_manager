- 原驗收第 1 條「兩個 hook 引用同一份清單定義」已不成立：0.5.0-W1-281.3.1 已移除 cli-failure-help-reminder-hook（含註冊、檔案與引用），目前只剩 cli-error-feedback-hook 的一份 HANDLED_BY_OTHER_HOOKS。該條已移除，where.files 也同步拿掉已刪除的 hook。

## Solution
<!-- Schema[IMP/Solution]: 選填（.claude/pm-rules/ticket-body-schema.md） -->
比對規則：is_handled_by_other_hooks 先用共用 lib.test_command_parse.find_test_invocations（涵蓋 flutter/dart test、pytest、uv run pytest、npm test，含 KEY=VAL、cd x &&、uv --directory x run 等前綴）；非測試項（dart analyze、go test、go vet、ticket、skill、uv run ticket）以 parse_command_statements 切敘述，經同模組的 _strip_launch_prefixes 剝前綴後比對開頭 token 序列。go test 不在共用判定範圍，故歸非測試項。全部項目皆無維持子字串比對者。
失敗語意：共用判定拋例外或命令無法解析時回 False（不抑制），例外寫 logger.error；以 patch 例外的測試鎖住。
舊碼紅燈（實跑）：5 failed／36 passed——pip install pytest、引號內 flutter test、引號內 dart analyze、判定例外、未閉合引號皆被誤抑制；真 pytest／flutter test／ticket 與前綴案例為綠（正向對照）。
Phase 4：重構需要否；技術債務：_strip_launch_prefixes 為 lib 私有函式被跨模組 import，建議日後 test_command_parse 公開；程式碼品質 A。
