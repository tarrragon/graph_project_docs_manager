### WRAP（快速+，e1，2026-10-10）：flowKeyOf 與上游 str() 在 bool／list／map 的差異

事證：Dart 字串插值與 Python str() 在字串與 int 上結果相同；bool（true／True）、list（[a]／['a']）、map 不同。差異只在「轉字串後恰好等於某個 step id 或 domain 名」時影響解析結果。step id 為 kebab-case、domain 名受 id_pattern 約束（小寫與連字號），`True`、`['a']`、`{...}` 都不可能是合法 id——兩種轉法對 bool／list／map 都必然解析不到，結果同為「未解析／未宣告」。兩份語料 0 筆。差異會影響的是缺陷負載中的 rawValue 文字呈現（原值保存，不受影響）與項目 id（表二以原始值為鑑別成分）。

| 候選 | 做法 | 代價 |
|---|---|---|
| K1 | 收窄宣稱：S1「與上游一致」限字串與 int；bool／list／map 依 id 格式必然解析不到，App 以 Dart 轉法，規格寫明此差異不影響解析結果 | 規格多一句例外說明 |
| K2 | 實作對齊 Python：bool 轉 True／False、list 與 map 模擬 Python repr | 為不可能命中的值維護一份 Python repr 模擬，易錯 |
| K3 | bool／list／map 不轉字串，直接判未解析（rawValue 記原值） | 與「轉字串比對」的 S1 字面略有出入，但結果相同 |
傾向 K1，信心中：解析結果在兩種轉法下必然相同，對齊 repr 沒有使用者可見收益。
