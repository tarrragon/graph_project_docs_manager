### WRAP 評估（2026-10-08）

對象：本票 NeedsContext 1～4。事證取兩份語料（本專案 6 UC／40 步、flutter_balance 1 UC／9 步）與 main 現行 lib/diagnostics、tracking_schema。未選定。

#### 1. 三種新缺陷的子類名、負載、報告分組

| 候選 | 作法 | 代價 |
|---|---|---|
| 1a | `graphDefect` 下新增三個子類（如 `flowRefUnresolved`、`flowStepDuplicateId`、`traversesUndeclared`），負載 {UC ID, step id, 欄位, 原始值}，報告在 graphDefect 下另立「flow」小組 | 新增 enum 值與 l10n；IT-2 凍結值不受影響（manifest 無 flow） |
| 1b | 沿用既有子類（danglingRef／duplicateId） | danglingRef 負載含邊型與宣告路徑，flow 參照不是邊，欄位語意對不上 |
| 1c | 新 GapCategory（如 `flowDefect`），與 graphDefect 平行 | 改 Diagnostics 類別列舉與報告分頁；Graph 回報管道須分流 |
| 1d | 規格不定義／Diagnostics 不回報 | 001.4／001.5 無法寫 E2 對照斷言；懸空步驟在泳道最後一欄但無處解釋 |

事證：`GraphDefectKind` 現為 4 值；既有 danglingRef 負載含邊型，flow 參照不建邊（FR-10）。兩語料三種缺陷皆 0 筆。傾向 1a。

#### 2. UC 內 step id 重複時子圖怎麼處理

| 候選 | 作法 | 代價 |
|---|---|---|
| 2a | 兩步皆保留，指向該 id 的參照標未解析 | 與主圖 D3（重複 ID 兩節點皆不建）不一致 |
| 2b | 兩步皆不進子圖（比照主圖 D3） | 違反 2026-10-08 裁決 3e「結構異常不消失」 |
| 2c | 保留第一個 | 依檔內順序隱性取捨，第二步靜默消失 |
| 2d | 規格不定義 | 實作自選 |

事證：兩語料 0 筆；3e 的精神是「看得到才會被修」。傾向 2a。

#### 3. flow yaml 區塊解析失敗

| 候選 | 作法 | 代價 |
|---|---|---|
| 3a | 照框架函式靜默略過（現行寫法） | 壞掉的 flow 與「沒有 flow」同形，泳道只顯示空子圖 |
| 3b | 該 UC 產生 `parseFailure`（新增原因碼「flow 區塊無法解析」） | App 須自行判別「含 flow 鍵的 yaml 區塊解析失敗」，不能只靠框架函式回傳 None |
| 3c | 上游 doc validate 回報 | 框架變更；未升級專案不受保護 |
| 3d | 規格不定義 | 同 3a |

事證：`uc_registry._extract_structured_flow_steps` 對解析失敗的區塊與無區塊都回 None；兩語料 0 筆。傾向 3b（3c 可另提）。

#### 4. `association` 鍵名例外的移除

查證：上游方向欄位已由 0.4.0-W1-072 落地（completed）；框架 JSON 與 App 內建副本皆帶 `direction`（17 處），只有 association 為 undirected。移除責任在 SPEC-007 FR-05／D6 與 W1-001 驗收第 3～5 項，但沒有子票承接，lib/schema 未讀 direction。前提已成立，屬落地缺口而非新裁決。

| 候選 | 作法 |
|---|---|
| 4a | 開 W1-001 子票（IMP）：改讀 direction、移除 D6 association 例外、S6-13 改斷言依欄位、EdgeTypeEntry 方向參數必填 |
| 4b | 移到 0.6.0 |
| 4c | 永久保留例外，刪除 W1-001 驗收 3～5 與 FR-05 移除句 |
| 4d | 規格不定義（維持現狀） |

傾向 4a：前提已滿足、範圍小，且可抵銷 W1-103 新增的例外。

盲點：未實測 doc validate 對 flow yaml 語法錯誤的行為；未查 l10n 對新子類的既有命名慣例。
可合併：1、2、3 都屬「flow 子圖結構缺陷」，可一次裁決。
