### 來自 0.5.0-W1-164.4 的需求與歸屬變更（PM 89，2026-10-13）

歸屬：本票由協調 session 轉入框架工具線，PM 89 接手；狀態仍為待處理。

0.5.0-W1-164.4 的結論中與本票相關者：

1. 共用模組、不共用判定語意。git-index-lock-cleanup-hook 與 bare-commit-guard 都使用 lib.git_command_parse，但需求不對稱：bare-commit-guard 須精確辨識 commit，且在合併進行中拒絕，解析盲區是安全缺口；鎖檔清理 hook 改為每次 Bash 呼叫都檢查 cwd，解析器只負責額外取得 -C 的目標路徑，盲區只會退回「只查 cwd」，不是安全缺口。
2. 第二個消費者。0.5.0-W1-164.4.1 落地後，會成為該模組「取得 -C 目標路徑」的第二個消費者。本票若調整解析結果的資料結構（各次 git 呼叫的子命令與 -C 路徑欄位），須保留這個用途，並在方案比較中把它列為既有呼叫端。
3. 盲區修復的歸屬。絕對路徑的 git、command 前綴、巢狀 shell、別名這幾種寫法取不到子命令或 -C 路徑，由本票在共用模組內統一處理；0.5.0-W1-164.4.1 不另開解析修復，直接繼承本票的結果，也不依賴本票完成才能落地。
4. 可沿用的實測。0.5.0-W1-164.4〈重現實驗結果〉已對 25 種命令字串逐一記錄現行子字串判定與解析器的輸出，本票可直接引用，不必重測同一批字串；接手者仍應自行核對數量與範圍。

排程：本票為分析票，0.5.0-W1-164.4.1 為實作票，兩者互不阻擋。
