### WRAP 評估（2026-10-08）

範圍：lavender 自行補定的兩項（SPEC-004 §4.0.6 1.69 domain 列首顯示名 key；SPEC-003 §3.5 新增理由句）。不選定，交用戶裁決。

#### 項目 1：domain 列首顯示名

錨點：App 觀測其他專案；10-08 裁決 1c 的理由正是「對他專案可用」。阻擋 2（10-07）原文：「App 精確比對，不一致交 Diagnostics；畫面顯示名另由 i18n 取。」——只說顯示名走 i18n，未說 key 如何對應任意 domain。

R 事證：
- 8 份 domain-map frontmatter 只有 `id`／`domain`，標題為「# Domain Map — <Name>」（TicketDetail 有大小寫）；flutter_balance 為 `domain: "balance-sheet"`，標題「# Domain Map — Flutter Balance」（標題與 domain 不同源）。
- 上游 DomainBundle 必填僅 `{id, domain}`；模板無 title／display 欄位；App 的 `RawNode` 不帶本文（W1-001 實驗），讀標題須新增本文解析。
- Flutter ARB 產生的是靜態 getter，執行期字串 → key 需寫死 switch；未知 domain 沒有 key 可取。
- 現行 App：4.37／4.38 列首取 `DomainViewFixtures.domainNames`（fixture，4 個英文名，標 i18n-exempt），尚未接真資料。
- `presentation` 不同：它是本專案 SPEC 定義的保留字（App 自有詞彙），不是被觀測專案的資料。

| 候選 | 作法 | 未知 domain 的行為 | 主要代價 |
|------|------|------|------|
| K1 lavender 版 | 8＋1 個固定 key，執行期 switch | 未定義（無 key；實作會各自補退路） | 只對本專案名稱有效，與 1c 理由相反；他專案同名 domain（如 `graph`）會被套上本專案譯名 |
| K2 原值 | 列首直接顯示 `domain` 字面 | 與已知相同，一律原值 | 中文介面出現 `ticketdetail` 等識別字；無翻譯 |
| K3 取 domain-map 標題 | 解析「# Domain Map — X」 | 有標題即可；無則退原值 | 依賴散文格式；需本文解析；flutter_balance 會顯示「Flutter Balance」（專案名而非 domain） |
| K4 混合 | 已知 8 名走 i18n，其餘原值 | 原值 | 同 K1 的他專案同名誤譯；顯示風格在已知與未知間不一致 |
| K5 上游選填 `display_name` 欄位 | DomainBundle frontmatter 選填，缺則原值 | 原值 | 框架變更（83 協調、推送授權）；單一語言，失去 zh／en 切換 |
| K6（反向框架）資料原值＋App 詞彙 i18n | domain 列一律原值（K2）；只有 `presentation`（App 自有保留字）走 i18n key | 原值 | 同 K2 的識別字外觀；需把阻擋 2「顯示名另由 i18n 取」讀為「App 自有詞彙由 i18n 取」 |

反向框架：顯示名是否必要？domain 名是被觀測專案的識別字（同 traverses 精確比對的對象），使用者是開發者，原值與其文件、程式碼一致反而利於對照；需要翻譯的只有 App 自己定義的詞（`presentation`／「畫面」）。K1／K4 的翻譯對象其實是本專案的資料。

次要：文案本身——「圖」單字與「圖片」歧義、「語料」對多數讀者陌生、「型別表」可接受；若保留 K1／K4 宜改。

P（失敗預想）：K1——接真資料時第一個他專案即出現無 key 的列，早期警訊：fixture 以外的語料列首為空或拋例外。K4——他專案 `graph` 被譯為「圖」而語意不同，警訊：無（靜默）。K2／K6——使用者覺得列首不友善，警訊：用戶回饋。K5——上游不接受新欄位，回退成本低（缺欄位即原值）。

傾向：K6（K2 加上 presentation 走 i18n），若要友善名再疊 K5。盲點：不確定用戶 10-07「畫面顯示名另由 i18n 取」原意是否就是 K1；未量測中文介面混英文識別字的觀感。

#### 項目 2：SPEC-003 §3.5 理由句

tech-decisions 2026-10-08 補記 Why 原文：「畫面消費 domain 事件是正常的，畫面發出 domain 事件代表事件起點放錯層，應被檢查抓出。」SPEC-003 句子與之同義（「應」→「須」），屬忠實轉述，非擴張。檢查承擔者：§3.5 既有 event-declaration-mismatch（Diagnostics `gapCategoryEventDeclarationMismatch`）——producers 只接受已宣告 domain 名，`presentation` 出現在 producers 即為不符；不新增檢查類別，也不需新票。盲點：未核對該比對在 lib 的實作是否已接上 producers 收窄後的規則（屬 W1-095.1／.3 後續實作範圍）。
修訂輪（K6）：AC6 SPEC-004 1.71：§4.0.6 1.69 表刪 8 個 domainDisplayName<Domain> key，presentation key 改名 swimlaneScreenLaneName，引言改為 domain 列首不經 i18n；4.37 rows、4.38 lanes 列首改為 DomainBundle.domain 原值（未知亦原值），僅畫面列經 i18n。AC7 system-layer §6 句改寫。grep 命中另處理：SPEC-001 1.30 §1 列鍵比對列與間接依賴路徑 domain 顯示名改原值。保留：SPEC-003 §3.2 本 UC 外 presentation i18n、§3.5 理由句、各變更歷史舊列。layout domain-map 無命中。
