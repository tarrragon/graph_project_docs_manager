### 問題根因

非回歸，無引入 commit。測試 helper `TestPerSuiteReuse._suite_of`（test_merge_gate.py）以 `" ".join(argv)` 是否含 `.claude/hooks` 判定為 hooks 套件；但 `merge_gate.wrapped_argv` 的 argv[0] 為 `sys.executable`。以 `uv --directory .claude/hooks run pytest ...` 執行時 `sys.executable` = `.claude/hooks/.venv/bin/python3`，使 scripts 套件（`uv --directory .claude/scripts ...`）被誤判為 `hooks`，`ran[3:]` 得 `['hooks']`。閘門的 skill:worktree 套件因 skill 有 pyproject.toml，以 `uv --directory .claude/skills/worktree run pytest` 執行（直譯器為 skill 自身 venv），不含 `.claude/hooks`，故綠燈（410.3.1 時的 526 passed 即此路徑）。

重現（輸出逐字）：
- hooks venv：`uv --directory .claude/hooks run pytest ../skills/worktree/tests/test_merge_gate.py -q -k test_suite_outside_first_set_is_added` → `AssertionError: assert ['hooks'] == ['other']`，1 failed
- 同命令於 5b697901c 的暫時 detached worktree → 同樣 1 failed（排除區間內 commit）
- skill venv：`uv --directory .claude/skills/worktree run pytest -q tests/test_merge_gate.py -k test_suite_outside_first_set_is_added` → 1 passed
- 捕獲 stdout 顯示實際跑的是「套件 scripts」，判讀錯誤只在測試 helper

### 影響範圍

僅測試 helper；merge_gate.py 實作正確。merge-gate.yaml（410.4）與本紅燈無關（captured stdout 顯示未讀到宣告）。434 若以閘門執行 skill:worktree 套件應為綠，需 PM 確認 434 代理人當時的執行方式（推定為 hooks venv 手動執行）。
