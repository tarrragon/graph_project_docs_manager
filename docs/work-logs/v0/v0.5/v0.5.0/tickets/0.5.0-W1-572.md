### 派發 context（L38，2026-10-31）

**現象**（465.2 實測）：實機字型下 Ticket 清單 960x640 的 `FilterDropdown` 內容 Row 實得高度 12.4、固有高度 15.0；1280x800 不裁切；測試字型下不顯現。

**規格約束（預期值出處，TEST-GPD-1006）**：
| 項目 | 出處 | 值 |
|------|------|----|
| 觸發器高 | SPEC-004 §4.13〈尺寸契約〉最小與最大尺寸列 | 高 = `LayoutSize.hitTargetMin`（固定，不隨內容變） |
| 最小命中區 | SPEC-004 §4.13 | `LayoutSize.hitTargetMin` |
| 不溢位 | SPEC-004 §4.13 測試點「兩種視窗尺寸下不溢位；高等於 `LayoutSize.hitTargetMin`」 | — |
| 字級 | `AppText.singleLine` 預設 body（`AppFontSize.body`） | — |

**要求**：
1. 先查根因再修：為何 960x640 時內容 Row 只得 12.4（觸發器 `Container(height: hitTargetMin, padding: Space.sm/Space.xs)` 加邊框，以及祖先 `Toolbar` 與 ScreenUtil 縮放的影響），根因寫入 Solution。
2. 修法須維持「高 = `hitTargetMin`」契約，不得只把數字調到剛好通過；若在契約內無解（例如需要改變觸發器高或字級 token），停手寫 NeedsContext，由 PM 轉用戶裁決規格。
3. 移除 `integration_test/real_font_layout_test.dart` 內 FilterDropdown@min 的已知缺陷釘住，改回直接 `expectNoVerticalClip`（本票 acceptance）。
4. 測試字型下的 widget test 不得跟著改：`test/unit/components/filter_dropdown_test.dart`、`toolbar_test.dart` 與 Ticket 清單畫面相關測試維持原斷言全綠；若必須改，逐項寫出改動與規格依據。
5. 測試執行一律經 `python3 .claude/scripts/run-with-timeout.py 600 -- <命令>`：integration 檔 N>=5 記 load；widget test 指定檔案執行。commit 前 `fvm dart format --output=none --set-exit-if-changed` 改動檔。

## Solution
<!-- Schema[IMP/Solution]: 選填（.claude/pm-rules/ticket-body-schema.md） -->
根因：Toolbar 以 (hitTargetMin + 2*Space.xs).h 與 Space.xs.h 設高與垂直內距，ScreenUtil 在 960x640 縮放 0.8，子件可用高 = 28.8 - 6.4 = 22.4，FilterDropdown 的 Container(height: hitTargetMin) 被 enforce 成 22.4，扣內距 8 與邊框 2 後內容 Row 得 12.4 < 固有 15.0。1280x800 縮放 1.0 故不顯現；SearchField 內容 Row 無內距故未受害。
修法：lib/components/toolbar.dart 高度與垂直內距改為不縮放的 hitTargetMin + 2*Space.xs 與 Space.xs。依據 SPEC-004 §4.32 尺寸契約「高固定 hitTargetMin + 2 x Space.xs」及 §4.13「高 = hitTargetMin」；FilterDropdown 未改，契約高不變。移除 integration_test/real_font_layout_test.dart 的 FilterDropdown@min 釘住，改直接 expectNoVerticalClip。
Widget test：無改動，原斷言全綠。
Phase 4：無需重構；技術債務無；品質 A。
