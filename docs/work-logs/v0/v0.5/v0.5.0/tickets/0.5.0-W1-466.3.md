## Problem Analysis
<!-- Schema[ANA/Problem Analysis]: 必填（.claude/pm-rules/ticket-body-schema.md） -->

### 問題根因

本票是 0.5.0-W1-466 的正式階段，**只有 466 的試水溫判定通過時才執行**。若試水溫判定不通過，本票以 requirement_vanished 關閉。

完整脈絡在 466 票面的三節，依序讀：〈用戶補充裁示：Haiku 是反指標〉、〈WRAP 完整模式評估〉、〈並行評估結果與修訂〉。三節發生衝突時，以〈並行評估結果與修訂〉為準。

本票承接試水溫刻意省略的三類工作：

| 類別 | 為何移到這裡 | 來源視角 |
|---|---|---|
| 替代原因對照（尺寸、語系、標記、無圖先驗） | 試水溫只做成對差分，這些因素在原版與壞版之間相同，差分會抵銷；正式階段再一次只改一個因子量測 | linux、Scope |
| 無害變體、強度梯度 | 用來量誤報，並確認失敗率是否隨破壞強度上升，避免單點比較出現 100% 對 0% 的結果 | Alternatives |
| 非設計者校準 | 用戶是設計者，判定會偏向「容易」（知識詛咒）；而試水溫以構造為正解，有循環論證風險。兩者都需要由非設計者校準 | WRAP R 階段、Alternatives |

### 影響範圍

- **判定規則**：見 466〈並行評估結果與修訂〉「正式階段判定規則」，共五條，必須全部成立。
- **截圖與變體**：沿用 0.5.0-W1-466.2 的產生器，以及 466 已凍結的變體目錄。新增的變體（無害變體、強度梯度）同樣要先寫入本票並提交凍結，才能開始取樣。
- **與 465 的仲裁**：只使用沒有渲染缺陷的截圖。
- **要比較的既有方案**：
  - `.claude/skills/ux-design-evaluation`
  - 由 widget 樹算出的主操作顯著度排名
  - 本地顯著度模型，或 OCR 降質
- **人工校準的成本**：需要 3 到 5 位非設計者做非同步的第一次點擊測試或 5 秒測試，人選要由用戶提供。
