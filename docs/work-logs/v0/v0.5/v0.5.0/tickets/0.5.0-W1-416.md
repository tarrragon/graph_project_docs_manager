## Solution
### 實作摘要

- `renderSessions`、`renderMergeLog` 簽章改為 `(elements: Elements, board: ReadyBoard)`，與 lanesView 的 `renderLaneGroups(elements, board, ...)` 及 dispatchView 的 board 參數一致；`readAtMs`、`sessions`、`mergeLog` 改由函式內自 board 取出。內部私有的 `renderSession`、`renderMergeGateEntry` 維持收 `Text`（非匯出、只在檔內呼叫）。
- 新建 `tools/line-board/hooks/readers.ts`，承接 PM set-where 所列八個函式：`findCheckouts`、`readSessions`、`readSessionFile`、`isSessionAlive`、`readLanes`、`readTicketStatus`、`readDispatches`、`readMergeLog`；連同只供讀取使用的 `PS_ENV`、`MERGE_LOG_LINES`。`readSessionFile`、`isSessionAlive`、`PS_ENV` 只在 readers.ts 內使用，不匯出。
- `messageOf` 移到 readers.ts 並匯出：readers.ts 各讀取函式與 register.tsx 的 toggle 失敗日誌、refresh 失敗日誌都用它，放在 readers.ts 避免 register.tsx 與 readers.ts 反向依賴。
- `refresh` 與 `formatTime` 留在 register.tsx：`refresh` 持有 `snapshot` atom 與 `isRefreshing` 旗標，屬刷新的協調；`formatTime` 只被 refresh 用來產生 snapshot 的 `updatedAt`，與讀取無關。
- README〈結構〉表新增 readers.ts 列，register.tsx 列改述為刷新協調；`*View.tsx` 共通列補「繪製函式以元素與 snapshot 為參數」；parse.ts 列的取用者補 readers.ts。
