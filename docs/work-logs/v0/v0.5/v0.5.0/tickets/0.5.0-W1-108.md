## Solution
<!-- Schema[IMP/Solution]: 選填（.claude/pm-rules/ticket-body-schema.md） -->
### 結論

`doc validate` 對非 data-contract 文件通過時，不再只印 /spec 路由，改為依文件型別列出實際執行並通過的檢查；前提不成立而沒有檢查的項目列為「略過」並附原因，最後列出不適用項。只有 SPEC 保留 /spec validate 提示，UC 與 PROP 等其他型別都不印。檢查邏輯與 exit code 都未改動，tracking_schema 匯出也未改動。doc skill 升為 1.24.9。合併 commit 775182ce4（branch commits b1b480dcb、00d858b41）。

| 型別 | 新輸出 |
|------|--------|
| UC | 已執行的檢查：domain 引用宣告（traverses）、branch_from 結構、主線 next 順序；語料沒有 DomainBundle 或 UC 沒有 flow 區塊時，對應項列為略過 |
| SPEC | 已執行的檢查：domain 引用宣告（depends_on_domains），同樣有略過條件；並附 /spec validate 提示 |
| 其他（PROP 等） | 一行「沒有適用的檢查」 |

實作方面，抽出 `_declared_domains` 與 `_read_flow_steps`，由檢查函式與報告函式共用，判斷「是否實際檢查」不另寫第二份邏輯。

### 自檢結果

- PM 審查退回一輪：第一輪的「通過」清單是寫死的，語料沒有 DomainBundle 時（`_find_undeclared_domain_references` 直接回傳空清單），沒做的檢查仍列為通過；UC 沒有 flow 區塊時屬空集合通過；PROP 也被導向 /spec。這與本票要修的「輸出與實況不符」是同一類問題。退回後補上 E2 測試，在修正前 4 紅
- PM 實地觸發：以合併前快照（git archive 775182ce4^1）與合併後的 main，對真語料執行 UC-02、SPEC-001、PROP-001。三者舊版皆為「非 data-contract 文件，請用 /spec validate（subdomain=None）」；新版依型別分別輸出，如上表。rc 新舊皆為 0
- 失敗路徑：E2「flow 順序錯誤的 UC 仍 exit 1」改前改後皆綠，這是設計使然，守的是新輸出不會吞掉失敗
- skill-cli-sync：SKILL.md 的 validate 列已更新；pm-rules 與 doc references 都沒有描述舊訊息的文字
- canonical dedup：已記錄於 how.strategy，與 #98 為引用關係，不另開 issue

### Phase 4 評估

- 技術債務：無新增。順帶消除一處重複：原本兩個 flow 檢查各自重讀並解析 flow 區塊，現已收斂為 `_read_flow_steps`
- 程式碼品質：A
