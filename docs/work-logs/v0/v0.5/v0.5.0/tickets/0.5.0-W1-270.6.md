## Problem Analysis
<!-- Schema[IMP/Problem Analysis]: 選填（小型 IMP 可留 placeholder；大型 IMP 建議填寫）（.claude/pm-rules/ticket-body-schema.md） -->
兩支 hook 皆 PostToolUse(matcher Bash)，非阻擋（exit 0）。
- post-ticket-lifecycle-hook：完成命令且 stdout 含「已完成」後，遞增 session 完成計數器（/tmp 檔，ppid）並輸出 checkpoint 提醒 additionalContext。辨識原為子字串清單（complete／batch-complete／ticket complete），finish 不命中。
- handoff-cleanup-hook：完成命令成功（exit 0 或 75 且 stdout 有成功標記）後，刪除 .claude/handoff/pending|archive/{id}.json。辨識原為字面 "ticket track complete" in command，finish 與 batch-complete 皆不命中。
只改辨識，處理行為不動。

## Solution
<!-- Schema[IMP/Solution]: 選填（.claude/pm-rules/ticket-body-schema.md） -->
兩支 hook 改用 lib.ticket_command_parse.has_complete_command；失敗語意：回傳 None（未閉合引號）視為非完成命令，不處理、exit 0（與 session-context-guard-hook 接法一致）。
- lifecycle：移除 COMPLETE_COMMAND_PATTERNS，is_ticket_complete_command 改走共用解析。行為差異：原清單的 "ticket complete"（無 track）不再命中，該形式非現行 CLI 語法，共用判定與 acceptance-gate 同一規則。
- handoff-cleanup：字面比對改為 has_complete_command(command) is not True。
測試：.claude/skills/ticket/tests/test_completion_post_hooks_finish_alias.py。
