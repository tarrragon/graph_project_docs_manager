## Solution
<!-- Schema[IMP/Solution]: 選填（.claude/pm-rules/ticket-body-schema.md） -->
### 實作（commit ad6cf8f7e，分支 worktree-agent-a81e7b539d800dbda）

- 新增 `.claude/lib/hook_registry.py`（僅依賴標準庫）：`load_registry_groups`、`load_group`、`registry_commands`、`merge_dispatch_registry`。併入時 registry 的 group 鍵 `PreToolUse:Bash` 拆成真實事件與 matcher，command 與原註冊等價（`uv run --quiet $CLAUDE_PROJECT_DIR/<path>`），timeout 沿用。
- 消費端：hook-registration-coverage-check、hook-health-monitor（`_load_settings`，供 lib/hook_health 的分類使用）、hook-dependency-isolation-check-hook（路徑與呼叫前綴兩個抽取函式）、hook-liveness-summary-hook（刪除 189.1 內的私有 `_merge_dispatch_registry`，改呼叫共用 helper）。lib/hook_health.py 本身只吃 settings dict，不需改動。
- hook-dispatcher 的 `load_group` 也改以檔案路徑載入同一模組，repo 內只剩 hook_registry.py 解析 registry 檔（有不變量測試 test_only_hook_registry_module_parses_registry_file）。該 commit 在 189.1 範圍內（90aebafb0）。

### 實地確認（dogfooding）
對本 worktree 執行 hook-registration-coverage-check：改動前誤報 27 個 hook 與 10 個 skill hook 未出現在 settings.json；改動後 0 個、skill hook 36 個全數出現。

### Phase 4 自評
重構需要：否。技術債務：無新增（四個消費端各一行呼叫共用 helper）。程式碼品質：A。結論：helper 單一職責、僅標準庫依賴；hook_base.py 未動。

### 自檢結果
- 驗證：新測試 test_hook_registry.py 含 E1 對照（同一支 hook 有無 registry 時涵蓋率檢查結果不同）與正向對照（兩處皆無的 hook 仍判未註冊），另覆蓋依賴隔離與健康監控兩個消費端、讀取失敗的可見性（logger 記錄）。
- 未驗證：hook_health.classify_hook 對併入的 Bash hook 的分類結果只透過 `_load_settings` 的併入間接涵蓋，沒有逐一核對各 hook 的分類字串；SessionStart 真實觸發留給 PM。
- 收尾依用戶裁決只到 commit，不執行 complete／finish。
