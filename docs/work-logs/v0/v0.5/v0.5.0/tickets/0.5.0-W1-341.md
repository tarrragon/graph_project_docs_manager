### 修正
- lib/git_operation_state.py 新增 _resolve_detect_dirs_multi、_override_dirs、_git_dir_overrides、_pending_operation_in_git_dir；_pending_operation_in_dirs 對每個目錄同時以 rev-parse 與 git-dir 檔案檢查判別。hook main 改用 _resolve_detect_dirs_multi(invocations)。dispatch_scope 未改（並行期過濾已保守計入，不需動）。
- 測試修正：test_git_dir_resolution_convergence 的變異測試 patch 目標由 _resolve_detect_dirs 改 _resolve_detect_dirs_multi（hook 流程呼叫點改名所致）。

### 修正前紅、修正後綠（真實倉庫，不 mock 偵測）
- 修正前（hook 未改）：TestPendingOperationAllTargets 4 個應擋案例失敗（串接第二筆 -C、GIT_DIR 前綴、--git-dir=、--git-dir 分離 token，回 0 放行並走 WARN）；3 個放行對照通過。
- 修正後：同 3+4 全綠；範圍測試 230 passed（test_bare_commit_guard_hook、test_git_dir_resolution_convergence、test_git_operation_state、test_dispatch_scope、test_hook_dispatcher）。

### 失敗語意
- 覆寫值含變數或 ~：退回 payload cwd 與 project root 兩處（不猜）。覆寫路徑不存在：rev-parse 失敗走既有 fail-open 並雙通道回報。只帶 GIT_WORK_TREE 不帶 GIT_DIR：work tree 一併列入偵測。偵測失敗仍 fail-open。
- 已知殘餘：git dir 為 gitlink 檔（worktree 的 .git 檔案）時 --git-dir 指向檔案，檔案檢查不適用，僅靠 rev-parse 路徑；--amend 豁免仍只看 invocations[0]（沿用）。
