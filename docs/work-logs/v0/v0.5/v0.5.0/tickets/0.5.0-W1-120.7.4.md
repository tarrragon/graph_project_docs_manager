### PM 派發前更新（2026-10-14）

0.5.0-W1-120.7.9 改採丙案後，殘留清單改依新模型撰寫，原本的「三類」不再適用。

- 阻擋型守衛已改用 scan：0.5.0-W1-120.7.9.2 涵蓋分級守衛四支，0.5.0-W1-120.7.9.3 涵蓋狀態型守衛五支。「白名單未收錄的前綴命令」這個開放類別，對阻擋型守衛已不存在。
- scan 仍會漏判的封閉類別（取自 0.5.0-W1-120.7.9 與 120.7.9.1 Solution）：
  1. shell 別名與函式。命令文字中看不到它們的展開內容。
  2. 變數或命令替換組出的命令。這類命令無法靜態判定。
  3. 字串形式的腳本載體：su -c、script -c、sg -c。
  4. echo 引號內的命令替換。
  5. 遠端或容器內執行：ssh、docker exec、kubectl exec。這類 scan 會命中，但實際作用在另一個 repo，屬判定目標不一致。
- scan 的誤判情境需另立一節：git 作為其他命令的參數（grep、man、ssh、bash script.sh git … 等）。阻擋型守衛在並行期會擋下這類命令，解法是把 git 字樣加上引號，或把 git 放在命令位置。
- 提示型 hook 仍用位置判定，白名單未收錄的前綴命令對它們依舊會漏判，但後果只是少一則提醒。
- 依 reference-stability 規則 8，框架檔中不引用本專案票號。

## Solution
<!-- Schema[DOC/Solution]: 免填（DOC 類型以變更摘要取代）（.claude/pm-rules/ticket-body-schema.md） -->
變更範圍：`.claude/hooks/bare-commit-guard-hook.py` 只改模組 docstring（新增「辨識範疇」路由段，無程式碼變更）；`.claude/references/bash-tool-usage-details.md` 在規則七詳細下新增〈守衛如何辨識 commit：位置判定、任意位置掃描與殘留範圍〉，版本升 1.19.0，既有條文未動。

新增小節三部分：兩種辨識模型與 via_scan 處置；scan 仍漏判的封閉類別（五類，不寫死數字）及各自承擔者或不承擔理由；誤判情境（git 作為其他命令的參數）與改寫方式（加引號、置於命令位置）。docstring 以小節名稱路由到 details，不重複全文。引用規則：無票號、無行號、無寫死類別數。

實地觸發與 liveness：以 settings 註冊的啟動方式（hook-dispatcher.py --group PreToolUse:Bash）餵 payload，暫存 repo 內兩筆活躍派發、staged 跨兩者範圍的 `git commit -m x`，hook 載入並照常判定，輸出並行期裸 commit 阻擋訊息，rc=2。失敗語意不變，沿用現行（本票僅改 docstring，不動任何判定與 fail-open／fail-closed 路徑）。
