### 候選訊號對照表（PM 89，2026-10-13，供規格與測試設計組裁決）

**現況實測**（主 checkout，check_domain_coverage.py 逐份執行，七份皆 rc=0）

| SPEC | 所在目錄 | domain 欄 | 同目錄 domain-map | 現行路徑 |
|------|---------|-----------|------------------|---------|
| SPEC-001、SPEC-002、SPEC-003 | ui | ui | 無 | 定位鏈為空且 domain 欄不在已宣告集合，判為層級 SPEC，以系統層判定，通過 |
| SPEC-004 | ui | ui | 無 | 宣告無 FR，提前結束，不進層級判定 |
| SPEC-005 | workspace | workspace | 有 | 宣告無 FR，提前結束 |
| SPEC-006 | corpus | corpus | 有 | 同目錄 map 與列名的 map 聯集，通過 |
| SPEC-007 | graph | graph | 有 | 同上，通過 |

已宣告 domain 集合為八個（各 domain-map 的 domain 欄，皆與目錄名相同）；docs/spec 下唯一沒有 domain-map 的目錄是 ui。系統層的 FR 覆蓋對照節下，SPEC-001、SPEC-002、SPEC-003 各有一個小節，另有一個「SPEC-006 與 SPEC-007」合併小節。

**關鍵事實**：本專案真正的層級 SPEC（ui 下三份）本身即「目錄名等於 domain 欄、同目錄無 domain-map、domain 欄不在已宣告集合」，與本票所述「新 domain 尚未建 map」在這三項上完全同形。任何只看這三項的訊號都無法區分兩者。

**候選對照**（SPEC-004 至 SPEC-007 在各候選下皆不受影響：前兩份提前結束，後兩份定位鏈非空，層級判定不啟動。下表只列會變動的對象。「新 domain」＝SPEC 位於 docs/spec/a/、domain 欄 a、a 無 domain-map；「新層級 SPEC」＝新增一份層級 SPEC、系統層尚未為它建小節。現行列的前一格為實測，其餘格由現行程式邏輯推得，未實跑。）

| 候選 | 判定依據 | SPEC-001／002／003 | 新 domain | 新層級 SPEC | 是否改變規則語意 |
|------|---------|-------------------|-----------|-------------|-----------------|
| 現行 | domain 欄不在已宣告集合即層級 | 層級，通過（實測） | 判為層級，訊息請使用者到系統層補列（指引方向錯） | 層級，訊息指向系統層（正確） | — |
| 甲 | 目錄名等於 domain 欄者判為尚未建 map | 三份由通過轉為失敗，被要求建 ui 的 domain-map（假紅） | 正確 | 若放在同名目錄，被要求建 domain-map（錯） | 是 |
| 乙 | 層級名稱的明示清單，列名者才是層級 | 清單含 ui 時通過 | 正確 | 清單未更新前被要求建 domain-map；更新清單後正確 | 是（由排除法改為列名法） |
| 丙 | 系統層的 FR 覆蓋對照節已有該 SPEC 小節者為層級 | 通過（三份皆有小節） | 正確 | 尚無小節，被要求建 domain-map（錯，與現行缺陷方向相反的同型錯誤） | 是 |
| 丁 | SPEC frontmatter 由作者明示宣告為層級 | 三份須各補一欄才維持通過 | 正確 | 作者宣告即正確 | 是 |
| 戊 | 判定不變，只改訊息：走系統層而失敗時並列兩種處置 | 不變 | 仍走系統層，訊息同時說明「若為 domain 請建 domain-map」 | 不變 | 否 |

**各候選的成本與殘留**

- 甲：對現有三份層級 SPEC 產生假紅，且對新層級 SPEC 也判錯。無鑑別力，建議排除。
- 乙：需要為清單指定唯一權威住址；清單的維護點即判定點，新增層級時須先改清單。錯字的層級名稱會落到「請建 domain-map」。
- 丙：判定依賴系統層的小節標題格式（現有「SPEC-006 與 SPEC-007」合併標題形態，格式非單一）；新層級 SPEC 的第一次檢核必然收到錯誤指引，除非先寫系統層再跑檢核。
- 丁：需回填三份 SPEC。欄位是否進型別表須一併裁決（進型別表會觸發 schema 匯出的合併閘門；has_functional_requirements 的先例是不進）。未宣告的預設方向也須定：預設非層級時，新 domain 得到正確指引，忘記宣告的層級 SPEC 得到「請建 domain-map」。
- 戊：不解決判定，只修正指引方向錯誤這一項後果；可與乙、丙、丁任一併用，也可單獨先行。

**工具組的看法（非裁決）**：乙與丁是僅有的兩個對三類對象都能判對的候選，差別在宣告放在集中清單還是放在各 SPEC。戊不改語意，可獨立先做以止住錯誤指引。甲、丙各有一類對象必然判錯。

**待規格與測試設計組裁決**：(1) 採哪一個候選或組合；(2) 採乙時清單的住址，採丁時欄位名稱、預設方向、是否進型別表；(3) 乙、丙、丁皆改變「層級 SPEC 依 domain 欄判定」的原裁決，依本票 acceptance 須有用戶裁決記錄。
