## 重現實驗結果
### 實驗方法

- 守衛原始日誌：主 checkout 的 `.claude/hook-logs/bash-write-boundary-guard/` 在 2026-10-29 只有 source=main 紀錄（712 筆），沒有 source=agent 紀錄；第二例的代理人在 worktree 內執行，當時的判定紀錄已無法取回。
- 改用合成輸入重現：以 jq 組出 PreToolUse payload（tool_name=Bash、帶 agent_id 模擬代理人、cwd=主 checkout），直接把 payload 餵給 `.claude/hooks/bash-write-boundary-guard-hook.py`，讀 exit code（2=deny，0=allow）。守衛只做判定，不執行命令，實驗不寫任何檔案。

### 實驗發現

- 已驗證：守衛第一層（主線程與代理人皆適用）對 lib/ 與 test/ 的處理一致。字面路徑兩者都擋；路徑以拼接、迴圈或 argv 組出時都放行（判為無目標，fail-open）。票面原記「寫 test/ 被攔、寫 lib/ 未攔＝攔截範圍不一致」不成立，比較符合的解釋是兩次呼叫的路徑寫法不同。
- 已驗證：docs/ 不在第一層範圍（範圍為 lib/、test/、integration_test/、.claude/**），代理人以 Bash 寫 docs/ 不經任何寫入守衛。第一例（saffron 以 python 改 SPEC-003）走的正是這條路徑。
- 未驗證：第二例當時的實際命令文字（日誌已不可得；#103 的 2026-10-30 觀測指出 fail-open 筆不記命令，屬同一缺口）。
