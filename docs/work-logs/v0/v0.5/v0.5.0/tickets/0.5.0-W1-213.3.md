### 派發前盤點（PM，2026-10-30，213.2 合併後）

**現行違規（4 條）**
- `components/app_shell.dart`：
  - import `../app/degraded_schema.dart`
  - import `../app/router.dart`（使用 `AppDestination`、`selectedDestinationProvider`、`returnToProvider`）
  - import `../screens/domain_view/gate_detection_notifier.dart` show `inferredVersionProvider`
- `components/app_snack_bar.dart`：import `../app/attention_level.dart`

**AttentionLevel 的歸屬（PM 建議，代理人可提出異議）**
- AttentionLevel 是不依賴任何東西的純 enum，共 24 行。現有 12 個檔案 import 它，其中包括 547 要改的 `uc_flow_screen.dart`。
- 建議做法：
  - 把定義移到 `lib/components/attention_level.dart`。
  - `lib/app/attention_level.dart` 只留一行 `export '../components/attention_level.dart';`。app 往下 import components 符合 §2.1 的方向。
  - 12 個引用端的 import 不改，避免和 547 撞檔。
- 理由記在 Solution。若代理人認為應該全部改 import，停手回報，不要擴大範圍。

**app_shell 的參數化**
- components 不能依賴 `AppDestination`。導覽目的地改由建構參數傳入元件層的資料，例如 slot 或項目清單。returnTo、降級旗標與版本、推定版本也一樣改成參數。
- 由 `lib/assembly/shell.dart` 讀 provider，再把值傳進來。

**where.files（已設定，共 7 個）**
- 上述 4 個檔，加上新的 `components/attention_level.dart`
- `assembly/shell.dart`
- `app_shell_test`
- `shell_test`

**驗證**
- 以 grep 確認 lib/components 內沒有任何 import 指向 lib/app、lib/screens、lib/assembly。
- `app_shell_test` 改成以建構參數驅動後，原有的行為斷言（選中態、returnTo、降級徽章、推定版本）都要保留。
- `shell_test` 要能證明 provider 的值經過組裝根傳到畫面上。
