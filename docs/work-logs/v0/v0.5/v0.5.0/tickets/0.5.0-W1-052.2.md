## Solution
<!-- Schema[DOC/Solution]: 免填（DOC 類型以變更摘要取代）（.claude/pm-rules/ticket-body-schema.md） -->
在 `.claude/references/hook-architect-technical-reference.md` 新增「deny 輸出失敗語意」章，內容如下：
- 章首寫明失效方向。以 PreToolUse 為例，例外由 `run_hook_safely`（預設 `fail_closed=False`）接住後回 exit 1。exit 1 屬非阻擋錯誤，結果是放行。
- 「三項必載」表，每列附 Why／Consequence：fail_closed 只用於不可逆守衛；deny 輸出失敗由 emit_hook_output 兜底，無法改用的守衛須自行 exit 2；自帶 except-all 的守衛不得吞 SystemExit。
- 子節「新守衛撰寫檢查項：deny 輸出失敗測試」含 E1 對照、E2 正向對照輸入、except-all 穿透三項，每項附後果句。

`.claude/methodologies/hook-system-methodology.md` 原則 0 補一行互連，指向上述章節。兩檔版本行依各自既有慣例更新。合併 ab160b4b1（commit 5c8bc5495、75e9b1e47、107647d52）。

### 自檢結果

- 三項必載與 E1／E2 檢查項皆在：acceptance 兩項的依據。
- 事實正確性：初版把輸出失敗被吞掉的結果寫成 exit 0，PM 依兩次實地觸發的 rc=1 退回；執行者打開 `run_hook_safely` 與 `emit_hook_output` 核對後更正。basil-writing-critic 再次比對兩函式，全部吻合。
- 文字審查：basil-writing-critic 結論可合併。低嚴重度 3 項（PreToolUse 事件限定、第三檢查項後果句、失敗／失效方向用詞）已於本票修正。「用戶」一詞依 language-constraints 規則 2 邊界條款判定為專案 canonical。
- 規則 8 grep 三次提交皆 0 命中；zhtw strict 0 error。
