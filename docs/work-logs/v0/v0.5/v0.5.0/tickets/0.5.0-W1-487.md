## Problem Analysis
<!-- Schema[ANA/Problem Analysis]: 必填（.claude/pm-rules/ticket-body-schema.md） -->
### 事實（2026-10-21）

- 研究線的合併閘門卡在 flutter-integration 約 31 分鐘。現場只有 App 一個葉程序（CPU 約 0，畫面停在「已處理 0 個節點」），閘門逾時實為 3600 秒（merge_gate.py SUITE_TIMEOUT_SECONDS），期間全機名額一直被佔住，其他線排隊。
- 處置：由擁有那筆合併的線（研究線）先確認 App 的路徑位於 merge-gate worktree 底下，再只對 App 送 SIGTERM；閘門程序沒有動。
- 結果：flutter test 以失敗結束，被終止的測試項記為 did not complete。閘門走正常紅燈路徑，main 的 ref 沒變，名額釋放，merge-gate worktree 自行清理（worktree list 中 0 筆）。

### 框架問題兩條判準

- 抽象可攜：成立。任何使用合併閘門加全機名額的 consumer，測試葉程序都可能卡住而佔住名額；「只終止葉程序、讓閘門走正常失敗路徑」與專案無關。
- 根源在 `.claude/` 通用資產：成立。multi-session-orchestration 的 `references/shared-resources.md` 只寫了「125 持有者疑似卡住時回報 PM、不重送」與「不自行終止他線程序」，沒有寫 PM 收到回報後的處置步驟。

### dedup

關鍵字：卡住、名額、持有者。沒有直接對應的 issue。#77（Multi-PM 並行架構：跨 session 協作）是跨 session 協調的總題，關係判定為引用，觀測進 #77。
