## Solution

### 分析結論

採 **移除**：刪除 post-git-commit-hook 的 Wave 完成偵測與 `WAVE_COMPLETION_REMINDER`，連同未註冊的 commit-handoff-hook 殘留檔（實作：`0.5.0-W1-424.3.1`）。版本完成時的多視角審查改由發版流程承接（`0.5.0-W1-424.3.2`）。

### 候選方案

| 方案 | 做法 | 否決或採用理由 |
|------|------|---------------|
| 移除（採用） | 刪偵測、常數、殘留檔；審查步驟放進 version-retrospective | 7 天 0 次觸發，刪除不損失任何現行輸出；審查落在 PM 決定發版的時刻 |
| 改版本單位 | active 版本 pending=0 時提醒 | 發版判準是契約阻擋而非池清空，發版時 pending 前移，版本的 pending 在發版前不必歸零，仍結構性沉默 |
| 改 topic patch 單位 | patch 的票全部完成時提醒 | patch 與 minor 同構，同樣不以池清空為發版條件；且 hook 須另讀 topic 指派，偵測點仍只看 Bash 的 `git commit` |
| 維持 | 不動 | 失效方向是不提醒，讀者會以為版本完成時有提醒在把關 |

### 行為變更分級

刪除的是附加在 commit handoff 提醒後的一段字面，該段 7 天內從未印出；commit handoff 提醒本身與任何放行或阻擋結果不變。依 424.1 的同型裁定，`0.5.0-W1-424.3.1` 合併後回報主控即可。
