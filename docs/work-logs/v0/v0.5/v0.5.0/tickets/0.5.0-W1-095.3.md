### WRAP 評估：lavender 自行補定規則（2026-10-07）

範圍：本票把「畫面」例外（本地保留字 `presentation`）同時套用到 EVT `consumers` 與 `producers`（SPEC-003 §3.5、layout domain-map §6、system-layer §6）；0.5.0-W1-095 第二輪裁決 A′ 的問句只問 consumers。以 WRAP 快速+ 模式評估（例外範圍放寬即檢查放寬，屬防護增減，但現況資料零影響，故未升完整模式），不選定，交用戶裁決。

事證：
- 9 個 EVT 的 producers 全為已宣告 domain（corpus×3、diagnostics、graph、layout、schema×2、workspace），0 個用 `presentation`；consumers 有 3 個用 `presentation`（DIAGNOSTICS-001、LAYOUT-001、SCHEMA-002）。
- 6 個純畫面步驟（`traverses == []`）沒有一個 `emits` 任何 EVT（0.5.0-W1-095 R3）。
- 9 個 EVT 皆 category `domain_event`。
- G2 保留的專案規則本身寫的是「`consumers`／`producers` 必須是已宣告的 domain 名」，兩欄同一條規則。
- `docs/tech-decisions.md` 2026-10-07 補記（e1，9febc61af）寫「`presentation` 表示畫面層消費者」「延伸到 EVT consumers」，與現行三處規格（含 producers）不一致。

| 候選 | 規則 | 現況影響 | 致命風險 |
|---|---|---|---|
| 4a 維持 lavender 版（對稱） | consumers 與 producers 皆可用 `presentation` | 0 | 允許「畫面發出 domain_event」，而 domain event 起源於 domain 是事件建模的常見前提；這類建模錯誤之後不會被標出；與決策補記不一致，須補記更正 |
| 4b 只限 consumers（依裁決字面） | producers 的 `presentation` 視為未對應，交 Diagnostics | 0 | 規則不對稱，需在 §3.5 寫明理由；若日後真有畫面發出的事件（如使用者操作事件），要再開例外 |
| 4c 規格不定 producers | 只寫 consumers 的保留字，producers 遇 `presentation` 的行為不定 | 0 | 實作自行決定，App 與 doc validate 判定可能不同 |

傾向：4b，信心低。理由是畫面層「消費」domain event 是常態，「發出」domain event 則暗示事件起點放錯層，保留為可被標出的不一致較有診斷價值；且決策補記已寫 consumers。盲點：未查上游 EVT 模板或 flutter_balance 是否有由畫面發出的事件慣例；process_event 是否應另有規則與 W1-104 相關，未納入。W1-106 票面已載明：若裁決只限 consumers，由該票收窄三處條文。

需用戶裁決：畫面例外套用到 consumers 與 producers（4a），或只限 consumers（4b）／不定 producers（4c）？
