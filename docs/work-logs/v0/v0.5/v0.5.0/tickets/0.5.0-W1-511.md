## 重現實驗結果
### 實驗方法

- 讀兩個互動式 `claude --debug` session 的 debug log（主 checkout，line-board 由 skills-dir 自動載入）：
  - S1：`~/.claude/debug/f21f4e36-e232-4a17-982d-94c07262733e.txt`（2026-10-28 14:46 啟動，本 session）
  - S2：`~/.claude/debug/8e01fa1c-5dad-4d1c-b08f-b2644118f7d7.txt`（2026-10-28 12:39 啟動）
- 比對三類時間戳：SessionStart 開始（以 cbm-session-reminder 結束時刻減其耗時回推）、各 SessionStart hook 結束（`Hooks: SessionStart:startup [...] finished／timed out`）、`ui.open line-board ... placed`。
- 未做「停用 cbm-session-reminder」對照組：主假設已被兩組資料直接否證（見實驗發現），不需改 settings。

### 實驗發現

- 已驗證（不成立）：Pane 放置不等待 SessionStart hooks 全部結束。兩組都在 SessionStart 開始後 12～15 秒放置，此時仍有 16／27 筆 hook 未結束，最後一筆在 2～2.5 分鐘後才結束。
- 已觀測：兩組 Pane 都在 cbm-session-reminder 結束後 1.8～3.7 秒放置，這是 485.6 推測的來源；但同時段仍有大量 hook 在跑，兩者的先後不構成等待關係的證據。
- 未驗證：Pane 放置的實際前置條件（debug log 沒有等待事件）。候選包含 line-board session.start 完成後的 worker hop 與首次 render；屬平台端，與 485.6.1 已記錄的平台延遲（啟動、worker hop、render）一致。

## Solution
### 結論

假設不成立。看板 Pane 放置不等待 SessionStart hooks 全部結束：兩組 debug log 中，Pane 都在 SessionStart 開始後 12～15 秒放置，此時仍有 16／27 筆 hook 未結束，最後一筆在 2～2.5 分鐘後才結束。485.6 觀察到的「Pane 緊接 cbm-session-reminder 結束」是時間上相近，不是等待關係。剩餘延遲屬平台端（line-board session.start 約 5 秒 worker hop 與首次 render），框架端沒有可移出的 SessionStart hook 能縮短 Pane 放置。

### 候選方案

| 方案 | 內容 | 利 | 弊 |
|------|------|----|----|
| 結案不派修（採用） | 主假設已否證，acceptance 第 2 條的前提不成立 | 不為不存在的因果改 settings | Pane 延遲本身仍在，但屬平台端，已在 485.6.1 記錄 |
| 移出或改非同步慢 hook | 把 cbm-session-reminder 等慢 hook 改非同步 | 可能縮短 SessionStart 整體耗時 | 對 Pane 放置無效（資料顯示不等待）；只能以「縮短總耗時」為目的另案評估 |
| 停用 cbm-session-reminder 做對照組 | 原計畫的對照實驗 | 可直接測 cbm 結束與 Pane 的關係 | 主假設已由「Pane 放置時仍有大量 hook 未結束」直接否證，對照組無額外鑑別力，且需改 settings |
