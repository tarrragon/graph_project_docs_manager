## Solution
<!-- Schema[IMP/Solution]: 選填（.claude/pm-rules/ticket-body-schema.md） -->
提交 4d3156756。四支守衛改傳 scan=True，判定規則一致：命中的呼叫全部 via_scan=True 且無位置命中，走各守衛既有的無法解析分支；有位置命中時丟棄掃描命中、位置命中處置不變。
- bare-commit-guard：invocations 在取得後轉為 None，沿用既有分支（進行中操作一律擋，並行期 DENY，非並行期 WARN）。
- tracking-schema-json-staleness-guard、domain-import-lint：is_commit_command 回 None，沿用 main() 的並行期阻擋、非並行期提醒。domain-import-lint 改為單次 find_git_invocations({commit, merge}, scan=True)，移除 match_git_commit 引用。
- workspace-wipe-guard：_invocations_or_conservative_default 在僅掃描命中時回 parse_failed=True，各偵測器視為命中，再走既有並行期或主 repo 髒的 DENY、乾淨 WARN 判定。
已知差異：無法解析提醒文字仍寫「未閉合引號等原因」，對掃描命中略不精確，本票未改文案。

實地觸發（本 session，scratchpad 暫存 repo，payload 經 hook-dispatcher.py --group PreToolUse:Bash 餵入，CLAUDE_PROJECT_DIR 指向暫存 repo）：
- 並行期（dispatch-active.json 有 1 筆）：find -exec git commit 與 grep git commit 皆 rc=2，domain-import-lint 與 bare-commit-guard 輸出無法安全解析的阻擋訊息；setsid git reset --hard 與 git reset --hard 皆 rc=2；grep 'git stash'（加引號）rc=0。
- 非並行期：find -exec git commit、grep git commit 為 rc=0 並輸出三支守衛的提醒；grep 'git commit' 無輸出 rc=0；reset --hard 與 setsid reset --hard 為 rc=0 並輸出 workspace-wipe 提醒。
- liveness 驗證方式：以 dispatcher 實際回傳的 stderr 訊息與 exit code 判定各守衛確實執行；單元層另有變異確認（移除 scan=True 後，並行期掃描命中輸入翻為放行 exit 0）。
- 失敗語意：bare-commit-guard、staleness、domain-import-lint 在無法解析時為並行期 fail-closed、非並行期 fail-open 加提醒；workspace-wipe-guard 為 fail-closed（run_hook_safely fail_closed=True，視為命中後依狀態阻擋）。staleness 的 doc schema export 失敗仍為既有 fail-open，本票未動。
