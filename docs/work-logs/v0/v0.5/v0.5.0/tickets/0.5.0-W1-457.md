分析 commit 內容守衛以 repo 相對路徑比對前導斜線的 skip_patterns，根目錄 test/ 與 integration_test/ 下非 _test 檔被誤擋

## Problem Analysis
<!-- Schema[ANA/Problem Analysis]: 必填（.claude/pm-rules/ticket-body-schema.md） -->
### 問題根因

主控讀碼覆核（2026-10-20），與 why 欄一致：

- 提交期呼叫端 `commit_content_guards.py` 的 presence 檢查以 `sf.rel_path`（repo 相對路徑，不以 `/` 開頭）呼叫 `presence-detection-hook.py` 的 `should_skip_file(file_path, profile)`。
- `should_skip_file` 只把反斜線換成斜線，就逐條 `search` profile 的 `skip_patterns`。
- `presence_profiles.py` 的目錄類 pattern 一律寫成前導斜線形式：dart 的 `/test/`、`/integration_test/`、`/l10n/`、`/generated/`、`/design_system/`；python 的 `/tests?/`、`/migrations/`、`/\.claude/hooks/`、`/\.claude/skills/`。
- 目錄位於 repo 根時，相對路徑以目錄名開頭，前導斜線那一格不存在，永遠比對不到。編輯期 hook 收到絕對路徑，所以同一檔在編輯期放行、提交期被擋。

### 影響範圍

- 已驗證：根目錄 `test/`、`integration_test/` 下不帶 `_test` 後綴的 dart 檔（114.13 的兩個新檔、`test/helpers/`）在提交期被擋。
- 同機制推論：python profile 中根目錄的 `tests/`、`migrations/`、`.claude/hooks/`、`.claude/skills/` 在提交期同樣比對不到。這幾條是否真的進到提交期掃描，取決於 `get_profile_for_path` 對 .py 的回傳，交修正票以測試確認。
- 不受影響：目錄不在根的情況（如 `lib/l10n/`，相對路徑仍含 `/l10n/`）。

### 相關 Error Pattern

- tarrragon/claude#90 同類而方向相反：絕對路徑多出 worktree 路徑片段，與本票的相對路徑少一格前導斜線，同屬「路徑形態與 pattern 假設不一致」，屬引用關係。

### 修法選項（WRAP 精簡）

| 選項 | 涵蓋 | 代價 |
|------|------|------|
| A 改 dart 兩條 pattern 為 `(^|/)test/` 等 | 只修 dart 兩條 | 其餘前導斜線 pattern 與 python profile 仍有缺口；日後新增 pattern 會重犯 |
| B 呼叫端改傳 `"/" + rel_path` | 提交期呼叫端 | 其他呼叫端若傳相對路徑仍會重犯 |
| C `should_skip_file` 入口正規化：不以 `/` 開頭就補一個 | 所有 profile、所有呼叫端 | 絕對路徑行為不變；需確認沒有依賴「相對路徑不匹配」的既有測試 |

選 C：單一修正點涵蓋全部 profile 與呼叫端，絕對路徑輸入不受影響。反向檢查：若有 pattern 刻意只匹配非根目錄（目前沒有這類 pattern 註解），C 會改變其行為，由修正票以既有測試全綠確認。
