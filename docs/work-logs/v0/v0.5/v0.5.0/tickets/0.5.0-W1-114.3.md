### WRAP 評估（快速+，2026-10-08）：elementNotString 筆數、負載、空字串與其他格式問題

事證（R）：
- 上游 `check_path_pattern_format` 對每個值檢查：非空字串、不以 `/` 或 `./` 開頭、不含 `..` 段、不含 glob 字元；`find_non_domain_path_problems` 逐值各報一則
- 096.7 第二批 WRAP 原文「與上游同形」指的是「元素級報錯、不否決整檔」，不是筆數；選項文字是「另報一筆」
- 空字串作為字面前綴會命中所有路徑：非 domain 清單有一個 `""`，所有未命中 domain 的路徑都會歸入非 domain 層，「domain 未宣告」與「無法定位」被靜默吃掉。其餘上游格式問題（`/` 開頭、`..`、glob）在 App 的前綴比對下命不中任何路徑，效果等於該值不存在
- DomainBundle `path_patterns` 在 App 規格中同樣無元素格式規則（SPEC-006、UC-02 皆未定義）；一個 bundle 宣告 `""` 會把所有路徑歸給該 bundle
- 兩份語料目前都沒有 S2 檔、也沒有 `path_patterns` 值，0 筆

議題一：筆數與負載
| 候選 | 規則 | 破洞數 | 致命風險 |
|---|---|---|---|
| A1 | 每個壞元素一筆，負載加元素位置與原值文字 | 依壞元素數 | 一份寫壞的清單可產生大量破洞，淹沒其他破洞 |
| A2 | 每個壞元素一筆，負載只有 path／reason | 同上 | 同上，且多筆內容相同無法區分 |
| A3 | 每輪一筆，負載加壞元素數 | 每檔最多一筆，與其他三種一致 | App 不指出是哪個元素，要靠 `doc validate-paths` 定位 |
傾向 A3，信心中：與「另報一筆」字面一致，破洞報告以檔為單位與 yamlInvalid 等一致，定位交上游工具。結果型別不需改為多筆（4a 指出）。

議題二：哪些元素算壞
| 候選 | 規則 | 致命風險 |
|---|---|---|
| C1 | 非字串與空字串都算，子原因改名 `elementInvalid` | 其餘上游格式問題在 App 靜默無效 |
| C2 | 完整比照上游 `check_path_pattern_format` | App 多維護一份與上游同步的格式規則，上游改了要跟 |
| C3 | 只擋非字串（現況） | 空字串命中所有路徑，宣告缺口被靜默吃掉 |
傾向 C1，信心中：空字串是唯一會造成錯誤分類的值，其餘格式問題只是無效、`doc validate` 會報。盲點：未查上游是否計畫再擴充格式規則。

議題三：同一規則是否套到 DomainBundle `path_patterns`
| 候選 | 規則 | 致命風險 |
|---|---|---|
| D1 | 套用：bundle 的壞值略過，並以既有事件通道報出 | 需要決定走哪個事件（Graph 讀 bundle 欄位，不是 Corpus 讀檔），本版範圍擴大 |
| D2 | 開票延後到 0.6.0，本版只處理非 domain 清單 | 本版 bundle 寫入 `""` 時錯誤分類不被標出 |
傾向 D1 的最小版（只擋空字串、略過即可、不另發事件），信心低。

### 用戶裁決（2026-10-08，第三批）
