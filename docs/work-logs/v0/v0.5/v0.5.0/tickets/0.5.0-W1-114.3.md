### 事實更正（e1，2026-10-08，完整 WRAP 前）

快速+ WRAP 寫的「空字串作為字面前綴會命中所有路徑」不成立，用戶裁決議題一、三時看到的是這個錯誤前提。上游比對語意（`tracking_schema.py` path_patterns 註解，UC-02〈ticket 定位〉同文）：以 `/` 結尾才是目錄前綴，不以 `/` 結尾是單一檔案的精確比對。空字串不以 `/` 結尾，只會和路徑 `""` 精確比對，因此不會命中任何路徑。只有實作把所有值都當 `startsWith` 處理，才會出現「命中全部」；這是實作風險，不是規則語意。

- 議題三（D2，延到 0.6.0）的風險描述要降級：bundle 的空字串依規格同樣命不中任何路徑。0.6.0-W1-075 的 why 已同步更正

### WRAP 評估（完整模式，2026-10-08）：非 domain 清單哪些字串元素算壞元素

**錨點**：使用者看到的是路徑分類與破洞報告。App 的職責是如實顯示分類，以及影響顯示的缺口；值的格式回饋是 `doc validate` 的職責。App 只在「會改變顯示」的地方重做上游檢查，先例是 FR-11 的 `traverses` 未宣告名稱。評估單位是一條規則，套用到全部字串元素，不是單一個值。

**Step 0**：資料足夠。已知：上游五項格式規則（非空、不以 `/` 開頭、不以 `./` 開頭、不含 `..`、不含 glob 字元）、比對語意、App 不執行 doc CLI 做分析（`Process.run` 只出現在 external_opener）、上游規則今天才由 665b94358 建立。未知：上游之後會不會再擴充規則；實際語料出現頻率（目前 0 筆）。

**R：依比對語意，各類不合法值的效果**
| 值 | 上游判定 | App 比對效果 |
|---|---|---|
| `""` | 非空字串違規 | 精確比對路徑 `""`，不命中任何路徑 |
| `/docs/`、`./docs/` | 開頭違規 | 專案相對路徑不以 `/` 或 `./` 開頭，不命中 |
| `docs/../x/` | `..` 違規 | 掃描路徑已正規化、不含 `..` 段，不命中 |
| `docs/*` | glob 違規 | 當作字面比對，不命中 |
| `docs`（少了結尾 `/`） | 合法，視為單一檔案 | 只命中名為 `docs` 的檔案 |

結論：依規格語意，每個字串格式違規都等於「這個值不存在」，不會造成錯誤分類。被漏掉的路徑會顯示為「無法定位」或「未宣告」，這是如實狀態，不是靜默吃掉。
