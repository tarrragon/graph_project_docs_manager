## Problem Analysis
<!-- Schema[ANA/Problem Analysis]: 必填（.claude/pm-rules/ticket-body-schema.md） -->

### 問題根因

hook 函式庫 `get_effort_level()`（`.claude/lib/hook_io.py`）優先讀 payload 的 effort，缺席才讀環境變數 `CLAUDE_EFFORT`。effort=low 抑制 6 支 hook 的 warn 與 audit 輸出；hooks 共用 conftest 隔離 `CLAUDE_PROJECT_DIR` 與 `HOOK_TEST_ISOLATION`，但不清除 `CLAUDE_EFFORT`。測試若走 main() 並斷言該輸出，紅綠即取決於呼叫者 shell。現況影響僅 1 個檔（W1-055 已逐檔 delenv 修補），缺口是統一層缺席，而非現存紅燈。

### 影響範圍

已驗證：
- 讀取呼叫者環境變數的位置（hook 本體與 lib，排除 archived 與 worktrees 副本）見 Solution 盤點表。
- 呼叫 `get_effort_level` 的 hook 共 6 支：phase-completion-gate、auq-option-pattern-detector、askuserquestion-charset-guard、5w1h-compliance-check、sibling-blockedby-validator、phase4-decision-enforcement。
- 6 支中僅 phase4-decision-enforcement 的測試斷言 effort 敏感輸出，且已於 `_run_main_with_stdin` delenv；其餘 5 支測試不含 effort 引用，三環境皆綠。
- 專案根、日誌、模式類變數（HOOK_MODE、PRESENCE_HOOK_MODE 等）：測試均已逐檔 setenv/pop；以雜值全設後相關 145 案仍綠。
未驗證：`.claude/lib` 套件自身測試在 low 下的結果（lib 目錄 uv 環境無 pytest，未跑；lib 內僅 config_loader 一處讀環境變數 CLAUDE_PROJECT_DIR，且 lib conftest 已隔離）。

### 相關 Error Pattern

test-assertion-design 規則「不可靠斷言判準」之因素類型（程式以外的可變因素）。框架 issue #58（測試品質缺口，時間／負載／共用狀態切角）為同類；本件切角為環境變數，以 observe 附加。未另建 error-pattern（根因為單點缺口，改為 child 實作修補）。

## Solution
<!-- Schema[ANA/Solution]: 必填（.claude/pm-rules/ticket-body-schema.md） -->

### 盤點表（hook 本體與 lib；讀取呼叫者環境變數）

| 讀取點 | 變數 | 受影響測試（隔離現況） |
|--------|------|----------------------|
| lib/hook_io.py get_effort_level（6 支 hook 呼叫） | CLAUDE_EFFORT | test_phase4_decision_enforcement_hook（int_3、int_4；helper 已 delenv）；test_effort_awareness、test_effort_awareness_w14_036 自行 pop／set；其餘 5 支 hook 測試無斷言敏感 |
| lib/common_functions、config_loader、git_utils、path_permission、12 支 hook | CLAUDE_PROJECT_DIR | conftest 統一隔離（HOOK_TEST_ISOLATION）；test_hook_base_get_project_root、test_project_root_symmetry 逐檔 set |
| lib/common_functions | CLAUDE_HOOKS_DIR、CLAUDE_LOGS_DIR | 無測試引用；探針設雜值仍綠 |
| lib/git_utils | USER、USERNAME | test_git_utils_index_tripwire 引用 |
| task-dispatch-readiness-check | HOOK_MODE | 逐檔 |
| presence-detection-hook | PRESENCE_HOOK_MODE | test_presence_detection_hook、test_dart_presence_detection_hook 逐檔 pop／set |
| memory-dir-audit-hook | MEMORY_DIR_AUDIT_MARKER_FILE | test_memory_dir_audit 逐檔 |
| context-depth-warning-hook | CONTEXT_DEPTH_WARNING_STATE | 逐檔或無 |
| file-size-guardian-hook | FILE_SIZE_GUARDIAN_VERBOSE | 探針設 1 仍綠 |
| changelog-update-hook、post-git-commit-hook | VERSION_RELEASE_SCRIPT | 探針設雜值仍綠 |
| python-environment-guard-hook | PATH、PYTHONUTF8 | 系統性變數，不屬呼叫者設定敏感 |

### 方案比較

| 面向 | 案 A：逐檔 monkeypatch（現況） | 案 B：hooks conftest autouse fixture 統一清除 |
|------|------------------------------|---------------------------------------------|
| 影響面 | 僅被改的檔；新測試須作者自記 | 全套件；新舊測試一體生效 |
| 與既有 conftest 隔離 | 與 pytest_configure（setenv HOOK_TEST_ISOLATION、CLAUDE_PROJECT_DIR）互不相干 | 與其同層、同為環境整備；fixture 先清，effort 行為測試後設，順序成立 |
| 副作用風險 | 無 | 測試若依賴呼叫者預設 effort 會改變；盤點顯示 0 案 |
| 可攜性 | 每個 consumer 各自補 | 隨 conftest sync-push 一處擴散；清單可擴為白名單 |
| 子程序測試 | 須另傳 env | autouse 清的是 os.environ，子程序繼承清除後環境（優於案 A） |

結論：採案 B。
