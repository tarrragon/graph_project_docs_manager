## Solution
<!-- Schema[IMP/Solution]: 選填（.claude/pm-rules/ticket-body-schema.md） -->
### 修法
test_command_parse._all_specific_test_files 在命名樣式（test_*.py、*_test.py、*_test.dart）之外，新增「位置參數為基準目錄下既存一般檔案且副檔名為 .py／.dart」亦判具體檔案。封堵端（find_unwrapped_heavy_with_redirects）與閘門端（classify_argv_weight）共用 _weight_of_stripped，兩端同時生效；合併閘門快照內套件經 run-with-timeout 持有標記，不走此判斷（不受影響）。

### 路徑解析基準
pytest 子程序的 cwd 決定相對路徑指向，故基準須與之一致：預設 os.getcwd()（hook 與閘門皆與 Bash 工具同 cwd）；argv 中出現 uv `--directory X` 或 `--directory=X` 時，相對路徑對 X 解析（可連續出現，後者相對前者）。`--project` 不改變 cwd，不納入。

### 決策理由（acceptance 2）
- 不存在路徑：無法證明是單一檔案（可能是拼錯或將由他物建立），保守 heavy。
- glob 字面（含 * ? [）：shell 未展開時為字面名稱，展開後為多檔，保守 heavy。
- 目錄、integration_test（flutter 分支先判）、非 .py／.dart 副檔名：維持 heavy。
- 失敗語意：檔案檢查例外時 except 回 False 判 heavy；命名樣式命中者不經檔案檢查，維持 light（測試鎖住）。

### Phase 4 結論
重構需要：否。技術債務：無（hook 與閘門 cwd 假設已於 docstring 載明）。程式碼品質：A。
