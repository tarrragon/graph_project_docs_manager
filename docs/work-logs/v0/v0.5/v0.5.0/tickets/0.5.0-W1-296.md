## Problem Analysis
<!-- Schema[ANA/Problem Analysis]: 必填（.claude/pm-rules/ticket-body-schema.md） -->
問題：settings.json 對 mcp__dart__run_tests 註冊了 post-test-hook（PreToolUse、PostToolUse），但該工具失敗時走哪個事件從未實測。281.1 只開了 PostToolUseFailure:Bash 群組，281.2 只處理 Bash；若 MCP 工具失敗走 PostToolUseFailure，post-test-hook 目前收不到。

調查方式：先查證本專案能否實測。查設定檔的 mcpServers、以 ToolSearch 查工具、查 post-test-hook 日誌中的 mcp__dart 次數，三者交叉確認，結果見 Solution。

分析結論：本專案無法實測，實測轉交有 dart MCP 的 consumer；補註冊前須先取得失敗事件的 payload 形狀，因為 post-test-hook 的失敗解析只接受 Bash 的「Exit code N」首行。

## Solution
<!-- Schema[ANA/Solution]: 必填（.claude/pm-rules/ticket-body-schema.md） -->
### 實測可行性查證（PM，2026-10-15）

- 本專案沒有設定 dart MCP server。~/.claude.json 的全域與本專案 mcpServers 合計只有 codegraph、github、zhtw-mcp，另有 plugin 提供的 serena、context7；專案根沒有 .mcp.json；CLAUDE.md 列出的 MCP 也沒有 dart。
- PM session 以 ToolSearch 查 dart 與 run_tests，結果為 0；parsley 代理人定義雖然列了 mcp__dart__*，但 server 未設定，代理人同樣呼叫不到。
- post-test-hook 全部日誌中出現 mcp__dart 的次數為 0。settings.json 中 matcher 為 mcp__dart__run_tests 的兩處註冊（PreToolUse 與 PostToolUse）在本專案從未觸發。

### 結論

- 本專案不需要補 PostToolUseFailure 註冊：這個工具在本環境不存在，補了也不會觸發。
- 這兩處註冊屬框架資產，會隨 sync 送到其他 consumer；有設定 dart MCP 的 consumer 才能實測「失敗時走 PostToolUse 還是 PostToolUseFailure」。
- 即使在那些 consumer 加了 PostToolUseFailure 註冊，post-test-hook 目前的失敗事件解析只接受 Bash 的「Exit code N」首行格式，MCP 工具的 error 格式不同，會 fail-open 略過。所以補註冊之前，必須先實測取得 payload 形狀，否則沒有意義。
- 第 1 條驗收（實測紀錄）在本環境無法達成，理由如上。實測要轉到有 dart MCP 的 consumer 進行，落地為 0.5.0-W1-296.1：在框架 issue（查重時引用的 #35，payload 欄位讀取正確性未驗證）補一則觀測，請有 dart MCP 的 consumer 實測。
