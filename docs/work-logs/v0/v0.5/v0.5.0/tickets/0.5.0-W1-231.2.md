根因：共用切分器把重導向留在敘述 token 內（`2>&1` 單一 token；`2> /tmp/e` 切成 `2`、`>`、`/tmp/e`；`&>`、`>>`、`<` 同理），`_all_specific_test_files` 將其視為非測試檔位置參數，任何帶重導向的單檔執行皆判 heavy。deny 建議寫法同樣把 `2>&1` 以引號納入 `--` 之後的命令參數。

測試缺口：「三種常用形態放行」的測試與端到端探測皆未含重導向，而 `2>&1 | tail` 正是 Bash 規則二建議的寫法。

處置：建子票 0.5.0-W1-231.2.1（P0）修正，已通知派發方並提供暫行寫法（單檔先去掉重導向）。第 5 條驗收待 231.2.1 合併後重做實地觸發再勾。
