### 實作（thyme-python-developer 於 worktree，PM 依流程 B 代寫，2026-10-14）

提交 96a31c01b，以 worktree merge 隔離索引 CAS 合併為 253accdf2。

- lib：
  - 新增 `resolve_dir_path(base, target)`（expanduser、絕對路徑取代、相對路徑接續、一律 normpath）；`_join_dir` 改委派給它，所以 effective_dir 現在是 normpath 後的值。
  - GitInvocation 新增 `dash_c_dirs`，記錄每個 -C 套用後的累積目錄。
  - 新增 `find_git_dash_c_dirs(command, base_dir)`，以 scan 模式列舉任意子命令的 git 呼叫，回傳全部 -C 累積目錄加 effective_dir（有序去重）；無法解析時回 None。
- 取捨：選「find_git_invocations(base_dir=payload cwd) 的 effective_dir」，不另寫單一解析函式，讓 cd、-C 串接、別名展開都走同一條解析路徑。
- 三支 hook：
  - merge-staged-index-guard 改取 effective_dir，dir_unknown 時退回 payload cwd。
  - git-index-lock-cleanup 刪除自有的 `_resolve_path`、`_dash_c_paths`、`_GIT_OPTS_WITH_VALUE`，改用 find_git_dash_c_dirs 與 resolve_dir_path。它也會把語句內 cd 的目錄納入，屬超集，不會漏掉原有目標。
  - bare-commit-guard 改為 `_resolve_detect_dirs`（回傳清單）。
- dir_unknown 策略：目錄可知時只查 effective_dir；dir_unknown 或無法解析時，payload cwd 與 project root 兩處都查（去重），任一處有阻擋型進行中狀態就擋。
- 偵測失敗日誌：依偵測對象分別標示。MERGE_HEAD 偵測失敗視為 git 整體失敗，只回報一次並略過第二次呼叫；只有第二次失敗時標為「cherry-pick、revert、rebase 狀態」。

  - 執行者在 scratchpad 以 hook-dispatcher 分組餵入：-C 相對路徑指向有 MERGE_HEAD 的 repo 時擋（rc=2）；-C 指向他處、cwd 有 MERGE_HEAD 時放行（rc=0）；dir_unknown 時由 cwd 那處觸發而擋（rc=2）。

- liveness 驗證方式：以上述探針路徑在 `.claude/hook-logs/bare-commit-guard/` grep 命中。
