### 交接備註：231.2 對基準的影響（2026-10-14，派發 session 預告）

- 231.2 合併後，PreToolUse(Bash) 的行為會改變：pre-test-hook 增加封堵判定，未經 run-with-timeout 包裝的 heavy 命令會被 deny。動工時先確認 231.2 的封堵是放在既有的 pre-test-hook 裡，還是另外新增一支 hook，據此寫設計段的接法驗收
- 189 的基準是在 231.2 合併前量的（HEAD 6ee53f5b6～2ba607aa3）。189.1 改動前要在 231.2 合併後的 HEAD 上重量一次基準，再拿來和改動後比較，不直接沿用 189 的數字

### 與 231.2 的協調結果（2026-10-14，-fa 線回覆）

- 231.2（be3cdc3fc）與 231.2.1（3064e20e2）都已合併到 main。改動前基準要在 3064e20e2 或之後的 HEAD 上量
- 231.2 的封堵判定加在既有的 `.claude/hooks/pre-test-hook.py`，入口是 `build_block_reason`，判定函式是 `.claude/lib/test_command_parse.py` 的 `find_unwrapped_heavy_with_redirects`。沒有新增 hook，也沒有改 settings.json
- pre-test-hook 同時註冊在 matcher `Bash` 與 `mcp__dart__run_tests` 兩處。本票只合併 Bash 段，mcp 段維持單獨執行，所以 hook 的單獨執行入口必須保留
- 分派程序要保留的行為：子 hook 輸出的 `permissionDecision: deny` 與 reason 要原樣傳出（封堵靠它生效）；pre-test-hook 判定失敗時 fail-open，回傳 allow
- -fa 線承諾：189.1 動工後，不再改 pre-test-hook 與 settings.json 的 Bash 段
