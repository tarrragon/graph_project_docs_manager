# Execution Log

## Task Summary

track fix-multi-view-status 依設計只覆寫欄位行、reason 不寫入 body；acceptance-gate 對 multi_view_status=skipped 要求 reason 子欄位，修正後 complete 仍報缺 reason

---

## Problem Analysis
### 問題根因

寫入端與驗證端對同一欄位各持一份契約，互未對照。寫入端 `track_multi_view_status.py` 的防濫用結論 2 刻意「只覆寫欄位行、reason 不寫入 body」；驗證端 `multi_view_checker.py` 依 `ana-solution-schema.yaml` 的 `required_subfields` 要求 skipped／n_a 附平鋪 `reason:`。兩者各自合理，組合後修正指令的產出必然通不過閘門。缺口二同源：指令以「命中 0 行拒絕」避免誤改，但該保護同時封死「補寫」用途。缺口三（非法值 single_view）由閘門正確攔下，屬閘門運作正常。影響：每個以 fix 修正的 skipped／n_a 票，complete 皆出 WARN（不阻擋），修正工具失去完成修正的意義。

### 影響範圍

已驗證：`track_multi_view_status.py`、`lib/multi_view_status.py`（SSOT 複製清單）、`hooks/acceptance_checkers/multi_view_checker.py`、`config/ana-solution-schema.yaml`。reviewed 值需 reviewers／conclusion 兩個子欄位，fix 現亦不寫，同型缺口（未重現，列為假設）。既有票相容：fix 只在被呼叫時作用，已 complete 的票不受影響。

### 相關 Error Pattern

PC-117（nested YAML 誤判，schema forbidden_format 已記）屬同一欄位的格式面；本案是寫入面。與 framework issue #55（ticket CLI 契約缺口叢集）同形，關係判定為引用，已 observe。

## 重現實驗結果
### 實驗方法

pytest tmp_path fixture（沿用 test_fix_multi_view_status.py 的 git_repo／patch_paths_to_repo），不觸碰任何真票。fix 指令執行後，以 `multi_view_checker.check_multi_view_status` 檢查結果。腳本在 scratchpad 的 test_e2_mvs_gate.py，不入庫。

### 實驗執行

- 缺口一：Solution 含非法值行，執行 fix --value skipped --reason（合法長度），rc=0；再跑 gate 函式。
- 缺口二：Solution 只有 `### multi_view_status` 標題、無欄位行，執行 fix。

### 實驗發現

- 缺口一（修改前紅）：gate 回傳 should_warn=True，訊息「multi_view_status=skipped 缺少必填子欄位，缺少欄位: reason」。已驗證。
- 缺口二（修改前紅）：rc=1，輸出「找不到 multi_view_status 行，未寫入」。已驗證。
- 缺口三：由閘門攔下，無需實驗。
- 未驗證假設：reviewed 值同型缺口。

## Solution
multi_view_status: skipped
reason: 本 ANA 為契約衝突的修改方判定，兩案比較已由單一視角完成，無架構設計決策需多視角

### 結論

修改方為寫入端（CLI）。方案 A 採用，方案 B 不採。

### 方案比較

| 項目 | 方案 A：CLI 同時寫 reason，缺欄位行時新增平鋪行 | 方案 B：gate 放寬（skipped／n_a 不要求 reason） |
|------|------|------|
| 與 ana-solution-schema.yaml | 不動 schema；寫入端對齊既有 required_subfields，SSOT 不變 | 須改 schema 的 required_subfields 與 multi_view_checker 預設 schema 兩處，並改 acceptance-gate 測試 |
| 既有票相容 | 無影響：已 complete 票不重跑；未 complete 票照原 gate 規則 | 已有 reason 的票仍通過；但稽核基準降低，無法再區分「附理由跳過」與「未思考跳過」 |
| 解缺口二 | 一併解（缺行時新增） | 不解，仍須另案 |
| 風險 | CLI 寫入面擴大（由單行擴至兩行）；須改 docstring 防濫用結論 2，並以 reason 取代既有 reason 行避免重複 | 破壞 skipped「必須附理由」的設計初衷（W10-051 治本方案 D） |

採 A 理由：gate 的要求是設計意圖，修正工具應通過它，而非反向；A 同時解兩個缺口。CLI 本身已驗 reason 長度 >= 10 並要求呼叫端提供，現僅是把已驗證的值落地。
