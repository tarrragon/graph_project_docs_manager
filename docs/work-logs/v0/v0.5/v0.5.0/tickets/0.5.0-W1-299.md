## Solution
<!-- Schema[IMP/Solution]: 選填（.claude/pm-rules/ticket-body-schema.md） -->
採 (a)：移除 11 支 hook 的 HOOK_METADATA 區塊（commit 607cc3733 共 10 支、58bb2b03d 為 pre-test-hook.py 單支）。只刪 docstring 內的區塊，行為不變。

**理由**

- 所有已知 repo 都沒有會執行的讀取者（盤點見 Problem Analysis）。
- 11 支中有 8 支的 dependencies 已與 PEP 723 不一致；沒有讀取者的欄位必然漂移，而且會誤導依賴盤點。
- 採 (b) 對齊，就得為一個沒人讀的欄位加檢查器，持續付維護成本。
- 權威來源改為：依賴看 PEP 723（uv 實際依它安裝）；事件與 matcher 看 settings.json 與 .claude/hooks/hook-dispatch-registry.json。

**對其他 consumer 的影響**

- 這次移除會隨下次 sync-push 送到 canonical，再由各 consumer sync-pull 收到。各 consumer 都沒有會執行的讀取者，只有封存且未註冊的 hook-auto-register.py，所以不影響任何執行中的行為。
- 唯一的後果：若有人重新啟用 archived/hook-auto-register.py，它在這 11 支 hook 上抽不到中繼資料。該工具已封存，其功能由 settings.json 與 registry 取代，因此不另外處理。
- canonical 的 skills/ticket/hooks/creation-acceptance-gate-hook.py 仍帶這個區塊，本地版本已經沒有。這屬於 canonical 與本地的既有差異，下次 sync-push 時會一併收斂，本票不額外動作；sync-push 不在本 session 的授權內。

**提交方式**：第一次提交被 bare-commit-guard 擋下，因為 pre-test-hook.py 落在 0.5.0-W1-231 的派發宣告範圍內。依守衛建議拆成兩次提交，兩次的 index 都先以 git diff --cached --name-only 核對，pre-test-hook.py 的 staged diff 只有本票的 9 行刪除（numstat 0/9）。

**Edit 時的警告**：修改 post-ticket-lifecycle-hook.py 時，hook 警告該檔「正被背景代理人處理（0.5.0-W1-231）」。本票只改 docstring，若與該代理人的修改衝突，合併時會由 CAS 擋下，不會靜默覆蓋。

### 事後發現與教訓（2026-10-15）

快照全套件發現 1 個紅燈：281.1 的測試 test_header_event_type_lists_failure_event 以欄位名 "event_type" 讀取 hook-dispatcher.py 的 HOOK_METADATA。所以這個區塊其實還有一個讀取者，就是這支測試。盤點時只 grep 區塊名 HOOK_METADATA，沒有 grep 區塊內的欄位名，因此漏掉。修正由 0.5.0-W1-301 承接，改為斷言 settings.json 的註冊，不回復 HOOK_METADATA。

教訓：刪除一個區塊或結構前，除了搜區塊名，也要搜區塊內每個欄位名在測試與程式碼中是否被讀取。讀取者可能只認欄位，不認區塊名。

另一個教訓：本票在共用主 checkout 直接提交 .claude/ 修改，結果被其他線的推送一起帶上 origin，而且發生在快照全套件跑完之前，紅燈因此進了 main。非票面修改應在 worktree 進行，合併前先通過快照閘門。
