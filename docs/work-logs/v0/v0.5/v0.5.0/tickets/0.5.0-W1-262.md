### PM 查證（2026-10-14）：fixture 形態問題，非產品缺陷

- **真實 repo**：在主 checkout 實測 `get_project_root()` 為專案根，`get_git_common_dir()` 與檔案系統解析 `_resolve_git_common_dir_from_fs()` 都得到 `<專案根>/.git`。一般建票不會降級，也不會出現警告。
- **測試環境**：`.claude/skills/ticket/conftest.py` 有一個 autouse fixture，把 `CLAUDE_PROJECT_DIR` 導向一個非 git 的 tmp 目錄（防止鎖污染真實 repo）。`test_create_auto_commit.py` 的 `patch_paths_to_repo` 只把 tickets_dir 改到測試自建的 git repo，專案根仍是那個非 git 的 tmp 目錄，因此 `get_git_common_dir` 回傳 None。
- **為何 152.1 之後才紅**：152.1 之前，「common dir 無法解析」這條分支靜默落回票目錄；152.1 讓它印出 WARNING，這是 152 結論要求的可見性。兩個測試斷言 stderr 不含 `[WARNING]`，原本要防的是提交重試相關的警告，結果被鎖降級的警告觸發。
- **修法方向**：不放寬斷言。讓 `patch_paths_to_repo` 的專案根指向測試自建的 git repo：設定 `CLAUDE_PROJECT_DIR` 為該 repo 並重設 `get_project_root` 快取。這樣 fixture 才符合實際形態（tickets_dir 位於 git 專案根之下），鎖也會落在該 repo 的 common dir。
