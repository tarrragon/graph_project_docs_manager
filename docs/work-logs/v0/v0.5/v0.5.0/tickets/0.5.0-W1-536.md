## Problem Analysis
<!-- Schema[ANA/Problem Analysis]: 必填（.claude/pm-rules/ticket-body-schema.md） -->
### 實測（2026-10-30，本機 uv 0.8.13）

| 入口 | 不加 --with pyyaml 的結果 | 原因 |
|------|------|------|
| 步驟 7：以 `uv run python -` 執行 SKILL 片段，import allocator | 失敗：`ModuleNotFoundError: No module named 'yaml'` | `allocator.py` 在模組層 `import yaml`，本身沒有 PEP 723 區塊（它是被 import 的 lib，不是腳本） |
| 步驟 7：`uv run allocator.py --help` | 失敗，同上 | 同上 |
| 步驟 8 CLI：`uv run readme_index.py sync` | 成功，rc=0（「README.md 已與現況一致」） | `readme_index.py` 有 PEP 723 宣告 `dependencies = ["pyyaml"]` |
| 步驟 8 Python API 片段 | 未實測；推論會失敗 | 片段 import 的 readme_index 第 90 行 `import yaml`，又從 allocator import；以未帶依賴的 python 執行時，會遇到同一個缺口 |

修法要涵蓋的入口：步驟 7 片段（必修）；步驟 8 的 Python API 片段（推論上需要修）；步驟 8 的 CLI 不必修。

### 兩條 AND 判準

1. 抽象可攜：成立。只要照 SKILL.md 原文執行步驟 7，任何 consumer 都會失敗一次，與專案無關。
2. 根源在 `.claude/` 通用資產：成立。缺口在 `.claude/skills/error-pattern/SKILL.md` 執行指示沒有寫出依賴，不在本專案程式碼。

兩條都成立，判定為框架問題。

### dedup 與關係判定

- 關鍵字：pyyaml、allocator、ModuleNotFoundError、PEP 723、依賴宣告、error-pattern add。
- 命中：#52 的軸四（comment 5566719904、5566720234）已記錄「同段程式碼以 python 執行拋 ModuleNotFoundError（yaml）」，根因也一樣：allocator 是 lib，不該帶 PEP 723，缺口在 SKILL.md。修法票已列在該 issue（另一個 consumer 的票，於 SKILL.md 步驟 7 明示 pyyaml 依賴，狀態為待裁票）。
- #97 只在討論 parser 時提到 pyyaml，主題是 hook 的執行前提，與本問題無關。
- 判定：重複（#52 軸四）。不切分，也不只是引用：現象、根因、修法三者都相同。本次 observe 只補新證據：第二個 consumer 也踩到；步驟 8 CLI 已有 PEP 723，可以正常執行，修法範圍可以排除它；步驟 8 的 Python API 片段可能也要修（未實測）。
- 依修補節奏，P3、不屬 P0／P1，不派修。
