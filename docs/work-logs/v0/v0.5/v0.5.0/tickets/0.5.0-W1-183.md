### 派發 context（PM 89，2026-10-13）

今日與本票相關的實測，供設計測試時參考：

1. git 收到 SIGTERM 會自行清除 index.lock。0.5.0-W1-164.5 以 harness 逾時終止 hook 取樣 6 次、0.5.0-W1-164.6 以直接終止 git status 取樣 42 次，皆未留下鎖。故清鎖測試的鑑別力取決於「逾時當下鎖確實存在」：鎖從未取得時，測試會因鎖不存在而通過，與修法是否有效無關。這正是本票 why 第 (2) 點，修正方向為在同一測試內先確認鎖已存在再觸發逾時，取不到鎖時 skip 並說明。
2. 讓 git 長時間持鎖的可靠做法（0.5.0-W1-164.5 採用）：git add 搭配 clean filter，filter 內等待；git 先取 index.lock 再執行 filter，鎖在 filter 期間持續存在。
3. 機器負載今日在 15 至 105 之間波動（1 分鐘值）。門檻維持寬鬆，不寫緊的毫秒值；耗時上界的斷言以「有上界」為目的，不以速度為目的。

約束補充：
- 測試結束時終止自己啟動的程序群組；只針對以 PID 或程序群組 ID 指名的對象，不用 pkill、killall。
- orphan-test-procs.py 的列出模式顯示「符合 0」不代表沒有殘留（父程序非 1 的形態目前認不出）。驗收第三項「測試結束後無殘留」請以測試自己記錄的 PID 逐一確認已不存在，不依賴該腳本的輸出。
- 兩份 helper：.claude/skills/worktree/hooks/worktree-auto-commit-hook.py 的 _run_with_graceful_timeout 與 ticket CLI 的 git_ops 內的對應實作。本票只改測試，不改 helper；若發現 helper 有缺陷，停手寫入 NeedsContext 回報。
