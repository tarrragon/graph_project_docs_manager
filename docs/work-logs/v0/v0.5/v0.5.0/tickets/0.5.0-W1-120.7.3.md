### PM 拆分與前提更正（2026-10-14）

- 拆分：原範圍為 10 支 hook，超過修改檔案數 5 的閾值；本票已在深度 3，無法再建子票，故於 0.5.0-W1-120.7 下另建同層票 0.5.0-W1-120.7.6，承接其餘 5 支 PostToolUse 提示型 hook。
- 本票範圍：PreToolUse 的 tracking-schema-json-staleness-guard、uncommitted-ticket-md-reminder、homoglyph-guard，以及 PostToolUse 的 post-commit-fetch、commit-msg-layer2-marker-check。
- 前提更正：0.5.0-W1-120.7 稱這 10 支「皆為 PostToolUse 提示，漏判只是少一則提示」。PM 實查發現 tracking-schema-json-staleness-guard 是 PreToolUse，且有 exit 2 路徑，屬阻擋型；子字串漏判（例如 git -C x commit）會使它放行。須在 Solution 寫明該 hook 改用解析器之後，find_git_invocations 回 None 時的處置，比照其他阻擋型守衛：並行期保守處理，或寫明不保守的理由。
- 執行者改為 basil-hook-architect（原誤設 parsley-flutter-developer）。

## Solution
<!-- Schema[IMP/Solution]: 選填（.claude/pm-rules/ticket-body-schema.md） -->
改法：五支 hook 的 commit 判定改為 contains_git_word 前置後呼叫 lib.git_command_parse.find_git_invocations(command, {'commit'})；amend 排除保留（任一 invocation 的 args 不含 --amend 即命中）。原 git log、show、diff、status 子字串排除由解析器的子命令比對取代。post-commit-fetch 原無 amend 排除，維持不排除。uncommitted-ticket-md-reminder 一併移除已無使用的 EXCLUDED_COMMAND_PATTERNS 常數，並補 ImportError 降級用的 stub。
None 的處置：tracking-schema-json-staleness-guard 的 is_commit_command 改回傳 Optional[bool]，None 表無法解析；main 比照 bare-commit-guard：新增 has_parallel_dispatch（讀 dispatch_tracker.get_active_dispatches，讀取失敗視為非並行），並行期 exit 2 保守擋下，非並行期 stderr 提醒後 exit 0。理由同 bare-commit-guard（無法判定時於並行期放行會讓守衛失效；非並行期擋下干擾單線作業）。其餘四支（uncommitted-ticket-md-reminder、homoglyph-guard、post-commit-fetch、commit-msg-layer2-marker-check）回 None 視為未命中。
實地觸發：scratchpad 暫存 repo（暫存 tracking_schema.py 已 staged），以 uv run --quiet 啟動方式、CLAUDE_PROJECT_DIR 與 HOOK_TEST_ISOLATION 指向暫存 repo 餵 payload。git -C x commit：命中並進入 schema 檢查（日誌 WARNING 無法計算預期 schema，fail-open 放行，成因為暫存 repo 無 doc skill）；echo git commit：日誌為 跳過 非 git commit 命令。兩者 rc=0。
Phase 4：重構需要 否；技術債務 無（四支內的 is_commit 邏輯各自重複約 5 行，與既有結構一致，抽共用屬額外範圍）；程式碼品質 A；結論：無需重構。
