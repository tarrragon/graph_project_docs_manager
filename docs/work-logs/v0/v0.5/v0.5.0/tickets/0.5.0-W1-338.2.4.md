## Solution
<!-- Schema[IMP/Solution]: 選填（.claude/pm-rules/ticket-body-schema.md） -->
拆分結果：hook 992 行/25 函式 -> hook 257 行 + tripwire/ 套件 5 檔（__init__ 8、config 202、state 171、signals 414、render 68），共 1120 行，模組數 4（不含 __init__）。
各模組職責：config=常數/dataclass(ContextBlacklist,SignalDef,Config)/YAML 解析 load_config；state=_now 時鐘注入點/狀態檔路徑解析/載入/原子寫入/過期清理/cooldown/換票重置；signals=DetectResult/票號推導/手動 wrap 偵測/ticket 讀取/四個 Strategy+SIGNAL_STRATEGIES；render=render_message/_build_prompt_excerpt；hook=_process_signals/is_pytest_environment/main + re-export。DetectResult 放 signals（render 與 signals 共用，避免循環）；cooldown 輔助放 state。
兩個 commit：0c1e78283 測試改鎖行為（先於搬移，對舊單檔 125 passed）；44a0fc5c7 純搬移（125 passed，邏輯逐行未改，僅 _now/get_project_root 的存取點隨模組調整）。
鎖位置寫法盤點與處置：測試 patch 了 hook_mod._now、hook_mod.get_project_root（S3 路徑）、hook_mod.subprocess.run，均鎖位置。處置：(1) subprocess.run 改 patch 測試檔自身 import 的 subprocess（同一模組物件，與位置無關）；(2) _now 與 AnaClaimStrategy 的 get_project_root 改由符號反查其定義模組 _module_of(hook_mod, obj) 再 patch；(3) J 系列 AST/原始碼掃描改涵蓋 hook+tripwire/*.py。main 內使用的 get_project_root/derive_ticket patch 仍有效（main 留在 hook 檔，屬行為而非位置）。
陷阱：(a) 若 hook 檔 re-export _now，對副本的 monkeypatch 會靜默無效，故刻意不 re-export _now，signals 以 _state._now() 屬性存取，全套件單一注入點；get_project_root 在 hook 與 signals 各有一份 from-import 綁定，patch 一處不影響另一處，S3 與 main 須分別 patch。(b) 票面前提『hook-dispatcher in-process 載入』與現況不符：hook-dispatch-registry.json 未登錄本 hook，settings.json 以 uv run --quiet 直接執行；仍以 hook-dispatcher.run_inprocess 實測連跑兩次可載入且 sys.path 被還原，tripwire 因 sys.modules 快取不受還原影響。(c) 套件須自行把 hook 同目錄掛入 sys.path（兩種載入方式皆不含該目錄）。(d) signals.py 的 lib import 必須 try/except 降級，否則缺 lib 的消費端會在匯入階段 ImportError，破壞原『找不到 lib 則 WARNING 並 exit 0』行為。(e) 註解中的 W10-052 觸發 rule8 守衛，以 relocation 豁免標記搬移。(f) hook-dependency-isolation-check 只掃 hook 檔 import：yaml 已移至 config.py，hook 檔不再 import yaml，PEP 723 宣告仍須保留（A2 測試與 uv 隔離環境實際需要），此一致性目前無機器檢查，屬檢查器盲點。(g) 新模組 stem config/state/signals/render 會進入該檢查器的全域本地模組索引，之後同名外部套件 import 會被視為本地而漏報。
