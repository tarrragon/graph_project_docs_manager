## Problem Analysis
### 問題根因

wrap-decision SKILL.md 2.16.1 全檔約 5,088 tokens（skill-design-guide 的分段估算指令：ASCII 字元 ÷ 4 + 非 ASCII 字元 ÷ 1.3，含 frontmatter），比 5k 入口檔門檻多 88；行數 273，在 500 行內。超出的部分來自三節情境性內容：只有在特定疑問出現時才需要，卻放在每次觸發都會讀的主文裡。

### 影響範圍

- 受影響：`.claude/skills/wrap-decision/SKILL.md`（portable: true，會隨 skill-sync 散布到其他 consumer）。
- 已驗證：逐節 token 數（見〈重現實驗結果〉）。
- 未驗證：外移後讀者是否仍能在需要時找到外移內容（外移段保留一行路由，以此降低風險）。

### 相關 Error Pattern

無直接對應。skill-design-guide〈Progressive Disclosure — 三層載入〉規定第 2 層 < 5k tokens，沒有 hook 執法（issue #87 已追蹤執法層缺口）。

### 查重紀錄

## 重現實驗結果
### 實驗方法

以 skill-design-guide 的估算公式（ASCII ÷ 4 + 非 ASCII ÷ 1.3）逐節量測 SKILL.md 2.16.1，節的切法依二、三級標題。

### 實驗執行

`python3 -I -` 從 stdin 執行，只讀檔、輸出到 stdout。全檔 5,088 tokens。各節（tokens）：frontmatter 與開頭 353、觸發條件 666、二元處置取捨邊界 402、錨點確認 293、Step 0 共 537（模式辨識 112、判定流程 236、與 requirement-protocol 的分工邊界 146）、W 共 596、R 共 583、A 共 499、P 共 397、絆腳索 302、與其他決策類 Skill 的關係 183、參考文件 279。

### 實驗發現
