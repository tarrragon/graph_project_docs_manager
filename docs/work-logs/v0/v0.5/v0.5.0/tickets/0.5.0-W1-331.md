# Execution Log

## Task Summary

should_check_git_operation 以 'git push'／'git merge'／'git cherry-pick' 子字串比對命令；Bash 規則一要求 git 操作用 git -C <path>，該形式中間夾 -C <path> 而永不命中，hook 靜默通過

---

## Problem Analysis
<!-- Schema[IMP/Problem Analysis]: 選填（小型 IMP 可留 placeholder；大型 IMP 建議填寫）（.claude/pm-rules/ticket-body-schema.md） -->
PM 補充實例（2026-10-15 21:0x）：建立本票的 ticket create 命令中，git push 字樣只出現在 --why 的引號參數內，worktree-branch-check 仍判為 push 並輸出未合併進度警告，即 E2 情境（引號內字樣誤觸發）的實例。現行子字串比對同時有漏判（git -C 形式）與誤判（引號內文字）。

## Solution
<!-- Schema[IMP/Solution]: 選填（.claude/pm-rules/ticket-body-schema.md） -->
### 實作（thyme-python-developer，worktree commit e9df9944d）

- `should_check_git_operation`、`is_merge_or_cherry_pick` 改用既有 `lib.git_command_parse.find_git_invocations`（`contains_git_word` 先短路），辨識全域選項（-C、-c、--git-dir 等）後的子命令、逐語句解析、遞迴 bash -c／eval、展開 git 別名、剝離 heredoc 內文
- 解析回 None 時 fail-open 回 False，記 warning「無法解析命令（長度 N），fail-open 不檢查」（只記長度不記全文）
- lib 匯入失敗的 fallback 補兩個符號，退化為不檢查
- 本 hook 只輸出提醒、不阻擋：觸發範圍放寬只增加提醒，不擋下任何操作

### 產生路徑盤點表（acceptance 6）

| 路徑 | 修正前 | 修正後 |
|---|---|---|
| `git push`／`merge`／`cherry-pick`（無全域選項） | 觸發 | 觸發 |
| `git -C <path>`、`git -c k=v`、`--git-dir` 等全域選項後接三個子命令 | 漏判 | 觸發 |
| `cd X && git ... push`、`;`、`\|\|` 後的語句 | 子字串命中才觸發 | 逐語句解析 |
| `bash -c`、`eval`、前綴包裹、環境變數賦值後的 git | 子字串 | 遞迴解析 |
| git 別名（內建與 `alias.X`） | 漏判 | 展開 |
| 引號內、`--why "..."`、echo 的 `git push` 字樣 | 誤判觸發 | 不觸發 |
| heredoc 內文的字樣 | 誤判觸發 | 不觸發 |
| 無法解析（引號未閉合、巢狀過深、別名查詢超限） | 子字串命中則觸發 | fail-open 不觸發並記 warning |
| lib 匯入失敗 | 子字串比對可用 | 不檢查（stderr 有匯入警告） |
