- 未驗證：CAS 搬出後 worktree_manager.py 的實際行數（預估約 1990 行）

## Solution
### 判定

| 檔 | 判定 | 理由 |
|----|------|------|
| `worktree_manager.py` | **拆：只搬出 CAS 引擎** 到 `.claude/skills/worktree/scripts/merge_cas.py` | §3.1 職責分群得兩群：CAS 引擎（238、231 改）與 merge 入口加閘門接線（266、310、231 改）。CAS 引擎外部依賴只有三個名稱，邊界乾淨；待辦的 328 需要它的 `_compute_merge_tree`，不先搬出會再多一棵票樹改同一區 |
| `worktree_manager.py` 的 merge 入口 | 不拆 | 不同票樹改的是同一職責（merge 子命令的參數與目標解析），這是該職責的集中處；搬到另一檔只是把競爭換位置。create／status／cleanup 在窗口內 0 次修改，只依行數拆違反 §1 Consequence |
| `merge_gate.py`、`test_merge_gate.py` | 不拆 | §2 最後一列：測試檔隨產品檔判定。三棵票樹同屬「閘門在多線負載下的排隊與診斷」主題、各改不同子區塊，且已全數完成；待辦中只剩 328 會再改，且與 257 同線依序執行，不會互等 |

### 候選方案

| 方案 | 內容 | 利 | 弊 |
|------|------|----|----|
| A（採用） | 只搬 CAS 引擎（約 283 行）到 merge_cas.py | 對準實測的競爭區；與既有 257 的 strategy 一致；位置鎖定 patch 只有 4 處 | worktree_manager.py 仍約 1990 行 |
| B | A ＋ merge 入口與閘門接線搬到 merge_command.py | worktree_manager.py 只剩 create／status／cleanup 與 main | 無競爭證據支持；入口測試大量 patch `worktree_manager._merge_*`（test_helper_functions.py 等），位置鎖定面擴大數倍 |
| C | 不拆，只調整票序 | 零搬移成本 | 328 會在 CAS 區加第五棵票樹；GateVerdict 的重複定義持續存在 |

### 對既有佇列的影響

- **257 吸收為本票的拆分實作**：已 `set-parent` 改掛為 338.3 的子票；where.files 補新模組、三支位置鎖定測試、merge_gate.py docstring、references/subcommands.md、SKILL.md、CHANGELOG.md；acceptance 補三項（純搬移、位置鎖定改指新模組且 `_sleep`／`_clock` 不 re-export、文件同步）。原 acceptance 第 1 項的「17 項測試」為建票時的數字，執行時以實際收集數為準
