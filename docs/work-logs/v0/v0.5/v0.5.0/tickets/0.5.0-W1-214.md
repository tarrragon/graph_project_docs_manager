### 四項的取證、判準套用與查重（PM 89，2026-10-13）

判準出處：.claude/skills/framework-issue/references/escalation-flow.md〈介入判斷〉（抽象可攜性、資產範圍，兩條皆成立才屬框架問題）。查重：section_comment dedup 以六組關鍵字執行（Co-Authored-By、trailer、creation_accepted、Review Status、who.history、tdd_phase），rc 為 0；另以關鍵字比對 .claude/error-patterns 既有條目。

**第一項：提交訊息的歸屬資訊格式不一致**

取證：最近 600 筆提交中，非票務、非合併的工作提交 56 筆——兩行相鄰 29、兩行之間有空行 3（即票面所指）、只有 Co-Authored-By 6、兩行皆無 18。票務 CLI 程式碼內無任何處理這兩行的位置；它們由代理人依 harness 的歸屬指示自行寫入訊息。

| 判準 | 結果 |
|------|------|
| 抽象可攜性 | 是 |
| 資產範圍 | 否：來源是 harness 的歸屬指示與代理人的排版，.claude/ 內沒有產生這兩行的範本或工具 |

結論：不屬框架問題。查重無相關 issue。本專案的 CLAUDE.md 與規則未對這兩行設要求。落地：無需建 ticket——兩條判準不同時成立，專案亦無對應要求，依捕獲時分流屬「兩者皆非不記錄」；現象與計數保留於本節，已另向用戶回報供其決定是否要設要求。

**第二項：票面後設資料在狀態轉換後停在預設值**

取證（v0.5.0 共 313 張，已完成 190 張）：creation_accepted 於 313 張全為 false，已完成的 190 張亦全為 false；who.history 於已完成的 190 張全為空；Completion Info 的 Review Status 為 pending 147、reviewed 43；tdd_phase 於今日結案的 0.5.0-W1-164.3 仍為 phase1；同票 Completion Info 的 Executing Agent 仍為改派前的代理人（set-who 未同步）。另：creation-acceptance-gate-hook 於 claim 前檢查 creation_accepted，track_acceptance 內有將其設為 true 的指令，但全部票皆為 false 而 claim 照常成功。

| 判準 | 結果 |
|------|------|
| 抽象可攜性 | 是：為票務 CLI 與其 hook 的行為 |
| 資產範圍 | 是：.claude/skills/ticket 與其 hooks |

結論：屬框架問題。查重：creation_accepted、who.history 零命中；tdd_phase 命中 #55（ticket CLI 契約缺口叢集），關係為引用（同一 CLI 的狀態欄位未隨命令更新），非重複。落地：建子票做根因分析（各欄位的寫入端與消費端是否接上），觀測於該票結論後附加至 #55。

**第三項：以樹雜湊相同沿用隔離樹的測試結果時，漏列未入版控的輸入**

| 判準 | 結果 |
|------|------|
| 抽象可攜性 | 是：任何以內容相同為由沿用另一工作樹測試結果的情境皆適用 |
| 資產範圍 | 否：為 PM 的論證形態，非 .claude/ 資產的缺陷；現有規則未提供此沿用路徑 |

結論：不屬框架 issue；屬跨專案可重現的結構性錯誤。既有 error-pattern 無對應條目。落地：建子票記錄為 error-pattern。

**第四項：三種記錄錯誤形態**

| 形態 | 既有條目比對 |
|------|-------------|
| 豁免理由引用一張範圍不涵蓋該項的票 | 與 ARCH-BAL-005（豁免理由無消費者）同家族：理由寫錯無任何管道發現；候選為補案例而非新條目 |
| 接手續作只處理票面多組範圍補充的最後一組而宣稱無遺留 | PC-BAL-019 處理的是交接指標未寫入讀取端，結構不同；候選為新條目 |
| 票在產出合併前即被標為完成 | PC-BAL-002 處理的是檔案合併遺漏子功能，結構不同；候選為新條目，須先比對 worktree 交付相關條目 |

兩條判準：三者皆可攜；資產範圍皆否（為記錄行為的形態）。結論：不屬框架 issue；屬 error-pattern 層。落地：建子票，由撰寫者取得原稽核報告後逐一比對既有條目，新增或補案例。
