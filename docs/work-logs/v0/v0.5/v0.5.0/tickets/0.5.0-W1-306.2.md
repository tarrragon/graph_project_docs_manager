## Problem Analysis
<!-- Schema[IMP/Problem Analysis]: 選填（小型 IMP 可留 placeholder；大型 IMP 建議填寫）（.claude/pm-rules/ticket-body-schema.md） -->
PM 派發前查證（2026-10-15）：.claude/lib/hook_io.py 已有 emit_hook_output（26 支 hook 使用，組合 generate_hook_output 並負責 audience=pm_only 的受眾過濾單點，ARCH-V1-001／ARCH-020）。另立平行的 emit_model_reminder 會出現第二個輸出入口與第二份過濾邏輯。實作前先確認 emit_hook_output／generate_hook_output 對 306 對照表六個事件（UserPromptSubmit、SessionStart、PreToolUse、PostToolUse、PostToolUseFailure、Stop）是否都產出模型可見的形狀：若已涵蓋，本票收斂為補齊缺口與六事件形狀測試，遷移票直接改用 emit_hook_output；若要新增 emit_model_reminder，只能是委派給 emit_hook_output 的薄包裝，不得複製受眾過濾。Stop 事件的 additionalContext 會讓模型續跑，helper 的說明文件必須寫明這一點。

## Solution
<!-- Schema[IMP/Solution]: 選填（.claude/pm-rules/ticket-body-schema.md） -->
判定：emit_hook_output／generate_hook_output 對六事件（UserPromptSubmit、SessionStart、PreToolUse、PostToolUse、PostToolUseFailure、Stop）皆已輸出 hookSpecificOutput.additionalContext JSON，對照 306 表一，六事件 additionalContext 皆模型可見，形狀無缺口；缺口僅為(a)無事件名驗證(b)無六事件形狀測試(c)Stop 續跑語意未寫入說明。
做法：hook_io.py 新增 MODEL_REMINDER_EVENTS 與 emit_model_reminder(event, text, *, audience, input_data)，僅驗證事件名後委派 emit_hook_output（受眾過濾不複製，ARCH-020）；emit_hook_output 簽名行為未動。docstring 寫明 Stop additionalContext 會讓模型續跑。__init__.py 匯出。新增 .claude/hooks/tests/test_emit_model_reminder.py。
Acceptance 對應：AC1 emit_model_reminder 完成；AC2 輸出恆為 JSON，對照測試涵蓋；AC3 六事件形狀測試完成。無需改寫 acceptance。commit 389b16bd7。

### 自檢結果
- 簽名未改、既有 hook 呼叫面不受影響（audience 測試 23 通過）
- Python 3.9 相容（沿用字串型別註解）
- 框架檔無 ticket ID 引用（rule8 守衛曾攔截，已移除）

### Phase 4 評估
重構需要：否；技術債務：無；程式碼品質：A；結論：薄包裝無需重構。遷移票可用 emit_model_reminder 或 emit_hook_output。
