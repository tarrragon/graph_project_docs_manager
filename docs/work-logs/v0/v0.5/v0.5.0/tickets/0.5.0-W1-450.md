## Solution
<!-- Schema[ANA/Solution]: 必填（.claude/pm-rules/ticket-body-schema.md） -->
### 結論

- 直接原因：PATH 上的 `flutter` 是 fvm global 預設的 3.38.10，專案 `.fvmrc` 釘選 3.47.1。未經 fvm 執行的 gen-l10n 產出沒有那個空行；入庫版在 114.18（dd0703a94）時變成 3.38.10 的產出，之後每個用 `fvm flutter` 跑測試的 worktree 都會把它改回 3.47.1 的產出，於是出現漂移。原先懷疑的 dart format 經實驗排除。
- 現況：114.12（4785aa10e）已以 3.47.1 重新生成，HEAD 與釘選版本產出一致，**本票不需要改 l10n 檔**。
- 根本問題比 l10n 大：未經 fvm 的 flutter test／analyze／build 都跑在錯的 SDK 上，綠燈不代表釘選版本可用。修法由 0.5.0-W1-450.1 落地：Bash 守衛在 `.fvmrc` 存在時擋下未經 fvm 的 flutter／dart。此修法屬框架層，歸屬交主控裁定。
- 另一個做法 `fvm global 3.47.1` 只改本機預設，會影響本機其他 Flutter 專案，屬用戶裁決，不在本票範圍。
