parallel-dispatch-verification 的票號擷取支援子任務後綴，並把 where.files 的比對基準由未提交變更改為該票實際提交範圍

## Problem Analysis
<!-- Schema[IMP/Problem Analysis]: 選填（小型 IMP 可留 placeholder；大型 IMP 建議填寫）（.claude/pm-rules/ticket-body-schema.md） -->
bb 指定（2026-10-14）：裁決 B 下 complete 時變更已在 commit 內，比對基準改為「本票相關 commit 範圍」（帶票號的 commit，或含這些 commit 的 merge commit diff），不用 git diff HEAD。須附正反對照：where.files 已改到時不警告、真的漏改時才警告並列出該檔，同一 git fixture、修正前為紅。

### 問題根因
(1) extract_ticket_id 正規式 `\d+-W\d+-\d+` 無子任務後綴，且命令無命中時退回從 stdout 任意擷取。(2) 比對基準 `git diff HEAD` 只含未提交變更；裁決 B 時序下 complete 在合併提交後執行，working tree 乾淨，where.files 恆被判缺失。兩者原被成功判定死路徑遮蔽。

### 比對基準選定
候選：(a) 訊息含票號的 commit 範圍；(b) 合併提交的 diff；(c) 僅非隔離派發時比對。選定 (a)+(b) 合併實作加上 git diff HEAD 聯集：
- git log --fixed-strings --grep=<票號> 取候選，再以 `票號(?!\.?\d)` 過濾，父票不吃子任務票的 commit。
- 每個命中 commit 用 diff-tree -m --first-parent 取檔案：一般 commit 得其變更，帶票號的 merge commit 得合併帶入的變更，兩者統一處理。
- 聯集 git diff HEAD：程式碼未提交即 complete 時仍可比對（覆蓋表該列）。
- 不選 (c)：停用比對等於放棄檢測；票號是 complete 時唯一與該票綁定的穩定識別（框架 commit 慣例皆帶票號）。
- 已知限制：commit 訊息未帶票號的變更會被判缺失（警告內文已註明）。
票號解析沿用 lib.ticket_command_parse.complete_statement_args + lib.ticket_id_pattern.SEARCH_WITH_SUFFIX_RE，只取完成類語句動詞後的 token，不再讀 stdout。
## Solution
<!-- Schema[IMP/Solution]: 選填（.claude/pm-rules/ticket-body-schema.md） -->
修改 parallel-dispatch-verification-hook.py：extract_ticket_id 改用完成類語句 token 解析（含多層後綴、不讀 stdout）；get_git_changed_files 改為「票相關 commit 範圍（含 merge first-parent）聯集 git diff HEAD」，簽名增 ticket_id；警告文字同步。測試檔新增真實 git fixture（base/父票/子任務票/merge）與正反對照。

- Python 3.9 相容：未用 PEP 604/match；沿用既有 list[str] 註記風格。
