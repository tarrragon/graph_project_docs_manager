# Execution Log

## Task Summary

以 isolation: worktree 派發的代理人，第一輪無變更即停手回報；PM 以 SendMessage 恢復它後，它在共用 main checkout 執行 git mv 與修改並暫存到共用 index，commit 才被 branch-verify 守衛擋下。待查：成因是否為第一輪無變更導致 worktree 自動清除、恢復後 cwd 落回主 repo；派發規則（agent-failure-sop、parallel-dispatch 的 SendMessage 恢復路徑）是否需要加註或改為重新派發；寫入前（git add／git mv）能否偵測

## Problem Analysis
<!-- Schema[ANA/Problem Analysis]: 必填（.claude/pm-rules/ticket-body-schema.md） -->
### 最小重現（PM 執行，2026-10-08）

結論：成因已確認。以 isolation: worktree 派發的代理人若第一輪沒有任何變更，它的 worktree 與分支會在 task-notification（完成通知）送達時被自動清除；之後以 SendMessage 恢復它，代理人的工作目錄就落回主 repo 的 main。

| 時點 | 觀測 |
|------|------|
| 第一輪派發（只讀，不改任何檔案） | pwd 與 show-toplevel 皆為 .claude/worktrees/agent-<id>，分支為 worktree-agent-<id> |
| 交回報告後、完成通知前（13:30:05） | worktree 目錄存在，git worktree list 列出且為 locked，分支存在 |
| 完成通知送達後（13:30:34） | 目錄不存在，git worktree list 未列出，分支已刪除 |
| 以 SendMessage 恢復的第二輪 | pwd 與 show-toplevel 為主 repo 根目錄，branch 為 main |

輔助觀測：
- 這次無變更代理人的完成通知沒有附 worktree 欄位；有 commit 的代理人（0.5.0-W1-108、W1-109）的完成通知都附了 worktreePath 與 worktreeBranch。這個欄位可以當作「恢復後是否仍在隔離環境」的判斷訊號
- 對照組：0.5.0-W1-108 的代理人第一輪已 commit，worktree 保留，恢復後仍在原 worktree（rev-parse 已驗證）

風險面：恢復後代理人收到的仍是原本的 prompt 脈絡，它以為自己在隔離環境，寫入卻直接進入共用 working tree 與共用 index。branch-verify 守衛只在 commit 時攔下；在那之前的 git mv／git add／編輯都已經生效。0.5.0-W1-105.1 即為此案例。

PM 立即採行的作法（在本票落地防護之前）：恢復代理人之前，先確認上一輪的完成通知是否帶 worktree 欄位，或以 git worktree list 確認該 agent 的 worktree 還在；不在就重新派發，不恢復。

### 2. 防護選項（acceptance 3 前半）

| # | 選項 | 強制點 | 攔得到什麼 | 成本 | 誤報風險 |
|---|------|-------|-----------|------|---------|
| A | 恢復前檢查 worktree：看上一輪完成通知是否帶 worktreePath，或以 worktree list 比對 agent id | PM 自律（統一判準段落＋各恢復段落一行路由） | 所有恢復路徑（續用、審查退回、NeedsContext 補料、超時催促） | 低 | 無誤報；漏報＝PM 未執行（自律層） |
| B | 上一輪無變更即重派、不恢復 | PM 自律 | A 的主要成因情境，不需判讀通知欄位 | 最低；重派失去前一輪對話脈絡（需先寫回 ticket） | worktree 其實仍在時也改重派（保守、無害） |
| C | 子代理人寫入守衛 hook：PreToolUse（Edit/Write 與 Bash 的 add/mv/rm/commit），subagent 環境且該派發記錄 isolation=worktree，而 show-toplevel 等於主 repo 根 → 警告或 deny | hook（機械，代理人側） | 寫入前攔下，涵蓋所有恢復路徑與未知路徑；補上 branch-verify-hook 對 .claude/、docs/ 的豁免與 Bash 守衛只擋 commit 不擋 add/mv 的缺口 | 中：需從 agent_id 對回 isolation（active-dispatch-tracker-hook 已記錄 isolation），但 #89 指出 SubagentStop 在 idle 時即清空 dispatch-active.json，恢復時記錄可能已不在，需另存持久映射 | 中：非 isolation 派發的子代理人在 main 寫入屬合法；映射缺失時須 fail-open＋警告，否則誤擋 |

建議組合：A（必要時加 B）合併為一段統一判準作自律層；C 或 D 擇一作強制層（C 覆蓋面較大，D 時點較早；兩者共同依賴 agent→isolation 映射持久化，與 #89 同根）。
