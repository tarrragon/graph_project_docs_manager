## Problem Analysis
### 問題根因

三個 hook 各自判定「什麼算一次測試執行」，判定方式互不相同：

| Hook | 職責 | 判定 | 缺陷 |
|------|------|------|------|
| `pre-test-hook.py` | 測試前 Flutter 環境檢查 | 0.5.0-W1-232 已改為切 token 只認敘述開頭 | 不認得 pytest（本就不需要）；切分邏輯只有它自己一份 |
| `test-timeout-pre.py` | 寫入 `test-monitor.json` 開始時間 | 子字串 `"flutter test" in command` | grep／建票參數誤判；不認 pytest |
| `post-test-hook.py` | 逾時監控與失敗評估（讀開始時間） | `TEST_COMMAND_PATTERN` 對原始字串做 regex | 引號內 `\|` 被當敘述邊界（本 session 實測：grep 命令觸發「測試完成：0.3 分鐘」與一次假的 TEST FAILURE）；包裝腳本的 `--` 不是敘述邊界，`run-with-timeout.py N -- flutter test` 不被認得；不認 pytest |

E 線轉交（0.5.0-W1-187.15 完成後）：包裝腳本已定為唯一的逾時寫法（0.5.0-W1-187.6），兩項缺陷相加使「照規範執行的測試，監控全看不到」。

### 影響範圍

- 新增 `.claude/lib/test_command_parse.py` 與其測試：沿用 `lib/git_command_parse.parse_command_statements` 的切分（heredoc 剝離、換行正規化、引號語意已處理），不另寫 tokenizer
- 三個 hook 改用共用判定；pre-test 只取 flutter／dart，其餘兩者取全部執行器
- 寫入端與讀取端判定集合必須一致，否則時長落在上一次的開始時間

**修改檔案數超過 5 的依據**：適用認知負擔規則的跨進程同步修復豁免——開始時間寫入端（test-timeout-pre）與讀取端（post-test）分票修改會產生判定不一致的空窗；三個 hook 的改動各僅為判定函式替換。

### 設計決策與 RED 測試

完整設計、模組草稿、RED 測試與接線表：`docs/work-logs/v0/v0.5/v0.5.0/companions/0.5.0-W1-232.1-design.md`

**pytest 納入（驗收第 5 項）**：納入。理由：(1) 包裝腳本為唯一逾時寫法、框架自身測試全以 pytest 執行，不納入則監控全看不到；(2) post-test 成功輸出樣式已含 pytest 格式，失敗評估本就為 pytest 設計；(3) `cli-error-feedback-hook`／`cli-failure-help-reminder-hook` 的抑制清單宣稱 pytest 已由測試 hook 處理。pre-test-hook 不納入 pytest（其職責是 Flutter 環境檢查）。

### 相關 Error Pattern

查重 issue：#54（hook 判定邏輯的隱含前提未驗證：誤報）。

### 執行限制

## Solution
commit 184368fe3（6 檔）：新增 `.claude/lib/test_command_parse.py`（`find_test_invocations`，沿用 `git_command_parse.parse_command_statements` 切分，回傳每個測試呼叫的 runner），pre-test-hook（只取 flutter／dart）、test-timeout-pre 與 post-test-hook（全部 runner）改用之，移除 post-test 的 `TEST_COMMAND_PATTERN` 與 pre-test 自帶的切分函式。設計見 `docs/work-logs/v0/v0.5/v0.5.0/companions/0.5.0-W1-232.1-design.md`。

PM 覆核（2026-10-14）：
