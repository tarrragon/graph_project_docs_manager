## 重現實驗結果
### 實驗方法

以固定值查證（grep 呼叫序 + 讀程式）判定 `_GraphUnavailableBody`（lib/screens/domain_view/domain_view_screen.dart）渲染時 `builtinSchemaVersionProvider` 是否可能非 data；不跑 flutter 測試。

### 實驗執行

1. `builtinSchemaVersionProvider` 定義（lib/screens/domain_view/domain_view_schema_version.dart）：非 autoDispose 的 `FutureProvider<String>`；`grep -rn "invalidate(builtinSchemaVersionProvider\|refresh(builtinSchemaVersionProvider" lib` rc=1（無任何重載）→ 一旦為 data 即在 container 生命期內保持 data。
2. `_GraphUnavailableBody` 只在 `DomainReady` 下由 `domainGraphUnavailableProvider` 為真時渲染。`DomainReady` 唯一生產者為 `DomainViewLoader`（lib/app/domain_view_loader.dart）；loader 的入口（`grep -rn "domainViewLoaderProvider" lib`）：
   - gate 正常路徑：`GateDetectionNotifier.detect` 先 `await ref.read(builtinSchemaVersionProvider.future)` 再呼叫 `load`
   - 降級路徑：`_SchemaUnconsumableView` 的 `onDegradedView` 僅在 `canDegrade` 為真時提供，`canDegrade` 由 `builtinVersionAsync.maybeWhen(data: ..., orElse: () => false)` 決定 → 降級按鈕只在 provider 已為 data 時出現
   - `reload()`（`_LoadFailedView`）與 `cancelLoading()`：皆發生在先前一次 load 之後，即 provider 已為 data 之後
3. 資產載入失敗時 gate 的 await 拋錯，不會到達 `load`；降級出口因 `orElse: false` 不提供。
4. 測試面：`grep -rn "builtinSchemaVersionProvider" test integration_test` 全數以已完成的 Future override（如 domain_view_test.dart 的 `'0.0.1'`）；圖不可用測試（domain_view_test.dart group「圖不可用 state-domain-graph-unavailable」）斷言 `domainGraphUnavailableMessage('0.0.1')`，無任何測試覆蓋 `orElse` 分支。

### 實驗發現

- 已驗證：正式路徑上，所有到達 `_GraphUnavailableBody` 的路徑都以 provider 已為 data 為前提，`orElse: () => ''` 不可達。
- 已驗證：測試面亦無覆蓋該分支（override 皆為已完成值）。
- 未驗證假設：將來若 provider 改為 autoDispose、加入 invalidate，或新增不經 gate 的 loader 入口，此不變式會靜默失效，畫面會出現缺版本號的原因文字且無任何訊號。
