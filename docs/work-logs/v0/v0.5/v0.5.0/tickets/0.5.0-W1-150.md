## Problem Analysis
<!-- Schema[ANA/Problem Analysis]: 必填（.claude/pm-rules/ticket-body-schema.md） -->
### 問題根因

`append-log --replace` 的取代範圍是整個 H2 章節：保留標題行，其餘內容全部以新內容覆寫（`track_acceptance.py` 中 replace 分支）。`ticket track dispatch --note` 則把派發日誌寫在「## Problem Analysis」之下的「### 派發日誌」H3 子節（`track_dispatch._append_dispatch_note`）；同一 H2 下另有冪等覆寫的「### Commit 規範」子節（`_ensure_commit_section`）。兩者都是 CLI 管理的內容，但 --replace 不區分 CLI 管理的子節與人寫內容，對 Problem Analysis 執行 --replace 會連同這兩個子節一起取代。

### 影響範圍

- 已驗證：派發日誌（含 --note 的暫態約束）被取代後無任何訊號；--replace 印出的摘要截斷於 200 字元，而派發日誌附加在章節尾端，摘要通常看不到它（實驗輸出的摘要只到「### 相關 Error Pattern」）。
- 已驗證：「### Commit 規範」與派發日誌位於同一 H2，同樣會被取代。
- 未驗證：其他 H2 是否也有 CLI 管理的子節；目前只在 track_dispatch 找到這兩個。

### 相關 Error Pattern

與 #80（拒絕寫入仍宣告已更新）同屬寫入命令的副作用不可見，結構不同；無既有 error-pattern 直接對應。
