現象重新確認：以 HEAD（spec 1.9.7）實跑，層級 SPEC 且 id 為 SPEC-UI-101 時印「N 個 FR 未在系統層覆蓋」並指去系統層補歸屬，現象仍成立。

範圍外缺口（id 無法辨識且找不到 map 時，source_specs 無法解析的 map 不列名）：現況成立，只需在既有訊息處補上列名，故併入：該分支（reason 為 id_unrecognized）呼叫既有 warn_unparseable_maps，stderr 列名，不改 rc，不動其他路徑。補測試。
