## Solution
<!-- Schema[IMP/Solution]: 選填（.claude/pm-rules/ticket-body-schema.md） -->
新增 lib/ticket_command_parse.find_complete_invocations(command)：回傳 (動詞, 動詞後 token) 清單，解析失敗回 None。語句內任意位置的 ticket track <complete|finish|batch-complete> 皆辨識（ticket 可為絕對路徑），shell -c/eval 遞迴（深度上限 5），echo/printf 之後與 command -v 語句不辨識。重用 git_command_parse 的 _skip_wrappers/_nested_script/_SHELLS/_SCAN_OUTPUT_COMMANDS。既有三函式未改。
acceptance-gate：is_complete_command 改用共用函式，解析失敗仍走 _legacy_complete_substring（fail-closed，測試鎖定）；has_force_flag_on_complete 改用共用函式，仍先剝引號（否則 --why '--force' 與旗標同形，既有測試 e2 鎖定）。取捨：bash -c '... --force' 因剝引號不旁路，方向為維持 deny（安全側），測試記錄。
hook 例外行為不變：_resolve_force_bypass 的 try/except 仍 fail-closed，test_force_bypass_fail_closed_when_parser_raises 改為 patch find_complete_invocations。phase4 未動（由 .5.4 承接）。

### 自檢結果
- 範圍：僅改票列 4 檔，phase4 未動。
- 正向對照：timeout/ionice+caffeinate 包裝、&& ; | 串接、for/if 區塊、bash -c / sh -c / -lc / 兩層巢狀、絕對路徑 ticket；反向：echo、printf、command -v、引號內字面、claim/query。
- 解析失敗：未閉合引號（含巢狀）回 None，hook 走 legacy 字面後備。

### Phase 4 結論
重構需要：否。技術債務：無新增（掃描函式依賴 git_command_parse 私有符號，同 lib 內部，已註記）。程式碼品質：A。結論：無需重構。
