## Problem Analysis
<!-- Schema[IMP/Problem Analysis]: 選填（小型 IMP 可留 placeholder；大型 IMP 建議填寫）（.claude/pm-rules/ticket-body-schema.md） -->
### 處置裁定（PM，2026-10-14 21:4x）

採 (b)：保留警告，改寫措辭。

查證：
- `MAX_TICKET_DEPTH`（constants.py，SSOT）在 258.1 之後仍有作用，只是對象不同。
- `agent-ticket-validation-hook.py` 在**子代理人派發**時，以派發者持有票的 `holder_depth < MAX_TICKET_DEPTH` 判定 can_descend；持有票映射缺失時，退回「被派發票 depth > MAX_TICKET_DEPTH 才 deny」。
- 主線程派發不受票樹深度限制。

因此正確的語意是：深度達到上限的票，**子代理人持有時**不可再往下派發；**主線程派發不受影響**。

不選 (a)：完全移除後，代理人在建立深層子票時會失去預警，直到派發時才被 hook 擋下。
不選 (c)：門檻本身沒有錯，錯的是措辭把「子代理人派發」講成了「所有派發」。

新措辭須同時寫明「主線程派發不受影響」與「子代理人持有此票時不可再往下派發」。agent-ticket-validation-hook.py 第 253 行附近的 deny 訊息「不可再往下派發」屬子代理人情境，語意正確，不改。

文件同步：how 列出的 7 份 md 加上程式碼，超過 5 檔，依 how 拆 DOC 子票處理。
