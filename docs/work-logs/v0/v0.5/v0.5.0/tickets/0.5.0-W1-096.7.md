### WRAP 評估（2026-10-08）

範圍：NC-1（S2 檔 `docs/non-domain-paths.yaml` 格式錯誤：缺 key、值非 list、YAML 解析失敗）。NC-2 已由 PM 決定（擴及 lib/schema 兩檔；型別表缺兩欄時回落內建表值），不重評。

**事證**
- E1：`parseFailure` 已兩度以「新原因碼」擴充而不另立類別：`idMissing`／`idPatternMismatch`（0.3.1-W1-081）、flow 區塊解析失敗（1a／3b）。先例是「同類失敗擴原因碼」。
- E2：EVT-CORPUS-003 事實為「文件未進入圖譜」，負載以文件節點為中心（`nodeType`、`candidateTypes`、`salvagedFields`、`severity`），且只對「命中 carrier」的失敗檔發出；S2 不是 carrier、沒有 frontmatter 與型別，負載大半不適用。
- E3：CD1 先例——語意不同於 003 時另立事件（EVT-CORPUS-004）而非擴充 003。
- E4：SPEC-006 FR-08 破洞數＝命中 carrier 數＋flow 失敗 UC 數；任何進破洞報告的方案都要再加一項。
- E5：096.6 載體定義「壞檔不得當作缺席」是上游 validate 的判準；App 端五態目前只有宣告表 6 列，無「格式錯誤」列。
- E6：7a 已規定「未宣告」不進破洞報告，報告頁有專案層級宣告狀態行（只在有缺口時出現、列缺哪一側）。
- R（兩份語料）：本專案與 flutter_balance 目前皆無 S2 檔，實例 0 筆。

**(i) 對應哪種 Diagnostics 項目**

| 候選 | 作法 | 代價／風險 |
|---|---|---|
| I-a | 沿用 `parseFailure`＋新原因碼，經 EVT-CORPUS-003 承載 | 003 負載以文件節點為中心，多數欄位對 S2 無意義；003 只對 carrier 命中檔，語意要擴 |
| I-b | 沿用 `parseFailure`＋新原因碼，新增 EVT-CORPUS-005 承載（比照 CD1） | 多一個 EVT；FR-08 破洞數再加一項 |
| I-c | 新增破洞類別（如宣告檔錯誤） | 改 Diagnostics 列舉與報告頁分節；與 1a／idMissing「擴原因碼不立類別」先例不一致 |
| I-d | 不進破洞報告，只在報告頁宣告狀態行顯示「非 domain 清單格式錯誤」 | 最小改動；但錯誤只出現在一行說明，Diagnostics 無項目可導覽、不計入健康度 |
| I-e | 規格不定義 | 096.7 acceptance 2 無法照規格實作，pair-2 兩份各自選邊 |

**(ii) 五態中非 domain 側算什麼**

| 候選 | 作法 | 代價／風險 |
|---|---|---|
| II-a | 視為缺席：未命中路徑標「非 domain 未宣告」，錯誤另經 (i) 回報 | 不增狀態；「壞檔≠缺席」只在錯誤回報層成立，路徑標籤與真缺席同形 |
| II-b | 新增第六狀態（如「非 domain 宣告損壞」） | 宣告表、矩陣、票列表、i18n 都多一種；與 E1「不新增顯示狀態」的取向相反 |
| II-c | 視為已宣告空清單 `[]`：未命中路徑成「無法定位」 | 把宣告缺陷灌進 `unlocatable`（本專案假設對照中可達 70%），正是 P2+ 要消除的雜訊 |
| II-d | 規格不定義 | 同 I-e |

**傾向（暴露偏好）**：(i) I-b——延續兩個先例（擴原因碼、語意不同另立事件），且 Diagnostics 有可導覽的項目；若不願多一個 EVT，次選 I-d。(ii) II-a——路徑層不新增狀態，「壞檔≠缺席」由 (i) 的錯誤項目承擔，宣告狀態行可同時列出「格式錯誤」。

**盲點**：未查 Diagnostics 健康度計數是否需要區分此類；未查報告頁宣告狀態行能否容納錯誤字樣；未確認 `doc validate-paths` 對同一壞檔的訊息用語，App 端文案可能需對齊。
