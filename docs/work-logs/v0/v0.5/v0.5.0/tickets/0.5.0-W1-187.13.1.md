## Problem Analysis
### 問題根因

`test-timeout-pre.py` 把開始時間寫進每專案唯一的 `test-monitor.json`，`post-test-hook.py` 的 `check_test_timeout` 再從同一檔讀出並寫回 end_time／duration／status／history。兩支 hook 之間沒有鍵，並行時後到的 pre 會覆寫先到者。187.13 實測：並行 A/B 時 A 量到 3.4s（實際約 6.7s），history 兩筆都記成 B 的命令。

### 影響範圍

- 寫入端：`test-timeout-pre.py`（開始時間）
- 讀取與收尾端：`post-test-hook.py` 的 `check_test_timeout`（end_time、duration_seconds、status、action、history）、`_classify_duration`
- 243 已改：`post-test-hook.py` 的 `main()` 在 `tool_input.run_in_background is True` 時直接 return，不呼叫 `check_test_timeout`；欄位缺失或為 False 時視為前景。現有測試：`test_foreground_command_is_timed_and_evaluated`、`test_background_command_skips_timing_and_evaluation`、`test_background_false_treated_as_foreground`
- 243 留下的兩項（Phase 4 審查）：背景命令的 pre 仍會寫開始時間，post 又跳過收尾，所以監控檔停在 running；以及前景、背景交錯時前景的開始時間被覆寫。兩項都歸本票
- 目前 hooks 內只有 post-test-hook 讀這個檔，且不讀 status
- conflicts：194、252、256 也改到 post-test-hook.py 與其測試，三張都還是 pending，沒有人在做
