## Solution
<!-- Schema[IMP/Solution]: 選填（.claude/pm-rules/ticket-body-schema.md） -->
兩支 hook 在 main 讀完 stdin 後沿用 281.5 的接法：is_failure_event 為真時以 auto_commit_failure_as_success 正規化，回傳 None 即不處理（pdv 輸出 DEFAULT_OUTPUT，wmr 直接 return 0）；結束碼 75 時 hookEventName 輸出 PostToolUseFailure。
與 286.2 的關係：parallel-dispatch-verification 正規化後的 payload 仍走既有 is_ticket_complete_success，即 is_complete_transition_success 加 make_completed_verifier；未另寫成功判定，票面未 completed 時不觸發（測試覆蓋）。worktree-merge-reminder 原本就無成功判定，僅以命令辨識觸發。
registry 的 PostToolUseFailure:Bash 群組新增兩支。
修改檔：parallel-dispatch-verification-hook.py、worktree-merge-reminder-hook.py、hook-dispatch-registry.json、新增 test_pdv_wmr_exit75_failure_event.py。

### 自檢結果
- 結束碼 75 觸發、結束碼 1 不處理、error 格式不符與 stdin 非 JSON 為 no-op（fail-open）：已測。
- 正向對照：移除兩支 hook 的改動後新測試 7 項紅（含 exit75 樣本不觸發）；還原後全綠。
- 驗收第 3、4 條（實地觸發、liveness）未做，由 PM 合併後執行。
