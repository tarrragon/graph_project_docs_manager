## Problem Analysis
<!-- Schema[IMP/Problem Analysis]: 選填（小型 IMP 可留 placeholder；大型 IMP 建議填寫）（.claude/pm-rules/ticket-body-schema.md） -->
### WRAP 評估（快速+，e1，2026-10-09）：兩個以上 bundle 等長命中同一路徑時的歸屬

缺口來源：4a 審查 096.5 回報。執行者目前取 Map 迭代序第一個，結果依插入順序，屬隱性規則。

事證（R）：
- 等長且同時命中同一路徑的兩個值必為同一字串：路徑長度 n 的前綴唯一；不以 `/` 結尾的值為精確比對，與等長目錄前綴不會同時命中同一路徑。本題即「同一字串出現在兩個以上 bundle」
- 上游 `tracking_schema.py` path_patterns 註解：同一字串不得出現於兩個以上 bundle（含同 bundle 內重複），`find_path_pattern_problems` 會把跨 bundle 重複同時回報給所有涉及的 bundle；但未定義消費端歸屬
- 相近先例：T1（同字串在 bundle 與非 domain 清單→歸 domain，衝突交 doc validate）；D-3（兩個 DomainBundle 宣告同一 domain 名→兩者都不進名稱索引、另報缺陷）；UC-02 6a（一票多路徑逐路徑判定、矩陣高亮取聯集）
- 本專案語料（096.4 後）0 筆重複

| 候選 | 規則 | 致命風險 |
|---|---|---|
| X1 | 歸全部宣告它的 bundle（多 domain），矩陣高亮取聯集；衝突交 doc validate | 一條路徑屬兩個 domain，與「最長前綴決定唯一歸屬」的語意不同；下游若假設單一歸屬需處理清單 |
| X2 | 依 domain code point 序取第一個 | 決定性但任意，使用者看不出另一個 bundle 也宣告了 |
| X3 | 視為無法定位，衝突交 doc validate | 把宣告衝突混進「沒宣告到」，與 T1 時用戶否決的 T3 同形 |
| X4 | 比照 D-3：涉及的 bundle 該值全部失效，路徑依其餘宣告判定 | 規則較複雜；路徑可能落到較短前綴的其他 bundle，結果出人意料 |

傾向 X1，信心中：不丟資訊、不引入任意序，與 6a 的聯集高亮同一呈現；X2 是本來要消除的隱性規則換成另一種隱性規則。盲點：未查 W1-119 宣告狀態行的「受影響路徑數」對多歸屬路徑如何計數（應仍計 1 條路徑）。

用戶裁決（2026-10-09）：X1，同一字串出現在兩個以上 bundle 時路徑歸全部、高亮聯集、受影響路徑數計 1；衝突交 doc validate。PM 處置（同日，直接推論）：零個 DomainBundle 時 domain 側視為未宣告（防空真）；兩側皆無宣告時票列表摘要為「不判定」。皆寫入 UC-02 v1.11 並各附一條驗收。
