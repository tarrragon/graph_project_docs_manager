## Solution
<!-- Schema[IMP/Solution]: 選填（.claude/pm-rules/ticket-body-schema.md） -->
`track_query.py` 新增兩個函式：
- `_load_ticket_cross_version`：以 `extract_version_from_ticket_id` 推導版本，載入不到再退回 fallback 版本。
- `_with_cross_version_children`：從 children 欄位補上不在清單內的跨版本子票；載入不到者以 status=not_found 佔位，顯示為 (not_found)。

`execute_tree` 與 `execute_chain` 改用 children 補載，`_collect_spawned_tree` 改用跨版本載入。同版本樹輸出逐字不變。ticket skill 2.44.43。commit 6faf77a6f，合併 9174c2f87。

### 自檢結果

- RED：新增 6 個測試，修改前 5 failed、1 passed（唯一綠的是同版本樹輸出不變的對照）。GREEN：6 passed。
- E1：tree 與 spawned 測試各在同一批 fixture 內做有／無舊版本子票的對照，斷言輸出不同。E2：不存在的 ID 標 not_found，循環防護保留。
- CLI 同步：SKILL.md 與 pm-rules 無此輸出細節的描述，CHANGELOG 記錄檢查結論。規則 8：fixture ID 以常數拼接，新增行 0 命中。
- 實地觸發：在 `git clone --no-hardlinks` 的 clone 內，讓 0.5.0 的一張 ANA 的 children 指向 0.4.2 已完成的 IMP 與一個不存在的 ID，執行 `ticket track tree`。修正前兩張子票皆不顯示；修正後前者顯示「已完成」，後者標 (not_found)。
