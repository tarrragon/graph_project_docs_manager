### error-pattern 候選（主控 2026-10-19）

候選模式：守衛以產生過程的中間狀態（此處 MERGE_HEAD）判定行為類別，另一條產生相同最終產物的路徑（merge-tree + commit-tree）不留該中間狀態，守衛對其失效；且因既有使用全落在豁免範圍，失效長期不可見。收尾時判定是否跨專案可重現（替換工具名後仍成立），成立則依 quality-baseline 規則 6 `/error-pattern add`，先查重 `.claude/error-patterns/`
### Context Bundle（-3e 讀碼，2026-10-19 15:50）

`.claude/hooks/git-ref-transaction-content-guard.py` 的 `main()`：

1. `new_commits = _collect_new_commits_with_parents(new_oids, project_root)`，即 `rev-list --parents <new> --not --all`。CAS 合併時，分支上的 commit 已能從 `refs/heads/worktree-agent-*` 走到，會被排除，所以新 commit 只有那一個雙 parent 合併 commit。該函式已取得每個 commit 的 parents
2. `is_merge = _merge_in_progress(project_root)` 是**整個 transaction 共用的單一布林值**，只看 MERGE_HEAD，並對每個 commit 傳入 `_run_all_checks(..., is_merge_commit=is_merge)`

**修法要點**：

- `is_merge_commit` 改為逐 commit 判定：該 commit 的 parent 數大於 1。這個資訊已在 `_collect_new_commits_with_parents` 的回傳值裡
- `_merge_in_progress` 不刪。deny 分支中「MERGE_HEAD 已寫入但不會隨本次 deny 自動撤銷」的提示仍依它判斷
- `ENV_PREVALIDATE_ONLY` 分支的 `not is_merge` 條件要一併檢查語意，判定改依據後是否需要調整

**對 tarrragon/claude#101 待裁項的影響**：該項是「MERGE_HEAD 存在時，以單 parent 提交寫入保護分支的非豁免路徑被放行」。改為依 parent 數判定後，這種提交就不再被豁免，兩個方向一起收斂。真正的 `git merge`（有 MERGE_HEAD、雙 parent）維持豁免。`git merge --squash`（無 MERGE_HEAD、單 parent）維持被擋，行為與修前相同

**對照組（E1／E2）**：

| 情境 | 修前 | 修後 |
|------|------|------|
| CAS 雙 parent、無 MERGE_HEAD、含非豁免檔 | 擋 | 放 |
| 單 parent 直接提交非豁免檔 | 擋 | 擋 |
| MERGE_HEAD 存在、單 parent、含非豁免檔（#101） | 放 | 擋 |
| 一般 `git merge` 雙 parent、有 MERGE_HEAD | 放 | 放 |
2026-10-15 兩筆中止查證（worktree-merge.log）：agent-ab6827023014bc1fd（20:33:57，commit cfb0ba52470f）與 e-batch-hooks1（22:15:13，commit 9238cea6802f）。兩筆中止前各套件皆綠燈或沿用，日誌無 guard 阻擋訊息；兩分支改動為 .claude/hooks 等 .claude/ 豁免路徑，branch-verify 不會對其 deny，故判定與本票（非豁免路徑 + 無 MERGE_HEAD）不同因。ab68 同時段另有 a7e360 與 a2d756 並行閘門，e-batch 結束時間與 aebc6a 同秒，較像並行閘門互斥或舊 commit 被後續重試取代，非本守衛；日誌不足以確證，不在本票範圍。
## Solution
<!-- Schema[IMP/Solution]: 選填（.claude/pm-rules/ticket-body-schema.md） -->
改 .claude/hooks/git-ref-transaction-content-guard.py：新增 _collect_parent_counts（rev-list --parents），is_merge_commit 改逐 commit 依 parent 數大於 1 判定，不再用整筆 transaction 共用的 MERGE_HEAD 布林。_merge_in_progress 保留為 merge_head_present，僅用於 deny 的殘局提示與 ENV_PREVALIDATE_ONLY 的 PREVALIDATE_CLEAN 條件（語意不變：MERGE_HEAD 存在時不輸出 token；CAS 路徑無 MERGE_HEAD 故行為同修前）。日誌每個新 commit 記 parents、is_merge、merge_head_present；取不到 parent 數時視為非合併（不給豁免）。對 tarrragon/claude#101 待裁項：MERGE_HEAD 存在的單 parent 提交不再被豁免，改為被擋（測試第 3 列），與真 git merge（雙 parent）仍放行並存，兩方向由同一判定點收斂；#101 該待裁項可視為已有實作方案，裁決權仍在主控。
