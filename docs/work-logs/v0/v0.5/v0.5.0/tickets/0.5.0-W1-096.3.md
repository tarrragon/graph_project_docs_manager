### WRAP 評估（2026-10-08）

對象：NeedsContext 5～7（本票 1～3）。事證：270 張 where.files 含 lib 的票（腳本以 W1-096 盤點的前綴對照、degraded_schema／scan_notifier 歸非 domain、補尾斜線）；兩份語料的宣告現況。未選定。

#### 5. 只有部分 DomainBundle 宣告 path_patterns

現況：本專案 0/8 宣告（096.4 待做，History 將明確宣告 `[]`）；flutter_balance 0/1。部分宣告只會出現在補宣告的過渡期。096.2 已區分「欄位缺席」與「`[]`」。

| 候選 | 作法 | 代價 |
|---|---|---|
| 5a | 只要有任一 bundle 宣告即視為 domain 側已宣告；未命中路徑照 096.1 裁決落「非 domain 未宣告」或無法定位 | 未宣告 bundle 的檔案會被誤歸 |
| 5b | 全部 bundle 宣告（含 `[]`）才算 domain 側已宣告，否則 domain 側整體「未宣告」 | 過渡期什麼都看不到 |
| 5c | 逐 bundle：已宣告者照常比對；仍有 bundle 缺席時，未命中路徑標「domain 未宣告」（可能屬缺席的 bundle） | 規則多一層；最貼近 P2+「未宣告不等於無法定位」 |
| 5d | 規格不定義 | 096.7 自選 |

傾向 5c。

#### 6. 一張票的 where.files 落在不同狀態

實測 270 張：僅非 domain 179、僅 domain 67、domain＋非 domain 17（6.3%）、僅無法定位 7；含無法定位的混合 0 張；跨兩個以上 domain 9 張。

| 候選 | 作法 |
|---|---|
| 6a | 不做整票歸類，逐路徑顯示（UC-02 現行寫法）；矩陣高亮取命中的 domain 聯集 |
| 6b | 整票取「最需要注意」的狀態（無法定位 > 未宣告 > domain > 非 domain） |
| 6c | 整票取 domain 命中優先（有任一命中即可定位） |
| 6d | 規格不定義 |

事證：混合主要是 domain＋非 domain（17 張），且非 domain 本身不是問題；含無法定位的混合為 0。傾向 6a（必要時以 6c 作為票列表的摘要欄）。

#### 7. 「domain 未宣告」「非 domain 未宣告」是否進破洞報告

現行破洞類別：parseFailure／graphDefect／traceGap／unlocatable。

| 候選 | 作法 | 代價 |
|---|---|---|
| 7a | 不進破洞報告；只在矩陣／票列表以狀態標示，並在報告頁顯示專案層級的宣告狀態一行 | 需定義那一行的位置 |
| 7b | 進破洞報告，新類別 | 補宣告前會冒出大量逐票項目，正是 P2+ 要避免的雜訊 |
| 7c | 只在「部分宣告」時進報告（提醒補完） | 規則依 5 的裁決而定 |
| 7d | 規格不定義 | — |

傾向 7a。

盲點：270 張的分類用的是 W1-096 的假設對照，非實際宣告；未查破洞報告頁現有版面是否有專案層級欄位。
可合併：5 與 7 互相牽動（7c 依 5），建議同批裁決；6 獨立。

### 用戶裁決（2026-10-08）

- 題 6：6a，不做整票歸類，逐路徑顯示；矩陣高亮取各路徑命中 domain 的聯集；票列表若需摘要欄，以「任一路徑命中 domain 即可定位」為規則。
- 題 7：7a，兩種未宣告不進破洞報告；矩陣與票列表照常標狀態，報告頁加一行專案層級宣告狀態。
