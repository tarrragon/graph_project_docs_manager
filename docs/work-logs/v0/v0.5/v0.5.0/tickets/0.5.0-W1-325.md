## Solution
<!-- Schema[IMP/Solution]: 選填（.claude/pm-rules/ticket-body-schema.md） -->
實測依據：以 claude -p 在專案外目錄註冊 PostToolUse(Edit|Write|MultiEdit) dump hook。Write 與 Edit 的 payload 皆含 tool_name 與 tool_input.file_path（絕對路徑），hook 環境內 CLAUDE_FILE_PATH 計數為 0（未設定）。本 runtime 無 MultiEdit 工具（模型回報不存在），MultiEdit 無從實測；settings 本就只註冊 Edit、Write 兩個 matcher，hook 對任何含 tool_input.file_path 的 payload 一視同仁，若 MultiEdit 日後存在且同欄位即自動涵蓋。

改法：dart-style-guardian-hook.py 以 read_json_from_stdin 讀 payload，新增 extract_file_paths 取 tool_input.file_path；缺欄位、型別錯、空字串、空 stdin 皆輸出 {"continue": true} 並 logger.info 後 return 0（fail-open）。移除 argv 讀取與逗號切分；docstring 的過期註冊範例改為現況。settings.json 僅移除兩處命令尾端的 CLAUDE_FILE_PATH。306.7 的 additionalContext 輸出未動。

實地觸發方式（PM 合併後）：在主 checkout 對 lib/presentation 下 dart 檔 Edit 加入 TextButton(...) 一行，確認 .claude/hook-logs/dart-style-guardian-hook/ 當日日誌不再出現 No files to check、且回合內收到 NativeComponent 提醒；再 Edit 一個 lib/domain 下檔案確認無提醒。

- E1（presentation dart 違規觸發，Edit 與 Write 兩種 payload）／E2（txt、.g.dart、.freezed.dart、/test/ 目錄、非 presentation 不輸出）／缺路徑五種變體與空 stdin fail-open／argv 被忽略：皆有測試
- grep CLAUDE_FILE_PATH 與 dart-style-guardian：其餘命中（hook_command_resolver、test_migrate_settings_hooks、required-features-config）為通用機制或註冊檢查，不依賴此 hook 的 argv，未動
- 未做：以真實 uv subprocess 端到端跑一次（沙箱命令限制），由 PM 實地觸發補
