## Solution

重驗：票面 (a)(b) 兩現象在目前 main 皆仍成立（定位函式第三回傳值僅用於找不到任何 map 的訊息；layer_banner 固定寫「無任何 map 列入本 SPEC」），無需標註已不成立。

處置（commit 3cc326956）：
- 路徑 (a)：有 map 被定位到（含 spec 同目錄、列入本 SPEC、舊版 docs/domain-map.md 後備）時，於 stderr 逐檔輸出「WARNING: domain map 的 source_specs 格式無法解析，未納入本次判定，其歸屬可能含本 SPEC：<路徑>」。
- 路徑 (b)：層級模式橫幅在有無法解析的 map 時改為「無可解析的 map 列入本 SPEC（另有 map 的 source_specs 格式無法解析，見 stderr）」，並同樣輸出上列 WARNING；無此類 map 時橫幅逐字不變。
- 找不到任何 map 的路徑維持原 stdout 訊息，不重複輸出。
- 無關 map 的處理：格式無法解析即讀不出它是否列了本 SPEC，故一律列出（寧多勿漏；誤報成本是一行 stderr，漏報成本是使用者去查錯地方）。測試 test_unrelated_unparseable_map_is_listed_too 固定此行為。
- 不改 exit code、層級判定、FR 抽取、宣告讀取、矛盾比對。SKILL.md/CHANGELOG 同步為 1.9.7，未寫票號。
- 範圍外觀察：spec id 無法辨識（REASON_ID_UNRECOGNIZED）且找不到 map 時，無法解析的 map 仍不列名；不屬本票兩條路徑，未處理。
