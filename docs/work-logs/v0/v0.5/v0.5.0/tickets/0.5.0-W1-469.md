## Problem Analysis
<!-- Schema[ANA/Problem Analysis]: 必填（.claude/pm-rules/ticket-body-schema.md） -->
### 問題根因

`.claude/skills/ticket/ticket_system/commands/track_acceptance.py` 的 resolve-spawn-request：`spawned_values = args.spawned_ticket or []` 取得值之後，`--status processed` 時逐項 append 進 `spawned_tickets`，只做去重，沒有 ticket ID 格式驗證，也不確認目標票存在。

**實例**：研究線 session 以 `$(...)` 取得新票 ID 後傳入 `--spawned-ticket`。ticket create 失敗時變數為空，CLI 照樣回 `[OK]`，0.5.0-W1-466.1 的 spawned_tickets 因此多了一筆 `''`。主控已用 `ticket track remove-spawned 0.5.0-W1-466.1 ''` 清除，目前只剩 0.5.0-W1-468。

**後果**：空字串或格式錯誤的值進入血緣欄位。下游消費者（acceptance-gate 的 spawn 落地計數、stuck-anas、孤兒偵測）會把它算成一張「已落地」的票，或在解析時出錯。

### 兩條判準（escalation-flow.md）

1. **抽象可攜**：把專案描述換掉後仍成立：「寫入血緣欄位的 CLI 不驗證值的格式，呼叫端的空變數會被當成合法 ID 寫入」。任何 consumer 只要以命令替換串接 create 與 resolve 都會撞上。成立。
2. **根源在 `.claude/` 通用資產**：缺陷在 ticket skill 的 CLI 程式碼，沒有專案設定參與。成立。

### 處置

- 依框架修補節奏（2026-10-20 用戶裁示），本項不是 P0／P1：殘留可以用 remove-spawned 清除，而且沒有阻擋專案工作。所以不派修，只觀測進 issue。
- 查重：dedup 關鍵字為 resolve-spawn-request、spawned_tickets 空字串、ticket ID 格式驗證。#102「spawned_tickets 血緣只進不出：誤登無撤銷路徑、寫入前無驗證⋯」是同一個缺口（寫入前無驗證），本項是 resolve-spawn-request 入口的新實例，關係判定為「重複（新實例）」，observe 到 #102。
- 修法方向：resolve-spawn-request 與 add-spawned 共用 ticket ID 格式驗證，空字串與不存在的票直接以非 0 結束；呼叫端的命令替換若得到空值，CLI 會拒絕而不是回 [OK]。

### 相關 Error Pattern

`.claude/rules/core/bash-tool-usage-rules.md` 規則二 Action 第 0 項：寫入類 CLI 讀 exit code 判成敗。這次的呼叫端已經讀了 rc，問題出在 CLI 對空輸入回 0。
