### 盤點：lib/ 目錄 vs 8 DomainBundle（2026-10-07 實測）

| domain（system-layer §2 層） | lib 目錄 | domain-map 是否寫明路徑 |
|---|---|---|
| Schema (L0) | lib/schema/（6 檔）；lib/app/degraded_schema.dart 散落 | 有（lib/schema/） |
| Workspace (L0) | lib/workspace/（5 檔） | 無 |
| Corpus (L1) | lib/corpus/（9 檔）；lib/services/（scan_notifier 三檔，歸屬待判，暫推 Corpus） | 有（lib/corpus/） |
| Graph (L2) | lib/graph/（7 檔） | 無 |
| Diagnostics (L2) | lib/diagnostics/（3 檔） | 有 |

| Layout (L3) | 無目錄；components/swimlane_*、matrix_* 為呈現元件 | 無 |
| 非 domain | screens/（L4 畫面狀態，system-layer 明定為 layer 非 domain）、components/、app/、l10n/、tokens/、main.dart | — |

### 樣本與計算方式

- 樣本：docs/work-logs/**/tickets/*.md 全部 1359 張可解析 frontmatter 的票；取 where.files 以 `lib/` 開頭者 → 256 張票、543 筆引用（唯一路徑 140；`::read` 等後綴截除）。現存路徑 541/543。
- 比對：最長前綴命中（字串 startswith）。引用可定位率＝命中筆數/543；票可定位率＝至少一筆命中的票/256。
- 「L4/共用」＝落在 screens/components/app/l10n/tokens/main.dart 的引用，依 system-layer 本就不屬任何 domain。

| 規則集 | 引用可定位 | L4/共用 | 其他無法定位 | 票可定位 |
|---|---|---|---|---|
| R0：domain 目錄前綴（6 目錄，ticket_detail→ticketdetail） | 140/543＝25.8% | 384 | 19 | 71/256＝27.7% |
| R1：R0＋services/→Corpus、components/swimlane_*/matrix_*→Layout、app/degraded_schema.dart→Schema | 154/543＝28.4% | 378 | 11 | 79/256＝30.9% |

R1 剩餘 11 筆：裸目錄無尾斜線（lib/corpus、lib/diagnostics、lib/services、lib/app 各 1，lib/screens、lib/components 各 2）、`lib/` 3 筆。

### 候選比較

| 候選 | 放置位置 | 維護者 | 比對方式 | 對既有 543 筆的可定位率 | 主要代價 |
|---|---|---|---|---|---|
| A 重整 lib：每 domain 一目錄（lib/<domain>/，名稱＝宣告名，L4 另置 lib/ui/ 等） | 目錄結構本身＝表；Graph 以「lib/<宣告名>/」推導 | 實作者（搬檔時） | 第一段目錄名＝domain | 不改歷史票：舊路徑全失效，除非附搬遷對照表；附對照表時上限同 R1（28.4%），未來新票可達「domain 碼 100% 可定位」 | 大量搬檔、import 重寫、歷史 where.files 斷鏈；L4/共用 70% 仍無 domain |
| B 不動 lib，只建路徑模式表 | 單一表檔（Graph 消費，如 docs/ 下 yaml） | PM／SA 一處維護 | 前綴／glob 對照 | R1：28.4%（票 30.9%） | 表與 domain-map 兩處真相；新增目錄需記得補表 |
| C 各 domain-map frontmatter 宣告 path_patterns | 8 份 docs/spec/*/domain-map.md frontmatter | 各 domain 擁有者 | Graph 聚合 8 份宣告；需檢查重疊／遺漏 | 同 B（28.4%），規則集相同只是載體不同 | 跨 domain 重疊需衝突檢查；L4/共用無 domain-map 可宣告，需另立歸屬 |

三候選的天花板相同：72% 引用落在 L4/共用層，不是表的問題而是分層定義——不屬任何 DomainBundle。

### 對 UC-02 與矩陣高亮的影響

- 若「無法定位」＝未命中任一 domain：三候選下約 69% 的帶 lib 路徑票被判無法定位，判定訊號失去鑑別力。需先決定 L4/共用是否為獨立判定類別（「非 domain 層」≠「無法定位」）；這是比表形態更前置的決策。
- 矩陣高亮：可定位票以命中 domain 列高亮；A 的未來票高亮最完整，但歷史票在無搬遷表時全失效；B/C 對歷史與未來一致。
- C 下 History/Layout 無目錄，frontmatter 宣告空集合需被允許（domain-map §3 規劃中 bundle 不得宣告不存在路徑，PC-APP-012）。
- 裸目錄（無尾斜線）引用需比對規則正規化，否則任一候選都漏 6 筆以上。

### 建議後續票（未建）

1. ANA：L4/共用路徑在 UC-02 的判定類別（無法定位 vs 非 domain 層），為三候選共同前置。
2. ANA：lib/services/scan_notifier* 與 lib/app/degraded_schema.dart 歸屬判定。
3. DOC：依裁決結果寫對照表（B 表檔或 C 的 8 份 frontmatter path_patterns）＋schema 欄位定義。
4. IMP：Graph 路徑比對器（前綴正規化含裸目錄、重疊衝突檢查）。
5. 若選 A：IMP lib 搬遷（含 ticket_detail→ticketdetail 命名對齊）＋歷史 where.files 搬遷對照表。

無需建 ticket（本票）：依派發約束僅列出，建票由 PM 於用戶裁決後執行。
