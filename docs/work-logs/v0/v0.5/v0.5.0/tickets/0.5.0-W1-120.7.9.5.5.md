## Problem Analysis
<!-- Schema[IMP/Problem Analysis]: 選填（小型 IMP 可留 placeholder；大型 IMP 建議填寫）（.claude/pm-rules/ticket-body-schema.md） -->
### 派發 context（PM，2026-10-14）

**實測**：用 jq 組 PreToolUse payload，分別餵給 5245b3ae1^ 版與現行版 hook 程序，比較 exit code。被測命令本身不執行。

| 命令 | 舊版 | 現行版 |
|---|---|---|
| `rg --pre pkill x .` | 0 | 0 |
| `rg --pre=pkill x .` | 0 | 0 |
| `man -P 'pkill dart' ls` | 0 | 0 |
| `man --pager='pkill dart' ls` | 0 | 0 |
| `less '+!pkill dart' f` | 0 | 0 |
| `timeout 5 rg --pre pkill x .` | 0 | 0 |
| `grep -r pkill . \| xargs pkill` | 2 | 2 |

**成因**：`_is_view_statement` 用命令位置判斷閱讀類，命中就整句跳過 `_scan_any_position`。rg、man、less 有能執行外部命令的選項。

**實作注意**：任意位置掃描比對的是 token 的 basename。`--pre=pkill` 和 `pkill dart`（引號字串）這兩種 token 的 basename 都不等於 pkill，所以只取消例外還不夠，選項值要另外拆開檢查（等號後的值、引號字串的第一個字）。

**同輪的另一項審查發現**：parser-differential（global-pkill-guard），細節沒有送達。依協調 session 先前的約定，這類發現不逐輪追修，只記錄出現次數，作為 0.5.0-W1-120.7.9 的量化依據。本票不處理。

**測試入口**：`uv --directory <root>/.claude/hooks run pytest <root>/.claude/hooks/tests/test_global_pkill_guard_hook.py`，`<root>` 為專案根絕對路徑。

## Solution
<!-- Schema[IMP/Solution]: 選填（.claude/pm-rules/ticket-body-schema.md） -->
修法：global-pkill-guard-hook.py 新增常數 _EXEC_OPTS（rg --pre/--pre=、man -P/--pager/--pager=、less + 開頭）；_is_view_statement 在語句含執行類選項時回 False，改走任意位置掃描；對 rg/man/less 語句另以 _expand_tokens 把 token 依空白與等號拆片段並去掉 +/! 前綴，使 --pre=pkill、'pkill dart'、'+!pkill dart' 命中。拆片段僅限 _EXEC_OPTS 內的程式，不影響其他命令（git commit -m 'x pkill' 仍放行）。

### 自檢結果
- 六個新增正向對照輸入皆 exit 2；新增 rg -n pkill src、man -k pkill、less pkill.log 仍放行。
- 未改 .claude/lib/；fail-open 語意未動。
- 未涵蓋：LESSOPEN/PAGER/MANPAGER 等事先 export 的環境變數、ripgreprc 設定檔、man 的 -H/--html 等其他執行器選項、rg --pre 與其他閱讀類（如 grep 的別名/wrapper）、帶執行類選項的語句其搜尋樣式含 pkill 時會多擋（設計取捨）。

### Phase 4
重構需要：否；技術債務：選項表與 man 其他執行器選項未窮盡（上列）；程式碼品質：A；結論：無需重構。
