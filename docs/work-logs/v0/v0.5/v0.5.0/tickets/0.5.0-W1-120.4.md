### PM 派發前盤點（2026-10-14，D 線）

**現行碼（main e9ee807e3 之後）**

- `_merge_in_progress(project_root)` 以 `run_git_command(["rev-parse","-q","--verify","MERGE_HEAD"], cwd=project_root)` 判定，回傳 `success`。
- `run_git_command`（`.claude/lib/git_utils.py`）只回 `(bool, str)`：returncode 非 0、逾時（`TimeoutExpired`）、git 不存在三者都回 `False`，與「無此 ref」（rev-parse -q --verify 回 1、stderr 空）同形。這是 acceptance 第 3 項要拆開的兩種情形。
- `main()` 已有 `invocation.dash_c_path`（`lib.git_command_parse.GitInvocation`），但偵測未使用。
- payload 的 `cwd` 欄位未使用；`project_root = get_project_root()`。

**可沿用的先例（不另寫解析）**

- `merge-staged-index-guard-hook.py` 的 `_resolve_target(cwd, dash_c)`：`cwd = input_data.get("cwd") or os.getcwd()`，`-C` 為相對路徑時接在 payload cwd 之後，絕對路徑覆蓋。
- `git-index-lock-cleanup-hook.py` 的 `_resolve_path`：另含 `expanduser` 與 `normpath`。
- 兩者寫法不同，本票擇一沿用，不新增第三種寫法；是否收斂到 lib 列入 Phase 4 評估，不在本票改動範圍。

**PM 裁定的偵測目錄優先序**

`-C` 路徑（相對者以 payload cwd 為基準）> payload `cwd` > `get_project_root()`。

理由：MERGE_HEAD 是各 worktree 獨立的 ref，`git commit` 實際作用在 shell 的 cwd 或 `-C` 目標，不是 hook 的 project root。只改 `-C` 而不讀 payload cwd，審查列出的「cwd 在 worktree 內的提交被誤擋」不會消失。

**範圍邊界**

- 本票只改 MERGE_HEAD 偵測的目錄與失敗語意。staged 清單（`_get_staged_files`）與派發範圍判定仍讀 project root，屬既有範疇邊界（模組 docstring 已載明），不在本票。
- `git -C a -C b` 的串接語意（git 視為 a/b），解析器只取第一個 `-C`，屬解析差異，由 0.5.0-W1-120.7 處理，本票不改 `lib/git_command_parse.py`。
- 失敗語意：子程序失敗（returncode 非 0 且非 1、逾時、git 不存在）時維持 fail-open 放行，但須寫 warning log，訊息含偵測目錄與錯誤內容。可在本 hook 內以 `subprocess.run` 直接取 returncode，或在 lib 新增回傳 returncode 的變體；改 lib 時須跑 lib 的其他使用者測試。

**CLAUDE_PROJECT_DIR 實測**（acceptance 第 2 項）由 PM 另派 worktree 隔離的量測代理人取得後寫入本票，實作代理人不需處理。

## Solution
<!-- Schema[IMP/Solution]: 選填（.claude/pm-rules/ticket-body-schema.md） -->
改法（bare-commit-guard-hook.py）：新增 _resolve_detect_dir（-C 路徑，相對者以 payload cwd 為基準 > payload cwd > project root）；_merge_in_progress(detect_dir, logger) 改於 hook 內以 subprocess.run 取 returncode（未改 lib）。rc 0=有合併；rc 1=無此 ref（不寫 log）；其他 rc／逾時／OSError=偵測失敗，fail-open 放行並寫 warning（含 dir、rc、stderr）。staged 清單與派發判定未動。

四格（tmp_path 主 repo + linked worktree，真實 git，不 mock 偵測函式；root 固定主工作樹）：
| 合併位置 | 主工作樹提交 | cwd=wt | -C wt | -C 主 + cwd=wt |
| 主工作樹合併 | rc2 | rc0（原誤擋） | rc0（原誤擋） | rc2 |
| worktree 合併 | rc0 | rc2 | rc2（原漏擋） | - |
另測相對 -C（../wt 以 payload cwd 為基準）rc2；無 payload cwd 退回 root。

失敗語意：替身 rc=128 與 TimeoutExpired 各寫 1 則 warning 並回 False；真實 repo 無合併寫 0 則 warning；不存在目錄寫 1 則（可區分）。

實地觸發（scratchpad 暫存 repo，worktree 合併進行中，root=主 repo）：cwd=主 repo rc=0（stderr 為非並行 WARN）；cwd=worktree rc=2（stderr「[合併進行中，裸 commit 被阻擋]」）。

liveness：以 sed 複本把 _resolve_detect_dir 變異為一律回 root，四格 3 個測試全 FAIL（3 failed），確認測試鑑別力；主 checkout hook 本體未動。

Phase 4：重構需要=是（小）；技術債務=有；品質 A。_resolve_detect_dir 與 merge-staged-index-guard-hook 的 _resolve_target、git-index-lock-cleanup-hook 的 _resolve_path 共三種 -C 解析寫法，應收斂至 lib（git_command_parse 或 git_utils 的單一 resolve_git_target(payload_cwd, dash_c)，含 expanduser/normpath）。改動跨三 hook 與 lib，不在本票，登記 spawn request。
