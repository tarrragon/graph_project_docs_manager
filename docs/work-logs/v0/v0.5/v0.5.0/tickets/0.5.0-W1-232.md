## Task Summary

修正 pre-test-hook 以子字串比對命令文字，grep 或建票命令含測試指令字樣即被判為測試執行

---

## Problem Analysis
### 問題根因

`is_test_command` 以子字串比對整段命令文字（`"flutter test" in command`），grep 的 pattern、建票命令的參數只要含該字樣即判為測試執行。本 session 執行 `grep -n "...\|flutter test\|dart test..." post-test-hook.py` 時再次重現，pre-test 與 post-test 兩個 hook 同時觸發。

### 影響範圍

- `.claude/hooks/pre-test-hook.py`：`is_test_command`（本票修正）
- `.claude/hooks/post-test-hook.py`：`_is_test_command` 的 `TEST_COMMAND_PATTERN` 雖已收斂到敘述邊界，但對原始字串做 regex，引號內的 `\|` 會被視為管線邊界，屬同型誤判（實測見 Test Results）。轉子票 0.5.0-W1-232.1，因該檔正由 0.5.0-W1-187.15 修改

### 相關 Error Pattern

查重 issue：#54（hook 判定邏輯的隱含前提未驗證：誤報）同類。

### WRAP 三問

- W：其他做法有 (a) 沿用 post-test 的 regex（已實測同型誤判，排除）(b) 擴充豁免清單（只蓋得住已列命令，排除）(c) 依 POSIX 引號規則切 token 後只看敘述開頭（採用）
- R：實測 shlex 對 `&&`、`|`、`(`、換行與引號的切分行為後才採用
- A：不改 post-test-hook（避免與 187.15 衝突），以子票承接

## Solution
`pre-test-hook.py` 的 `is_test_command` 改為：

1. `_split_statements`：以 `shlex`（POSIX 引號規則，分隔符 `; & | ( )` 與換行）切 token，引號內文字成為單一參數，再依分隔符切成各敘述
2. `_strip_launch_prefixes`：去除環境變數前綴、`run-with-timeout.py ... --` 包裝（在敘述內任意位置找包裝器）與 `fvm` 前綴
3. 任一敘述剩餘的前兩個 token 為 `flutter test` 或 `dart test` 即判為測試命令；解析失敗回 False
4. `mcp__dart__run_tests` 維持判為測試命令

驗收第 3 項：PostToolUse「測試完成」來自 `post-test-hook.py`，其 `TEST_COMMAND_PATTERN` 有同型誤判（引號內 `|` 被當敘述邊界），以子票 0.5.0-W1-232.1 承接，策略為把本票的切分判定抽至 hooks/lib 共用，供 post-test-hook 與 0.5.0-W1-231 的本機閘門共用。

Phase 4 結論：重構需要＝是（審查發現已於本票追修）；技術債務＝發現（判定邏輯兩份並存，已由 0.5.0-W1-232.1 承接）；品質 A；不支援的前綴形態已寫入 docstring。
