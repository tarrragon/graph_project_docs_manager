### 原始證據（2026-10-27，研究線 PM 收尾 466.6 時觀測）

- 指令：`worktree cleanup --branch worktree-agent-a8cb85fbdd8f19a9d`（已先 push）。輸出：Level 1／2／3 檢查皆通過，接著 `[錯誤] 移除 worktree 失敗：Command timed out after 10s`，rc=0（失敗但結束碼為 0，另一個缺陷候選）。
- 中斷後：`git -C <wt> status --porcelain` 3318 行，全為 ` D`；HEAD 32b92e146 為 main 祖先，`git merge-base --is-ancestor` 核對。
- 重試 `git worktree remove <wt>`：被 worktree-remove-deliverable-check-hook Guard C 擋下，「已追蹤但未提交（3318 項）」，建議 `git -C <wt> restore .`。
- 照做：workspace-wipe-guard-hook 擋下「全工作區破壞性操作被阻擋：git restore .」，理由「並行派發中：目前有 7 個實作代理人正在派發中」。該守衛未區分 -C 目標為非共用 worktree。
- 推測逾時成因（未驗證）：worktree 內有 build/ 等大型被忽略目錄，刪除耗時超過 10 秒。
