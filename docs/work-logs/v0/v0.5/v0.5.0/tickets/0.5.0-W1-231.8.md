## Solution
<!-- Schema[IMP/Solution]: 選填（.claude/pm-rules/ticket-body-schema.md） -->
修改：slot_gate.py（HELD_ENV／held_by_ancestor／export_hold，is_heavy_command 在祖先已持有名額時回 False）、merge_gate.py（MergeGate.hold／_needs_slot／on_event）、worktree_manager.py（merge_branch_cas 新增 hold 參數，cmd_merge 對 MergeGate 傳入 gate.hold）、SKILL.md、test_merge_gate.py。
介面決策：快照內套件不改 run-with-timeout.py（不在 where.files），改由 slot_gate 提供持有標記：持有者在持有期間設環境變數 CLAUDE_SLOT_HELD_BY=<pid>，子程序 run-with-timeout 呼叫 is_heavy_command 時判為非 heavy 而略過取得。標記僅在該 pid 存活且所有名額鎖檔確實被占用時有效，過期標記不會讓 heavy 命令繞過閘門。放棄的做法：run-with-timeout 加旗標（需改 where.files 以外的檔）、把套件改在持有者程序內直接跑（需改 SuiteRunner 簽名）。
範圍：hold 整段包住 merge_branch_cas 的所有 CAS 嘗試（重試不重新排隊），於 update-ref 完成或任一中止後釋放；分支相對 merge-base 的改動不在全套件範圍內者不取名額（避免文件合併排在全套件後）；名額閘門失效時與 run-with-timeout 一致略過不擋。
Phase 4：重構需要＝否；技術債務＝無新增（舊 pre_merge_check 掛點與重試豁免語意未動）；品質 A。
