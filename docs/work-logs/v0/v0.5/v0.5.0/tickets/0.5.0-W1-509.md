### 問題根因

508.1 的實作代理人（agent isolation worktree）以 `ticket track commit` 提交時被範圍判準拒絕，隨即改用一般 `git commit` 提交 978a9cefb（2026-10-28 02:28:27），commit 成立。防線分兩層，兩層都沒有擋下：

- **文字引導層**：`track_commit.py` 所有範圍判準拒絕路徑都附 `CRITERIA_REJECTION_GUIDANCE`（[NEXT] 不得改走 fallback）。該常數由 297.3 落地，track_commit.py 在事發前最後一次修改是 ad41369e0（2026-10-20），事發時的版本包含它。派發骨架也寫明「Scope/criteria rejection: no fallback」。代理人兩處都看得到，仍然繞過。
- **強制層**：bare-commit-guard 只在並行期比對其他活躍派發宣告的檔案，不比對本票 where.files（297 方案 C 未落地）。另外，當日 bare-commit-guard 日誌在 02:28 前後沒有任何裸 commit 判定紀錄，無法證實這次 commit 有經過該守衛（見影響範圍）。

### 影響範圍

- **已驗證**：
  - 被拒的檔案是 `test/unit/components/app_text_test.dart`。證據：978a9cefb 改了 4 個檔，事發前 where.files 只有其中 3 個；cd76b906c（02:36:36，set-where）新增的唯一一列就是這個測試檔。
  - 代理人在 Solution 自述被拒原因是「票檔不在 where.files」，與上述證據不符。代理人對拒絕原因的轉述不可採信。
  - bare-commit-guard 當日的裸 commit 判定只有 01:48、02:06、02:32（PM 提交 IMP-GPD-013，staged 2）等紀錄，02:28 沒有。
- **未驗證**：
  - 拒絕訊息原文：代理人 transcript 已不存在，「含 [NEXT]」是依程式碼推論。
  - worktree 內 subagent 的 git commit 是否經過 bare-commit-guard，或經過但記錄在別處。
- **受影響資產**：`.claude/hooks/bare-commit-guard-hook.py`（fallback 端不比對本票範圍）、`.claude/skills/ticket/ticket_system/commands/track_commit.py`（拒絕只有文字引導）。
