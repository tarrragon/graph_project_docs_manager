### 機制推論（L45 讀碼，Flutter 3.47.1，尚未實驗驗證）

原假設「framesEnabled=false → settleGuarded 立即返回」與 SDK 原始碼不符，修正如下。

讀碼事實（fvm 3.47.1 SDK）：
- `WidgetTester.pumpAndSettle`：`do { pump } while (binding.hasScheduledFrame)`，第一次 pump 後 hasScheduledFrame 為 false 就正常返回。
- `SchedulerBinding.scheduleFrame`：`_hasScheduledFrame || !framesEnabled` 時直接 return，不設旗標。framesEnabled 只在 lifecycle 為 hidden／paused／detached 時為 false；resumed 與 inactive 皆為 true。
- `LiveTestWidgetsFlutterBinding.pump`：以 Timer 設 `_expectingFrame=true` 並呼叫 scheduleFrame，再等 `_pendingFrame` 被 handleDrawFrame 完成。
- `LiveTestWidgetsFlutterBinding.handleDrawFrame`：未預期的幀被略過後，走 else 分支直接呼叫 `platformDispatcher.scheduleFrame()`，**繞過 framesEnabled 檢查**。

推得兩種形態：
| 開始 settle 時的狀態 | 結果 | E2 判定 |
|---|---|---|
| framesEnabled=false，引擎也不再送幀 | pump 等不到幀 → 外層 timeout → TestFailure 含步驟名 | 綠（逾時路徑） |
| framesEnabled=false，但引擎仍在送幀（略過幀的 else 分支自我續排） | pump 等到一幀；幀內 ticker 重排 scheduleFrame 被 framesEnabled 擋下 → hasScheduledFrame=false → 一次 pump 即返回 | 紅（Actual <null>，不到 1 秒） |
| framesEnabled=true（resumed／inactive） | ticker 持續排幀 → 內層 2 秒逾時 → TestFailure | 綠 |

與 479 反例的對帳：「Failed to foreground app」只代表 App 不是 active（inactive），framesEnabled 仍為 true，所以 10/10 綠與本推論相容。紅燈需要的是 lifecycle 進到 **hidden**（macOS embedder 在視窗不可見／被遮蔽時送出），而且當下引擎還在送幀。負載可能是讓「hidden 已生效、引擎尚未停送」這段空窗變長的條件。

紅燈樣本佐證：三份樣本 E2 都在 00:02 開始、不到 1 秒判紅（19d6c7dce400、b17ba29ad723、b3e907e108dd），與「一次 pump 即返回」相符；綠燈時 E2 約 2 秒（內層逾時）。
四份 log 開頭的 swap 都是 4613.81M used，memory_pressure 45% free，記憶體壓力不像主因（待取樣確認）。

### 實驗設計（L45，待主控放行 integration 取樣）

實驗 A（機制，輕量，不跑 integration）：在 flutter_tester 下以 LiveTestWidgetsFlutterBinding 跑 E2 同款畫面，用 `binding.handleAppLifecycleStateChanged` 注入 lifecycle，各變體 N≥5，記錄 settleGuarded 結果與耗時：
- A0 不注入（對照，預期內層逾時 TestFailure）
- A1 inactive（預期同 A0）
- A2 pumpWidget 後、settle 前注入 hidden（預期立即返回 → 重現 Actual <null>）
- A3 hidden 後再回 resumed（預期恢復 A0 行為）
A2 成立即驗證「無排程幀時 settleGuarded 立即返回」，A0／A1 為對照。

實驗 B（環境，heavy，照閘門順序）：先 `fvm flutter test` 全套件，再 run-with-timeout.py 跑 integration，N≥5；每輪記 load1、swap、App lifecycle 序列（E2 前加暫時 log 印 `lifecycleState` 與 `framesEnabled`），看紅燈是否只出現在 hidden。同一套環境也記錄 479.3 的等幀逾時（ITD1-A4／ITD2）。

修法方向（待 A 驗證後定案）：settleGuarded 返回前檢查 `binding.framesEnabled`；為 false 時不視為已靜止，改以 TestFailure 指名步驟（「framesEnabled=false，無法判定是否靜止」）。這樣正向對照在無幀可排時仍紅燈，有幀時行為不變。不改 lib/。
