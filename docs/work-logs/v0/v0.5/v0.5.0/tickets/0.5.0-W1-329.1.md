## Solution
<!-- Schema[IMP/Solution]: 選填（.claude/pm-rules/ticket-body-schema.md） -->
### 實作
- 新增 resolve_state_path(base_path, event, logger)：payload 的 session_id 為非空字串時，狀態檔改為 <stem>-<session_id><suffix>（例 wrap-tripwire-state-sessA.json），session_id 以 [^A-Za-z0-9_-] 換成底線消毒（防路徑穿越）；缺少、空字串、非字串時退回原共用檔並 logger.info（fail-open，不寫 stderr）。
- main() 以 resolve_state_path 取代原單一路徑；只讀 stdin payload，不 fallback 環境變數。
- 手動 /wrap-decision 重置：reset_all_signals 作用於已載入的 state，state 現為當前 session 檔，故自然只清當下 session，不需另行處理；日誌字樣同步更新。
- 過期 session 檔清理：本票未實作（父票設計提到併入），需 PM 裁決是否另開票。

### session_id 依據
- 實證：PreToolUse(Edit) 與 UserPromptSubmit 的 stdin payload 帶 session_id（父票 Problem Analysis 實測）。
- 規格推定、未實證：PostToolUse / PostToolUseFailure。依據為 .claude/hook-specs/claude-code-hooks-official-standards.md 各事件範例皆含 session_id；無實機擷取。測試 fixture 因此用 session_id 為頂層鍵，與規格範例形狀一致。若實機該事件不帶，行為為退回共用檔（與改前相同），不會更壞。

### 實地觸發方式（供 PM 合併後補）
合併後，在主 checkout 觸發一次 Agent 失敗事件（或 Agent 成功的 PostToolUse），確認 .claude/hook-state/ 下出現 wrap-tripwire-state-<實際 session_id>.json；並查 .claude/hook-logs/wrap-decision-tripwire/ 日誌：若出現「payload 無可用 session_id；退回共用狀態檔」表示該事件實機不帶 session_id（回答 acceptance 3）。

### 自檢結果
- [x] 缺 session_id / 空字串退回共用檔，E2 測試斷言檔案集合僅含共用檔、換票清空行為同改前
- [x] E1 對照：sessA 失敗後 sessB 換票，sessA 狀態檔 count 仍為 1，再失敗為 2，共用檔不產生
- [x] 手動重置僅清當前 session（sessB 計數保留）
- [x] Python 3.9 相容語法；無 print 日誌；未動設定版本問題（W1-330）
- [x] 框架檔內文無本專案票號
