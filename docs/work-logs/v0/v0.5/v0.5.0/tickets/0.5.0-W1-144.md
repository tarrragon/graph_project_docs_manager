## Problem Analysis
<!-- Schema[ANA/Problem Analysis]: 必填（.claude/pm-rules/ticket-body-schema.md） -->
### 2026-10-15 補充實例（PM 彙整）

同一天至少 4 張票第一次 complete 被「缺 ### 自檢結果」擋下，都是補上子章節後第二次才成功：303、316（新線）、264.5、264.6（D 線）。共同點是 ANA 父票或由 PM 側收尾的票，沒有經過派發骨架（骨架才會提示這個子章節），ticket create 也不預先帶入。各線每次都要多跑一次 complete，且容易被誘導補一行字面標題過關（與 276 同型）。

建議修法方向（供本票分析時比較）：create 依票型預先帶入 `### 自檢結果` 範本骨架；或 complete 擋下時直接列出可貼用的子章節範本。優先序建議由 P3 提到 P2：每天穩定重複發生。

### 補充觀測：IMP 票同樣被擋（0.5.0-W1-532.1，2026-10-30）

- 0.5.0-W1-532.1（IMP）第一次 `ticket track complete --as rosemary-project-manager`，rc=1：`[Error] 0.5.0-W1-532.1 body 未依 IMP schema 填寫必填章節／未填寫的必填章節：Solution > ### 自檢結果`。
- 同一次執行，complete 前清單第 8 項只標 `[WARNING] Solution 缺 ### 自檢結果 子章節（Layer 1）`，並註明「本檢查為 warning（不阻擋 complete）」。
- `agent-self-check-template.md`〈自檢結果寫入範本〉寫的是「若自檢無任何發現，可省略 `### 自檢結果` 子章節」。
- 所以本票標題寫的「ANA 票」範圍太窄：IMP 票同樣有三處定義不一致，而且 complete 驗證會實際擋下。處置：補一份無發現的自檢結果後，complete 成功。
