### WRAP 評估：lavender 自行補定規則（2026-10-07）

範圍：本票寫入 SPEC-001 §1〈間接依賴格的詳情卡：依賴路徑〉的多路徑規則（每來源取最短、同長全列、排除經直接 domain 的路徑、依長度與列序排序）超出 0.5.0-W1-093 裁決 A3（只定「下游不限跳數可達」與「顯示依賴路徑、跳到來源節點」）。以 WRAP 快速+ 模式評估，不選定，交用戶裁決。

事證（PyYAML 解析 6 UC flow 與 8 份 domain-map 的 depends_on_bundles，列舉所有簡單路徑）：

| 量測 | 結果 |
|---|---|
| 間接依賴格 | 10 格（與 SPEC-001 期望分布 19／10／19 一致） |
| 有多於一條路徑的格 | 10／10（全部；來源數 2～4） |
| 同一來源有多條路徑的格 | 0（依賴圖無菱形，「同長全列」在真實資料不會觸發） |
| 有路徑經過直接 domain 的格 | 7／10 |
| 套 lavender 規則後每格行數 | 7 格 1 行、3 格 2 行（皆 UC-04：corpus／schema／workspace，來源 graph 與 ticketdetail） |
| 不排除時最多行數 | 4 行（UC-02 × schema：layout、ticketdetail、graph、corpus 四個來源） |

| 候選 | 規則 | 真實資料行數 | 致命風險 |
|---|---|---|---|
| 3a 維持 lavender 版 | 每來源最短、同長全列、排除經直接 domain、依長度再列序排序 | 1～2 行 | 「同長全列」與「同來源多路徑」無真實資料，測試須合成 fixture（E2 正向對照）；規則四條，對使用者是否可理解未經 UX 審查 |
| 3b 只列一條 | 全部候選路徑中最短者，同長依列序取第一 | 恆 1 行 | UC-04 的兩個來源只顯示一個，使用者看不到 ticketdetail 也導致此依賴 |
| 3c 全列不排除 | 每個直接貫穿 domain 的最短路徑都列 | 1～4 行 | 長路徑（layout → graph → corpus → schema）其實已被較短的 corpus → schema 涵蓋，資訊重複 |
| 3d 只列來源 domain，不列中間節點 | 「間接（經 corpus）」式的來源清單 | 1～4 個名稱 | A3 裁決明寫「顯示依賴路徑」，此候選降級為來源清單，需用戶確認可接受 |
| 3e 規格不定，交實作 | 只寫「顯示依賴路徑」 | 未定 | 跳轉目標依「第一行來源」，排序不定則跳轉目標不定，無法寫期望值 |

傾向：3a。理由是排除規則在 7／10 格生效且結果只剩真正的入口來源，跳轉目標（第一行來源）也因排序明確而可測。盲點：「同長全列」是為一個現況不存在的圖形（菱形依賴）預先定規則，可能是過度規格；若用戶偏好最小規則，可刪去該條改為「同長依列序取第一」而不影響現況任何一格。另，排序依「泳道列序」，列序本身正待 W1-092.1 議題 1 裁決，兩者連動。

需用戶裁決：多路徑呈現取 3a／3b／3c／3d／3e？若 3a，「同長全列」保留，或改為「同長依列序取第一」？
