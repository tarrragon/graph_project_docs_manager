## Problem Analysis
### 問題根因

前移規則（0.4.1 ticket 2.44.31）讓已完成子孫留在舊版本、只改寫 parent 引用，父票在新版本、子票在舊版本成為常態。部分程式以 `list_tickets(version)` 或 `load_ticket(父版本, id)` 解析 children／spawned，只看得到父票所在版本。W1-047 已修 complete 閘門（`_find_non_terminal_by_id`）；本票盤點其餘位置。

### 影響範圍

已驗證（tmp_path 實測）：
- `acceptance_auditor._has_impl_or_adj_child`：父新版本、已完成 IMP 子票在舊版本，回 False（應 True），同型，已建 .1。
- `lifecycle._cascade_unblock_children`（含 `_post_complete_cascade`、complete 主流程以 list_tickets(version) 建 map）：舊版本已完成子票被 `_classify_child` 判 skip，結果正確，非缺陷。

推導未實測（程式閱讀）：
- `track_query._collect_spawned_tree`（`load_ticket(version, id)`）與 `execute_tree`／`execute_chain`（`list_tickets(version)` 餵 `format_ticket_tree`）：舊版本子票／spawned 顯示 not_found 或從樹消失，已建 .2。
- `field_validators` blockedBy 循環偵測的 `all_tickets` 為單一版本，跨版本環可能漏判，已建 .3（第一步為重現）。

已排除：blockedBy 解析（`blocker_resolution.resolve_blocker` 已跨版本）、`ana_coupling_hint`（已用 `resolve_reference_version`）、hooks `children_checker`（W1-047 已確認）。

### 相關 Error Pattern

無新增。同族為 #102（spawned 血緣）、#55（ticket CLI 契約缺口叢集），關係＝引用。未另建 error-pattern：根因已由 W1-047 記錄，本票只擴充盤點範圍。

## 重現實驗結果
### 實驗方法

臨時 pytest 檔（用完已刪，未入庫），沿用 tests/conftest 的 `_isolate_project_root` 隔離（tmp 專案根），在 0.4.9（舊）與 0.5.9（新）兩版本以 `get_tickets_dir` 寫票檔；`uv run pytest -q -s`。不碰真實票。

### 實驗執行

實驗 A：父 0.5.9-W1-001 children = [舊版本已完成 .1、舊版本 blocked .2、新版本 blocked .3]，呼叫 `_cascade_unblock_children(parent, "0.5.9")`（未傳 ticket_map，走 list_tickets fallback）。輸出 `UNBLOCKED ['0.5.9-W1-001.3'] WARN []`。
實驗 B：父 0.5.9-W1-002 children = [舊版本已完成 IMP .1]，呼叫 `_has_impl_or_adj_child`。輸出 `HAS_IMPL False`。

### 實驗發現

- cascade：舊版本已完成子票 .1 被 skip，結果正確，無缺陷。舊版本 blocked 子票 .2 不在 map，被當 child=None 靜默 skip，不解鎖、無警告；但前移規則只讓已完成子孫留舊版本，blocked 子票不會留在舊版本，屬理論路徑。結論：不建票。
- `_has_impl_or_adj_child`：缺陷成立（False 應為 True），建 .1。
- 未實測：track_query 樹／spawned、field_validators 環，僅程式閱讀推導，已在 .2、.3 的 acceptance 要求先重現。
