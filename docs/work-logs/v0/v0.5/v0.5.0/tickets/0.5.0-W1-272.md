## Solution
<!-- Schema[IMP/Solution]: 選填（.claude/pm-rules/ticket-body-schema.md） -->
本票的修正已由 main 上的 e5294a83e（2026-10-14 20:37，commit 訊息沒有票號，歸屬已請派發 session 確認）完成，本票不另派發，改由 PM 驗收結案。

e5294a83e 的判準：ahead=0 的 worktree 中，以下三種歸「進行中」，不列入建議清理：

- git worktree list --porcelain 標為 locked（執行中的代理人 worktree）
- 分支 tip 落在 main 的 first-parent 歷史上（零提交，只是派發基底）
- 上述判定失敗（fail-open，不建議清理）

這比原 how 的兩個選項（dirty 判準、dispatch-active 判準）更寬：零提交的 worktree 不論 dirty 與否都排除，而且不依賴 dispatch-active 是否登記。因此第 1 條驗收的 E1 對照改為「零提交與以 merge commit 合併完成的分類不同」。

### 自檢結果

- 驗收逐條對照 e5294a83e 的測試：AC1 對應 test_classify_zero_commit_worktree_not_in_merged 與 test_classify_locked_worktree_not_in_merged；AC2 的正向對照對應 test_classify_finished_merged_worktree_still_in_merged。
- 驗收措辭有修改，原因已寫在 acceptance 與本段；沒有降低要求，判準反而變寬。
- 無 emoji，未使用禁用詞；只寫 Schema 章節。

### Phase 4 重構評估（PM 審查 e5294a83e）

- 重構需要：否。classify_worktrees 把三種「進行中」原因分開記錄，提醒訊息附上原因，可追溯。
- 技術債務：無新增。fast-forward 合併的分支會被判為零提交，結果是少給一筆清理建議；程式碼註解已寫明偏安全，可接受。
- 程式碼品質：A。正向對照與失敗語意都有測試。
- 結論：無需重構。
