### 派發決策（PM）

- **合併程序（83 定，必須遵守）**：
  1. 在本票 worktree 開工前先 `git merge --no-edit worktree-agent-ae5483b2aa3aa95e7`（.1 的 7b6e20b6a），之後才改檔。
  2. 完成後由 PM 只合併本票分支，讓 .1 與 .2 一次進 main。main 若只拿到 2.77.0 的 JSON、內建副本未同步，App 會把本專案自己的 schema 判為超出已知範圍。
  3. 執行者不得 merge 進 main、不得 push。
- **內建副本**：`builtin_tracking_schema.json` 以 .1 產生的 `tracking_schema.json` 完整覆寫（逐位元組一致，以 `cmp` 驗證）；`builtin_schema_version.json` 只改版本欄為 2.77.0，`_comment` 不動。
- **`lib/schema/edge_type.dart`**：只在測試證明需要時才改（proposed 邊型應已由既有解碼處理）；改動需在回報中說明理由。
- **單份派發**：不作成對實驗（磁碟撐不住兩份 flutter worktree，且合併程序綁死），派 parsley 一份，記入 0.5.0-W1-063。
- **前置**：派發前 PM 以 `df -h` 確認可用空間 ≥ 5Gi（e1 通知用戶清理完成後才派）。
- **全套 flutter test 一律加 `< /dev/null`**；`cmd > log 2>&1 < /dev/null; echo rc=$?`。
- **驗收指令**：`fvm flutter analyze`、`fvm flutter test`、`fvm flutter test test/integration/`，記 rc 與通過數；integration 必須等於 66；另跑 `.claude/skills/doc` 的 pytest（.1 帶入的測試），記 rc。
- **合併後**：PM 通知 e1 與 83（觸發第二次 canonical 推送申請、W1-070.3 拆檔接續）。

### 補充約束（e1 轉 83 要點，2026-10-07；派發後以 SendMessage 告知執行者）

- `builtin_schema_version.json` 取 .1 分支 `tracking_schema.json` 的 `schema_generated_at_framework_version`（2.77.0），不取 `.claude/VERSION`（main 已是 2.77.1）；照 VERSION 設會使內建版本宣稱涵蓋一個不存在的產生版本。
- `builtin_tracking_schema.json` 直接複製 .1 的 JSON（`cmp` 逐位元組一致）；不得在 .2 worktree 執行 `doc schema export` 重產，否則會讀到 2.77.1，JSON 高於內建，App 降級。跑 doc pytest 後須以 `git status` 確認 `tracking_schema.json` 未被改動。
- 合併由 PM（4a）負責，只合併 .2 分支；83 只負責保留 .1 分支 `worktree-agent-ae5483b2aa3aa95e7`。合併後通知 e1 與 83。
- 長期風險（日後重產 JSON 時產生版本高於內建）由 83 開票承接，本票不處理。
