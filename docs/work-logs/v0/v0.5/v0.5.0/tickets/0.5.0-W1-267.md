## Problem Analysis
<!-- Schema[IMP/Problem Analysis]: 選填（小型 IMP 可留 placeholder；大型 IMP 建議填寫）（.claude/pm-rules/ticket-body-schema.md） -->
### 問題根因（PM 前台定位，2026-10-14）

- 被替換的函式是 `agent-ticket-validation-hook.py` 的 `validate_task_dispatch`。258.1（581b62c92）把它的簽名改成 `(tool_input, logger, input_data=None)`，main 改以三個位置參數呼叫 `validate_task_dispatch(tool_input, logger, input_data)`。
- 替身位於 `.claude/hooks/tests/test_deny_output_failure_exit2.py` 的 `_validation_setup`，寫法是 `lambda tool_input, logger: ...`，只收兩個參數，呼叫時拋出 TypeError。這個例外被 run_hook_safely 接住並轉成 exit 1，所以斷言 exit 2 的測試失敗。

### 影響範圍（驗收第 2 項的 grep 結果）

- 執行 `grep -rln validate_task_dispatch .claude --include='*.py'`，排除 worktrees 與 archived 後，命中檔案只有：
  - `test_deny_output_failure_exit2.py`：用 monkeypatch 替換。這是唯一的替身，也是本票的修改點。
  - `test_agent_ticket_validation_hook.py`：直接呼叫真實函式，沒有替身，不需要改。
- 修法：替身改成 `lambda tool_input, logger, input_data=None: ...`，與真實簽名一致。不要用 `*args`，因為簽名再變時 `*args` 會把變化吞掉，測試不會報錯。產品程式碼不動。
