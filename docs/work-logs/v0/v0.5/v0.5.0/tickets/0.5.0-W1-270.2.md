## Problem Analysis
<!-- Schema[IMP/Problem Analysis]: 選填（小型 IMP 可留 placeholder；大型 IMP 建議填寫）（.claude/pm-rules/ticket-body-schema.md） -->
### 根因

`.claude/skills/ticket/hooks/acceptance-gate-hook.py` 的 `is_complete_command()` 只比對 `"ticket track complete"` 與 `"ticket track batch-complete"`（經 `_strip_quoted_spans` 去掉引號內字面）。fast-path（main 開頭）以它判斷要不要做完整驗收，所以 `ticket track finish` 直接 `Fast-path skip`。實證：0.5.0-W1-270.1 在 worktree 內執行 finish，gate 日誌 16:21:35 為「Fast-path skip: 非 ticket track complete 命令」，票即完成。

同檔其他以字面 complete 定位的地方也要一起看：`detect_chained_pre_complete_write()` 以 `command.find("ticket track complete")` 定位串接寫入，finish 時找不到。

`finish` 是 complete 的完全等價別名（同一實作與全部旗標），所以 gate 的語意應是「完成類命令」而非字面 complete。

### 修法

1. 抽出一個辨識完成類命令的單一來源（complete／finish／batch-complete），`is_complete_command` 與 `detect_chained_pre_complete_write` 都用它；引號內字面仍不算。
2. 盤點其他以字面 complete 判定完成命令的 hook：phase4-decision-enforcement、phase-completion-gate、sibling-blockedby-validator、handoff-cleanup、post-ticket-lifecycle、parallel-dispatch-verification、session-context-guard、bare-commit-guard 等（`grep -rln "track complete"`）。阻擋類同批修正；提示類列表，修正與否由 PM 另判。
3. 264.1（6c36af006）已改 gate 讀票面的根，與本票的修改區塊不重疊；本票不動路徑解析。

### 測試（E2）

- 正向對照：IMP 票驗收未勾選，`ticket track finish <id>` 被 gate 擋下（修正前為放行，必須先紅）。
- `finish` 在引號內（如 `--why "... ticket track finish ..."`）不觸發。
- 組合情境：暫存 repo 加 linked worktree，主倉庫票面未勾選、worktree 副本也未勾選時擋下；判定讀主倉庫票面（可參考 `tests/test_acceptance_gate_hook_worktree_state_root.py` 的 fixture）。

### 補充：同一比對函式的誤判（反方向）

2026-10-14 PM 執行 `ticket track append-log 0.5.0-W1-270.2 --section ... "$(cat <<'EOF' ... EOF)"`，heredoc 內文含字面的完成命令字串（本票根因段落的引用），gate 把這條 append-log 當成完成命令，跑了完整檢查並輸出 [Complete 清單]（只有警告，沒有擋下）。`_strip_quoted_spans` 沒有涵蓋 heredoc 內文。修正辨識函式時一併處理：heredoc 內文與引號內字面都不算完成命令，補對應測試（append-log 帶含完成命令字面的 heredoc 不觸發）。
### 設計指定（bb，2026-10-14）

漏判（finish）與誤判（heredoc 內文）同一根因：以子字串比對整條命令文字，與 232 的 pre-test-hook 同型。不另寫判定，改走既有共用解析器：
- `.claude/lib/git_command_parse.py` 的 `parse_command_statements`：依引號規則切 token，以 `; & | ( )` 與換行切敘述，heredoc 與引號內文字不視為命令（gate 已 import）。
- `.claude/lib/test_command_parse.py` 的 `skip_prefix_wrapper_count`：處理 env、nohup、time 等前綴。
- 判定改為「敘述開頭（去前綴後）的 token 序列為 ticket track 加上 complete、finish 或 batch-complete」。

驗收正反對照：finish 與 complete 都觸發完整檢查；append-log 的 heredoc 內文含完成命令字面不觸發。另建的其他 hook 票同樣改走共用解析器。
