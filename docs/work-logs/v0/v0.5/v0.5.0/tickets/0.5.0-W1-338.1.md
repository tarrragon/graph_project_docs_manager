## Solution
<!-- Schema[IMP/Solution]: 選填（.claude/pm-rules/ticket-body-schema.md） -->
實作：ticket_system/lib/file_contention.py（git log 量法、票樹根、聚合檔常數、渲染）；track_conflicts.py 只呼叫與輸出，新增 --since-days（預設 14）；JSON 輸出有紀錄時多一個 contention 鍵，conflicts 鍵不變。
取捨：
- 票樹根用正則取 版本-波次-序號 第一段，不依賴 .N 切割（版本號本身含點）；chore( 開頭 commit 排除。
- 只對衝突命中檔統計（matched_files，含 a ~ b 拆開），不掃全庫；目錄宣告因 git 路徑為檔案而自然無命中。
- 聚合檔：基名集合 + *registry*/*index* 樣式 + docs/work-logs/v*/ 直接子層 md（版本日誌），常數集中在模組頂部。
- git 失敗拋 ContentionUnavailable，由 conflicts 在 stderr 印一行並略過，原輸出與 exit code 不變。
陷阱：
- 無衝突時不跑 git（避免每次查詢多一次 log 成本）。
- 既有測試的 project_root=/proj 非 git，會多一行 stderr，不影響斷言。
- fixture 巢狀目錄 mkdir 需 parents=True。
- 在 worktree 跑 ticket CLI 會作用於主倉庫，實跑樣例反映主倉庫 log。
測試：test_file_contention.py 11 項（E1 同票樹 vs 不同票樹、聚合/非聚合、chore 排除、非 git 降級）+ test_track_conflicts.py 全綠，共 50 passed。
文件待補：track-command-session.md 於本 worktree 不存在，未改文件。
