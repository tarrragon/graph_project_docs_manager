## Problem Analysis
### 問題根因

ticket 與 log 的讀者多半是下一個 session 或代理人。讀者讀錯或需要追問時，交接就會失真。asd-ste100 1.0.0 已有 zh-TW pack（句子規則與詞庫），但沒有證據顯示它能讓讀者讀得更準或更快。本票用實測取得這項證據。

### 影響範圍

- 受影響：asd-ste100 skill 的適用範圍、`language-constraints` 規則 1（只有在英文 STE 組明顯勝出時才需要另開票）。
- 已驗證：無。
- 未驗證：zh STE 改寫能提高答對率或減少追問；英文 STE 對 Haiku 讀者是否較易讀。

### 相關 Error Pattern

PC-168（少量綠燈不等於穩定）：樣本少時的連勝不可當結論。本票每格 3 名讀者、8 段素材，取樣與判定規則都在開跑前寫定。

### 查重紀錄

查重關鍵字：`STE`、`詞庫`、`controlled language`、`翻譯`。dedup 列出 21 個 issue（#48–#109），標題都不涉及受控語言或寫法實測，關係判定：無關，不引用。

**評分方式**：
1. 腳本比對：作答含答案鍵的關鍵詞即判對。不一致的作答，由 PM 在隱藏組別的清單上人工判讀。
2. 答對率：每組 72 個作答（8 段 × 3 題 × 3 名）中答對的比例。
3. 一致率：每組 24 格（段 × 題），3 名讀者判讀結果相同（全對或同一錯答）的格數比例。
4. 追問數：第 4 題中非「無」的條目數。
5. 讀者 token：取 Agent 結果回報的用量；沒有回報就記「未取得」，改用題卷長度。
6. 改寫長度：依 zh-TW-rules 規則 8 計數（中文字、英文詞、一段行內程式碼各 1 單位，標點不計）。

**判定規則**（開跑前定）：
- zh 的答對率不低於現行，而且追問數不多於現行 → ticket/log 採 zh STE。
- zh 答對率比現行低 5 個百分點以上 → 不採用，維持現行寫法。
- 介於兩者之間 → 差異不足，維持現行寫法，asd-ste100 作為可選工具。
