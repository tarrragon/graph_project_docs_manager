## Solution
<!-- Schema[IMP/Solution]: 選填（.claude/pm-rules/ticket-body-schema.md） -->

改法（where.files 依 NC-1 更正版，330e1a47d）：

- `types/index.d.ts`：BoardSnapshot 的 ready 分支加必填欄位 `ticketPrefix: string`。
- `hooks/register.tsx`：`refresh()` 組 ready snapshot 時填 `ticketPrefix: ticketPrefixOf(config.coordinationTicket) ?? ''`。readProjectConfig 已確認協調票推導得出前綴，`??` 只用於型別收窄。readProjectConfig 未改。
- `hooks/dispatch.ts`：移除 `TICKET_PREFIX` import。`dispatchRows` 加第三個參數 `ticketPrefix: string`，`shortTicketId(id, prefix)` 改用它。DispatchContext 與 LayoutContext 未變，layout.ts、lanesView.tsx 未改。
- `hooks/dispatchView.tsx`：呼叫時把 `board.ticketPrefix` 當第三個參數傳入。
- shared.ts 的 `TICKET_PREFIX` 定義保留（刪除屬 485.7.2；lanes.ts 仍在用）。
- 測試：
  - dispatch.test 既有呼叫補傳前綴，另新增 E1：同一批紀錄分別以 `0.5.0-W1-`、`0.6.0-W2-` 呼叫，斷言兩次任務欄不同，且各自只去掉該前綴。
  - boardDispatch.test 新增 E1，以設定檔驅動：先以協調票 `0.5.0-W1-349` 讀取，再把設定檔改為 `0.6.0-W2-349` 重讀，斷言同一批派發列的短票號跟著改變。改動前前綴是常數，第二次讀取的結果會與第一次相同，這個測試會失敗。
