## Task Summary

build_lib_dependency_index 以 lib 子模組 stem 加 lib 作為 local_names，未使用 build_local_module_index 的全域本地索引，致 lib 模組內以 sys.path.insert 掛載的 doc_system 被判外部依賴；改傳全域 local_names

## Problem Analysis
<!-- Schema[IMP/Problem Analysis]: 選填（小型 IMP 可留 placeholder；大型 IMP 建議填寫）（.claude/pm-rules/ticket-body-schema.md） -->
### 追加觀察（2026-10-19，來源 338.2.4 拆分 tripwire hook）

hook 拆成「hook 檔 + 同目錄套件」後，hook-dependency-isolation-check 暴露兩個盲點，與本票修的本地模組名單同屬一支檢查器：
1. 只掃 hook 檔本身的 import：yaml 搬到套件內的 config.py 後，hook 檔不再 import yaml，但 PEP 723 宣告仍必須保留；目前沒有機器檢查「套件內 import 與 hook 的 PEP 723 宣告一致」，宣告被誤刪不會告警。
2. 拆出的新模組 stem（config、state、signals、render）會進全域本地模組索引；之後任何 hook import 同名的外部套件，會被當成本地模組而漏報。
建議本票修法一併評估：本地模組判定改以「相對於 hook 目錄可解析」為準，而非全域 stem 集合；掃描範圍擴及 hook 同目錄套件。
