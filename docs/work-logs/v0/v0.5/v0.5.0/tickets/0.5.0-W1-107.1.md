# Execution Log

## Task Summary

agent-ticket-validation-hook 的 check_depth_descend 由「can_descend(被派發票)為 False 即擋」（depth >= MAX）改為「被派發票 depth > MAX 才擋」，與 AGENT_PRELOAD D3（can_descend 判斷呼叫者持有的票）對齊；ticket_id_allocator 建立端警告門檻由 new_depth >= MAX 改為 > MAX；兩端訊息文案說明同一判準

---

## Problem Analysis
<!-- Schema[IMP/Problem Analysis]: 選填（小型 IMP 可留 placeholder；大型 IMP 建議填寫）（.claude/pm-rules/ticket-body-schema.md） -->
根因：check_depth_descend 對被派發票呼叫 can_descend（depth < MAX），比 AGENT_PRELOAD D3 多算一層，深度 3 的票不論誰派都被擋。裁決 E：被派發票 depth > MAX 才擋；建立端 create --parent 警告門檻同改為 new_depth > MAX。fail-open 分支原僅 logger.info，已補 stderr 與 warning 日誌。

## Solution
<!-- Schema[IMP/Solution]: 選填（.claude/pm-rules/ticket-body-schema.md） -->
修法（實作 commit 822740b17，ticket skill 2.44.45，合併 2960a9b8e）：

- `agent-ticket-validation-hook.py`：`check_depth_descend` 改以 `compute_depth` 判斷被派發票 depth > MAX_TICKET_DEPTH 才 deny（移除對被派發票呼叫 `can_descend`），與 AGENT_PRELOAD D3 對齊；兩條 fail-open 分支（模組不可用、計算異常）改為 stderr 警告加 `logger.warning`
- `ticket_id_allocator.py`：建立端警告門檻改為 new_depth > MAX；`messages.py` 的 `DEPTH_LIMIT_REACHED` 改為「超過」判準
- `references/track-command.md` 深度段同步；SKILL.md 與 CHANGELOG（CHANGELOG 首次 commit 含票號被規則 8 守衛擋下，改日期標記）

- E1／E2：實作前 6 failed 12 passed（深度 3 仍 deny、深度 4 訊息判準、建立端深度 3 仍 warn、兩條 fail-open 無 stderr），實作後全綠；執行者發現 E1 一度因 hook 內真實 `can_descend` 未被 patch 而假綠，改為同時 patch 兩處才確認真紅

- 失敗語意：深度模組不可用或計算異常時 fail-open 放行，stderr 與日誌雙通道可見；產生路徑盤點表見 how.strategy
