## 重現實驗結果
### 實驗方法

1. 列出兩個測試根的 `.py` 檔名：`ls .claude/skills/ticket/tests` 與 `ls .claude/skills/ticket/ticket_system/tests`，兩邊都加 `LC_ALL=C sort`，再用 `comm -12` 取交集
2. 對每一對同名檔做三項檢查：
   - 用 `grep -oE "def test_[a-zA-Z0-9_]+"` 取出測試函式名的交集
   - 讀檔頭 docstring，確認測的是哪個面向
   - 測試函式的總數
3. 查 pytest 設定：`pyproject.toml` 的 testpaths，以及兩個目錄有沒有 `__init__.py`

### 實驗執行

- 檔數：tests/ 有 169 個 `.py`，ticket_system/tests/ 有 148 個 `.py`，同名 9 個
- pytest 設定：`testpaths = ["tests", "ticket_system/tests"]`，兩棵在同一次 pytest 執行
- `__init__.py`：tests/ 有，ticket_system/tests/ 沒有。兩邊模組名分別是 `tests.test_x` 與 `test_x`，不會撞名，同名檔在技術上可以並存

| 同名檔 | tests/（A）測試數與面向 | ticket_system/tests/（B）測試數與面向 | 同名函式 |
|-------|------------------------|--------------------------------------|---------|
| conftest.py | 根 fixture | 子目錄 fixture | — |
| test_create_hook_acceptance_template.py | 8：觸及 hook 本體時帶入模板（E1 對照） | 3：模板去重不受核取框前綴影響（379 新建） | 0 |
| test_handoff_from_worklog.py | 2：交接段落掃描範圍 | 8：--from-worklog CLI 邏輯 | 0 |
| test_hook_logs_isolation.py | 2：根 conftest 的隔離契約 | 4：不產生巢狀 hook-logs 副產物 | 0 |
| test_identity_guard.py | 22：check_identity 五情境 | 25：分命令轉為強制申報 | 0 |
| test_ticket_validator.py | 63：ID 格式與必填欄位 | 71：_is_placeholder 與 execution log | 0 |
| test_track_batch.py | 15：batch-claim／complete | 7：registry lease 接線 | 0 |
| test_track_board.py | 41：看板渲染 | 14：主題分組模式 | 0 |
| test_track_runqueue.py | 37：runqueue 核心行為 | 73：_render_list 的 resume 過濾 | 0 |

### 實驗發現

已驗證：
- 8 對測試檔都沒有同名的測試函式，各自測同一模組的不同面向，彼此不重複，也不矛盾
- 同名檔共存並非 pytest 設定錯誤，而是缺少命名約定
- 失效形態與 0.5.0-W1-384 相同：改某模組的行為或字面時，只找到一份同名檔，就誤以為已經改過那一份

## Solution
<!-- Schema[ANA/Solution]: 必填（.claude/pm-rules/ticket-body-schema.md） -->
### 結論（狀態 a）：改名，不合併；另加同名防護測試

| 同名檔 | 判定 | 理由 |
|-------|------|------|
| conftest.py | 保留 | pytest 以目錄劃分 fixture 範圍，兩棵各需一份屬慣例 |
| 其餘 8 對 | B 側（ticket_system/tests）改為面向化檔名 | 測試函式名沒有交集，面向各自獨立。合併後單檔會超過 100 個測試，徒增認知負擔；改名就足以消除「只找到一份」的混淆 |

- 源頭防線：新增一支守衛測試，斷言兩個 testpaths 之間沒有同名的 `test_*.py`（conftest.py 豁免），之後新建同名檔時會直接轉紅
- 與 L6 的 0.5.0-W1-395 分工：
  - 395 處理「怎麼找到相關測試」：以改動物字面 grep 所有測試目錄
  - 400 處理「從源頭消除同名檔」
  - 兩者互補。即使改名，同一模組的測試本來就分散在兩棵，找法仍要靠 395 的 grep；改名只是消除「同名就以為已改過」的誤判
- 不需改的部分：兩個測試根的分工。tests/ 的歷史較早，ticket_system/tests/ 的測試貼近 commands 層，這只是目錄由來，不是明文規範。改名加守衛已能消除混淆，另訂分工屬額外約束，不在本票要求內
