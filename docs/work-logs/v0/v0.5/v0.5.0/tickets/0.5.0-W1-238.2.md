<!-- Schema[DOC/Solution]: 免填（DOC 類型以變更摘要取代）（.claude/pm-rules/ticket-body-schema.md） -->
### 實作

在 `.claude/references/bash-tool-usage-details.md`〈兩段式合併禁令（MERGE_HEAD 空窗）〉之下新增變體小節「合併途中 HEAD 被他方推進（update_ref 失敗）」，內容依序為：
- Why／Consequence／Action。
- 辨識訊號三項。
- 禁止事項。
- 兩種處置與選擇判準；處置一列出五個編號步驟，並寫明 tree 等於第一親代時改走處置二。
- 預設路徑改指 worktree skill 的 `merge` 子命令。
- 手寫 CAS 腳本在 zsh 未做字詞切分而產生空合併的陷阱。

檔尾的版本紀錄補一行 1.17.0。提交為 4e50af88a。

### 寫作審查（basil-writing-critic）

共 4 項發現，最高為中，處置如下：
1. 處置一的儲存格塞了五個有序步驟，條件分支也被壓在括號裡（DOC-GPD-006）→ 已修：儲存格只留摘要，步驟改為表格下方的編號清單，並寫明分支。
2. 兩種處置缺少選擇判準 → 已修：補上「處置的選擇」一段。
3. Why 段的 update_ref 容易被讀成可執行指令 → 已修：改寫為「git 內部的 update_ref 步驟」，與步驟中的 `git update-ref` 分開。
4. 同節上文（不在本次新增範圍）引用的 IMP-V1-005 是否已同步到 canonical → 無需建 ticket：該檔存在於 `.claude/error-patterns/implementation/`，且自動載入的 `bash-tool-usage-rules.md` 主文早已引用同一編號並通過 rule8 守衛；這是既有引用，不是本次新增。
