## Problem Analysis
<!-- Schema[IMP/Problem Analysis]: 選填（小型 IMP 可留 placeholder；大型 IMP 建議填寫）（.claude/pm-rules/ticket-body-schema.md） -->
### PM 審查（2026-10-15）

- 沿用判定的信任基礎：沿用規則與首次選套件共用同一套 select_suites 判準（「若這段差異單獨合併，此套件會不會跑」），因此沿用範圍與首次選擇範圍一致。相較舊規則只沿用守衛測試涵蓋的豁免檔，新規則以套件選擇規則為準，其正確性等同首次選擇的正確性。
- 成本變化：全部套件都沿用時，現在仍會建立快照，因為 select_suites 需要在快照內掃描匯入關係。舊規則只在豁免差異時才沿用，且直接跳過快照。每次建立快照約需數秒，相較重跑一個套件可以忽略，判定為可接受。
- SKILL.md 在本票 where.files 內，已要求實作者在同一分支同步 CAS 重試描述，不另開 DOC 票。

## Solution
<!-- Schema[IMP/Solution]: 選填（.claude/pm-rules/ticket-body-schema.md） -->
MergeGate.verified_commit 改為 verified_suites（套件 -> 最近一次確認綠燈或沿用的合併 commit）。每次嘗試：以既有 select_suites 取本次套件集合；各套件以「該套件上次驗過的 commit -> 新 commit」的差異再跑 select_suites，不含該套件即沿用（輸出「套件 X：沿用｜沿用 <sha> 的驗證結果」並延伸驗證 commit），否則重跑。_run_suites 增 on_green 回呼，後面套件紅燈時前面已綠者仍留紀錄。名額 hold、豁免清單、CLAUDE_SLOT_HELD_BY 未動。沿用行不符綠燈正則，不污染名額預估。
