## Solution
<!-- Schema[IMP/Solution]: 選填（.claude/pm-rules/ticket-body-schema.md） -->
### 實測依據
以 claude -p 搭配 --settings 註冊 dump hook（UserPromptSubmit、Stop），記錄 stdin 與環境變數：
- UserPromptSubmit payload 鍵：session_id、transcript_path、cwd、prompt_id、permission_mode、hook_event_name、prompt。無 transcript 欄位。
- Stop payload 鍵：同上加 effort、stop_hook_active、last_assistant_message 等；有 transcript_path。
- 兩事件的 hook 行程中 CLAUDE_TRANSCRIPT_PATH 皆為 UNSET。
- transcript_path 為 session JSONL 檔（行形狀 type + message.role/content blocks）。

### 改法
- language-guard-hook.py：extract_previous_assistant_message 改讀 payload.transcript_path，經 lib.transcript_tail_reader.read_last_assistant_text 取最後一則 assistant 文字；無路徑、檔案不存在、解析失敗皆 fail-open 並 logger.info。不改 306.4 的 additionalContext 輸出。
- evaluate-session.py：stdin payload 一次讀入（_read_payload），transcript 來源改 payload.transcript_path，移除 CLAUDE_TRANSCRIPT_PATH 讀取；缺失時 stderr 一行並 exit 0。stop_hook_active 檢查保留。
- 測試：fixture 改實測 payload 形狀並建臨時 JSONL；新增 E1 對照（前一輪違規觸發 vs 最新乾淨不觸發）、無 transcript_path 不輸出、檔案不存在 fail-open、舊 transcript list 欄位被忽略；evaluate-session 測試移除環境變數、補無路徑與檔案缺失對照。grep 全 .claude 的 CLAUDE_TRANSCRIPT_PATH 與 "transcript": 特徵，僅此兩測試檔依賴舊欄位，已更新。

### 實地觸發方式（PM 合併後）
合併並 sync 後，在新 session 送一則 prompt（前一輪回應含 emoji 或「通常來說」），檢視 .claude/hook-logs/language-guard-hook/ 當日日誌：不應再出現「無 transcript 或 transcript 為空」，應見警告計數與下一輪 additionalContext 提醒（注意每 10 次觸發抽樣 1 次）。evaluate-session：長 session 結束時看 Stop additionalContext 是否出現 [ContinuousLearning]。
