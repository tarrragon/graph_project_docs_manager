### 用戶需求補充：看板 plugin 預設載入（2026-10-21，主控經 claude-code-guide 查官方文件）

用戶要求不必再以 `claude --plugin-dir` 啟動，開啟專案就自動載入。官方文件可行的做法：

| 問題 | 答案 | 來源 | 可信度 |
|---|---|---|---|
| 專案設定能否宣告本地 marketplace 並自動啟用 | 可以。`.claude/settings.json` 的 `extraKnownMarketplaces` 宣告 marketplace（source 類型含 `directory`、`file`、`settings`），再用 `enabledPlugins` 寫 `"<plugin>@<marketplace>": true` | https://code.claude.com/docs/en/settings-reference.md 、https://code.claude.com/docs/en/plugin-marketplaces.md | 高（schema）；`directory` 的相對路徑以哪裡為基準，文件沒寫 |
| marketplace.json 位置 | `<marketplace 根>/.claude-plugin/marketplace.json`。plugin 的 source 路徑不得含 `..`，所以 marketplace 根必須是 plugin 目錄的上層 | 同上 | 高 |
| 首次信任 | 在用戶接受該資料夾的 workspace trust 之前，repo 宣告的 marketplace 會被靜默忽略，`-p` 也一樣。相對路徑的 plugin 不需另外安裝 | https://code.claude.com/docs/en/plugins/loading.md | 高 |
| 有沒有和 `--plugin-dir` 等效的設定鍵 | 沒有。環境變數 `CLAUDE_CODE_PLUGIN_DIRS` 有同樣效果，但只限單一 session，路徑必須是絕對路徑或 `~` | https://code.claude.com/docs/en/env-vars.md | 高 |
| repo 內修改 plugin 會不會自動生效 | 本地路徑 marketplace 的相對路徑 plugin 會原地載入、不複製，下次啟動或執行 `/reload-plugins` 就生效。git 來源或複製安裝的則有版本快取 | https://code.claude.com/docs/en/plugins/loading.md | 中高（`directory` 宣告是否算原地載入，文件沒明寫） |

列入 485 的規劃：
- 預設載入的設定，要等框架內的位置定案後才寫，因為 marketplace 根與 plugin 的 source 路徑都取決於位置。
- `.claude/settings.json` 會不會隨 sync 傳到 consumer，決定這個預設載入是本專案專屬，還是所有 consumer 共用。要先查 sync 的涵蓋範圍再決定。
- 原地載入不會自動安裝 npm 依賴，要確認看板程式在 runtime 有沒有依賴需要安裝。
- 驗證：第一次用 `claude plugin marketplace add` 確認相對路徑以哪裡為基準；接受 trust 之後，不帶 `--plugin-dir` 啟動時，側邊欄要出現看板（實機驗證，由用戶確認）。

### 決策一：框架內位置與載入方式

| 方案 | 做法 | 利 | 弊 |
|------|------|----|----|
| A（建議）skills-dir plugin | 移到 `.claude/skills/line-board/`（含 `.claude-plugin/plugin.json`、`hooks/`、`tests/`），manifest 設 `defaultEnabled: false`；本專案在 `.claude/settings.local.json` 寫 `enabledPlugins` 的 `"line-board@skills-dir": true` | 不需 marketplace 宣告；相對路徑基準問題不存在；consumer sync 後預設不啟用，各自選擇開啟；使用說明可直接寫在同目錄 SKILL.md | 同一目錄兼 skill 與 plugin 的行為未實測；skill 類 SessionStart 檢查可能報警 |
| B marketplace | 移到 `.claude/plugins/line-board/`，`.claude/plugins/.claude-plugin/marketplace.json` 列出它，settings 寫 `extraKnownMarketplaces` 與 `enabledPlugins` | `.claude/plugins/` 已有三個 LSP plugin 的先例；不涉 skill 檢查 | `directory` source 的相對路徑基準文件未寫，需實測；寫進 settings.json 會 sync，寫進 settings.local.json 則每台機器各寫一次 |

A 的前提是實測通過：專案層 skills-dir plugin 在 `defaultEnabled:false` 時不載入、`settings.local.json` 啟用後載入；SKILL.md 與 plugin 共存時兩者都生效。實測不通過則改 B。

### 決策二：consumer 是否預設啟用

看板在 `session.start` 會自動開 Pane。建議預設不啟用（A 的 `defaultEnabled:false`），本專案以 `settings.local.json` 啟用；另加防護：讀不到專案設定時不自動開 Pane、`/board` 顯示「尚未設定協調票」。若用戶要所有 consumer 預設啟用，這屬跨專案行為變更，需用戶裁定。

### 決策三：設定機制（協調票）

只有協調票 ID 是專案值（票目錄、短票號前綴由它推導；閘門日誌路徑為框架慣例，不列設定）。`userConfig` 只能存 user 層，排除。

| 方案 | 做法 | 弊 |
|------|------|----|
| C1（建議）`.claude/project-integration/multi-session.json` | `{"coordinationTicket": "<票號>"}`；看板與 `statusline_lane.py`（未給 `--coord-ticket` 時）共讀；不 sync | rule8 守衛不豁免 `project-integration`，寫入會被擋。需讓守衛豁免路徑區段 `project-integration`（與 sync manifest 的 PER_PROJECT_PATTERNS 同判準：不 sync 就沒有跨專案失效軸）。這是守衛放寬，須附正向對照，屬共用守衛的行為變更 |
| C2 專案目錄的設定檔 | 放在 `.claude/` 以外（如 repo 根 `.line-board.json`） | 不動守衛，但框架看板讀專案根目錄的自訂檔，位置慣例要另外約定；放 `docs/` 則觸發 flutter 閘門套件 |

### 決策四：合併閘門套件改指

`.claude/project-integration/merge-gate.yaml` 的 `line-board` 套件：`prefixes` 改為新位置（A：`.claude/skills/line-board/`），`command` 改 `[claude, plugin, test, .claude/skills/line-board]`，summary、failure 不變。該檔不 sync，consumer 自行加套件，寫進使用說明。此為所有線共用的設定，依主控指示合併前先回報主控。

### 決策五：使用說明載體

A 成立時寫在 `.claude/skills/line-board/SKILL.md`（啟用方式、設定檔、閘門套件範例、佇列行格式路由至 multi-session-orchestration）；multi-session-orchestration〈按需讀取〉加一列路由。依 skill-design-guide 判準於落地子票複核 description 預算。
