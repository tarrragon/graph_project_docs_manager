## Solution
<!-- Schema[IMP/Solution]: 選填（.claude/pm-rules/ticket-body-schema.md） -->
修改 phase4-decision-enforcement-hook.py 的 extract_ticket_targets_from_command：動詞參數中取符合 TICKET_ID_PATTERN 的非旗標 token，complete/finish/batch-complete/phase 皆收集全部符合者；phase 形態改判斷參數含 phase4 字樣。測試：新增 option-value 正向對照（--as X、--version X、--as OK BAD、等號形式、選項在 ID 後）與無 ID/phase3b 負向；既有測試的合成 ID（TST-001、T-1 等）不符 TICKET_ID_PATTERN，依約束「不以 TICKET_ID_PATTERN 以外方式辨識 ID」改為 0.1.0-W1-NNN 形式（斷言語意不變）。

### 自檢結果
- 4 種帶值選項寫法端到端回 2，complete OK 與 phase OK phase4 回 0。
- 失敗語意：掃描回空清單維持 fail-open；hook 例外行為未動；無 ID 的命令（如 complete --as X）回空，與舊版查無票略過同向。
- 未改 .claude/lib/。

### Phase 4 結論
重構需要：否。技術債務：無新增。程式碼品質：A。結論：改動集中於單一函式，邏輯較舊版更簡短。
