session-context-guard-hook 與 phase4-decision-enforcement-hook 的完成命令辨識改走共用解析器並涵蓋 finish 別名

## Problem Analysis
<!-- Schema[IMP/Problem Analysis]: 選填（小型 IMP 可留 placeholder；大型 IMP 建議填寫）（.claude/pm-rules/ticket-body-schema.md） -->
### 兩支 hook 現況（PM 查證，2026-10-14）

| hook | 事件與語意 | 現行辨識 | 漏判後果 |
|------|-----------|---------|---------|
| `.claude/hooks/phase4-decision-enforcement-hook.py` | PreToolUse 對完成命令做殘留二次掃描，命中 MUST-block（M1-M4）時 exit 2 阻擋；主觸發為 PostToolUse 的 `ticket track phase <id> phase4` | 已 token 化（自有 `_tokenize_statements`：strip_heredoc_bodies + shlex），以 `statement[2] == "complete"` 固定位置比對；不處理 env、nohup 等前綴 | finish 收尾時 Phase 4 結論的延後語意殘留不被掃描，阻擋失效 |
| `.claude/hooks/session-context-guard-hook.py` | PostToolUse，計數本 session 完成的票，達閾值提示 handoff；不阻擋（盤點時歸為阻擋類有誤，本票照修） | `COMPLETE_COMMAND_PATTERNS` 子字串比對 `ticket track complete`、`ticket complete`；成功標記為輸出含「已完成」 | finish 完成的票不計數；子字串比對另會把引號或 heredoc 內文誤判 |

### 修法

兩支都改用 `.claude/lib/git_command_parse.py` 的 `parse_command_statements` 切敘述、`skip_prefix_wrapper_count` 去前綴，判定敘述開頭為 ticket track 加上 complete、finish 或 batch-complete（與 acceptance-gate 的 `_statement_complete_verb` 同一判定）。phase4 的 `ticket track phase` 辨識沿用同一套解析，不另寫。是否抽出共用函式給三支 hook 共用，由實作者評估並在 Phase 4 記錄；抽出時放 `.claude/lib/` 並保持 acceptance-gate 行為不變。

### 測試要求（參考 TEST-GPD-004）

E2 斷言要比對結構化決策或具體副作用：phase4 斷言 exit code 2 與 stderr 的阻擋訊息；session-context-guard 斷言計數檔或輸出的計數值。不得以輸出含某個字樣斷言決策。

## Solution
<!-- Schema[IMP/Solution]: 選填（.claude/pm-rules/ticket-body-schema.md） -->
新增共用 .claude/lib/ticket_command_parse.py（complete_statement_args / is_complete_statement / has_complete_command，判定同 acceptance-gate 的 _statement_complete_verb，未改 acceptance-gate）。
- phase4-decision-enforcement-hook（PreToolUse/PostToolUse，M1-M4 命中 exit 2 阻擋）：extract_ticket_id_from_command 改走 parse_command_statements + skip_prefix_wrapper_count；complete/finish/batch-complete 皆進 residual_gate；phase4 主觸發也去前綴；刪除自有 _tokenize_statements。解析失敗仍 (None,None)=fail-open（不變）。
- session-context-guard-hook（PostToolUse，不阻擋，exit 0）：子字串比對改走共用解析；解析失敗視為非完成命令（本就不阻擋，不變）。

### 自檢結果
兩 hook 事件類型與阻擋語意已確認如上；引號、heredoc 內文不辨識；失敗語意不變且有測試。

### Phase 4 結論
重構需要：否（共用函式已抽出至 lib；acceptance-gate 因約束未改）。技術債務：acceptance-gate 與 lib 兩份相同判定，後續可收斂。品質 A。
