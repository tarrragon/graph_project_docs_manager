## Context Bundle

### 派發前定稿（2026-10-12，基準 main 含 114.7、W1-139 規格）
來源：0.5.0-W1-114.15 Context Bundle〈PM 處置（e1，2026-10-09）〉第 4、5 項原樣移入本票（e1 同意 2026-10-12）；SPEC-003 §2.4（載入態最短存續）、§2.5（取消 C1～C8，「丟棄結果」即滿足）。

#### 範圍
- 新增 `lib/app/scan_round.dart`（識別名由執行者定）：一輪＝讀型別表 → `scanCorpus` → `buildGraph`，產出不可變的輪次結果（至少含 CorpusScanResult、GraphBuildResult、型別表來源判定結果與是否降級、輪次所屬工作區）。
- 型別表：沿用 `lib/schema/schema_source_resolver.dart` `resolveSchemaSource`（與 Domain 視圖關卡同一來源）；使用者選「以 App 內建型別表檢視」（`degradedSchemaProvider` 為真）時，以內建表作為專案型別表傳入（SPEC-007 FR-01）。`scanCorpus` 的 `builtinTable` 必填。讀取失敗或缺席走既有關卡，本票不另定。
- 檔案系統以既有 `DocsFileSystem` 抽象注入（測試用假檔案系統，不讀真實磁碟）；工作區根目錄取自既有工作區狀態（WorkspaceReady.path）。
- 開始時機：任一消費者需要資料且目前工作區沒有輪次時開始；已有完成輪次直接回傳，不重掃。
- 失效：切換工作區（新輪次）、手動「重新掃描」（新輪次）。「再次可見自動重掃」屬 system-layer §6 待決，不在本票。
- 取消：0.5.0 不為 scanCorpus 新增取消參數；取消時丟棄該輪結果即可（SPEC-003 §2.5）。

#### 期望紅燈（main 現況：無輪次 provider，buildGraph 在 lib 無呼叫端）
| # | 案例 | 期望 |
|---|------|------|
| R1（E1） | 同一輪兩個消費者讀取 vs 一個消費者讀取 | scanCorpus 與 buildGraph 各只被呼叫一次（以計數替身斷言兩情境次數相同） |
| R2 | 已有完成輪次時再次讀取 | 不重掃（呼叫次數不增） |
| R3 | 切換工作區 | 舊輪次失效、開新輪次（呼叫次數＋1，結果屬新工作區） |
| R4 | 手動重掃 | 開新輪次 |
| R5（E1） | 降級旗標真／假 | 前者以內建表作為專案型別表傳入；兩情境 scanCorpus 收到的 table 不同 |
| R6 | 取消 | 該輪結果被丟棄，不寫入 provider（之後讀取開新輪次） |
| R7（守衛） | import 方向 | lib/app 為編排層；corpus／graph／diagnostics／schema／layout 不 import lib/app、lib/screens（含 E2 違規樣本，比照 graph_import_direction_test 遞迴寫法） |

- 不含：報告頁消費（114.15）、Domain 視圖消費（114.14）、投影（114.20）。
- 回報必附：輪次結果公開形狀與 provider 識別名（供 114.14／114.15 引用）。
