## Solution
<!-- Schema[IMP/Solution]: 選填（.claude/pm-rules/ticket-body-schema.md） -->
實作於 worktree 分支 worktree-agent-afdffaeda7f7aeaec，commit d5859c58bcd2cd0794760d91555b2f8f0d33d3f2（只改 where.files 三檔）。

GitInvocation 新欄位（皆有預設值，既有欄位與 dash_c_path 語意不變）：
- dash_c_paths: Tuple[str, ...]，預設空 tuple。全部 -C 依出現順序。
- effective_dir: Optional[str]，預設 None。基準目錄依語句前的 cd 與全部 -C 依 git 語意串接（絕對路徑取代、相對路徑接續，~ 展開）。基準來自 find_git_invocations 新增的選用參數 base_dir（預設 None，payload cwd 由呼叫端傳入）。無 base_dir 且無 cd 與 -C 時為 None；有 base_dir 且無變動時等於 base_dir；dir_unknown 為真時為 None。
- dir_unknown: bool，預設 False。目錄含 $ 或反引號、cd 無參數或 cd -、popd、cd 在 || 前後、或結果來自 shell 別名時為真。
- cd 作用域：括號與管線兩側的 cd 不外溢；bash -c 與 eval 內的 cd 不外溢。
- 別名：git config --get alias.X 於 effective_dir（未知時用 base_dir）讀取；一般別名展開後以展開序列重新解析（statement 為展開後序列，args 含別名預設旗標）；! 開頭別名內容當腳本遞迴解析，命中者標 dir_unknown 並清除 effective_dir，內容解析不出 git 呼叫者不命中。讀取失敗（無 git、逾時 2 秒、非 repo）一律視為無別名，不拋例外。git 內建子命令不查別名。
- 遞迴深度上限 5。parse_command_statements 與兩函式既有回傳形狀不變。

每個使用者受影響的寫法（原漏判，現命中）：/usr/bin/git X、command git X、exec git X、bash|sh|zsh -c 'git X'（含 -lc 與絕對路徑 shell、巢狀）、eval 'git X'、git <使用者別名> 與 shell 別名。此外 cd X && git 與 git -C a -C b 的 effective_dir 才有新語意，原命中不變。受影響使用者共 12 個：bare-commit-guard、bash-git-add-broad-guard、bash-git-protected-branch-guard、commit-stage-guard-gate、global-pkill-guard、git-index-lock-cleanup、merge-staged-index-guard、phase4-decision-enforcement、workspace-wipe-guard、lib/test_command_parse、acceptance-gate、needs-context-listener。其中阻擋型守衛現在會開始擋上述寫法（預期效果）；git-index-lock-cleanup 與 skill hooks 為資訊型，只是多取到 -C 路徑。
已知殘留：變數或命令替換組成的命令、shell 函式型別名（! 開頭且非 git 直接呼叫）、& 背景符號串接的語句（既有行為）。
供 E 線 0.5.0-W1-189.1：新增欄位純為資料，不影響 hook 啟動方式；呼叫端要用 effective_dir 須傳 base_dir。

Phase 4：重構需要 否；技術債務 發現：&、{ } 語句邊界未處理（既有，未擴大）；程式碼品質 A；結論：無需重構。0.5.0-W1-263 負責 bare-commit-guard 改用 effective_dir 與 dir_unknown 策略。

審查修正（commit e192fbadee7dda6fe81bd8cb2658fd845176281c，接在 d5859c58b 之後）。

取捨與做法：
1. 無法解析一律回 None：內部以 _Unparseable 例外傳遞，find_git_invocations 捕捉後記 warning 並回 None（公開 API 不拋例外，回傳形狀不變）。觸發情形：巢狀深度達 5、巢狀腳本無法 tokenize、別名鏈達 5 層（含別名迴圈）、別名查詢超限、別名讀取逾時。逾時原先視為無別名（放行），改為無法判定。無 git 等其他讀取失敗仍視為無別名。
2. 別名查詢：每次解析有 (目錄, 名稱) 快取；實際讀取上限 8 次、累計時間上限 3 秒、單次逾時由 2 秒降為 1 秒。超限回 None。最壞情況耗時約 3 秒加一次逾時，不再是 N 乘 2 秒。內建子命令清單擴充（plumbing 與常見指令），減少不必要查詢。
3. 對 8 支阻擋型守衛的影響：以下輸入原本回 [] 或漏判（放行），現在回 None，各守衛依自身 None 處置（並行期保守擋下，或各自既有 fail 策略）：嵌套超過 5 層的 bash -c 或 eval；巢狀字串引號未閉合；一條命令含超過 8 個不同的非內建 git 子命令；別名鏈迴圈或過深；別名讀取逾時。一般命令不受影響。守衛若原本對 None 放行（fail-open），該類輸入仍放行，行為與頂層未閉合引號一致，由各守衛自行決定。

攻擊者視角檢視結論（第三項）：
- 別名展開的目錄來源：查詢目錄來自 effective_dir，未知時退回 base_dir；目錄未知時真實別名可能與 base_dir 的不同，故展開後的呼叫沿用未知旗標而標 dir_unknown，呼叫端須以 dir_unknown 為真時保守處理（0.5.0-W1-263 策略）。查詢目錄不存在或非 repo 時讀不到別名，視為無別名（殘留：目錄尚未建立但命令執行時才建立的情形，如 mkdir x && git -C x ci）。
- shell 別名遞迴：內容當腳本解析，受同一深度、查詢上限約束，結果一律 dir_unknown；! 開頭且為函式或動態組字的別名解析不出，屬已知殘留（無法靜態判定）。
- _GIT_BUILTINS 不完整：只影響是否查別名。缺項代價是多一次查詢（現受快取與上限約束），不會漏判；git 不允許別名覆蓋內建，清單內的名稱不會被誤略過真實別名。清單若誤含非內建名稱才會造成漏判，已核對僅含內建。
- 其他殘留：git -c alias.x=commit x 的行內別名不展開；變數或命令替換組出的命令；& 與 { } 語句邊界（既有）。
- 資源面：快取與上限已封堵最壞耗時；遞迴深度上限 5 約束 CPU。
