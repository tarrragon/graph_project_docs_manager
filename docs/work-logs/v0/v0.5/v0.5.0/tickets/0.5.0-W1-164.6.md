## Task Summary

盤點 hook 內帶逾時的 git 呼叫點（唯讀未帶 --no-optional-locks、逾時即 SIGKILL、逾時不寫日誌）

---

## Problem Analysis
### 問題根因

0.5.0-W1-164 系列只盤點了 ticket_system 的 git_ops 與 worktree-auto-commit（164.1）以及三個唯讀呼叫檔（164.3）。本票以 AST 掃描主 checkout 的 .claude/hooks、.claude/skills/*/hooks 與其共用函式庫 .claude/lib（hook_io.py、git_utils.py），逐一確認 git 呼叫點（不以 status／diff 字面代判，字面命中多為字串常數或 frontmatter 的 status 欄位）。結論：帶 timeout 的 git 呼叫點共 101 列（42 檔），其中 subprocess 直接點 48（含 4 個 helper 實作）、經 helper 的呼叫點 53。所有 subprocess.run(timeout) 逾時均為 SIGKILL（Python 標準行為）；唯一例外是 worktree-auto-commit 的 _run_with_graceful_timeout（164.1 已改）。

結構性事實：
1. 共用 helper .claude/lib/git_utils.run_git_command 已固定帶 --no-optional-locks（34 個呼叫點因此免於唯讀取鎖缺口），但逾時只回傳字串，是否寫日誌取決於呼叫端。
2. 共用 helper .claude/lib/hook_io.run_git 不帶 --no-optional-locks（呼叫端自帶者 2 處：changelog-update、post-git-commit 的 log），逾時寫 warning 但僅在呼叫端傳入 logger 時；prompt-submit 傳 logger，其餘 hook 的 run_git 呼叫端是否傳入未逐一核對。
3. 會取 optional index lock 的子命令是 status 與工作樹側 diff（git 文件對 --no-optional-locks 的描述與用途）；log／rev-list／rev-parse／show／branch／worktree list／diff 兩 ref 之間／diff --cached 判為低風險，此分類為依 git 文件的推論，本票未逐指令實測。
