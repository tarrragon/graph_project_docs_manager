## Problem Analysis
<!-- Schema[ANA/Problem Analysis]: 必填（.claude/pm-rules/ticket-body-schema.md） -->

### 問題根因

每個 hook 行程內 `get_project_root()` 被呼叫 3 次且互不共用結果，每次都經 `_linked_worktree_root()` 執行 `git rev-parse --git-dir --git-common-dir`：

| # | 呼叫點 | 說明 |
|---|--------|------|
| 1 | `run_hook_safely` -> `setup_hook_logging`（hook_logging.py root_dir 取值） | project_root 未傳時走 get_project_root |
| 2 | hook `main()` 自身再呼叫 `setup_hook_logging(name)` | 150/151 個用 run_hook_safely 的 hook 皆如此（grep 實測） |
| 3 | `run_hook_safely` -> `mark_hook_entry` -> `_liveness_log_dir` | project_root 未傳時走 get_project_root |

票面「setup 兩次 + mark 一次」與實測吻合。linked worktree 內每次再多一次 `--show-toplevel`（6 次）；CLAUDE_PROJECT_DIR 未設時（僅手動執行）主 repo 也是 6 次（每次多一個優先級 3 的 --show-toplevel）。

### 影響範圍

已驗證：settings.json 註冊下，Bash 工具呼叫觸發 PreToolUse+PostToolUse 共 43 個 hook 註冊項、42 個用 lib（run_hook_safely），上界 126 次 rev-parse；Edit/Write 約 29 個 lib hook，上界 87 次。
未驗證：各 hook 是否因提早 exit 而少於 3 次（實測 2 個樣本皆為 3）；高負載下單次延遲（見下，量測解析度僅 10ms）。

### 相關 Error Pattern

未執行 error-pattern query；本題為效能重複成本，非錯誤模式。

## 重現實驗結果

### 實驗方法

在 scratchpad 放 git shim（PATH 前置，記錄引數後 exec 真 git），以 `uv run --quiet <hook>.py`（與 settings.json 相同啟動方式）餵 PreToolUse Bash JSON，數 shim 記錄。唯讀，未改 .claude/。

### 實驗執行

| hook | 環境 | N | rev-parse 次數 |
|------|------|---|----------------|
| global-pkill-guard-hook | CLAUDE_PROJECT_DIR 已設（真實情境） | 6 | 3,3,3,3,3,3 |
| bash-edit-guard-hook | 同上 | 6 | 3,3,3,3,3,3 |

### 實驗發現

每 hook 行程 3 次為實測事實；三次結果在行程內恆定（cwd、環境變數、git 狀態於單一 hook 生命週期內不變）屬推論，未驗證 hook 內部有無 chdir。

### 結論

建議處置：採方案 A（行程內快取，鍵含 cwd / CLAUDE_PROJECT_DIR / HOOK_TEST_ISOLATION），3 次降為 1 次，已開 0.5.0-W1-228.1。

每次工具呼叫實測 rev-parse 總次數：每 hook 行程 3 次；乘以註冊項上界，Bash 呼叫 126 次、Edit 87 次（推算，非逐 hook 實測）。

### 候選方案

| 方案 | 利 | 風險 |
|------|----|------|
| A 行程內快取 `_find_project_root`（鍵 cwd+env 三元組） | 改動單點、3 -> 1、語意不變 | 測試 monkeypatch env/cwd 須落在鍵內，否則殘留；不快取例外/None 路徑 |
| B 以檔案系統上溯判斷 `.git` 為檔或目錄取代 subprocess（同 164.4.1 做法） | 3 -> 0，無子程序 | 須重現 git 判準（GIT_DIR/GIT_WORK_TREE 環境、submodule、gitfile 相對路徑），與 paths.py 判準分叉風險 |
| C 讓 main() 傳 project_root 給 setup（消除第 2 次） | 無快取失效問題 | 需改 150 個 hook，只減 1 次 |

A 先行，B 待 A 後視剩餘成本再評。
