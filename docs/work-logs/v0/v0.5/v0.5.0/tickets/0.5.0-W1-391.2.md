## Problem Analysis
<!-- Schema[IMP/Problem Analysis]: 選填（小型 IMP 可留 placeholder；大型 IMP 建議填寫）（.claude/pm-rules/ticket-body-schema.md） -->
### Context Bundle（L7，2026-10-20，依 391.1 合併版 48fc24d76）

現況（lease.py）：
- `_branch_hit_by_dispatch(branch, unmerged)`：分支在 unmerged 即命中；否則 `_worktree_path_of_branch` 取 worktree 路徑，`git status --porcelain`（cwd=wt）回 None 或非空即命中
- `_worktree_path_of_branch`：`worktree list --porcelain` 結果 `or []`，失敗等同未命中（C）
- `GhostReport.clean` 由 unmerged_branch / dirty_intersection / dispatch_record_unknown / unmerged_branch_unknown / dirty_intersection_unknown 組成

修法定案：
- (A) 解析 `worktree list --porcelain` 區塊的 `prunable` 行；分支已合併且其 worktree 為 prunable 時不跑 status、不判殘留，記入新欄位（失效 worktree 清單），報告另列「worktree 已失效（需 prune）」，不計入 clean。分支未合併仍判殘留
- (B) 判殘留改用 `status --porcelain --untracked-files=no`；未追蹤檔另取一次（`--untracked-files=all` 或 `ls-files --others --exclude-standard`）。PM 收窄：未追蹤檔與本票 ticket_files 有交集（沿用 `files_intersect`）仍判殘留，因為代理人新建未 add 的檔案即為未追蹤；其餘未追蹤檔只列警告（新欄位），不計入 clean。ticket_files 需由 `run_ghost_forensics` 傳入
- (C) worktree list 失敗以哨兵值區分「失敗」與「無此分支」，失敗時 `unmerged_branch_unknown = True`
- (D) 補 tmp repo 測試覆蓋 `_dispatch_state_path` 真實實作（不 patch 它）；既有 autouse fixture 一併隔離 `_subject_hit_branches`，既有測試不掃描真實 repo 的 worktree-agent-* 分支
- 測試一律真實 git（tmp repo + `git worktree add`，prunable 情境以刪除 worktree 目錄造成），不 mock git 輸出
- (A)(B) 屬放寬方向，E2 必含：分支未合併、已追蹤未提交變更、未追蹤檔命中 ticket_files，三者仍判殘留
- 測試若走到 run_ghost_forensics，比照 test_lease.py 以 monkeypatch 把 `_dispatch_state_path` 指向不存在檔案（-16 提示）

## Solution
<!-- Schema[IMP/Solution]: 選填（.claude/pm-rules/ticket-body-schema.md） -->
commit 4942abe10（只含 lease.py、test_lease.py）：
- GhostReport 新增警告欄位 `stale_worktrees`、`untracked_warning_files`，不計入 clean
- `_worktree_path_of_branch` 改為 `_worktree_of_branch`：回 `(路徑, prunable)`／None（無此分支）／哨兵 `_WORKTREE_LIST_FAILED`；失敗時 `_branch_hit_by_dispatch` 設 `unmerged_branch_unknown`（C）
- `_branch_hit_by_dispatch` 先判 `branch in unmerged`，(A) prunable 放行只對已合併分支成立；prunable 記入 `stale_worktrees`
- 新增 `_worktree_hit_by_changes`：`status --porcelain --untracked-files=no` 回 None 或非空即命中；`ls-files --others --exclude-standard` 回 None 即命中；未追蹤檔與 ticket_files 交集（`files_intersect`）命中，其餘記入 `untracked_warning_files`（B）
- 目錄不存在但無 prunable 標記：status 以不存在的 cwd 查詢回 None，判殘留（不落入 A）
- `render_ghost_report` 新列「警告: worktree 已失效（需 prune）: …」「警告: worktree 內有未追蹤檔（與本票檔案無交集，不影響鑑識）: …」；有未追蹤檔時結論行附「；有未追蹤檔，接手前先檢查舊 worktree」
- 既有 `test_dispatch_record_with_dirty_worktree_hits` 原以未追蹤檔造 dirty，新規則下會 clean，改為修改已追蹤檔（名稱不變）
- autouse fixture 一併隔離 `_subject_hit_branches`；需要真實主旨掃描的兩測試以 `_use_real_subject_scan` 還原
- PM 審查：三個改名／改簽名函式在 lease.py 外無呼叫端（grep 0 筆）；邏輯逐項對照主控 2026-10-20 三項追加要求成立
- 放寬已於閘門前報主控並獲同意（(A)(B)(C) 含 (B) 收窄，2026-10-20）
- Phase 4：重構需要 否；技術債務 無新增（lease.py 體量既有超標，非本票引入）；程式碼品質 A；結論：維持現狀
