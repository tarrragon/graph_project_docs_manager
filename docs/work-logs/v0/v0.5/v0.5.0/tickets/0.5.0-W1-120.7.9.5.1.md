### 派發 context（PM，2026-10-14）

**來源結論**：0.5.0-W1-120.7.9.5 Solution 對 global-pkill-guard 的裁定為 B+view（任意位置掃描加閱讀類命令例外）。量化與理由見該票〈重現實驗結果〉與 Solution 表格的 global-pkill-guard 列，這裡不重述。重點如下：
- 現行寫法：命令位置判定加前綴白名單。手寫正向 33 筆漏 21；B+view 漏 2，漏的是 su -c、env -S 字串載體，屬已知殘留。
- 裸掃描誤判 16/37；加閱讀類例外後降到 6/37。剩下的是遠端或容器內執行 3 筆、不明執行者參數 3 筆（python3 tool.py、npm run、git log --grep）。
- 守衛辨識即 DENY，沒有狀態條件可以緩衝，所以被攔下的訊息必須附上誤擋時的改寫方式。

**現行實作**（`.claude/hooks/global-pkill-guard-hook.py` 的 `_find_violation`）：
- 用 `parse_command_statements` 加 `skip_prefix_wrapper_count`，只看命令位置。
- shell -c 遞迴上限 `_MAX_DEPTH`。
- orphan-test-procs.py 的 `--kill` 搭配 `--root` 判定獨立於 pkill 判定，保留不動。
- `main` 有字面預篩（命令不含 pkill、killall、orphan 腳本名就直接放行），保留。

**誤擋改寫指引的方向**（寫進 `_message`）：
- 閱讀類命令已經是例外，不需要改寫。
- 遠端或容器內真的要執行的，改用 `kill <PID>` 或在目標端另行處理。
- 只是把字樣當參數時（例如 `git log --grep`），改寫成不含完整字樣的樣式，例如 `p[k]ill`。

**既有測試**：`.claude/hooks/tests/test_global_pkill_guard_hook.py` 有一筆鎖定「對 pkill 字樣做 grep 要放行」的輸入，B+view 必須維持放行。新增的正向對照至少包含：前綴包裝（timeout、nice 等）、絕對路徑、shell -c 巢狀。

**測試入口**（0.5.0-W1-291）：`uv --directory <root>/.claude/hooks run pytest <測試檔>`，`<root>` 為專案根絕對路徑，不自拼 `--with`。驗收時連同 hooks 下其他引用本 hook 的測試檔一起跑。

## Solution
<!-- Schema[IMP/Solution]: 選填（.claude/pm-rules/ticket-body-schema.md） -->
實作 B+view：_find_violation 對每個語句，命令位置為閱讀類（echo printf grep egrep fgrep rg man which type ls cat head tail less whereis apropos，及 command -v/-V）則略過 pkill 掃描；否則 _scan_any_position 掃語句內任何 token basename 為 pkill/killall 即命中，shell -c 於任何位置遞迴（_MAX_DEPTH）。orphan-root 判定與 main 字面預篩不動。_message 追加誤擋改寫方式（閱讀類已放行；p[k]ill 樣式；遠端改 kill <PID>）。
修改檔案：.claude/hooks/global-pkill-guard-hook.py、.claude/hooks/tests/test_global_pkill_guard_hook.py
仍會誤擋：git log --grep pkill、python3 tool.py pkill、npm run ... pkill、ssh/docker exec 內的 pkill 字樣 -> 改寫 p[k]ill 或 kill <PID>。
已知殘留（不覆蓋）：su -c、env -S 字串載體、別名/變數組字串、腳本內 subprocess。
### 自檢結果
正向對照 7 筆（timeout/nice 前綴、ssh/docker exec、絕對路徑 killall、timeout 包 bash -c、sh -c 內絕對路徑）均被擋；新增放行 6 筆（rg、man、which、command -v、type、pipe grep）。
Phase 4：重構需要 否；技術債務 無；品質 A；結論：無需重構。

退回修正：閱讀類判定改用 skip_prefix_wrapper_count(stmt, extended=True) 取命令位置（timeout/nice 包 grep/rg 現放行）；orphan-root 仍用原 idx；_ORPHAN_SCRIPT 等號補空格。新增測試：放行 timeout 5 grep -r pkill .、nice -n 5 rg pkill .、env FOO=1 grep pkill f；仍擋 timeout 5 pkill、nice -n 5 killall。
已知殘留補充（新舊版皆放行）：echo "$(pkill dart)"（引號內命令替換）；echo pkill | bash（管線送進 shell）。
