## Problem Analysis
<!-- Schema[IMP/Problem Analysis]: 選填（小型 IMP 可留 placeholder；大型 IMP 建議填寫）（.claude/pm-rules/ticket-body-schema.md） -->
### Context Bundle（PM 讀碼，2026-10-19，未實測）

**推測：目前放行。** 路徑（`.claude/lib/git_operation_state.py`）：

1. `_override_dirs` 把 `--git-dir=<wt>/.git` 原樣當偵測目錄（相對 effective_dir 解析）
2. `_pending_operation_in_dirs` 對該路徑先跑 `_pending_operation`：`subprocess.run(..., cwd=<gitlink 檔>)` 對檔案設 cwd 會丟 `NotADirectoryError`（OSError），走 fail-open，只寫 warning
3. 再跑 `_pending_operation_in_git_dir`：`Path(<gitlink 檔>) / "MERGE_HEAD"` 不存在，回 None
4. 結果放行；但 git 本身接受 gitfile 當 `--git-dir`（讀 `gitdir:` 指向），commit 會落在該 worktree 的 git dir，MERGE_HEAD 在時會收尾成 merge commit

**待實測確認的兩點**：(a) git 對 `--git-dir=<gitlink 檔>` 的實際行為；(b) 守衛在 hook-dispatcher 真實呼叫下是擋還是放。兩者都以真實 `git worktree add` 建的 worktree 做，不手寫 gitlink 檔充數。

**修法方向（實測放行才做）**：覆寫值是檔案且首行為 `gitdir: <path>` 時，解析指向（相對路徑以 gitlink 檔所在目錄為基準）再交 `_pending_operation_in_git_dir`；`GIT_DIR=<gitlink>` 前綴同理。解析失敗（讀不到、格式不符）歸 `_UNRESOLVABLE_OVERRIDE` 保守阻擋，不 fail-open。

**E2 正向對照**：真實 worktree + 其 git dir 放 MERGE_HEAD + `git --git-dir=<wt>/.git commit` 必須被擋；同一 worktree 無 MERGE_HEAD 時放行（對照組）。

實測(2026-10-19，真實 git worktree add)：(a) git 接受 gitlink 檔當 --git-dir，MERGE_HEAD 在時 commit 收尾成 2 parents merge commit；(b) 修前守衛放行：--git-dir=、--git-dir 空白形、GIT_DIR= 三形式 x MERGE_HEAD/CHERRY_PICK_HEAD/REVERT_HEAD 皆回 None，原因為 cwd=gitlink 檔觸發 NotADirectoryError 走 fail-open，且 Path(gitlink)/MERGE_HEAD 不存在。PM 推測成立。
## Solution
<!-- Schema[IMP/Solution]: 選填（.claude/pm-rules/ticket-body-schema.md） -->
git_operation_state.py 新增 _follow_gitlink：覆寫值為檔案時讀首行 'gitdir: <path>' 指向（相對以 gitlink 所在目錄為基準），_override_dirs 套用；讀不到/格式不符回 _UNRESOLVABLE_OVERRIDE 保守阻擋，except 有 stderr 輸出。測試：test_git_operation_state.py 新增 TestGitlinkOverride（真實 worktree，含對照組、相對路徑、壞 gitlink）。Phase 4：無需重構，品質 A。
