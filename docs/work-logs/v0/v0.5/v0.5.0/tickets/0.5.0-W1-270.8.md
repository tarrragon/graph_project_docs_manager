## Problem Analysis
<!-- Schema[IMP/Problem Analysis]: 選填（小型 IMP 可留 placeholder；大型 IMP 建議填寫）（.claude/pm-rules/ticket-body-schema.md） -->
注意：parallel-dispatch-verification-hook 讀取 tool_response.exit_code，平台 Bash PostToolUse payload 可能不含此欄位（handoff-cleanup 實例見 0.5.0-W1-279），finish 辨識修好後成功分支仍可能不執行。本票只修辨識；實地觸發時若日誌顯示停在成功判定，記錄原文並引用 279，不在本票修成功判定。

兩支 hook 皆為 PostToolUse(Bash)，屬提示類、永遠 exit 0。parallel-dispatch-verification：完成命令成功後比對 where.files 與工作區差異，缺檔時輸出 additionalContext 警告。worktree-merge-reminder：完成命令後掃描非 main worktree，輸出未合併警告或清理提醒。原辨識為字面子字串（前者 'ticket track complete'、後者 'ticket' 且 'complete'），finish 不觸發，且引號內字面會誤觸發。事件類型與處理行為皆未改動。
## Solution
<!-- Schema[IMP/Solution]: 選填（.claude/pm-rules/ticket-body-schema.md） -->
### 修改
- parallel-dispatch-verification-hook.py：is_ticket_complete_success 改用 lib.ticket_command_parse.has_complete_command；解析失敗(None)視為非完成命令，不觸發。tool_response.exit_code 成功判定未動（0.5.0-W1-279）。
- worktree-merge-reminder-hook.py：is_ticket_complete_command 同樣改用 has_complete_command。
- 兩支測試檔各新增 E2（finish 觸發原處理，斷言結構化輸出）、batch-complete、引號字面、未閉合引號 fail-open。

### post-test-hook 判定
同型。TICKET_WRITE_COMMAND_KEYWORDS 以字面子字串比對，含 'ticket track complete' 但缺 finish 與 batch-complete，用途是豁免 ticket body 回顯的 FAILED 字面，finish 回顯時會被誤判為測試失敗。本票未改，已建 0.5.0-W1-280 追蹤。

### 自檢結果
- 兩支 hook 無其他字面判定殘留；Python 3.9 相容；logger 用法未變。
- Phase 4：重構需要=否；技術債務=發現 post-test-hook 同型（已建 280）；品質=A；結論：無需重構。
