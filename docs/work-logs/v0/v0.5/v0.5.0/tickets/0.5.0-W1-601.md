## Solution
<!-- Schema[ANA/Solution]: 必填（.claude/pm-rules/ticket-body-schema.md） -->
### 收束（L47，2026-11-01）

- 根因（對照原始碼確認）：`bash-write-boundary-guard-hook.py` 的 `_const_path` 能解析常數、變數、`+`／`/`、Path 建構與 `os.path.join`、`sys.argv[n]`，但不處理 f-string（`ast.JoinedStr`），遇到時回 None。`_call_write_target` 因此判為「無寫入目標」並放行（fail-open）。597.1 的第一個腳本用 f-string 組出檔名，所以被放行；第二個腳本把完整路徑放在 argv，可以解析，所以被擋。
- 兩條判準：(1) 抽象可攜：成立，任何 consumer 用 f-string 組寫入路徑都會穿透。(2) 根源在 `.claude/`：成立，該 hook 也在 canonical repo。
- dedup：`bash-write-boundary-guard` 命中 #58、#92、#103。#103 的 issuecomment-6516531787 已記錄同一機制（執行期組出的目標被判為無目標而 fail-open）。`JoinedStr`、`_const_path` 為 0 命中。關係判定：補充 #103 的既有觀測，observe 到 #103。
- 依框架修補節奏，P2 不派修。
