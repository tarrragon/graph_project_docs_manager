### 逐筆判讀（唯讀分析代理人，2026-10-21；用戶裁定前不動 EVT／UC 文件）

**總數核對**：以 `fvm dart run` 對真實 docs 跑 scanCorpus → buildGraph → detectEventGaps（內建型別表），結果孤立事件 0 筆、宣告不符 14 筆；另依判準以 python 手算，逐筆相同。

**判讀**：補 flow 13 筆、不確定 1 筆（EVT-CORPUS-002）、改宣告 0 筆。每個宣告的 domain 都有實際消費或發出的證據（system-layer §2 依賴表、各 domain-map、SPEC-007、lib import）。

| 類 | 成員 | 共同理由 | 建議處置 |
|---|---|---|---|
| A. UC-01 少了建圖步驟 | CORPUS-001→graph、GRAPH-001 producers graph、SCHEMA-001→graph | UC-01 記了 load-schema、parse-nodes，唯獨沒有建圖這一步 | UC-01 新增 build-graph（traverses [graph]，consumes CORPUS-001、SCHEMA-001，emits GRAPH-001），empty-graph 的 branch_from 改指它；正文主要成功場景同步加一步 |
| B. 既有步驟的 consumes 漏列 | CORPUS-001→ticketdetail、CORPUS-001→diagnostics、CORPUS-004→diagnostics、CORPUS-005→diagnostics、GRAPH-001→layout、GRAPH-001→diagnostics、WORKSPACE-001→corpus | traverses 已含該 domain 的步驟存在，只缺 consumes | 補在 UC-04 jump-to-detail、UC-06 enter-gap-report（收四筆）、UC-02 switch-to-swimlane、UC-01 parse-nodes；不新增步驟。CORPUS-001 正文「Diagnostics 取錯誤清單」已過時，要一併改寫 |
| C. 解析失敗事件的發出端沒進 flow | CORPUS-003／004／005 producers corpus | Corpus 確實發出，但沒有任何步驟 emits；UC-01 例外只有敘述 | UC-01 新增分支步驟 partial-parse-failure（branch_from parse-nodes，emits 003／004／005）；004、005 的場景敘述要一併補 |
| D. domain 內部事件 | CORPUS-002 consumers corpus | 宣告與 EVT 設計一致（domain 內部觸發，不跨界） | 待裁定：(a) UC flow 要不要記 domain 內部事件；(b) UC-06 rescan 是按鈕觸發，EVT 寫的是「檔案監看偵測到變動」，而檔案監看在 lib 與 pubspec 中都沒有實作 |

**併入裁定包的附帶發現**
- 反方向不符，偵測器不檢查：UC-01 reach-domain-view 的 traverses 是 [corpus]，並 consumes CORPUS-001，但 CORPUS-001 的 consumers 沒有 corpus。這是 0.1.0-W3-345 SR-1 依「consumes 即觸及 Corpus 公開面」改的（f5aa68d16），和本判準「消費步驟的 traverses 就是消費方 domain」語意衝突；UC-05 damaged-tickets 同型。要和類 A 一起裁定：reach-domain-view 改 [graph]，或改 [] 並在 consumers 加 presentation
