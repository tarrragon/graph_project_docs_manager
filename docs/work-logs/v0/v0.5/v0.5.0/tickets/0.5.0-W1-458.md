## Problem Analysis
### 問題根因

114.22.1 上線的事件類破洞偵測（SPEC-003 §3.5 判準：EVT 宣告的每個 producer／consumer domain，須有 emits／consumes 該事件且 traverses 含該 domain 的步驟）對真實語料回報 14 筆宣告不符。根因是 UC flow 記錄不完整（缺建圖步驟、缺解析失敗分支、消費步驟漏列 consumes），以及 CORPUS-002 對應錯誤（UC-06 rescan 誤發 CORPUS-002）；EVT 宣告本身經查證全部正確。

### 影響範圍

已驗證：UC-01、02、04、05、06 的 flow 區塊與正文，EVT-CORPUS-001 設計註記，SPEC-006〈本版不做〉一列，app-use-cases UC-01 摘要。EVT producers／consumers 未改。

### 相關 Error Pattern

無匹配既有模式。附帶發現的反方向不符（traverses 含非消費方 domain，偵測器不檢查）已由用戶裁定以「消費步驟的 traverses 即消費方 domain」為準一併修正。

**WRAP 過程中更正的前提**：
- 「檔案監看是程式觸發，UC flow 寫不進去」這個說法不成立。判準只要求「traverses 含該 domain 的步驟 emits／consumes 該 EVT」，沒有要求必須是使用者操作。
- 原本說重掃被對應成 CORPUS-002 的有三份文件，實際只有 UC-06 與 SPEC-006 兩份。

**被否決的選項與理由**：
- EVT 擴大為「重新解析請求」：與設計註記的 debounce 目的不符。
- 新增「重掃請求」事件：producers 填 presentation 依 §3.5 一律算未對應，新事件本身就會變成新的不符。
- 改用 `process_event` 類別：定義不符，而且該類別只被孤立事件判準排除。
- 以 `status` 區分：11 個 EVT 全是 draft，分不出來。
- 判準加例外（I1）：以替代指標寫判準，DOC-GPD-005 記錄過同類問題。
