### 實作（worktree commit c6d71ca11）

- `hooks/resumeNoticeLog.ts`（純函式）：`resumeNoticeLogLine` 一行 tab 分隔 `<時間>`、`session=<前 8 碼>`、`source=`、`step=`，之後依步驟帶 `isDelivered=`／`reason=`／`detail=`；換行與 tab 壓成空白。`appendCappedLog` 只留最後 `RESUME_NOTICE_LOG_MAX_LINES`（500）行。路徑 `RESUME_NOTICE_LOG_PATH = .claude/hook-logs/line-board/resume-notice.log`（主 checkout）
- `hooks/resumeNotice.ts`：`resumeNoticeTarget` 改為 `resumeNoticeDecision`，不送時帶原因 `no-session-name`／`coordinator`／`lane-not-found`／`lane-ended`（舊函式在 production 已無呼叫者，連同重疊測試移除）
- `register.tsx`：`notifyResumed` = 寫 phase → `sendResumeNotice`（每個提早結束都回傳步驟與原因：send-disabled、config-unavailable、state-unavailable〔session 狀態與協調票分開讀、分開記〕、skipped、sent〔含 isDelivered=false 的 reason〕、error）→ `appendResumeNoticeLog`（read 失敗視為空檔；寫不進去送 transcript）
- plugin 的 `$.fs` 沒有 append，以讀出後整份寫回實作；`fs.write` 會建目錄
- 文件：line-continuity.md §4〈送出紀錄檔〉（欄位、六個步驟、無對應行代表未判定到）；board-screens.md 結構表補 `resumeNoticeLog.ts`
