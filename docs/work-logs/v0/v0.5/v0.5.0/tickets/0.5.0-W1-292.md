## Problem Analysis

### Context Bundle（PM 於派發前整理，2026-10-14）

**機制（.claude/hooks/hook-dispatcher.py）**

- run_inprocess 執行期間把 sys.stdin、sys.stdout、sys.stderr 換成 StringIO，再以 runpy.run_path 執行 hook，最後回傳 HookResult(name, code, out, err, error)。
- 這只換掉 Python 物件層。hook 啟動的子程序繼承的是作業系統的 fd 1 和 fd 2，也就是分派器的真實 stdout 和 stderr。
- main() 最後以 `sys.stdout.write(out)` 輸出合併後的 JSON。子程序在這之前寫進 fd 1 的文字會排在 JSON 前面。
- run_subprocess（尾段與退回路徑）用 capture_output，不受影響。
- 另外：hook 若在 Python 層直接 os.write(1, ...)，也會同樣外洩。

**已知實例**

- `.claude/skills/dart-test-async-guardian/hooks/pre-test-scan.py`：flutter test 或 dart test 指向存在的路徑時，以 `subprocess.run(cmd, capture_output=False)` 執行 `scripts/async_resource_scanner.py`，掃描腳本以 print 輸出結果。
- 275（3ed9a626d）已讓它改用 run_hook_safely，入口行為不變。

**修法方向（擇一，理由寫進 Solution）**

1. 分派器層：run_inprocess 前 flush，os.dup 保存 fd 1/2，再把兩者 dup2 到暫存檔；結束後還原，讀回內容併入該 hook 的 err（不可併入 out，out 必須維持可解析的 JSON）。這個做法涵蓋所有 hook，日後新增 hook 也不必注意。要確認 SIGALRM 逾時中斷時同樣會還原 fd（放在 finally）。
2. hook 層：只改 pre-test-scan，用 capture_output，把輸出轉寫到 sys.stderr。射程只限已知實例。
- PM 傾向 1，理由是分派器的隔離承諾（「每支 hook 有自己的 stdout 緩衝」）應該對子程序同樣成立。若 1 有阻礙（例如與 stdin 或執行緒互動），停手在 NeedsContext 回報。

**驗收要點**

- 第 1 條先實測重現，記錄修正前分派器 stdout 的實際內容。
- 回歸測試：探針 hook 以 subprocess 執行 echo 且不擷取輸出，斷言分派器 stdout 為合法 JSON，echo 的內容出現在該 hook 的 stderr。
- E2：同一測試在修正前的程式碼上會翻紅，結果記在 Test Results。
- 第 3 條：掃描 hook-dispatch-registry.json 內所有 hook 的 subprocess、os.system、os.write(1 呼叫，列出未擷取輸出的實例。採修法 1 時說明已一併涵蓋。

**注意**

- 動到 hook-dispatcher.py 前先確認 main 上沒有他線的未合併修改（git log -3 -- .claude/hooks/hook-dispatcher.py）。
- 測試入口：uv run --directory .claude/hooks pytest tests/test_hook_dispatcher.py。
- 該檔既有的同程序測試因 budget 只有 30 而實際改走子程序，由 0.5.0-W1-293 處理。本票新增的測試請傳 disp.DEFAULT_GROUP_BUDGET，參考 274 的 TestSharedStateRootCacheIsolation。

## Solution
<!-- Schema[IMP/Solution]: 選填（.claude/pm-rules/ticket-body-schema.md） -->
**重現（修正前）**：探針 hook 以 subprocess.run(capture_output=False) 執行 print，經 disp.dispatch + merge_results 後，分派器真實 stdout 為兩行：第一行 `LEAKED-FROM-CHILD`，第二行才是 deny JSON，json.loads 失敗。確認讀碼結論。

**採用修法 1（分派器層）**：hook-dispatcher.py 新增 _FdCapture，run_inprocess 執行前 flush 真實 stdout/stderr、os.dup 保存 fd 1/2、dup2 到暫存檔；finally 內 finish() 還原 fd 並讀回文字，併入該 hook 的 stderr（out 不動，維持合法 JSON）。還原放在 run_inprocess 最外層 finally，SIGALRM 逾時同樣經過。理由：涵蓋所有 hook 與日後新增者，且 tail 子程序路徑本就 capture_output；分派為序列同程序執行，全域 fd 重導無執行緒競爭。dup/dup2 失敗時還原已動部分並退化為舊行為。pre-test-scan 未改。

**Registry 掃描**（AST 掃 hook-dispatch-registry.json 的 43 個 hook 檔所有 subprocess.run/call/Popen/check_*）：未同時擷取 stdout 與 stderr 者僅 pre-test-scan.py:86（capture_output=False），已由分派器層涵蓋。os.system / os.write(1|2 無實例（僅一處註解提及）。

**新增測試**（TestChildProcessOutputIsolation，傳 DEFAULT_GROUP_BUDGET）：stdout 為合法 JSON（E2）、子程序文字落在 hook stderr、逾時後 fd 1/2 還原。

### 自檢結果
- 表面（grep）：變更僅 hook-dispatcher.py 與 test_hook_dispatcher.py；無新增 ticket ID 於框架檔。
- 語意：stdout 只含合併 JSON；子程序輸出走 stderr；fd 還原在 finally。
- 邊界：fd 重導失敗退化舊行為；非主執行緒無 SIGALRM 路徑不影響 fd 還原。
