- 可行性已寫在 0.5.0-W1-277 的 Solution〈擴充新事件的可行性〉：registry 的 group 鍵是「事件:matcher」，分派器用 `--group` 選群組，沒有寫死事件；需要改的只有檔頭的 `event_type`；fallback 清單以 `.get(group, [])` 取值

### 派發前補充（2026-10-14，278.1 合併後）

- 輸入欄位已定：how.strategy 的 payload 契約（頂層 error、is_interrupt、duration_ms，無 tool_response）取代上方「尚未確認」一項。
- 輸出事件名一致性：分派器合併子 hook 輸出時，hookSpecificOutput.hookEventName 必須等於實際事件（PostToolUseFailure 群組不可輸出 PostToolUse），否則平台會拒收該輸出。請在分派器內以實際事件名產生合併輸出，並以測試覆蓋兩個群組各自的事件名。
- 基準：main 49120a785 之後。278.1 已把 session-context-guard 與 post-ticket-lifecycle 的狀態鍵改為 session_id（lib/session_state_key.py），本票不改這兩支 hook 的邏輯。

## Solution
### 改動

| 檔案 | 內容 |
|------|------|
| .claude/hooks/hook-dispatcher.py | 新增 event_of_group；merge_results 加 event 參數，hookEventName 以群組實際事件為準（平台拒收事件名不符的輸出）；檔頭 event_type 加入 PostToolUseFailure；FALLBACK 清單列入空的 PostToolUseFailure:Bash；payload 不改寫，hook_event_name 原樣轉交 |
| .claude/hooks/hook-dispatch-registry.json | 新增 PostToolUseFailure:Bash 群組（budget 60，成員為探針 hook）；同一 hook 可列兩群組（registry 以 group 為鍵，測試證明） |
| .claude/hooks/post-tool-failure-liveness-hook.py | 新增探針：run_hook_safely 自動寫 liveness，並把失敗事件摘要記入日誌；恆 exit 0、無 stdout |
| .claude/settings.json | 新增 PostToolUseFailure（matcher Bash）指向分派器，timeout 140（budget 60 + 最大單支 60 + 餘裕 20） |
| .claude/lib/hook_output_validator.py | JSON_SCHEMA_EVENTS 納入 PostToolUseFailure，驗證器會跑失敗群組成員 |
| tests/test_hook_dispatcher_failure_event.py、test_post_tool_failure_liveness_hook.py | 新增 |

lib.hook_registry、coverage-check、依賴隔離檢查、健康監控、liveness 彙整不需改碼：split_group_key 依「事件:matcher」拆出事件；測試證明新群組成員被判為已註冊（含併入前未註冊的對照）。

### 群組成員決策

選「只記 liveness 的新探針 hook」而非搬既有 hook：搬移屬 F 線範圍外；測試 fixture 無法在 PM 實地觸發時留下 liveness 紀錄。

### PM 合併後實地觸發（驗收 2、3、5，代理人不勾）

1. 失敗命令（不加管線或分號遮蔽）：`false`，另跑 `ls /nonexistent-path-281`。
2. 成功命令對照：`true`。
3. 查 `.claude/hook-logs/_liveness/<session_id>.jsonl`，依 pid 分組。預期：
   - 失敗命令：PostToolUseFailure 群組的 hook-dispatcher 一筆 + post-tool-failure-liveness-hook 一筆，同一 pid；該次 PostToolUse 群組沒有紀錄。
   - 成功命令：只有 PostToolUse 群組紀錄，post-tool-failure-liveness-hook 不出現。
4. `.claude/hook-logs/post-tool-failure-liveness-hook/` 日誌出現 `收到失敗事件 event=PostToolUseFailure interrupt=False ... error=Exit code 1`。
5. 若失敗命令無任何 PostToolUseFailure 紀錄，先確認 session 是否在 settings.json 變更後重啟（hook 設定於 session 啟動時載入）。
