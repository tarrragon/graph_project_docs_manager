## Solution
<!-- Schema[IMP/Solution]: 選填（.claude/pm-rules/ticket-body-schema.md） -->
### 實作
- 狀態檔：.claude/hook-state/persistence-reminder-<消毒 session_id>.json，內容 {notified_ids: [...]}；session_id 以 [^A-Za-z0-9_-] 換 _、截 128 字；超過 7 天的狀態檔於寫入時清理。
- 增量判定：掃描結果與狀態檔 notified_ids 取差集，只列差集內的票並寫回聯集；差集為空不輸出（suppressOutput）。
- 缺 session_id：不節流、不寫狀態（保守：照舊每次提醒），理由是無鍵可分檔，共用鍵會讓並行 session 互相吞掉提醒。
- 讀寫狀態失敗：fail-open（照舊提醒），logger.warning 記日誌。stop_hook_active 檢查與 Stop additionalContext 管道保留。
- 實地觸發：合併後在有 context 敏感票的 session 連續結束兩輪，第二輪應無續跑；新建一張 ANA 票後第三輪僅列該票；確認 .claude/hook-state/ 出現對應狀態檔，hook-logs 有「已提醒過，不重複輸出」。

### 自檢結果
- 語法 Python 3.9 相容（無 PEP 604）；logger 於 main 內建立；stdin 用 read_json_from_stdin。
- Phase 4：無需重構；技術債：狀態檔 mtime 清理僅在有新增時觸發，可接受；品質 A。

PM 審查（2026-10-15）：通過。狀態檔 .claude/hook-state/persistence-reminder-<session_id>.json 記 notified_ids，以差集做增量提醒、差集為空不輸出；缺 session_id 照舊每次提醒且不寫狀態（無鍵可分檔，共用鍵會使並行 session 互吞提醒），讀寫失敗 fail-open。代理人回報的依賴隔離 WARNING 已由 0.5.0-W1-333 追蹤。
