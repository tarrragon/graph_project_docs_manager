### PM 派發前待查（2026-10-14）

0.5.0-W1-120.7.9 把 homoglyph-guard 歸為狀態型阻擋守衛，但 PM 在 0.5.0-W1-120.7.3 盤點時，grep 該檔的 exit 2 路徑計數為 0，判定它不阻擋。兩者不一致。動工前先查明它的阻擋方式：是否以 PreToolUse 的 JSON permissionDecision 回 deny，而不是用 exit 2。若它實際上不阻擋，只需加 scan 參數，「有風險狀態才阻擋」這條 acceptance 對它改為「提示」，並在 Solution 寫明。

## Solution
<!-- Schema[IMP/Solution]: 選填（.claude/pm-rules/ticket-body-schema.md） -->
提交 1cc61bb3c。五支守衛的解析呼叫全數改傳 scan=True，處置邏輯未動：protected-branch 4 處（頂層、子 shell、同範圍 git add 兩處）、add-broad、merge-staged-index、commit-stage-guard-gate 各 1 處，homoglyph 的 match_git_commit 1 處。add-broad 與 merge-staged-index 遇 None 仍放行（未改）。

homoglyph-guard 查明結果：它會阻擋。以 EXIT_BLOCK = 2 結束並寫 stderr（Homoglyph Guard 訊息），不是 JSON permissionDecision；120.7.3 的 grep 計數為 0 是因其用常數 EXIT_BLOCK 而非字面 exit 2。故歸類為狀態型阻擋守衛正確，acceptance 不需改為提示。無法解析（None）時視為未命中放行，未改。

實地觸發（本 session，scratchpad 暫存 repo，payload 經 hook-dispatcher.py --group PreToolUse:Bash 餵入，依各守衛需要設定 CLAUDE_PROJECT_DIR 與 cwd）：
- add-broad：有未提交變更時 setsid git add -A rc=2 並輸出廣域 add 阻擋訊息；grep 'git add -A' rc=0。
- merge-staged-index：staged 時 setsid git merge feature rc=2，輸出 merge-staged-index-guard 阻擋訊息。
- homoglyph：staged 為 汙 改 汲 時 setsid git commit rc=2，輸出 Homoglyph Guard；grep 'git commit' rc=0。
- commit-stage-guard-gate：staged 含 W9-002 違規時 setsid git commit rc=2，輸出 reference-stability-rule8-guard；grep 'git commit' rc=0。該 hook 以程序 cwd 取 toplevel，故須在暫存 repo 內啟動 dispatcher。
- protected-branch：host 為本專案、目標暫存 repo 在 main 且 staged 非豁免檔，setsid git -C 目標 commit 回 permissionDecision deny；grep 引號文字 rc=0。
- liveness 驗證方式：以 dispatcher 實際回傳的 stderr 或 JSON 訊息與 exit code 判定各守衛確實執行；單元層另有變異確認（monkeypatch 拿掉 scan 後，正向輸入翻成放行，五支各一項）。
- 失敗語意：add-broad 與 merge-staged-index 對無法解析 fail-open（merge-staged 自身例外亦 fail-open）；homoglyph 對無法解析視為未命中放行；commit-stage-guard-gate 對無法解析放行；protected-branch 對無法解析 fail-closed（既有）。本票皆未改。

單元測試新增：各支一組 E2（僅掃描才命中的 setsid 或 find -exec 輸入：有風險狀態阻擋、無風險狀態放行）、grep 引號反向輸入、變異確認；add-broad 與 merge-staged 另有無法解析仍放行的測試。

Phase 4：重構需要否。技術債務：無新增（無法解析提醒文案對掃描命中的不精確已由 0.5.0-W1-120.7.10 承接）。程式碼品質 A，每處僅加 scan=True 參數。
### 自檢結果

- acceptance 3（無法解析的輸入處置與改動前相同）：由未改動的處置邏輯，加上 add-broad 與 merge-staged-index 的「無法解析仍放行」測試支撐。
- 無法解析提醒文案對掃描命中仍寫「未閉合引號」的問題，由 0.5.0-W1-120.7.10 承接，本票不處理。
- homoglyph-guard 的歸類已更正：它以 EXIT_BLOCK = 2 阻擋，屬狀態型阻擋守衛；120.7.3 的 grep 只找 exit 2 字面，未涵蓋常數，故判讀為不阻擋。
