## NeedsContext
lavender 盤點，未改 SPEC-004，依約束停手。(1) 摘要與徽章間距可推出 Space.sm：4.9 自身水平內部間距全為 Space.sm，ListRow 最小寬式 一字元 + Space.sm + trailing 為文字接尾端元素先例；Space.xs 出處 BadgeRow 是徽章與徽章之間，不適用。(2) 一字元 無法唯一推出：4.0.3 只定行高無字寬約定；分歧 a 字寬取 1em 或實測指定字，b 字級取 body 或 caption（4.9 兩行字級不同），c 是否含省略號（4.1 等多數寫 一字元 + 省略號，4.7/4.8/4.9 只寫 一字元，全檔不一致）。(3) 徽章自身放不下時的分配 無法唯一推出：內容政策已定降級標籤於最小寬下截斷；未定 a 摘要可縮到 0 才截徽章（現行實作：徽章上限 = 可用寬 - 間距），b 摘要保留最小寬後徽章才截斷且最小寬式須加徽章最小寬。影響：acceptance 1、2 未達成，W3-004 B1/B3 仍依賴本票。建議：PM/用戶裁決 (2)(3) 後重派。

### 裁決（e1，2026-10-07）

- **(1) 間距**：`Space.sm`，依 lavender 推導，與現行實作一致。
- **(2)「一字元」**：
  - a. 取 1em：不需實測，在任何語系都是確定值，CJK 全形字寬約等於 1em。
  - b. 字級取該文字 slot 自身字級；4.9 的最小寬由名稱列決定，故取 `AppFontSize.body`。
  - c. 含省略號，4.7、4.8、4.9 一併統一為「一字元 + 省略號」。
  - 定義只寫一次：在 §4.0.3 定義「一字元 = 該文字 slot 字級的 1em」，各條目直接引用，不逐條重述。
- **(3) 徽章本身也放不下時**：選 a，摘要縮到 0 之後才截斷徽章。理由：名稱是主要資訊；徽章標示資料可信度狀態；摘要的節點數與票數是次要資訊。此選項也與現行實作一致，W3-004 不需改實作。
- **(2)c 擴及 4.7、4.8 的理由**：「一字元」改為在 §4.0.3 集中定義後，各條目引用的是同一個定義。只有 4.7、4.8、4.9 寫法與全檔多數條目不一致，只改 4.9 會讓同一定義出現兩種寫法。統一這三條是本次定義收斂的直接後果，不是範圍蔓延。
