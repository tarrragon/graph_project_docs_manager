## Problem Analysis
<!-- Schema[IMP/Problem Analysis]: 選填（小型 IMP 可留 placeholder；大型 IMP 建議填寫）（.claude/pm-rules/ticket-body-schema.md） -->
根因：parse_command_statements 把重導向留在敘述 token 內（2>&1 為單一 token；2>/tmp/e 拆為 2、>、/tmp/e；&>、>>、< 與其目標各自成 token），_all_specific_test_files 將它們視為非測試檔的位置參數，單檔測試被判 heavy 而被 deny；建議寫法再把 2>&1 加引號接在 -- 之後，變成命令參數。影響：所有 session 的 pytest／flutter test 單檔加重導向寫法。

## Solution
<!-- Schema[IMP/Solution]: 選填（.claude/pm-rules/ticket-body-schema.md） -->
commit ece27d67e03751ddedd8fa787b94b53b00c5a0a0（分支 worktree-agent-a0617d62fb0f40ade）。lib/test_command_parse.py 新增 split_redirections 與 find_unwrapped_heavy_with_redirects；find_unwrapped_heavy 委派之且不含重導向；classify_argv_weight 未改。pre-test-hook._wrapped_form 把重導向原樣接在包裝命令之後、不加引號。判定失敗仍 fail-open。測試 4 檔合計 284 passed；新增 e2e 對舊實作 5 紅。已知限制：選項值為單一數字且緊接重導向運算子時該數字被當 fd，僅影響建議寫法文字。合併後實地觸發與 liveness 由 PM 執行。
