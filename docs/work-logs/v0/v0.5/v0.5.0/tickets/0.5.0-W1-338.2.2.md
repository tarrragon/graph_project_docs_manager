### 失敗語意（拆分前後相同）

- 未預期例外：`run_hook_safely(main, ...)` 未帶 fail_closed，fail-open（記 traceback，非零非阻擋碼）；hook-dispatcher 以掃描 hook 檔字面判定 fail_closed，該字面仍在 hook 檔，未變。
- 偵測 git 子程序（MERGE_HEAD／git-path／rev-parse --show-toplevel）不存在、逾時、rc 非預期：fail-open（回無進行中操作／不過濾），stderr + logger.warning 雙通道回報。
- 讀 pm-registry 失敗：fail-closed（全數派發條目維持佔用）。
- 讀派發登記失敗：fail-open 回空清單（降級為非並行期 WARN）。
- 讀票面 where.files 失敗：退回派發快照 + warning，不新增放行或阻擋路徑。
- 目標 checkout 無法判定、帶 GIT_DIR／GIT_WORK_TREE／--git-dir／--work-tree：不過濾，全數計入（保守方向，阻擋面較大）。
- 讀 staged 清單失敗：空清單，視為安全放行（既有行為，僅低估範圍）。

### 實作陷阱（供 339 回饋部落格）

1. 鎖位置的測試：22 個測試在搬移後翻紅，全因 `monkeypatch.setattr(hook_module, "_merge_in_progress"|"_other_operation_state"|"_read_registry_sessions", ...)` 與 `hook_module.subprocess`。re-export 保住 `hook_module._x` 這個名稱，但呼叫端（`_pending_operation`、`_exclude_orphan_confirmed`）在新模組命名空間查名稱，patch 換掉的是舊模組那份，新模組照跑真實偵測。這些測試改為 patch 新模組（lib.git_operation_state／lib.dispatch_scope）。main 留在 hook 檔，所以對 main 直接呼叫的名稱（`_get_staged_files`、`_get_active_dispatches_safe`、`_with_live_declared_files`、`get_project_root`）patch hook_module 仍有效——判準是「誰查這個名稱」，不是「名稱是否 re-export」。
2. `hook_module.subprocess.run` 這種 patch 在模組不再 import subprocess 後直接 AttributeError（不會靜默失效）；但 `raising=False` 的 patch 會靜默失效，orphan 測試原帶 `raising=False`，已移除。
3. 可變注入點不 re-export：`subprocess` 只保留在 git_operation_state 與 dispatch_scope 兩個實際使用者，hook 檔不再 import。
4. 套件自加 sys.path：`bare_commit_guard/__init__.py` 保證 `lib` 可匯入，不依賴 hook 檔、測試或分派器先插路徑。
5. PEP 723 與套件 import 一致：套件只用 stdlib + lib，hook 的 `dependencies = ["pyyaml"]` 不變。hook-dependency-isolation-check 對本 hook 報 `ticket_system` 未涵蓋，拆分前即存在（lib.hook_base 遞移，同類 31 支），非本次引入。
6. 盤點單檔前提工具：hook-dispatcher 以 runpy.run_path 載入並讀 hook 檔字面判 fail_closed，套件式拆分不影響；hook-dependency-isolation 以 AST 掃 hook 檔 + lib 遞移，不掃 hooks/ 套件目錄，但套件內只有 stdlib 與 lib 匯入故無漏報。
7. 搬移後註解中「見模組 docstring『六/七修正』段」的指涉在 messages.py 內改為「hook 檔 docstring」，否則指向不存在的段落。
8. 新增 .claude/ 框架檔含專案票號會被 rule8 guard 擋下（docstring 與註解不可寫票號）。
