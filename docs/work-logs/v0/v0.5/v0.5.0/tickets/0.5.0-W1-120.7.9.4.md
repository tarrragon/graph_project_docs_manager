### 結案前追修：行接續造成的註解剝除繞過（PM 確認，2026-10-14）

背景安全審查（MEDIUM）指出，strip_line_comments 沒有處理 bash 的行接續（反斜線加換行）。PM 以 main 上的解析器實測：

| 命令 | bash 實際語意 | 解析器結果 | 判定 |
|---|---|---|---|
| `echo a\<換行>#x; git commit -m x` | 行接續後為 `echo a#x; git commit`，# 在詞中，不是註解，commit 會執行 | 0 筆 | 繞過 |
| `echo a \<換行>#x; git commit -m x` | 行接續後 # 前為空白，屬註解，commit 不執行 | 0 筆 | 正確 |
| `echo a<換行>#x; git commit -m x` | 整行為註解 | 0 筆 | 正確 |

成因：剝除器遇到跳脫狀態下的換行時，把換行照常加入結果，並把 prev 設為換行，導致下一行開頭的 # 被判為行首註解。

修法：比照 bash 先合併行接續。可以在剝除前把未在單引號內的「反斜線加換行」整段移除，或在剝除器中遇到跳脫換行時，彈出已加入的反斜線並略過換行，prev 保持反斜線之前的字元。單引號內的反斜線加換行不是行接續，要保留。

補測試三組：
- 正向：第一列，應命中 1 筆。
- 反向：第二列，應命中 0 筆。
- 單引號內的反斜線加換行不被合併。

另做變異確認：移除行接續處理後，第一列翻回 0 筆。

本票在全套件通過前不結案；追修完成後重新排入快照。

### 實作（thyme-python-developer 於 worktree，PM 依流程 B 代寫，2026-10-14）

提交 c1434c15c，以 worktree merge 隔離索引 CAS 合併為 69768b3c7。

- 新增公開函式 `strip_line_comments`：以引號感知的逐字元掃描，追蹤單引號、雙引號與反斜線。`#` 只在行首、空白，或 `;`、`&`、`|`、`(` 之後才算註解，刪到行尾、保留換行。
- `_tokenize_command` 先執行 strip_heredoc_bodies，接著是 strip_line_comments，然後才抽反引號本體、正規化換行。這個順序確保註解內的反引號不會被抽成語句，且在換行轉成分號之前，行界線資訊仍在。
- `_tokenize` 設 `lexer.commenters = ""`：shlex 預設也會把詞中的 `#` 當成註解（如 `a#b`），與 bash 不同；關閉後兩者一致。
- 取捨：只改 normalize_newlines_to_separators 不足，因為那不處理 shlex 本身的註解。所有 tokenize 路徑（含 bash -c 巢狀）都經過 _tokenize_command，一處修改即全面生效。公開簽名與回傳形狀不變。

提交 6ae5a71bb，以 worktree merge 的隔離索引 CAS 合併為 d6b966191。

- 修法：`strip_line_comments` 新增 `prev_before_backslash`。在單引號外（含雙引號內）遇到跳脫狀態的換行時，彈出已加入的反斜線、略過換行，並把 prev 還原為反斜線之前的字元，與 bash「先合併行接續、再判斷註解」的順序一致。單引號內不進入跳脫分支，反斜線加換行原樣保留。註解內的反斜線加換行維持原狀，註解仍在換行處結束。

  - 變體：多重行接續（詞中命中 1，空白後命中 0）、雙引號內合併、雙反斜線加換行（換行是真換行，下一行為註解，命中 0）。

  - `echo 'a\<換行>#x'; git commit` 為 1。
