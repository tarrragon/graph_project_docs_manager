### 問題根因（待查證；研究線接手 session 依 466.1 結果整理，2026-10-21）

**量測結果**（來源：0.5.0-W1-466.1 Solution 結果表，`test/widget/accessibility/guideline_baseline_test.dart` 的 `_knownFailures`）：

| 畫面 | 失敗節點 | 對比值 | 字級（min／design） | 尺寸 |
|---|---|---|---|---|
| ucFlow | 「選擇 UC」 | 1.18 | 7.5pt／10pt | 960×640、1280×800 皆重現 |
| nodeDetail | 「關聯節點」 | 1.17 | 7.5pt／10pt | 同上 |

另兩條準則（labeledTapTarget、MinimumTapTarget 28×28）六畫面全數通過；其餘四畫面的 textContrast 通過。

**兩處元件的位置**：
- 「選擇 UC」：`lib/screens/uc_flow/uc_flow_screen.dart` 的 `Section(variant: SectionVariant.static, testKey: Key('panel-ucFlow-uc-selector'))`，`header` 為 `AppText(l10n.ucSelectorTitle, variant: AppTextVariant.caption)`。
- 「關聯節點」：節點詳情的關聯分節標題，文字來自 `lib/screens/node_detail/node_detail_fixtures.dart` 的 `NodeRelationCategory(label: '關聯節點')`（fixture 資料，非 i18n），由節點詳情畫面以 Section 分節渲染。
- 兩處同為 `lib/components/section.dart` 的 static 分節標題。失敗若為真，根因較可能在共用的 Section 標題樣式，而不是兩個畫面各自的寫法；本票分析範圍應包含 `lib/components/section.dart`。

**懷疑是取樣誤判的依據**：
1. widget test 使用方塊測試字型（Ahem 類），`textContrastGuideline` 以文字邊界框內的像素估前景與背景色；字形不是實際字型，取樣結果只能粗篩（466.1 已註明）。
2. 466.1 回報兩處取樣到的前景與背景都是白色或近白淺色（light 主題為白、dark 為近白）。若前景真的接近白色，人在實機上幾乎讀不到這兩個標題，但目前沒有這樣的使用者回報；比值 1.17 更接近「取到同一塊背景」而非「文字顏色偏淡」。
3. 其他畫面使用同一 caption 變體的文字通過準則，代表 caption 色票本身不一定有問題；兩處的共同點是 Section static 標題，可能是標題所在的底色區塊或疊層讓取樣落在同色區域。

**反向可能**：Section static 標題若確實疊在淺色底上且文字用淺色 token，則為真實缺陷；用實機截圖量色值即可分辨。

## 重現實驗結果
### 實驗方法

採 token 定義查證（派發前 context 路徑 b）：追 `lib/components/section.dart`（Section 無底色，僅 Column）→ 外層 `lib/components/panel.dart` `Panel.build` 的 `BoxDecoration(color: AppColors.surfaceBase)` → 標題 caption 的 `_defaultColor`（`lib/components/app_text.dart`：caption => `AppColors.textSecondary`）→ `lib/tokens/colors.dart` 色票。以 WCAG 2.x 相對亮度公式（python3）算對比，並反查 466.1 的 1.17／1.18 對應哪一對色票。未拍實機截圖：產生器 variant 不涵蓋 ucFlow／nodeDetail，加 variant 不在本票範圍。

### 實驗執行

- 標題前景 `AppColors.textSecondary` = `_Palette.gray600` = #6A7674；背景 `AppColors.surfaceBase` = `_Palette.white` = #FFFFFF（Panel 底色，Section 不另上色）。對比 4.71:1。
- 標題下方項目底色：ucFlow 選中的 `ListRow.option` 為 `AppColors.surfaceIconTint` = #E0EFED（`lib/components/list_row.dart` ColoredBox）；nodeDetail 的 `RelationItem` 為 `AppColors.surfaceChip` = #E9EEED（`lib/components/relation_item.dart` BoxDecoration）。
- 反查：#E0EFED 對 #FFFFFF = 1.184（466.1 量到 ucFlow 1.18）；#E9EEED 對 #FFFFFF = 1.172（466.1 量到 nodeDetail 1.17）。兩值逐一吻合且各自對應該畫面標題下方的項目底色。
- dark 主題：`grep -rn "darkTheme\|Brightness.dark\|ThemeMode" lib` 零命中；`AppColors` 為 static const 單一色票，App 無 dark 主題，dark 值不適用。

### 實驗發現

- 已驗證：標題實際對比 4.71:1，達 WCAG AA 一般文字 4.5:1，非缺陷。
- 已驗證：1.18／1.17 是「項目底色 vs 白」的比值，不含任何文字色；取樣矩形涵蓋到標題下方項目區塊，取到兩種背景色而非字色。
- 未驗證（不影響結論）：取樣矩形放大的機制（推斷為標題文字 semantics 片段併入較大父節點）。結論只依賴比值與色票逐一吻合。
