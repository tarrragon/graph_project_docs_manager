## Solution
<!-- Schema[IMP/Solution]: 選填（.claude/pm-rules/ticket-body-schema.md） -->
### 受眾裁定與改法

| hook | 事件 | 裁定 | 理由 | 續跑一次 |
|------|------|------|------|---------|
| confabulation-audit | Stop | 僅用戶可見，維持現狀 | 內容是髒工作區與 in_progress 票的狀態報告；本專案並行 session 常態有未 commit 檔，模型續跑只會無謂延長每次結束 | 不可接受（幾乎每次 Stop 都命中） |
| context-depth-warning | Stop | 僅用戶可見，維持現狀 | 建議對象是用戶（考慮 /clear 或 handoff），模型無可執行動作 | 不可接受（模型無可執行動作） |
| session-experience-persistence-reminder | Stop | 模型可見，改 emit_model_reminder Stop | 原文即寫明提醒對象是 Claude，要它評估 context 是否已持久化 | 可接受且為本意 |
| evaluate-session | Stop | 模型可見（僅長 session 分支），改 emit_model_reminder Stop | 原註解 Signal to Claude，要模型評估可萃取模式；短 session 的 skipping 訊息維持 stderr | 可接受且為本意 |
| language-guard | UserPromptSubmit | 模型可見，三類警告合成單一 additionalContext | 提醒的是模型自己前一輪輸出的違規，用戶端 stderr 無效 | UserPromptSubmit 無續跑問題 |

### stop_hook_active 處理
- persistence-reminder：main 讀 stdin，stop_hook_active 為真則直接輸出 suppressOutput，不掃描不提醒。
- evaluate-session：長 session 分支輸出前讀 stdin，為真則 exit 0 不輸出。
- 未改的兩支不輸出 additionalContext，無迴圈風險。

### 阻擋語意與 JSON
- 四支原本皆無 decision 或 permissionDecision，無需合成；每次執行只印一份 JSON（language-guard 三類警告合併；persistence-reminder 提醒時只印 emit 的 JSON）。
- language-guard 內部錯誤 stderr 維持（規則 4）。

### 實地觸發方式與要避開的提早返回
- language-guard：UserPromptSubmit 送出一則 prompt。避開：(1) 抽樣，每 10 次才完整檢查（計數檔 hook-logs/_sampling/language-guard-hook.count，實測前設為 9）；(2) 發現：extract_previous_assistant_message 讀 hook_input 的 transcript 欄位且要求為 list，但 Claude Code 實際 payload 提供的是 transcript_path（檔案路徑），可能恆回 None 而靜默。此為既有問題，範圍外，實地觸發若無輸出先查此項。
- persistence-reminder：Stop 時需有今天建立、pending 或 in_progress、type 為 ANA 或標題含審查/分析等關鍵詞的票，否則 build_reminder 回 None。stop_hook_active 為真的續跑回合不輸出（預期行為，驗證第一次 Stop 即可）。
- evaluate-session：Stop 時 CLAUDE_TRANSCRIPT_PATH 環境變數須存在且檔案存在（否則 exit 0），transcript 中 type user 次數須 >= min_session_length（預設 10，config.json 可覆寫），且 stop_hook_active 非真。該環境變數是否真由 Claude Code 設定未驗證，實地無輸出先查此項。

### 自檢結果
- 範圍僅 where.files 與對應測試；Python 3.9 相容；lib 統一入口；Edit/Write 修改。
- persistence-reminder 的測試併在 test_stop_reminder_hooks.py，Hooks 測試 gate 依命名慣例仍提醒無對應測試檔，PM 可決定是否改名拆檔。

### Phase 4 評估
重構需要：否；技術債務：發現 2 項（language-guard 的 transcript 欄位與實際 payload 不符；evaluate-session 依賴的環境變數是否存在未驗證），皆屬既有、範圍外，由 PM 於實地觸發後決定開票；程式碼品質：A。

PM 審查（2026-10-15）：受眾裁定採納（confabulation-audit、context-depth-warning 僅用戶可見維持現狀；persistence-reminder、evaluate-session 長 session 分支、language-guard 改模型可見），兩支 Stop 輸出者皆檢查 stop_hook_active，通過。限制：language-guard 經日誌證實 runtime 從未取得前一輪回應（讀 payload 的 transcript，實際只有 transcript_path），本票對它的遷移在來源修好前無實效；evaluate-session 依賴的 CLAUDE_TRANSCRIPT_PATH 亦未驗證。兩者由 0.5.0-W1-323 處理，本票合併後的實地觸發以 persistence-reminder 為主。
