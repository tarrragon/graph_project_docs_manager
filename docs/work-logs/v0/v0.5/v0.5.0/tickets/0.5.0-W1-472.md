## Problem Analysis
<!-- Schema[ANA/Problem Analysis]: 必填（.claude/pm-rules/ticket-body-schema.md） -->
### 問題根因

`ticket create --type ANA` 由 `.claude/skills/ticket/ticket_system/lib/ticket_builder.py` 把 Problem Analysis 三節（問題根因、影響範圍、相關 Error Pattern）填成「（必填：⋯）」placeholder。建票時不提示這些章節是空的；唯一的強制點是 `acceptance-gate-hook.py` 在 complete 時檢查。

**實例（2026-10-21，同一天、三個不同 session）**：0.5.0-W1-465、0.5.0-W1-466.3 由主控建立，0.5.0-W1-468 由研究線建立，0.5.0-W1-471 由產品線 L19 建立。四張建立時 Problem Analysis 都是 placeholder，都是 Stop hook 或主控事後讀票面才發現、再請建票者補寫。

**後果**：ANA 票常在建立後隔著 session 切換才開工。建票者手上的查證結果（符號位置、量測值、判斷依據）若沒有當場寫入，接手者只拿得到 placeholder，必須重新查一遍；complete 時的強制點擋得住不完整的結案，但擋不住背景在中間流失。

### 兩條判準（escalation-flow.md）

1. **抽象可攜**：「建票 CLI 產出必填章節的 placeholder，強制點只在結案時，背景在建票到開工之間流失」，換掉專案名稱後仍成立，任何 consumer 的 ANA 票都適用。成立。
2. **根源在 `.claude/` 通用資產**：ticket skill 的建票 CLI 與 acceptance-gate hook，沒有專案設定參與。成立。

### 處置

- 不是 P0／P1：complete 時已有強制層，不會產生錯誤的結論。依框架修補節奏觀測進 issue 後關閉。
- 查重：dedup 關鍵字為 Problem Analysis 空白、placeholder 殘留、ANA 建立。#33（placeholder 殘留於實質內容之前）談的是 append-log 之後的排序，與本項不同；#55（ticket CLI 契約缺口叢集）收錄 CLI 行為與使用者預期之間的落差，本項屬於這一類，關係判定為「引用」，observe 到 #55。
- 修法候選：(a) `ticket create --type ANA` 接受 `--problem-analysis` 或 `--root-cause`，讓背景在建票同一步寫入；(b) 建 ANA 票時，若 Problem Analysis 仍是 placeholder，在輸出加一行提示，告訴建票者趁背景還在時用 append-log 補上；(c) Stop hook 列出本 session 建立、Problem Analysis 仍為 placeholder 的 ANA 票。(b) 成本最低，(a) 最符合「結構由工具生成、語意值由人提供」的原則。
