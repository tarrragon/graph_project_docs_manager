## Solution
<!-- Schema[IMP/Solution]: 選填（.claude/pm-rules/ticket-body-schema.md） -->
### 狀態判別表
| 狀態 | 判別（git rev-parse --git-path 取得路徑） | 處置 |
|---|---|---|
| merge | MERGE_HEAD 可解析（既有） | 擋 |
| cherry-pick | CHERRY_PICK_HEAD 檔存在 | 擋 |
| revert | REVERT_HEAD 檔存在 | 擋 |
| rebase 衝突或中斷停下 | rebase-merge 或 rebase-apply 目錄存在，rebase-merge/amend 不存在 | 擋 |
| rebase edit 停下 | rebase-merge/amend 存在 | stderr WARN，其後照原流程判定（並行期範圍檢查仍適用）；--amend 先行放行 |

優先序 merge, cherry-pick, revert, rebase。偵測目錄沿用 _resolve_detect_dir。find_git_invocations 為 None 時以 payload cwd 或 root 偵測，擋類狀態一律 deny，不論並行期。

### 拒絕訊息全文（cherry-pick 例；revert、rebase 僅替換名詞與 --continue）
[cherry-pick 進行中，裸 commit 被阻擋]
理由：偵測到 CHERRY_PICK_HEAD（有未收尾的 cherry-pick），裸 `git commit` 會把目前 index 內容（可能含他方已 stage 的內容）併成單一 commit、以本次 -m 取代原訊息，且cherry-pick 的狀態可能被清除或歷史被改寫。
若 cherry-pick 是你發起的，請改用（無 tty 環境須以 GIT_EDITOR=true 略過編輯器）：
  GIT_EDITOR=true git cherry-pick --continue
自訂訊息：先把訊息寫入 `git rev-parse --git-path MERGE_MSG` 所指的檔案，再執行上一行。
若 cherry-pick 非你發起：請停手並回報 PM，不要自行收尾或放棄。
（revert 同用 MERGE_MSG；rebase 為 rebase-merge/message。訊息不含 abort。MERGE_HEAD 沿用原訊息。）

### 實地觸發結果
pytest tmp_path 暫存 repo，真實 git，不 mock 偵測函式：cherry-pick 衝突已解決、revert --no-commit、rebase 衝突已解決、rebase -i edit 停下、worktree 內 revert（主 checkout 不擋、cwd 在 worktree 擋、-C worktree 擋）皆符合預期。共用主 checkout 未執行任何改狀態的 git 操作；對本專案以 payload 實跑 hook：rc=0，無誤擋。

### liveness 驗證方式
以 git 自身判定進行中的檔案或目錄存在性為準，不讀 reflog 或行程。殘留的過期狀態檔 git 也視為進行中，故同樣擋，處置是 --continue 或由發起者 --abort。未驗證：rebase-apply（am）路徑；edit 步驟本身衝突時 amend 是否存在。

### 失敗語意
git 呼叫失敗（OSError、逾時、rc 非 0、輸出行數不符）fail-open 回 None，stderr 與 warning log 雙寫（沿用 _report_detect_failure，訊息仍以 MERGE_HEAD 起頭文字）。merge 與其他狀態各一次 git 呼叫，git 全壞時報兩次。

### 自檢結果
各條 acceptance 對照：三態 deny 與訊息、edit 停下 WARN 放行與 --amend 放行、每態正向與反向測試及偵測目錄順序、本專案實跑 rc=0、無法解析命令時擋類狀態一律 deny，皆已在 Solution 與 Test Results 記錄。技術債（git 整體失敗時回報兩次、第二則日誌誤標 MERGE_HEAD 偵測失敗）已由 0.5.0-W1-263 承接。
