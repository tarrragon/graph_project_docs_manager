### 現況（2026-10-28，讀 `.claude/skills/worktree/scripts/merge_gate.py`）

- `select_suites(changed_paths, root)` 以改動路徑決定要跑哪些套件；`suite_command(suite, root)` 回傳宣告的固定 argv。改動檔清單只用來選套件，不會傳進命令。
- 「只檢查本次合併改動的 .dart 檔」因此無法只改 `merge-gate.yaml` 達成，需要在框架開一條傳遞管道。
- `MergeGate._reusable` 只在同一次合併的 CAS 重試之間沿用綠燈：若從上次驗過的 commit 到新 commit 的差異沒碰到套件範圍，就沿用。這代表已檢查過的檔內容沒變，格式檢查照常適用，不需特例。

### 實作指引（給代理人）

- 宣告：`_parse_suite` 解析選填欄位 `changed_files`（正規式字串，以 `_parse_pattern` 驗證；格式錯誤時 fail-closed，同其他欄位）。

- 免跑：符合但全部已刪除（快照內不存在）時不執行，輸出一行「套件 <名>：免跑｜<原因>」，沿用 `_suite_result_line` 的格式，狀態字樣與綠燈不同。
- 沿用：`_reusable` 的判定以 `select_suites` 套在差異上，新欄位納入後自然一致，不另寫特例。
- 專案層：`merge-gate.yaml` 新增 `dart-format` 套件，`prefixes: [lib/, test/, integration_test/]`、`command: [fvm, dart, format, --output=none, --set-exit-if-changed]`、`changed_files: '\.dart$'`。
