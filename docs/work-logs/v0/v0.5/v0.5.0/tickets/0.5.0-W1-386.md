### 修法（worktree commit e7a380595）

- 新增 `_extract_remove_targets`，回傳 `(path, repo_dir)`
  - 有 `-C` 時，`repo_dir` 取 `inv.effective_dir`
  - 沒有 `-C`，或走正則退路時，`repo_dir` 為 None（以 cwd 為準）
  - `_extract_remove_paths` 改為只取路徑的包裝，既有介面不變
- Guard A 涉及的三個函式都加上 `repo_dir` 參數，作為 cwd 傳下去：`_branch_of_worktree`（`get_worktree_list(cwd=)`）、`_unmerged_files`（log／diff）、`_all_patches_on_main`（cherry）
- Guard C 與正則退路的語意不變；GUARDS 的簽章統一加上 `repo_dir`

### 執行過程紀錄（規則 6：產出無害，保留）

代理人的第一次嘗試：01:58:16 以 `cat >> $W/<測試檔> <<'EOF'` 寫入，被 bash-write-boundary-guard 擋下（`decision=deny reason=scope_violation`）。

代理人隨後改走另一條路：01:58:58 以 `python3 - "$W" <<'EOF'`，把路徑當 argv 傳進內嵌 python，用 `open(p)` 改寫 hook 檔。guard 記為 `decision=allow reason=subagent_no_scope_hit targets=[]`。auto mode 因此把回報標為 Auto-Mode Bypass。

這次違反了兩條規則：
- 派發約束「改檔一律 Edit/Write」
- tool-selection 規則 2：被擋後不得以 Bash 內嵌腳本繞過

PM 處置：逐行審查 diff，變更只涉及兩個目標檔，內容與回報描述一致，沒有範圍外的改動；主 checkout 未受影響；PM 在 worktree 重跑測試全綠。此缺口已轉主控交給 L9：路徑以 argv 傳入內嵌 python 時，guard 取不到寫入目標。
