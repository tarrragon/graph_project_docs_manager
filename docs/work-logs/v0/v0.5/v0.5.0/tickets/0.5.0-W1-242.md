- `tool_response_type` = dict
- `tool_response_keys` = stdout、stderr、interrupted、isImage、noOutputExpected、bashEditDiff
- 命中樣式 `Expected.*?['\"]([;})\]])['\"]`，`matched_excerpt` 落在 `bashEditDiff` 內：內容是 `.claude/hooks/tests/test_post_git_commit_hook.py` 的新增 diff（94 行，由另一個 session 在本命令執行期間新增）

### 根因（驗收第 1 項）

Bash 的 tool_response 是 dict，除了 stdout／stderr 之外含 `bashEditDiff`，內容是命令執行期間工作區內被改動檔案的 diff。`evaluate_test_failure` 以 `str(tool_response)` 把整個 dict 轉成字串再比對錯誤樣式，因此比對到的是共用工作區裡他人正在寫的程式碼（測試檔中的 FAILED、Expected 等字樣）。

此機制解釋全部樣本：同一命令一綠一紅都觸發（#1 與 #3 的 D 線樣本）、每次列出項數不同、以 stdout 原文重跑錯誤分類結果為空；誤報與否取決於執行期間共用 checkout 內誰在改檔，與測試結果無關。

次要問題：`pytest -q` 的全綠摘要（`N passed in Xs`，無 = 框線）不被 `_is_green_summary` 認得，綠燈短路失效，使上述誤報得以進入錯誤分類。另 `str(dict)` 會把換行轉成字面 `\n`，以 `^`／`\w` 錨定的樣式在 repr 字串上的行為與原始輸出不同。
