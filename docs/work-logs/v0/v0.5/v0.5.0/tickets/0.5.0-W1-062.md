## Problem Analysis
<!-- Schema[ANA/Problem Analysis]: 必填（.claude/pm-rules/ticket-body-schema.md） -->

### 問題根因

派發記錄由 `active-dispatch-tracker-hook.py` 於 PostToolUse(Agent) 寫入（`dispatch-record-hook.py` 的 PreToolUse 寫入已 DEPRECATED，為避免被 deny 的派發留下幽靈記錄而遷移）。cleanup 由 `subagent-stop-dispatch-cleanup-hook.py` 於 SubagentStop 執行，兩條比對路徑（agent_handle／agent_id 精準、null-entry FIFO）皆假設條目已存在。同步派發時 Agent 工具要等代理人完成才回傳，PostToolUse 因此晚於 SubagentStop；cleanup 找不到條目，其後寫入的條目 turn_ended_at 永為 null。

時序表（程式碼設計假設）：

| 派發模式 | 記錄寫入 | SubagentStop | cleanup 假設成立？ |
|---------|---------|-------------|------------------|
| 背景／worktree | PostToolUse 於派發啟動時觸發（tracker 檔頭實測） | 之後 | 成立 |
| 同步 | PostToolUse 於工具回傳後 | 之前 | 不成立 |

框架問題判定（兩條 AND）：(1) 抽象可攜：「同步派發時 SubagentStop 早於 PostToolUse 記錄寫入」替換專案名後成立；(2) 資產範圍：根源在 `.claude/hooks/` 通用 hook 與 `.claude/lib/dispatch_tracker.py`。兩條皆成立，屬框架問題。

### 影響範圍

已驗證：-p 同步派發的事件順序與殘留條目（見重現實驗）。受影響：dispatch-active.json 計數、bare-commit-guard 等依活躍派發判斷並行的防護（條目殘留使並行判定虛高）。
未驗證：互動 session 的同步派發是否同序（推論同形，未實測）；背景派發在 -p 下的順序。
dedup（section_comment.py dedup）：#89 命中（SubagentStop 清空時點，同生命週期）。關係判定：引用，非重複非切分——#89 是過早清除，本案是過晚寫入。已 observe：https://github.com/tarrragon/claude/issues/89#issuecomment-6016349204

### 相關 Error Pattern

未執行 /error-pattern query；相關脈絡為 ARCH-019（hook event 時機錯位）：啟動與完成職責分掛時機不同步。非同一案例，僅同族。

## 重現實驗結果

### 實驗方法

`git clone --no-hardlinks` 主 repo 到 scratchpad，於 clone 內以 `claude -p`（bypassPermissions）同步派發一個 general-purpose 代理人回覆 ok；以 clone 內 hook-logs 與 dispatch-active.json 取證。主 repo 未執行 claude -p。

### 實驗執行

claude -p 實際執行 1 次（另有 1 次因無 timeout 指令未啟動）。事件順序（log 本地時間）：

| 事件 | 時間 | 證據 |
|------|------|------|
| PreToolUse(Agent) prompt 長度守衛 | 20:32:45 | agent-prompt-length-guard 通過 |
| SubagentStop cleanup | 20:32:50 | 「dispatch-active.json 不存在，跳過」 |
| PostToolUse(Agent) tracker | 20:32:54 | recorded dispatch agent_id=a575d715b48ff25d5 |

最終 dispatch-active.json：該條目 dispatched_at=12:32:54Z、turn_ended_at=null。

### 實驗發現

已驗證：同步派發順序為 Pre -> SubagentStop -> Post，條目寫入晚於 SubagentStop，永不標記。未驗證：互動 session 同序、背景派發順序（-p）。單次實驗，N=1，順序由工具回傳語意決定而非競態，故不需 N>=5 取樣。

## Solution
<!-- Schema[ANA/Solution]: 必填（.claude/pm-rules/ticket-body-schema.md） -->

結論：根因為寫入點（PostToolUse）與 cleanup 時序假設在同步派發下不相容。

候選方案：

| 方案 | 利 | 弊 |
|------|----|----|
| A 墓碑：SubagentStop 無匹配時記 agent_id 墓碑，tracker 寫入時見墓碑則直接帶 turn_ended_at | 不動寫入點，不重現幽靈記錄 | 墓碑需 TTL 與清理；未驗證背景模式無副作用 |
| B 恢復 PreToolUse 寫入 | 記錄必先於 SubagentStop | 重現被 deny 派發的幽靈記錄（原遷移理由），否決 |
| C cleanup_expired 超時回收 | 零改動 | 回收前並行防護持續虛高，非修復 |

採 A，由 0.5.0-W1-062.1 實作。
