## Solution
<!-- Schema[IMP/Solution]: 選填（.claude/pm-rules/ticket-body-schema.md） -->
### 改動
agent-ticket-validation-hook.py：check_depth_descend 改判實際巢狀層數。
- 主線程（payload 無 agent_id，is_subagent_environment=False）：放行，不計算被派發票深度。
- 子代理人：find_dispatcher_ticket 以 agent_id（精確或 agent_handle 正規式）查 dispatch-active.json（dispatch_tracker）取得其被派發時綁定的 ticket_id，作為「派發者持有票」；以 depth(持有票) < MAX_TICKET_DEPTH 判定 can_descend。映射缺失／過期：退回舊判準（被派發票 depth > MAX 才擋）。
- fail 語意不變：DEPTH_AVAILABLE=False 或計算例外 fail-open，stderr 與日誌雙通道；映射讀取例外同樣 stderr+日誌後退回保守判準。
- constants.py 註解與 AGENT_PRELOAD 規則 9.2 寫明樹深度 vs 巢狀層數。

### 派發者持有票的取得方式
dispatch-active.json 的 entry.ticket_id（active-dispatch-tracker-hook 於 PostToolUse(Agent) 從 prompt 解析寫入），以 agent_id 比對（與 isolated-subagent-main-write-guard-hook 同一映射）。

### 鑑別力驗證（結果：部分成立，需 PM 實地確認）
- 既有證據：is_subagent_environment 以 payload.agent_id 判別，已用於 Edit/Write/Bash 的 PreToolUse（isolated-subagent-main-write-guard 等）。
- 缺口：本代理人無 Agent 派發工具，無法取得 PreToolUse(Agent) 的實際 payload 樣本；repo hook 日誌無 Agent 事件 payload。故 PreToolUse(Agent) 帶 agent_id 屬依共通欄位推定，未實測。
- 失敗方向：若子代理人派發的 payload 缺 agent_id，會被視為主線程而放行（守衛弱化為不擋，非誤擋）。

### Liveness 驗證方式與失敗語意（供 PM 實地觸發）
hook 日誌（.claude/hook-logs/agent-ticket-validation/）每次判定寫一行「深度判定分支=main_thread | subagent_holder | subagent_fallback」。PM 合併後：主線程派發一次應見 main_thread；經子代理人派發一次應見 subagent_holder 或 subagent_fallback。子代理人派發卻見 main_thread = agent_id 缺失，鑑別力不足，需回頭處理。fail 語意：fail-open（模組不可用／例外／映射缺失皆不誤擋）。

### Phase 4 結論
重構需要：否；技術債務：無；品質：A。新增兩個小函式，check_depth_descend 巢狀 <= 3。
