- 位置更正：被誤報的標題在 `0.5.0-W1-531` 的〈重現實驗結果 / 實驗執行〉章節（不是 Problem Analysis），位於 ```` ``` ```` code fence 內，例：`## 1 MissingSourceState`、`## 2a LoadPrompt count=1` … `## 5b SwitcherOverlay items=3 chooseOtherFailureReason=失敗原因`，共 13 行。

- 影響：只發 warning，不阻擋 complete（rc=0，531 已 completed）。
- 重現材料：`git show 63a529225:docs/work-logs/v0/v0.5/v0.5.0/tickets/0.5.0-W1-531.md`（531 completed 版本）即含該 code fence。

### 實測（2026-10-30，主控）
- 531 票面〈重現實驗結果〉中，第 124 行與第 235 行為一組 code fence，fence 內第 128 至 225 行有 16 行以 `## ` 開頭（傾印輸出的變體標題，例如 `## 1 MissingSourceState`）。complete 時 hook 把這些行當成 H2 章節並發出 warning。
- 範圍不限於 warning。ticket 系統以 `^## ` 切章節的地方都沒有略過 fence，搜尋 `.claude/skills/ticket` 與 `.claude/hooks` 共命中十餘處 `(?=^## |\Z)` 形式的正則，例如 acceptance_checkers 下的 execution_log_checker、phase4_review_checker、multi_view_checker、spawn_request_checker，以及 ticket_validator、context_bundle_extractor。另有 worklog_appender 以 `lines[i].startswith("## ")` 判斷區段邊界。
- 推論後果（尚未實測）：章節內 fence 只要含 `## ` 行，該章節的擷取就會在 fence 內被截斷。checker 會讀到不完整的內容，append-log 也可能把內容插進 fence 內，而不是寫到章節末尾。

### 框架問題兩條 AND 判準（逐條）
1. 抽象可攜：成立。換掉專案名與路徑後，問題仍然是「ticket 章節切分以行首 `## ` 判斷，沒有略過 code fence；只要票面貼的是 markdown 格式的工具輸出，就會誤判並截斷章節」。任何 consumer 只要在票面貼這類輸出都會遇到。
2. 根源在 `.claude/` 通用資產：成立。切分邏輯位於 `.claude/skills/ticket/ticket_system` 與 `.claude/hooks/acceptance_checkers`，屬共用框架，不是本專案的程式。
