## Solution
<!-- Schema[IMP/Solution]: 選填（.claude/pm-rules/ticket-body-schema.md） -->
修前漏掉的形態（皆被當 skip）：2> file、2>> file、&> file、&>> file、>& file。1>、fd>=3 已由 284.1 處理。
修法：fd 2 無 & 時改為寫入；>& 後 token 為純數字或 - 才是 fd 複製，否則是檔案目標（新增 redirect 狀態 dup，flush 時判定）；&> 改為寫入。/dev/null 由既有豁免放行。
sibling worktree：本 hook 的 worktree 位於 .claude/worktrees/，改以 cmd 2> .claude/worktrees/w1/lib/a.dart 測試。
commit：2c029c37c

PM 覆核更正（2026-10-19）：代理人回報「本 hook 的 worktree 在 .claude/worktrees/ 底下、checkout 外路徑本來就豁免」不正確——worktree create 的預設版面是主 checkout 同層 <repo>-<ticket>，377（ba287fcdc，本 worktree 已含）起以 git common dir 判定同 repo 後同層 worktree 受阻擋；代理人的同層測試未用 git worktree add 建真實 worktree，故判為不同 repo 放行屬預期。同層 worktree 的 2> 寫入改由合併後實機驗證覆蓋。
補修：0> / 0>> 檔案目標改為寫入（移除 fd 0 skip）；< 與 >&N／<&N／0<&- 維持放行。修前 2 failed、266 passed；修後 268 passed。
