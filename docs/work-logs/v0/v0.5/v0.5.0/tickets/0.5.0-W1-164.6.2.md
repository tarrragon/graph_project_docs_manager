## Problem Analysis
<!-- Schema[IMP/Problem Analysis]: 選填（小型 IMP 可留 placeholder；大型 IMP 建議填寫）（.claude/pm-rules/ticket-body-schema.md） -->
### 派發 context 與執行約束（PM 89，2026-10-14；派發 prompt 不重述，以此為準）

背景（必讀其依據）：
- 0.5.0-W1-164.6.3 已確定機制：git 於持有 index.lock 的期間被 SIGKILL，留下 0 位元組、無行程持有的鎖；被 SIGTERM 則自行清除。subprocess 的逾時參數於逾時時送的是 SIGKILL。
- 既有的溫和終止函式有兩份私有複本，內容幾乎相同：worktree-auto-commit-hook 內一份、ticket CLI 的 git_ops 內一份，寬限期皆為 5 秒；其行為由 worktree skill 的契約測試固定（test_graceful_timeout_contract.py，對兩份參數化）。本票於 lib/git_utils 新增第三處時，行為須與之相同，並把該契約測試的案例移植為 lib 的測試（不修改既有的契約測試檔）。
- 既有函式只終止直接啟動的行程，逾時後只等行程本身結束、不等輸出管線。本票沿用此語意，不引入行程群組終止（該議題由 0.5.0-W1-164.6.8 評估）。
- worktree-zombie-cleanup-hook 已匯入 lib；其寫入類呼叫為刪除已併入的分支、解除 worktree 鎖定、強制移除 worktree；靜默逾時兩處為判斷 worktree 是否有未提交變更、判斷分支是否已併入。前者於 0.5.0-W1-164.6.1 已補 --no-optional-locks，不得移除。

設計要求：
- lib 的函式為公開介面，命名與 git_utils 既有函式的慣例一致；說明文字寫清楚其與 run_git_command 的分工（後者為唯讀查詢並固定帶 --no-optional-locks；本函式供會取鎖或需溫和終止的呼叫）。寬限期以具名常數定義，只定義一次。
- hook 端的呼叫改用該函式後，逾時時的回傳與既有錯誤處理路徑維持等價：原本落入的例外類別、回傳值、已有的錯誤日誌不變。若改用後例外類別不同，於 hook 端轉接，不改變呼叫者看到的結果。
- 靜默逾時補日誌：逾時與其他失敗各一則可區分的訊息，含函式名與 git 子命令；正常完成時不寫該訊息；回傳值不變。

測試要求：
- 先寫測試確認修改前為紅，再實作。
- lib 的契約測試至少含：逾時先收到 SIGTERM（以會記錄所收訊號的子程序驗證）；忽略 SIGTERM 者於寬限期後被終止；孫程序握住輸出管線時等待時間有上界；未逾時時回傳內容正確。耗時上界採寬鬆門檻，不寫緊的毫秒值。測試啟動的子程序於結束時以 PID 逐一確認已不存在，不留孤兒（0.5.0-W1-183 的做法）。
- hook 的測試斷言：三個寫入類呼叫經由該函式（而非直接以逾時參數執行）；兩處靜默逾時於逾時時有日誌、正常完成時無。
- 效果層對照一則：於暫存 repo 讓一個會持 index 鎖的 git 呼叫經 lib 函式逾時，斷言逾時後鎖檔不存在；並有一則對照以直接 SIGKILL 終止同一呼叫，斷言鎖檔殘留（證明 fixture 有鑑別力）。取不到鎖時 skip 並說明，不計為通過。

位置與範圍：
- 主 repo，直接在 main 編輯；不建分支、不建 worktree。只改 where.files 的四個檔。
- 修改 repo 內的檔案只用 Edit 或 Write；變異驗證只在 scratchpad 的副本上進行。
- 不改既有的兩份私有複本與其契約測試；不處理 post-git-commit、confabulation-audit、branch-check（各有子票）。

停手條件（寫入 NeedsContext 並回報，不繞過）：
- 改用 lib 函式後，zombie-cleanup 既有測試有失敗且原因不是測試替身的對象改變。
- lib 的既有測試（test_git_utils.py 及 hooks 測試目錄下與 git_utils 相關者）有任何失敗。
- 1 分鐘 load 高於 45：不跑測試，等候；等候超過 15 分鐘務必回報。高負載下有計時上界的測試失敗不據以判定缺陷，回報即可。
- 編輯被拒；Unable to write index 或 index.lock 錯誤（不刪鎖檔）。

測試執行（只跑涉及的檔，不跑全套）：
- lib：以 uv 於 .claude/lib 或 .claude/hooks 目錄執行其測試檔，執行方式先確認既有慣例。
- hooks：uv run --quiet --directory .claude/hooks pytest tests/test_worktree_zombie_cleanup_hook.py -q；另跑 hooks 測試目錄下檔名含 git_utils 的測試檔。
- load 記入 Test Results。

提交：以 ticket track commit 提交，四個檔中有改到的在同一筆提交內。禁用 git add -A、git add .、git commit -a、pathspec 提交。不吸入其他 session 的檔案。提交後以 git status --porcelain 確認工作區乾淨。

其他：不用裸 cd；git -C 的目標寫字面絕對路徑；終止只針對測試自己啟動的 PID，不用 pkill、killall；每次 append-log 用獨立的一個指令並取得 exit code；自檢的每一句只陳述實際驗證過的範圍。

票面須寫入：
- Solution：lib 函式的介面與分工說明、hook 端三處的改法與例外轉接、兩處日誌的字樣、自檢結果小節。
- Test Results：執行指令、各項紅轉綠、效果層對照的結果（含 skip 與否）、變異驗證、load。

收尾：完成後不要 complete、不要 push；回報 commit hash、三項驗收是否達成、效果層對照的結果、未完成項，由 PM 覆核與審查後再結案。
