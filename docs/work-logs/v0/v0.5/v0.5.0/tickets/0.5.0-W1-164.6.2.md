### 派發 context 與執行約束（PM 89，2026-10-14；派發 prompt 不重述，以此為準）

背景（必讀其依據）：
- 0.5.0-W1-164.6.3 已確定機制：git 於持有 index.lock 的期間被 SIGKILL，留下 0 位元組、無行程持有的鎖；被 SIGTERM 則自行清除。subprocess 的逾時參數於逾時時送的是 SIGKILL。
- 既有的溫和終止函式有兩份私有複本，內容幾乎相同：worktree-auto-commit-hook 內一份、ticket CLI 的 git_ops 內一份，寬限期皆為 5 秒；其行為由 worktree skill 的契約測試固定（test_graceful_timeout_contract.py，對兩份參數化）。本票於 lib/git_utils 新增第三處時，行為須與之相同，並把該契約測試的案例移植為 lib 的測試（不修改既有的契約測試檔）。
- 既有函式只終止直接啟動的行程，逾時後只等行程本身結束、不等輸出管線。本票沿用此語意，不引入行程群組終止（該議題由 0.5.0-W1-164.6.8 評估）。
- worktree-zombie-cleanup-hook 已匯入 lib；其寫入類呼叫為刪除已併入的分支、解除 worktree 鎖定、強制移除 worktree；靜默逾時兩處為判斷 worktree 是否有未提交變更、判斷分支是否已併入。前者於 0.5.0-W1-164.6.1 已補 --no-optional-locks，不得移除。

設計要求：
- lib 的函式為公開介面，命名與 git_utils 既有函式的慣例一致；說明文字寫清楚其與 run_git_command 的分工（後者為唯讀查詢並固定帶 --no-optional-locks；本函式供會取鎖或需溫和終止的呼叫）。寬限期以具名常數定義，只定義一次。
- hook 端的呼叫改用該函式後，逾時時的回傳與既有錯誤處理路徑維持等價：原本落入的例外類別、回傳值、已有的錯誤日誌不變。若改用後例外類別不同，於 hook 端轉接，不改變呼叫者看到的結果。
- 靜默逾時補日誌：逾時與其他失敗各一則可區分的訊息，含函式名與 git 子命令；正常完成時不寫該訊息；回傳值不變。

### Commit 規範

Recommended: commit via isolated index (files must be a subset of this
ticket's where.files; never touches the shared index):
  ticket track commit <ticket-id> -m "..." -- {exact files}
In a linked worktree (files changed under a worktree dir, not the main repo):
add `--worktree <abs-worktree-path>` to the command above.
Fallback (not recommended; only if `ticket track commit` fails or is
unavailable) — use precise staging + verified bare commit only (no pathspec):
  git add {exact files}
  git diff --cached --name-only   # confirm index contains ONLY {exact files}
  git commit -m "..."             # bare commit; no -- <paths> / --only / -o / -a
Forbidden: git add . / git add -A; git commit -- <paths> / --only / -o / -a
  (pathspec-style commit discards the index and rebuilds it from working-tree
   content for the given paths — it silently absorbs unstaged edits other
   sessions may have on the same path, not just already-staged ones)
Before fallback commit: git diff --cached --name-only to check staged scope; git restore --staged <path> for any non-owned file
If bare `git commit` fallback is DENYed by bare-commit-guard-hook (another
dispatch active), stop and escalate to PM; never switch to pathspec /
--only / -o / -a to get around it.
If a commit is later found to have swept in out-of-scope content (e.g. a
peer session's staged changes):
Forbidden recovery actions: git revert; git reset --soft; git commit
--amend; any "reverse apply"/reapply of the diff. None of these may be
used to undo or rewrite the commit.
The ONLY permitted actions are: stop, record the commit SHA and file
list in the ticket, report to PM.
Reason: swept-in content is diff-indistinguishable from a peer's
legitimate concurrent write in the same window, so any of the forbidden
actions above would also undo the peer's legitimate work.

## Solution
<!-- Schema[IMP/Solution]: 選填（.claude/pm-rules/ticket-body-schema.md） -->
- lib/git_utils 新增公開函式 run_with_graceful_timeout(args, timeout, grace=None, **popen_kwargs) 與常數 TERMINATE_GRACE_SECONDS=5（定義一次）。行為同兩份私有複本：逾時 SIGTERM、寬限後 SIGKILL、只等行程本身；回傳 CompletedProcess，逾時拋 TimeoutExpired。docstring 載明與 run_git_command 分工（後者唯讀、固定 --no-optional-locks；本函式供取鎖／寫入類）。
- hook 端：branch -d（10s）與 worktree unlock／remove --force（15s）三處改經該函式。逾時拋出的仍是 TimeoutExpired（SubprocessError 子類），落入既有 except，日誌與回傳值不變，無需轉接。逾時秒數抽為 _READ_TIMEOUT_SECONDS／_WRITE_TIMEOUT_SECONDS。
- 靜默逾時日誌（logger HOOK_NAME，warning）：逾時「{func}: git {subcmd} 逾時（{N}s），保守視為…」；其他失敗「{func}: git {subcmd} 執行失敗（{原因}），保守視為…」（含 returncode 非 0）。正常完成不寫。回傳值不變；--no-optional-locks 保留。
- 自檢：僅驗證所列四檔與下列測試範圍；未修改兩份私有複本與其契約測試；未跑全套。
- 已知影響：skills/worktree/tests/test_worktree_zombie_branch_cleanup.py::TestDeleteBranchIfMerged::test_deletes_branch_when_ahead_zero 以 hook.subprocess.run 為替身偽造 branch -d，改用 lib 函式後替身失效而失敗（測試替身對象改變；該檔不在 where.files，未改）。需另票或 PM 授權更新替身。
