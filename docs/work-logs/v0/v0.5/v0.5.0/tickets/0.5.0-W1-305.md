### 第二個缺陷（同一段日誌發現）

- 同一次觸發也記錄「manual /wrap-decision detected; all signals reset」。該報告沒有手動執行 /wrap-decision，只提到路徑 `.claude/skills/wrap-decision/hooks/wrap-decision-tripwire-hook.py`。
- 原因：is_manual_wrap_invocation 對 UserPromptSubmit 以 `"/wrap-decision" in prompt` 判定，路徑中的 `/wrap-decision` 被子字串命中。
- 後果：任何提到 wrap-decision skill 路徑的訊息都會把所有訊號計數歸零，S1 的連續失敗計數會被無關訊息重置。
