## Problem Analysis
<!-- Schema[IMP/Problem Analysis]: 選填（小型 IMP 可留 placeholder；大型 IMP 建議填寫）（.claude/pm-rules/ticket-body-schema.md） -->
### Context Bundle（PM 於派發前整理，2026-10-14）

**現況（.claude/skills/dart-test-async-guardian/hooks/pre-test-scan.py，121 行）**

- 入口是 `sys.exit(main())`，不匯入 lib，不經 run_hook_safely，所以沒有 liveness，也沒有頂層例外日誌。
- PEP 723 的 dependencies 為空；main 讀 stdin JSON，只處理含 `flutter test` 或 `dart test` 的 Bash 命令，再以子程序執行 `../scripts/async_resource_scanner.py`，回傳掃描腳本的 returncode。

**修法依據（.claude/lib/hook_logging.py）**

- `run_hook_safely(main_func, hook_name, fail_closed=False, ...)` 內部已呼叫 `setup_hook_logging` 與 `mark_hook_entry`，只要改用它包裝入口就會寫 liveness，不必另外呼叫 mark_hook_entry。
- sys.path 插入方式比照其他 skill hook，例如 `.claude/skills/ticket/hooks/acceptance-gate-hook.py` 的檔頭。
- hook_name 用 `pre-test-scan`，和分派器 `hook_name_of` 以檔名推得的名稱一致，liveness 才對得上。

**射程邊界**

- 掃描腳本不擷取輸出（capture_output=False），在分派程序內會直接寫進分派器 stdout。這個問題由 0.5.0-W1-292 承接，本票不處理，維持既有行為。
- 掃描結果回 1 時，CC 不會阻擋（只有 2 會擋），和 docstring 說的「阻止測試執行」不一致。這也是既有行為，本票不改。

**測試**

- 單獨執行：以子程序執行 hook，送不含 flutter test 的 Bash payload，斷言 liveness 檔多一筆 hook=pre-test-scan。
- 分派程序內：以 hook-dispatcher 的 dispatch 執行同一支 hook，斷言同樣有一筆。
- 行為不變：比較改動前後同一組 payload 的 exit code 與輸出（非測試命令回 0，flutter test 指向不存在路徑回 0）。
- liveness 路徑：`.claude/hook-logs/_liveness/<session_id>.jsonl`，測試要用暫存專案根隔離，不寫真實 hook-logs。

## Solution
<!-- Schema[IMP/Solution]: 選填（.claude/pm-rules/ticket-body-schema.md） -->
pre-test-scan.py 入口改為 sys.exit(run_hook_safely(main, "pre-test-scan"))，檔頭以 parents[3] 插入 .claude 到 sys.path 後 from lib import run_hook_safely。run_hook_safely 內含 mark_hook_entry，故每次觸發寫一筆 liveness。main 與掃描子程序邏輯未動（輸出外洩歸 0.5.0-W1-292，exit 1 不阻擋維持既有）。
新增 .claude/hooks/tests/test_pre_test_scan_liveness.py，暫存專案根隔離。

### 自檢結果
- diff 僅入口與 import 兩處，無越界修改
- Python 3.9 相容語法（本檔 PEP 723 為 >=3.10，新增碼無新語法）
- E1：5 組 payload（非測試命令、不存在路徑、非 Bash、空輸入、非 JSON）對照未包裝版本，exit code 與 stdout 相同
- E2：未包裝版本不寫 liveness，斷言對缺口翻紅
- 測試未寫入真實 hook-logs

### Phase 4 重構評估（PM 審查 diff）

- 重構需要：否。hook 只把入口包上 run_hook_safely，掃描邏輯不變；sys.path 插入比照其他 skill hook 的寫法。
- 技術債務：有，都已有票。掃描腳本的輸出外洩由 0.5.0-W1-292 處理；exit 1 不阻擋與 docstring 不符，屬既有行為，本票範圍刻意不改。
- 程式碼品質：A。測試涵蓋單獨執行、分派同程序與尾段子程序三種路徑，並有 E1（行為不變）與 E2（未包裝版本斷言翻紅）。
- 結論：無需重構。
