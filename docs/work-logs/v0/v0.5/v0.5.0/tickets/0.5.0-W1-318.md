## Solution
<!-- Schema[IMP/Solution]: 選填（.claude/pm-rules/ticket-body-schema.md） -->
選修法 (a)：測試目標（位置參數，不含選項值）含未展開 shell 變數時視為無法判定，fail-open 放行並寫 stderr 與日誌。
理由：(b) 代入需處理跨敘述指派、環境變數、迴圈、檔案來源，解析不完整時仍會誤擋或誤放；(a) 與檔頭 fail-open 設計一致，成本最低。代價：變數實際指向目錄時漏擋（已列入檔頭已知破口）。
改動：lib/test_command_parse.py 新增 has_variable_test_target、find_variable_target_statements，find_unwrapped_heavy_with_redirects 略過此類敘述；pre-test-hook.py 新增 _note_variable_target_passthrough（stderr+logger.info）並更新檔頭破口清單。classify_argv_weight（slot_gate 使用，argv 已展開）未動。
呼叫端：find_unwrapped_heavy* 僅 pre-test-hook 使用；find_test_invocations（post-test-hook、test-timeout-pre）、classify_argv_weight（slot_gate、run-with-timeout）行為不變。

### 自檢結果
- E1 字面路徑放行、變數放行、E2 全套件仍 deny、-m $t（選項值）仍 deny、同命令另一裸敘述仍 deny：均有測試
- Python 3.9 相容語法；logger 由參數傳遞

### Phase 4 評估
重構需要：否；技術債務：無（變數指向目錄漏擋已文件化）；品質 A。

PM 審查（2026-10-15）：通過。判定只看位置參數，選項值（-m $t）略過，-- 之後一律視為位置參數。取捨（接受）：變數實際指向目錄時會漏擋，等同未經名額閘門的全套件可通過，與檔頭「判定失敗一律 fail-open」一致，已列入已知破口；誤擋代價（正當命令被擋、需改寫）高於此漏擋，維持原設計取向。受影響呼叫端僅 pre-test-hook，find_test_invocations 與 classify_argv_weight 未變。
