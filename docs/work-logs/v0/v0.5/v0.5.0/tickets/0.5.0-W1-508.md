## 重現實驗結果
### 實驗方法

不新增 ux_capture variant（分析票約束）。以三個依據交叉：
1. Flutter SDK 原始碼（fvm 釘選 3.47.1，`~/fvm/versions/3.47.1/packages/flutter/lib/src/`）：`TextPainter.ellipsis` 與 `TextPainter.didExceedMaxLines` 的文件註解、`RenderParagraph` 對 `TextOverflow.ellipsis` 的轉譯。
2. 已實測樣本：0.5.0-W1-505 的 `build/ux_capture/long_title/zh.png`（主倉庫）。
3. 盤點：以 Python 腳本掃 `lib/**/*.dart`（排除 `app_text.dart` 與 l10n），配對 `AppText(` 括號取完整呼叫，保留「variant 為 body 或未指定」且「呼叫內無 maxLines」者，再逐處讀上下文判定用途與承載容器。

### 實驗執行

- `RenderParagraph`（rendering/paragraph.dart）建構子與 `overflow` setter：`overflow == TextOverflow.ellipsis` 時把 `_textPainter.ellipsis` 設為 `_kEllipsis`（U+2026），與 maxLines 無關。
- `TextPainter.ellipsis` 文件註解：ellipsis 套用於「maxLines 非 null 時，被 maxLines 截斷前的最後一行」，或「maxLines 為 null 時，第一個寬於寬度約束的行」。
- `TextPainter.didExceedMaxLines` 文件註解：maxLines 為 null 時，若 ellipsis 非空且有任一行超出 maxWidth 即為 true。
- `AppText.build`（lib/components/app_text.dart）：全部變體 `overflow: TextOverflow.ellipsis`；body 為 `softWrap: true`、`maxLines: maxLines`（未傳即 null）。
- 掃描結果：20 處命中，其中 `list_row.dart` 一處位於文件註解（非呼叫），實際呼叫 19 處。`empty_state.dart` 的 `maxLines: _isPage ? null : 2` 被腳本排除，人工檢查：`_isPage` 時變體為 subtitle（固定單行，maxLines 被忽略），非 body，不屬本題。

### 實驗發現

已驗證（原始碼與 505 實機截圖一致）：
- `overflow: ellipsis` 加 `maxLines: null`，在寬度受限時只畫到第一個超寬行並在該行加省略號，其後各行不畫。效果等同單行截斷，`softWrap: true` 不改變這點（文字短於一行時看不出差異）。
- 因此 `AppText` 的 body 變體註解「可多行」、`maxLines` 註解「不傳則無上限」、SPEC-004 4.1「未傳 maxLines 時換行」三者皆與實際行為不符。
- 前提為承載容器給出有限寬度。19 處皆在有界寬度內（Panel／Section／ListRow／AppTableRow／SplitRow／Expanded），無一處走無界寬度分支。

未驗證（假設）：
- 各處實際文案在現行視窗寬度下是否超過一行，未逐處實機截圖；「受影響」指「文字超過一行寬時會被截成一行」，屬原始碼推導。
