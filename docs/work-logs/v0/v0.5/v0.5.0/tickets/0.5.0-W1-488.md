## Problem Analysis
<!-- Schema[ANA/Problem Analysis]: 必填（.claude/pm-rules/ticket-body-schema.md） -->
### 另一側的實例：--acceptance 認直線分隔（L18，2026-10-21）

- 實例：建立 0.5.0-W1-470.1 時，acceptance 寫入 failure 正規式字面 `Unable to start the app|Error waiting for a debug connection`，被拆成兩條 acceptance（第 3、4 條）。PM 事後以 `ticket track set-acceptance --edit 3`／`--remove 4` 修正為一條，正規式改用文字寫法（兩擇一）。
- 機制：`.claude/skills/ticket/ticket_system/lib/acceptance_parser.py` 的 docstring 寫明 `|` 是單一值內的多條分隔符，`\|` 跳脫為字面，未跳脫而被拆條時會印警告。所以 --acceptance 這一側是刻意設計，而且有警告。
- 當次沒看到警告的原因：PM 以 grep 白名單 `OK|ERROR|Error` 過濾 create 輸出，警告行被濾掉（bash-tool-usage-rules 規則二已涵蓋）。
- 對本票的意義：同一個 create 命令裡，--acceptance 以 `|` 分條（有跳脫與警告），--where-files 以逗號分隔、不認 `|`（存成單一字串、無警告）。兩邊分隔符不一致，而且只有一側會警告。

### 事實與根因（2026-10-21）

- 同一個 `ticket create` 命令中，`--acceptance` 用「|」分隔多條（create-command.md〈多值參數格式〉），`--where-files` 則經 `lib/list_args.py` 的 `expand_list_arg` 只用逗號切分。
- 主控建 484、485 時，以 `a|b` 傳入 `--where-files`。CLI 沒有報錯，把整串存成單一路徑，`validate_where_files` 也沒有攔下含「|」的路徑。
- 後果：484 complete 時，並行派發驗證把那串路徑當成單一檔案，誤報「缺失檔案」。485 已由主控以 `set-where --files`（逗號）修正。

### 框架問題兩條判準

- 抽象可攜：成立。任何 consumer 依 acceptance 的慣例對 where-files 用「|」，都會被靜默存成錯誤的路徑。
- 根源在 `.claude/` 通用資產：成立，位置在 `.claude/skills/ticket/ticket_system/lib/list_args.py` 與 where-files 驗證。
