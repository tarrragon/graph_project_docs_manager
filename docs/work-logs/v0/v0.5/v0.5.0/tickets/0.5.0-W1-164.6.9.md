## Problem Analysis
<!-- Schema[ANA/Problem Analysis]: 必填（.claude/pm-rules/ticket-body-schema.md） -->

### 問題根因

hook 內部單一 worktree 最壞逾時總和（status 10 + unlock 15+5 + remove 15+5 + log 10 + branch -d 10+5）約 75 秒，大於外層 30 秒；外層先到期是結構上可能的。現行 lib（164.6.11／164.6.14／164.6.15）已讓 run_with_graceful_timeout 在 hook 收到 SIGTERM 時 killpg 轉送子群組，故 TERM 路徑下 git 能自清鎖；殘留風險只在外層不經 TERM 直接 SIGKILL hook 時。

### 影響範圍

僅 worktree-zombie-cleanup-hook.py 的三個寫入類呼叫（unlock／remove／branch -d）；status／log 為 subprocess.run 直接 SIGKILL 單一 git，不在本實驗範圍。已驗證與未驗證項見實驗發現。

### 相關 Error Pattern

未另行查詢；相關結論見 0.5.0-W1-164.6.3、164.6.8.2。

## 重現實驗結果

### 實驗方法

scratchpad e69：暫存 repo 含一個 PID 已死、mtime 為 2020 的 locked agent worktree；PATH 前置 git 包裝腳本，對 `worktree remove` 建 .git/index.lock 並 sleep（收 TERM 時清鎖退出，模擬 git；收 KILL 則殘留）。以 `uv run` 啟動真實 hook（CLAUDE_PROJECT_DIR 指向暫存 repo），git 卡住 1 秒後模擬外層到期。外層實際 30 秒以提早到期代替（不等 30 秒），三種模式各 5 次：tree＝對 uv 啟動鏈整棵後代送 TERM；top＝只對 uv 送 TERM；topkill＝只對 uv 送 SIGKILL。

### 實驗執行

| 模式 | N | 7 秒後 hook 鏈 | 包裝 git | index.lock |
|---|---|---|---|---|
| tree（TERM 整棵） | 5 | 已結束 5/5 | 已結束 5/5 | 無 5/5 |
| top（TERM 僅 uv） | 5 | 已結束 5/5 | 已結束 5/5 | 無 5/5 |
| topkill（SIGKILL 僅 uv） | 5 | uv 已結束 5/5 | 存活 5/5（孤兒） | 殘留 5/5 |

三種模式 worktree 目錄皆仍在（remove 未完成）。實驗後以 PID 指名清掉殘留行程。負載：load avg 約 24。

### 實驗發現

已驗證：外層以 TERM 到期（含只送 uv）時，現行 lib 轉送使 git 收 TERM、鎖被清，N=10 全數乾淨。外層直接 SIGKILL 時 git 成孤兒持鎖，N=5 全數殘留（SIGKILL 不可攔截，hook 內任何機制皆無解）。
未驗證：(1) git 為包裝腳本模擬，非真實 git 持鎖（真實 git 收 TERM 清鎖已由 164.6.3 驗證）；(2) 實際 harness 是否在 TERM 後升級 SIGKILL 及其寬限秒數；(3) hook 的 python 行程本身在 topkill 下的結局未單獨量測；(4) status／log 等唯讀呼叫路徑；(5) 外層以 30 秒而非縮短值到期的行為。

## Solution
<!-- Schema[ANA/Solution]: 必填（.claude/pm-rules/ticket-body-schema.md） -->

### 結論

內部逾時總和大於外層不構成目前的缺陷：TERM 路徑已由 164.6.14 的轉送覆蓋，殘留鎖僅出現在外層直接 SIGKILL，該情境任何 hook 內機制皆無解，只能縮短被 SIGKILL 的機率。

### 候選處置

| 方案 | 代價 | 評估 |
|---|---|---|
| A 維持現狀 | 0 | TERM 路徑已乾淨；SIGKILL 風險不變 |
| B 整體期限逐步扣減（每次呼叫 timeout=min(原值, 剩餘-grace)） | 改 hook 與測試，中 | 讓內部溫和終止先於外層到期，直接降低走到 SIGKILL 的機率；建議 |
| C 調高外層逾時 | 拉長 SessionStart 阻塞 | 治標，使用者每次多等 |
| D 單 worktree 失敗即中止本輪 | 清理變慢 | 與 B 擇一即可 |

建議：採 B（低優先）。
