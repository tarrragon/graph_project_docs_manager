同一命令、同一 session，差別只在 stdout 是否被導向檔案。

### 盤點（PM，2026-10-15）

**以 stdout 成功標記判定成敗的 hook（排除 git commit 類）**

| hook | 判定方式 | 成功標記 | 對應命令 | 輸出被吸走時的行為 |
|------|---------|---------|---------|-----------------|
| .claude/hooks/parallel-dispatch-verification-hook.py | is_bash_success | "已完成"、"成功" | complete、finish | 判為非成功，靜默結束，驗證不執行（285 實例） |
| .claude/hooks/session-context-guard-hook.py | 自行比對 | "已完成" | complete、finish、batch-complete | 不計數，不提醒 handoff |
| .claude/skills/ticket/hooks/post-ticket-lifecycle-hook.py | 自行比對 | 含 "已完成" 等 | complete | 不跑完成後檢查點 |
| .claude/skills/ticket/hooks/handoff-cleanup-hook.py | is_bash_success（忽略大小寫） | "[OK]"、"已完成"、"completed" | handoff 相關 | 不清理 |
| .claude/hooks/parallel-claim-audit-hook.py | is_bash_success | "[OK] 已接手" | claim | 不記錄 claim 快照 |
| .claude/skills/ticket/hooks/needs-context-listener-hook.py | is_bash_success | "已追加日誌到" | append-log NeedsContext | 不通知 PM |
| .claude/skills/ticket/hooks/cli-error-feedback-hook.py | is_bash_success（反向：非成功才給回饋） | "[OK]" | ticket CLI 全部 | 誤判為失敗並給回饋，或因 stdout 沒有錯誤文字而什麼都不做 |

**「輸出被吸走」的三種形態**（都會讓 stdout 不含標記）

1. 重導向到檔案：`ticket ... > log 2>&1`。結束碼沒有被遮蔽。
2. 以分號接其他命令：`ticket ... > log 2>&1; echo rc=$?`（285 實例）。結束碼被遮蔽。
3. 命令替換：`out=$(ticket ... 2>&1); rc=$?`。結束碼被遮蔽。**這是 `.claude/rules/core/bash-tool-usage-rules.md` 統一檢查清單要求寫入類 CLI 使用的寫法**（判成敗讀 rc，不讀輸出外觀）。所以現行規則與標記判定在設計上互相衝突：遵守規則的呼叫，正好會讓完成類 hook 靜默略過。本 session 大量使用此寫法執行 append-log，needs-context-listener 對這些呼叫都不會觸發。

**結束碼是否被遮蔽**（PostToolUse 只在 shell 層結束碼為 0 時觸發，見 .claude/lib/bash_tool_response.py 模組說明）

- 單一命令，或以 `&&` 串接、且 ticket 呼叫失敗時後續不執行：沒有遮蔽。收到 PostToolUse 就代表 ticket 呼叫成功（75 走 PostToolUseFailure，已由 auto_commit_failure_as_success 處理）。
- `;`、`|`（未設 pipefail）、`||`，或命令替換後接其他陳述：遮蔽。收到 PostToolUse 不能推得 ticket 呼叫成功。
- `.claude/lib/ticket_command_parse.py` 能找出呼叫（含 `$( )` 內的呼叫，實測 5 種形態皆可），但目前不回報遮蔽與否。
更正：上段「本 session 大量使用此寫法執行 append-log，needs-context-listener 對這些呼叫都不會觸發」不準確。needs-context-listener 只處理寫入 NeedsContext 章節的 append-log，本 session 的 append-log 都不是寫這個章節。正確的說法是：若以 out=$(...) 的寫法向 NeedsContext 追加，listener 會因 stdout 沒有標記而不通知 PM。本 session 沒有實際發生過。
