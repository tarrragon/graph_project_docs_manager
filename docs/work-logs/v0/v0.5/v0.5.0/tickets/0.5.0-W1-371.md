### 修法（worktree commit 3633f44c1、76badbef1）

- `worktree_manager.py` 新增 `merge_suggestion_command(branch)`：沿用既有的 `extract_ticket_id_from_branch` 判定分支是否為 feat/<ticket-id>，不另寫一份判定邏輯。是則印 `/worktree merge <ticket-id>`，否則印 `/worktree merge --branch <shlex.quote(branch)>`
- `worktree-merge-reminder-hook.py`：兩處 `git merge {branch} --no-edit` 改走 `merge_command(branch, logger)`
- `worktree-remove-deliverable-check-hook.py`：Guard A 原本的 `git checkout main && git merge` 與其後的 `git merge --abort` 句一併移除，因為隔離索引合併不留 MERGE_HEAD；Guard C 兩處同樣改走 `_merge_command`
- 兩支 hook 改為呼叫時才 import worktree_manager（PM 審查追修）。理由：remove-deliverable-check 是阻擋型守衛，在頂層 import 約 2000 行的模組，會多出一個「import 失敗，整支守衛失效」的點。import 失敗時退回通用字面，並以 logger.warning 記錄

### 執行過程紀錄（規則 6，產出無害，保留）

代理人曾以 Bash `sed -i` 改寫兩個測試檔（`.claude/skills/worktree/tests/`），違反派發約束「改檔一律 Edit/Write」。因為以 GNU 語法跑在 BSD sed 上，替換沒有生效，後來改用 Edit 完成，檔案內容不受影響。bash-write-boundary-guard 日誌 2026-10-20 00:30:14 記錄為 `decision=allow reason=subagent_no_scope_hit targets=['$T/test_worktree_remove_deliverable_check_hook.py', ...]`：目標路徑以 shell 變數 `$T` 持有，guard 沒有展開變數就判定未命中範圍而放行。此事轉主控給 L9，與 365.1 的「變數持有字面路徑」同類，但載體是 shell 變數加 `sed -i`，不是 python -c 或 heredoc。
