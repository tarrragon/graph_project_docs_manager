# Execution Log

## Task Summary

新增保留「同一專案最後一次完成的輪次結果」的 provider（切換專案時清除）；新增 domainMatrixProvider 由它衍生，DomainReady 不再帶 matrix；domainSwimlaneProvider、firstNodeInLaneQueryProvider 改讀同一來源；_emptyLanes 移入投影層

---

## Problem Analysis
<!-- Schema[IMP/Problem Analysis]: 選填（小型 IMP 可留 placeholder；大型 IMP 建議填寫）（.claude/pm-rules/ticket-body-schema.md） -->
矩陣為載入當下快照(DomainReady.matrix)，泳道讀 scanRoundProvider 即時狀態；重掃/取消/失敗時輪次非 Completed，泳道為 null 而誤顯示需先選定 UC，且新輪完成後兩者跨輪錯位。

## Solution
<!-- Schema[IMP/Solution]: 選填（.claude/pm-rules/ticket-body-schema.md） -->
新增 lastCompletedRoundProvider(scan_round.dart)：收 Completed 即更新，Running/Idle/失敗保留，工作區路徑變更清除。新增 domainMatrixProvider、domainEmptyLanesProvider(投影層 projectEmptyLanes 與泳道共用 _orderedBundles 列序)；domainSwimlaneProvider、firstNodeInLaneQueryProvider 改讀同源；DomainReady 移除 matrix；畫面 _emptyLanes 刪除，_SwimlaneBody 分支邏輯未動。loader 載入起手讀 lastCompletedRoundProvider 確保擁有者先於輪次建立。
既有測試調整(DomainReady 契約改變)：domain_view_loader_test(B1/B4 改讀 domainMatrixProvider)、indirect_dependency_test 與 domain_view_state_driven_test(matrix 改以 domainMatrixProvider override，後者另 override domainEmptyLanesProvider)、helpers/domain_view_fixtures(fixtureReady 去 matrix，domainFixtureOverrides 加兩個 override 與 emptyLanesOfMatrix)。
Phase 4：重構需要=否；技術債=無新增(本機 fvm dart format 會大量改動無關檔，已還原未提交)；品質 A；結論無需重構。
