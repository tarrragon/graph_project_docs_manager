### WRAP 評估：lavender 自行補定規則（2026-10-07）

範圍：本票寫入 SPEC-001 §1〈泳道布局規則〉的兩條規則超出 0.5.0-W1-092 裁決（R1／C2／B2／E2）。以 WRAP 快速+ 模式評估，不選定，交用戶裁決。事證腳本：以 PyYAML 解析 6 UC flow 區塊與 8 份 domain-map frontmatter（本專案），flutter_balance 1 UC 同法。

#### 議題 1：同層 domain 的列序

錨點：R1 的目的是「換 UC 列序不跳動、與矩陣一致」；R1 選項本身註明「同層內次序需另定」。

| 候選 | 規則 | 本專案結果 | 致命風險 |
|---|---|---|---|
| 1a 維持 lavender 版 | 寫死 9 列：畫面、schema、workspace、corpus、graph、diagnostics、ticketdetail、history、layout（取 system-layer §2 圖由左而右） | 同左 | 寫死的是本專案 8 個 domain 名；App 觀測其他專案時（flutter_balance 只有 1 個 domain、名稱不同）規則無從套用，未列名的 domain 落在哪一列未定義 |
| 1b 層序取 §2，同層以 domain 名字母序 | 層序同 1a，同層 tie-break 為字母序 | L2 變 diagnostics、graph、history、ticketdetail | §2 分層只寫在 system-layer 散文，機器讀不到，對其他專案同樣無法套用 |
| 1c 層序由 bundle_dependency 推導，同層字母序 | 層＝沿 depends_on_bundles 到無依賴 bundle 的最長路徑長；同層字母序 | L0 schema、workspace；L1 corpus、history；L2 diagnostics、graph、ticketdetail；L3 layout | 推導結果與 §2 宣告不同：history 只依賴 workspace，推導為 L1，§2 宣告為 L2；沒有 bundle_dependency 的專案全落 L0，只剩字母序 |
| 1d 規格不定，交實作 | 只規定「固定、與 UC 無關」，次序由實作決定 | 未定 | 測試無期望值可比對；矩陣與泳道可能各自實作出不同次序 |

事證：R1 文字為「system-layer §2 由下而上」，§1 表格列序（Workspace 在 Schema 前、TicketDetail 在 Layout 前）與 §2 圖不同，lavender 取的是 §2 圖。依賴邊：corpus→schema,workspace；graph／diagnostics／ticketdetail→corpus；history→workspace；layout→graph。

#### 議題 2：無法放置的步驟

錨點：泳道是本 App 的差異化元件，結構違規要被看到，但報告職責在 Diagnostics。

在現行裁決下會出現「無法放置」的情形：
- 「主線不構成單鏈」：在 W1-001 裁決 (c)（主線順序取清單順序、validate 檢查 `next` 一致）下，若泳道規則改以清單順序定主線，此情形不會發生；但本票寫入的〈主線〉判定式仍是「自起點依 `next[0]` 走」，與 (c) 字面不一致（兩者在現況結果相同：6/6 個 UC 的 `next` 主線鏈等於清單順序，flutter_balance 1/1 亦同）。
- 「`branch_from` 指向不存在的步驟」：上游無任何 validator 檢查 flow 內參照完整性（只有 uc_registry 取主線摘要），對被觀測的其他專案可能發生。現況本專案 0、flutter_balance 0。
- 「`branch_from` 指向分支步驟（巢狀分支）」：schema 不禁止（branching 只定 forward_field、cardinality one）。現況兩語料皆 0。lavender 版把它歸為無法放置，但 C2「插在起點後」可遞迴套用。

| 候選 | 規則 | 致命風險 |
|---|---|---|
| 2a 維持 lavender 版 | 未輸出的步驟依檔內順序接在最後一欄，不畫 branch_from 邊，本畫面不顯示錯誤，交 Diagnostics | 使用者在泳道看到一個無連線的尾欄節點，無任何提示，需自己去破洞報告找原因；Diagnostics 是否有對應類別未確認 |
| 2b 對齊 (c) 並遞迴 C2 | 主線改為清單順序（刪除「主線不構成單鏈」）；巢狀分支插在其起點之後；只剩懸空 `branch_from` 接最後一欄 | 規則變長；巢狀分支無真實資料可驗，需合成 fixture |
| 2c 規格不定，交實作或 Diagnostics | 只寫「結構違規由 Diagnostics 報告」，泳道行為不定 | 實作可能丟掉步驟；測試無期望值 |
| 2d 泳道內就地標示 | 同 2a 或 2b 的放置，另在該節點加「結構違規」標記 | 本畫面多一種節點狀態，需 SPEC-004 元件與 UX 審查 |

#### 傾向與盲點

- 議題 1 傾向 1c：App 觀測的是其他專案，只有 bundle_dependency 是機器可讀的分層來源。盲點：用戶裁決 R1 時是否只針對本專案；1c 會讓 history 與 §2 宣告不同層，需決定以宣告或推導為準。
- 議題 2 傾向 2b（並維持本畫面不另顯錯誤）：與 (c) 對齊後，現況唯一可能的情形只剩懸空參照。盲點：未確認 Diagnostics 目前是否有 flow 結構違規類別（若無，2a／2b 的「交 Diagnostics」落空）。

#### 需用戶裁決

1. 同層列序：1a／1b／1c／1d？若 1c，history 以推導（L1）還是 §2 宣告（L2）為準？
2. 無法放置：2a／2b／2c／2d？〈主線〉判定式是否改為 (c) 的清單順序？
