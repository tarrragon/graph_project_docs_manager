## Solution
<!-- Schema[IMP/Solution]: 選填（.claude/pm-rules/ticket-body-schema.md） -->
新增 .claude/lib/ticket_completed_verifier.py：make_completed_verifier，命令內每張票 status 為 completed 且 completed_at 距現在 120 秒內才回 True；票不存在、無票號、completed_at 缺漏拋 VerifierUnavailable，lib 退回標記判定；讀票用 find_ticket_file 加 parse_ticket_frontmatter，根為 get_shared_state_root。三支 hook 改呼叫 is_bash_success 並傳 command 與 state_verifier：parallel-dispatch-verification、session-context-guard、post-ticket-lifecycle；後兩者原自行比對標記，計數與檢查點只在共用判定成功時發生一次。

### 自檢結果
- 窗 120 秒涵蓋 CLI 收尾數秒，遠小於重新 complete 舊票的間隔；容忍 5 秒時鐘落差。
- 讀票失敗拋例外而非回 False 或 True，不會被當成功。
- 既有測試中依賴未遮蔽命令看標記的 7 項改用遮蔽命令（語意依 286 第 1 層變更）。
- Python 3.9 相容。

### Phase 4 重構評估（PM 審查 diff）

- 重構需要：否。共用驗證器與 is_complete_transition_success 集中在 .claude/lib/ticket_completed_verifier.py，三支 hook 呼叫同一個入口。
- 技術債務：無新增。

- 結論：無需重構。
