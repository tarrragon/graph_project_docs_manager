### PM 補充：2026-10-12 同區域的三筆實測（派發前）

當日共用工作樹有四個 PM session 與多個代理人並行，load average 約 55 至 110。

1. **寫入成功但共用索引同步失敗，留下過期索引項**（本 session 實測，17:04）：`ticket track append-log` 回 rc=0，並印出 `[WARNING] 共用 index 同步失敗（update-index）：fatal: Unable to create '.git/index.lock': File exists.`。提交已成立（HEAD 含新內容），工作區與 HEAD 雜湊相同，但 `git rev-parse :<票檔>` 仍為寫入前的舊雜湊，`git status` 顯示 `MM`。此時任何裸 commit 會把該票檔回滾為舊內容。處置為 `git restore --staged -- <票檔>`，其後三平面雜湊一致。警告訊息未給出這條補救指令，也未說明後果。
2. **complete 的 auto-commit 因 HEAD 被推進而 CAS 失敗**（另一 session 回報，約 15:52）：rc=75，訊息為 `update_ref failed for ref 'HEAD': is at <新> but expected <舊>`，票檔停在工作區未提交；依訊息列出的 `ticket track commit` 補提交後正常。
3. **票面寫入期間共用索引出現瞬時暫存項**（另一 session 觀察，約 15:24）：代理人寫票面時該票檔於 `git status` 短暫顯示 `MM`，數十秒後隨提交消失。對正在共用索引上合併的其他 session 有被夾帶的風險。

對本票的含意：第 1 項顯示「提交成功、索引同步失敗」是一條獨立的失敗路徑，rc=0 而後果是靜默的過期快照；鎖與重試的設計須涵蓋同步步驟，或在同步失敗時以非零 rc 或明確的補救指令呈現。以上為觀察，是否納入本票範圍或另立子票由執行者於分析後提出。
