- 程式位置：`.claude/hooks/bare-commit-guard-hook.py` 的 `main()` 在 `invocation = invocations[0]` 之後依序是 `_has_amend_exemption`（命中就整條 return 0）→ `_pending_operation_in_dirs(_resolve_detect_dirs_multi(...))` → `_has_all_exemption` → `_is_index_discarding_form` → 並行期 staged 範圍檢查。程式註解自述「僅處理第一筆，沿用單一命令對應單一 commit 的隱含假設」，修正時一併改寫該註解
- 改法要點：進行中操作偵測維持「全部目標聯集」，且移到任何單筆豁免之前；之後對每筆 invocation 跑單筆判定鏈，任一筆回 2 就擋。staged 與 unstaged 的查詢以 project_root 為準，可在迴圈外取一次

- 測試環境：用 `uv --directory <checkout>/.claude/hooks run pytest <path>`，不要用 `uv run --with pytest`（後者在 worktree 內缺 pyyaml，見 0.5.0-W1-353）

## Solution
<!-- Schema[IMP/Solution]: 選填（.claude/pm-rules/ticket-body-schema.md） -->
main() 改為：進行中操作偵測（全目標聯集）先於逐筆迴圈；迴圈內 --amend 只 continue 該筆；其餘走新抽出的 _judge_invocation（單筆判定鏈，含 pending 阻擋、-a、index-discarding、並行期裸 commit），任一筆回 2 即擋。rebase-edit WARN 每命令一次。改寫「僅處理第一筆」註解。344 日誌分流未動。

產生路徑盤點表（exit 路徑 / 測試覆蓋）：
- pending 阻擋(非 amend 筆): 覆蓋 (TestMergeHeadPresent, A2/F/B/D)
- amend 筆豁免: 覆蓋 (單筆 amend、C)
- -a 非並行期放行: 覆蓋 (既有)
- -a 並行期安全放行/阻擋: 覆蓋 (既有、E、G)
- index-discarding 並行阻擋/非並行 WARN 放行: 覆蓋 (TestIndexDiscardingFormNoLongerBypassed)
- 並行期裸 commit 放行/阻擋: 覆蓋 (TestParallelPeriodBareCommit、E1 對照)
- 非並行裸 commit WARN: 覆蓋 (既有)
- rebase-edit WARN 一次: 既有單筆覆蓋；多筆只 WARN 一次無專屬測試(缺口，低風險)
- 無法解析/無 commit 早退: 覆蓋 (既有，未改)
