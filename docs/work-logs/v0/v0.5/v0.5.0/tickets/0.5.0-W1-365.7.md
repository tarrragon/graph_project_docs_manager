## Task Summary

<!-- Schema[IMP/Problem Analysis]: 選填（小型 IMP 可留 placeholder；大型 IMP 建議填寫）（.claude/pm-rules/ticket-body-schema.md） -->

## Solution
<!-- Schema[IMP/Solution]: 選填（.claude/pm-rules/ticket-body-schema.md） -->
三形態處理（既有 _const_path/_argv_index 路徑上擴充，commit 0ef582537）：
- from sys import argv [as x]：_collect_argv_names 收集別名，_is_argv 認列為 argv。
- a = sys.argv / a = <別名>：同函式反覆至不再增加，別名同樣走 argv[n]。
- 負索引：_argv_index 認 UnaryOp(USub, Constant)，回負值；_const_path 以 -len<=i<len 判範圍，超出回 None（放行）。
- 對應出的引數沿用 _python_argvs 組合展開與邊界檢查；直譯器帶參數選項未動。
381 文件反查（SKILL／references／pm-rules，grep from sys import argv、argv[-k]、= sys.argv）：僅命中 hook-architect-technical-reference.md:877 的處置判準敘述句，非受限目錄寫入例行範例。結果：無受影響範例。

第二輪補修（commit 397274853）：_argv_index 移除 not isinstance(bool) 排除，改 int(idx.value)，bool 依 Python 語意視為 int（True→1、False→0）；-True 走負號分支本就得 -1。未改為 fail-closed。
### PM 收尾（2026-10-20）

- 合併：第一輪 b3179ce42；推送後審查指出 bool 索引回歸，第二輪補修 397274853，合併提交 b3ed4ab6a，皆已推送 origin/main。主控兩輪條件已滿足。審查另建議「argv 下標無法解析即 fail-closed」不採（與 365.5 經主控接受的 fail-open 一致）。
- 第二輪 E2 的引數順序由代理人更正（[True] 搭 "$W" x、[-True] 搭 x "$W"，使下標指到 $W），PM 原指令順序有誤，更正正確。
- 收緊前文件反查（381）：無。
