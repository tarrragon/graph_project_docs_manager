## Problem Analysis
### 問題根因

直接原因有兩層，彼此獨立：

1. **合併前驗證套件由改動目錄決定，不由產物的消費者決定**。0.5.0-W1-096.6 的改動全在 `.claude/skills/doc/`，合併前後執行的是 hooks＋lib、doc 兩套 pytest（該票 Test Results），未執行 App 端 `test/unit/schema/`。但它改動的 `tracking_schema.json` 是 App 契約測試直接讀取的輸入（`builtin_schema_version_contract_test.dart`、`framework_schema_json_within_builtin_test.dart` 皆以相對路徑讀框架 JSON）。「main 全綠」的回報只涵蓋框架套件。
2. **副本同步票被排成「框架票合併之後」而非「同一次合併」**。0.5.0-W1-096.8 於 096.6 合併前 43 分鐘已建立（建票 10-08 00:42，096.6 進 main 01:25），`when` 欄寫「096.6 合併後、096.7 之前」，strategy 寫「worktree 合入 096.6 **或**待其進 main 後開」。票面引用了 W1-070.2 前例，但前例中承重的那一步（副本票 worktree 先合入框架票分支、PM 只合併副本票，使兩者一次進 main）在此變成二選一，實際走了後者。

兩層疊加的結果：096.6 於 89c52e081 單獨進 main，守衛測試（已存在）沒有被執行，紅燈窗口自 10-08 01:25 持續到 10-08 14:45（096.8 於 b7772fe4b 進 main），約 13 小時 20 分。
