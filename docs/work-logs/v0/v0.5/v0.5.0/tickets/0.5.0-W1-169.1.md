## Problem Analysis
<!-- Schema[ANA/Problem Analysis]: 必填（.claude/pm-rules/ticket-body-schema.md） -->
### 問題根因

`WorkspaceRepository._persistAndInspect` 先寫偏好設定、後呼叫 `_inspect`，寫入與否不看探測結果。資料夾不可用時，已存路徑照樣被覆寫成不可用的路徑。

### 0.2.0-W1-021「先寫入」理由的射程（主控指派要求先讀）

021 的理由只涵蓋兩個 key 之間的順序，不涵蓋「寫入」與「探測」之間的順序：
- 021 程式註解與 `docs/tech-decisions.md` 補記「shared_preferences 的 key 版本化與遷移策略」：path key 先、版號 key 後。理由：中途失敗只會留下「有 path 無版號」，此形狀與 v0 舊資料相同，`_migrateSchema` 可讀出 path；反過來「有版號無 path」無從補救。
- `_inspect` 放在 try 之外的註解（同函式 dartdoc）理由是：避免 `_inspect` 的例外被誤判為持久化失敗，也避免同一 path 探測兩次。它要求 `_inspect` 不在 try 內，不要求 `_inspect` 在寫入之後。
- 全庫查無任何文件為「先寫入、再探測」給出理由：tech-decisions、SPEC-005 §2.2 回饋點表、W3-121 均未論及兩者先後。

結論：把整段寫入移到探測之後、且只在 `WorkspaceReady` 時寫入，021 的兩個不變式（path 先於版號；兩個 key 同次寫入）與 `_inspect` 不入 try 的理由都保持成立。

### 影響範圍

- 程式：`lib/workspace/workspace_repository.dart` 的 `_persistAndInspect`（`chooseFolder` 與 `openPath` 共用）。
- 規格：SPEC-003 §3.1〈互動反應〉「選定資料夾不可讀或不存在」列、§3.7 兩列（「選擇其他（選定資料夾不可讀或不存在）」「最近專案項（點擊後判定不可讀或不存在）」）、SPEC-001 §8 邊界表「Domain 視圖選定資料夾不可讀或不存在」列，四處都寫「不寫入已存路徑」。`openPath` dartdoc 也寫「失敗時……不寫已存路徑」。
- 已驗證：上列事實皆為讀碼與讀規格得出。未驗證：未實機、未跑測試。

### 相關 Error Pattern

### 實驗執行

| # | 分支 | path key | 版號 key | 回傳 | 下次啟動 restore |
|---|------|----------|----------|------|-----------------|
| 1 | `open()` 拋例外 | 未寫 | 未寫 | `NotRemembered(state)` | 舊路徑 |
| 2 | path `writeString` 回 false | 磁碟未寫（`setString` 回 false 時記憶體快取可能已更新，跨啟動以磁碟為準；adapter 行為為推論） | 未寫 | `NotRemembered(state)` | 舊路徑 |
| 3 | path `writeString` 拋例外 | 未寫 | 未寫 | `NotRemembered(state)` | 舊路徑 |

| 5 | path 成功、版號拋例外 | 已寫 | 未更新 | `NotRemembered(state)` | **新路徑**：提示說「下次啟動需重新選擇」，實際會還原 |
| 6 | 寫入全成功、`_inspect` 回 `WorkspaceUnavailable` | **已寫（覆寫原已存路徑）** | 已寫 | `Selected(Unavailable)` | 不可用路徑 → 降級 `state-domain-unset`，常駐「無法存取先前的資料夾」；原本可用的專案不再被還原 |
| 7 | 1–3 或 5 之一 ＋ `Unavailable` | 同該分支 | 同該分支 | `NotRemembered(Unavailable)` | 同該分支（169 主票的連發組合） |

第 6 列兩個入口皆可達：`chooseFolder` 選到不可讀資料夾；`openPath` 點擊已刪除、已搬移或磁碟未掛載的最近專案項（`_buildRecentProjectItem` 一律 enabled，見 169 主票）。後者可達性高：只要最近清單裡有一項失效即可。

### 實驗發現

已由讀碼確立：
1. 第 6 列與 SPEC-003 §3.1、§3.7 兩列、SPEC-001〈8.2〉表、`openPath` dartdoc 共五處「不寫入已存路徑」皆不一致。使用者可見後果：點一次失效的最近專案，下次啟動就落到「無法存取先前的資料夾」，原本正在用的專案要重新選。
2. 第 5 列「未能記住」提示與事實相反。第 4 列結局正確，但日誌記 `persistCompleted`，與版號 key 實況不符。
3. 若寫入只在 `WorkspaceReady` 時發生，第 7 列在產生端消失：`Unavailable` 時不寫入，`failureReason` 恆為 null，回 `Selected(Unavailable)`。即 169 主票候選 X3。

未驗證：`setString` 回 false 時記憶體快取是否已更新（影響本次執行期內的 `readString`，不影響跨啟動結論）；無測試覆蓋第 4–7 列。
