### Context Bundle（L23 開線，2026-10-30，HEAD c2e596c1a）

**範圍修正**：原 AC1（DomainReady.matrix 非空）對象已於 205.2.1 移除，已以新 AC（第 4 項）取代：評估 `domainMatrixProvider`（`lib/screens/domain_view/domain_view_providers.dart`，回傳 `DomainMatrix?`，無輪次／建圖不可用／無節點時為 null）在畫面的 null 退路。

**讀碼現況（PM 查證，符號名定位）**
- null 退路：`_MatrixBody.build` 的 `matrix?.rows ?? const <DomainRow>[]`；頂層函式 `_jumpFocus` 的 `matrix?.rows...`；`_SwimlaneBody.build` 將 `matrix` 傳入 `_ucTitleOf`。實作者須 grep `domainMatrixProvider` 全量列出，不以此清單為準。
- 判斷要點：`DomainReady` 由 `lib/app/domain_view_loader.dart` 在節點數 > 0 時進入；但 `domainMatrixProvider` 讀 `lastCompletedRoundProvider`，兩者來源不同，須確認 DomainReady 下 matrix 是否可能為 null（例如輪次切換的瞬間、`_SwimlaneBody` 的投影準備中分支明確處理 `lastCompletedRoundProvider == null`）。可達者保留並註明業務狀態，不可達者移除。
- 三個欄位（`domain_view_state.dart`）：`DomainLaneEdge.fromLane`／`toLane` 只由 `domain_view_projection.dart` 寫入，lib 內無讀取者；`DomainLaneNode.stepId` 須 grep 讀取者。票庫內僅 114.20／114.21／208 提及，實作前讀這兩張確認是否有預定消費者。測試若斷言這些欄位，刪欄位時一併判斷該測試是否只在測欄位本身。
- `_CellDetailPanel.build` 以 `ref.read(domainViewStateProvider) as DomainReady` 強制轉型；父層已持有 `DomainReady state`，改為建構子參數傳入。

## Solution
<!-- Schema[IMP/Solution]: 選填（.claude/pm-rules/ticket-body-schema.md） -->
AC4（domainMatrixProvider 的 null 退路，grep 全量 3 處）：全部可達，保留並於註解寫明業務狀態。
- _MatrixBody.build（matrix?.rows／matrix?.columns）：可達。LastCompletedRoundNotifier（lib/app/scan_round.dart）在工作區切換時將 state 設為 null，而 domainViewStateProvider 由 DomainViewLoader 另行寫入，兩者非同步切換；重掃結果無節點時 event.nodes.isEmpty 亦為 null。
- _jumpFocus（matrix?.rows）：可達，同上。
- _SwimlaneBody.build（傳入 _ucTitleOf／_highlightName）：可達，該處本就明確處理 lastCompletedRoundProvider == null 的投影準備中分支。
找不到「DomainReady 下 provider 必有值」的上游保證，依附加條件視為可達。
三欄位：全部保留並註明消費者。DomainLaneNode.stepId 供 domain_view_projection_test 辨識節點；DomainLaneEdge.fromLane／toLane 由 domain_view_projection_test 斷言 SPEC-001 §1 邊端點規則（lib 內無讀取者，SwimlaneEdge 尚無列欄位）。刪除會移除端點規則唯一的測試覆蓋。
