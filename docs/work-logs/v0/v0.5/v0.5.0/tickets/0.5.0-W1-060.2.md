## Solution
<!-- Schema[IMP/Solution]: 選填（.claude/pm-rules/ticket-body-schema.md） -->
ticket migrate 單票與子樹兩條 dry-run 路徑遇撞號改為 rc=0，輸出 `[WARNING]` 改號預覽與 `[MIGRATE-MAP] <原目標> -> <預覽目標>`；正式執行改號時同樣輸出 MIGRATE-MAP。批次內以 reserved 保留集合避免兩票預覽同一目標，並新增 `--reserve-id`（可重複）供跨程序帶入。version-release finish 每票一個 subprocess：`migrate_overflow_tickets` 把前面各票的實際目標以 `--reserve-id` 傳給後一票，撞號預覽不再中止 dry-run，新增 `mapping_out` 與 `print_overflow_mapping` 在結尾列出「來源 ID: 原目標 -> 實際目標」。`--force-overwrite` 的 dry-run 語意不變。ticket 2.44.41、version-release 2.10.5。commit 48d0cf865，合併 3fdde9056。

- RED：ticket 新增 3 案修改前全紅；version-release 3 failed、1 passed。
- 既有測試依新語意更新 3 處（dry-run 撞號 rc 1→0），逐一列於執行者回報。
- E1：同批 fixture 撞號與不撞號 dry-run 皆 rc=0，撞號輸出含改號預覽、不撞號無標記，兩者不同且 dry-run 不寫檔。E2：兩票目標皆為同一已佔用 ID，批次預覽目標彼此不同，且與同批正式執行落地 ID 逐一一致。
