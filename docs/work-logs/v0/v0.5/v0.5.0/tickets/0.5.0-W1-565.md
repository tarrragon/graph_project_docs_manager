## Solution
<!-- Schema[IMP/Solution]: 選填（.claude/pm-rules/ticket-body-schema.md） -->
修正 commit d4884fab1，只改 `.claude/hooks/coordination-queue-line-check-hook.py` 與它的測試檔。

- 檢查 3：Solution 內以 `**L<n> 現行佇列**` 開頭、卻不符 LANE_LINE 的行，若位在該線最後一筆合格行之後，就報出原文與格式 `**L<n> 現行佇列**（<session 名稱>）：<票序，或（無）>`。之後已補上合格行的歷史錯誤行不報，否則舊的錯誤會永遠留在提示裡。
- 檢查 2 的「請寫（無）」提示附上同一個格式範例。
- 解析層（parse_lanes）不變，仍與 line-board 的 lanes.ts 一致，共用案例的漂移守衛照常通過。

### 自檢結果

- AC1（不符格式的行會報出並附範例）：test_check3_missing_colon_after_last_valid_prompts、test_main_malformed_line_emits 通過。
- AC2（「請寫（無）」附完整格式）：test_check2_all_terminal_without_none_prompts 斷言格式字串。
- AC3（E2 缺冒號必紅）：停用檢查 3 時兩項翻紅，見 Test Results。

### Phase 4 評估

- 重構需要：否。技術債務：無。程式碼品質：A。
- 結論：新增一個函式 find_malformed_lines（只讀 Solution 行、單一迴圈），格式字串集中成常數 LANE_FORMAT，由檢查 2、3 共用，沒有重複。

### 框架 issue

依框架修補節奏，此修正在本地 `.claude/` 落地（本專案為主控方），上推 canonical 屬 sync-push，不在授權內，將隨下次 sync-push 一併送出。查重關係：引用 #54。

### 防護驗證證據

- 失敗語意：fail-open；觸發條件：hook 內部拋例外（run_hook_safely 攔截並寫 log 後 exit 0），或 multi-session.json 缺席、協調票檔讀不到。本 hook 只提示、不阻擋，失敗時不輸出提示。
