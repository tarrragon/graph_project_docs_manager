## Problem Analysis
<!-- Schema[IMP/Problem Analysis]: 選填（小型 IMP 可留 placeholder；大型 IMP 建議填寫）（.claude/pm-rules/ticket-body-schema.md） -->
### Incident 分析（PM，派發 session 裁決免派 incident-responder，2026-10-15）

- **失敗**：`.claude/hooks/tests/test_hook_dispatcher_failure_event.py::TestMetadataAndFallback::test_header_event_type_lists_failure_event`
- **直接原因**：測試以 `[ln for ln in text.splitlines() if '"event_type"' in ln][0]` 取得 hook-dispatcher.py 檔頭的 event_type 行；299 刪除 HOOK_METADATA 區塊後，檔內沒有任何含 `"event_type"` 的行，[0] 取值失敗。
- **範圍驗證**：299 合併 commit 的快照全套件為 1 failed、6733 passed，只有這一筆。
- **分類**：設計問題，不是實作 bug。這支測試讀的是沒有其他讀取者的中繼資料，屬「測中繼資料而非測行為」；299 移除中繼資料後，測試失去讀取對象。
- **299 為何漏掉**：盤點讀取者時只 grep 區塊名 HOOK_METADATA，沒有 grep 區塊內的欄位名（event_type、matcher、dependencies），而這支測試正是以欄位名讀取。

### Context Bundle（給實作代理人）

- 權威來源：`.claude/settings.json` 的 hooks.PostToolUseFailure（約第 517 行起），其 command 為 `uv run --quiet $CLAUDE_PROJECT_DIR/.claude/hooks/hook-dispatcher.py --group PostToolUseFailure:Bash`。PreToolUse 與 PostToolUse 也各自註冊分派器的群組。
- 原測試的兩個意圖都要保留：(1) 失敗事件確實接到分派器；(2) 既有事件（PreToolUse、PostToolUse）沒有被擠掉。
- E2 的建議做法：把「從 settings 物件找出註冊分派器的事件集合」抽成測試內的小函式，對讀進來的 settings dict 做斷言；E2 對照則傳入一份刪掉 PostToolUseFailure 的 copy，斷言結果不同。這樣不必暫改 settings.json，可避免 293 遇到的 auto mode 拒絕，也不會在共用檔留下暫時狀態。
- 同一檔的其他測試（TestMetadataAndFallback 其餘兩案、registry 相關）不動。
- 入口：`uv run --directory .claude/hooks pytest tests/test_hook_dispatcher_failure_event.py`

## Solution
<!-- Schema[IMP/Solution]: 選填（.claude/pm-rules/ticket-body-schema.md） -->
改寫 test_header_event_type_lists_failure_event 為 test_settings_registers_failure_event_and_keeps_existing_events：以 _dispatcher_events(hooks) 從 settings.json 找出 command 含 hook-dispatcher.py 的事件集合，斷言含 PostToolUseFailure 且 PreToolUse、PostToolUse 為其子集。新增 test_dispatcher_events_detects_missing_failure_registration 作 E2 對照（傳入刪掉 PostToolUseFailure 的 dict 複本）。僅改測試檔，未動 hook-dispatcher.py 與 settings.json。
