## Solution
<!-- Schema[IMP/Solution]: 選填（.claude/pm-rules/ticket-body-schema.md） -->
新增 .claude/lib/bash_tool_response.py 的 is_bash_success(tool_response, success_markers, ignore_case)：exit_code 存在時沿用（0 或 75 為成功），缺席時以 interrupted 非 true 且 stdout 含成功標記判定；非 dict 回 False。handoff-cleanup-hook 與 parallel-dispatch-verification-hook 改用，其餘行為不動。新增 test_handoff_cleanup_real_payload.py，並於 test_parallel_dispatch_verification_hook.py 增 TestRealPayloadShape，fixture 為五鍵真實形狀。

### 自檢結果
- 覆蓋表六條路徑皆有測試（真實成功／失敗／interrupted／exit_code 0、75／非零／非 dict）。
- fail-open：非 dict 與失敗情形兩 hook 皆 exit 0，有測試。
- Python 3.9 相容，無新語法。

### Phase 4
重構需要：否。技術債務：無（其餘三支 hook 改接 helper 由 0.5.0-W1-279.2 承接）。程式碼品質：A。結論：無需重構。

### PM 收尾（裁決 B，主 checkout）

- 審查：helper 只負責成功判定，兩支 hook 其餘行為不變。已知推斷風險（成功標記改寫或 stdout 中出現相同字樣即誤判；handoff 的 "completed" 以忽略大小寫比對）由 0.5.0-W1-279.2 查證平台失敗事件後處理，並於 docstring 記錄。
