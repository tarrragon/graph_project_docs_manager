### 發現者補充（L18，2026-10-27）

以下三點只出現在 L18 session 中，分析根因時需要納入：

1. **指引的來源有一部分是 PM 手動複製**：`ticket track dispatch 0.5.0-W1-486 --as saffron-system-analyst --isolation none` 產出的骨架**沒有**「先 Write 內容檔、不用 heredoc」這一行。後來改用 worktree 派發，PM 從 479.1 的 `--isolation worktree` 骨架手動複製了該行。所以觸發條件是「`--isolation worktree` 骨架 × 沒有 Write 的代理人」。分析時要分兩層判斷：骨架是否依 isolation 加入該行（是），以及是否依工具清單切換（否）。
2. **改用 worktree 是被守衛逼的**：同一 session 中，agent-dispatch-validation-hook 曾以「目標含非 .claude/ 路徑」擋下非隔離派發（0.5.0-W1-492），PM 因此預設改用 worktree，連帶帶入了上述那一行。486 的 where.files 含 `lib/`，即使沒有 492，依判準表也應走 worktree。
3. **PM 也寫不了 scratchpad**：PM 為 492 寫內容檔時，主線程寫入守衛以「主線程禁止編輯此路徑」擋下 `/private/tmp/.../scratchpad/` 下的 Write。PM 最後在主 repo 用 heredoc 傳 append-log 才寫成（主 repo 不受 worktree 的換行限制）。這代表「--content-file 搭配 scratchpad」對 PM 也走不通。
