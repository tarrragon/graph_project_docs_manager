## Solution
<!-- Schema[IMP/Solution]: 選填（.claude/pm-rules/ticket-body-schema.md） -->
改法：lib/git_command_parse.py 新增 match_git_commit(command, exclude_amend=True, base_dir=None)，回傳 True（命中）、False（未命中）、None（無法解析），docstring 寫明參數與三態。四支 hook（uncommitted-ticket-md-reminder、homoglyph-guard、post-commit-fetch、commit-msg-layer2-marker-check）的判定函式改為 match_git_commit(...) is True，移除各自的 contains_git_word、find_git_invocations、amend 篩選；post-commit-fetch 維持原行為，傳 exclude_amend=False。uncommitted-ticket-md-reminder 的 ImportError 降級 stub 同步改為 match_git_commit。None 在四支皆視為未命中（fail-open，只是少一則提示）。未改 tracking-schema-json-staleness-guard 與 find_git_invocations 回傳形狀。
實地觸發：scratchpad 暫存 repo（已 git init 並 stage 一檔），以 settings.json 註冊的啟動方式 uv run --quiet hook-dispatcher.py --group PreToolUse:Bash，CLAUDE_PROJECT_DIR 指向暫存 repo，餵 payload 給 homoglyph-guard。git -C x commit 的 payload：暫存 repo 的 .claude/hook-logs/homoglyph-guard-hook 日誌出現 INFO homoglyph 檢查通過（進入 diff 掃描，判定為 commit）；echo git commit 的 payload：日誌為 DEBUG 非 git commit 命令，跳過。兩者 rc=0。liveness 驗證方式：逐行比對該日誌兩次 payload 的差異。失敗語意：無法解析（None）四支皆視為未命中，fail-open。
Phase 4：重構需要 否；技術債務 無；程式碼品質 A；結論：無需重構。
