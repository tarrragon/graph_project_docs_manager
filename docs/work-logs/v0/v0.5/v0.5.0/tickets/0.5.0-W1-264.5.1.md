### 回歸修正（gate-action-mismatch）
- 成因：過濾基準誤用 hook 的 project_root（cwd 所屬 checkout），commit 實際作用目錄由 -C／cd 決定。
- 修法：bare-commit-guard 新增 _commit_target_checkout，取 invocations[0].effective_dir（即 _resolve_detect_dirs 所用的同一解析結果，含 -C／cd）的 git rev-parse --show-toplevel 為基準；dir_unknown、無解析、目錄不存在、非 git repo 一律不過濾（全計入）；其他 rev-parse 失敗 fail-open 並 stderr+log 雙寫。
- has_parallel_dispatch 的兩個呼叫端（domain-import-lint、tracking-schema-json-staleness-guard）只在「命令無法解析」分支呼叫，此時作用目標本就未知，用 cwd 推定會重現同一回歸。處置：has_parallel_dispatch 新增 checkout 參數，預設 None=不過濾；兩呼叫端不改，維持全計入。

### work_checkout 與實際寫入 checkout 不一致的評估（誤濾 = 放行方向）
| 情況 | 是否可能誤濾 | 處置 |
| (a) 非隔離代理人用 cd／git -C 寫另一個 checkout | 是：條目登記派發者 checkout，代理人實際寫別處；對該別處的 commit 判定，條目被濾掉而放行 | 判定端只能以 commit 目標為基準（已修），無法得知代理人其他寫入。已知殘留，失敗方向：放行。登記端無從預知代理人日後 cd 到哪 |
| (b) 隔離派發 runtime 未回報 tool_response.worktreePath | 否：留空=位置不明，所有 checkout 皆計入（多擋）。worktreePath 欄位是否存在仍未實測；若 runtime 回報了與實際不同的路徑則屬 (c)/誤報，不可知 | 已知殘留，失敗方向：多擋。隔離代理人於未回報時失去過濾收益 |
| (c) 路徑別名（/tmp 與 /private/tmp、symlink、大小寫） | 已處理：_same_path 改 os.path.samefile（inode 比對）；任一路徑不存在或無法比對視為相同（計入） | 單元測試涵蓋 symlink；大小寫別名依 samefile 語意於大小寫不敏感檔案系統成立，未另行實測 |
另一殘留：非隔離派發於 PM 切換 cwd 之前登記，之後 PM 在別的 checkout 工作，條目仍指原 checkout，對該原 checkout 的判定正確、對新 checkout 不計入，失敗方向：放行，登記端無解。
