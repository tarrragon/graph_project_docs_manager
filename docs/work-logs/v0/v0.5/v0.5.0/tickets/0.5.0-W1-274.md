### Context Bundle（PM 於派發前整理，2026-10-14）

前置：189.1、264.1 皆已完成並在 main。

**兩種根與兩個快取（.claude/lib/hook_base.py）**

| 函式 | 語意 | 快取 | 快取鍵 |
|------|------|------|--------|
| get_project_root -> _find_project_root | linked worktree 內回 worktree 根 | _PROJECT_ROOT_CACHE | (cwd, CLAUDE_PROJECT_DIR, HOOK_TEST_ISOLATION) |
| get_shared_state_root(default_root) -> _main_repo_root_of_linked_worktree | linked worktree 內回主倉庫根（git-common-dir 父目錄），其餘回 default_root 或 get_project_root | _MAIN_REPO_ROOT_CACHE | 只有 cwd |

- 兩快取各自獨立；clear_project_root_cache 同時清兩者。
- get_shared_state_root 在 HOOK_TEST_ISOLATION=1 時直接回 fallback，不碰快取。conftest 的 hook_project_env fixture 會設此旗標，本票測試必須 delenv，否則共用根那一側等於沒測。

**分派程序（.claude/hooks/hook-dispatcher.py）**

- main 只 import 一次 lib；各 hook 以 runpy.run_path 同程序執行，共用同一個 lib.hook_base 模組物件，所以兩個快取跨 hook 共用。
- 每支 hook 執行後 _restore 還原 argv / sys.path / environ / cwd，但不清快取。
- 測試入口：disp.dispatch([hook_paths], payload, cwd, timeout)、disp.run_group(group, payload, registry_path=...)。

**Bash 群組內兩類 hook（registry：.claude/hooks/hook-dispatch-registry.json）**

- 共用狀態類（PreToolUse:Bash）：acceptance-gate-hook（get_shared_state_root(get_project_root())）、domain-import-lint-hook 與 tracking-schema-json-staleness-guard-hook（has_parallel_dispatch(get_project_root())）
- worktree 路徑類：直接用 get_project_root 的 hook，例如 tracking-schema-json-staleness-guard 的 project_root

**既有測試的缺口（.claude/hooks/tests/test_hook_dispatcher.py TestProjectRootInLinkedWorktree）**

- test_worktree_root_is_read_when_cwd_is_linked_worktree 只在目前 checkout 本身是 linked worktree 時才跑，主 checkout 一律 skip；也沒有涵蓋 get_shared_state_root。
- 本票改用 tmp_path 內自建的 repo 與 git worktree add 產生的 linked worktree，讓測試在任何 checkout 都會執行。

**建議測法**

1. tmp_path 建主 repo（git init、一個 commit），再 git worktree add 建 linked worktree，cwd 設為 worktree。
2. 兩支探針 hook：一支印 get_project_root()，一支印 get_shared_state_root()；以 disp.dispatch 依 A→B 與 B→A 兩種順序執行，斷言分別等於 worktree 根與主 repo 根（比較前 resolve，macOS /private/var 與 /var 會不同）。
3. E1 對照：同一組探針各自以子程序單獨執行，讀到的根與同程序結果相同。
4. E2 正向對照：加一個斷言證明測試有鑑別力，例如確認 worktree 根與主 repo 根確實不同。
5. 若有餘力，用真的 acceptance-gate 或 has_parallel_dispatch 觀察共用根（例如只在主 repo 放 dispatch-active.json）；做不到就在 Solution 寫明理由。

**預期結論**：依程式碼閱讀不應有汙染，這張票主要是加回歸測試鎖住行為。若測出汙染，停手在 NeedsContext 回報，不要自行修改 hook_base.py。
