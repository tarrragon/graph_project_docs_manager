## Solution
<!-- Schema[IMP/Solution]: 選填（.claude/pm-rules/ticket-body-schema.md） -->
選定做法 (a)：移除第二層。理由：(1) Agent 事件已由第零層（prompt 首行 Ticket:）涵蓋；(2) 全域最新 dispatched_at 在並行派發或派發已結束時會取到別張票，語意不正確，修形狀也無法修語意；(3) 保留須額外限定恰一筆進行中，仍無法歸屬 UserPromptSubmit 事件。層 3 git branch 與判定失敗回 None（fail-open）不變。
修改：wrap-decision-tripwire-hook.py derive_ticket 刪除層 2；測試檔新增 f10（實檔形狀 {dispatches:[兩筆]} 不取票號，回 None）與 f11（同 fixture 下 Agent prompt 首行仍取對應票號）。盤點：測試檔中 dispatch-active 依賴僅 f8（損毀）、f9（缺檔），行為仍成立無需改。
實地觸發方式（PM 合併後補）：在主 checkout 派發一個 prompt 首行含 Ticket: <id> 的 Agent，確認 hook-logs/wrap-decision-tripwire 的 state current_ticket 為該票號；並行派發兩個 Agent 各自首行票號，確認各取各票。
