## Problem Analysis
<!-- Schema[ANA/Problem Analysis]: 必填（.claude/pm-rules/ticket-body-schema.md） -->
### 問題根因

合併閘門的套件對應寫死在 `merge_gate.py` 的三個常數：`FLUTTER_SCOPE_PREFIXES`／`FLUTTER_SCOPE_FILES`（範圍）、`SUITE_COMMANDS`（命令）、`REQUIRED_ARTIFACTS`（快照內須先生成的產物）。三者都是 Flutter 目錄慣例；框架檔內不能寫專案路徑（reference-stability 規則 8），所以專案自帶的套件（tools/line-board）接不上，非 Flutter 的 consumer 則套到錯的預設。

### 影響範圍

- 已驗證：`.claude/` 對應（hooks／scripts／skill:<名稱>）屬於框架自身，不需要專案宣告；需要宣告的只有「專案路徑 → 專案套件」這一段。
- 已驗證：`REQUIRED_ARTIFACTS` 已有「快照內缺 gitignored 產物時先生成」的機制，宣告格式可直接沿用，作為「必要產物」欄。
- 0.5.0-W1-110.2（內嵌副本守衛）同樣需要專案側宣告，因為副本路徑不可寫死於框架。

### 相關 Error Pattern

reference-stability 規則 8（框架禁止引用專案識別符）；PC-GPD-037（判斷閘門行為前先讀判定碼）。

## 重現實驗結果
### 實驗方法

1. 讀 `merge_gate.py` 的 `select_suites`、`suite_command`、`_ensure_artifacts` 與相關常數（PC-GPD-037）。
2. 盤點框架既有的專案側載體：`.claude/config/`、各 skill 的 `references/project-integration/`、`.claude/lib/sync_exclude_manifest.py` 的排除分類。
3. 以 `python3 -I` 直接呼叫 `sync_exclude_manifest.should_exclude`，逐一確認候選路徑是否會被 sync 推送或覆蓋。
4. 以 `gh api repos/tarrragon/claude/contents/...` 查 canonical 是否已收有本專案的專屬設定檔。
5. 確認 merge_gate 的執行環境可以解析 YAML（worktree skill 的 pyproject 依賴）。

2. `.claude/project-integration/`（根層）不需修改 sync manifest，就已被雙向排除；它也不屬於任何單一 skill，可供多個消費者共用。
3. merge_gate 可以直接讀取 YAML。

- `claude plugin test` 在沒有 `.claude-plugin/types/` 的快照內是否能執行，交由 410.4 實測（見 410.4 AC 1）。

## Solution
<!-- Schema[ANA/Solution]: 必填（.claude/pm-rules/ticket-body-schema.md） -->
### 結論

宣告載體定為 `.claude/project-integration/merge-gate.yaml`。宣告存在時，以宣告的 suites **取代**內建的 Flutter 對應；不存在時沿用內建預設；格式錯誤時閘門判紅（fail-closed）。`.claude/` 的對應屬於框架自身，固定保留、不可宣告。

### 載體候選比較

| 案 | 位置 | 利 | 弊 |
|---|---|---|---|
| A | `.claude/config/merge-gate.yaml`，另登記 sync 排除 | 與其他設定檔放在一起 | 排除要逐檔登記，漏登記就外洩；`dart-style-guardian.json` 已示範這個失敗形態 |
| **B（採用）** | `.claude/project-integration/merge-gate.yaml`（根層） | 已被既有 `PER_PROJECT_PATTERNS` 雙向排除，不需改 manifest；目錄名就說明這是專案層；不屬單一 skill，110.2 可共用；之後新增的專案宣告放進來，自動受到排除 | 根層 `project-integration/` 是新用法；`sync-exclusion-guide.md` 的範例只寫到 skill 層，需補一句 |
| C | repo 根目錄的獨立檔（`.claude/` 之外） | 永遠不會被同步 | 框架要讀 `.claude/` 外的固定檔名，增加 repo 根目錄的雜訊；不在框架的可發現範圍內 |
| D | `skills/worktree/references/project-integration/` | 已被排除 | `references/` 是文件層，放機讀設定會混淆語意；只屬 worktree skill，110.2 的守衛要跨 skill 讀 |
| E | CLAUDE.md 區段 | 人讀方便 | 沒有 schema，解析脆弱，否決 |

### 宣告格式

```yaml
# 合併閘門套件宣告（專案層，不隨 sync 同步）
suites:
  <套件名>:                     # 不可為 hooks、scripts 或 skill: 開頭（框架保留）
    prefixes: [<路徑前綴>, ...]  # 與 files 至少一項
    files: [<精確檔名>, ...]
    command: [<argv>, ...]      # 相對快照根目錄執行
    artifacts:                  # 選填；沿用 REQUIRED_ARTIFACTS 語意
      - path: <gitignored 產物路徑>
        generate: [<argv>, ...]
```

- 宣告從合併快照讀取，與 `select_suites(root=快照)` 一致；分支自身新增或修改的宣告，對該分支即時生效。
- 取代而非疊加：這樣非 Flutter 的 consumer 一宣告，就不會再套到 Flutter 預設。本專案的宣告因此必須同時寫出 flutter 與 line-board 兩個套件；flutter 一項要等價於現行內建常數（由 410.3.1 的 AC 2 以測試鎖定）。
- 缺宣告時沿用內建 Flutter 預設，並印一行 INFO，讓既有 consumer 零變更。
- 格式錯誤（缺 command、prefixes 與 files 皆空、使用保留名）時判紅並指名檔案與欄位。理由：靜默忽略會退回 410 所記的「無聲免跑」。
- 410.2 的未對應路徑警告，把宣告前綴視為已對應。

### line-board 的型別檢查

閘門不跑型別檢查。`.claude-plugin/types/` 要先以 `--plugin-dir` 啟動一次才會產生，目前沒有已知的無頭生成命令，所以無法填入 `artifacts`。型別錯誤仍由代理人與審查者以 416 的做法檢查。line-board 宣告只放 `claude plugin test`；它在沒有 types 的快照內能否執行，由 410.4 實測。

### 與 0.5.0-W1-110.2 的關係

**共用載體目錄，分開檔案。** 兩者都放在 `.claude/project-integration/`；merge-gate.yaml 由 worktree 閘門讀，內嵌副本宣告另立一檔，由 110.2 的守衛讀。分檔的理由是消費者、schema 與失敗語意各自不同，110.2 還有阻擋時機（commit 或合併）尚未定案；合成一檔會讓兩個守衛為了不同理由修改同一份 schema。附帶提供 110.2 一個候選：在合併時點，「匯出源路徑 → 消費端契約測試命令」可以直接寫成本格式的一個 suite。採用與否由 110.2 判定，本票不代為決定。
