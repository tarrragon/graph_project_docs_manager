# Execution Log

## Task Summary

分析 worktree 建置累積 Xcode DerivedData 使磁碟耗盡（每個 worktree 一份 Runner-*，移除 worktree 不清）

---

## Problem Analysis
### 問題根因

Xcode 以 workspace 絕對路徑為鍵，在 `~/Library/Developer/Xcode/DerivedData` 為每個路徑建立一個 `Runner-*`。worktree skill 移除 worktree 與合併閘門快照時，只處理目錄與分支，不處理這些以路徑為鍵的外部快取。flutter_tools 3.47.1 原始碼查證：macOS 建置傳 `-derivedDataPath <worktree>/build/macos`，產物留在 worktree 內；`-showBuildSettings`（`lib/src/ios/xcodeproj.dart`）不帶該參數，仍為每個路徑建約 200KB 的 PIFCache／Logs 殘留。iOS 建置（`lib/src/ios/`）完全不帶 `-derivedDataPath`，每個 worktree 留下約 400MB。

### 影響範圍

已驗證：本專案（macOS）的殘留件數持續累積，但每份很小；大份殘留來自 iOS consumer。未驗證：2026-10-09 那次 15G 的組成（已刪除，無法回溯）。

### 相關 Error Pattern

無直接對應。框架查重落點 tarrragon/claude#120（worktree cleanup 的移除步驟），關係判定為同一 skill、同一步驟的不同缺陷，issue 尚無區段，以 observe 附加。


## 重現實驗結果
### 實驗方法

唯讀量測，不刪任何資料夾。逐一讀取每個 `Runner-*` 的 `Build/Intermediates.noindex/XCBuildData/PIFCache` 內含的 workspace 路徑；沒有 PIFCache 時讀 `info.plist` 的 WorkspacePath。再檢查該路徑是否仍存在，並記錄 `du -sk` 與修改時間。

### 實驗執行

2026-10-30，本機 macOS 單次量測：DerivedData 合計 1.8G，共 88 個資料夾，其中 83 個是 `Runner-*`（40 個超過 3 天）；磁碟可用 62Gi。

| 來源 | 份數 | 合計 | 路徑仍存在 |
|------|-----|------|----------|
| 本專案 `.claude/worktrees/merge-gate-*` | 49 | 9.8MB | 否 |
| 本專案 `.claude/worktrees/agent-*` | 25 | 6.6MB | 否 |
| 本專案主 checkout | 1 | 0.2MB | 是 |
| flutter_balance `.claude/worktrees/agent-*`（iOS） | 5 | 830.9MB | 否 |
| flutter_balance 主 checkout（iOS） | 3 | 428.4MB | 是 |

本專案份數的時間分布：merge-gate 份數集中在最近 3 天（36 份），約每天 8 份。

### 實驗發現

已驗證：原推測「每個 worktree 路徑一份 Runner-*，移除後不清」成立；合併閘門快照路徑每次不同，因此每跑一次閘門就新增一份。已驗證：本專案單份約 200KB，磁碟壓力主要來自 iOS 建置。未驗證：10-09 那次 15G 的來源組成。


## Solution
### 結論

判定為框架問題，兩條 AND 判準逐條套過：

1. 抽象可攜：成立。凡以 worktree 隔離派發、且建置 Xcode 專案的 consumer 都命中，因為 Xcode 以 workspace 絕對路徑為快取鍵。
2. 根源在 `.claude/` 通用資產：成立。worktree 與合併閘門快照由 worktree skill 建立與移除，移除步驟不處理外部快取。

依修補節奏，本題為 P2，不派修，走路徑 A：觀測已附加至 tarrragon/claude#120（issuecomment-6522796781），本地票關閉，issue 為唯一權威。
