## Problem Analysis
<!-- Schema[ANA/Problem Analysis]: 必填（.claude/pm-rules/ticket-body-schema.md） -->
### 真實 Bash PostToolUse payload 的 tool_response 鍵集合（現成證據）

`.claude/hook-logs/pre-fix-evaluation-*.json`（pre-fix-evaluation hook 於 Bash PostToolUse 寫入，記錄 `tool_response_keys`）共 25 份，鍵集合一致：

```
"tool_response_keys": ["stdout", "stderr", "interrupted", "isImage", "noOutputExpected"]
```

25 份中含 `exit_code` 鍵者 0 份（`grep -l '"exit_code"'` 計數）。平台提供的成功相關訊號只有 `stdout`、`stderr`、`interrupted`（布林）；沒有退出碼。實地探針（acceptance 1）仍需另做一次，以本證據為前置。

### 測試 fixture 與真實 payload 形狀不一致（bb 指示記錄）

handoff-cleanup 的單元測試 fixture 自帶 `exit_code: 0`，真實 payload 沒有此鍵，所以測試全綠、實機成功分支從未執行。這與 0.5.0-W1-242（tool_response 整包字串化）同屬「測試 fixture 與真實 payload 形狀不一致」：測試依作者想像的形狀建構輸入，與平台實際送出的形狀脫節，斷言再精確也只驗到想像中的路徑。落地項須含「fixture 改用真實 payload 樣本」。

### 排程（bb，2026-10-14）

F 線，排在 0.5.0-W1-270.8 之後、270.3 之前（已發生的功能失效優先於文件收尾句）。
