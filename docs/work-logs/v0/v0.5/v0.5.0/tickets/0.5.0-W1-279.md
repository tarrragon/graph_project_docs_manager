## Problem Analysis
<!-- Schema[ANA/Problem Analysis]: 必填（.claude/pm-rules/ticket-body-schema.md） -->
### 真實 Bash PostToolUse payload 的 tool_response 鍵集合（現成證據）

`.claude/hook-logs/pre-fix-evaluation-*.json`（pre-fix-evaluation hook 於 Bash PostToolUse 寫入，記錄 `tool_response_keys`）共 25 份，鍵集合一致：

```
"tool_response_keys": ["stdout", "stderr", "interrupted", "isImage", "noOutputExpected"]
```

25 份中含 `exit_code` 鍵者 0 份（`grep -l '"exit_code"'` 計數）。平台提供的成功相關訊號只有 `stdout`、`stderr`、`interrupted`（布林）；沒有退出碼。實地探針（acceptance 1）仍需另做一次，以本證據為前置。

### 測試 fixture 與真實 payload 形狀不一致（bb 指示記錄）

handoff-cleanup 的單元測試 fixture 自帶 `exit_code: 0`，真實 payload 沒有此鍵，所以測試全綠、實機成功分支從未執行。這與 0.5.0-W1-242（tool_response 整包字串化）同屬「測試 fixture 與真實 payload 形狀不一致」：測試依作者想像的形狀建構輸入，與平台實際送出的形狀脫節，斷言再精確也只驗到想像中的路徑。落地項須含「fixture 改用真實 payload 樣本」。

## Solution
<!-- Schema[ANA/Solution]: 必填（.claude/pm-rules/ticket-body-schema.md） -->
### 分析結論

平台 Bash PostToolUse 的 tool_response 只有 stdout、stderr、interrupted、isImage、noOutputExpected 五個鍵（pre-fix-evaluation hook 記錄的真實 payload，25 份一致，最近一份 2026-10-14 15:48）。沒有退出碼。以 `get("exit_code", -1)` 判定成功的兩支 hook（handoff-cleanup、parallel-dispatch-verification）因此恆走失敗分支，自 2026-10-07 起主體邏輯從未執行。單元測試 fixture 自帶 `exit_code: 0`，與真實形狀不符，所以測試全綠。

另做一次新探針需改 settings.json 註冊探針 hook；settings.json 目前有他線未提交修改，且現成證據已是 hook 實機記錄的真實 payload，故以現成證據為準，不另改 settings。

### 候選比較

| 候選 | 做法 | 優點 | 缺點 |
|------|------|------|------|
| A 各 hook 就地改判定 | 2 支死路徑 hook 各自改為 stdout 成功標記 + `interrupted` 為 false | 改動最小 | 4 支讀 exit_code 的 hook 各寫一套，判定再次分歧；下一支新 hook 仍會照抄 exit_code 寫法 |
| B 共用成功判定 helper | `.claude/lib/` 新增判定函式：有 exit_code 時沿用，缺席時以 `interrupted` 與命令自身的成功回音判定；各 hook 傳入自己的成功標記 | 一處定義，容忍缺席（needs-context-listener 已驗證的做法）；未來平台若補上 exit_code 自動生效 | 需逐支遷移 |
| C 改用平台的失敗事件 | 以 PostToolUseFailure 之類事件分流成功與失敗 | 不靠文字判定 | 平台是否提供、對 Bash 非零退出是否觸發皆未查證；無證據不採用 |

### 選定

採 B。死路徑兩支（handoff-cleanup、parallel-dispatch-verification）P1 先修；降級與死碼兩支（cli-error-feedback、parallel-claim-audit）與已正確的 needs-context-listener 改接 helper 列 P3。所有改動的測試 fixture 以真實 payload 形狀為準（五個鍵、無 exit_code），並保留一筆帶 exit_code 的相容案例。
