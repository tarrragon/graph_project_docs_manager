### Context Bundle（PM 讀碼，2026-10-19）

- 要改的位置：`.claude/hooks/bare-commit-guard-hook.py` 的 `main()`，`pending = _pending_operation_in_dirs(_resolve_detect_dirs_multi(...))` 之後 `if pending in _BLOCKING_OPS:` 分支的 `logger.warning("%s 進行中，裸 commit 會收尾他方操作，阻擋", pending)`。`pending == _OP_UNRESOLVABLE`（值 `unresolvable-override`，定義於 `.claude/lib/git_operation_state.py`）時改記「覆寫目標無法靜態解析，保守阻擋」
- 不需改的位置：同函式 `invocations is None` 分支的「命令無法安全解析且 %s 進行中」——該分支偵測目錄來自 `_resolve_detect_dirs`（不經覆寫解析），`_UNRESOLVABLE_OVERRIDE` 標記不會出現
- stderr 拒絕訊息（`_build_pending_operation_deny_message`）342 已依種類分流，本票不動
- 測試：斷言日誌文字（unresolvable 情境不含「進行中」「收尾他方操作」；merge 情境原文不變，E1 對照）

## Solution
<!-- Schema[IMP/Solution]: 選填（.claude/pm-rules/ticket-body-schema.md） -->
bare-commit-guard-hook.py main() 阻擋分支依 pending 種類分流：_OP_UNRESOLVABLE 記「覆寫目標無法靜態解析，保守阻擋」，其餘維持原「%s 進行中，裸 commit 會收尾他方操作，阻擋」；補 import _OP_UNRESOLVABLE。stderr 訊息與 exit code 不變。測試以 setup_hook_logging 替身（全級別 sink，沿用檔內 _Sink 慣例）斷言日誌行，因 hook 日誌走檔案且 main 內部建 logger，caplog 不適用。
