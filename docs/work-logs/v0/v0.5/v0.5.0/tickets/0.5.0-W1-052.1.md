## Solution
<!-- Schema[IMP/Solution]: 選填（.claude/pm-rules/ticket-body-schema.md） -->
`emit_hook_output` 的 print 包進 try/except Exception。決定不是 deny 時原樣 re-raise，allow 與無 decision 路徑行為不變。決定為 deny 時，把 reason 與例外寫到 stderr 後 `raise SystemExit(2)`。SystemExit 不會被 except Exception 與 run_hook_safely 攔截，因此在 hook 內層有 except-all 的守衛上也成立。stderr 寫入本身失敗時吞掉例外並附註解：已無通道可回報，但仍須維持 exit 2。commit 0664df873，合併 621f175de。

### 自檢結果

- E2：print 拋 OSError 時，deny 為 exit 2 且 stderr 含 reason；stderr 也失敗時仍為 exit 2。
- E1：同批 fixture 下，allow／無 decision 的 print 失敗仍 re-raise，與 deny 的結果不同。
- 本票只改 lib；直接 print 的守衛屬 0.5.0-W1-052.3 範圍，未動。Python 3.9 相容。規則 8 grep 0 命中。
- 實地觸發（本 session 實地觸發確認）：以 stdout 寫入必失敗的包裝器執行 mcp-write-tool-on-text-file-guard-hook，餵 deny 輸入。修正後 rc=2 且 stderr 含標記；修正前（befbed05a 的 clone）rc=1，即放行。allow 輸入在兩版皆為 rc=1，行為不變。
- 執行者全套件的 1 個 FAILED 經 incident-responder 歸因為既有 flaky（受測 hook 不經 emit_hook_output；worktree 與主 repo 各 6 次全綠），由 0.5.0-W1-068 追蹤。

### Phase 4 評估

- 重構需要：否。
- 技術債務：無新增。直接 print 的守衛遷移已有 0.5.0-W1-052.3。
- 程式碼品質：A。
- 結論：改動集中在單一輸出點，巢狀兩層，分支語意與既有 fail_closed 分工一致，不需重構。
