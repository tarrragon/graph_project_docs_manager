## Problem Analysis
<!-- Schema[IMP/Problem Analysis]: 選填（小型 IMP 可留 placeholder；大型 IMP 建議填寫）（.claude/pm-rules/ticket-body-schema.md） -->
### 追加實證（PM，2026-10-14）

建立 0.5.0-W1-238.1 時，建票的 auto-commit 回 rc=75（CAS 失敗）：票檔停在 untracked，topic-assignments.txt 多出一行未提交。照補救路徑執行 `ticket track commit 0.5.0-W1-238.1 -m ... <票檔> docs/work-logs/topic-assignments.txt`，被拒絕：「以下檔案不在 ticket where.files 宣告的寫入範圍內」。

由此可知，被 track commit 拒絕的不只有工作日誌，CLI 自己管理的 topic-assignments.txt 也一樣，同屬 CLI 寫入、卻不在 where.files 的檔。最後只好將票檔以 track commit 提交，topic-assignments 改用精確 add 加裸 commit。修法須把這類 CLI 管理的檔（版本工作日誌、topic-assignments）視為隱含可寫。

## Solution
<!-- Schema[IMP/Solution]: 選填（.claude/pm-rules/ticket-body-schema.md） -->
方案比較：(a) track commit 隱含可寫 CLI 管理檔；(b) 補救文案拆多條指令。採 (a)：(b) 無法涵蓋建票後 topic-assignments，且文案需隨檔案種類分支。實作：track_commit._cli_managed_paths 集中回傳 {票自身 md, 版本工作日誌, topic-assignments.txt}；範圍檢查改用該集合，worktree 票面守衛仍只針對票自身 md。他票票檔與一般 docs 檔仍被拒（E2 測試）。
Phase 4：重構需要 否；技術債務 無；品質 A；結論 無需重構。
### 自檢結果
改動限範圍判定相關函式，未動 -m 處理與訊息組裝；補救文案不變（不帶工作日誌時行為不變）。
