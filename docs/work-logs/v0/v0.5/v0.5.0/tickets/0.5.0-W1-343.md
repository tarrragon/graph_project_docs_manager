### 查證起點（PM，2026-10-19）

- 事發位置：worktree `.claude/worktrees/agent-a9308f2a47471af66`（分支 worktree-agent-a9308f2a47471af66，最終 commit fd04159e7，訊息為單行、無附註）。
- 時間窗：2026-10-19 約 12:05 至 12:08，該代理人重新派發後到 commit 之間。
- 先查 `.claude/hook-logs/` 下該時間窗內記有 deny 或 block 的 hook 日誌，再依 how.strategy 實測兩種 heredoc 寫法。

### 日誌查證結果（PM，2026-10-19 15:10）

- 主 checkout `.claude/hook-logs/` 在 12:05–12:08 窗內無任何 deny／block 行；Bash 類 PreToolUse hook（bash-edit-guard、bash-write-boundary-guard）的紀錄停在 12:06:18，之後到 commit fd04159e7（12:07:44）之間無紀錄
- 原因：`.claude/lib/hook_logging.py` 的 `setup_hook_logging` 未傳 `project_root` 時用 `get_project_root()`，在 worktree 內解析為 worktree 副本（該函式 docstring 已寫明此行為），日誌寫進 `.claude/worktrees/agent-a9308f2a47471af66/.claude/hook-logs/`；該 worktree 合併後已移除，事發日誌不可得
- 結論：擋下的 hook 只能靠重現確定，重現時在 worktree 內讀 `.claude/hook-logs/`（不是主 checkout）

### 重現要點（交實測者）

- 必須以 subagent 身分、在 isolation worktree 內執行（主 checkout 與主線程的 hook 判定路徑不同）
- 兩種寫法各試一次：`git commit -F - <<'EOF' ... EOF` 與 `git commit -m "$(cat <<'EOF' ... EOF)"`；訊息含 Co-Authored-By 與 Claude-Session 兩行附註
- 擋下時記錄：拒絕訊息全文、worktree 內 hook-logs 對應行、hook 名稱

## Solution
<!-- Schema[ANA/Solution]: 必填（.claude/pm-rules/ticket-body-schema.md） -->
判定：無法重現，不判誤擋；heredoc 本身不是觸發條件（兩種寫法皆放行，rc=0）。無 hook 判定位置可指。

候選方案：
1. 結案為無法重現，向 342 實作者索取原拒絕訊息全文再重開。利：零成本、不猜測；弊：缺資料時 342 的偏離原因仍未知。
2. 擴大重現：改用 342 實際的 staged 檔案範圍、較長訊息、有 ticket 範圍宣告的派發條件再試。利：涵蓋範圍型守衛（commit-stage-guard-gate）假說；弊：需還原 342 條件，需 PM 提供派發快照。
3. 於 hook 日誌補強：deny 行一律寫入主 checkout 日誌（或在 worktree 日誌路徑外加記），使日後事發可查。利：根治「worktree 日誌合併後消失」；弊：要改 .claude/lib/hook_logging.py，屬框架變更，需另案。
