### PM 覆核：heredoc 命令是否被認成 commit（2026-10-19 15:23）

重現時兩次 commit 在 worktree 與主 checkout 的 bare-commit-guard 日誌都找不到判定行，因此另外驗證「heredoc 讓守衛認不出 commit 而直接放行」這個可能。做法：主 checkout 以 stdin JSON 直接呼叫 `bare-commit-guard-hook.py`（不產生 commit），三種命令的日誌如下：

| 命令 | rc | 判定日誌 |
|------|----|---------|
| `git commit -m "x"`（對照） | 0 | 並行期裸 commit，staged 範圍落在單一派發宣告內，放行 |
| `git commit -F - <<'EOF' ... EOF` | 0 | 同上 |
| `git commit -m "$(cat <<'EOF' ... EOF)"` | 0 | 同上 |

結論：heredoc 形式的命令會被正確認成 commit，走正常判定，沒有繞過守衛。重現時找不到判定行的原因沒有查明；本票沒有擋下事件，不影響結論。實驗腳本已刪除，未入庫。
