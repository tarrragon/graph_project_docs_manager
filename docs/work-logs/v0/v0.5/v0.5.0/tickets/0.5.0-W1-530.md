## 重現實驗結果

### 實驗方法

parsley 於 worktree 暫存 `test/widget/probe_530_semantics_test.dart`（已刪，未入庫）。fixture 沿用 `test/unit/screens/domain_view_test.dart`「圖不可用」group（`fakeRound(graphUnavailable: projectVersionOutOfKnownRange)`、`FakeScanRound(initial:, latency: 5s)`、`DomainReady(matrix)`、`pumpHarness`）；兩態（非掃描中、點擊後 pump 兩次的掃描中）+ EmptyState 外無 `semanticExpanded` 的 `AppButton`（label="ctl"）對照。`ensureSemantics` + `debugDumpSemanticsTree` + 從按鈕節點逐層走 parent。`fvm flutter test <該檔>` rc=0。

規格偏差：此 Flutter 版本無 `SemanticsNode.mergeAllDescendantsIntoNode` getter，改印 `isMergedIntoParent`；`SemanticsFlags` 無 `isFocusable` getter，focusable 證據以傾印 `flags:` 行與 `focus` action 為準。

### 實驗執行

非掃描中，傾印原文：

```
└─SemanticsNode#3
  │ flags: scopesRoute
  └─SemanticsNode#4
    │ Rect.fromLTRB(0.0, 0.0, 960.0, 640.0)
    │ flags: isLiveRegion
    │ label: "此專案的型別表版本不在 App 已知範圍內（不高於
    │   0.0.1），最近一次掃描無法建立圖譜；型別表修正或重新產生之前，重新掃描仍會得到相同結果"
    │ textDirection: ltr
    └─SemanticsNode#5
        Rect.fromLTRB(24.0, 53.0, 96.4, 81.0)
        actions: focus, tap
        flags: isButton, hasEnabledState, isEnabled, isFocusable
        label: "重新掃描"
        textDirection: ltr
```

掃描中，傾印原文：

```
└─SemanticsNode#4
  │ Rect.fromLTRB(0.0, 0.0, 960.0, 640.0)
  │ flags: isLiveRegion
  │ label:
  │   "掃描中
  │   已掃描 0 項"
  │ textDirection: ltr
  └─SemanticsNode#5
      Rect.fromLTRB(24.0, 70.0, 96.4, 98.0)
      flags: isButton, hasEnabledState
      label: "重新掃描"
      textDirection: ltr
```

按鈕祖先鏈（兩態相同結構）：`id=5 isButton=true isLiveRegion=false isMergedIntoParent=false` → `id=4 isLiveRegion=true isMergedIntoParent=false` → id=3（scopesRoute）→ 2 → 1 → 0（皆無旗標）。

對照組傾印原文：

```
└─SemanticsNode#4
    Rect.fromLTRB(0.0, 0.0, 60.3, 28.0)
    actions: focus, tap
    flags: isButton, hasEnabledState, isEnabled, isFocusable
    label: "ctl"
```

對照組祖先鏈：`id=4 isButton=true isMergedIntoParent=false` → id=3（scopesRoute）→ 2 → 1 → 0。

### 實驗發現

**(a) 按鈕是否有自己的節點且帶 button 與 focusable — 成立，非缺陷。** 重新掃描鈕為獨立 SemanticsNode（#5，`isMergedIntoParent=false`），非掃描中帶 `isButton`、`isEnabled`、`isFocusable` 與 `focus`／`tap` action，label 等於 label 值，與 EmptyState 外對照組旗標一致，符合 SPEC-004 §4.4 朗讀標籤。掃描中缺 `isEnabled`／`isFocusable` 與 action 是停用態的正常語意（`hasEnabledState` 仍在）。503.2 的「同一節點」觀察為 `getSemantics` 取法假象：它回傳 finder 所在 render object 往上第一個擁有節點者，與節點樹結構無關（傾印中 #5 確實存在）。

**(b) 按鈕文字是否落在 liveRegion 節點子樹內、是否被重播 — 結構上落在子樹內；重播與否未驗證。** 已驗證事實：
- #5 是 #4（`isLiveRegion`）的子節點；按鈕 label 不在 #4 自身 label 內
- #4 的 Rect 為 960×640 全畫面，而非訊息文字的範圍：EmptyState 的 `Semantics(liveRegion: true)` 未設 `container`，liveRegion 旗標與訊息 label 上併到外層容器節點
- 掃描中 #4 的 label 含 explanation（`已掃描 N 項`），即計數文字也在 live region label 內；SPEC-004 4.21 定為「進入本狀態時訊息以 `liveRegion` 播報一次」，計數每次更新改變 #4 label 時可能重播整段

未驗證假設：macOS（目標平台）上 Flutter liveRegion 的實際播報行為——是否只在 #4 自身 label 變更時播報、是否連子節點一併朗讀、計數更新是否觸發重播——widget 測試無法觀測，需實機 VoiceOver 驗證。
