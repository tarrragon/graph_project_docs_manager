### Commit 規範

Recommended: commit via isolated index (files must be a subset of this
ticket's where.files; never touches the shared index):
  ticket track commit <ticket-id> -m "..." -- {exact files}
In a linked worktree (files changed under a worktree dir, not the main repo):
add `--worktree <abs-worktree-path>` to the command above.
Fallback (not recommended; only if `ticket track commit` fails or is
unavailable) — use precise staging + verified bare commit only (no pathspec):
  git add {exact files}
  git diff --cached --name-only   # confirm index contains ONLY {exact files}
  git commit -m "..."             # bare commit; no -- <paths> / --only / -o / -a
Forbidden: git add . / git add -A; git commit -- <paths> / --only / -o / -a
  (pathspec-style commit discards the index and rebuilds it from working-tree
   content for the given paths — it silently absorbs unstaged edits other
   sessions may have on the same path, not just already-staged ones)
Before fallback commit: git diff --cached --name-only to check staged scope; git restore --staged <path> for any non-owned file
If bare `git commit` fallback is DENYed by bare-commit-guard-hook (another
dispatch active), stop and escalate to PM; never switch to pathspec /
--only / -o / -a to get around it.
If a commit is later found to have swept in out-of-scope content (e.g. a
peer session's staged changes):
Forbidden recovery actions: git revert; git reset --soft; git commit
--amend; any "reverse apply"/reapply of the diff. None of these may be
used to undo or rewrite the commit.
The ONLY permitted actions are: stop, record the commit SHA and file
list in the ticket, report to PM.
Reason: swept-in content is diff-indistinguishable from a peer's
legitimate concurrent write in the same window, so any of the forbidden
actions above would also undo the peer's legitimate work.

## Solution
<!-- Schema[IMP/Solution]: 選填（.claude/pm-rules/ticket-body-schema.md） -->
接線 GateDetectionNotifier.detect() 至兩條進入路徑，並渲染 inferredVersion 徽章。

**修改檔案**：
- `lib/app/shell.dart`：`_AppShellState.initState()` 新增 `_restoreWorkspaceAndDetect()`（`unawaited`），呼叫 `WorkspaceRepository.restore()`；回傳 `WorkspaceReady` 時呼叫 `GateDetectionNotifier.detect(path)`。`restore()` 任何失敗皆降級為非 `WorkspaceReady`（既有契約），此時不呼叫 detect()，畫面維持預設狀態——實機驗證（協調者訊息）指出此路徑先前完全無呼叫者，本票補上。
- `lib/screens/project_switcher/project_switcher_overlay.dart`：`_handleChosenState` 改為 `Future<void>`，`WorkspaceReady` 分支先重置 `degradedSchemaProvider`／`degradedSchemaVersionsProvider`／`inferredVersionProvider` 三旗標，再 `await detect(path)`，最後才 `_dismiss`；`_chooseFolder` 對應改為 `await` 呼叫並在 `ChooseFolderNotRemembered` 分支的 SnackBar 前補 `context.mounted` 檢查。`_selectProject`（點擊最近專案卡片）同步重置 `inferredVersionProvider`，但**不**呼叫 detect()——`RecentProjectFixture`（`project_switcher_providers.dart`）是 fixture 資料，未帶真實工作資料夾路徑，本票範圍內無 path 可偵測；架構缺口記錄於下方，非本票新增。
- `lib/components/app_shell.dart`：`AppShell.build` 新增 `ref.watch(inferredVersionProvider)`，傳入 `_MainArea`；返回列左側在 `isDegraded` 為假時改渲染推定版本徽章（`hasInferredVersion` 為真時），兩徽章互斥（SPEC-001 v1.19〈推定版本〉註記）。
- `lib/l10n/app_zh.arb` / `app_en.arb`：新增 `inferredVersionBadgeLabel` key（SPEC-004 §4.0.6 1.45 新增，placeholder 名稱 `inferredVersion`），並執行 `fvm flutter gen-l10n` 重新產生 `app_localizations*.dart`。
- `test/unit/screens/project_switcher_test.dart`：新增 `_FakeSignalProbe` 與 `_gateDetectionOverrides`，套用於四個經 `WorkspaceReady` 分支的既有測試（避免 `detect()` 碰觸真實檔案系統造成 `pumpAndSettle` 無法確定性收斂，實測命中三個測試 flaky 失敗，詳下）；新增一則測試直接斷言 `detect()` 確實被呼叫（`domainViewStateProvider` 反映 `DomainNotFramework`）；既有降級旗標重置測試擴充同時斷言 `inferredVersionProvider` 重置。
- `test/widget/app/shell_test.dart`：`_pumpShell` 補 `overrides`／`settle` 參數；新增啟動 restore→detect 測試（假 `WorkspaceRepository` + 假 `FrameworkSignalProbePort`）與推定版本徽章渲染／不渲染兩則測試。

**where.files 修正**：ticket 原列 `test/unit/app/shell_test.dart`（不存在），實際檔案為 `test/widget/app/shell_test.dart`；已於執行前以 `ticket track set-where` 更正，並補列本票新增的 ARB 兩檔。

**中途 SPEC 更新處理**：main 於執行中合入 SPEC-001 v1.19／SPEC-004 v1.45（`0.2.0-W1-040`），新增〈推定版本〉徽章規格（key `inferredVersionBadgeLabel`、id `badge-<screen>-inferred-version`、與降級徽章互斥、常駐於返回列、切換專案重置）。已 `git merge origin/main`（fast-forward）並依新規格實作，未使用原先臆測的 `version` placeholder 名稱與徽章形態。「App 已知版本範圍」面板改動已另立 `0.2.1-W1-001`，不在本票範圍，未觸碰。

**已知架構缺口（非本票新增，記錄供後續票參考）**：最近專案清單（`recentProjectsProvider`）為 fixture 資料，無真實路徑，因此「切換專案」入口（點擊最近專案卡片）無法對 gate 偵測提供輸入；僅能重置旗標。真正的雙路徑 gate 偵測目前是「App 啟動 restore」與「選擇其他資料夾」，均已接線。
