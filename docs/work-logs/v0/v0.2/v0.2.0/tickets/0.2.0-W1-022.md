### 問題根因

本票評估的兩個呼叫點（WorkspaceRepository、gap_report_screen._openExternally）在
tech-decisions.md「2026-09-08：跨邊界驗證形態定案」盤點時被識別為平台端事實零覆蓋。
問題不是程式碼有 bug，而是跨邊界呼叫的平台端行為從未被實機驗證過——自動測試全以
替身（fake/mock）驅動，替身正確不代表平台正確。

### 影響範圍

|---------|---------|-----------|-----------|
| `file_selector.getDirectoryPath()` → NSOpenPanel | WorkspaceRepository | `_FakePicker`（test/unit） | 零覆蓋 |
| `SharedPreferences` → NSUserDefaults | WorkspaceRepository | `_FakePreferencesPort`（test/unit） | 零覆蓋 |
| `dart:io Directory.exists()` / `.list()` | WorkspaceRepository | `_FakeDirectoryProbe`（test/unit） | 零覆蓋 |
| `Process.run('open', [path])` | gap_report_screen | `gapItemProcessRunnerProvider` override | 零覆蓋 |
| `File(item.filePath).existsSync()` | gap_report_screen | 真實暫存檔（test/unit） | 零覆蓋 |

### Commit 規範

Recommended: commit via isolated index (files must be a subset of this

Fallback (not recommended; only if `ticket track commit` fails or is
unavailable) — use precise staging + verified bare commit only (no pathspec):
  git add {exact files}
  git diff --cached --name-only   # confirm index contains ONLY {exact files}
  git commit -m "..."             # bare commit; no -- <paths> / --only / -o / -a
Forbidden: git add . / git add -A; git commit -- <paths> / --only / -o / -a
  (pathspec-style commit discards the index and rebuilds it from working-tree
   content for the given paths — it silently absorbs unstaged edits other
   sessions may have on the same path, not just already-staged ones)
Before fallback commit: git diff --cached --name-only to check staged scope; git restore --staged <path> for any non-owned file
If bare `git commit` fallback is DENYed by bare-commit-guard-hook (another
dispatch active), stop and escalate to PM; never switch to pathspec /
--only / -o / -a to get around it.
If a commit is later found to have swept in out-of-scope content (e.g. a
peer session's staged changes):
Forbidden recovery actions: git revert; git reset --soft; git commit
--amend; any "reverse apply"/reapply of the diff. None of these may be
used to undo or rewrite the commit.
The ONLY permitted actions are: stop, record the commit SHA and file
list in the ticket, report to PM.

## Solution
<!-- Schema[ANA/Solution]: 必填（.claude/pm-rules/ticket-body-schema.md） -->

### 分析結論

兩個對象各自按「須實機驗證的平台端事實」與「app 端即可驗的回饋義務缺口」兩類分述。

#### 一、WorkspaceRepository

**app 端回饋義務缺口**：無。已由 `0.1.0-W3-121` 完整處理，不重做。

**須實機驗證的平台端事實**：

| 平台邊界 | 風險等級 | 建票建議 | 理由 |
|---------|---------|---------|------|
| `file_selector.getDirectoryPath()` → NSOpenPanel | **高** | **建票** | 跨邊界判準命中（需人工回應系統 UI）；原生選取器行為從未在本 app 上驗證；sandbox off + Developer ID 簽章條件下 NSOpenPanel 是否正常呈現是發布前必驗項 |
| `SharedPreferences` → NSUserDefaults | 低 | 不建票 | 標準 Flutter 套件，無 macOS 特有風險；跨啟動持久化可在正常 QA 流程中附帶驗證，不值得獨立票 |
| `dart:io Directory` | 低 | 不建票 | 通用 Dart runtime 行為，非 macOS 專有；程式碼已處理所有已知邊緣條件（FileSystemException、StateError、不存在） |

#### 二、gap_report_screen._openExternally

**app 端回饋義務缺口**：

| 缺口 | 嚴重度 | 建票建議 | 理由 |
|------|--------|---------|------|
| `File.existsSync()` 無呼叫發出日誌且不可替身觀察 | 中 | **不建票** | `0.1.1-W1-004` 遷移至 ExternalOpener 後自動消除（ExternalOpener 的 `FileSystemEntity.type()` 已含完整日誌）；建獨立票修當前程式碼再由遷移票替換，成本 > 收益 |

**須實機驗證的平台端事實**：

| 平台邊界 | 風險等級 | 建票建議 | 理由 |
|---------|---------|---------|------|
| `Process.run('open', ...)` | 低 | **不建票** | `0.1.1-W1-004` 遷移至 ExternalOpener 後，由 `0.2.0-W1-027`（ExternalOpener 在簽章 .app 內的 open 行為）覆蓋；建獨立票驗當前直接呼叫路徑再由遷移替換，成本 > 收益 |
| `File.existsSync()` | 低 | 不建票 | 通用 dart:io 行為，遷移後被 ExternalOpener 的 `FileSystemEntity.type()` 取代 |

### 候選方案

#### 方案 A（建議）：建一票覆蓋 file_selector，其餘引用既有票

- **建票**：`file_selector.getDirectoryPath()` 在 macOS + sandbox off + Developer ID 簽章條件下的實機驗證
  - 驗證項目：(1) NSOpenPanel 是否正常呈現 (2) 選取路徑是否正確回傳 (3) 取消是否回傳 null (4) 搭配 `WorkspaceRepository.chooseFolder()` 端到端
- **不建票**：SharedPreferences、dart:io Directory、gap_report_screen 的 Process.run 與 File.existsSync()
  - SharedPreferences 與 dart:io：低風險，正常 QA 附帶可驗
  - gap_report_screen：`0.1.1-W1-004` 遷移後由 `0.2.0-W1-027` 覆蓋

**利**：精準覆蓋唯一的高風險缺口，不產生會被後續遷移替換的短命票
**弊**：SharedPreferences 跨啟動持久化未以獨立票追蹤

#### 方案 B：建兩票，加 SharedPreferences 跨啟動持久化驗證

- 同方案 A，額外建一票驗證 `SharedPreferences.setString` / `getString` 跨 app 啟動後資料仍存在
- **利**：覆蓋更完整
- **弊**：SharedPreferences 為標準套件，獨立建票的邊際收益低；該驗證可在 file_selector 實機驗證同場次附帶進行（選完資料夾 → 關 app → 重開 → 看路徑是否還原）

### 建議

採 **方案 A**。file_selector 原生選取器是唯一滿足跨邊界判準（需人工回應系統 UI）且無既有票覆蓋的平台邊界。SharedPreferences 跨啟動可在同場次附帶驗證（不需獨立票追蹤）。

### Spawn 規劃表

| 項目 | 類型 | 對象 | 建票/豁免 |
|------|------|------|----------|
| file_selector 實機驗證 | IMP | `WorkspaceRepository.chooseFolder()` 端到端 | **建票** |
| SharedPreferences 跨啟動驗證 | - | `WorkspaceRepository.restore()` | 無需建 ticket：方案 A 場次附帶驗證，邊際收益不足以獨立追蹤 |
| dart:io Directory 邊緣條件 | - | `WorkspaceRepository._inspect()` | 無需建 ticket：通用 Dart runtime，程式碼已處理全部已知邊緣 |
| gap_report File.existsSync 回饋缺口 | - | `gap_report_screen._openExternally` | 無需建 ticket：`0.1.1-W1-004` 遷移後自動消除 |
| gap_report Process.run 平台驗證 | - | `gap_report_screen._runOpen` | 無需建 ticket：遷移後由 `0.2.0-W1-027` 覆蓋 |
