## Problem Analysis
### 問題根因

SPEC-001〈Gate 三問對照〉schema gate「不確定」欄定義了「`.claude/VERSION` 缺失但 JSON 存在 → 以 JSON 內的產生版本推定並標示」的行為，但：
1. §1 狀態表無對應列——判定順序 step 3（JSON 存在 → 依版本範圍分正常／schema 不相容）的隱含前提是 VERSION 存在，但 step 1 只攔截「兩者皆缺」，VERSION 單獨缺失而 JSON 存在的路徑直接落入 step 3 卻無載體
2. `DomainViewState` sealed class 的七個子類別皆不承載「版本來自推定」的語意：`DomainReady` 無版本欄位、`DomainSchemaIncompatible` 的 `projectVersion` 語意為 `.claude/VERSION` 真實值而非推定值
3. Gate 偵測 notifier 尚未建置（W1-033 核心缺口），但即使建置，路由至 state 的映射也缺此分支

### 影響範圍

**已驗證的事實**：
- W1-032 manifest 的 17 個真實專案中 **0 個**命中此路徑（6 個兩訊號皆缺、9 個只有 VERSION、2 個兩者皆有）
- `DomainSchemaUnconsumable` 的 `version` 欄位為 required String（domain_view_state.dart），語意綁定 `.claude/VERSION` 真實值
- `DomainSchemaIncompatible` 的 `projectVersion` 同樣語意綁定 `.claude/VERSION`
- `isDegraded` 旗標已在 `DomainReady` 與 `DomainEmpty` 上實作，為正交疊加旗標的先例
- 降級徽章由 `degradedSchemaProvider` + `degradedSchemaVersionsProvider` 兩個獨立 provider 承載，`AppShell` 於返回列常駐渲染

**仍未驗證的假設**：
- 「App 已知範圍」判準（W1-024 pending）未定，推定版本落入 in-range 或 out-of-range 的邊界未完全確定

### 相關 Error Pattern

## 重現實驗結果
### 實驗方法

本票分析的是設計缺口而非 runtime bug。「重現」方式為：驗證現有程式碼對「VERSION 缺 + JSON 有」路徑的處理。

1. 檢查 `DomainViewState` sealed class 子類別是否有承載「推定版本」的載體
2. 檢查 `domain_view_screen.dart` 的 switch 分支是否處理此路徑
3. 比對 W1-032 manifest 確認 17 個真實專案的命中分佈

### 實驗執行

**載體檢查**：

```
grep -n "inferr\|推定\|inferred" lib/screens/domain_view/domain_view_state.dart
```

結果：0 筆命中。`DomainViewState` 七個子類別（`DomainUnset`／`DomainLoading`／`DomainReady`／`DomainEmpty`／`DomainNotFramework`／`DomainSchemaUnconsumable`／`DomainSchemaIncompatible`）皆無推定版本相關欄位。

**畫面分支檢查**：

`domain_view_screen.dart` 的 switch（約行 55-62）：

```dart
DomainNotFramework() => const _NotFrameworkView(),
DomainSchemaUnconsumable() => _SchemaUnconsumableView(state: state),
DomainSchemaIncompatible() => _SchemaIncompatibleView(state: state),
```

sealed class 已窮盡，若 gate 偵測邏輯將「VERSION 缺 + JSON 有 + 版本在範圍」路由至 `DomainReady`，畫面會正常渲染但無任何標示；若路由至 `DomainSchemaIncompatible`，`projectVersion` 會收到 JSON 推定值但無法與真實 VERSION 值區分。兩者皆缺「推定並標示」語意。

**真實專案分佈**（W1-032 manifest，2026-09-23 實測）：

- 6 個兩訊號皆缺（不是框架專案）
- 9 個 VERSION 有 + JSON 無（無可消費的型別表）
- 2 個兩者皆有（可載入）
- **0 個 VERSION 缺 + JSON 有**（本票目標路徑）

### 實驗發現

**已驗證的事實**：

1. 現有 `DomainViewState` 與畫面渲染對「VERSION 缺 + JSON 有」路徑的處理為**零覆蓋**——無載體、無標示、無推定邏輯
2. 17 個真實專案無一命中此路徑，但 Gate 三問對照已定義其行為（「以 JSON 內的產生版本推定並標示」），屬防禦性設計而非空想
3. `isDegraded` 旗標是「正交疊加旗標」的既有先例：不新增 state 子類別、以 bool 欄位疊加於 `DomainReady`／`DomainEmpty`、搭配獨立 provider 承載徽章文字
4. 降級徽章渲染位置為「頁面框架於返回列常駐」（SPEC-001 §1 降級註記 (4)），推定版本標示可比照同一位置

**仍未驗證的假設**：
- Gate 偵測 notifier（W1-033）尚未建置，推定邏輯與 state 路由的整合行為無法端到端驗證
