### 世界平面查證（不採票面轉述）

`lib/components/app_snack_bar.dart` 現況：`messenger.hideCurrentSnackBar()` 在第 267 行，其上第 251-260 行為 `if (decision == _Preemption.yieldToHolder) { ...; return; }` 提前返回。裁決來自第 164-178 行的純函式 `_resolvePreemption`，函式體比較 `holder.level.index` 與 `incoming.index`。呼叫確已非無條件。

### 一處為結論證據更換，非僅措辭調整

票面 why 述「結論不變，依據失效」（PC-GPD-014 形態），此判斷對四處成立，對 §2.15 規則 2 驗收（原 1055）不完全成立：

- 原文的靜態證據為「`hideCurrentSnackBar()` 呼叫不含任何比較目前佔用者級別的邏輯」。該陳述現已為假——`_resolvePreemption` 正是在比較級別，且原始碼註解明寫「比較鍵恆為級別的序，不得以載體型別、變體或呼叫路徑為鍵」。
- 其結論「規則 2（排隊或合併）未被滿足」仍成立，但支撐它的證據必須整條更換，不能只改措辭：新證據為「同級別落在取代分支，既不排隊也不合併，而本節兩列同為可棄級別恆走該分支」。

acceptance 第 3 條「確認結論未被動到」在此處的正確判讀是：結論未動，證據已換。若逕以措辭調整處理，會留下一句與原始碼相反的靜態證據。

原 1030 與 1055 以 `app_snack_bar.dart:121` 指涉呼叫點。實測第 121 行現為無關的 `static const`，實際呼叫在第 267 行。因兩處正是本次改寫的句子，一併改為符號指涉。
