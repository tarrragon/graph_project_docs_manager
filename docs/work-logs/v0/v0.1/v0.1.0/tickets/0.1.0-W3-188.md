### PM 補充（2026-09-09）：本票的形狀比「補一份清單」大

實查 `.claude/hooks/canonical-schema-consistency-check-hook.py`：該 hook 是**專門為此 canonical 集合而建的守衛**，其 docstring 第 20-24 行明列所守的下游清單：

| # | 下游 |
|---|------|
| 1 | `hooks/acceptance_checkers/custom_h2_checker.py` 的 `_SCHEMA_SECTION_NAMES` |
| 2 | `hooks/acceptance_checkers/execution_log_checker.py` 的 `_SCHEMA_SECTION_NAMES` |
| 3 | `skills/ticket/ticket_system/lib/ticket_validator.py` 的 `_SCHEMA_SECTION_NAMES` |
| 4 | `pm-rules/ticket-body-schema.md`（Schema 對照表第一欄 + 補列項） |
| 5 | `references/agent-definition-standard-details.md`（Schema 章節清單行） |

**`references/agent-self-check-template.md` 不在這份登記表內。**

所以本票要處理的不是「一份清單落後」，是**守衛的宣告涵蓋範圍窄於實際存在的下游數量，而窄的那部分不會產生任何訊號**——守衛回報「無漂移」的同時，第六份正在漂。這是 `ARCH-BAL-006`（宣告範圍窄於執行範圍）的形狀。

**只補 `Spawn Requests` 是修症狀。** 守衛的可信度來源是登記表的完整性：若登記表可以漏第六份，它也可以漏第七份，而每一次漏都以「檢查通過」的形式呈現。

#### 追加的處置要求

| 項目 | 要求 |
|------|------|
| 補齊 `agent-self-check-template.md` 的清單 | 全量比對模板產生的全部 H2，不只補 `Spawn Requests` |
| 把 `agent-self-check-template.md` 登記進該 hook 的下游表 | 使它從此有訊號 |
| 回答「這個 canonical 集合到底有幾份下游清單」 | 以機械手段盤點（grep 該集合的成員名於 `.claude/` 全域），不以現有登記表為準——**現有登記表正是被質疑的對象** |
| 判定登記表如何保證不再漏 | 兩個方向：登記表改為自動發現（掃描全域找持有該集合子集的檔案），或維持人工登記但在新增下游時有強制點。二擇一並記錄理由 |

#### 已知既有落差的處置形態值得沿用

該 hook 的 docstring 已有「已知既有落差（本 hook 的設計目的即讓其可見，非本 hook 待修復範圍）」段落，明文區分「已知且接受」與「新出現」。**但該基線寫在 docstring 給人看，未編碼成資料讓工具把它從輸出減掉。** 若本票決定擴充登記表，一併評估是否把基線編碼化——否則涵蓋範圍變大會使輸出中的既有落差同步變多，重演「每次都報、每次都被略過」。


### 路由更正（2026-09-09）：本票的升級判定與 `escalation-flow` 判準不一致，待裁示

建票時本票判定為「不走 framework issue 升級——建立端行為正確，錯的只是驗證端清單落後，屬即時可修的下游同步」，依據是 `tool-output-trust-rules` 規則 6 的判定順序。

**該依據用錯了問題。** 規則 6 回答的是「建立端與驗證端衝突時誰是權威」，**不是「該在哪裡修」**。後者的判準在 `escalation-flow.md`〈介入判斷〉，為兩條 AND，本票兩條皆符合：

| 判準 | 判定 |
|------|------|
| 抽象可攜性 | 符合——「一支專門為某 canonical 集合而建的守衛，其宣告涵蓋範圍窄於實際存在的下游數量，而窄的那部分不產生任何訊號」，替換專案名與路徑後成立 |
| 資產範圍 | 符合——`.claude/hooks/canonical-schema-consistency-check-hook.py` 與 `.claude/references/agent-self-check-template.md`，皆為通用資產 |

**後果**：此缺陷現存於每一個 consumer——它們的自檢模板同樣缺該章節、守衛同樣未登記該檔。在本地修的結果是修復困在本地 commit 歷史、下次 `sync-pull` 可能被上游未修的舊版覆蓋。

**與 `0.1.0-W3-193` 一併裁示**：兩張票套用同一判準皆應升級，不宜一張升級一張不升級。升級所需的 `observe` 或建立 issue 屬外顯動作，先前的用戶授權範圍限於建立 `#102`／`#103`／`#104`，不自動延伸，故兩票同樣停在授權裁示。

**裁示未到之前本票不執行**——若逕行在本地修，等於製造上述被明文警告的下場。
