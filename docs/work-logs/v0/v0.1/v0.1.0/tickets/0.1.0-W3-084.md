### Rationale Chain
- 0.1.0-W3-075 why: `component-contract-design` 的核心產出是元件目錄加逐元件契約欄位，畫面票因此只剩「選件與排位」。測試側無對應物：`doc-handoff.md` 有規格→測試的映射與 GWT 轉換，`layered-test-strategy.md` 有「哪一層要測」，但沒有「**要測哪些對象**」的目錄，也沒有「**每個測試對象要定義到什麼程度**」的欄位表。

三處具體落差（對照元件庫 skill）：起點只有「有規格」一條，缺接手模式（既有測試如何盤點、補契約）；完成判準只有覆蓋率數字（行為場景 100%、分支 100%），那是量的判準，沒有質的可機械檢查；無派發語言，測試票仍要實作者自行決定測什麼。

後果：測試設計品質依賴 Phase 2 代理人當下的判斷，不同票之間無一致性可言，且「這個測試對應規格的哪一條」無處記載——這正是「設計出與專案無關的測試」的結構成因（用戶 2026-09-08 指出）。
