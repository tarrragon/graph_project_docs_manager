#### D1（V4R-01 G09）UC-05 載入期間離開

**兩端原文**：UC-05〈例外場景〉〈載入期間離開〉「使用者於載入期間取消或切換畫面，系統中止載入並保持可操作」；SPEC-003 §2.8〈生命週期契約〉L1「任務繼續（離開畫面不等於取消）」、§3.4〈生命週期〉「切至其他導覽項：載入繼續」；SPEC-001 §4 載入中可用操作「切換至其他畫面」。
**現文核對**：矛盾仍在。
**假設根因**：UC-05 寫於 L1 定案前，把取消與離開併成一句。

| 選項 | 類別 | 內容 |
|------|------|------|
| O1 | 改造既有（原文一端：SPEC-003） | UC-05 改為兩分支：取消中止回未載入；切換畫面載入繼續 |
| O2 | 改造既有（原文另一端：UC-05） | Ticket 載入於切換導覽項時中止，§2.8 L1 對 Ticket 加例外 |
| O3 | 零新增（反向框架：讓離開不可達） | 載入中停用導覽項 |
| O4 | 新增 | 切換導覽項時彈確認「是否中止載入」 |

**R 事證**：SPEC-001 FR-02 驗收「取消操作恆可用且可離開該畫面」不要求離開即中止；SPEC-003 §2.11「三處載入態…C1–C8 與 L1–L2，共 10 條完全相同」，O2 破壞三處同一；SPEC-001 §8.1 表後段落以「Domain 載入與 Ticket 載入同樣可在使用者離開後完成」為判否理由，O2 使該理由對 Ticket 失效；O3 違反 SPEC-003 §5 判讀「導覽列恆可點（§2.8 L1）」；O4 新增 Dialog 無 UC 出處，與 §2.5 C5「取消完成後不出現 Dialog」同精神相悖；UC-05 flow `cancel-loading` 的 `return_to: enter-ticket-list` 只描述取消分支，與 O1 相容。
**裁決**：O1。
**被放棄選項優點**：O2 離開即釋放解析資源；O4 讓使用者明示意圖。
**選定方案缺點**：(1) 使用者在他頁時無全域指示得知 Ticket 仍在載入；(2) UC-05 一句拆兩分支，flow 步驟名「載入期間離開」涵蓋兩者但只有取消回未載入；(3) 期望離開即停的使用者會多付一次解析成本。
**P 失敗訊號**：實機驗證時使用者回報「離開後仍在載入」或回到清單時對已完成表示意外 → 重評 O4 或補全域進度指示。
**改動位置與改法**：UC-05〈例外場景〉〈載入期間離開〉改「使用者於載入期間取消時，系統中止載入並回到未載入；切換至其他畫面時載入繼續，回到本畫面顯示當時進度（SPEC-003 §2.8 L1）」；UC-05 frontmatter `version` 與〈變更歷史〉補一列。
**同步點**（grep「中止載入」「載入繼續」「切換畫面」）：SPEC-001 §4 載入中列（已一致，不改）；SPEC-003 §2.8 L1、§3.4〈生命週期〉切至其他導覽項列、§3.4〈導航跳轉與退出〉載入中列、§4 #16（已一致，不改）；UC-05〈驗收條件〉第 2 條（已一致，不改）。改動點僅 UC-05 一處。
