## Solution
<!-- Schema[IMP/Solution]: 選填（.claude/pm-rules/ticket-body-schema.md） -->
建立 `lib/components/expander_icon.dart`（`ExpanderIcon`，StatefulWidget）並自新建 `lib/components/components.dart` barrel 匯出，實作依 SPEC-004 條目 4.18 契約：

- slot：`isExpanded`（必填）、`isLeaf`（預設 false）、`onToggle`（非 leaf 必填）、`testKey`（必填，呼叫端定址 key，直接掛在最外層 Semantics/SizedBox）
- 尺寸：固定 `LayoutSize.hitTargetMin` × `LayoutSize.hitTargetMin`（leaf 與非 leaf 皆同，對齊已由測試驗證）；圖示 `LayoutSize.iconSm`，色彩 `AppColors.textSecondary`
- 狀態：collapsed 渲染 `Icons.keyboard_arrow_right`，expanded 渲染 `Icons.keyboard_arrow_down`，leaf 用 `ExcludeSemantics(SizedBox(...))` 不渲染箭頭但保留尺寸且排除語意樹
- 互動：`InkWell` 點選呼叫 `onToggle`；額外用 `Shortcuts` + `Actions`（`SingleActivator(enter)` / `SingleActivator(space)` → `ActivateIntent`）掛在自管 `FocusNode` 上保證鍵盤觸發，不依賴 InkWell 內建鍵盤路徑（實測 InkWell 在無 Material 祖先包裝時 tap 不會自動移轉 primaryFocus，改為 onTap 內顯式 `_focusNode.requestFocus()`）
- 焦點裝飾：`DecoratedBox` 恆為非 null decoration（未聚焦透明邊框、聚焦 `AppColors.accent` 邊框 + `Radius.sm`），符合 SPEC-003 §2.10 焦點裝飾斷言（非 null decoration 需恆存在，非條件式建立節點）
- 無障礙：`Semantics(button:true, label: l10n.expanderLabel, expanded: isExpanded)` 掛在最外層；`InkWell` 加 `excludeFromSemantics: true` 避免與外層 Semantics 產生第二語意節點導致 flag 判讀不一致（開發過程實測命中：語意查詢一度落在 root scopesRoute 節點而非本元件節點）
- i18n：`expanderLabel` key（W1-056 已建，zh/en 皆有）
- token：全部走 `lib/tokens/tokens.dart`（`AppColors`、`LayoutSize`、`Radius`）；唯一裸值 `Colors.transparent`（未聚焦邊框色，非語意色彩）已加 `// color-exempt` 標記通過 Presence Guard

測試 `test/unit/components/expander_icon_test.dart`：13 個測試，涵蓋 collapsed/expanded/leaf 三態於 `WindowSize.min`/`design` 兩尺寸不溢位、leaf 寬度對齊非 leaf、點選呼叫 onToggle 恰一次、`Semantics.expanded` 與 `isExpanded` 一致、leaf 無語意節點（`find.bySemanticsLabel` 落空）、鍵盤 Enter/Space 觸發、`disableAnimations` 下渲染成功。

契約無修訂——4.18 十一欄位皆可直接落地，未遇契約值實測不成立需回改 SPEC-004 的情況。
