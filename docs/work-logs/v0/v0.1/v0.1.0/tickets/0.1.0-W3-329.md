## Solution
<!-- Schema[IMP/Solution]: 選填（.claude/pm-rules/ticket-body-schema.md） -->
成本先解、再談其餘三項：**SessionStart 新增成本 = 一次本地 JSON 檔案讀取（無 gh 呼叫、無 `todo --json`）**。方向：把「計算 delta」從讀取端移到寫入端——`section_comment.py` 的 cmd_init/cmd_add/cmd_update 已在正常寫入流程中持有「此次寫入後的完整表格列」，故新增 `todo_pending_registry.py`（`.claude/skills/framework-issue/scripts/`）在每次成功寫入後對 `(issue, owner)` 範圍做一次全量同步：狀態為「待裁票」的列 upsert 進本地 pending 登記檔，原本 pending 但這次不再是「待裁票」（狀態改變或整列消失）的項目視為已處理並移除。SessionStart hook（`session-start-todo-delta-hook.py`）只讀這份本地檔案，零額外 gh/CLI 呼叫。

四項未決逐一交代：

1. **ack 訊號的取得方式與載體**：載體為 `.claude/state/framework-issue-todo-pending.json`（per-worktree、已在 .gitignore、不寫入 canonical issue，同 `owned_issues_registry` 定位）。ack 訊號**不是獨立動作**，而是隨 curator 正常的裁票／更新流程自然發生——`sync_section_rows` 對範圍做全量同步時，凡狀態離開「待裁票」或整列消失即視為已處理並移除。這是 ack-based（狀態真正變化才消失），不是 seen-based（被印過就消失）：本模組從不因「被 SessionStart 印過」而移除項目。
2. **成本控制**：見上段，SessionStart 路徑零 gh 呼叫；三個候選方向中選定「寫入端增量維護 + 讀取端純檔案讀取」，未選「本地快照僅在寫入端更新後仍由讀取端輪詢」（仍需讀取端額外邏輯）與「僅掃本 consumer 擁有的 issue」（仍需一次 gh 往返）。
3. **推送範圍**：限**本 consumer 透過本機 section_comment.py 寫入**所產生的列；他方 consumer 或繞過本 CLI 直接以 `gh api` 寫入的列不會出現在此登記檔。這是成本約束下的必然選擇——偵測他方寫入需要重新拉取全量資料（即 `todo --json`），而 SessionStart 路徑禁止此呼叫。此範圍限制記錄於 `todo_pending_registry.py` 檔頭，供日後重評。
4. **狀態遺失後的退化行為**：**選擇全列沉默，不選全列重印**。全列重印需要重建完整 baseline，即呼叫 `todo --json`，違反本機制的成本前提；沉默的代價是遺失期間新增的列不會被通報，直到下一次寫入端呼叫重新建立範圍內的 pending 項目。這是被成本約束逼出的選擇，非任意偏好。

**誤報定義**（硬要求）：本登記檔可能落後於 canonical 真實狀態——若某列被繞過本 CLI 的方式（直接 `gh api` 編輯 comment）標記為已處理，本登記檔不會得知，會持續通報一個實際已處理的項目，直到下一次透過本 CLI 對同一 (issue, owner) 範圍執行寫入操作、觸發一次全量同步為止。這是本機快取類機制共有的已知限制（同 `owned_issues_registry` 定位），已寫入模組 docstring。

修改檔案：
- 新增 `.claude/skills/framework-issue/scripts/todo_pending_registry.py`（schema、讀寫、`sync_section_rows` 同步邏輯）
- 修改 `.claude/skills/framework-issue/scripts/section_comment.py`：import 新模組、新增 `_todo_rows_from_content` 純本地解析 helper、cmd_init/cmd_add/cmd_update 三處呼叫點（成功寫入後同步 + stderr 回印，`0.1.0-W3-326` 裁定的輔通道）
- 新增 `.claude/hooks/session-start-todo-delta-hook.py`（主通道，讀 pending 登記檔、subagent 略過、非 startup/resume 略過、缺檔退化為沉默、fail-open）
- 修改 `.claude/settings.json`：SessionStart 註冊新 hook，timeout 5000ms（純檔案讀取，遠低於既有 `session-start-issue-check-hook.py` 的 20000ms）

hook 異常走 stderr + 檔案日誌雙通道：沿用 `hook_utils`（`setup_hook_logging` / `run_hook_safely`），與 `session-start-issue-check-hook.py` 同規格。
