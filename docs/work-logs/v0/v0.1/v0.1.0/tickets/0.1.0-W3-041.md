## Solution
<!-- Schema[ANA/Solution]: 必填（.claude/pm-rules/ticket-body-schema.md） -->
### 上游正式意見（廢除方回覆，2026-09-07）——裁決依據已齊

**廢除方自陳：「職責已由其他機制覆蓋」這句話是錯的。** 他們去讀了被刪除的原始碼才
確定，因為三份紀錄（版本紀錄 0.17.0 與 0.92.0、CLAUDE.md、刪除提交）沒有一份說得出
接手的是誰——全部只有那一句沒有指向的話。

**正確歸類：consumer 特化（不適用於廢除方的環境），不是被取代。**

| 檔 | 廢除方環境的實況 | 判定 |
|----|----------------|------|
| `comment-qa-hook.py` | 檢查 Dart／JS／TS 事件處理函式、StatefulWidget／ConsumerWidget、UseCase 與 Domain 層公開函式的追溯資訊；規範內指名 `docs/event-driven-architecture-design.md`。該專案是 Hugo blog，無 Dart、無該架構文件，唯一的 TS 是四個 Playwright spec 而 hook 自己豁免測試檔 | **目標集合為空，非被取代** |
| `worklog-format-check.py` | 警告 markdown 表格單元格內會使 Claude Code CLI crash 的 emoji（`⏳`／`🔄` 這一類），作用域寫死 `docs/work-logs/`。該專案路徑為 `content/work-log/`，一開始就不匹配 | **路徑不匹配，非被取代** |

**兩支皆無已知缺陷**，本專案繼續執行不構成問題。

**廢除方的正式意見（逐字）**：「兩支歸類為 consumer 特化，我方環境不適用，無缺陷，
不反對保留在任何不會被我方 push 覆蓋的位置。」他們同時說明落地需其使用者點頭，
因為那是影響九個以上消費端的共用庫版面決定。

#### 一項對本專案的功能性判斷

`worklog-format-check.py` 緩解的是**表格單元格 emoji 造成 Claude Code CLI crash**。
廢除方明說他們那側「emoji 由 AGENTS.md 與字句層 grep 承接，而那是人工 grep，
`mdtools` 至今沒有 emoji 規則」——**即使在他們那邊，覆蓋也只成立一半，且覆蓋的是
風格層而非那個 crash 的緩解。**

本專案的 `docs/work-logs/` 正是該 hook 的作用域，且該 crash 與專案無關。
**這使「跟著移除」成為明顯錯誤的方向**：唯一寫死的是路徑，不是適用性。

#### 裁決方向（待 PM 定案）

依上述，全體廢除已被排除。餘下二擇一：

1. 三檔移入 `references/project-integration/`（排除於 sync），本專案與 flutter_balance
   各自保留註冊——但該目錄的語意是「各專案自備」，而兩個 consumer 有相同需求，
   放進去等於複製兩份。
2. 發佈庫恢復三檔並更正 0.92.0 條目，作用域由寫死改為可設定——需廢除方使用者點頭。

`portability-check.sh` 兩側皆未註冊，可與兩個 hook 分開裁決。

### 三方定案：不恢復至 compositional-writing，另立由本方持有版號的 skill

廢除方的使用者裁決為**不恢復**，理由不是「他們用不到」，而是**這兩個 hook 的主題不屬於
`compositional-writing`**。該框架由 WRAP 的反面框架換出——原問題是「這兩個檔該不該在
共用庫」，反面是「這支 skill 該不該承載這兩個主題」。

**四項依據，本側查證了其中兩項可機械驗證者**：

| 依據 | 本側查證 |
|------|---------|
| 該 repo 是主要作者，CHANGELOG 0.3.0→1.7.1 整條線是寫作方法論 | 未獨立查（屬對方 repo 歷史） |
| 兩個 hook 的主題不在該線上，且無任何 CHANGELOG 記載它們如何進來 | 未獨立查 |
| **發佈庫七支帶 `hooks/` 的 skill，每一支的 hook 都是該 skill 自己的主題** | **屬實**（見下表） |
| **`references/project-integration/` 已在 `EXCLUDE_DIRS`** | **屬實**（`cli.py:29`） |

| skill | hooks/ | 主題相符 |
|-------|--------|---------|
| dart-test-async-guardian | `pre-test-scan.py` | 是 |
| error-pattern | `error-pattern-flat-gate-hook.py` | 是 |
| tdd | `layer-boundary-validator-hook.py` | 是 |
| ticket | `acceptance-gate` 等 21 支 | 是 |
| version-release | `version-release-guard-hook.py` | 是 |
| worktree | `worktree-*` 9 支 | 是 |
| wrap-decision | `wrap-*` 2 支 | 是 |

**七支全部相符，而唯一的例外正是被刪掉的那一支。**

**決定性的一條**：這支 skill 的版號由**不跑那兩個 hook 的一方**持有。恢復等於固化
「兩個作者、一個版號」——而那正是本次落差的產生方式（他們刪、我們不知道、紀錄與檔案
在我們這裡互相否證）。

**裁決**：兩檔搬離 `compositional-writing`，另立由本專案持有版號的 skill。共用價值完全
保住（三方一份、修一次全部受益），而**寫它的人也是跑它的人**。搬移時一併做兩件本側
先前提出的事：路徑改為可設定、架構文件引用改為可省略。

**主題可分為二**：`worklog-format-check` 屬工具相容性（表格單元格字元使 CLI 崩潰）、
`comment-qa-hook` 屬特定架構風格下的註解規範。可各自成家或合為一支專案規範 skill，
形態由承接票決定。

**檔案來源**：本專案與 flutter_balance 各有可執行副本，後者 09-02 還修過，取新者即可，
不需從廢除方取。歷史版本在其 `332b3c27^`。

**push 處置**：兩檔搬離後 `compositional-writing` 不再持有它們，本專案 push 該 skill
不再有覆蓋風險，凍結可解除。廢除方已備妥 1.7.2（未推），內含改寫為合規的刪除紀錄
（寫明不適用條件與作用域、無接手機制、**無已知缺陷**），待本票結案通知後推送。
