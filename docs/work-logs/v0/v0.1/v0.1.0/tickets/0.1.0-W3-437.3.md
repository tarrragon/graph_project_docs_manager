## 重現實驗結果
### 實驗方法

本票為建模慣例評估，「重現」指取得兩類事實：(1) 本專案既有元件規格實際把資料態驅動的外觀放在哪一欄；(2) 業界設計系統對「狀態」與「變體」的分界基本率。

- 專案：`grep -c "| 資料態" docs/spec/ui/SPEC-004-component-library.md`；逐列讀命中的狀態矩陣列；`grep -n "tone\|修飾參數"` 同檔；`grep -rn "修飾參數\|tone" .claude/skills/component-contract-design`。
- 方法論：`component-library-bidirectional-constraint-methodology.md`〈元件契約判準〉欄位順序段。
- 業界：WebFetch Adobe Spectrum Design Data states registry、Primer StateLabel 文件；WebSearch Material Design states。

### 實驗執行

| 來源 | 觀察 |
|------|------|
| SPEC-004 狀態矩陣 | 「來源」欄為資料態的列 42 列。例：4.4 AppButton `disabled`（呼叫端 provider 的取消進行中欄位）、4.6 IssueMarker `default`（存在與否由損壞資料決定）、4.7 NavItem `unselected`／`selected`（`selectedDestinationProvider`）、4.8 ProjectSwitcherEntry `collapsed`／`expanded`。元件皆為傳值純 widget（§2），資料態由呼叫端 watch 後傳入，仍列狀態矩陣列 |
| SPEC-004 4.5 Badge、4.1 AppText | 分類資料值（票狀態 draft／pending／completed）驅動的顏色走 `tone` 語意色參數，明標「非變體」；AppText `emphasis`／`secondary`／`tone` 為「修飾參數（非變體）」。狀態矩陣不為每個狀態值開列 |
| SPEC-004 §3.7 第 5 項 | 「L2 原則：外觀差異不構成變體」——chip／inline 外觀由容器格位決定 |
| component-contract-design skill | 無「修飾參數」「tone」概念；step-3 狀態集列已含「來源：資料態」「同步策略」；變體列定義「行為不同的形態」 |
| 方法論〈元件契約判準〉 | 「回饋契約是邊，狀態集是節點，邊必須晚於節點定義」 |
| Spectrum states registry | default／hover／active／focus／keyboard-focus／disabled／down／pending／selected／drag-and-drop——含非互動的 disabled、pending、selected |
| Material（M2 States 頁、M3 applying states） | enabled／disabled／hover／focused／pressed／dragged／selected／activated，selected 與 activated 可與互動瞬態疊加 |
| Primer StateLabel | 議題／PR 狀態以必填 `status` prop（issueOpened／issueClosed／pullMerged／draft…）表達；原 `variant` prop 管尺寸，已棄用改 `size` |

### 實驗發現

已驗證的事實：
1. 業界基本率：「狀態」除互動瞬態外，普遍納入由應用資料決定、執行期可切換的二元旗標（disabled、selected、pending）。「變體」保留給呼叫端依設計意圖選定的樣式族或尺寸；三個來源皆未見把執行期可切換的資料旗標建模為 variant。
2. 業界另有第三種形態：分類資料值直接映射外觀（Primer `status`、SPEC-004 Badge `tone`）——既非狀態也非變體，是值對映參數。
3. 本專案 SPEC-004 已隱含採用選項 A（42 列資料態狀態列），並已實際使用第三種形態（tone／修飾參數），但 skill 條文未收錄第三種形態。
4. 方法論把狀態集定為回饋契約的節點；資料態若降為變體，其轉場（例：封存變暗的過渡）在回饋契約中沒有節點可掛。

仍未驗證的假設：archived 的「可操作性」是否改變（封存卡能否點入詳情）屬正例情境的設計決定，本評估不定；草稿沿用 437.1「可操作：同 default」。
