**依據只在範例內**（閘門第二條件，須清零）

2. B-13：「緩衝量沒有固定公式」只寫在範例 Q2。

**條文風險**（依規則 5 追蹤，判定是否改文）

## Solution
<!-- Schema[DOC/Solution]: 免填（DOC 類型以變更摘要取代）（.claude/pm-rules/ticket-body-schema.md） -->
逐項處置（全部屬階段 1，皆為既有條文補句，無需新判準）：

1. B-20／UX-20a（`error-recovery.md`〈Degraded mode〉靜默隱藏句）：補「判斷依據是該功能是否有使用者用過，不是上線時間長短或採用率高低」，排除按功能上線久暫或採用率判定「從未用過」的讀法。
2. B-13（`interaction-feedback.md`〈按鈕級回饋〉timeout 兜底句）：補「沒有固定公式或倍數可推導出具體秒數，只要求晚於後端逾時值」，把範例 Q2 的澄清收進條文本身。
3. B-02（`input-mechanism.md` Special keys 排列依據句）：補「沒有使用頻率資料不是不排列的理由，退回臨界路徑判定即可」。
4. UX-06（`input-mechanism.md` 搜尋觸發模式表）：條文風險屬實——表格「即時」列的「本地過濾」易被讀成「本地＝低成本」；於表後補一句明示判斷依據是「搜尋運算成本」而非「是否為本地」，本地高運算量情境（如大量記錄全文搜尋）仍屬高成本。
5. UX-12a（`interaction-feedback-waiting-and-notification.md`〈畫面級回饋〉維度表）：條文風險屬實——表格「退出路徑｜每個中間狀態都必須有」與檔首〈不適用〉宣告表面衝突；於表後補一句澄清該列是說明畫面級的一般需求（與按鈕級的差異），非要求本節回饋表另填退出路徑欄，權威值仍在 `screen-state-matrix.md`。
6. UX-09a（`interaction-feedback-component-semantics.md` 六項判準第 2 項）：補「兩者擇一即合格、與是否和按鈕同列無關」，排除「同列有按鈕時圓點／文字 chip 一律不合格」的誤讀。
7. UX-06a（`input-mechanism.md`〈判斷搜尋成本的依據〉範例）：範例結論「採按送出或 debounce」的 debounce 選項不受表格支持（表格將 debounce 定位為「遠端搜尋的常見選擇：平衡即時感和 API 呼叫次數」，本情境無 API 呼叫考量）；改為只採「按送出」並附理由，不修改條文表格本身。

全部 7 則已用 `git grep -F` 逐句驗證原句在編輯前唯一命中，編輯後重新 diff 確認無誤植。
