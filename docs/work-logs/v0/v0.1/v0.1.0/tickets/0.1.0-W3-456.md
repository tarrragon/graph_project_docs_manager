### 用戶原話與派發 context（PM 寫入，2026-09-16）

**用戶原話**
> 我設想可能遇到的狀況是，當我跟別人協作或者接手舊專案時，我需要做專案分析盤點，但是我不可能開 ticket 系統，這種協作專案或者已經上線的專案應該有他自己的任務分派系統比如 asana 或者使用 slack ，那我應該需要一個報告或者一個 todo 清單或者一個 excel 表去列出來或者可以盤點修復進度，我們需要設計這個替代性的系統，這應該是剛好找到我們目前框架中缺失的一部分功能

**發現脈絡**
- 0.1.0-W3-452.1 WRAP 複核 foundation-design FD-13a 時，判定「缺 ticket 系統時，應建票內容記入降級記錄」是新判準。
- PM 以 AUQ 詢問落點偏好，用戶回覆上段。
- 草稿見 0.1.0-W3-452.1 Solution；待落檔票為 0.1.0-W3-455。

**要回答的問題**
1. 框架內哪些地方假設 ticket 系統存在，且在「對方有自己的任務系統」時不成立？請盤點（至少含 foundation-design、version-bootstrap 的建票步驟、component-contract-design step-5）。
2. 替代產物的形態：報告、todo 清單、表格或匯出格式。需求條件：
   - 讓對方系統能匯入或照抄；
   - 能追蹤修復進度；
   - 能表達先後順序（取代 blockedBy）。
   用 WRAP 評估。
3. 替代產物與本框架 ticket 的對應關係：哪些欄位必留，哪些可省。
4. 框架問題判準：依 `.claude/skills/framework-issue/references/escalation-flow.md` 的兩條 AND 判準逐條套用並記錄，再跑 dedup，記錄關係判定（重複／切分／引用）。

**約束**

- 屬用戶偏好的欄位或形態選項，明標後交 PM 以 AUQ 詢問。
