## Problem Analysis
<!-- Schema[ANA/Problem Analysis]: 必填（.claude/pm-rules/ticket-body-schema.md） -->
### Context Bundle

**審查對象（四檔，全部唯讀）**

`.claude/skills/skill-design-guide/SKILL.md` 與 `references/` 下三檔：`patterns-and-troubleshooting.md`、`seeing-like-an-agent.md`、`splitting-an-existing-skill.md`。

**定位（frame 判斷標準的輸入）**

這是**查閱型參考文件**，不是照著跑的操作手冊——與本專案前一次審查的對象（component-contract-design，操作手冊）定位不同。讀者有兩種：(a) 正在建立或修改一個 skill 的人／agent，帶著具體問題來查一節；(b) 審查別人寫的 skill 的人，把 §12 檢查清單當閘門走一遍。讀完之後的動作落在世界上（改一個 skill 的 frontmatter、拆一份檔案、重寫一段 description），但**不是照第 1 節走到第 13 節**。體例應為查表 + 判準，不是編號流程。

**體量現況（主 session 已量測）**

| 檔案 | 字元 | 對自身門檻 6,500 |
|------|------|-----------------|
| SKILL.md | 15,807 | **2.4 倍** |
| references/patterns-and-troubleshooting.md | 6,513 | 1.0 倍（微幅超標） |
| references/seeing-like-an-agent.md | 3,974 | 通過 |
| references/splitting-an-existing-skill.md | 2,288 | 通過 |

SKILL.md 各節占比（已排除程式碼區塊內的偽標題）：核心心法 15.3%、Description 寫作 14.9%、Body 寫作 18.4%、YAML Frontmatter 7.4%、Skill 建立流程 6.7%、Claude Code 特有功能 5.5%、嚴禁清單 5.2%、Anatomy 4.8%、發布前檢查清單 4.7%、命名規則 3.6%、類型速查 3.2%、延伸閱讀 2.8%、安全考量 1.7%、開場 5.8%。

**這份文件的特殊性**

它規範「skill 該長什麼樣」，因此違反自身條文的成本高於一般 skill——引用它的人會照它的形狀做。它自己已違反自己的第 2 層預算 2.4 倍。§6.4 末段有一句自陳「**寫完條文與用條文掃過自己是兩個動作**」，可作為自審 frame 的錨點。

**本次新增而未經審查的內容**

v1.4.0 新增 §6.5 與 `references/splitting-an-existing-skill.md`，內容提煉自一次拆分的實測失誤，**寫的人與審的人相同**，尚未經任何外部 frame。該 reference 的主張（位元搬移正確不等於拆分後可用、四類必查、兩類高頻缺陷、檔頭三段式、路由表涵蓋章節欄、收尾兩步）皆為單一案例歸納，需驗其可泛化性。

**主 session 已發現的一項（不需重報，供參）**

§6.1 的推薦骨架在 ```` ``` ```` 程式碼區塊內使用 `## ` 標題，共 5 處（L259／263／267／271／430）。任何以 `^## ` 解析章節的工具都會把它們誤讀為本文件的章節——主 session 第一次量測即中招。

**用戶指定的兩個評估項（除一般 finding 外必須回答）**

1. **是否需要補範例**：哪些節的判準給了而範例沒給、或範例不足以校準粒度。
2. **若要拆該怎麼切**：切分點、每塊的「何時讀」、以及切完 SKILL.md 該留什麼。

**共通產出契約（所有 reviewer 適用）**
