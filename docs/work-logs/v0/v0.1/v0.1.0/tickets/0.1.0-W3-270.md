### Rationale Chain
- 0.1.0-W3-207 why: `0.1.0-W3-184` 第三節裁定協調形態為**單一仲裁點而非分散式協商**：各 domain 不互相確認，改為向注意力通道的持有者請求，由後者依級別規則裁決。

**為何不能讓 domain 互相確認**：注意力競爭發生在任何兩個會產生注意力請求的 domain 之間、不分層級（協調圖與 `docs/domain-map.md` §2 的依賴圖正交），因此互相確認需要 N² 條協調邊，且迫使 domain 互相知道彼此存在——直接違反 §3 Bundle 界定表的公開面設計。仲裁只需 N 條，且 domain 之間維持互不知情。

**不做則後果**：`0.1.0-W3-204` 的級別規則會停在單一載體內（`AppSnackBar`），跨 domain 的請求仍各自直達載體，「現在是不是請求使用者注意的適當時機」沒有任何地方在回答。
