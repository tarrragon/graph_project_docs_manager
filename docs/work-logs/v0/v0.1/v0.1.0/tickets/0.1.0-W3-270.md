### 兩處分歧的判定

票面 how 要求「不預設答案」，兩處各自判定如下。**兩處皆判為 §2.17 需修訂，但理由完全不同**——(A) 是規格自己委派出去的決定被受託方做了，(B) 是規格的論證前提用錯條件。

### (A) 請求識別產生方：規格的暫行描述被自身委派的決定覆寫

| 面向 | §2.17 原文 | 實作（`attention_arbiter.dart`） |
|---|---|---|
| 型別 | process 內單調遞增整數 | `final String id` |
| 產生方 | 仲裁點受理當下產生 | 請求方於標定點填入，仲裁器只讀取不推導 |
| 與載體識別的關係 | 不同計數空間，另需關聯機制 | 同一個值 |

三個面向全不同，不是同一件事的兩種說法，故排除「不同觀測點的對應關係」這個可能。

**判定為規格修訂而非實作偏離，依據在規格自身**：SPEC-003 v1.20 的變更歷程明寫「具體關聯機制留待 `0.1.0-W3-207` Phase 1 設計，本票不代為決定」。§2.17 既然把該機制委派出去，其欄位表當時填的「不同計數空間 + 整數計數器」就是待覆寫的暫行描述，不是被違反的規格條文。受託方 Phase 1 的決定是共用單一識別（與載體端配對識別同源），該決定已落地。規格對齊之，`0.1.0-W3-176` D1 的計數器先例不再適用於本欄位。

### (B) 決策值域：兩組值確為不同觀測點，但「拒絕不使用」的斷言為假

**結構層面票面假設成立**：§2.17 的五值是請求方視角結局（判準 T／T1 判否三承接），實作的四值是仲裁層動作。同一次請求在兩處各有一個值，非同一集合的兩種切法。已補〈兩個觀測點的決策值對應〉表逐條映射。

**但「拒絕不使用」這個斷言必須推翻，且其論證有明確的斷點**：

- 原論證：「拒絕是等待型在**通道飽和**時的動作」→ 引 §2.16「本通道無佇列滯留」→ 故無成立條件。
- 實作的拒絕條件：`holderLevel` 嚴格高於請求級別（`request()` 步驟 4 的 `waiting` 分支），**與佇列深度無關**。
- 斷點：原論證把「通道飽和」與「通道被更高級別佔用」當成同一狀態。後者在佇列深度恆為 0 或 1 之下完全可以成立，§2.16 的結論對它沒有排除力。

**可達性以規格自身的表佐證，非理論情形**：§2.17 九格表已列「自發型×不可棄」（§2.14 列 11–13）與「等待型×可棄」（列 5–10）皆有實例。前者持有通道而後者到達時，三條讓步規則第三條使該請求不能搶佔，仲裁層動作即為拒絕。

**原論證的第二個斷點**：「使用者正在看著畫面」（T1 判是）回答的是「這則訊息值不值得呈現」，與「這次請求能不能取得已被更高級別佔用的通道」是兩個問題。T1 恆判是不推出恆不被拒絕。

### 票面 why 對分歧規模的低估

票面述「`Rejected` 實際被使用（空 id 驗證即回傳它）」。實測 `AttentionRejected` 有三個回傳點：空 id 驗證、持有並等待（協定違規）、**等待型被更高級別持有**。第三個是實質仲裁結局，正是 §2.17 斷言不存在的那一種；若只依票面所述的空 id 一項處置，會得出「拒絕僅用於錯誤路徑、仲裁層仍不使用」的錯誤結論，§2.17 的斷言會被保留。

### acceptance 第 3 條的判定：無需停手回報

該條要求「判定實作偏離規格原始意圖者停手回報 PM」。兩處皆判定為規格側問題，不觸發該條：

- (A)：規格自己委派，受託方依委派決定，非偏離。
- (B)：實作的行為（可棄等待型不得搶佔不可棄持有者）正是三條讓步規則第三條的要求，符合規格的原始意圖；偏離意圖的是 §2.17 那段論證本身。

本票執行者為 PM，未修改 `lib/` 任何檔案。
