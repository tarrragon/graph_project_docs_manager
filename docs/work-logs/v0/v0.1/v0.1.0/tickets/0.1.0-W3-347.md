## Problem Analysis
### 問題根因

domain-map 有兩處缺口阻擋 FlowStep traverses 回填：

1. **貫穿數計算歸屬未定**：§2.5 定義「貫穿」詞義（一條 UC flow 經過某個 domain），但未指定由哪個 domain 計算這個數值。UC-02 步驟 read-traversal-count 的 traverses 無法判定。
2. **路徑模式→domain 對照表不存在**：PROP-004 的「以 ticket 切入」模式需用 where.files 反查 domain，但 domain-map 全篇以「唯一變更理由」定義 domain，無任何 domain 標註涵蓋哪些路徑（§9 已明列此待決項）。UC-02 步驟 enter-from-ticket 的 traverses 無法判定。

### 影響範圍

- UC-02 的 read-traversal-count 與 enter-from-ticket 兩步直接受阻
- UC-02 驗收條件第 1 條（矩陣格的三態判定）依賴貫穿數計算
- PROP-004 的「ticket 無法定位」例外場景依賴對照表
- W3-345 的 22 步中，此兩處是 domain-map 本身的缺口（非 traverses 欄位形狀問題）

### 相關 Error Pattern

無直接相關的已知錯誤模式。

## Solution
### 缺口一：貫穿數由哪個 domain 計算

### 問題定位

UC-02 步驟 read-traversal-count 描述「該列的小計欄顯示被幾條 UC flow 直接貫穿」。貫穿數的計算需要：(1) 取得所有 FlowStep 的 traverses 清單，(2) 對指定 domain 計數。

§2.5 定義「貫穿」是圖上的水平關係，可計數。§3 Graph 公開面列「輕節點、邊、鄰接查詢」，§3 Layout 公開面列「泳道／矩陣的座標與尺寸」。貫穿數不在任何 domain 的公開面中。

### 候選方案

| 方案 | 計算者 | 依據 | 利 | 弊 |
|------|--------|------|-----|-----|
| A | Graph | FlowStep 是 Corpus 解析產物投影到 Graph 的輕節點之一；traverses 是 FlowStep 的欄位；計數是對圖上節點欄位的聚合查詢，屬圖語意 | 與 §2 依賴方向一致（Layout → Graph）；鄰接查詢已在 Graph 公開面，貫穿數可視為同類查詢 | 需將「鄰接查詢」泛化為「圖上的聚合查詢」；Graph 的變更理由從「圖語意」擴展到「統計」 |
| B | Layout | 矩陣的格值即為貫穿數；Layout 已負責「座標與尺寸」，貫穿數是格的內容值 | 矩陣呈現與計算同源，不需跨 domain 取值 | 違反 §2 依賴方向：Layout 需直接讀 FlowStep（Corpus 產物），但 §2 Layout 只依賴 Graph，不依賴 Corpus |
| C | 不歸任何 domain，由 L4 畫面狀態層計算 | 貫穿數是視圖的呈現需求，非業務邏輯 | 不擴展任何 domain 的責任 | §2 明寫「畫面狀態不是 domain，是 layer」——把計算放在 layer 使其不可獨立測試（與 §5「Graph 的票不得依賴 UI」精神矛盾） |

**建議**：方案 A 最符合現有架構。理由：(1) 依賴方向 Layout → Graph 已存在且正確；(2) FlowStep traverses 經 Corpus 解析後投影到 Graph，Graph 對其欄位做聚合屬純函式查詢；(3) 不新增依賴邊。

### 缺口二：路徑模式→domain 對照表

### 問題定位

PROP-004 §採用方案明寫：「以 where.files 反查涵蓋的 domain 並高亮」，並自注「這條推導成立的前提是先建立路徑模式→domain 對照表。該表尚未建立」。

domain-map §9 待決項亦明列：「路徑模式→domain 對照表不存在。PROP-004 的以 ticket 切入模式要求用 where.files 反查 domain，並指名對照本檔推導；但本檔全篇以唯一變更理由定義 domain，未標註任何 domain 涵蓋哪些路徑。」

### 候選方案

| 方案 | 載體 | 維護方 | 利 | 弊 |
|------|------|--------|-----|-----|
| D | domain-map §3 每個 domain 新增「涵蓋路徑模式」欄 | 人工維護，隨 domain 增減更新 | 與 domain 定義同源、讀者一處可見 | 本專案 lib/ 目前僅 main.dart、l10n/、workspace/，分層命名未定（PROP-004 已指出），表太早建會全改 |
| E | 獨立對照表檔案（如 docs/path-domain-mapping.yaml） | 人工維護 | 可獨立版控、不膨脹 domain-map | 多一份需同步的文件 |
| F | 延後至 lib/ 分層命名定案後再建 | 無（延後） | 避免建表後全改 | UC-02 enter-from-ticket 與「ticket 無法定位」判定在表建立前不可實作 |

**關鍵事實**：本專案 lib/ 目前只有三個目錄（main.dart、l10n/、workspace/），離八個 domain 各有對應路徑的狀態很遠。對照表的實際內容取決於 lib/ 的分層命名決策，而該決策尚未做。

**建議**：方案 F（延後）最務實，但必須綁定 trigger——建立一張追蹤票「lib/ 分層命名定案後建立路徑→domain 對照表」，並將 UC-02 enter-from-ticket 與 PROP-004「ticket 無法定位」標為依賴此表。這不是無 trigger 延後：trigger 是 lib/ 分層命名定案票。

### 裁決題

### 裁決題一：貫穿數計算歸屬

**問題**：UC-02 矩陣的「被幾條 UC flow 貫穿」這個數值，由哪個 domain 計算？

| 選項 | 後果 |
|------|------|
| A. Graph（建議） | Graph 公開面新增「聚合查詢」能力（貫穿數）；Layout 從 Graph 取值呈現；依賴方向不變（Layout → Graph）；read-traversal-count traverses = [Graph] |
| B. Layout | 需新增依賴邊 Layout → Corpus（違反 §2 現有 DAG），或 Layout 間接經 Graph 取 FlowStep（等同方案 A 但多一層）；read-traversal-count traverses = [Layout] |
| C. L4 畫面層 | 不歸任何 domain；read-traversal-count traverses = []；計算不可獨立測試 |

### 裁決題二：路徑模式→domain 對照表時機

**問題**：UC-02 enter-from-ticket 需要「where.files → domain」反查。本專案 lib/ 目前僅 main.dart / l10n/ / workspace/，分層命名未定。何時建表？

| 選項 | 後果 |
|------|------|
| F. 延後至 lib/ 分層命名定案後（建議） | 建追蹤票綁定 trigger；enter-from-ticket traverses 暫定 [Graph, TicketDetail]（取 ticket 資訊 + 圖查詢）；「ticket 無法定位」例外場景在表建立前不可實作但可先寫入 UC-02 |
| D. 現在在 domain-map §3 加路徑欄 | 可立即判定 enter-from-ticket，但表內容在 lib/ 分層命名定案後大概率全改 |
| E. 建獨立 YAML 對照表 | 同 D，只是載體不同 |
