### 問題根因

範例撰寫者在校準分歧時，把「條文沒寫、但判定需要」的判準直接寫進【產出】理由欄或【驗證】預期答案，未回寫條文。三段鏈式規格（skill-design-guide chained-examples）只要求驗證段引用【產出】段已定義的欄位，沒有要求判準須在所校準條文中找到依據句，故撰寫與審查皆無機械關卡。

### 影響範圍

- 已驗證：99 則範例中 34 則有可指認的藏判準或與條文衝突（明細見 Solution）；其中 10 則為 Critical（範例結論與條文字面相反，或範例自身【產出】與【驗證】互相矛盾）。
- 未驗證：本稽核以範例所在檔與其直接路由的權威檔（方法論未逐一展開）核對；component-library 範例若依據在 component-library-bidirectional-constraint-methodology 內而範本未轉述，本表會列為「範本缺條文」，修補時可能改為補路由而非補條文。

### 相關 Error Pattern

W3-335.28 承接「驗證段判準必須能在條文找到依據句」的 error-pattern 與機械檢查，本稽核不重複記錄。
