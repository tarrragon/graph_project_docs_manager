# Execution Log

## Task Summary

稽核 本輪新增與改寫的範例是否把條文沒有的判準藏進範例

---

## Problem Analysis
### 問題根因

範例撰寫者在校準分歧時，把「條文沒寫、但判定需要」的判準直接寫進【產出】理由欄或【驗證】預期答案，未回寫條文。三段鏈式規格只要求驗證段引用【產出】段已定義的欄位，未要求判準須在所校準條文中找到依據句，撰寫與審查皆無關卡攔截。

### 影響範圍

- 已驗證：99 則範例中 58 則有藏判準或與條文衝突（新發現 56 則、已承接 2 則）；新發現中 Critical 11 則（範例結論與條文字面相反，或範例自身前後矛盾）。明細見 Solution。
- 未驗證：component-library 範例的判準可能存在於 component-library-bidirectional-constraint-methodology 而範本未轉述；本表列為「範本缺條文」，修補時可能改為補路由。

### 相關 Error Pattern

W3-335.28 承接「驗證段判準必須能在條文找到依據句」的 error-pattern 與機械檢查，本稽核不重複記錄。

## 重現實驗結果
### 實驗方法

1. 範圍取得：以 grep 掃 where.files 各路徑的驗證段起始行（`【驗證】`／`驗證（`／`驗證：`），再以 `git blame` 將每個驗證段回溯到引入 commit，只保留 W3-335 子票（.3/.5/.7/.10/.12/.20/.21/.25）或其後重切拆檔搬移的範例。
2. 逐則核對：讀【產出】理由與【驗證】每個 Q／Then 句，在同檔條文與其直接路由的權威檔（範本本文、step 檔共用規則、completeness-criteria、layered-test-strategy）搜尋依據句。
