### 合併或分立的判斷

**判定：合併為一則，含三個變體。** 編號 `DOC-GPD-010`。

三者共享同一個根因，且該根因可寫成一句涵蓋三者的主張：條文要生效，讀者與條文之間需要一個到達事件；三個變體各自缺了到達事件的一個必要條件。

| 變體 | 來源 | 缺的必要條件 |
|------|------|------------|
| A 位置在程序之外 | 規範文字放在讀者執行的程序之外時零效力 | 步號（不在程序上） |
| B 表內取到可填的值即停止 | 判定表把終值託付給表外段落 | 優先權（更早的一格先給了值） |
| C 新增定義款使既有款次前提恆空 | 誤傷分析往回看、可達性分析往前看 | 可達性（前提恆空） |

支持合併的三項理由：

1. **B 是 A 的實例，不是平行議題。** A 的五個同形實例清單中，第二例逐字就是 B 的內容（讀者在表內取到可填的值就停止，表外段落不被當作取值來源）。拆為兩則會使同一份讀數在兩個檔案裡各出現一次，且兩檔互為對方的實例。
2. **共同的強證據只需寫一次。** 位置判準的可證偽檢驗（條文由段落移入編號程序後取用率 0/3 升為 3/3，證偽條件未觸發）與其射程限制（同一編號單位內末句仍會掉，6/6 引用而末句 1/6 抄出）對三個變體同時適用。分立三則會讓同一組證據重複三次，或散落而任一則都不完整。
3. **關聯本身就是內容。** 三者的防護是同一個問題問在三個時點——「這一條，讀者會走到嗎？」——差別只在走不到的原因。分立會遺失這層結構。

曾考慮把 C 獨立成則，理由是其失效機制與 A、B 不同軸：A、B 的成因在讀者的注意力與省力路徑，C 是邏輯上的不可達，對逐字讀完全文的讀者同樣不可達。最終仍合併，並在檔內明寫這項軸差異，因為 C 的偵測與防護（增列定義款後往回看與往前看兩道檢查）在讀者不到達這個共同框架下才說得清楚它為何容易被漏——往回看的失敗有可觀測訊號（既有答案翻面），往前看沒有。
