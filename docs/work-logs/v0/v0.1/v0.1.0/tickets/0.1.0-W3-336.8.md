### G26：非近似值時加階判準（不改檔，草稿供 WRAP／PM 裁決）

**位置**：`references/spacing-system.md`〈Migration Guide〉〈Non-Standard Values〉表。

**現狀**：四列（`10`、`14`、`20`、`28`）各列兩個候選階，以「或」並列，無取捨規則；同表另外兩列（`6`、`18`）只給單一候選。

**是否改變既有判定**：會。四個有「或」的值目前讀者可以選任一候選都不算違反文件；一旦定出 tie-break 規則，其中一個候選會變成不合規的選擇。這正是母票與本票「新增判準會改變既有判定」的情形，不自行選邊。

**候選方向**：
- 方向 A（就近取整，相等距離時取較大階）：`10`→`sm(12)`、`14`→`md(16)`、`20`→`lg(24)`、`28`→`xl(32)`。理由：間距不足比間距過多更常導致視覺擁擠或誤觸；但屬工程判斷取捨，非唯一正確答案。
- 方向 B（就近取整，相等距離時取較小階）：`10`→`xs(8)`、`14`→`sm(12)`、`20`→`md(16)`、`28`→`lg(24)`。理由：避免不必要地放大版面密度；同樣是取捨，非必然。
- 方向 C（不裁定固定方向，改為「達到門檻次數即提案加一階」）：沿用兩候選並列，但補一句「同一模糊值在同一畫面／元件庫內重複出現達 N 次，視為證據支持新增一階，走 foundation-design 提案，不在此處強制二選一」。此方向不產生「哪個候選不合規」的既定答案，改為量化門檻觸發加階流程；門檻次數 N 待另定。

**理由**：三個方向對「模糊值該讓步給哪一階」的價值判斷不同（方向 A/B 是二選一裁決，方向 C 是流程性延後裁決），無法從既有文件或本專案程式碼（`lib/tokens/spacing.dart` 用的是完全不同的六階數值 2/4/8/12/16/20，不含本表數值，無法反查）推得何者為既定慣例。

**是否屬用戶程式碼風格偏好**：否——這是 dart-style-guardian 作為跨專案通用資產的抽象間距判準，不牽涉本專案實際程式碼寫法；依母票裁示「不涉用戶程式碼風格偏好者，改由獨立評估者跑 WRAP」處理，不需上呈用戶本人。

**改後文字草稿（若採方向 A，其餘方向替換對應階名）**：

於〈Non-Standard Values〉表後補一段：「四捨五入的方向：與相鄰兩階距離相等時，取較大的一階（原則：間距不足比間距過多更常造成視覺擁擠或誤觸風險）。距離不相等時一律取距離較近的一階，不受此規則影響。」並將表中四個「或」列改寫為單一候選（`10`→`sm(12)`、`14`→`md(16)`、`20`→`lg(24)`、`28`→`xl(32)`）。
