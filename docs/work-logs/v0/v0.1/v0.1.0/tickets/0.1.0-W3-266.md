why: '`--no-topic` 的說明是「明示本票不指派主題」，但實測**在自動推導成功時完全不生效**。


  **最小重現**：`0.1.0-W3-265` 建立時傳入 `--no-topic` 且帶 `--source-ticket 0.1.0-W3-264`，輸出為「依 S1 上游繼承（source_ticket=…） 自動指派主題：0.1 App 地基」，`topic-assignments.txt` 第 384 行確有該筆。同批未傳 `--no-topic` 的 `0.1.0-W3-264` 得到完全相同的結果——**傳與不傳無差別**。


  **根因在回傳值無法表達意圖**：`lib/topic_inference.py` 的 `resolve_topic_arg` 在只給 `--no-topic` 時走到最後一行 `return None, None, None`，與「使用者什麼都沒指定」的回傳完全相同。呼叫端拿到 `None` 即往下執行 S1／S2 自動推導。`commands/create.py:955` 的 `elif getattr(args, "no_topic", False)` 分支只在 `topic` 為假時可達，也就是自動推導本來就失敗的情況——那時不指派本來就是預設行為。**旗標只在它不改變任何結果的情境下生效。**


  **為何測試全綠**：`test_no_topic_writes_no_assignment` 以 `_make_args(no_topic=True)` 呼叫，該 fixture 不帶 `source_ticket`，走不到 S1 繼承路徑。測試覆蓋的是「推導失敗時 no_topic 也不指派」，而那條路徑上 `no_topic` 為真或為假結果相同。測試是真的，「旗標有效」這層關係是假的。


  **後果**：主題中央清單的漂移無法被操作者阻止。S1 繼承不看內容——上游主題指派錯一次，全部下游繼承該錯誤；`--no-topic` 本是唯一的人工出口，而它在需要它的時候不作用。已觀測的漂移實例見 `0.1.0-W3-265` 的 why（`框架 skill 撰寫` 群含純專案票、`0.1 App 地基` 群含純框架票）。輸出訊息也不揭露覆蓋——它只說「依 S1 自動指派」，不說「你傳的 --no-topic 被忽略了」。'
