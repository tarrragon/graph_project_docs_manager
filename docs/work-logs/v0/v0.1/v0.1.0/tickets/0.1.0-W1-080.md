## Problem Analysis
<!-- Schema[IMP/Problem Analysis]: 選填（小型 IMP 可留 placeholder；大型 IMP 建議填寫）（.claude/pm-rules/ticket-body-schema.md） -->
### 問題根因

比對本票 how 欄與 SPEC-004 §4.35「slot 契約」「狀態矩陣」located 列、§4.0.10 場景 (d) 三處，內容一致，無需修正。

實測確認：`isLocated` 欄位已存在於 `AppTableRow` 私有建構式（`isLocated = false` 具名參數）並用於渲染（`build()` 內 `DecoratedBox` 底色、`eventFlow` 分支 `Semantics.focusable`）；`.eventFlow` 工廠已轉發；唯獨 `.ticket` 工廠未暴露該參數，實測 `dart analyze` 命中 `undefined_named_parameter`（W3-640 因此在 `_ticketRow` 留下 NOTE 標記停手）。

### 影響範圍

`lib/components/app_table_row.dart`（`.ticket` 具名建構式）、`lib/screens/ticket_list/ticket_list_screen.dart`（`_ticketRow`、`_ReadyListView`、`_ReadyTopicView`、`_TopicSection`）。

### 相關 Error Pattern

無直接對應；性質為既有欄位漏轉發，非新設計問題。

## Solution
<!-- Schema[IMP/Solution]: 選填（.claude/pm-rules/ticket-body-schema.md） -->
### 修復方式

1. `AppTableRow.ticket` 具名建構式新增 `bool isLocated = false` 並轉發至私有建構式（比照 `.eventFlow` 既有寫法）；更新欄位與建構式文件註解。
2. `ticket_list_screen.dart`：`_ticketRow` 新增 `String? targetId` 參數，`isLocated: targetId != null && targetId == ticket.id`；`_ReadyListView`（列表模式）與 `_ReadyTopicView` → `_TopicSection`（主題模式）皆將 `state.targetTicketId` 傳入，兩種呈現模式共用同一高亮邏輯。移除 W3-640 遺留的 `NOTE(0.1.0-W3-640 NeedsContext)` 標記。
3. 範圍邊界：主題節收合時的自動展開（SPEC-004 §4.0.10 場景 d 提及的例外「所在主題節收合時由頁面層先展開」）未在本票實作——現況盤點確認專案內無任何 `先展開`/`autoExpand` 相關程式碼，且本票 how 欄未提及此需求，屬另一件工作；若後續需要，應另開票，不在本票 Solution 逕自擴大範圍。

### 0.1.0-W3-640 acceptance 第 2 項核對結果

W3-640 acceptance 第 2 項原文：「目標列定位高亮的承接票 0.1.0-W1-080 已建立並掛雙向血緣（射程需元件庫 slot，超出本票範圍邊界，依 0.1.0-W3-642 的撰寫原則收窄）」——該項驗收標的是「承接票已建立並掛雙向血緣」，非「高亮已實作」，故 W3-640 於建立本票（`source_ticket: 0.1.0-W1-080`）時已達成，狀態維持 `[x]` 不需改動。本票完成後，W3-640 NeedsContext 章節所述「`isLocated` 參數暫不接入」的技術缺口已由本票補齊（見 lib/components/app_table_row.dart .ticket 工廠）。
