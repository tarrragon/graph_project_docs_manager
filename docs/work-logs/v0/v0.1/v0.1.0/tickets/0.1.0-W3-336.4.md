### 問題根因

C10、X3、X4 為 W3-332 審查發現的 version-bootstrap 原文矛盾與計數過期（詳見來源審查子票 Solution）。

### 分類判斷：C10 為何直接改而非走矛盾裁決流程

母票 0.1.0-W3-336.1（foundation-design 矛盾統一）的 C08／C09 兩則原文矛盾走「提草稿、不改檔、needs_context 停手」流程，因為兩者是兩種設計意圖互斥、無外部依據可裁決對錯。C10 不同：`component-contract-design/SKILL.md`〈與 version-bootstrap 交界〉一節已自述「本 skill 落在第三塊之後、第四塊之前」——即元件契約不計入「四塊」。這已是可查證的既有事實，不是需要新判斷的設計選擇；version-bootstrap 一側的「表列五列／動作句四塊／Checkpoint 只驗四塊」矛盾，答案已由對方 skill 的自述文字唯一決定。本票 acceptance 對 C10 的措辭也是直接描述目標終態（非「提出建議並經簽核」），與 336.1 對 C08／C09 的措辭不同，判斷為屬「字面不一致，可直接改」，不進入需裁決流程。

### 附帶發現：票面標題含 X6，但 X6 不屬本票範圍

本票標題「修補 version-bootstrap 的原文矛盾與計數過期（C10、X3、X4、X6）」列了 X6，但查證 W3-332.7 Solution：X6 原文為「foundation-design/SKILL.md〈工作流〉步驟 3 vs〈權威缺席時〉形態 2　兩條互指（F9）」——內容完全在 foundation-design/SKILL.md，與 version-bootstrap 無關；且該缺口已被 W3-332.13 彙整為 G35，指派給 0.1.0-W3-336.2（foundation-design 缺引導）acceptance 第 2 項「工作流步驟 3 與權威缺席形態 2 的互相指向加上終止條件」。本票 acceptance 三項亦不含 X6。判定：X6 為建票時標題沿用草稿列表的殘留（草稿 R04 行原列「C10, .7 X1-X4,X6」，P7 修正僅移出 X1，未移出同屬 foundation-design 的 X2、X6；X2 已在 336.1 正確歸位，X6 未歸位但已由 336.2 acceptance 承接，未造成缺口遺漏）。本票 where.files 不含 foundation-design 檔案，不就地修，亦不需另開 spawn request（已有承接票 336.2，非新缺口）。
