## Solution
### 結論

條文有鑑別力，但鑑別力的落點不在它自己聲稱的地方。它對「規模不構成豁免」這一軸確實有效且給出過與直覺相反的正確答案（見第三節）；對「證據狀態」這一軸則因為「消費端」一詞可兩讀而不可推翻。更根本的一項：**條文的作用面只到票的欄位，而 framework-issue 流程的終點是 issue；票被 close 之後條文的 Action 失去載體**。下列缺口分 issue 記錄，不合併。

### 一、`#103` 上的條文失效點

**失效點 1-1：三問的作用單位未定義，而真實修法是清單。**

失效句：〈原則二〉表格三列的問句皆以單一修法為主詞（「修法要改的東西」「修法若錯就會失敗」）。

實際輸入：`#103` 的第一列待辦是「模式 A 擴充涵蓋直譯器內嵌腳本（`python3 -c`／`python -c`／`node -e`／`ruby -e`）、heredoc 寫檔、`>` 與 `>>` 重導向、`awk -i inplace`、`ed`／`ex`」——六類手段，證據狀態逐類不同：三類有探針實測，兩類（`awk -i inplace`、`ed`／`ex`）只有讀原始碼推論，一類（`>` 重導向）body 自記為「該檔 docstring 明載這是刻意降級的決策」。

條文給不出答案的是：三問對這一列該回答一次還是六次。整體回答則兩個未實測項把三個已實測項一併拖進 ANA；逐項回答則條文沒有任何一句說明六個答案如何合成一個票型。

**失效點 1-2：「消費端已觀測」對同一輸入可得出相反結論，兩者都有條文支持。**

失效句：〈原則二〉表格第一列「修法要改的東西，誰讀它、在什麼條件下執行，是已觀測而非推定？」

條文自身三個檢驗案例對這句用了兩種讀法：案例一「消費端＝那兩個測試檔自身」（讀法 A，執行環境與觸發條件）；案例二「消費端＝其他 consumer 是否呼叫該工具」（讀法 B，資產的使用者群）。

實際輸入：`#103` 的四項探針實測。讀法 A 下「誰讀它、在什麼條件下執行」已被正向對照組直接觀測 → 是；讀法 B 下其他 consumer 的 Bash 使用形態完全未觀測 → 否。**同一組證據、同一句條文、相反結論，且各自可引條文中的一個案例為據。** 這使判準不可被推翻——任何結論都有支持文字。

### 二、`#92` 上的條文失效點

**失效點 2-1（最硬的一個）：條文處置與 comment-as-section 協定直接衝突，且兩份文件互不提及。**

失效句：〈擴散面〉表第二列「修法形狀移至 framework issue 區段決定，發現票降為分析票（ANA）」。

**失效點 2-2：close 動作使條文的 Action 失去載體。**

失效句：同〈原則一〉Action（對象是發現票的欄位）。

實際輸入：`#92` 最後一則觀測記載 `0.1.0-W3-005` 已 close，reason `not_executable_knowledge_captured`，理由是「body 已逐字收錄該票的 `why` 與 `how.strategy`」。也就是說：路徑 A 的 close 把修法**內容**搬進 canonical，把證據狀態的**標記**留在一張沒人再讀的 closed 票上。條文的 Action 在路徑 A 下結構性無效，而〈兩條路徑〉與〈修法時點分離〉同在一個檔案裡、相隔三行，兩節都沒提到對方。`ticket-intake.md`〈步驟五：ticket 處置〉也沒有要求 close 時檢查證據狀態。

**失效點 2-3：三分表對聚合型 issue 恆輸出「引用」，與被比較對象的內容無關。**

失效句：`comment-as-section-protocol.md` 三種關係處置表的判定依據欄——「同一問題領域、同一層級」／「同一領域、不同層級」／「僅提及，領域不同」。

實際輸入：`#92` 的「領域」是按**場合**定義的（發生在派發事件上），不是按失效機制定義的。證據是 `#92` 自己現在同時容納：輸出載體維度、合併衝突腳本、假驗收、身份死結、派發前判準的代理量脫鉤、派發驗證 hook 誤報、hook 警告輸出通道——其中最後兩項與 `#54` 第 2、3 項是同一機制（`#92` 自己的邊界表就寫了「機制同源、實例不同」）。

**對本票 acceptance 第 5 條的直接回答**：條文對「重複／切分／引用」三分**給不出可推翻的依據**。「領域」與「層級」兩個詞無定義、無操作程序，只有「讀內容不看標題」一句反面提醒。真正可推翻的判別程序在框架條文之外——`#97` body 自訂的反事實問法「把該 hook 的判定謂詞改對之後，這個徵狀還在不在？還在則屬本 issue，不在則屬 `#54`」——輸出隨事實改變，可被證偽。該問法由 consumer 在 issue 上自行發明，不在任何 skill 條文裡，因此不會傳到下一個 curator。
