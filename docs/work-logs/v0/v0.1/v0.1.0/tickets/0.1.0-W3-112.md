### Rationale Chain
- 0.1.0-W3-103 why: `0.1.0-W3-099` 驗證了元件層：22 個可互動元件的第一層回饋（互動當下的表現）全部齊備，由 Material `InkWell` 的 ripple 提供，且該回饋不依賴任何服務回應。

同時它指出元件把第二層（服務受理）與第三層（event 效果）**委派給呼叫端**——SPEC-004 的回饋契約明文寫「本元件承載三層中的點擊確認層；等待指示為畫面級／結果通知為狀態轉換本身」。委派本身是設計上正確的：元件只發 callback，不該知道服務存在。

**但「已委派」不等於「承接方有做」**，而承接方從未被驗證。本次實機驗證撞到的正是這一層——按下重新掃描之後，第二層（服務受理：toast 或 loading）與第三層（event 效果：成功／失敗結果）都沒有出現，而元件自身的 ripple 是有的。缺陷完全落在呼叫端。

因此 `ARCH-GPD-001` 在本專案的實際落點是頁面層，不是元件層。元件層盤完不代表問題盤完——那反而是最容易誤判「已檢查過」的地方，因為結論是全綠。
