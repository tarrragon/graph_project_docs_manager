## Problem Analysis
<!-- Schema[IMP/Problem Analysis]: 選填（小型 IMP 可留 placeholder；大型 IMP 建議填寫）（.claude/pm-rules/ticket-body-schema.md） -->
### 問題根因

`lib/components/list_row.dart` 的 `ListRowVariant` 只有 tree/sectionHeader/item/
meta/numbered 五變體，SPEC-004 §4.40「變體」表與 §4.41 `Section.items` slot 契約
已核定 `option`（0.1.0-W3-335.62 一致），但實作未跟進，導致 0.1.0-W2-002 無法組
UC Flow 右欄〈UC 選擇入口〉三狀態。

### 影響範圍

`lib/components/list_row.dart`（新增 `ListRow.option` 建構子、`isSelected` 欄
位）、`test/unit/components/list_row_test.dart`（矩陣測試涵蓋第六變體、新增
selected/非 selected 對照測試）。`lib/components/section.dart` 的 `items` 為
`List<Widget>`（無型別檢查），SPEC-004 §4.41 slot 契約中 `List<ListRow.option>`
不需額外程式碼變更即滿足。

### 相關 Error Pattern

無相關既有 error pattern；`test-assertion-design` 規則 E1（明示旗標需對照測
試）直接適用 `isSelected` 旗標，已依此設計測試。

## Solution
<!-- Schema[IMP/Solution]: 選填（.claude/pm-rules/ticket-body-schema.md） -->
新增 `ListRowVariant.option` 與 `ListRow.option` 建構子（`primary`／`onTap`／
`testKey` 必填，`isSelected` 選填預設 `false`）。渲染：無 leading／trailing，高
`rowHeightDense`；`isSelected: true` 時整列底色 `ColoredBox(AppColors.
surfaceIconTint)` + 主文字 `AppText(emphasis: true)`；`Semantics(button: true,
selected: isSelected)`。`_isTappableRow` 擴充納入 `option`，沿用既有 `InkWell`
點選路徑（呼叫 `onTap` 恰一次）。新增 assert：`isSelected` 僅 `option` 變體接受
（其餘變體傳入即觸發開發期斷言，對齊既有 `secondary` 限定模式）。

測試（`test/unit/components/list_row_test.dart`）：`_buildVariant` 補
`ListRowVariant.option` 分支（既有五變體矩陣測試自動涵蓋第六變體，不溢位/最長
文案/子件邊界盒等既有斷言全數沿用）；新增「option 列點選呼叫 onTap 恰一次」；
新增 selected/非 selected 底色對照測試（`test-assertion-design` E1：以
`find.byWidgetPredicate` 精準匹配 `surfaceIconTint` 色的 `ColoredBox` 計數，避開
`pumpHarness` 背景亦有 `ColoredBox` 的干擾）；新增 `Semantics.selected` 隨
`isSelected` 對照測試（`flagsCollection.isSelected` 回傳 `dart:ui` 的
`Tristate` 非 `bool`，改以 `Tristate.isTrue`／`Tristate.isFalse` 斷言）。

`lib/components/section.dart` 的 `items` 為未型別化 `List<Widget>`，
SPEC-004 §4.41 `List<ListRow.option>` slot 契約不需額外程式碼即滿足，範圍內未
修改該檔（票面約束：只改 `lib/components/` 與 `test/unit/components/`，消費端
UC Flow 由 0.1.0-W2-010 承接）。

### 自檢結果

Phase 4 結論：本次為既有元件的變體擴充，沿用既有渲染／語意分支模式（與
`sectionHeader` 的 `_buildPrimary` 覆寫模式一致），無新增重複邏輯或壞味道。
程式碼品質：A。重構需要：否。技術債務：無新增。
