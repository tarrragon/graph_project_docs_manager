## Solution
<!-- Schema[IMP/Solution]: 選填（.claude/pm-rules/ticket-body-schema.md） -->
**修法三處，全在 `section_comment.py`：**

1. `_find_index_heading_above`（新增）取代原本內嵌的標題偵測。原邏輯只往上看一格、最多容許一個空行，標題與表格之間夾了導言即找不到標題；改為由表格頂端往上掃到同名標題為止，遇另一個 `## ` 標題（別的章節）才中止。找到後連同標題與其間的導言一併自原處移除。
2. `extract_index_preamble` + `_preamble_until_table`（新增）取出索引標題與表頭之間的導言。兩個來源合流於同一函式：手寫索引的導言於首次併入時遷移，已在標記區塊內的導言於每次重渲染時回讀。掃描時遇 `## ` 或 `INDEX_END` 即判定該標題底下沒有表格（例如修法前殘留的孤兒標題），續掃下一個同名標題。
3. `render_index_table(rows, preamble="")` 接受導言參數，渲染於標題與表頭之間。`cmd_init`／`cmd_add` 在 strip 之前先 `extract_index_preamble(body)`，再把導言傳回渲染。

**回讀是必要的，不是保險**：`upsert_section` 對標記區塊是整段替換。導言若只在遷移當次寫入而不回讀重渲染，第二次 `add` 就會靜默抹除它——與本票在抱怨的缺陷同族（操作成功、驗證通過、被承諾的東西沒了）。第三個測試 `test_add_preserves_migrated_preamble_on_subsequent_add` 專門守這個方向：它的鑑別力來自「跑第二次」，只驗第一次的測試對此完全不會翻紅（即 `test-assertion-design-rules` 規則 E2 的正向對照輸入，該規則於同批 `0.1.0-W3-268` 落地）。

**配方與協定同步**（`skill-cli-sync-check` 規則：命令副作用變更屬行為變更）：
- `ticket-intake.md` 步驟二第三列的「不再產生第二張索引表」射程只到表格列，改寫為「整塊處理手寫索引（標題＋導言＋表格）……故標題與表格各只留一份」。
- `comment-as-section-protocol.md` 的索引表格式補一段：導言的存放位置（標題與表頭之間）與回讀約定，附 `#82` 的後果作為反例。
- SKILL.md `metadata.version` 2.3.0 -> 2.4.0，CHANGELOG 同步。

**Phase 4 重構評估**：

**未處理（已建票）**：存量孤兒標題掃描 -> `0.1.0-W3-274`。修法後執行任一次 `add`／`init` 不會自動修復存量——`_strip_raw_index_rows` 在 body 已含 `section-index` 標記時提前返回，孤兒標題不在其射程內。
