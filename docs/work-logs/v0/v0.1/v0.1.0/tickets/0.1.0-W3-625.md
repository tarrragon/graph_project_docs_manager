## Solution
### 一、Step 1：規格層兩項的逐字改動（`probe-authoring-spec.md` 1.4.0 → 1.5.0）

#### 1.1 外部驗證的 brief 分兩階段交付（1.7 新增小節）

處置須同時滿足兩件事——遮蔽推導者不得先看到被遮字、登載項仍須事先定稿可複核。採「改交付順序」而非「請他先不要看」：

| 階段 | 交付物 | 不得含 |
|---|---|---|
| 階段 0（遮蔽推導） | 遮蔽後節錄、題目檔、計分欄中標為「結論內容」的條件、受測款次編號（僅編號）、三格判讀定義、關鍵可見字回報要求 | 三個登載項逐字、遮蔽 span 原文、計分欄中標為「依據句」的條件、三輪作答 |
| 階段 1 | 未遮節錄、三個登載項逐字、來源 (b) 改前改後對照、計分欄全文、已對帳的豁免清單、分區複核一句、粒度敏感度一句、零覆蓋回報欄、三輪作答 | — |

配套三項：階段 1 於階段 0 回報後才交付且兩次時點留痕；**防倒灌**（階段 0 判讀一經回報即定稿，改變判讀者另記「階段 1 追記」並依裁決力取較嚴的一邊）；分區複核與粒度敏感度兩句隨輸入移到階段 1。另明寫**計分欄的結論內容條件必然透露正解實質，不列為洩漏**——本關的判讀就是拿結論去對照計分欄，且兩側條件相同，要隔離的是受測款次的原文而非正解的實質。

**Why（為什麼不是請他先不要看）**：brief 是一份文字，讀取順序不可複核；改交付順序把保證移到派發者的動作上，第二人以兩份 brief 的內容差即可複核。§7 第 24 項因此改寫為兩階段的內容判準（遮蔽 span 整句對階段 0 brief 出現數須為 0，另以 `MIN_LEN` 視窗比對並逐則登記），並新增第 28 項（結案前：兩階段時序留痕、階段 0 判讀未被改寫）。

#### 1.2 雙向對帳表補第三條出路（1.7，新增「改前推導」作為機械分流）

**改前推導**：以該條改動的改前文本取代改後文本（其餘條文一字不動），推一次本題計分欄中標為「結論內容」的條件。改前推得出＝該改動未引入原本推不出的判定；改前推不出＝該改動確有新增內容。這是（丙）類定義的機械測試，判別依據因此不是執行者對自己的改動有沒有內容的判斷。

同向紅那一個方向因此由一列拆為兩列：改前推得出者走原出路（改寫該條改動或改標（丙）接受零覆蓋）；改前推不出者**保留 Step 1 的類別**，成因判為「本題的受測步驟與其餘既有條文在該題材上結論重合——題目選錯」，處置是依〈同向紅燈的處置〉表改題、該題不列覆蓋題並回填零覆蓋清單、重出題另跑本關。〈同向紅的成因分辨〉第三格與 §7 第 21e 項同步改寫。
