  **現有機制為何擋不住**：`dispatch-validate` 的五條規則檢查 Context Bundle、檔案存在、acceptance 項數與內容、UC 對齊——**沒有一條看 `who`**。派發後才失敗的成本是一次無效派發加一次改派，而若 PM 未逐票覆核，代理人會在 claim 之後才卡住，ticket 停在 `in_progress` 需要 release。


  **判準是可機械檢查的**：從 `.claude/agents/<who>.md` 的 frontmatter 讀 `tools`，與票的產出性質比對。產出性質的來源可用 `where.files`（有檔案清單即需寫入能力）或 `type`（DOC／IMP 需寫入，ANA 可能只讀）。'
