## Problem Analysis
<!-- Schema[DOC/Problem Analysis]: 選填（若 DOC 起因於缺陷或盤點結論可填）（.claude/pm-rules/ticket-body-schema.md） -->
### 問題根因

父票 0.1.0-W3-099 盤點發現：SPEC-004 既有元件條目的回饋契約語意正確、格式落後——
「等待與結果」列以散文「本元件承載三層中的點擊確認層」表述掛載點，未顯式標欄；
且僅寫成功結局，未依方法論〈失敗路徑覆蓋〉四段呈現；等待期政策（服務類型／
輸入阻擋範圍／重複觸發防護）尚未標註（SPEC-003 §2.12 於 0.1.0-W3-108 落地）。

### 影響範圍

docs/spec/ui/SPEC-004-component-library.md §4.1–4.7（AppText 至 NavItem）。
逐條目盤點：

- 4.1 AppText／4.2 AppIcon／4.3 Divider／4.5 Badge：純顯示、零互動層級，
  回饋契約已以「不適用（六類事件全部）」單列涵蓋六類事件並附理由，本身
  即為顯式掛載點呈現（無層級可掛），判定不需改動
- 4.4 AppButton：互動元件，但泛用於全部四種服務類型（依 onPressed 掛的
  動作而定），第一層本身不隨服務類型變動（SPEC-003 §2.12 明文）；「等待
  與結果」列需展開
- 4.6 IssueMarker／4.7 NavItem：互動元件，皆為本地導覽切換（jump／rail
  切換），服務類型定為「本地即時」（SPEC-003 §2.12 表中 0.1 實例明列
  「導覽切換」）；「等待與結果」列需展開

### 相關 Error Pattern

無新增；沿用父票引用的 ARCH-GPD-001（掛載點錯置案例）與 DOC-005（跨文件
原則失步）。
