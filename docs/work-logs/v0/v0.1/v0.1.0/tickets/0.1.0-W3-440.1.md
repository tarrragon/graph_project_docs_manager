### F-02：全域狀態清單「可拆成逐畫面」

**假設根因**：起點表需要的不是「有沒有畫面欄」，而是路徑 A 步驟 2 的「兩單元各自出現的狀態列（畫面加狀態）」集合比較與「只在單一畫面內共現」判定能否執行——即每一列的所屬畫面能否從清單本身讀出。反向框架「路徑 A 不需要分組」不成立：步驟 2 與步驟 4「逐畫面列出每一個佈局結構」都以畫面為單位。

**W 選項**（三類涵蓋：改造既有／新增條文／零工具）：

| 選項 | 做法 | O3 可推性 | 機會成本／風險 |
|------|------|----------|--------------|
| A1 原草稿 | 具名畫面欄或「欄位語意等價者」 | 否：「語意等價」屬橋接 | 兩位讀者對「頁面」「路由」欄是否等價可分岔 |
| A2 只認欄名「畫面」 | 逐字比對欄名 | 是 | 過窄：欄名為「頁面」的合格清單被判否 |
| A3 值層逐字比對（建議） | 每列有一欄的值逐字等於畫面清單中的畫面名，欄名不限 | 是 | 「全部畫面」類聚合值會判否，須展開列出（見 P） |
| A4 零條文 | 刪括號與範例，全域清單一律不算 | 是 | 過嚴；可分組的合格 spec 被迫改寫 |
| A5 前綴推導 | 由狀態列名字首推所屬畫面 | 否：推測即橋接 | 「清單載入中」可屬清單頁也可屬清單側欄 |

**附帶缺口**：現範例判否分支「改判無規格，須改走路徑 B 或 C」在僅有規格時無出口。比照 step-1 情況二的「起點判定標「待決」」出口改寫。

**P 失敗預想**：(1) 跨畫面共用列（如離線橫幅）的畫面欄值寫「全部」，逐字比對判否——早期警訊：規格票 Problem Analysis 出現補欄票而原清單其餘列皆合格；處置為補欄票展開為逐畫面名，屬可接受成本。(2) spec 無畫面清單——A 列本身以「狀態矩陣、畫面清單」為規格內容，缺畫面清單時同走待決出口。

**改文草稿 1**（`references/step-1-pick-starting-point.md`〈判定〉，插於「### 情況一」之前）：

```
### 全域狀態清單算不算逐畫面狀態表

規格只有一張全域狀態清單（非逐畫面分節）時，**清單每一列都有一欄的值逐字等於畫面清單中的一個畫面名**，才算逐畫面狀態表；欄名不限，一列屬多個畫面者，該欄值須逐一列出畫面名。任一列在每一欄都找不到逐字等於畫面名的值，整張清單不算逐畫面狀態表，A 的訊號不命中。不得從狀態列名稱的字首或顯示欄內容推測所屬畫面。

A 的訊號因此不命中、且 B、C 的訊號也不命中時，起點判定標「待決」，建規格補欄票（為清單補所屬畫面欄）並設為本規格票的 blockedBy，回覆前不進 step 2。
```

**改文草稿 2**（`SKILL.md`〈判定起點〉起點表 A 列）：「（一張全域狀態清單可拆成逐畫面者亦算）」改為「（一張全域狀態清單符合 `references/step-1-pick-starting-point.md`〈全域狀態清單算不算逐畫面狀態表〉者亦算）」。

**改文草稿 3**（`SKILL.md` 範例）：輸入補「畫面清單：清單頁、詳情頁」；判定表第一列依據改為「每列的畫面欄值（清單頁、詳情頁）逐字等於畫面清單中的畫面名」；第二列改為「否，A 的訊號不命中；本例無畫布無程式碼，起點判定標待決，建規格補欄票」；檢驗問句改為：

- Q 清單每一列是否都有一欄的值逐字等於畫面清單中的畫面名？　預期：是（依據：「清單每一列都有一欄的值逐字等於畫面清單中的一個畫面名，才算逐畫面狀態表」）
- Q 清單只有「狀態列」「顯示」兩欄、無畫布無程式碼時，起點判定為何？　預期：待決（依據：「起點判定標「待決」，建規格補欄票」）

**判否反例輸入**：畫面清單為「清單頁、詳情頁」；全域清單兩欄，列為「清單載入中｜骨架卡片」「詳情載入中｜骨架版面」。「清單載入中」不逐字等於「清單頁」，兩欄皆無逐字畫面名，判「否」——即使字首「清單」「詳情」看似可分組，依「不得從狀態列名稱的字首……推測所屬畫面」不得判是。

**用戶程式碼風格偏好**：否。屬起點判定的機械判準；嚴格度（逐字 vs 推測）依 O3 可推性要求定案，不是風格選擇。

### F-05：視覺單元「可獨立辨識」

**假設根因**：草稿以「圖層樹子圖層＋間距標註」定義，但實驗發現 1——圖層樹在條文零命中，只存在於範例輸入；〈輸入形態〉表的三種合格交付物中兩種不含圖層樹。草稿把範例的偶然屬性升為判準，屬「範例替條文發明判準」的同型錯誤。

**W 選項**：

| 選項 | 做法 | O3 可推性 | 機會成本／風險 |
|------|------|----------|--------------|
| B1 原草稿 | 獨立子圖層 AND 有間距標註 | 是，但前提不可得 | 對點陣圖匯出與人工描述無法執行；排除零間距緊貼的分色塊 |
| B2 路由至〈輸入形態〉（建議） | 可獨立辨識＝交付物為該區塊給出自身位置資料 | 是：引文逐字取自既有表 | 結構化匯出層級過細時候選變多（見 P） |
| B3 刪形容詞 | 步驟 1 改「框出每個區塊」 | 否：「區塊」仍未定義 | 等於把分岔移到「區塊」一詞 |
| B4 人眼可辨 | 以視覺辨識定義 | 否：橋接 | 兩位讀者必然分岔 |

與步驟 3〈同型歸併〉的銜接：可獨立辨識決定「是否成為候選」，歸併在其後處理「候選是否合併」，兩者不衝突；本判準只放不收，漏列比多列貴（步驟 4 排列關係表會漏記）。

**P 失敗預想**：結構化匯出把圖示內部向量路徑也列為具座標區塊，候選清單膨脹——早期警訊：候選數明顯多於畫面上可命名的單元；處置為步驟 2 語意問句答不出五種承載類別者於步驟 3 併入其所在候選。此下界處置目前條文未寫，若落檔後出現該警訊，另建票補判準（本票不擴範圍）。

**改文草稿 1**（`references/step-2-path-b-canvas-decomposition.md` 程序區塊步驟 1）：

```
1 視覺單元盤點  逐畫面框出每個可獨立辨識的區塊——「可獨立辨識」指交付物為該區塊給出自身的位置資料
                （上方〈輸入形態〉表：座標、相對位置或間距實測值）；交付物未單獨給出位置者，
                併入給出位置的所屬區塊，不另列。相同外觀的區塊先各自列，不預設同型。
                容器與子件的關係留待步驟 4（排列關係盤點）判定，本步驟不判定
```

**改文草稿 2**（同檔範例）：輸入改為「設計工具的結構化匯出中，卡片、圖示、標題文字、按鈕各有一筆區塊名稱與座標」；判定表第二列依據改為「三者在交付物中各有自身座標，屬可獨立辨識的區塊」；第一則 Q 的預期依據改為引用新句「交付物為該區塊給出自身的位置資料」，刪除「遺漏間距標註會讓步驟 4 排列關係盤點漏記」（該句為範例自身推論）。

**判否反例輸入**：人工撰寫的區塊描述中，某列為「價格文字（含幣別符號與數字），位置：卡片右上，與標題間距 8」；幣別符號與數字沒有各自的位置資料。問「幣別符號是否另列為視覺單元候選？」預期「否」（依據：「交付物未單獨給出位置者，併入給出位置的所屬區塊，不另列」）。對照：若同一描述給出兩色塊緊貼、各有座標但間距為 0，兩者皆列——解除草稿「無間距標註即不列」的誤排除。

**用戶程式碼風格偏好**：否。

### F-18 選項 B：slot 值待決升為條文

**假設根因**：0.1.0-W3-437.1 以「補前提可並存」選 C，但實驗發現 5——畫面票欄位表無 blockedBy 列、方法論出口主語為元件，「slot 值缺資源時建前置票、設畫面票 blockedBy」在範例區塊外零命中。C 落檔後範例【產出】仍自帶此判準；依 O3 處置表「範例不得代替條文承載判準；先把判準寫進條文本身，範例的檢驗問句改為引用新寫入的條文句」，C 單獨不能通過 W2 閘門。反向框架「範例本意錯，slot 值缺資源也應擋寫法」不成立：how 可寫出識別名，寫法層無缺件；元件票 blockedBy 列已把「i18n 資源」票列為合法前置，畫面票比照不違既有政策。

**W 選項**：

| 選項 | 做法 | 通過 O3？ | 機會成本／風險 |
|------|------|----------|--------------|
| C 單獨 | 只改範例（437.1 草稿） | 否：出口仍只在範例 | 閘門不通過 |
