## 重現實驗結果
### 實驗方法

以 `grep -cF` 對三項待評估判準的相依條文逐字查證（O3 規則 1：引文須 `grep -F` 可命中），確認：(1) 各草稿所需的判定詞在範例區塊外是否已有條文；(2) 草稿引用的前提（圖層樹、畫面欄、slot 值出口）在條文中是否存在；(3) 下游步驟實際消費該判準的哪個值。

| 查證字串 | 檔案 | 命中數 | 位置 |
|---------|------|-------|------|

### 實驗發現

已驗證事實：
1. F-05 草稿的「畫布圖層樹」只存在於範例內；〈輸入形態〉表允許的三種交付物中，點陣圖匯出與人工描述不含圖層樹，草稿判準對其中兩種交付物無法執行。
2. 〈輸入形態〉表已要求每種交付物給出區塊的位置資料（座標、相對位置或間距實測值），「可獨立辨識」可由該表逐字推出，不需新判準。
3. F-02 的判準被路徑 A 步驟 2 消費：該步驟以「狀態列（畫面加狀態）」集合比較與「只在單一畫面內共現」判定，需要每一列的所屬畫面可讀出；草稿的「欄位語意等價者」屬 O3 規則 3 的橋接，不可機械判定。
4. SKILL.md 範例的判否分支「改判無規格，改走 B 或 C」在僅有規格、無畫布無程式碼時沒有出口；step-1 情況二已有「起點判定標待決」的同型出口可比照。
5. F-18：畫面票欄位表無 blockedBy 列，方法論〈派發語言〉的缺件出口主語為元件；「slot 值缺資源」的出口在範例區塊外零命中。0.1.0-W3-437.1 建議的 C（只改範例）落檔後，範例【產出】的「建 i18n 前置票、設為本畫面票 blockedBy」仍無條文依據，依 O3 處置表屬「缺引導，非缺範例」。

未驗證假設：F-02 新條文對既有專案 spec 的命中率（有多少份全域清單的畫面欄值與畫面清單逐字一致）未量測。
