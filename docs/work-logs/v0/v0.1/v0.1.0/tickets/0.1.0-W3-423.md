### 階段 2 草稿（新判準，會改變既有判定，未落檔，交 WRAP／用戶裁定）

**E-07（內容角色複合角色粒度）**
草稿：內容角色判定的媒介不限文字；圖示與文字同屬「內容部分」，依其描述對象判定角色，不因媒介為圖示
而排除於標題／內文／標籤／數值之外。描述元件或其子項目前狀態／分類者歸「標籤」角色。
會改變哪些判定：範本〈內容角色〉現行條文僅以文字舉例，未提及圖示媒介；新增後「狀態圖示」類內容首次
被明文歸入「標籤」類別，可能影響既有規格中已將狀態圖示另立「圖示」或未歸類的既有內容角色欄位（若有）。

**E-09（狀態矩陣退出路徑欄格式）**
草稿：退出路徑欄固定寫「{觸發事件} → {目標狀態}」，格式全表一致；觸發事件是否須與「可用操作」欄同名
待裁定（`ux-design-evaluation` skill 的畫面級狀態矩陣有此同名要求，但條文亦僅見於範例慣例未條文化，
元件層狀態矩陣是否比照，屬另一個待裁定項）。
會改變哪些判定：新增後，既有規格中未使用箭頭格式的自由文字填答（若有）需重新格式化；且需一併決定
是否比照 `ux-design-evaluation` 的同名一致性檢查，這會新增一項跨欄核對要求。

**E-11（狀態矩陣同步策略欄）**
草稿：三選項互斥，每個狀態列僅能填一項（同步策略欄為單一格值，理由：同一狀態的資料流向同一時刻只
落在一種同步模型）。適用判準：「本地即時」——狀態值不涉及伺服器或外部服務、純本地運算或輸入裝置事件
直接產生；「樂觀更新後確認」——符合〈樂觀更新政策〉低風險與可逆 AND 條件的操作觸發之狀態；「等確認
才顯示」——不符合樂觀更新政策條件的高風險或不可逆操作，或需伺服器確認結果才可顯示者。
會改變哪些判定：現行範本僅列選項名，未有任何判準；此草稿首次給出「本地即時」與「等確認才顯示」的
一般判準，可能與既有規格中僅依賴〈樂觀更新政策〉、未區分本地即時邊界的既有填答產生落差。

**E-12b（回饋契約對應狀態邊一事件多邊）**
草稿：狀態變更提示 state-change 等事件若對應多條狀態轉換邊（同一事件在不同結果下可能導向不同目標
狀態），逐條列出，不得合併為一格籠統描述；格式為「{來源狀態} → {目標狀態}（{條件}）」，同一事件多條
邊時以分號分隔或允許同一事件出現多列，呈現方式待裁定。
會改變哪些判定：現行回饋契約表為固定六列（每事件一列），此草稿若採「同一事件多列」會改變表格結構
本身（目前結構為一事件一列），屬結構性修改，非僅補句；若採「同格分號分隔」則不改表格結構，兩案取捨
待裁定。

**E-17a（slot 契約強語意判準）**
草稿：強語意判準為「文案是否會因呼叫端情境不同而需要不同用字」——固定不變、不因呼叫情境改變用字者，
屬強語意元件預設；需依情境客製化用字（非僅插入參數值，而是整句用字本身需因情境不同而改寫）者，改列
呼叫端傳入。
會改變哪些判定：方法論〈元件文字歸屬〉現行僅列舉「confirm / cancel 類按鈕標籤、載入預設提示、無障礙
標籤」等具體例子，未給一般判準；新增後需要重新檢視這些既有例子是否都通過新判準（例如「載入預設提示」
在某些情境下可能需要客製化文字，若是則不再自動屬於強語意類別），可能限縮既有強語意清單的既定歸類。

**E-22（框架容器安全區：對話框避讓）**
草稿：對話框（浮於頁面內容之上的容器）不加「安全區」列；其螢幕邊緣避讓透過尺寸契約的「最大尺寸」與
置中定位處理，不透過安全區欄位。
會改變哪些判定：現行第 5 章條文只說明頁面根堆疊／殼層「加一列安全區」，未反向明訂對話框類容器的
避讓機制歸屬；新增後會把「尺寸契約」章節的職責範圍擴大到涵蓋「避讓」語意，但尺寸契約章節（4.{N}
子節）現行條文未提及「避讓」一詞，需一併決定尺寸契約自己的定義段是否也要補對應敘述，不能只在容器
條目引言處單方宣稱由尺寸契約承接。
