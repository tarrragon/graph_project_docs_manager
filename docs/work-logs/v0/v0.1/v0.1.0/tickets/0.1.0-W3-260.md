why: '**`bash-tool-usage-rules` 規則五明訂**：長文字（append-log、commit msg、ANA 結論）以 heredoc 直傳 CLI，禁繞 `/tmp`。該規則的前提是 heredoc 可用。


  **worktree 隔離環境下三個限制疊起來使該規則無法遵守**（由 `0.1.0-W3-207` Phase 3a 的 worktree 代理人實測回報）：


  1. `ticket track append-log` **無 `--file` 亦不吃 stdin**，內容只能作為字面引數傳入。

  2. **worktree guard 拒絕任何 command substitution**——`"$(cat <<''EOF'' ... EOF)"` 這個規則五指定的形式在該環境下被擋。

  3. 單一約 20 KB 字面引數**被拒為「too complex」**。


  結果：一節內容須拆成四次呼叫才寫得進去。**規則指定的方法在該環境不可用，而沒有任何文件說明替代方式**——執行者只能自行摸索，且每個 worktree 代理人都會重新摸索一次。


  **與 `0.1.0-W3-247` 的分工**：`247` 管**寫入去向錯誤**（寫到共用 checkout 而非 worktree）與**提交被拒**；本票管**內容進不去**。兩者的使用者可見情境相鄰但成因不同，修法也不同——`247` 改的是路徑推導與範圍檢查，本票改的是輸入管道。


  **為何值得修而非記在文件**：`opinionated-default-design` 主張——「每一個『寫文件提醒使用者遵守操作規範』都是信號，工具的預設行為還有改善空間」。這裡連文件都還沒有，而正確做法（`--file` 或 stdin）是既有 CLI 慣例，不是新發明。'
