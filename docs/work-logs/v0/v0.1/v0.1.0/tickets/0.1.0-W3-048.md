## Problem Analysis

### 第三種斷鏈形態與可執行的檢查（blog 專案 Round 1-C 抓到，2026-09-07）

該專案的 2.0.0 **帶著 53 條斷鏈上了發佈庫**，六份檔 0/53 可解析，Round 1-C 才抓到。

**形態**：正文自 `SKILL.md` 搬進 `references/` 時，指向 `references/principles/x.md` 的連結
未改為 `principles/x.md`，從新位置解析成 `references/references/principles/x.md`。

**三種相對連結在「往下搬一層」時的行為**：

| 連結指向 | 搬一層後 | 誰抓到 |
|---------|---------|--------|
| 跨 skill（`../other-skill/…`） | 斷 | 其 pre-commit broken-link scan（3 條） |
| **同 skill 內的兄弟子目錄（`references/principles/…`）** | **斷** | **無人**——portable scan 只掃 `../`，hook 未報 |
| 同目錄（`x.md`） | 不變 | — |

**第二列是本 skill 的「指名不指路徑」規範不涵蓋的**——skill 內部的 principle 連結本來就該是
相對路徑，它不是外部引用。

**本專案零命中的原因不是規範擋掉了**：`skill-design-guide` 的 `references/` 無子目錄（扁平）、
全 skill 零 markdown 相對連結。**是結構湊巧，不是規則生效。** 故本票的必查項必須涵蓋一個本
skill 自己無法示範的形態。

### 為什麼三套指標系統的檢查也漏

該側照本 skill 的三套各驗過，第三套（正文跨檔指涉）掃的是**位置詞與 frame 編號**，
沒掃**普通的 markdown 相對連結**——因為它們在拆分前全部有效，「它們會因搬移而失效」
不在該問句的值域裡。

**故必查項要列的不是第四類指標系統，是相對連結這個獨立維度**，且它與前三套的差別在於：
前三套問「指標指向的東西在不在」，這一項問「指標本身會不會因為自己搬家而改變意義」。

### 可執行的檢查（該側已實作並驗過）

對每個 `](path)` 以**檔案所在目錄**解析後 `os.path.exists`。該側實測 62 條全過，
並以一條刻意壞掉的連結作正對照確認有偵測力。

**便宜、機械、且對三種搬移方向都有效**——應進本 skill 的拆分必查項表。

### 附帶：「亦由此進入」的可證偽化

該側依本 skill 的〈結構約定〉寫了三個「亦由此進入」，**兩個是假的、一個半假**——
全部是「主題相近被寫成了指向」。而本 skill 條文的措辭「這一步不可憑印象」**擋不住它**
（該側讀過那句才寫的）。

本 skill 已有可執行的部分（`grep -rn <本檔名> <skill 目錄>`），缺的是**證偽規則**：

> 宣稱 X 送讀者來，X 檔裡就要有本檔的檔名或節名；**grep 零命中就刪掉宣稱**。

本票一併補入——「不可憑印象」是禁令，缺的是禁令被違反時的判別動作。

### 四問判準的兩個缺口（blog 專案 steelman reviewer，2026-09-07）

`W3-030` 定案的〈外移什麼、留什麼〉四問，經該側以 6 倍門檻的實跑重測，暴露兩個缺口。

**缺口一：「多數列但非全部」沒有格。**

四問的問 2 是「每一列讀者都用 → 留」，問 3 是「指得出少數列 → 外移到那些目標檔」。
該側的實測落點：

| 段落 | 用得到的列 | 落在哪 |
|------|-----------|--------|
| 〈這一批要跑哪些 frame〉 | 6 列中 5 列（integrating 不用） | **問 2 與問 3 之間的空格** |
| 〈每個 frame 的產出契約〉 | 5 列中 4 列（planning 不用） | **同上** |

`5/6` 既不是「每一列」也不是「唯一或少數」。該側對兩段各挑了一格寫，
**故條文那句「第三方拿同一份路由表重跑會落在同一格」對這兩段不成立**——
而那句正是四問的可外部驗證性所依賴的。

**缺口二：問 3 的「指名列」可以被「先開一列」滿足。**

該側把產出契約搬去新檔時，**新造了一列路由（「寫 reviewer 的 prompt 時」），
再用那一列證明它該搬去那裡**。程序沒有禁止用拆分當下新造的列來填問 3。

這使問 3 的可外部驗證性失效：**驗的人看到的是一個指得出的列，看不到那列是為了通過
這一問而生的**。與 `W3-022` 的 (d) 組「消費者必須指得出是誰」同族——那一組的防護是
「指不出就是沒有」，而這一組缺的是「不能是自己剛造的」。

**兩者的修法方向**：

- 缺口一：四問補一格，或把問 2／問 3 的邊界改為可判的比例（例如「不用的列 <= 1 視為每一列」），
  並要求記下不用的是哪幾列——**落在空格時要能說出空格在哪，而不是各自挑一格**
- 缺口二：問 3 補一句「該列須在本次拆分之前即存在；為本次拆分新造的列不算」

### 附帶：該側對本側「結構湊巧」那句的回敬

本側先前說「我方零 `../` 命中是結構湊巧不是規範生效」。該側指出同樣的話適用於他們：
**拆分前其 round 檔都是單 `##`，所以「選段查閱」在結構上不存在，不是他們判過它不適用。**

這一則的通用形態值得記進條文：**判準在某個對象上「沒有命中」，可能是判準生效、
也可能是該對象的結構使那個判準無從適用——兩者在盤點表上都寫「通過」。**
### 第三個缺口：`###` 升 `##` 之後與 H1 同名的那個 H2 沒有處置（2026-09-07）

該側依本 skill 的〈一則最小走查〉範例做（該範例的修法是「H1 改複合」），結果是
**三份檔各有一個與 H1 逐字相同的 H2**，且**單 H2 使「選段查閱」在結構上不存在**——
最大單節等於全檔，第 3 層判準因此無從發揮。

**正確處置**是各子節自己升 `##`、刪掉那個與 H1 同名的 H2。**而程序的範例示範的是另一條路。**

**這不是範例錯了，是它只涵蓋一種情形**：最小走查的場景是「兩節併入同一新檔」，
H1 改複合是對的；該側的場景是「一節連同其 `###` 子節整體外移」，此時原本的 `##`
在新檔裡與 H1 重複，該刪而非保留。

**兩種情形的判別**：外移的是**多個並列 `##`**（H1 需複合以涵蓋全部）還是**單一 `##` 連同其
`###` 子節**（該 `##` 成為 H1，其 `###` 各自升 `##`）。條文須同時給兩條，
否則讀者照唯一的範例做會落到錯的那一條。

**後果為何不明顯**：產出的檔案結構上合法（有 H1、有 H2、內容完整），行覆蓋與位元比對
全數通過，**只有在量第 3 層單檔判準時才會顯形**——而那一步的失效方式是「選段查閱這個
選項在結構上不存在」，不是報錯。

### 附帶：跨專案引用鏈的兩端各自合理而合成失效

該側指出本側 `W3-021` 的自我更正與其引用行為是同一條鏈的兩端：

- 本側從該節抽出「兩處說法並存」這個**正確結論**，推出問題清單，**未回頭對照文件**
- 該側**引用本側的清單**，未讀該節

**兩步各自都是合理的省略，串起來變成兩個人都沒讀原文而都以為有人讀過。**

這對本 skill 的〈外部引用〉條文有含意：指名式引用解決的是「路徑會斷」，
**解決不了「被指名的那份內容是否被複核過」**。條文目前只管指標有效性，不管被指者的
成熟度——本票不擴充至此，但記錄供後續判斷是否成票。
