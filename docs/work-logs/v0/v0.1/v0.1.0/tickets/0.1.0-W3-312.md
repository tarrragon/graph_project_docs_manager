### V4 退回的成因：1.12.1 記了一個從未落地的修法

回查 git：`09186db5`（1.12.1）的 `--stat` 只有 `CHANGELOG.md` 與 `SKILL.md` 兩檔，**`references/splitting-an-existing-skill.md` 未被觸及**，「路由表指**入口檔**〈按需讀取〉那張表」原封不動。而 1.12.1 的 CHANGELOG 逐字寫著「改為明寫 `SKILL.md`」。

**第三輪 V4 量到 0/3，替這個不存在的修法簽了名。** 那次改善來自 1.12.0 新增的三欄定義（讀者答得出三欄了），與本條宣稱無關；三份樣本剛好都沒卡在「這張表住在哪」，於是「宣稱 + 數據」互相背書，中間缺的那一步——修法有沒有真的寫進檔案——沒有人查。

成因：CHANGELOG 是照**修改計畫**寫的，不是照 **diff** 寫的。批次套用腳本當時對該處回報 `[SKIP n=0]`（字串比對失敗），而寫記錄時已照計畫逐條謄完。

**處置**：本輪真正執行該修法（改為「先打開該 skill 的 `SKILL.md`，找到〈按需讀取〉那張表」）；1.12.1 的 CHANGELOG 條目就地標註更正，不刪除原文；機制記為 error-pattern `PC-GPD-024`，含防護（記錄照 diff 寫、commit 前用 `git diff --cached --name-only` 逐條對照、`[SKIP n=0]` 當阻擋不當提示）。

### 結論

切換條件未觸發（〈超標了怎麼辦〉0/3，上一版的對照表處置有效）；V2a 與 N1 兩項主驗達標；回歸五項維持、一項輕微退、**一項退回**。逐項數據見「重現實驗結果」。

本輪最重要的產出不是任何一項修法，是**查出 1.12.1 的 CHANGELOG 記了一個從未落地的修法，而第三輪的量測替它簽了名**。

### 三個方法層面的收穫

**一、「已判定生效而後續復發」的第一件事是回查 diff，不是重新設計修法。** V4 復發時的直覺歸因是「上次改得不夠好」，於是會投入更用力的修法。實際上上次什麼都沒改——`git show --stat` 一行就看得出來，而那一行在三輪之間沒有人跑過。已記為 `PC-GPD-024`。

**二、量測改善不能歸給批次裡的任一條處置。** 一批修改通常含多項處置，而量測項與處置項不是一對一。第三輪 V4 的 0/3 來自 1.12.0 的三欄定義，卻被記在 1.12.1 那條宣稱底下。**一批多項時，改善只能歸給整批。**

**三、切換條件可以方向對而對象錯。** 第三輪我寫死「若疲勞點仍落在 X 則外移」，X 訂成了當時最累的〈超標了怎麼辦〉。本輪 X 是 0/3、而真正常駐的 token 估算區回到 2/3——**單輪的最高峰不等於常駐源**，四輪回頭看才分得出來。訂切換條件時，對象要取跨輪的累計分布而非上一輪的單點。
