### 現況與票面描述的落差

票面 why 欄稱「domain_view_test.dart 對兩者零命中」。實測（Read + grep）發現：test/unit/screens/
domain_view_test.dart 既有兩個 group（「泳道 · 尚未選定 UC state-domain-swimlane-uc-unset」
L268-292、「泳道 · flow 未結構化 state-domain-swimlane-unstructured」L294-318）已存在，並以
AnchorFinder.state(...) 找到附掛在 EmptyState 上的 testKey，證明該狀態確實渲染。「零命中」的
準確描述應為：grep `swimlaneUcUnsetPrompt` / `flowUnstructuredMessage`（l10n 訊息鍵字面）零命中
——但本專案既有測試慣例本就不斷言 l10n 訊息文字（見 test-assertion-design-rules D3 類推：測試
斷言結構型別而非文案字面），故該字面零命中不代表狀態零覆蓋。

真正的缺口是 acceptance 要求的**型別鑑別力斷言**：既有測試用 SwimlaneGrid/SwimlaneNode
存在性區分兩狀態，但未斷言 `find.byType(EmptyState)`，也未斷言 `BadgeRow` 在「尚未選定 UC」
狀態不存在——這正是 acceptance 第 1、2 項要求的內容。故實際工作是**強化既有 group 的斷言**，
而非新建 group。

## Solution
<!-- Schema[IMP/Solution]: 選填（.claude/pm-rules/ticket-body-schema.md） -->
在既有兩個 group 的測試本體中補上型別斷言，未新建 group：

1. 「泳道 · 尚未選定 UC」group（L268-292）：加 `find.byType(EmptyState)` findsOneWidget、
   `find.byType(BadgeRow)` findsNothing。鑑別力：`find.byType(EmptyState)` 單獨對此狀態無鑑別力
   （「空圖」等其他狀態也渲染 EmptyState），鑑別力來自與既有 SwimlaneGrid findsOneWidget +
   SwimlaneNode findsNothing 合看；`BadgeRow` findsNothing 直接對照「正常 · 泳道」狀態
   （同樣渲染 SwimlaneGrid，但額外渲染 BadgeRow.legend）——此斷言翻紅的條件正是「若程式碼
   誤把 BadgeRow.legend 一併渲染」，具體針對 SPEC-004 §3.6 §1 該列「不渲染 BadgeRow.legend」
   的明文規定。

2. 「泳道 · flow 未結構化」group（L294-318）：加 `find.byType(EmptyState)` findsOneWidget。
   鑑別力：與既有 `SwimlaneGrid` findsNothing 合看——EmptyState 存在 + SwimlaneGrid 不存在
   同時成立，才能與「泳道 · 尚未選定 UC」（EmptyState 存在 + SwimlaneGrid 也存在）及
   「正常 · 泳道」（EmptyState 不存在 + SwimlaneGrid 存在）兩者區分。單獨任一斷言都不足以
   鑑別三個相鄰狀態，兩兩合看才能唯一定位。
