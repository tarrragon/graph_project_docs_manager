## Solution
### 判定結論：五個面向全部併入既有 issue，一張都不新開

範圍形狀為「**零新開、四張既有 issue 承接、一個面向已由前票完成**」。共同前提（框架 skill 假設單一 session）判定為**敘述框架而非收斂單位**，不作為 issue 標題、不作為分群邊界，只在各面向的觀測內文以一句交叉引用表示。

### 一、範圍形狀的判準與收斂條件測試

判準只有一條，且可證偽：**對候選 issue 寫出一句「滿足什麼條件時它可以 close」，若該句寫不出，或寫出來之後任何新的跨 session 發現仍然落在它射程內，即為收納桶，改判併入既有。**

| 候選形狀 | 收斂條件嘗試 | 結果 |
|---|---|---|
| 一個 issue（五面向合併） | 「框架不再假設單一 session」 | **寫不出可驗證的完成條件**。該句不指名任何資產、任何行為、任何可觀測輸出；且明日任何一個新的跨 session 發現都落在射程內。即 `0.1.0-W3-289` 對 `#56` 指出的無邊界收納桶形態。**否決** |
| 一族（每面向各一張新 issue） | 各面向可寫出收斂條件（如 A：「三個 owner 讀取端與供應端值域一致且有測試」） | 收斂條件成立，但**違反「主題已有 open issue 一律附加不新開」**——逐面向 dedup 後每一個面向都命中一張以該主題為題的 open issue（見第三節）。新開會把同一主題裂成兩張，正是 `framework-issue` skill 定義的失效形態（「open 數增長不是失效，同領域裂成兩張才是」）。**否決** |
| 全部併入既有 | 由承接 issue 的既有收斂條件承擔 | **採用** |

**這條判準對「本應新開」的情形仍會輸出新開**：若某面向 dedup 後無任何 open issue 以其為主題，且收斂條件寫得出來，即應新開。本次五個面向沒有一個落在該格，不是判準偏袒既有 issue。
