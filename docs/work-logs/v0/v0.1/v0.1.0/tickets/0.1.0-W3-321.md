## Problem Analysis
### 問題根因

**已驗證的事實**：(1) 合法 owner 值不存在於任何供應端，只存在於編造；(2) 跨 session 訊息不是載體在條文層已成立，缺的是執法層與涵蓋面；(3) C 面向已於前一票完成升級，本票不得重複開；(4) `check` 對 owner 存活性零感知，孤兒 agent 的「無回收路徑」是框架資產自己寫下的；(5) E 面向落在規則 5 射程之外，且其形態是「代理指標（兩來源一致）與目標性質（結論正確）之間有縫」。

**仍未驗證的假設**：五個面向在其他 consumer 的復現情況（本票未跨專案查證）；`#77` Phase 1／契約 v2 之後是否已有未記錄的後續落地。

**由 (5) 導出的判定輸入**：E 的形態與 `#105` 的主題（檢查量的軸與缺陷所在的軸不同）同構，這使 E 的落點判定不需依賴「它是否屬跨 session 主題」這一問。
