### 階段 2 草稿（不改檔，交 WRAP／PM 裁決）

以下 5 則因需新增判準或會改變既有判定，僅寫草稿，不寫入 skill 檔案。

**草稿一（C-09b）**：`SKILL.md`〈與 orchestration 的協作〉表「文件回答不了地基問題的既有實作」列「判別」欄，擬追加：「『相當程度的實作』要求已可執行、有業務邏輯的專案體量；僅有 scaffold、無業務邏輯的空殼專案不算，應直接走〈維度與產物〉逐維度盤點，不需要先跑接手模式的盤點→命名→固化程序。」
會改變的判定：目前「相當程度的實作」無明文定義，遇到空殼專案時情境判定結果不確定；補上後會把「零業務邏輯的空殼 scaffold」類專案的路由從「可能誤入接手模式」改為「明確排除、直接走逐維度盤點」，屬新增判準。

**草稿二（C-11a）**：`dimension-product-notes.md`〈複合產物與多子樹分列〉段末，擬追加：「複合產物落票時，依產物切，不依維度切——每個子產物各自成一張票（UI 維度四塊已依此原則各自成票，其餘維度的複合產物比照辦理）。」
會改變的判定：目前僅 UI 維度明文「四塊各自的實作票」，其餘維度（如資料庫維度的複合產物「已存在於 X + 改寫產物」）未明文是否比照分票。補上後會把「其餘維度的複合產物是否分票」從未定改為「一律依產物切」，可能使既有已建的合併票需重新拆分，屬新增判準且改變既有落票粒度。

**草稿三（C-13c）**：`SKILL.md`〈移植前置條件〉降級記錄段落，擬追加：「降級記錄須為缺項與不成立步驟的對照表，不得以單句散文帶過。」
會改變的判定：目前條文只要求「記下缺哪一項、因此哪幾步在本專案不成立」，未限定格式。補上後會把既有以散文寫成、內容完整的降級記錄一併判為不合格，屬新增格式性判準，可能使既有記錄需要重寫。

**草稿四（C-15）**：`handoff-mode.md`〈萃取的前提是既有 artifact 可信〉表「artifact 的決策者不可得」列，擬追加：「決策者仍在組織內但於合理等候期（例如兩週）內無回應，視為不可得，不要求永久失聯。」
會改變的判定：目前條文未定義「不可得」的可操作門檻，「兩週」是具體數字，屬新增判準（且非用戶程式碼風格偏好，不逕行上呈用戶，留待 WRAP／PM 決定門檻本身或改用其他判準如「已詢問 N 次無回應」）。
