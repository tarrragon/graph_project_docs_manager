#### C-09b：「空殼 scaffold 不算相當程度的實作」

**現況**：SKILL.md〈與 orchestration 的協作〉表第一列只寫「已有相當程度的實作」，沒有定義「相當程度」。examples-process.md〈文件回答不了地基問題〉的【產出】表自行加了一列「已可執行、有業務邏輯的專案體量才算命中；僅有 scaffold……不算」，第二則問句再引用這列，等於由範例承載判準。此外，【輸入】已寫明「相當規模的可執行程式碼」，第二問問的是輸入以外的情形。

**Step 0（資料不足）**：誤判的代價未知。空殼 scaffold 若命中第一列，會走接手模式，「既有 orchestration 皆不適用」；若不命中，則落到「其餘」列，產物交給 `version-sequencing`。兩條路徑的差異在於 `version-sequencing` 能否承接「無規格的空殼專案」的產物。目前查無證據：`version-sequencing` 的 SKILL.md 對「spec_refs／假設已有規格」零命中。所以現在沒有依據判斷新判準是否必要。

**反向框架**：假設體量型判準（「有業務邏輯」）是錯的，真正該問的是作用：接手模式第 1 步能不能盤點出既有值？這個問法更貼近本 skill 的「問作用，不問存在」，但也有反例：產生器範本（如預設主題色）會讓空殼專案盤點出值。體量型與作用型對同一個專案可能給出不同答案，不是同一方案換說法。

#### C-15：「作者在職但兩週無回應也算決策者不可得」

**現況**：handoff-mode.md〈萃取的前提是既有 artifact 可信〉表只有「artifact 的決策者不可得」的處置，沒有定義「不可得」。範例預期答案裡的「判準的目的是不讓地基波卡在等待外部回應上……不要求對方永久失聯」是範例自行提出的推理。

**反向框架**：本票草稿四用數字門檻（兩週）定義，假設反過來，判準根本不需要等候期呢？第四列的處置是「保留原值原名，疑義落為決策文件的待確認項，不在地基波內改」，不改值，而且可以回復：決策晚到時由待確認項承接。誤判為「不可得」的代價只是晚一張票改值，所以判準可以綁定「本次地基波」，不必設時間。這樣也避開一個沒有校準依據的數字。

| 選項 | 內容 | 會改變的判定 | 評估 |
|---|---|---|---|
| A 數字門檻（本票草稿四） | 「合理等候期（例如兩週）內無回應」 | 未滿兩週的無回應不算不可得，地基波須等候 | 數字沒有依據，「例如」使門檻不可機械套用；地基波可能被卡住等待 |
| B 作用型判準（建議） | 以「本次地基波內能否取得決策」判定，須已詢問 | 在職但未回應算不可得；未詢問不算 | 不需要數字；誤判成本低，因為處置不改值 |
| C 縮減範例 | 刪除「作者未回應」列，只留離職的情形 | 無 | 能清除無依據句，但少了最有鑑別力的相反分支 |
| D 移除範例 | — | — | 不成立 |
| E 改引他處 | 引 `parallel-dispatch.md`〈跨 session 同儕沉默時的接管判準（強制）〉 | — | 不成立：對象是並行 session，不是人類決策者；硬引屬誤用 |

**P（premortem）**：失敗形式是 session 一詢問完就立刻宣告不可得。因為處置不改值，這種情形可以接受。早期警訊：決策文件的待確認項收到回覆後，沒有後續票承接改值。「同『先命名、統一值另開票』的二分法」已經要求另開票，不需要新增機制。

**建議**：B。

**草稿**（handoff-mode.md，〈萃取的前提是既有 artifact 可信〉表下方、【輸入】上方新增一段）：

```
**「不可得」以本次地基波內能否取得決策判定，不以決策者是否仍在組織內判定。** 已向決策者詢問、而本次地基波內未獲回應，即屬不可得；未詢問者不屬之。本表各列的「不可得」皆依此判定。第四列的處置不改值、疑義留在決策文件的待確認項，決策日後到達時由待確認項承接，因此本判定不設等候期限。
```

範例的連動修改（同一節）：

- 【輸入】「另一個具名常數的作者仍在組織內，但兩週內詢問無回應」改為「另一個具名常數的作者仍在組織內，本次地基波期間已詢問但未獲回應」。
- 【產出】乙改為「乙：算不可得（已詢問，本次地基波內未獲回應）」。
- 【驗證】預期答案改為：

```
  預期：是——依據句「已向決策者詢問、而本次地基波內未獲回應，即屬不可得」（本節表下判定句），不以決策者是否仍在組織內判定，不要求對方永久失聯。
```
