PM 審查先導結果，發現三個會使歸因失真的方法缺陷，本批必須照下列修正執行：

**2. 猜測點表的「缺口類別」改為五選一（取代原「初判缺口來源」）**

| 類別 | 判定 |
|------|------|
| spec 未描述 | 允許輸入全數查過仍無答案 |
| spec 間矛盾 | 允許輸入內兩處說法不同且無覆寫條文 |
| skill 缺引導 | 須指名查過的 skill 步驟／章節錨點，並說明它為何沒決定此事；無錨點不收 |
| skill 缺範例 | 同上須錨點；該處有文字約束但你讀出兩種以上做法 |
| 漏讀 | 允許輸入內其實有答案（對照 SPEC-004 時才發現亦歸此類，並補記答案所在錨點） |

**3. SPEC-004 對照時加「上游出處」欄。** 分歧處 SPEC-004 有值時，追查該值能否在 SPEC-001／SPEC-003／UC／domain-map／proposals／tech-decisions 或 SPEC-004 自身的核定記錄找到出處。有出處 → 你漏讀或 skill 沒引導你去找；**無出處 → 標「SPEC-004 無上游出處」**，不得歸為「預期分工缺口、不需修正」。先導把篩選維度、排序欄、卡片欄位歸為預期分工缺口，但未查這些值從何而來；若無上游，代表前一位規格撰寫者同樣是猜的。

**4.【產出】段的選件與排位可用組合樹記法**：`容器[子件, 子件]`，名稱用 spec 內的中性元件名。此記法屬 ASCII 線框的一種，與 SPEC-004 對照成本較低。
