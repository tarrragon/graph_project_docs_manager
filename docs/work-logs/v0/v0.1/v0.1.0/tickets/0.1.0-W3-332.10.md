### §5 破洞報告（3 狀態）

#### 狀態 1：掃描中（`state-gaps-scanning`）

【輸入】SPEC-001 §5「掃描中」列：顯示＝骨架＋進度，可用操作＝取消，退出路徑＝取消→返回；完成→有／無破洞。SPEC-003 §3.5 生命週期：首次可見且圖已建立→自動進入掃描中。SPEC-003 §2.5 取消契約。SPEC-003 §3.5 動畫提示：shimmer `Motion.skeletonCycle`。

【產出】`頁面框架[導覽側欄, 主區[骨架佔位(shimmer), 取消按鈕]]`

關鍵契約欄：
- 骨架佔位：shimmer 動畫 `Motion.skeletonCycle`；`disableAnimations` 時靜態
- 取消按鈕：依 §2.5 取消契約，目標態為 `returnTo` 指定畫面；`returnTo` 為 `null` 時為 `nav-page-domain`

【驗證】
- Given 使用者進入破洞報告且圖已建立 When 畫面首次可見 Then 自動進入掃描中，顯示骨架佔位帶 shimmer 動畫與取消按鈕
- Given 掃描中 When 使用者點擊取消 Then 切至 `returnTo` 指定畫面（`null` 時為 Domain 視圖）
- Given 掃描中 When 掃描完成且破洞數為 0 Then 轉為無破洞狀態（cross-fade）
- Given 掃描中 When 掃描完成且破洞數 > 0 Then 轉為有破洞狀態（cross-fade）

猜測點：無。SPEC-001 §5 + SPEC-003 §3.5 + §2.5 已覆蓋所有欄位。

#### 狀態 2：無破洞（`state-gaps-none`）

【輸入】SPEC-001 §5「無破洞」列：顯示＝「未偵測到破洞」＋掃描範圍說明，可用操作＝重新掃描、導覽。SPEC-003 §3.5 互動反應：重新掃描 `action-gaps-rescan`。SPEC-003 §3.5 生命週期：再次可見不重新掃描。

【產出】`頁面框架[導覽側欄, 主區[結果訊息(「未偵測到破洞」), 掃描範圍說明, 重新掃描按鈕]]`

關鍵契約欄：
- 結果訊息：靜態文字，i18n key **G1 猜測：未知**
- 掃描範圍說明：**G2 猜測：形態未知——是路徑列表、數量統計、或文字描述？** SPEC-001 寫「掃描範圍說明」但未定義其內容結構
- 重新掃描按鈕：點擊→`state-gaps-scanning` 出現

【驗證】
- Given 無破洞狀態 When 畫面渲染完成 Then 顯示「未偵測到破洞」訊息與掃描範圍說明
- Given 無破洞狀態 When 使用者點擊重新掃描 Then 現有結果消失，掃描中骨架出現（SPEC-003 §3.5 動畫：舊結果立即被骨架取代）

#### 狀態 3：有破洞（`state-gaps-found`）

【輸入】SPEC-001 §5「有破洞」列：顯示＝依類別分節，各項帶檔案與行號，可用操作＝點項→開啟原始檔並定位、重新掃描。SPEC-003 §3.5 互動反應：破洞項 `card-gaps-<itemId>` 點擊→外部開啟；分節收合 `expander-gaps-<category>`；分節捲動 `scroll-gaps-sections`。SPEC-003 §3.5 系統通知 `ScanNotifier.activated` 與 SnackBar fallback `viewGapsAction`。

【產出】`頁面框架[導覽側欄, 主區[重新掃描按鈕, 可捲動區域[分節收合容器[破洞卡片*N]]]]`

關鍵契約欄：
- 分節收合容器：每個類別一個，錨點 `expander-gaps-<category>`，點擊→項目出現或消失，高度變化 `Motion.transition`
- 破洞卡片：顯示檔案路徑與行號；點擊→外部開啟（§2.2 外部開啟契約）；三種結果：`opened`→SnackBar `openedExternallyMessage`、`notFound`→SnackBar `sourceFileNotFoundSnackbarMessage` 帶「重新掃描」動作、`failed`→SnackBar `externalOpenFailedMessage`
- 系統通知：掃描完成時視窗非前景→macOS 系統通知（權限 denied 時 SnackBar fallback `viewGapsAction`）

【驗證】
- Given 有破洞狀態 When 畫面渲染 Then 依類別分節顯示，各項帶檔案路徑與行號
- Given 有破洞 When 點擊破洞項且檔案存在 Then 以系統預設方式開啟，SnackBar 顯示 `openedExternallyMessage`
- Given 有破洞 When 點擊破洞項且檔案不存在 Then SnackBar 顯示 `sourceFileNotFoundSnackbarMessage` 帶「重新掃描」動作
- Given 有破洞 When 點擊分節 header Then 該類別展開或收合（`Motion.transition`）
- Given 掃描完成時使用者不在破洞報告頁 When 掃描完成 Then 發送 macOS 系統通知（權限 denied 時改 SnackBar fallback）

猜測點：無。SPEC-001 §5 + SPEC-003 §3.5 + §2.2 已覆蓋。

#### 狀態 2：正常（`state-nodeDetail-normal`）

【輸入】SPEC-001 §6「正常」列：顯示＝全頁內容＋關聯右欄，可用操作＝開啟原始檔、點關聯→跳轉。SPEC-003 §3.6 互動反應：返回 `action-nodeDetail-back`→`returnTo`；開啟原始檔 `action-nodeDetail-open-source`→外部開啟；關聯項 `card-nodeDetail-relation-<nodeId>`→主欄內容替換（`returnTo` 不變）；主欄捲動 `scroll-nodeDetail-content`；右欄捲動 `scroll-nodeDetail-relations`。

【產出】`頁面框架[導覽側欄, 主區[工具列[返回按鈕, 開啟原始檔按鈕], 雙欄佈局[主欄(可捲動, 節點內容), 右欄(可捲動, 關聯項卡片*N)]]]`

關鍵契約欄：
- 雙欄佈局：主欄與右欄各自獨立捲動；關聯項點擊→主欄內容替換（cross-fade `Motion.transition`，主欄 offset 歸零，右欄 offset 保留）
- 返回按鈕：`action-nodeDetail-back`→`returnTo`；`returnTo` 為 `null` 時不渲染
- 開啟原始檔按鈕：外部開啟契約（§2.2），三種結果同 §5
- 關聯項卡片：`card-nodeDetail-relation-<nodeId>`，點擊→同畫面替換
- **G3 猜測：工具列是否為獨立容器元件？** skill step-2 路徑 A 步驟 4 要求逐畫面列出佈局結構含框架層（工具列／內容），但 SPEC-001/003 未明寫節點詳情有工具列——我從「可用操作＝開啟原始檔」與「返回」推導出需要承載控制項的容器

【驗證】
- Given 正常狀態 When 畫面渲染 Then 顯示全頁內容（主欄）與關聯列表（右欄）
- Given 正常 When 點擊關聯項 Then 主欄內容替換為該節點（cross-fade），主欄 offset 歸零，右欄 offset 保留，`returnTo` 不變
- Given 正常 When 點擊開啟原始檔且檔案存在 Then 外部開啟，SnackBar `openedExternallyMessage`
- Given 正常 When 點擊開啟原始檔且檔案不存在 Then 狀態轉為 `state-nodeDetail-missing`（不出現 SnackBar）
- Given 正常 When 點擊返回 Then 切至 `returnTo`

#### 狀態 4：原始檔已消失（`state-nodeDetail-missing`）

【輸入】SPEC-001 §6「原始檔已消失」列：顯示＝「原始檔已不存在」＋最後已知路徑，可用操作＝重新整理、返回。SPEC-003 §3.6 重新整理三分支。

【產出】`頁面框架[導覽側欄, 主區[工具列[返回按鈕], 消失狀態元件(訊息=「原始檔已不存在」, 路徑=最後已知路徑, 重新整理按鈕)]]`

關鍵契約欄：

【驗證】

- Given 原始檔已消失 When 點擊重新整理且檔案存在但有斷點 Then 轉為部分損壞狀態
- Given 重新整理 When 超過 `Motion.cancelDeadline` Then **G5 猜測：超時行為未定義**——SPEC-003 §3.6 寫「三分支皆須在 `Motion.cancelDeadline` 內抵達」但未寫超時後的行為
