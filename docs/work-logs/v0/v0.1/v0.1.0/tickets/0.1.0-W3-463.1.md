**W（選項）**：B 架構層級表優先／A 草稿（依賴優先、取較晚者）／A' 一律依分配原則（本票提出）／C 不改。

**R（推導，見〈重現實驗結果〉）**：B 使〈並行判斷〉表「同一批次 / 是」與「有 blockedBy / 否」同時命中，被既有正文排除。草稿 A 的「以較晚者為準」在不同構輸入下偏離分配原則的逐字結果，本身是新判準，應刪。A' 只重申「確保依賴關係正確」與說明欄已寫的依賴，未新增判準。

**建議改文**（兩份檔案逐字相同，置於架構層級執行順序表之後、〈框架整合〉提示之前）：

> 架構層級執行順序表是本節「情況 / 版本/批次分配」表在「說明」欄所列依賴成立時算出的批次，不是另一套判準。任務的直接依賴與該列說明欄不符時（另有其他直接依賴，或未依賴說明欄所列者），不沿用本表，改依「情況 / 版本/批次分配」表：排在其全部直接依賴任務中最晚批次的下一批。依據為本節引言「確保依賴關係正確」。
>
> 判「否」反例：`StarRatingBar` 評分顯示元件［Presentation］只直接依賴第一批的 `Rating` 值物件，未依賴任何 UseCase -> 說明欄「依賴 Application」不成立 -> 不沿用本表的第三批，依「依賴前一批 / 下一個批次」排第二批。

**逐詞可推檢查**（以探針結構走一次，不寫探針輸入）：讀者取任務的直接依賴 -> 與該層說明欄比對 -> 不符 -> 找直接依賴中最晚批次 -> 加一批。每一步的詞都在改文或既有表中；「直接依賴」一詞排除「經由 D 間接依賴 Domain 介面所以符合說明欄」的遞移讀法。

**同構檢查**：探針 21a/21b 為匯率換算、Infrastructure 任務依賴同層第二批任務而**延後**；反例為評分顯示、Presentation 任務少一個依賴而**提前**，方向與領域皆不同，不使用 `CurrencyCode`／`RateProvider`／`RateCache` 等題幹詞，也不含 b4-tdd-2 答案鍵污染檢查字串。

**A（機會成本）**：一句加一例，兩檔各一次，不擠壓其他工作；雙份副本的長期成本另由 0.1.0-W3-467 處理。

| 面向 | 方案 1（tdd） | 方案 2（rules/core） |
|---|---|---|

方案 2 的最強論點：實作代理人只自動載入 rules/core、不讀 tdd，看到「必須記錄 warning」列會以為無出口。反駁：同一張表的首句就在該列上方兩行，出口已對他們可見；他們缺的不是例外條文。方案 4 付出方案 2 全部成本，未多得任何消歧效果。

**建議改文**（取代 `phase1/rules.md` Q5〈行動路徑〉之後的「靜默」段，範例列不動）：

> 「靜默」指不記日誌且不通知使用者。僅在以下三項同時成立時可選靜默：(a) 該操作不寫入任何持久狀態；(b) 該結果列在本規格的正常流程中；(c) 呼叫端對該結果有處理分支。任一項不成立即選日誌，其中 catch 後回傳預設值者記 warning（`.claude/rules/core/observability-rules.md` 規則 1 表「catch 後 return 預設值」列）。選靜默時，catch 區塊須以註解說明靜默原因；三項同時成立而 catch 後回傳預設值者同樣可選靜默，該註解即滿足規則 1 表首句「每個 catch 區塊必須滿足以下至少一項，否則需附註說明原因」中的「附註說明原因」。

**判「否」反例**（建議併入 Q5 範例列）：

> 判「否」反例：清除本機過期推播紀錄時 catch 並回傳 0（清除筆數），規格正常流程列有「沒有過期紀錄」分支，呼叫端收到 0 時略過提示 -> (b)(c) 成立、(a) 不成立（清除會改動持久狀態）-> 不可選靜默，catch 後回傳預設值記 warning。

**逐詞可推檢查**：「三項同時成立而 catch 後回傳預設值者同樣可選靜默」直接回答交集情境；「任一項不成立即選日誌，其中……記 warning」把 warning 子句限定在不成立分支。

**同構檢查**：探針 29b 為三項全成立（只讀旗標、回傳 false）；29a 為 (a)(b) 不成立；既有判「否」反例為 (b)(c) 不成立。新反例是唯一「只有 (a) 不成立、(b)(c) 成立」的組合，示範正常流程與處理分支不足以支撐靜默，結構與三者皆不同；不用「旗標／新手導覽／匯入聯絡人／設定檔」題幹詞，不含答案鍵污染檢查字串。
