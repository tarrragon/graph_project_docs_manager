## Problem Analysis
### 問題根因

W3-463 將 TDD-21b、TDD-29b 兩項歸為「條文全域查無優先序，需新判準」。本票複核後，兩項的直接原因都不是判準缺席，是**既有權威句與消費句之間缺一條路由**：

| 項 | 既有權威（非範例，`git grep -F` 命中） | 缺的是什麼 |
|---|---|---|
| TDD-21b | 〈版本號分配規則〉引言句「確保依賴關係正確」；〈架構層級執行順序〉表說明欄逐列寫明該層的依賴（「依賴 Domain」「依賴 Application」等）；〈並行判斷〉表「有 blockedBy / 否」 | 未寫明架構層級表是分配原則在說明欄依賴成立時的結果，說明欄不符時回到分配原則 |
| TDD-29b | `.claude/rules/core/observability-rules.md` 規則 1 表首句「每個 catch 區塊必須滿足以下至少一項，否則需附註說明原因」；`quality-baseline.md` 規則 4 擴充「只做 `return`/`pass` 時在註解說明」 | Q5 句中「catch 後回傳預設值者記 warning」射程未限定在「任一項不成立」分支；Q5 引用的是規則 1 的空 catch 列，回傳預設值的 catch 不是空 catch，引錯列 |

### 影響範圍

- 已驗證：TDD-21b 的三表在 `.claude/skills/tdd/references/phase1-split-methodology.md` 與 `.claude/skills/tdd/references/phase1/rules.md`〈版本號分配規則〉**逐字雙份**，W3-463 草稿只列前者，補句須同落兩處（雙份問題另建 0.1.0-W3-467）。
