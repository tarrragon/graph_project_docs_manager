### 一、條文失效點（逐 issue 分開，不合併）

### G1（`#54`）：「範圍已量」問的是數字來源，不是量測手段的涵蓋率

**條文原句**：`| 範圍已量 | 涵蓋的呼叫點／檔案／consumer 數是量到的數字，而非估計？ |`

**實際輸入**（觀測 `5629090213`）：三個具名缺項（`references/agent-self-check-template.md` 已漂移、`skills/ticket/references/track-command.md` 未漂移、`scripts/charset-pollution-detector.py` 未漂移），盤點手段為 `.py` 端 `grep -rln` 逐檔判定獨立賦值、`.md` 端以「Task Summary」為錨點統計 400 字元窗內 canonical 章節名數量 `>= 6` 判為疑似完整副本。

**失效**：照條文字面，這三個是**量到的數字**，「範圍已量」判為「是」。但該觀測自身指出，缺口分「已漂移」與「未漂移但未登記」兩形態，第二形態今天完全正確、不觸發任何訊號；而窗口密度啟發式（`>= 6`）對「只列五項以下的部分副本」「以其他形式持有副本」無鑑別力。**量到的是下界，不是全集**，而條文的問句對「下界 vs 全集」完全沒有位置——它只區分「量到的」與「估計的」，兩者都預設量測手段涵蓋全體。

**後果（可構造）**：若某個缺項的擴散面落在左檔（限本 consumer、單檔、不動公開契約），三問答「是／是／是（量到 3 個）」即豁免，發現當下可寫定修法。而該觀測明說最自然的修法——「掃描出當前不一致的檔案並補進登記表」——對第二形態全數抓不到。**條文在這個具體輸入上不但沒有攔下錯誤修法，還會發給它豁免。**

**條文缺的那一問**：入表判準應為「是否持有獨立副本」而非「是否已經不一致」。這是一句關於**量測手段的鑑別力**的話，三問裡沒有對應者。第二問「反例已試」最接近，但它問的是修法的反例，不是量測的反例。

### G2（`#55`）：「移至 issue 區段決定」指定了目的地，沒有指定承擔者、載體與回程

**條文原句**：`| 跨 consumer（.claude/ 通用資產）、動公開契約、或多呼叫點 | 修法形狀移至 framework issue 區段決定，發現票降為分析票（ANA） | 一張 ANA |`

**實際輸入**（觀測 `5628962387`）：候選處置「隔離索引提交完成後由提交方對本次涉及路徑執行 `git restore --staged`」，明標「不預設定案」；擴散面為改 CLI 實作，跨全部 consumer。

**失效三處**：

1. **載體未指定**。「移至 issue 區段決定」中的「區段」是 `init`／`add` 建的區段，而本 session 不是 `#55` 任一區段的 owner（`graph-project-docs-manager` 側區段 owner 為 `graph-project-docs-manager-66`，已結束的 session）。非 owner 只能 `observe`，而 observe 是觀測流、不是決策載體。條文沒有說「若你不是 owner 該怎麼讓決定發生」。
2. **承擔者不存在**。區段 owner 是「實際執行該工作的 session」，觀測堆積時沒有任何機制把 owner 叫回來。實測 `check` 的主警訊在 7 天窗內不觸發（`#55` 最短間距 `20:35:08`），今日這則觀測對系統而言完全無聲。**條文把決定託付給一個既無載體、又無觸發器的動作。**
3. **自指阻擋**。條文要求的產出（降 ANA、票面記錄、提交）在本 issue 記錄的缺口上實際受阻：`ticket track commit` 對 ANA 型票拒絕票面以外路徑（`#55` 已記錄），推回裸 commit；而裸 commit 正是 `#56` 今日觀測記錄的靜默回滾路徑。條文對「產出方式被它所在的 issue 描述的缺口擋住」沒有任何退路。

### G3（`#56`）：兩檔擴散面表對「已列互斥候選但明說未定案」的形態無處置

**條文原句**：兩檔處置表左檔「同一張票內把修法寫成待驗證形態：標明未驗證項與停手條件，不另開票」，右檔「修法形狀移至 framework issue 區段決定，發現票降為分析票（ANA）」。

**實際輸入**（觀測 `5628952523`）：三個互斥條文候選 A／B／C，各附覆蓋面與代價，明寫「皆未定案」；並附最小重現（已實測，輸出與註解一致）與兩個時序樣本（8 分鐘、7 秒）。

**失效**：這則觀測的證據狀態不是「未驗證」，而是「徵狀已充分驗證、修法選擇未定」。條文的兩檔表只按**擴散面**分流，證據狀態只作為進表前的閘門（三問任一為否才進表）。於是三問裡「反例已試」為否 → 進表 → 右檔 → 「降為 ANA，修法形狀移至 issue 決定」。結論本身與實際做法一致（該票確為 ANA、候選已寫進 issue），但條文對「候選已列完、下一步是選一個」這個狀態**沒有任何說法**：誰在什麼條件下把三選一定案、定案後那張 ANA 如何轉成實作票、實作票的 trigger 是什麼，條文全部留白。

**具體後果**：條文在〈與品質基線規則 5 的銜接〉段聲稱「不觸及 `.claude/rules/core/decision-trigger-binding.md`（本節不產生無 trigger 的延後：分析票本身就是 trigger）」。這句話對**建票當下**成立，對**分析票完成之後**不成立——ANA 完成、候選寫進 issue、實作票尚未建立，此時延後的 trigger 是「issue 區段做出決定」，而那不是 ticket，命中 decision-trigger-binding 規則 2「合法 trigger 限 ticket ID」。條文製造了一個它自己宣稱不會製造的中間狀態。

### 五、acceptance #5 的判定：「範圍已量」對「未漂移但未登記」類**給不出答案**

1. **問句的對象錯位**。條文原句問「涵蓋的呼叫點／檔案／consumer 數是量到的數字，而非估計？」——這是關於**數字來源**（量測 vs 估計）的二分。「未漂移但未登記」的困難不在數字來源，而在**量測手段的鑑別力**：該形態今天完全正確，任何以「當前是否不一致」為輸入的量測都對它回傳空集。數字確實是量到的，因此問句回傳「是」，而正確答案應為「範圍的下界已量，上界未知」。
