### how 句型凍結與規格演進的同步承擔者

**判定：不設專職承擔者。**

理由：how 句型凍結是一次性設計輸入，非持續維護的活文件。規格演進（SPEC-004 §3.6）由 PM 在 DOC ticket 中改定，而 how 句型寫入 ticket frontmatter 後即為該票的實作契約，不隨規格自動更新。

正確的防護機制不是「有人負責同步 how」，而是：
1. **PM 改定規格時，同步檢查受影響的進行中/待派發畫面票的 how 句型**——這是 PM 改規格的附帶責任，不需獨立承擔者。
2. **已完成票的漏檢只能事後全量比對**（如本票所做）——頻率應綁定在規格重大改版節點，不需常態監測。

後果：若不做上述檢查，漏檢會以本票同一方式靜默累積。但建立常態監測機制的成本高於偶發的全量比對（規格改版頻率低且收斂中）。本判定為已決策（狀態 a），非延後。
