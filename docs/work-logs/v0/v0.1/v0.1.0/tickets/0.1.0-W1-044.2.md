### WAP 三問（claim 時強制）

- **W（Widen）**：候選方案 (1) 逐元件完整填十一欄位 + 逐容器三項不變式（本票採用）；(2) 只填 W1-005 第一波會用到的狀態元件（EmptyState / BlockedState / LoadingState）與其容器，其餘留骨架——否決，skill〈契約齊全的定義〉是全清單的存在性檢查，部分填寫等於全部不可消費；(3) 以 §4.0 通用約定承載跨元件相同的值（互動瞬態視覺、焦點裝飾、對比、測試形態、人工長文案），逐元件條目只寫差異——採用為 (1) 的寫法，減少 26 + 17 條目的重複。
- **A（Attain distance）**：本票擠壓的是 W1-005 的開工時點（W1-005 blockedBy W1-044）；代價可接受，因用戶裁示「契約先於實作」。另擠壓 044.2 自身的完成時點：待決欄位一律建票而非猜值，票數增加但不返工。
- **P（Prepare to be wrong）**：最可能失敗原因是「待決」與「不適用」誤用——把缺來源的值（欄寬、標題列高、hover 樣式）寫成看似落成的值。防護：每個非 token、非 SPEC-001/003 抄錄、非畫布量測的值一律標「提案」；來源不可得者標「待決」並於同一 commit 建票，spec 內標示不得被畫面票引用；完成前依〈契約齊全的定義〉五條逐元件核對並記入 Test Results。
