## Task Summary

核定 AppColors.textSecondary 對比未達 WCAG AA 的處置：調深 token 或收窄 AA 承諾

## Problem Analysis
### WRAP（ANA 強制）

- **W（Widen）**：候選 (a) 調深 token、(b) 收窄承諾、(c) 混合（文字角色調深、停用與裝飾角色保留畫布值）、(d) 改調深 `textPrimary` 以騰出次要色的明度預算（否決：147 次出現，偏離面積比 (a) 更大，且 `textPrimary` 5.79:1 本已達標）、(e) 調淺帶色表面（否決：四個表面已是近白，再淺則與 `surfaceBase` 無法區辨）、(f) `textPrimary` 加不透明度（票面已否決，疊底後對比同樣不足）。
- **R（Reality Test）**：先重算全部語意色對比再列方案，結果見「重現實驗結果」。
- **A（Attain distance）**：本票擠壓的是 W1-005 元件票的 a11y 對比斷言措辭；三案皆需先改 SPEC-004 §4.0.2 與 15 個條目的對比欄，差別只在 token 是否變動。
- **P（Prepare to be wrong）**：最可能失敗原因是以 CIE76 色差（ΔE）推斷「層級是否還看得出來」而未實機比對。防護：token 變更票的 acceptance 含 `kDesignSize` 下 `textPrimary` / `textSecondary` / 停用色並排截圖，由 PM 目視核定。

### 問題根因

1. **token 值本身**：`AppColors.textSecondary` = `_Palette.gray500` = `#8A9694`（CIE L* 61.1，畫布實測 116 次）。與 `surfaceBase` 對比 3.06:1，與四個帶色表面 2.36～2.82:1。WCAG 2.1 SC 1.4.3 AA 一般字級門檻 4.5:1。
2. **大字級豁免在本專案無可用對象**：SC 1.4.3 的「大字」為 18pt 或 14pt 粗體（約 24px / 18.7px）。`AppFontSize` 四階為 10 / 12 / 14 / 19 px，皆不達大字級；「AA 大字級通過」在本專案等於「無文字可套用」，只有 SC 1.4.11 非文字對比（3:1）能承接圖示與符號。
3. **結構性限制（本票最重要的發現）**：`textPrimary` = `#5C6866`（L* 43.0，白底 5.79:1）已偏淺。次要色要在白底達 4.5:1 需 L* 不高於 49.8（`#6D7977`，與 primary ΔE 6.8）；要在 `surfaceChip` 達 4.5:1 需 L* 不高於 45.5（`#636E6C`，與 primary ΔE 2.6，肉眼不可分）。primary 與 secondary 之間的明度預算（ΔE 18.1）不足以在 AA 門檻之上再切出一階：**「兩階灰文字層級」與「四表面 AA」在此調色盤不能同時成立**，只能三選二（層級、白底 AA、帶色表面 AA）。
4. **AA 承諾的來源**：SPEC-002、PROP-001～004、`docs/tech-decisions.md` 皆無 WCAG 承諾；「AA」由 SPEC-004 §4.0.2（W1-044.2）首次寫入，非上游需求。收窄承諾不違反任何上游文件，只是修正 SPEC-004 自己引入的門檻；反之，調深 token 違反 SPEC-002〈設計約束〉「兩者不符時以 artboard 為準」，需在該節增例外條款。

## 重現實驗結果
### 實驗方法

WCAG 2.x 相對亮度公式（sRGB 線性化：c/12.92 若 c ≤ 0.03928，否則 ((c+0.055)/1.055)^2.4；L = 0.2126R + 0.7152G + 0.0722B；對比 = (L_hi + 0.05)/(L_lo + 0.05)）以 Python 3 標準庫實作於 session scratchpad `contrast.py`（實驗器材，不入庫）。輸入為 `lib/tokens/colors.dart` `_Palette` 的原始值層色碼，與 SPEC-002 顏色分佈表逐一核對一致。候選色以 HLS 固定色相 170° 與飽和度 5.4%（原色的值）只降明度產生；色差以 CIE76 ΔE（D65）估算。

### 實驗發現

**已驗證的事實**

1. `textSecondary` 在全部七個表面皆未達 AA 一般字級；只在 `surfaceBase` 達 3:1，其餘表面連 3:1 也未達。
2. 白底達 4.5:1 的上限色是 #6D7977（L* 49.8）；帶色表面全數達 4.5:1 的上限色是 #636E6C（L* 45.5），此時與 `textPrimary` ΔE 2.6，兩階文字層級消失。
3. 候選 #6A7674 為白底 AA 含安全餘裕（4.71，抗字型抗鋸齒與 gamma 誤差）與層級可辨（ΔE 5.6）之間的折衷點；在帶色表面仍未達 4.5:1（3.98～4.02），但全數通過 3:1。
4. 三個帶色表面上的次要文字案例（Badge `secondary` tone、RelationItem damaged、RecentProjectItem selected）在任何單一 token 值下都無法同時滿足「AA」與「層級可辨」，必須改元件層（換色或刪變體）。
5. 新增發現：SegmentedControl 的 `textPrimary` / `surfaceSegmentTrack` 4.48:1 未達 AA（§4.10 對比欄誤記通過）。修正方向為軌道底調淺：#DDE5E3 → 4.52、#DEE6E4 → 4.56（畫布 6 次出現，偏離極小）。
6. 無契約測試鎖定色碼值，token 變更不需改測試。

**仍未驗證的假設**

- ΔE 5.6 在 10px 字級下的實際可辨性（需實機並排）。
- SPEC-004 色彩欄推斷的表面歸屬與最終實作一致。
