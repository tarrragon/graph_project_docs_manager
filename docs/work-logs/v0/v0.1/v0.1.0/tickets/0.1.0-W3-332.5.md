# Execution Log

## Task Summary

審查 dart-style-guardian 與元件契約交界處 的需範例位置與實作引導缺口

---

## Problem Analysis
### 問題根因

dart-style-guardian 寫的是「不該怎麼做」。每一類約束的正面寫法都分給 foundation-design（token 階）與 component-contract-design（契約欄位、豁免、baseline）處理。所以分歧最容易出在兩種位置：(1) 需要讀者判斷「該歸哪一階／哪一類」的位置；(2) 兩個 skill 對同一件事（豁免、原生元件直用、baseline、token 名）各自表述的交界。除此之外，正文與 references 的所有對照表都以 UIColors／UISpacing／UIFontSizes／`context.l10n!` 為名，校準檔卻是 AppPalette／AppSpacing／AppTypography／`AppLocalizations.of(context)`。〈起手〉明文禁止讀者「自己編一組類別名」，正文本身卻示範了一組不存在的類別名。

### 影響範圍

已驗證（Read 全文 + grep）：SKILL.md 與 references 共 4 份（color-system／spacing-system／typography-system／i18n-guidelines），另含 component-contract-design 的 SKILL.md〈與相鄰資產的交界〉、addresses.md、step-3〈逐元件欄位來源〉、step-5 遷移票。scripts/style_checker.py 只讀了 pattern 群組，用來核對文字宣稱與掃描器實際行為是否一致。
未驗證：`.claude/methodologies/component-library-bidirectional-constraint-methodology.md` 的豁免三條件、〈元件文字歸屬〉全文沒有讀，交界列中引用這兩處的部分標為「術語定義在別處」，細節由修補票核對。

### 相關 Error Pattern

同型：PC-166 家族以外沒有直接對應。「文件宣稱與工具行為脫節」和 language-constraints 規則 5 的 OpenCC 案例屬同一機制（規則文字與實作脫節、無人察覺），本票不另建 error-pattern。

## 重現實驗結果
### 實驗方法

依 `skill-design-guide/references/chained-examples.md` 的判準逐節掃描，步驟為：先判斷該決策點有沒有文字約束（沒有＝缺引導）→ 有文字約束就模擬兩位讀者分歧（五類無模糊詞仍分歧的類型逐一必查）。文字宣稱為可機械核對的事實時，對照 `.claude/config/dart-style-guardian.json` 與 `scripts/style_checker.py` 的 `build_pattern_groups`。

### 實驗執行

- grep `baseline` 於 skill 目錄與 `.claude/hooks/dart-style-guardian-hook.py`：只有 SKILL.md〈與相鄰資產的交界〉命中 1 處（「見〈Project Calibration〉的 baseline 說明」），〈Project Calibration〉全節 0 處。
- style_checker.py pattern 群組：Color／SizedBox／EdgeInsets／fontSize／BorderRadius／i18n 六組，沒有任何原生元件直用的偵測 pattern；Color 組另含 SKILL 沒有記載的 `.withOpacity(`；略過標記另有 `// OK:`、`// ignore:` 兩種，SKILL〈Project Calibration〉沒有列出。
- i18n pattern `Text\s*\(\s*['\"](?!http|[A-Z_]+|v\d)`：負向前瞻 `[A-Z_]+` 會排除所有以大寫字母開頭的字串。SKILL〈Quick Reference Card〉與 i18n-guidelines〈Violation 1〉的違規示例 `Text('My Library')` 就屬此形態（依 regex 推論，未實跑掃描器）。

### 實驗發現

已驗證：baseline 說明懸空；原生元件直用在本 skill 沒有偵測也沒有文字約束，交界表卻宣稱本 skill 負責；兩種略過標記未記載。
依 regex 推論、未實跑：大寫開頭的寫死文字不被偵測。此項屬掃描器行為缺陷，不是範例缺口，轉交父票成票時需要實跑確認。

## Solution
### 結論

範圍內共命中 14 個位置：缺範例 7、缺引導 7。缺引導集中在兩個 skill 的交界（原生元件直用、豁免、baseline、元件文字歸屬）。原因是兩邊都以為對方寫了。另有 1 項前提問題會決定所有既有範例的處置方向，由 PM 裁決（見〈前提裁決項〉）。
