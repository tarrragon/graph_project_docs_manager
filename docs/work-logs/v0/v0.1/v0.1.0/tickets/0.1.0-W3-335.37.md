### 逐項評估（R1–R4）

#### R1（.36 #2）主題態是否受搜尋／篩選作用

**兩端原文**：SPEC-003 §3.4〈排序欄首的元件級契約〉S6「排序與篩選只於 `state-tickets-list` 可觸發」；同檔〈帶目標跳入〉「已載入但目標被搜尋詞或篩選隱藏」列「主題模式下展開該票所在主題節」（隱含主題態受篩選作用）。
**假設根因**：S6 只定「可觸發處」，未定「作用範圍」；帶目標跳入撰寫時把作用範圍讀成兩模式共用。

| 選項 | 類別 | 內容 |
|------|------|------|
| O1 | 零新增 | 主題態不套用搜尋與篩選，值保留供切回列表（S6 字面延伸） |
| O2 | 改造既有（原文二選一的另一端） | 主題態套用列表設定的搜尋與篩選，但不提供修改控制 |
| O3 | 新增 | 主題態也渲染 `Toolbar`，搜尋與篩選兩模式皆可操作（排序仍限列表） |
| O4 | 反向框架 | 搜尋與篩選改為各模式各自一組值 |

**R 事證**：UC-05 替代場景〈列表模式篩選〉「使用者停留在列表模式，以搜尋與篩選定位特定票」，把篩選綁在列表模式；UC-05 步驟 3–4 主題模式的目的是看主題進度分佈與阻擋，全量才能呈現分佈；SPEC-004 §3.6 §4 正常 · 主題列無 `Toolbar`；SPEC-001 §4 正常 · 主題可用操作無搜尋篩選。O2 使主題態顯示子集卻無可見控制與提示，使用者無從得知票為何缺席。
**裁決**：O1。
**被放棄選項優點**：O3 讓大型專案可在主題分組內縮小範圍；O4 避免切模式時的語意混淆。
**選定方案缺點**：(1) 使用者在列表設了篩選後切主題，看到的票數與列表不同，需靠 S6 的保留語意理解；(2) 主題態無法縮小範圍；(3) 帶目標跳入在兩模式行為分岔，測試需分開。
**P 失敗訊號**：畫面票實作時為主題態加上篩選指示或清除按鈕（表示使用者需要看到篩選狀態）→ 重評 O3。
**改動位置與改法**：
- SPEC-003 §3.4〈排序欄首的元件級契約〉S6：補「主題模式不套用搜尋詞與篩選，一律呈現全部已載入票；值保留，切回列表時照原值套用」
- SPEC-003 §3.4〈帶目標跳入〉「已載入但目標被搜尋詞或篩選隱藏」列：限定為列表模式；刪「主題模式下展開該票所在主題節（收合時）」子句（主題態由既有「目標僅因主題節收合而不可見」列承擔）
- SPEC-001 §4 正常 · 主題：註記補一句「不套用搜尋與篩選」

#### R2（.36 #3）載入完成後帶 returnTo 是否渲染返回

**兩端原文**：SPEC-003 §2.3 規則 4「`returnTo` 為 `null` 時返回按鈕不渲染」（非 null 即渲染的通則）；同檔 §3.4〈導航跳轉與退出〉只在未載入列列出 `action-tickets-back`；同檔 §2.3「並非所有 jump 目標畫面都渲染規則 4 的返回錨點」段排除 §1、§3、§5。
**假設根因**：返回鍵的渲染被寫成「逐狀態列舉」，但 §2.4 已定為頁面框架單一渲染；兩種模型並存。

| 選項 | 類別 | 內容 |
|------|------|------|
| O1 | 零新增（原文二選一一端） | 只在 SPEC-001 退出欄列有返回的狀態渲染（Ticket 清單僅未載入） |
| O2 | 改造既有（原文二選一另一端，限縮） | §4、§6 兩畫面的全部狀態，`returnTo` 非 null 即渲染 |
| O3 | 改造既有（反向框架：取消逐畫面例外） | 六畫面全部狀態，`returnTo` 非 null 即渲染；刪 §2.3 例外段 |
| O4 | 零新增（反向框架：取消返回） | 全面移除返回鍵，一律靠導覽列 |

**R 事證**：UC-05 替代場景〈自破洞報告切入〉與 SPEC-003 §3.5 破洞項三種 jump（Ticket 清單、節點詳情、UC Flow）——使用者逐項處理破洞時需回到破洞報告，現行只有節點詳情有返回；O1 使「自破洞跳入 → 自動載入 → 載入完成」過程中返回鍵先出現後消失，控制在無使用者操作下消失；§2.3 例外段的唯一理由是「SPEC-001 退出欄未列」，屬循環引用；§2.4 與 SPEC-004 §3.7 第 17 項已定返回鍵由頁面框架在 `SplitRow.header` 單一渲染，O3 使框架只需一條規則；O4 違反 SPEC-001 §6「返回來源畫面」。
**裁決**：O3。
**被放棄選項優點**：O2 改動處少、不動 Domain／追溯／破洞三畫面；O1 零改動。
**選定方案缺點**：(1) Domain 視圖 header 已有 `PageTitle` 與 `SegmentedControl`，再加返回鍵使 `kMinWindowSize` 下擁擠；(2) SPEC-003 §4 對照表多列需補返回；(3) 自追溯視圖跳到節點詳情再點「前往追溯視圖」這類往返會出現意義薄弱的返回。
**P 失敗訊號**：SPEC-004 `SplitRow.header` 在 `kMinWindowSize` 下的排列不變式無法同時容納三件 → 回退為 O2。
**改動位置與改法**：
- SPEC-003 §2.3：刪「並非所有 jump 目標畫面都渲染規則 4 的返回錨點」段，改寫為「返回鍵為頁面框架通則：六畫面任一狀態，`returnTo` 非 null 即渲染 `action-<screen>-back`」；首段「四個退出路徑需要回到來源」改為引用本通則
- SPEC-003 §3.1～§3.6 各〈導航跳轉與退出〉表與 §4 對照表：不逐列補返回，於 §4 表頭註記「各列另含通則返回（`returnTo` 非 null 時）」
- SPEC-001 概述或 §7 之後：補一段「返回為殼層通則，不逐列列出；§4 未載入、§6 各列的返回為該通則的既有列舉」
- SPEC-004 4.28 `PageColumn` 或 4.29 `SplitRow.header`：確認返回鍵 slot 對六畫面皆存在（追修票核對）

#### R3（.36 #5）Domain 導航表載入中列缺三個阻擋落點

**兩端原文**：SPEC-003 §3.1〈導航跳轉與退出〉載入中列「解析完成 → `state-domain-matrix` 或 `state-domain-empty`」；同檔 §4 #2 與 SPEC-001 §1 載入中退出欄含三個阻擋狀態。
