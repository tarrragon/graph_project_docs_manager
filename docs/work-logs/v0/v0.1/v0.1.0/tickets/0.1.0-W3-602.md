## Problem Analysis
<!-- Schema[ANA/Problem Analysis]: 必填（.claude/pm-rules/ticket-body-schema.md） -->
### PM 裁決：採「改 key 依據句」，且理由是它本來就寫錯，不是為了配合新條文

三選項中採**改 key 依據句**，並**同時保留** A-1／A-2 分格（該分格已是 W3-552 的既定要求，兩者不互斥）。本票升 P1 並設為 W3-552 的前置。

#### 為何不是「只改計分口徑」

A-1／A-2 分格要求判定者在作答側分辨兩種主張。但判定者**讀 key 定分**——key 的依據句寫「大小逐字列在 8.2(3) 的清單內」，作答寫同形的話，判定者會直接比對兩者相符而記通過，**不會走到分格那一步**。分格擋得住有意識去分辨的判定者，擋不住「看起來跟 key 一樣」這條捷徑。這是本線已記錄多次的同一機制：最省力的路徑決定實際行為。

#### 為何不是「無須處置」

承辦者的判定是「判定不翻轉（實質依據是第一支），但判定者可能以同形措辭把 A-1 主張記為通過，**正好抵銷本次改文**」。一個會被抵銷的修法與沒改沒有差別，而且更糟——票面會記著已改，讀數卻反映未改。

#### 改法的定性：更正，不是調整

現行依據句寫「它明列在清單內」，而該格**實質依據是第一支**（項名字面即指這項差異）。也就是說**依據句錯誤描述了它自己的依據**——這在新條文落地之前就已經是錯的，只是舊 S1 的乙支讓它看起來說得通。

因此本票的改動定性為**更正既有錯誤**，不是「為了配合新條文而調整器材」。兩者的差別在可比性：前者不構成變數（原本就該這樣寫），後者會使跨批讀數多一個變數。請在票面逐字記明此定性，並附各格的實質依據與現行措辭的對照。

#### 執行約束

- 只改**依據句**，不改通過門檻、不改預期判定、不改題幹。
- 四格逐格處理（UX-N8x(1)(3)、W8s(4)、W8u(4)、Z8a(4)），改後措辭須與改文後的 ⑤ 第一支同口徑。
- 新增條目式落檔，既有記載一字不改（本線已七次套用的紀律）。
- verify_head 以差集判讀；分母以 `q/` 實際檔案守恆式對帳（W3-584 的方法）。

#### 量測過程中的一次工具判讀失誤（據實記載）

首次跑 verify_head 時以 `if out=$(...)` 的 exit code 分流，把「有 FAIL 因而 rc=1」的 59 個 stem 誤計為「例外」，得到 `ok=49 / err=69 / fail_lines=0`——與 `0.1.0-W3-598` 記載的 108／10／299 三項全部不符。改以輸出中是否含 `quotes total=` 判分流（不讀 rc）後三項全數對上。此為 `bash-tool-usage-rules` 規則二「判成敗讀 exit code」的反向誤用：verify_head 的非零 rc 表示「有 FAIL」而非「執行失敗」，該命令的成敗訊號在 stdout 的守恆行，不在 rc。若未與 `0.1.0-W3-598` 的三項基線對帳，`fail_lines=0` 會被讀成「改動前零 FAIL」，差集判讀整個失去意義。
