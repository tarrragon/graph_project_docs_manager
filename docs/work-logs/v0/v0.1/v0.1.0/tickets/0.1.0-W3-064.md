## Solution
<!-- Schema[IMP/Solution]: 選填（.claude/pm-rules/ticket-body-schema.md） -->
實作範圍（依 SPEC-003 §2.2）：

- `lib/services/scan_notifier.dart`：`ScanNotifier` 抽象、`NotificationAuthorization`、`ScanCompleteNotification`（逐字對應規格「介面」區塊）。
- `lib/services/macos_scan_notifier.dart`：`MacosScanNotifier`，透過 `MethodChannel`（`graph_project_docs_manager/scan_notifier`）呼叫原生 `UNUserNotificationCenter`；`provisional`/逾時/`MissingPluginException` 一律收斂 `denied`；`developer.log` 記錄授權查詢/請求/發送/撤回的入口與結果（observability 規則 5）；標題/內文透過 `updateLocalizedStrings` 由 controller 於每次 build 注入（`AppLocalizations` 需要 `BuildContext`，本類別不持有）。
- `lib/services/scan_notifier_provider.dart`：`scanNotifierProvider`，正式路徑供 `MacosScanNotifier`，測試以 `overrideWithValue` 注入 fake。
- `lib/app/app_lifecycle.dart`：`appLifecycleStateProvider`，由 `AppShell`（`WidgetsBindingObserver`）寫入。
- `lib/app/shell.dart`：掛載 `WidgetsBindingObserver`、建立並啟動 `ScanNotificationController`；**同時修正既有設計缺口**——`_AppShellState.build` 原用 `Material` 包裹 `components.AppShell`，樹上全域無任何 `Scaffold`，導致 `AppSnackBar.show`（`ScaffoldMessenger.showSnackBar`）在真實 App 執行時必定拋出 `_scaffolds.isEmpty` 斷言錯誤（既有 `gap_report_screen.dart` 檔案不存在提示走同一元件，測試靠 `pumpHarness` 自建 `Scaffold` 遮蔽了此缺口，實機從未驗證過）。依 quality-baseline 規則 3 隨本票一併修正為 `Scaffold`。
- `lib/screens/gap_report/scan_notification_controller.dart`：`ScanNotificationController` 純邏輯類別，掛三個 `listenManual`（`gapReportProvider`、`selectedDestinationProvider`、`appLifecycleStateProvider`）與一個 `activated` stream 訂閱，實作觸發判定、`denied` fallback 延後至 `resumed`、撤回時機（回頁／重掃）、點擊通知導向（rail 切換 + `pendingLocateGapItemProvider`）。取消完成不通知：以 `previous is GapReportScanning && previous.isCancelling` 判別（SPEC-003 §2.5 C5）。
- `lib/screens/gap_report/gap_report_screen.dart`：新增 `_LocatableGapItem` 包裹 `ListRow.item`，消費 `pendingLocateGapItemProvider`，命中時 `Scrollable.ensureVisible` + `FocusNode.requestFocus`，處理後清空 provider。
- `macos/Runner/AppDelegate.swift`：`FlutterMethodChannel` 處理 `authorizationStatus`/`requestAuthorization`/`show`/`withdraw`，`UNUserNotificationCenterDelegate` 處理點擊回呼（`onActivated`）。
- ARB 六個 key（`app_zh.arb` 為 template，`app_en.arb` 同步）：`scanCompleteNotificationTitle`、`scanCompleteNotificationBody`、`scanCompleteNoGapsNotificationBody`、`scanCompleteSnackbarMessage`、`scanCompleteNoGapsSnackbarMessage`、`viewGapsAction`。

已知限制（記錄不建票，屬本票範圍內的設計選擇說明，非新發現問題）：
- 「切換專案」撤回系統通知（SPEC-003 §2.2「不重複發送」列第三個事件）未接線——0.1 的專案切換尚未有真實多專案狀態轉換可觀察（`currentProjectNameProvider` 為唯讀展示），SPEC-003 §2.2 測試斷言十二列本身也不含此情境，故未實作對應邏輯；待多專案真實狀態存在時另評估。
- `state-gaps-none` 的定位（EmptyState 根節點移入焦點，不高亮）未實作——僅實作 `state-gaps-found` 的 scroll-into-view + focus；十二列斷言表第 11 列的 fixture 皆為 `state-gaps-found`，未涵蓋此分支。
