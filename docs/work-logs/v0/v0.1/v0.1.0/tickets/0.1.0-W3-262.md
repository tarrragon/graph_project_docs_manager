## Solution
<!-- Schema[IMP/Solution]: 選填（.claude/pm-rules/ticket-body-schema.md） -->
`AttentionHandle` 增 `deadline` 欄位（由 `_accept` 從 `AttentionRequest.deadline` 帶入）；5 個原本呼叫 `_deadlineFields(null)` 的離場型/相關日誌呼叫點改為傳入該事件所指涉主體的實際 `deadline`：

- `_accept` 內 `preempted`/`sameLevelReplaced` 事件 -> `preemptedHandle.deadline`
- `presented()` 的 `releasedNonHolder` 分支 -> `handle.deadline`
- `presented()` 成功路徑的 `presented` 事件 -> `handle.deadline`
- `release()` 的 `releasedNonHolder` 分支 -> `handle.deadline`
- `_releaseHolder()` 的 `released`/`expired` 事件 -> `leaving.deadline`

`_deadlineFieldsUnassigned` 於本票開票時已不存在（Phase 4b 已合併為單一 `_deadlineFields`），故本票不涉及函式改名，只修正呼叫端傳入值；`_deadlineFields` 本體邏輯不變（`null` 時填 `deadlineAssigned: true`，此語意現在對所有呼叫點皆為真）。同步更新該函式上方註解，移除已過期的「傳入 null 亦用於離開類事件」描述。

Phase 1 記載同步：`0.1.0-W3-207` 2.2 的 `AttentionHandle` 型別定義補 `deadline` 欄位；2.5「每則事件的 fields」段補一句明寫離場型事件（`preempted`/`sameLevelReplaced`/`released`/`expired`/`releasedNonHolder`）據實回報的規則，取代原文未區分事件類別的籠統描述。未動 `0.1.0-W3-263` 追加的 Phase 2 段與 3a.3 段。

修改檔案：`lib/app/attention_arbiter.dart`、`test/unit/app/attention_arbiter_test.dart`、`docs/work-logs/v0/v0.1/v0.1.0/tickets/0.1.0-W3-207.md`。
