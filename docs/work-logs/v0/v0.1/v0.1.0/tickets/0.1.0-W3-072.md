## Problem Analysis
<!-- Schema[ANA/Problem Analysis]: 必填（.claude/pm-rules/ticket-body-schema.md） -->
### 問題根因

tripwire 總表「加入編輯能力」的規定 action（備份／衝突／還原／PII 全部重評）在觸發條件成立後未執行。觸發條件於票 `0.0.3-W1-002` 定案「App 直接改檔」時成立，而該 tripwire 寫在 append-only 決策記錄中——無 status 欄、不受任何 CLI 掃描、無偵測承擔者，條件成立時沒有任何機制會讓它發聲。

### 影響範圍

**已驗證的事實**（2026-09-10 實查，不採票面轉述）：

| 主張 | 查證結果 |
|---|---|
| 決策層已跨線 | 成立。`0.0.3-W1-002` 與 `domain-map.md` §4.4 |
| 實作層尚未跨線 | 成立。`lib/` 無任何寫入使用者檔案的呼叫，八種寫入 API 命中數皆為 0 |
| 觸及檔案系統的操作共三處且皆唯讀 | **不成立**。共四處，第四處為 `Process.run('open', [path])`，App 自身不寫入但把路徑交給 Launch Services，稱其唯讀須附界定 |
| 五處失效標註皆作實作層現在式斷言 | **不成立**。五處中僅三處，另兩處本身即決策層陳述 |
| 破洞報告以文件中的 `filePath` 對外開啟檔案 | **不成立**。八個值為 App 原始碼中的硬編碼常數。但同一處有更強的實證：八者皆為相對路徑，解析基準為行程工作目錄而非使用者選定的工作區 |

**仍未驗證的假設**：使用者的目標工作區是 git repo 的比例。本專案無此資料，以「History domain 的資料來源即 git object DB，非 git 目錄已定案為可辨識的降級」為間接依據處理，不以群體推測支撐結論。

**下游影響範圍**（多視角審查掃描所得，皆不在原五處清單內）：`docs/tech-decisions.md` 的 W1-013 structured log 延後決策（三個理由中兩個已失效，且其 tripwire 列承接欄為待指名）；同檔錯誤到畫面接線段的前提句；`SPEC-004` 樂觀更新政策的重評 trigger（未綁 ticket ID 且指向錯誤事件）。
