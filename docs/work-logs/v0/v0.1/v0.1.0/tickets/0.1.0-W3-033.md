### flutter_balance 專案提供的已掃範圍與基準修正（2026-09-07）

**基準必須是 canonical，不是本地。** 該側三輪掃描比的都是「發佈庫 vs flutter_balance
本地」，不是「發佈庫 vs canonical claude.git」。**發佈庫有、canonical 沒有、但該專案
本地有的檔案，該側不會報出來。** 本票做全庫盤點時以 canonical 為基準，不可沿用該側方法。

**該側已確認無殘留的範圍**（差集 = 全庫減這七個）：

| 票 | 日期 | 範圍 | 結果 |
|----|------|------|------|
| `0.2.1-W3-455` | 2026-08-12 | `error-pattern`／`skill-sync`／`search-tools-guide`／`skill-design-guide`／`ticket`／`worktree` 六個整樹 `diff -ru`（排除 `__pycache__`／`.venv`／`.pytest_cache`／`build`／`*.egg-info`） | 遠端獨有檔案 0 |
| `0.2.1-W3-350` | 2026-08 | `ticket` 整樹 | `--prune` 清掉 `hooks/` 下 4 個本地已刪或更名的 hook |
| `0.2.1-W3-1050` | 2026-09-02 | 31 個分歧 skill 逐一 clone 後 diff（23 個無 `.skill-sync-base` 者人工比對） | `ticket` 再清 2 個測試檔；**其餘分歧全為內容改寫，未記錄發佈庫獨有檔案清單** |

**其餘 skill 的檔案級殘留該側從未盤點。**

**發佈庫有 7 個該專案本地沒有的整個 skill 目錄**（case-first-module-workflow、
content-extension-evaluation、golden-path-validation、linux-install-debug、
migration-playbook-methodology、team-design-evaluation、verification-driven-cli），
該側判定為其他 consumer 推送、非殘留。**本票須以 canonical 為基準重判這 7 個**——
該側的判定依據是「不在我們本地」，不足以證明「在 canonical」。

**該側更正**：其 `0.2.1-W3-367` 掃的是 canonical 的孤兒（3 個 dart skill 目錄 + 1 個
測試檔，已 `--clean` 清除），與發佈庫殘留無關，前一則訊息列入為誤植。

### 一個會誤導判定的形態（該側 W3-1050 事故）

push 不帶 `--prune` 時，發佈庫獨有的 `CHANGELOG.md` 會被保留，而本地舊格式的
SKILL.md 又覆寫上去，結果**版本紀錄同時存在兩處且無指標行銜接**。

**本票若找到 `CHANGELOG.md` 類的殘留，先判它是不是這種格式回退的產物，而非
繞過 canonical 直接寫入。** 兩者的處置相反：前者該補指標行或合併，後者該回收或 prune。
