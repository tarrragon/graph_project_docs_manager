### 問題根因

`detect_unregistered_spec_references`（.claude/skills/ticket/ticket_system/lib/spec_reference_checker.py）
遞迴掃描 traceability.yaml + proposals-tracking.yaml 兩檔全部字串值找
SPEC-NNN 子字串（`_collect_spec_ids`，非固定欄位路徑），聯集即「已登錄」
集合。SPEC-004 在兩檔中皆未出現任何字串命中，故被判為未登錄。

### 影響範圍

docs/traceability.yaml、docs/proposals-tracking.yaml。

**traceability.yaml 既有三筆的形態辨識**：`mappings` 軸（spec/usecase/
title 必填）僅 SPEC-001 有條目，因 SPEC-001（畫面狀態矩陣）與 UC-01~06
一對一配對；SPEC-002／SPEC-003 皆不在 mappings，而是以
`data_contract_tests` 軸的 `contract_ref` 值出現（各一筆，欄位
`contract_ref`+`description`+`tests` 必／選填由 tracking_schema.py 的
`data_contract_entry_required`/`optional` 定義）。SPEC-004（元件庫規格）
性質同 SPEC-002／003——跨畫面共用的基礎設施規格，不與單一 UC 配對——
故依 data_contract_tests 形態補，非 mappings 形態。

**proposals-tracking.yaml 既有一筆的形態**：`specs:` 區段無獨立
schema 常數（PROPOSALS_TRACKING_SCHEMA 未定義 specs_format），只有
SPEC-001 一筆條目建立慣例：id/title/status/domain/source_proposal 五
欄位，值取自對應 SPEC 檔 frontmatter。
