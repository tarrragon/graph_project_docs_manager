### V2a 未生效，且是 1.12.0 自己造成的迴歸

一份把它讀成「**第 2 層有 hook 涵蓋、第 3 層無 hook**」——與原文相反。讀反比漏掉更糟：它讓讀者以為有人會擋。

歸因：1.12.0 把該段從節末的 **Consequence** 前移到三層表正下方，開頭寫「**本層**無 hook 執法」。在節末「本層」有上下文，移到三層表底下之後表上有三層，指涉懸空；同句又寫「涵蓋 pm-rules / rules / **references** 三處」，那個字更容易把讀者導向第 3 層。原文可 grep，**文章自己這樣寫的**。

`splitting-an-existing-skill.md`〈拆分特有的高頻缺陷〉的〈位置性指涉〉條講的正是這件事——跨節搬動之後位置詞與代稱會失效。**1.12.0 一邊在補那條規則，一邊在同一次修改裡犯它。**

處置：「本層」改為明列「第 2 層與第 3 層都沒有 hook 會擋你」，並把唯一有執法的第 1 層獨立成句。

### V4 部分生效的分解

## Solution

### 結論

五項門檻：**三項生效、一項部分生效、一項未生效**。逐項數據與歸因在「重現實驗結果」。

### 方法層面的兩點

**同一次修改可以一邊補規則、一邊犯那條規則。** V2a 的迴歸是把段落從節末前移到表格下方，「本層」的指涉隨之懸空——而 `splitting-an-existing-skill.md`〈位置性指涉〉條講的正是這件事，那條規則在同一批修改中被強化過。作者對自己剛寫下的規則沒有免疫力，因為犯它的是編輯動作（搬移），而讀規則時想的是撰寫動作（下筆）。**兩者在同一次 commit 裡發生時，只有外部讀者分得出來。**

**壓縮論證會製造「沒有理由的否定」。** 上一版依診斷一把「為什麼不能全檔內插」的實證移進 CHANGELOG，留下主張句。本輪一份直指「這是對做法的否定，但沒立即說明為什麼」。診斷一是對的，但**壓縮的下界是「一句話的理由」而不是零**——沒有理由的禁令讀者記不住，也判不出邊界。

### 自檢結果

- **acceptance 1（四項基準各有命中數對照與判定）**：五項（登記時為四項，派發前另加 V4 的指向一致性條件）逐項對照見 Test Results 首表，各附 1.12.0 之前的基準與本輪數字。
- **acceptance 2（新 finding 完成歸因並分處置與不處置）**：1.12.0 新增內容引入五項，處置四項、不處置一項；跨兩輪收斂兩項一併處置；不處置另三項各記理由。三張表皆在 Test Results。
- **驗證**：路由表雙向檢查全通過；`SKILL.md` 4562 tokens / 200 行，兩門檻皆過；各 reference 最大單節不超過 2282；禁用詞與 emoji 零命中。
- **未做而應說明者**：
  1. **本輪九項處置未經第三輪量測。** V2a 已連續兩輪未達門檻，第三次修法是否生效只有再跑一批才知道——這與 component-contract-design 那一輪的教訓同型（該處連續兩輪命中，兩次修法各失敗一次且方式不同）。
  2. **V4 只是部分生效，未完全達標。** 三欄定義生效，但 2/3 仍不知道路由表住在哪；本輪的處置（「入口檔」改明寫 `SKILL.md`）是否解決，同樣待量。
  3. **疲勞點兩輪皆落在 token 估算區。** 本輪的處置是把理由寫回一句，但該區的密度（三個換算值加分段邏輯）本身未變；若第三輪仍 2/3 以上落在該區，該考慮的是把整個估算段外移而非再壓縮。
