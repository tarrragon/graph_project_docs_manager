# Execution Log

## Task Summary

評估 UX-09a「明顯」正向定義第二版：與畫面實際按鈕比較，且填色文字 chip 仍合格

---

## Problem Analysis
### 問題根因

W3-457.2 的第一版草稿以「構成要素」絕對判定（文字或圖示＋區塊，缺任一項即屬 (a)），推導結果是填色文字 chip 不屬 (a)。用戶裁示（W3-417〈UX-09a 定義第二輪用戶裁示〉）否決此結論：U1 填色文字 chip 仍屬合格；U2 判定時與同一畫面上實際的按鈕比較，不單獨判定指示本身；U3 例示措辭用「不加底色與外框的純文字」。

第一版不能讓 chip 合格的直接原因：填色 chip 與按鈕的構成要素相同（都有文字、都有區塊），兩者剩下的差別是底色深淺、圓角、尺寸。前兩項落在理由句「描邊 vs 實心不是可靠的互動性訊號，不能單靠外觀圓角或邊框區分」的排除範圍內。因此第二版若要讓 chip 合格，必須在構成要素之外另立一個不屬描邊、實心、圓角、邊框的比較軸。本票的候選軸為區塊高度，依據是用戶指定的判否反例本身以「尺寸與按鈕相同」為特徵。

### 實驗發現

已驗證（字面推導）：
1. 四個指定輸入可逐詞推出：(1) 合格、(2) 不合格、(3) 合格、(4) 圓點合格，與派發要求一致。(2)(3)(4) 不需要輸入沒給的屬性。
2. (1) 需要「chip 區塊高度低於按鈕」這項屬性才能推出合格。鏈式範例第 2 項現行輸入沒有寫這項，也沒有寫「刪除」按鈕的形態，落檔時必須補上，否則範例結論推不出（ARCH-BAL-004）。
3. (5) 與填色按鈕同高的 chip 判不合格。若 U1 的意思是「任何填色 chip 都合格」，此結果與 U1 衝突，而且無法在不動理由句的前提下消解：同高 chip 與填色按鈕剩下的差別只有底色深淺與圓角（見 Solution 三）。
4. (8) 相對比較處理了第一版殘留風險 R2：純文字按鈕旁的純文字指示判不屬 (a)。
5. (9) UX-09b 預期判定「不合格」不變。

殘留風險（未驗證的假設）：
- R1：直條可能被讀成整列左邊框，進而把整列當區塊。判定對象是指示本身，由 UX-09a 重跑驗證。
- R2：X2 只寫「低於」，沒有量級。高度差 1～2px 的 chip 在字面上也合格，「明顯」在高度軸重新出現（見 Solution 四 U5）。
- R3：讀者可能把理由句「外觀不可靠」延伸到尺寸，認為以高度放行 chip 違背理由句（精神張力，見 Solution 三 T1）。
- R4：X1 採對稱比較（多一項也算不同），(6) 的 chip 在只有純文字按鈕的畫面上判合格。這個結果是否符合用戶意圖未經裁示。

## Solution
### 一、「明顯非按鈕形態」正向定義第二版

**定義全文**（接在第 2 項「(a) 明顯非按鈕形態」之後，取代現行括號例示）：

> 「明顯非按鈕形態」以指示與同一畫面上實際的按鈕比較來判定，不單獨判定指示本身。按鈕的構成要素有兩項：一是文字或圖示；二是區塊，指由底色或外框圍住文字或圖示的範圍。純幾何形狀不算圖示；圖示指描繪具體事物或符號的圖形（如鈴鐺、信封）。比較以下兩個軸，指示在任一軸上與畫面上每一種按鈕都不同，即屬明顯非按鈕形態：
> 1. 構成要素：指示具備的構成要素與按鈕不同，即缺少按鈕具備的一項，或具備按鈕沒有的一項。例如按鈕帶文字時的圓點（缺文字與圖示）；按鈕帶區塊時，不加底色與外框的純文字（缺區塊）。
> 2. 區塊高度：指示與按鈕都有區塊時，指示的區塊高度低於按鈕的區塊高度。例如區塊高度低於按鈕、以底色包住文字的文字 chip。
>
> 兩軸都與某一種按鈕相同的指示，不屬明顯非按鈕形態，不論描邊或實心、圓角或直角、底色深淺，因為描邊 vs 實心不是可靠的互動性訊號，不能單靠外觀圓角或邊框區分。以上例示非窮舉。

**出處**：「與同一畫面上實際的按鈕比較」取自 U2；「不加底色與外框的純文字」取自 U3；構成要素兩項與「純幾何形狀不算圖示」沿用 W3-457.2 草稿；「區塊高度」軸為本票新增判準（依據：用戶指定的判否反例以「尺寸與按鈕相同」為特徵）；「底色深淺」列入排除為本票新增；最後一句取自同段既有理由句。

**四輸入推導結果**（逐詞明細見〈重現實驗結果〉）：

| 輸入 | 推導 | 結果 |
|---|---|---|
| 填色 chip | 有文字、有底色區塊；按鈕同樣兩項都有 → 構成要素相同；chip 區塊高度低於按鈕 → 高度軸不同 → 屬 (a) | 合格（前提：chip 高度低於按鈕，見三 T2） |
| 描邊「已同步」標籤，尺寸與按鈕相同 | 有文字、有外框區塊；按鈕兩項都有 → 構成要素相同；高度相同 → 兩軸皆同 → 不屬 (a)；描邊被定義排除；未移出動作列 | 不合格 |
| UX-09a 3px 直條，同列「分享」按鈕 | 無文字、直條是純幾何形狀不算圖示、未圍住任何文字或圖示所以不是區塊；「分享」按鈕帶文字 → 構成要素不同 → 屬 (a)；同列不影響 | 合格 |
| 圓點 | 無文字與圖示、不是區塊；按鈕至少帶文字或圖示 → 構成要素不同 → 屬 (a) | 合格 |

**例示與探針同構檢查**：定義內例示為圓點、不加底色與外框的純文字、文字 chip、鈴鐺、信封。未出現直條、檔案列、分享、相簿、SSH、訂單、退款。

### 三、與「描邊 vs 實心不是可靠的互動性訊號」的衝突處置

| 編號 | 衝突 | 能否消解 | 處置 |
|---|---|---|---|
| T0 字面 | 定義兩軸是否用到描邊、實心、圓角、邊框 | 能 | 構成要素軸只用底色與外框判斷區塊有無，不區分描邊與實心；高度不在理由句所列訊號內 |
