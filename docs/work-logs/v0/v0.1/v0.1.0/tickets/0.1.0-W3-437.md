## Problem Analysis
### 問題根因

W3-417 出題者盤點的方法是 `grep '【輸入】'`（見 W3-417〈出題者盤點〉方法段），只收三段標記格式；A 組另手動補入 5 則非標記範例（A-08～A-12）。其餘非標記格式的範例——`輸入：／產出物（…）／驗證（…）` 半形標記、`**範例**：` 條列、正反面對照表、Violation／Fix 程式碼對照、`範例（…）` 粗體標題——全部落在盤點之外。標記格式範例本身無漏列：九個 skill 逐檔計數與盤點表一致（ccd 7、ux 29、fd 19、tas 6、tdd 18、doc 24、vb 8、dsg 4、sdg 5）。

### 影響範圍

- 已驗證：漏列 56 則，集中在 component-contract-design（19）、tdd（18）、skill-design-guide（9）、dart-style-guardian（5）、foundation-design（3）、doc（2）；ux-design-evaluation、test-assertion-design、version-bootstrap 為 0。
- 已驗證：漏列中條文查無或部分覆蓋者 16 則，阻擋 W2 閘門第二條件。
- 未驗證：歷史／動機案例集（tdd `references/cases/` 17 份等）是否屬「範例」，未逐案評估，登記 SR-2。

### 相關 Error Pattern

盤點以單一標記字串 grep 取代「教判定的範例」定義，屬「以可機械篩選的代理指標取代定義本身、代理指標漏掉的類別無訊號」型態；與 tool-output-trust 規則 3（固定值查證）同源但方向相反——固定值查的是命中數，本例的缺口是篩選式本身的召回率。未另建 error-pattern（W3-417 階段 PM 定義 1 已修正口徑，本票即其補正）。

### WRAP 認領三問

- W：候選做法二。一是只補出題者列出的 ccd 線索；二是九個 skill 全目錄以多種標記格式掃描。採後者，因出題者線索只涵蓋 ccd。

- P：最可能失敗原因是範例與「規則表的例示欄」界線判不一致。防護：Solution 寫明納入與排除類別，排除者逐類列名，供 PM 核對。
