## Problem Analysis
<!-- Schema[IMP/Problem Analysis]: 選填（小型 IMP 可留 placeholder；大型 IMP 建議填寫）（.claude/pm-rules/ticket-body-schema.md） -->
### 問題根因

`ticket track` 對 `spawned_tickets` 只有 `add-spawned`，無對稱的移除子命令；
`acceptance` 欄位則 add/remove 兩者俱全，介面不對稱。實際後果已發生：
`0.1.0-W1-075` 的執行者誤把已存在且無關的既有票（source_ticket 指向他處）
寫入自己的 `spawned_tickets`。ticket md 受 hook 禁止直讀直編，該欄位一旦
寫錯即無合法更正路徑。

進一步追根因：`resolve-spawn-request --status processed --spawned-ticket`
與 `add-spawned` 皆接受任意既有 ticket ID 寫入 `spawned_tickets`，兩者都
不驗證該 ID 是否已宣稱歸屬另一張票（`source_ticket` 衝突）——這是本次
污染案例的實際源頭，不只是「缺移除子命令」。

### 影響範圍

- `.claude/skills/ticket/ticket_system/commands/fields.py`（新增
  `execute_remove_spawned` 與共用 helper `_clear_reverse_source_if_matches`）
- `.claude/skills/ticket/ticket_system/commands/track.py`（掛載子命令與
  argparse 定義）
- `.claude/skills/ticket/ticket_system/commands/track_acceptance.py`
  （`resolve-spawn-request` 整合血緣衝突提示）
- `.claude/skills/ticket/ticket_system/lib/ticket_ops.py`（新增共用函式
  `check_reverse_source_conflict`）
- `.claude/skills/ticket/ticket_system/lib/command_tracking_messages.py`
  （新增 `HELP_REMOVE_SPAWNED`）
- `.claude/skills/ticket/references/track-command.md`、

  `0.1.0-W4-001` 條目）
