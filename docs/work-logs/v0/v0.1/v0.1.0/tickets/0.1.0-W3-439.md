### 逐項處置（P1～P3，皆階段 1：依語意澄清定案，未改變原判準本身）

**P1（version-shift-sop.md 契約檔案界定判準 1／2）**：問句前段括號列舉（使用者端檔案、以 key 對接的翻譯提供者等）與後段子句（「使日後改形狀必須遷移或相容讀取」「使改形狀無法在同一次提交內一併修改」）的關係未寫明，探針把後段當獨立條件重新驗證，推出列舉對象「不需遷移」「本方可單次提交完成」而判不成立。新增〈列舉與後段子句的關係〉句：命中列舉任一項即判「是」，不需另行驗證後段是否對當下情境成立；未命中列舉但情境本身符合後段描述者，仍判「是」。此語意判定依原裁決（0.1.0-W3-336.10 已定案的三問判準與範例）——範例一、二皆示範「命中列舉即足夠」，未曾要求對列舉對象再次驗證後段。

**P2（SKILL.md Step 2 呈現通道表第一／二列優先序）**：第一列「圖形介面（由本應用程式渲染…含唯讀畫面）」與第二列「非圖形的人讀呈現（…匯出文件版面…）」在「應用程式產出、版面固定的匯出檔」（如固定版面 PDF）上字面重疊，表格未寫兩列同時命中時何者優先。第二列補註「（優先本列）」；`references/step-rationale.md` 新增〈呈現通道表兩列的優先序〉，說明判準依查看／操作當下是否仍在本應用程式視窗內即時繪製（歸第一列），或已離開視窗改由外部程式另開檔案呈現（歸第二列，不因版面固定或排版複雜而改判第一列）。此語意呼應 0.1.0-W3-397 的 E3 裁決本意——E3 以「呈現通道」（人如何看到/操作產物）為判準，而非以版面豐富度判準；PDF 縱有固定版面，仍需另一支檢視器開啟才能被看見，屬「非圖形的人讀呈現」。

**P3（SKILL.md Step 2 前置檢查表 L3 列「對應載體」欄）**：舊文「本步驟得先只到此，逐元件元件契約欄位表與容器條目於 Step 4.5 第 3 塊後補齊」的「得」是允許語氣、非定義句，讀者把括號內延後項也算進本步驟存在判準而誤判不通過。改為明訂句：「僅元件清單 + 原生元件禁用對照表 + 豁免清單三項屬本步驟範圍，契約欄位表與容器條目於 Step 4.5 補齊」；`references/step-rationale.md` 新增〈L3 元件庫章節的範圍收斂〉說明範圍收斂理由，並更正 `references/step-rationale.md`〈Step 2 的 UI 前置檢查〉既有句「檢查的是內容是否符合 SKILL.md 表格『對應載體』欄的定義」現在對應到已收斂後的定義，不需另外修改該句本身。
