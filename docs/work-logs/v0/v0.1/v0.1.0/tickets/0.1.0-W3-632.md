## Problem Analysis
### 問題根因

`0.1.0-W3-628` 的規格 × 工具判準分岔稽核（`keys/spec-tool-divergence.md`，234 行）判定該輪的
「字面通路已排除」在規格字面與腳本自長欄位兩種讀法下皆不成立。根因不在任一條判準寫錯，而在
**判準有兩個住址**：定義寫在 `docs/probes/probe-authoring-spec.md`，執行它的是每輪現寫的拋棄式
腳本，兩者分岔時跑的不是規格寫的那一關，而分岔在讀數上不留痕跡——腳本較窄時該關少判紅，
外觀與「本來就沒問題」相同。

- `docs/probes/probe-authoring-spec.md`（§0／2.1／2.2／2.4／4.2／4.3／4.4／4.6／1.7／§6 Step 3／§7，新增第 8 節）

  「字面通路已排除」結論：射程限縮，原句不動

### 相關 Error Pattern

`.claude/rules/core/test-assertion-design-rules.md` 鑑別力規則 E2（守衛的測試必須含正向對照輸入）

否定起手，而寫作規範手寫版只有一族，腐爛方向固定為手寫那份較窄）與本票的「腳本較窄」同構，
