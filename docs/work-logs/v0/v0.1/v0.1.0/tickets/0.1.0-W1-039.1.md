變更摘要（docs/spec/ui/SPEC-003-interaction-response.md，v1.1 → v1.2）：

1. §撰寫判準（原「每條敘述都是一個斷言」）改名為「條件欄與可觀察結果欄皆為斷言」：
   - 適用範圍收窄至各表格的「條件」欄與「可觀察結果」欄（含同義欄名），新增一段
     明示「依據／理由」等說明性欄位不受此限，得用一般論述語言（呼應 §2.1 依據欄、
     §5 判讀註記表的既有寫法）。
   - 可觀察形式表由三種（錨點存在性、錨點屬性、幾何關係）擴充為四種：
     元件樹結構（整併原三種為子範例）、狀態容器值（對應 §2.3 的 returnToProvider
     斷言）、靜態原始碼掃描（對應 FR-05 的 grep 檢查）、外部程序呼叫（對應 FR-06
     的外部開啟動作）。FR-05 與 FR-06 各自可指向一種新增形式。

2. §2.5 取消契約 C4「不得閃現空白、不得出現錯誤文字」：
   - C4 表格列補一句指向下方新段落。
   - 新增「C4 的斷言方式（強制）」段落：以固定幀距逐幀推進至
     `Motion.cancelDeadline`，每一幀斷言載入態骨架根錨點存在（任一幀不存在即為
     閃現空白）；同區間斷言 `SnackBar` 與 `Dialog` 皆不存在（即「不得出現錯誤
     文字」的可驗形式）。

3. §2.10 焦點與鍵盤：
   - Tab 列改寫為「三個區段依序窮盡」的描述，並指向新段落。
   - 焦點列改寫「渲染出焦點裝飾」為指向新段落的可執行斷言。
   - 新增「Tab 內容區順序（斷言方式）」：定義區段內順序依 Flutter 預設
     `ReadingOrderTraversalPolicy`（視覺由上到下、由左到右），斷言為連續 Tab
     焦點序列的幾何位置（dy 優先、dx 次之）不遞減。
   - 新增「焦點裝飾（斷言方式）」：斷言取得焦點元件的祖先鏈中存在至少一個
     decoration 非 null 的 Container/DecoratedBox，不規定裝飾外觀。

4. frontmatter version 由 1.1 改為 1.2；變更歷史新增一列（v1.2，2026-09-02）。
