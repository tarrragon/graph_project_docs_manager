### 63 條的處置

前一 commit（`8012874`）已修三條危害項：第 7 步因果反轉會合法化 bug、走訪漏符號 ref 前綴會 fatal、數量誤述。本次處理其餘 60 條。

**結構（#1 #48 #63）**——git 執行點內容 88 行佔 37%，拆為衛星檔；本體只留一句限定與路由。原「素材出處」節壓成「材料出處」前移至開頭：該節是解鎖全文指示代名詞的鑰匙（「那份規格」「這次」「同一批工作」原本懸空 90 行），冷讀者讀到 64% 處才發現前面理解全錯。三個角色與三個未具名專案的關係一次交代。

**承重層（#2 #3 #4 #5）**——核心主張補否證條件、修正修飾語掛層（長得不一樣的是宣稱不是程序）；七步指定執行者且每步留產物；適用範圍自「任何凍結分類的工作」收斂為「從既有 artifact 萃取分類」。

**程序層痕跡（#36-46）**——七步逐步補痕跡要求，並新增失敗態與終止條件。原程序無「無法繼續」狀態，四個非顏色個案字面上全走得完，無法區分「跑過」與「跑順」。

**自我應用（#26 #27 #28 #37）**——執行者對照表第三列改為「無」。詳見下節。

**判讀徵兆（#44 #46）**——每條補適用前提；順序詞那條補功能性順序的合規形態。

**可攜性與術語（#8-12）**——移除外部 pattern ID、專案檔名、hook 檔名、行號；「憑證」全換（術語探針 3/3 讀成 credential）；三個非通用詞就地界定。

**發現面（#34）**——加 frontmatter 的 name / description / keywords。

### 最實質的一項改動

`#26` 指出執行者對照表把核心機制的執行者記為「程序（做完就查過了）」，其真值由執行動作本身保證，**結構與本文用來否定序號式命名的判詞完全相同**。

該列已改為「無」，並補可否證欄。這不是承認方法論失效——**補上執行者的方式是第 3 步的來源座標**：有座標可查即為已執行，執行者從「程序」變成「產物」，而產物可被否證。`#26` 與 `#27` 與 `#37` 三條因此一起解。
