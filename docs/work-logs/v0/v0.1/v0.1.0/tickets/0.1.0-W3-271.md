## Solution
<!-- Schema[IMP/Solution]: 選填（.claude/pm-rules/ticket-body-schema.md） -->
### 修改的函式（本票 where 欄位所指模組）

| 函式 | 變更 |
|------|------|
| `_run_git_with_lock_retry` | 重試條件由 `"index.lock" in err` 改為 `_is_lock_contention(err)`；重試前先判讀鎖齡，命中殘骸即停止重試並附診斷 |
| `_is_lock_contention`（新增） | 涵蓋 `index.lock`／`cannot lock ref`／任何單引號內 `*.lock` 路徑（`refs/heads/*.lock`、`HEAD.lock`） |
| `_lock_paths_from_error`（新增） | 自錯誤文字取出鎖檔路徑，相對路徑以 cwd 補齊 |
| `_scan_ref_lock_files`（新增） | 以檔案系統掃 `HEAD.lock` 與 `refs/heads/**/*.lock`，不發出子命令（該路徑上會再撞同一把鎖） |
| `_describe_lock_file`（新增） | 單一鎖的診斷：mtime／鎖齡／大小／內容（前 200 bytes） |
| `_stale_lock_diagnosis`（新增） | 鎖齡 >= `_STALE_LOCK_AGE_SECONDS`（60 秒）判為殘骸，回傳診斷字串；不移除任何鎖 |
| `_describe_update_ref_failure`（新增） | update-ref 失敗錯誤組裝：原因 + 已建立的 commit-tree SHA + 鎖殘骸歸屬 |
| `commit_files_isolated` | update-ref 前快照既有 ref 鎖，失敗時改由 `_describe_update_ref_failure` 產生 error |

### 設計取捨

- 殘骸與活鎖錯誤輸出同形，唯一可程式化的區別是鎖齡，故以 mtime 為判準；閾值 60 秒（票面實測：活鎖約十秒消失、殘骸停留 17 分鐘）。
- 工具只停止重試並輸出診斷，不刪鎖：合法的移除判準是「可溯源為自己崩潰操作的產物」，該判斷須由執行者做。
- 鎖殘骸歸屬用「呼叫前不存在、失敗後存在」的前後快照差集，而非「舊鎖就刪」，使清理責任可歸屬到唯一有資格清理的執行者。
