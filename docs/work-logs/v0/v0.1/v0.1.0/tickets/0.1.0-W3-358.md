## Problem Analysis
<!-- Schema[ANA/Problem Analysis]: 必填（.claude/pm-rules/ticket-body-schema.md） -->
### 問題根因

兩項測試屬「real project 回歸驗證」，對 `FileLocator.get_project_root()` 的實際專案內容做斷言，skip 守衛只檢查 SSOT 是否含 UC-05／UC-06 的 ID，不檢查內容形狀。其斷言（UC-05 無主要成功場景走章節標題摘要、UC-06 以 6A／6B 子場景前綴合併）描述的是上游來源專案（W1-076）的 UC 內容；本專案的 UC-05／06 是不同文件，且 detail 檔已含結構化 flow YAML 區塊，`get_uc_summary` 依雙軌策略走結構化路徑，回傳 `is_section_summary: False`、步驟標籤為 step id。

### 影響範圍

- 已驗證：`.claude/skills/doc/doc_system/core/uc_registry.py` `get_uc_summary` 的行為與其 docstring（0.2.1-W3-1061 雙軌策略）一致，實作無誤。
- 已驗證：失敗只在 `TestGetUcSummary` 的兩項 real-project 測試；tmp_path 單元測試與 `TestGetUcSummaryDualTrack` 皆綠（同檔其餘 71 項未失敗）。
- 未驗證：同類 real-project 測試（uc08_uc09）目前因本專案無 UC-08/09 而 skip，存在同型潛伏風險。

### 相關 Error Pattern

同型於「測試依賴測試以外的可變因素」（test-assertion-design 不可靠斷言判準：斷言結果依賴專案文件內容，而非程式碼）。

## 重現實驗結果
### 實驗方法

`uv -d .claude/skills/doc run pytest tests/test_uc_registry.py -k "uc05_returns_section_summary or uc06_merges_6a_6b_with_prefix"`，輸出取 head+tail。

### 實驗執行

- uc05：`assert summary["is_section_summary"] is True` → 實際 `False`（test_uc_registry.py 斷言 is_section_summary is True 那行）。預期 True，實際 False。
- uc06：`assert labels == {"6A", "6B"}` → 實際 `{'enter-gap-report: 進入破洞報告', 'view-categories: 檢視分類', 'locate-item: 定位單項', 'open-source-file: 開啟原始檔', ...}`。預期 {6A, 6B}，實際為本專案 UC-06 結構化 flow 的 step id 標籤。
- 結果：2 failed, 71 deselected。

### 實驗發現

實作按 docstring 行為運作（detail 檔含結構化區塊 → 結構化路徑 → is_section_summary False、標籤為 step id）。失敗來自測試對「專案文件內容」的假設與本專案不符。

## Solution
<!-- Schema[ANA/Solution]: 必填（.claude/pm-rules/ticket-body-schema.md） -->
### 歸因結論

測試預期過期（實作無誤）。判定依據：`get_uc_summary` docstring 明定 detail 檔含結構化 flow 區塊時走結構化路徑且 is_section_summary 為 False；本專案 UC-05/06 detail 檔已結構化，實際輸出與 docstring 完全一致。兩項測試斷言的是上游來源專案（W1-076）UC 文件的內容形狀，skip 守衛只查 UC ID 存在，未排除內容不同的 consumer 專案。

### 候選方案

| 方案 | 利 | 弊 |
|------|----|----|
| A：改為 tmp_path fixture 自建散文型 UC-05／6A-6B UC-06 | 斷言對程式行為，跨 consumer 穩定 | 失去對真實文件的回歸覆蓋 |
| B：保留 real-project，強化 skip 守衛（detail 檔無結構化區塊才跑） | 保留原專案回歸覆蓋 | 本專案永遠 skip，守衛本身仍依賴文件內容 |

建議 A（B 作為次選），由修復票決定。另：測試位於 `.claude/` 框架資產，修後需評估是否走 framework-issue 回報上游。
