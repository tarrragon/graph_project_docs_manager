## Problem Analysis
### 問題根因

兩組判準各自壞在不同層次，但都表現為「同一個對象判不出唯一答案」。

**(a) 組**：`SKILL.md`〈Progressive Disclosure〉舊句把兩個維度壓成一句——「超標時外移『一次只用其中一段』的內容⋯⋯SKILL.md 留路由與判準」。前半用**互斥性**當外移訊號，後半用**內容類別**當保留訊號，而互斥性對判準表普遍成立：三層預算表（寫 frontmatter 只用第 1 列）、自由度三級表（一次只用高或中或低）、預設值四列表（一次用一列）全部互斥且全部是判準，兩個半句對同一批對象給相反處置。根因不是措辭不精確，是「該不該存在」與「該住哪一份」被寫成同一個問題。

**(g) 組**：`references/splitting-an-existing-skill.md`〈拆分特有的高頻缺陷〉的兩條失效條件中，第二條「目標可能移動即失效」要求撰寫者對未來下斷言。同段自陳的實證直接否證這個要求可被滿足——四處同型缺陷中三次由修法自身引入，寫的當下都判過不會動。判準要求的預測，正是它自己的實證顯示做不到的那一種。

## Solution
### 分析結論

兩組判準各產出一個替代版本並落地。兩者的共同修法是**把不可外部驗證的成分換成打開檔案就看得到的現況**：(a) 把「內容屬於哪一類」換成「哪一列的讀者用得到」，(g) 把「目標日後會不會動」換成「目標現在有沒有名字」。

### (a) 替代判準：外移什麼、留什麼

落地於 `references/splitting-an-existing-skill.md`〈外移什麼、留什麼〉，`SKILL.md` L64 改為一句路由。判準為四問依序，**每一格都要求指名入口檔路由表的具體某一列**，指不出列即不屬於該格：

| 問 | 判定 |
|----|------|
| 1. 它回答的問題，是路由表某一列「何時讀」欄的判斷條件嗎？ | 留在入口檔 |
| 2. 路由表每一列的讀者都會用到它嗎？ | 留在入口檔 |
| 3. 指得出唯一或少數幾列，且那些讀者不必讀它就知道自己是那一列？ | 外移到那幾列的目標檔 |
| 4. 三問都指不出任何一列？ | 沒有讀者情境，壓縮成主張句，敘事移入 `CHANGELOG.md` 或 ticket |

**為何可外部驗證**：判定的動作是「指名列」，與 W3-022 的 (d) 組要求指名機械消費者同一個手法。互斥性不再進入判定。

**對本 skill 六節的判定**（舊句給兩個相反答案，新判準給一個）：

| 節 | 舊：「一次只用其中一段」 | 舊：「留路由與判準」 | 新判準 |
|----|------------------------|-------------------|--------|
| 〈Progressive Disclosure〉門檻＋量測指令＋分段估算表 | 外移 | 留 | 問 1——它是路由表第 4 列「超出第 2 層預算」的判斷條件 → **留** |
| 〈按需讀取〉路由表 | 外移 | 留 | 問 1——它就是路由本身 → **留** |
| 〈Concise is Key〉兩問表 | 外移 | 留 | 問 2——六列讀者都在做「這段要不要留」的取捨 → **留** |
| 〈Degrees of Freedom〉三級表＋兩問＋三段範例 | 外移 | 留 | 問 3——只有第 5 列（`patterns-and-troubleshooting.md`）的讀者用 → **外移** |
| 〈Opinionated Defaults〉四列表 | 外移 | 留 | 問 3——同第 5 列 → **外移** |
| L64 矛盾句自身（該外移什麼） | 外移 | 留 | 問 3——判斷超標用的是門檻不是它 → **外移到 `splitting-an-existing-skill.md`**（已執行） |

外加問 4 的三處：分段法兩類誤判實證、245 行實測案例、全檔比例內插論證，皆指不出列，已壓縮為主張句（共減 119 tok）。

### (g) 替代判準：位置性指涉

落地於 `references/splitting-an-existing-skill.md`〈拆分特有的高頻缺陷〉。兩條失效條件，任一成立即改具名：

1. **跨檔**——目標與指涉不在同一檔（原條保留，本就可查證）。
2. **目標帶識別字**——目標段有 `##`/`###` 標題、粗體引導句或檔名，卻用位置詞去指它。

合規只剩一種情形：同檔、緊接、且目標沒有識別字（無標題的表，「見下表」是唯一寫法）。

**為何是事後可查證的條件**：判定兩步都是打開檔案就看得到的現況——先看目標段有沒有標題或粗體引導句，有就寫出那個字串；沒有才留位置詞並確認同檔緊接。不需要對未來下任何斷言，第三方重跑得同一答案。

**它如何吸收原本的實證**：舊條要撰寫者預測目標會不會動，而實證顯示三次缺陷由修法自身引入、寫的當下都判過不會動。新條不問移動——那四處（末段、下段、上節、下方）指的都是帶標題的節或帶粗體引導句的段，「有名字卻用位置詞」在寫的當下就看得見。同批留下的四處正確位置指涉指向無識別字的目標，新條照樣判為合規，未把它們翻成違規。

**機制上的理由**：具名指涉在目標改名或外移時會被死名／孤兒節檢查命中；位置詞不會——目標搬走後那句話依舊落在一段看似合理的內容旁，字串合法、檢查全綠。判準因此卡在「壞掉時有沒有訊號」。

### 兩兩比對重跑（acceptance 第 3 子句）

改動後對全 skill 七檔重跑特徵字串掃描與四項機械檢查，**未引入新的相反處置**。逐條結果見〈重現實驗結果〉的實驗執行段。三處自我違規（新 (g) 段的「上述實證」、`SKILL.md` L62「上面那行指令」、L44「單檔見下」）在本輪抓到並當場改具名——新判準對撰寫它的段落自身生效。

### 體量結果與未達標的成因（acceptance 第 4 子句，部分達成）

| 階段 | 分段估算 | 佔 5k |
|------|---------|-------|
| 改動前 | 4,670 | 93% |

**未達 80% 的原因是 where.files 範圍，不是判準判不出來。** 新判準對三節（〈Degrees of Freedom〉722 tok、〈Opinionated Defaults〉237 tok、〈三類 bundled resource 的分工〉186 tok，合計 1,145 tok）明確判為問 3「外移」，但它們的目標檔 `references/patterns-and-troubleshooting.md` 與 `references/creating-and-adopting-skills.md` 不在本票 where.files 內，寫入即越界。本票能寫的兩檔中，判準判為外移的只有 L64 矛盾句本身。已登記 SR-1 承接，任一節外移即可跨過 80% 門檻。

**這個結果本身是判準有效的證據**：where.files 是在 (a) 判準尚未設計出來時圈定的，當時無從知道判準會把哪些內容送到哪一份 reference。

### 候選方案

| 組 | 採用案 | 未採用案與捨棄理由 |
|----|-------|------------------|
| (a) | 四問，每格要求指名路由表的具體列 | **案二：保留「一次只用其中一段」但列舉例外清單**（判準表、路由表不適用）。捨棄理由——例外清單要窮舉「什麼算判準表」，而那正是原本判不出來的東西，等於把同一個未定義項往下推一層。**案三：以節的 token 大小排序，由大到小外移到湊足預算**。捨棄理由——體量不帶讀者資訊，會把問 1 的路由條件（門檻與量測指令）判成優先外移，讀者將無從得知自己超標 |
| (g) | 兩條件：跨檔、目標帶識別字 | **案二：一律禁用位置指涉，全部改具名**。捨棄理由——原段自陳同批四處位置指涉正確且比具名好讀，無標題的表沒有名字可寫，全禁會逼出「見〈上方那張表〉」這種更差的寫法。**案三：保留「可能移動」但要求寫下判斷理由**。捨棄理由——理由本身仍是對未來的斷言，寫下來只是讓不可驗證的判斷留下紀錄，第三方仍無法重跑 |
