### Task Reference
- 0.1.0-W3-097 what: 修復 scan_notifier MethodChannel 原生端未註冊，實機拋 MissingPluginException

### Rationale Chain
- 0.1.0-W3-097 why: 實機執行時，`MacosScanNotifier` 的第一次授權查詢即失敗。DevTools Logging 實測記錄（2026-09-08 15:12:51.441，`Level.WARNING (900)`）：

    查詢授權狀態失敗，原生端未註冊 handler（視為 denied）：
    MissingPluginException(No implementation found for method authorizationStatus
    on channel graph_project_docs_manager/scan_notifier)

**`macos/Runner/AppDelegate.swift` 的 `MethodChannel` 從未被註冊。** 該檔在 `applicationDidFinishLaunching` 內以

    guard let controller = mainFlutterWindow?.contentViewController as? FlutterViewController else { return }

取得 controller 後才建立 channel——guard 失敗時**靜默 return**，channel 不建立，且不留任何訊號。實測結果顯示這個 guard 確實失敗了（需確認 `mainFlutterWindow` 在該時點是否已由 NIB 載入完成，屬 macOS 啟動時序問題）。

後果：`0.1.0-W3-064` 實作的整套系統通知功能——授權查詢、授權請求、發送、撤回、點擊回傳——**在實機上零可用**。全部四個方法都會拋 `MissingPluginException`；Dart 端依 SPEC-003 §2.2 的「其他結果視為 `denied`」把它收斂掉，因此 App 不崩潰、畫面正常，只是通知永遠不會出現。

**為何 1159 個測試全綠**：`test/` 用 `FakeScanNotifier` 替換整個 `ScanNotifier`，從不經過真實 `MethodChannel`。這正是 `0.1.0-W3-074` 判定「跨邊界功能只有 fake 覆蓋、平台端事實零覆蓋」所指的缺口，本案是它的第一個實例化證據。

Dart 端的降級處理（收斂為 `denied` 並記 WARNING）設計正確——沒有它，這個缺陷會是崩潰而非靜默。但也因為降級太乾淨，缺陷在實機上唯一的痕跡就是那一行 log，而該 log 不出現在 `flutter run` console（`developer.log` 只進 VM service 的 Logging stream），必須開 DevTools 才看得到。
