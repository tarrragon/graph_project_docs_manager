## Problem Analysis
<!-- Schema[IMP/Problem Analysis]: 選填（小型 IMP 可留 placeholder；大型 IMP 建議填寫）（.claude/pm-rules/ticket-body-schema.md） -->
BlockedState.plain 無 onDegradedView slot；SPEC-004 §3.6 §1 要求「無可消費的型別表」列渲染降級說明與觸發按鈕（testKey action-domain-degraded-view，W1-035 定案）。domain_view_screen.dart 已留降級接點但註解明寫「BlockedState.plain 尚無 onDegradedView slot」而無法渲染該動作。

WRAP 三問：
W（候選方案）：(1) 加 onDegradedView slot + 按鈕由元件內渲染（採用，符合 SPEC-004 4.23 `plain` 變體表既定契約）；(2) 呼叫端自行包一層額外按鈕在 BlockedState 外部（不採用，違反 SPEC-004 ButtonRow 單一動作列承載規則，且 testKey 契約要求該 key 屬本元件動作列一部分）。
A（機會成本）：擠壓本 Wave 其他 IMP 票的執行順位；本票體量小（單一元件 + arb），機會成本低。
P（最可能失敗原因）：畫面側接線（domain_view_screen.dart 實際傳入 callback）超出本票範圍，若誤以為此票需完整打通退出路徑會越界改 lib/screens/。已依票面約束限定本票只交出 slot，畫面接線另評估是否需要承接票。

## Solution
<!-- Schema[IMP/Solution]: 選填（.claude/pm-rules/ticket-body-schema.md） -->
變更範圍：lib/components/blocked_state.dart、lib/l10n/app_en.arb、lib/l10n/app_zh.arb（+ 生成的 app_localizations*.dart）、test/unit/components/blocked_state_test.dart。

- BlockedState.plain 新增選填 onDegradedView（VoidCallback?）。withDetail 建構子固定為 null（不使用此 slot，符合 SPEC-004 4.23 slot 表）。
- _buildActions：plain 分支中 onDegradedView 非 null 時，於 ButtonRow 追加 AppButton.secondary（label: l10n.useBuiltinSchemaAction，testKey: action-domain-degraded-view），沿用既有 ButtonRow 單一動作列承載規則，無本地 Wrap 繞道。
- 新增 l10n key useBuiltinSchemaAction（en/zh 皆已翻譯，非空欄），對應 SPEC-004 §4.0.6 新 key 總表既定 key 名。
- 六個既有 BlockedState.plain 呼叫點（main.dart、domain_view_screen.dart ×2）未傳 onDegradedView，維持 null，行為不變。

範圍邊界：畫面側接線（Domain 視圖實際傳入 onDegradedView callback，含 VERSION 條件判斷與 badge-domain-degraded-schema 疊加）不在本票範圍，domain_view_screen.dart 的既有註解（第 193-195 行）仍指出該缺口；未動 lib/screens/ 與 lib/app/。是否需要承接票由 PM 於本票 NeedsContext 或後續 Wave 規劃裁決。

### 自檢結果

- Phase 4 結論：本次改動為單一元件的可選 slot 擴充，語意單純、無新增分支複雜度，程式碼品質 A；未發現需重構的周邊技術債務。
- 測試設計依 test-assertion-design E1：新增「不傳 onDegradedView」對照組斷言 action-domain-degraded-view 不渲染，「傳 onDegradedView」斷言渲染，另補互動測試斷言 callback 恰呼叫一次。
