## Solution
<!-- Schema[IMP/Solution]: 選填（.claude/pm-rules/ticket-body-schema.md） -->
建立 .claude/hooks/variable-count-literal-guard-hook.py（PostToolUse Bash matcher，
git commit 成功後觸發，INFO 級不阻擋）：

- 掃描範圍：.claude/rules/、.claude/references/、.claude/methodologies/、
  .claude/skills/*/SKILL.md（規則 10「適用情境」表）。
- 只掃描本次 commit 的新增行（git show --unified=0 HEAD -- <file> 解析
  hunk header 推算新檔行號），非全檔掃描。
- 偵測 pattern 沿用規則 10 原文字元類別，補 \s* 容許數字與單位間的
  排版空格（實測發現「714 檔」「1607 個」等既有寫法數字與單位間有
  半形空格，原文 pattern 逐字套用會漏放）。
- 例外過濾（規則 10 例外表 + 既有 stale 規則慣例）：變更歷史 /
  Version footer 行、規則編號與 error-pattern ID（規則 N / PC-N /
  IMP-N / ARCH-N / DOC-XXX-N）、版本號（x.y.z）、量測記錄標記
  （量測環境 / 實測）。
- meta 自我引用豁免：commit 含本 hook 自身路徑改動時不觸發（沿用
  skill-cli-sync-check-hook.py 既有模式）。
- subagent 環境早期跳過（is_subagent_environment，PC-V1-004 防護）。
- 已註冊至 .claude/settings.json PostToolUse Bash matcher（緊接
  skill-cli-sync-check-hook.py 之後），JSON 語法與 hook-completeness-check
  皆確認通過（本 hook 出現在「已註冊」清單，非「未註冊」清單）。

Dogfooding：對最近 30 個 commit 的 diff 重放掃描邏輯，範圍內檔案無
命中（history 樣本不足以驗證真實案例，但確認掃描流程對真實 commit
資料不拋錯）；核心行為改用單元測試涵蓋命中/豁免/範圍邊界共 26 案。
