## Problem Analysis
<!-- Schema[IMP/Problem Analysis]: 選填（小型 IMP 可留 placeholder；大型 IMP 建議填寫）（.claude/pm-rules/ticket-body-schema.md） -->
### 問題根因

SPEC-001 §7 定義專案切換浮層三個狀態（收合／展開／無最近專案）；`lib/app/shell.dart`
先前只有本地 `_isSwitcherOpen` bool 與固定零項的 `SwitcherOverlay`，未接
最近專案清單，且 `ProjectSwitcherEntry` 未傳 `projectName`。SPEC-004 §3.6
逐狀態元件組合、SPEC-003 §3.7 互動反應表、§4.8／4.9／4.27／4.42 契約皆已
到位，缺的是資料層（fixture provider）與 shell 接線。

### 影響範圍

新增 `lib/screens/project_switcher/`（provider + 組裝函式），修改
`lib/app/shell.dart` 的 overlay slot 接線；不涉及 `lib/components/`。

### 相關 Error Pattern

無新增；沿用既有元件契約（無需修改元件庫本身）。

## Solution
<!-- Schema[IMP/Solution]: 選填（.claude/pm-rules/ticket-body-schema.md） -->
新增 `lib/screens/project_switcher/project_switcher_providers.dart`：
`RecentProjectFixture` 資料類、`switcherOpenProvider`（StateProvider<bool>）、
`currentProjectIndexProvider`（StateProvider<int?>，預設 0）、
`recentProjectsProvider`（Provider<List<RecentProjectFixture>>，3 筆 fixture，
其中 1 筆 `enabled: false` 覆蓋 disabled 狀態）、`currentProjectNameProvider`
（衍生 provider，索引越界或空清單回傳 `null`）。

新增 `lib/screens/project_switcher/project_switcher_overlay.dart`：
`buildProjectSwitcherOverlay({context, ref})` 依 ticket how 句型組裝
`SwitcherOverlay`——`items` 由 fixture 逐筆轉 `RecentProjectItem`（health
badge 僅 `healthIssueCount > 0` 時傳、disabled 項帶 `reason`）、`chooseOther`
為 `AppButton.text`（label 依 items 是否為空切換 `switcherChooseOtherFolder`
／`switcherChooseFolderPrompt`）、`testKey` 依 items 是否為空切換
`state-switcher-expanded`／`state-switcher-no-recent`。收合態不經此函式——
`shell.dart` 只在 `switcherOpenProvider` 為 `true` 時呼叫。

修改 `lib/app/shell.dart`：移除本地 `_isSwitcherOpen` 與
`_toggleSwitcher`/`_dismissSwitcher`，改讀 `switcherOpenProvider` 與
`currentProjectNameProvider`；`ProjectSwitcherEntry` 補 `projectName` 傳入；
`overlay` slot 改呼叫 `buildProjectSwitcherOverlay`。只動 overlay 接線，
未碰 `lib/components/`、tokens、SPEC、pubspec。

三個狀態的退出路徑（開合、Esc、點外部、選擇項目）皆委由既有元件
`SwitcherOverlay`／`RecentProjectItem`（W1-005 已實作 Esc／點外部／焦點
限制）承載，本票只接資料與 callback，未新增互動邏輯。
