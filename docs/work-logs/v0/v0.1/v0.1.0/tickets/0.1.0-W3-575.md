## Problem Analysis
<!-- Schema[ANA/Problem Analysis]: 必填（.claude/pm-rules/ticket-body-schema.md） -->
### 問題根因

`0.1.0-W3-545` 在 doc 線查出「條文改動新增字面 → 題幹可純字面對到判定表某一列」的通路形態，並順帶指出 ux 線有同型且**方向相反**的風險：三次 ux 條文改動（`0.1.0-W3-541`、`0.1.0-W3-536`、`0.1.0-W3-566`）全部晚於現行全部 ux 題幹的產生時間，通路若成立，成因是**條文採用了既有題幹的用字**，不是題幹湊近條文。

方向相反使後果更嚴重：doc 線的 19c(a) 只是單題鑑別力歸零；ux 線的三次改動都是「改文後重測、以讀數判條文有沒有生效」的實驗變因，通路成立即代表讀數與條文效力之間多了一條無法排除的替代解釋。

**時序已逐檔查核**（題目檔為 scratchpad untracked，以 mtime 為證；條文改動以 commit date 為證）：

| 題幹批次 | 產生時間 | 三次改動 | 提交時間 |
|---|---|---|---|
| b6／b9／b12／b14／b15 ux 題組 | 2026-09-16 10:11～17:12 | `a0ab92a94`＋`e8f3bd0e6`（W3-541） | 2026-09-17 11:10／11:13 |
| b17-A1／A2／A3 | 2026-09-17 09:32／09:32／09:33 | `45eab74ef`（W3-536） | 2026-09-17 12:30 |
| b18-A1 | 2026-09-17 09:52 | `27ce38ed`（W3-566） | 2026-09-17 14:22 |
| b19-A1 | 2026-09-17 10:16 | — | — |

b17-A2b／A3b（10:03）、A2c／A3c（10:40）亦全數早於 11:10。`-post`／`-gate` 檔雖晚於改動，但與凍結原檔逐行只差第 3 行的條文基準 commit 字串（`0.1.0-W3-550`／`0.1.0-W3-567` 各自已程式比對確認），題幹本身未動。**三次改動皆晚於全部題幹，無一例外。**

### 影響範圍

- 受檢條文：`.claude/skills/ux-design-evaluation/references/interaction-feedback-component-semantics.md` 的「八項判準」章節（探針餵入的節錄範圍）
- 受檢題幹：餵入該節錄的全部 ux 題目檔 65 份，去重後為 **35 題**（同一題號在多批次重複出現且題幹逐字相同者合併為一列）
- 下游：`0.1.0-W3-550`（A3 軸 3/3、六輪否決全引條文句）與 `0.1.0-W3-567`（硬案 8.2(4) 取回 0/3→3/3、前置關句 6/6 引用）的核心結論，在本票判定前為暫定

**已驗證的事實**：三次改動的逐 commit diff、35 題的逐題新增命中與消失命中、每個新增命中在改動後條文中的出現次數與所在款次、W3-550 六輪與 W3-567 六輪的作答原文。
**仍未驗證的假設**：本比對法只量**字面**，不量**結構對應**（見〈方法的已知盲區〉）。

### 相關 Error Pattern

`test-assertion-design-rules` 規則 E1（明示旗標必須有對照測試）與 E2（守衛的測試必須含正向對照輸入）同型：條文在題幹字面射程內寫出界定句，等同把答案印在考卷上；此時「讀者讀懂了規則」與「讀者對到了字」在作答外觀上不可區分，與 E1 所治的「傳與不傳結果相同」是同一個失效形態。`PC-165`（測試綠燈不等於 Runtime 正確）為近鄰但不同軸。

### 比對法（可複驗，沿用 W3-545 並收窄目標）

取題幹全部長度 2 至 12 的連續子字串（首尾為標點、數字或拉丁字母者剔除），逐一檢查是否**逐字**出現於目標字串；只保留極大命中（不被更長命中包含者）。新增命中＝命中改動後目標但不命中改動前目標者；消失命中為反向。

**目標字串收窄為「八項判準」章節**（`## 八項判準` 起至 `### 三段鏈式範例` 前），即探針實際餵入的節錄範圍，而非整份條文檔。此收窄有一項副作用是本票所需：由於前後兩份目標的唯一差異就是該次改動的文字，**任何新增命中在構造上必然落在該次改動新增的句子裡**，不需另行標定位置即可確保命中屬該次改動。

三次改動各取一組 before／after：

| 改動 | before | after |
|---|---|---|
| W3-541 | `a0ab92a94^` | `e8f3bd0e6`（兩筆 commit 合為一次改動） |
| W3-536 | `45eab74ef^` | `45eab74ef` |
| W3-566 | `27ce38ed^` | `27ce38ed` |

**逐題而非逐檔**：b6／b9／b12／b14／b15 的題目檔每份含多題，且各題的餵入射程不同（只讀第 2 項／只讀第 7 項／只讀第 8 項／複合）。逐檔比對會把不同射程的題混在一起，故改以 `### UX-` 區塊為單位拆題，並記下各題自己的餵入欄。

**射程過濾**：一個新增命中要構成通路，該命中所在的款次必須在該題的餵入射程內。W3-541 的新增全部落在 8.2(3)；W3-536 的新增分落 7.2(3-2) 與 8.3(5)；W3-566 的新增落在 8.2(2)。故「只讀第 2 項」的題對三次改動全部射程外，命中數再多也不構成通路。

### 方法的已知盲區

本法逐字比對，量不到**結構對應**——條文的枚舉順序與題幹的敘述順序逐項對齊、但用詞全換。`7.2(3-2)乙`（輪廓走法：由哪幾條線構成、幾條、直的還是彎的、往內側還是外側彎、在哪裡相接、相接處是不是角、有幾個角、閉不閉合、輪廓之內還有沒有別的線）與 b19-A1 題幹對兩枚圖示的描述逐項可對應，但兩側幾乎沒有共用字串（本法對該題只驗出「各自寫出」「它畫的是」「整體的」三項）。`0.1.0-W3-536` 的 commit message 自陳「五道新防線皆對應 `0.1.0-W3-546` 硬案的實際作答讀數」，即該款是照著硬案的作答寫的。此軸不在本票射程內，另票承接。
