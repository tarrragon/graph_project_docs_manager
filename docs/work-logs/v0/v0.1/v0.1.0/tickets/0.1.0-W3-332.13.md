## Problem Analysis
<!-- Schema[ANA/Problem Analysis]: 必填（.claude/pm-rules/ticket-body-schema.md） -->
### 問題根因

九張子票（.2–.10）產出合計：六張審查（.2–.7）共 163 個需範例位置 + 既有範例判定，三張走查（.8–.10）共 35 個猜測點。同一決策點在不同 skill 以不同面貌重複出現（例：退出路徑是層級還是目的地，見 .2 #14 與 .6 #3），且走查的猜測點與審查的位置可能指向同一 spec 缺口。不去重即建票會造成：(1) 同一缺口修成多處，(2) 漏讀被當成缺口修，(3) 修補順序錯亂（矛盾條文未統一就補範例）。

- 六張審查涵蓋：component-contract-design (.2)、tdd/test-assertion-design (.3)、component-library-spec-template (.4)、dart-style-guardian (.5)、ux-design-evaluation (.6)、foundation-design/version-bootstrap (.7)

- 已處置排除：W3-334（掃描器 regex）、W3-333（ARCH-017 檢查時點）、chained-examples 退出路徑範例（commit 67bef8b1 前）

- 同一缺口在不同 skill 出現（例：退出路徑是層級還是目的地，見 .2 與 .6）→ 合併為一列，列出全部來源（子票號＋位置錨點）
