### 六類分類（修補順序即排列順序）

| 序 | 類別 | 判定 | 處置方向 |
|----|------|------|---------|
| 1 | 原文矛盾 | 同一 skill／spec 內或兩者之間說法互斥 | 先統一原文；未統一前，同位置的範例與引導修補一律阻擋 |
| 2 | spec 缺描述 | 走查類「spec 未描述」「spec 間矛盾」，以及「SPEC-004 無上游出處」與「僅有 SPEC-004 自我核定出處」 | 補 SPEC-001／003，或把 SPEC-004 的決策回寫上游 |
| 3 | skill 缺引導 | 決策點沒有文字約束 | 補規範條文（子票已附草稿者引用草稿） |
| 4 | skill 缺範例 | 有約束但會讀出兩種以上做法 | 依 chained-examples 補三段鏈式範例 |
| 5 | 既有範例改寫 | 子票判「需改寫」或「應刪除」 | 依規格改寫或刪除 |
| 6 | 非缺口 | 漏讀、走查方法造成的偏差（例：盲推導沒有元件目錄而自造元件名，但其中路徑 A 的真實缺口歸第 3 類，見父票 .9 審查紀錄） | 不建票，記豁免理由 |

### 去重規則

- 同一缺口在不同 skill 出現（例：退出路徑是層級還是目的地，見 .2 與 .6）→ 合併為一列，列出全部來源（子票號＋位置錨點）
- 走查猜測點與審查位置指向同一決策點 → 合併，走查證據補在該列
- 只合併同一決策點，不合併「同類型但不同決策點」

### 產出（寫入本票 Solution，不建票）

1. **缺口總表**：編號｜類別｜合併描述｜全部來源｜修補對象（skill 或 spec 檔）
2. **修補票規劃表**：以修補對象為單位分票（一個 skill 或一份 spec 一張），每張列：涵蓋缺口編號、票型（DOC／IMP）、前置票（第 1 類阻擋第 3–5 類）。避免兄弟票多前驅（ARCH-017：每張最多一個前驅兄弟）
3. **用戶裁決清單**：每項列出問題、選項、各選項後果。已知待裁決項：
   - dart-style-guardian 等語言專屬 skill 是否適用「禁程式語法」（.5 提出）
   - 範本佔位文字是否算範例、需否技術中立（.4 提出）
   - v02-walkthrough 改寫或刪除（.7 提出）
   - skill 內矛盾兩方以何者為準（F15、F19、X5、時間門檻等，逐項列出）
4. **複驗草擬**：修補後以探針複驗的批次、題目與判定門檻（比照 W3-302：門檻於派發前寫死，同批題目修補前後逐字相同）
