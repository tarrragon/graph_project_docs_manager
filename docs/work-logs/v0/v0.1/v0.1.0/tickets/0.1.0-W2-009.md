## Problem Analysis
<!-- Schema[IMP/Problem Analysis]: 選填（小型 IMP 可留 placeholder；大型 IMP 建議填寫）（.claude/pm-rules/ticket-body-schema.md） -->
### how 欄與 SPEC-001 §1 比對
本票 how 欄要求「先判定與 0.1.0-W2-008 的範圍關係」，W2-008 已完成且範圍是頁首
`SplitRow.header` trailing（per-screen，SPEC-004 §3.6 §1/§4/§5/§6 表），與本票的
「返回列」（SPEC-001 §1 降級註記 (4)：徽章由頁面框架於返回列同一列常駐渲染）
位置與生命週期不同，維持獨立不合併，符合 how 欄描述的第二種選項。

進一步查 SPEC-004 §4.27 AppShell〈實作註記〉：「返回列」實際實作不在
`lib/app/shell.dart`，而在 `lib/components/app_shell.dart` 的 `_MainArea`——
該處已有「`returnTo` 非 `null` 時渲染返回鍵」的既有列，且該節明文「降級徽章
`badge-<screen>-degraded-schema` 比照同一實作方式，與返回列同一列疊於
`IndexedStack` 內容之上」。故本票實際改動落在 `lib/components/app_shell.dart`
（既有返回列容器的擴充）而非 `lib/app/shell.dart` 本身——where.files 的路徑
記載有落差（likely 因該檔為呼叫端，容易誤植為實作處），已依 SPEC 現行內容
為準改動正確檔案，並記錄於此。

### 範圍限制的處置
降級旗標 `isDegraded` 目前只存在於 `lib/screens/domain_view/domain_view_state.dart`
（畫面內狀態），跨畫面容器讀不到。依指示不觸碰 `lib/screens/domain_view/`／
`lib/screens/ticket_list/`（另兩票並行修改中），故將旗標提升為 `lib/app/`
層級的新 provider `degradedSchemaProvider`（`lib/app/degraded_schema.dart`），
比照既有 `returnToProvider` 模式，由 `components.AppShell` 直接
`ref.watch` 讀取（不經 `shell.dart` 轉手，與 `returnToProvider` 讀取方式一致）。

**寫入端（畫面觸發降級後寫入此 provider、切換專案時重置）本票未接線**——
`domain_view_screen.dart` 檔頭本已註記依賴本票建立容器、且明示「不在頁面層
繞路自製」；now 容器已就位，但寫入端接線需要修改 `lib/screens/domain_view/`，
超出本票被授權的範圍。此為刻意的範圍切割，非遺漏，已記錄於 Spawn Requests。

## Solution
<!-- Schema[IMP/Solution]: 選填（.claude/pm-rules/ticket-body-schema.md） -->
### 修改內容
1. 新增 `lib/app/degraded_schema.dart`：`degradedSchemaProvider`
   （`StateProvider<bool>`，預設 `false`），比照 `router.dart` 的
   `returnToProvider` 慣例——單純資料態、無寫入端接線（見 Problem Analysis）。
2. `lib/components/app_shell.dart`：
   - `AppShell.build` 新增 `ref.watch(degradedSchemaProvider)`，傳入 `_MainArea`。
   - `_MainArea` 新增必填欄位 `isDegraded`；返回列容器渲染條件由
     `if (returnTo != null)` 擴為 `if (hasBackAction || isDegraded)`，使
     `isDegraded` 為真時即使無來源記錄也常駐渲染。
   - 返回列內部由單一 `Align(centerRight)` 改為 `Row(spaceBetween)`：
     左格為 `Badge.tag(key: badge-<screen>-degraded-schema, label:
     l10n.degradedSchemaBadgeLabel)`（`isDegraded` 為假時為
     `SizedBox.shrink()`），右格為既有返回鍵（`hasBackAction` 為假時同樣
     `SizedBox.shrink()`）——兩者互不覆蓋，皆存在時徽章置左、返回鍵置右。
3. `test/unit/components/app_shell_test.dart`：新增四類測試——
   - 六個目的地逐一驗證 `degradedSchemaProvider` 為真、`returnTo` 為
     `null` 時，對應 `badge-<screen>-degraded-schema` 存在、
     `action-<screen>-back` 不存在（六畫面任一狀態常駐，acceptance 2）。
   - 旗標為假時徽章不渲染。
   - 旗標為真且 `returnTo` 非 `null` 時，徽章與返回鍵同列並存且不重疊
     （`badgeRect.right <= backRect.left`，acceptance 3）。
   - 既有「returnTo 非 null / null」兩則測試維持原斷言不變，全數綠燈
     （acceptance 3 的「既有測試維持綠燈」）。

### 未接線的寫入端
`degradedSchemaProvider` 的寫入（畫面觸發降級後設真、切換專案時重置）需要
修改 `lib/screens/domain_view/`（觸發點）與 `lib/screens/project_switcher/`
（重置點），依派發範圍限制本票不觸碰，已於 Spawn Requests 建議後續票。
