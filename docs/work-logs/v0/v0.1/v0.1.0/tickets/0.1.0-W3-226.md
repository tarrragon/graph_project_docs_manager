### 對 #60 的實質修正（本票的主要產出）

#60 body 把建立端診斷為「framework-issue/SKILL.md 從未規範 closed_by 填法」。該描述成立但不是值能寫進去的原因，照它修不會關掉洞：

- 真正的寫入路徑是 lifecycle.py 的分歧驗證。REQUIRE_TICKET_ID 側（superseded_by / duplicate）驗格式且驗存在；ALLOW_NONE 側（requirement_vanished / cancelled_by_user）對 resolved_by 零驗證
- 故 #60 的建議方向「放寬值域 + SKILL.md 補填法」若照做，洞仍在——落在新值域內的值不報警，落在外面的自由文字照樣寫得進去、照樣每 session 報警
- 正確的兩端是「guard 值域 + close 對 ALLOW_NONE 分支補值驗證」；SKILL.md 屬引導層，不構成執法

第二項修正是放寬對象有兩類、性質相反：framework issue ref 可解析可驗證，跨 consumer ticket ID 兩者皆不能。以單一字元類一併放寬，等於由值域規則主動授權一類永遠無法滿足參照完整性的引用進入 closed_by——正是 PC-MON-002 判定為缺陷的形態。已列三個方向供上游取捨（只放寬 issue ref／分層標示／移交一律轉譯為 issue ref），未主張哪個。
