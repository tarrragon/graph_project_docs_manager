## Solution
### 結論

起草〈判定不拆分 Module〉判準：兩項條件（單一 UseCase 進入點；計入行數的替身設置全屬該 UseCase 步驟會呼叫的外部依賴）都可查證成立時判不拆；任一不成立或無從查證，照表列動作考慮拆分 Module。TDD-11a、TDD-11b 答案鍵的判定不變，反例 X 仍判否。編排型 UseCase 判不拆，3 個判否反例都判「不適用不拆」。推論主幹屬新判準，需用戶決定 6 點。

### 判準草稿（新段，接在〈多訊號同時成立時〉段之後；不含例示）

**判定不拆分 Module**（到達「考慮拆分 Module」時適用；單一 Given 訊號，或〈多訊號同時成立時〉移除後仍 > 10 行 Mock，皆同）：下列兩項條件都能從測試程式碼或題設逐項查證成立時，判定 Given 設置的長度來自受測 UseCase 串起的外部依賴，不是 Module 過大，不拆分 Module：

1. 受測 Module 對外只有一個 UseCase 進入點：該 Module 的所有 BDD 場景，When 都呼叫同一個 UseCase 進入點。
2. 計入 Given 設置行數的每一行替身設置，都屬於該 UseCase 某個流程步驟會呼叫的外部依賴。沒有任何流程步驟呼叫的外部依賴：建構受測對象不需要它時，其設置行先刪除、不計入行數；建構受測對象需要它時，本條件不成立。

任一條件不成立，或無法從測試程式碼或題設查證，依「Given 設置過長」列動作考慮拆分 Module。表中「步驟正確性由串接決定」一列只決定該步驟留在整合測試，不構成條件 1 或條件 2 成立的依據。判定不拆時，重複的設置依〈常見挑戰速查〉抽到 Test Helper／Builder，抽出的行仍計入行數。

配套改文：

- 〈多訊號同時成立時〉段末句「才考慮拆分 Module」後補：「，並依〈判定不拆分 Module〉判斷」。

### 需用戶決定之點

1. **條件 1 的判據**：(i) 單一 UseCase 進入點（機械可查；單一進入點以旗標分派兩流程時會誤判不拆）；(ii) SRP「需要用『和』連接描述」（phase1 有出處，但主詞是功能，而且列舉步驟時也會出現「和」，逐詞推導不唯一）。傾向 (i)。
2. **是否設外部依賴數上限**（例如編排 9 個外部服務仍判不拆）。無出處；cognitive-load「依賴模組數 > 3」的主詞是任務拆分，不能直接引用。傾向不設。
3. **條件 2 刪除子句是否保留**（建構不需要的依賴，設置行先刪、不計入）。傾向保留：與 B1 同型；若刪去，Builder 殘留會把 Module 誤判為過大（N3）。
