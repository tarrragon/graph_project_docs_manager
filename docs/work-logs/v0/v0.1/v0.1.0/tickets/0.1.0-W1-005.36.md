## Solution
<!-- Schema[IMP/Solution]: 選填（.claude/pm-rules/ticket-body-schema.md） -->
`Toolbar` 依 SPEC-004 4.32（十一欄位）與 5.6（子件契約、排列不變式）實作於
`lib/components/toolbar.dart`：`SearchField`（`Expanded` 吸收剩餘寬）+
`filters`（`List<Widget>`，1..3；`FilterDropdown` 由並行票 `0.1.0-W1-005.xx`
建立，尚未存在前以 `Widget` 承接，dartdoc 已註明，與 `AppButton` 慣例一致）
+ 可選 `marker`（`IssueMarker.damagedDetail?`，末格）水平排列，子件間以
`Space.sm` 分隔（呼叫端不得覆寫，無公開參數可覆寫間距）。容器自身高固定
`LayoutSize.hitTargetMin + 2 × Space.xs`，底邊框 `AppColors.borderStrong`，
外部另加 `Space.sm` 底部留白（`Padding.bottom`，5.6 排列不變式外的獨立間距
語意，不計入固定高）。`filters` 數量以 `assert` 收斂 1..3（SPEC-004 5.6
子件契約），空清單或 > 3 時建構期即拋出。無障礙：`Semantics(container: true)`
包裹整體，label 由子件承載（4.32 無障礙子節）。`lib/components/components.dart`
依既有慣例追加一行 `export 'toolbar.dart';`，未重排既有行。

契約值（十一欄位、5.6 三項不變式）實測皆成立，未修改 SPEC-004。

### 自檢結果

- Package 導入：`lib/components/toolbar.dart` 僅相對匯入同目錄與 `../tokens/`，
  符合既有元件（`button_row.dart`、`search_field.dart`）慣例，無跨層絕對路徑違規。
- 命名／五行原則：單一 `build` 方法約 25 行，含子件組裝迴圈與巢狀容器；
  未進一步拆分函式，因邏輯線性且無重複分支，符合認知負擔閾值（指數 <= 10）。
- 常數管理：零裸值，尺寸（`LayoutSize.hitTargetMin`、`Space.xs`、`Space.sm`）
  與色彩（`AppColors.borderStrong`）皆取 `lib/tokens/tokens.dart`。
- 測試設計：無計時斷言、無外部服務、無 `DateTime.now()`、無隨機輸入，
  符合 test-assertion-design-rules D1–D4。
- 可觀測性：`StatelessWidget` 無 catch 區塊，無需日誌；無平台互動。

**Phase 4 結論**：程式碼品質 A（風格與既有 `ButtonRow`/`Section` 一致，
零裸值，assert 收斂 slot 契約）；無技術債務發現；無需重構。
