### Rationale Chain
- 0.1.0-W3-056 why: 現行契約把 hover／pressed／focused（來源：輸入裝置、本地瞬態）與 selected／loading／error（來源：store、有同步問題）混在同一張狀態矩陣，沒有「來源」與「同步策略」維度；回饋通道只定義「按下」一種事件；「系統主動把注意力帶到元件」（scroll-into-view 高亮、新項閃爍）與「資料態 X→Y 當下的提示」是狀態圖的邊而非節點，現行十一欄位無處承載。用戶要求元件庫同時考慮呈現狀態與處理狀態的同步、hover／點擊／定位／狀態變更四類提示、以及 web／app／CLI／桌面系統通知等通道差異，並與狀態管理系統銜接。方法論是判準權威，範本與 skill 皆自它推導，故先改此處。
- 0.1.0-W3-057 why: 範本是契約的產物形狀；方法論升格第十二欄後，範本若無對應子節與欄位，skill 的填寫問句會問到範本沒有格子的東西。範本既有「互動反應」子節（互動／反應／動畫／時間門檻）標為額外承載，是升格的自然落點；狀態矩陣現缺 hover／pressed 列且無來源欄。
