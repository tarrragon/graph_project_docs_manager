## Solution
<!-- Schema[IMP/Solution]: 選填（.claude/pm-rules/ticket-body-schema.md） -->
依 SPEC-004 §4.6 契約實作 `IssueMarker`，三具名建構子（`damagedEdge` /
`damagedDetail` / `gap`）對應三變體，無 `disabled` 態（跳轉破洞報告恆可用）。

### 實作要點
- 三變體皆以 `Semantics(button: true, ...)` + `InkWell(excludeFromSemantics: true)`
  承載可點性；命中區以 `ConstrainedBox` 補足 `LayoutSize.hitTargetMin`。
- `damagedEdge`：`MergeSemantics` 包住 `Semantics(label: damagedEdgeMarkerLabel)`，
  讓 child 既有語意標籤與本元件標籤合併為一節點（依 4.6 無障礙子節「{child 標籤}，
  damagedEdgeMarkerLabel」）；child 文字色不覆寫（維持 textPrimary，依契約）。
  虛線框以 `CustomPaint`（`_DashedBoxPainter`）四邊繪製，樣式沿用
  `section.dart` 既有 `_DashedTopPainter` 慣例延伸至四邊。
- `damagedDetail`：label 手動組字 `{damagedDetailMarkerLabel}, {count 或
  explanation}`（純圖示形態無 suffix）；內容為 `AppIcon`（warning，error 色）+
  可選 `Badge.count` + 可選說明文字（`AppColors.error`、`AppFontSize.caption`，
  單行截斷）。
- `gap`：虛線框（同 `_DashedBoxPainter`）+ `gapMarkerLabel` 文字，label 即該文字。
- 顏色/間距/圓角/字級全數取 `lib/tokens/tokens.dart`，零裸值。

### 契約值變動
無。SPEC-004 §4.6 十一欄位契約值全數已由 W1-058/059/060 核定，實作直接依循，
未發現契約值實測不成立需回改條目。

### 命名與型別偏離說明
- `child` slot 契約標「必填型別 RelationItem」，但 `RelationItem` 元件尚未建立
  （非本票範圍）。實作型別放寬為 `Widget`（向前相容：`RelationItem` 建立後可
  直接傳入，無需改 `IssueMarker` 簽名）。此為型別層面的前瞻相容處理，不影響
  契約行為，未回改 SPEC-004。
