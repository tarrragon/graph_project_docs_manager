- 0.1.0-W3-319 why: 0.1.0-W3-315 裁定驗證器改為錨定本專案前綴（尾碼放寬為非空 [a-z0-9]+），但該修法**不觸及**兩件事，且兩者會因該修法而變得更急：

1. **子代理人無合法取值管道**：ListAgents 對 subagent 不可得，pm-registry.json 的 session 條目無序號欄。目前唯一通道是派發者代填，實測至少三次派發漏填或不填，成本延後到 curator 執行時才顯現，只能降級 observe。
2. **尾碼有兩個命名空間**：PM 用的短名尾碼為兩碼形態（如 -5d），而子代理人可從 scratchpad 路徑推得 session uuid 前綴（如 -dcead428），觀測流中已出現該形態的 owner 值。現行純數字驗證器把兩者一併擋掉，錨定前綴後**兩者會一併通過**——同一前綴下並存使「哪一次 session 寫的」語意失效。

因此 0.1.0-W3-315 的結論是 A（驗證器）與 B（本票）不可分開出貨：A 單獨落地等於主動製造一個新的不一致。（來源已完成，結論見 Solution）
