## Solution
<!-- Schema[IMP/Solution]: 選填（.claude/pm-rules/ticket-body-schema.md） -->
### 實作
`SearchField`（`lib/components/search_field.dart`）依 SPEC-004 4.12 十一欄位實作：受控 `value`/`onChanged`，防抖動用 `Motion.searchDebounce`，清除或刪至空立即呼叫、不等防抖動，IME 組字中不觸發。狀態矩陣 empty/filled/focused 三態；focused 邊框 `AppColors.accent`（依 §4.0.1）。搜尋圖示 `textDisabled` 純裝飾（`ExcludeSemantics`），清除鈕自訂 `Semantics.button` + `searchClearAction`，輸入框自訂 `Semantics.textField`（label 固定為 placeholder、value 為目前值）。尺寸：外層 `SizedBox(height: LayoutSize.hitTargetMin)`，寬填滿父格位（Toolbar 首格）。全數色彩/間距/字級/圓角/動畫取 `lib/tokens/tokens.dart`，無裸值。

`components.dart` 追加一行 export，未重排既有行。

### 除錯過程（自查發現，非既有 error-pattern）
首輪測試「輸入後 pump 前 onChanged 零次」失敗（expected 0 actual 1）。用最小重現腳本定位：`_focusNode` 取得焦點時，`TextEditingController` 收到平台送回的初始 editing state（text 仍為空但 `selection` 從無效值變為 collapsed(0)），`ValueNotifier` 判定為值變更而通知 listener；原實作只看 `text.isEmpty` 就視為「清空」並立即呼叫 `onChanged('')`，因此在使用者尚未輸入前就誤發一次呼叫。

修復：新增 `_lastKnownText` 追蹤上一次「文字實際變更」的值，`_handleTextChanged` 先比對 `text == _lastKnownText`，相同則視為純選取/焦點同步、不觸發 `onChanged`/計時器；不同才進入既有的組字檢查與防抖動/立即呼叫邏輯。修復後 19 個測試全綠，含「輸入後 pump 前零次」與「連續輸入只呼叫一次」兩項。
