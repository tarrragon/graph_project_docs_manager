# Execution Log

## Task Summary

修 W3-030 三節外移造成的三處跨檔指涉失效：writing-the-body.md:5 與 frontmatter-and-description.md:5 的檔頭「同目錄」段仍寫〈三類 bundled resource 的分工〉留在 SKILL.md（該節已搬至 creating-and-adopting-skills.md）；writing-the-body.md:166 的「SKILL.md〈Opinionated Defaults — 預設路徑引導正確做法〉」為死名（該節已搬至 patterns-and-troubleshooting.md）

---

## Problem Analysis
### 問題根因

W3-030 依 (a) 判準把三節自 `SKILL.md` 外移後，兩份 reference 的指涉仍指向舊位置。三處皆為指名式跨檔引用，在目標搬移後成為死名。

### 影響範圍

| 位置 | 舊內容 | 改為 |
|------|-------|------|
| `writing-the-body.md:5` | 檔頭「同目錄」段稱〈三類 bundled resource 的分工〉留在 `SKILL.md` | 指向 `creating-and-adopting-skills.md`，並補上自由度與預設值的新住址 |
| `frontmatter-and-description.md:5` | 同上 | 同上 |
| `writing-the-body.md:166` | 「`SKILL.md`〈Opinionated Defaults — 預設路徑引導正確做法〉」 | 「`patterns-and-troubleshooting.md`〈Opinionated Defaults — 預設路徑引導正確做法〉」 |

### 相關 Error Pattern

無既有 PC 對應。屬 `splitting-an-existing-skill.md`〈拆分特有的必查項〉的「外部引用」類——該表已載明此缺陷型態與查法（全站掃引用並逐條列出），本次即依該程序執行。

**值得留意的機制**：`SKILL.md`〈按需讀取〉的路由表雙向檢查（死名／孤兒節）**對這一類無鑑別力**——它只比對路由表的「涵蓋章節」欄與目標檔的 `##` 標題，不掃各檔檔頭的「同目錄」索引，也不掃正文裡的跨檔指涉。W3-030 當時雙向檢查全綠，三處失效仍然存在。

## Solution
三處依 W3-030 的 SR-2 所給替換文字機械替換，commit 5c84184a。

順帶把兩處「同目錄」段的 `patterns-and-troubleshooting.md` 描述補上「自由度與預設值」，與該檔搬入後的實際內容一致——不補的話該列會少報兩節，讀者依它判斷要不要開那份時會漏。

### 驗證

| 檢查 | 結果 |
|------|------|
| 全 skill 殘留掃描（`三類 bundled resource 的分工〉`、`` SKILL.md`〈Opinionated ``、`` SKILL.md`〈Degrees ``，排除 CHANGELOG 歷史紀錄） | 僅餘 `SKILL.md:95` 路由表指向 `creating-and-adopting-skills.md` 的正確條目，無殘留死名 |
| 兩檔體量複驗（第 3 層單檔判準，皆屬選段查閱） | `writing-the-body.md` 4,101 tok / 最大單節 1,306；`frontmatter-and-description.md` 2,450 tok / 最大單節 512，皆 PASS |
