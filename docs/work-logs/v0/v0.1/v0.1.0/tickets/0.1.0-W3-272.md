## Problem Analysis
<!-- Schema[IMP/Problem Analysis]: 選填（小型 IMP 可留 placeholder；大型 IMP 建議填寫）（.claude/pm-rules/ticket-body-schema.md） -->
根因確認：`lib/topic_inference.py` 的 `validate_topic_selection`（票面稱 `resolve_topic_arg`，現行函式名為前者）在只給 `--no-topic` 時落到最後一行 `return None, None, None`，與「三旗標皆未給」的回傳完全相同。`commands/create.py` 的 `if topic is None: topic, topic_basis = infer_topic(args)` 因此在明示不指派時照樣執行 S1／S2；報告階段的 `elif getattr(args, "no_topic", False)` 分支只在 `topic` 為假（即推導落空）時可達。

既有測試為何全綠：`test_no_topic_writes_no_assignment` 的 fixture 不帶 `source_ticket`，且空票庫下無叢集可供 S2 比對，S1／S2 皆落空——該路徑上 `no_topic` 真假結果相同，旗標完全失效時測試照樣通過。

## Solution
<!-- Schema[IMP/Solution]: 選填（.claude/pm-rules/ticket-body-schema.md） -->
### 形態：falsy 哨兵物件 `NO_TOPIC`

`topic_inference` 新增 `_NoTopicSentinel`（`__slots__` 空、`__bool__` 回 False、`__repr__` 為 `NO_TOPIC`）與模組級單例 `NO_TOPIC`。`validate_topic_selection` 在 `--no-topic` 且無 `--topic`／`--new-topic` 衝突時回 `(NO_TOPIC, None, None)`；「三旗標皆未給」維持 `(None, None, None)`。兩者型別不同，呼叫端可分辨。

定為 falsy 的理由：既有呼叫端以 `if topic:` 判斷「是否有主題可寫入」，明示不指派在該語意下與無主題同義，不需逐處改寫報告與持久化分支。

`create.py` 的推導閘門改為三分支：`if topic is NO_TOPIC: topic = None` / `elif topic is None: 推導` / 其餘（顯式主題）不動。S1／S2 在明示不指派時不執行，非執行後才被報告分支攔截。
