## Problem Analysis
<!-- Schema[DOC/Problem Analysis]: 選填（若 DOC 起因於缺陷或盤點結論可填）（.claude/pm-rules/ticket-body-schema.md） -->
### PM 裁決：不得改任一側題幹；標的是工具與流程，不是題材

b19-A1（UX-Y7b）與 b17-A3 共用題材詞「尖角」，破口在 b19 側（b17 於自查時 hits=0，b19 後續重用）。**兩側題幹都不准改**：

- b19-A1 是 0.1.0-W3-536 的改檔前 baseline，題幹與子問已凍結，改動即作廢該次量測（本輪唯一一組「改檔前落在目標側相反端」的讀數，不可重來）。
- b17-A3c 是 0.1.0-W3-541 的 baseline，同理。

處置：**接受該重疊並登記**，在兩票的 baseline 引用處各註一行「與另一題共用題材詞『尖角』，隔離未達成」。承辦者沒有改工具讓紅燈變綠、也沒有主張隔離已達成，此處置正確，本票延續之。

### 真正的缺陷：isocheck 是單向自查，因此不構成保證

現行流程是「新批次對既有全部題目自查」。這只擋得住新批次撞既有詞，**擋不住新批次把自己的詞留給更後面的批次撞**——先出的題目沒有任何機制得知自己的題材日後被重用。於是「題材零重疊已機械驗證」這句話，對任何一個非最新的批次都不成立。

本線先前每一批都寫過「題材重疊經機械驗證為 0」。那句話在當下為真，在往後未必；**先前所有批次的隔離宣告都須降級為「出題當下為真」**。

本票要做的兩件事：
1. isocheck 改為雙向——新批次落檔後，回頭對全部既有批次重跑一次，命中即在**雙方**的清冊各記一筆。
2. 建一份跨批次題材詞總表（append-only），出題前先查表，取代逐檔 grep。

### 附帶：A3c-r3 的計分爭議依先例處理

承辦者兩種讀法都記了、未擇一隱去，正確。裁決採第一版 J1 對 A2-r3 建立的先例：**正文兩點都判過者計通過，另記「表述不精確」**。理由是先例已在同一軸的前一版生效，此時改採 key 字面會使同軸三版的計分規則不一致。兩種計分下 A3 欄命中數皆為「正面 2、否決 1」，結論不受影響。
