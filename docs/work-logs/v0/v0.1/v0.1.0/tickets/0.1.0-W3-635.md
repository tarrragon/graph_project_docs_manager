## Problem Analysis
<!-- Schema[IMP/Problem Analysis]: 選填（小型 IMP 可留 placeholder；大型 IMP 建議填寫）（.claude/pm-rules/ticket-body-schema.md） -->
### 問題根因
W2-002 需組成 UC Flow「正常」態的事件流小表（SPEC-001 §2、SPEC-004 §3.6 §2），但 `app_table_row.dart` 只有 header/ticket/step 三變體、`app_data_table.dart` 無 appendix slot，兩者皆不存在，無法完成該畫面。

### 影響範圍
`lib/components/app_table_row.dart`、`lib/components/app_data_table.dart`、`lib/l10n/app_zh.arb`、`lib/l10n/app_en.arb`（及其生成的 `app_localizations*.dart`）。消費端（uc_flow_screen）由 0.1.0-W2-010 承接，本票不動 lib/screens/。

### 相關 Error Pattern
無相關既有 error-pattern；本票屬純元件庫補件。

## Solution
<!-- Schema[IMP/Solution]: 選填（.claude/pm-rules/ticket-body-schema.md） -->
### 修改內容

**`app_table_row.dart`**：`_TableRowVariant` 新增 `eventFlow`；新增 `eventFlowColumns`（事件固定寬沿用 ID 欄寬、發出/消費兩填滿欄等分、標記固定寬，SPEC-004 4.35 尺寸契約）；新增 `AppTableRow.eventFlow({event, emittedBy, consumedBy, marker, isLocated})` 具名建構子；新增 `isLocated` 欄位（base 私有建構子預設 `false`，僅 `eventFlow` 對外暴露，`ticket`/`step`/`header` 不受影響，無回歸風險）；`_isTappable` 收斂為僅 `ticket`/`step`（`eventFlow` 非互動，SPEC-003 §3.2 無列點擊條文）；`build()` 對 `eventFlow` 改走非按鈕 `Semantics`（label 為事件/發出/消費/標記朗讀文字串接，container: true，focusable 隨 isLocated）；`isLocated` 為 true 時整列底色 `AppColors.surfaceIconTint`（§4.0.10 高亮 token）。

**`app_data_table.dart`**：`scrollKey` 由必填改 `Key?`（nullable）；新增 `appendix`（`AppDataTable?`，僅 `plain` 接受、0..1、自身不得再帶 appendix、`virtual` 變體或 scrollKey 為 null 時拒絕，三條 assert 對應 SPEC-004 §5.10 slot 契約）；`build()` 依 `scrollKey == null` 分流——為 null 時扮演「他人的 appendix」角色，不建自身 `ListView`，只以 `header` + `rows` 疊放（無 `Expanded`，交由外層捲動）；`plain` 變體的 `_buildRows()` 在 `appendix` 非 null 時於列尾追加 `Space.lg` 間隔 + `appendix!`，仍共用外層唯一的 `scrollKey`（SPEC-004 §5.10「appendix 高固有、隨外層表捲動」）。

**i18n**：`app_zh.arb`（樣板語系）與 `app_en.arb` 新增 6 個 key——`columnEvent`/`columnEmitter`/`columnConsumer`（事件流小表欄首文案）、`eventFlowStepDomain`（{step} · {domain}，發出/消費格組合）、`eventOutsideUc`（本 UC 外 fallback）、`orphanEventMarkerLabel`（孤立事件標記朗讀）。`fvm flutter gen-l10n` 重新生成 `app_localizations*.dart`；確認缺漏僅既有 2 個既存 key（`gapCategoryMissingFrontmatter`/`gapItemLineLabel`），非本票引入。

### 設計取捨
- `eventFlow` 的 semantic marker 朗讀文字直接讀 `(cells[3] as AppIcon).semanticLabel`（呼叫端傳入），不在元件內耦合 `AppLocalizations`——與 `ticket`/`step` 既有 `_semanticLabel` 模式一致（各格文字串接，非另建 l10n 依賴）。
- `AppDataTable` 用 `scrollKey == null` 作為「root 角色」vs「appendix 角色」的判別，不新增額外旗標欄位——與 SPEC-004 §5.10 slot 契約「appendix 內的表不接受 scrollKey」語意直接對應，是最小改動。
- 未觸碰 `ticket` 變體的 `isLocated`（spec 表列出但既有程式碼從未支援），維持原範疇不擴張。
