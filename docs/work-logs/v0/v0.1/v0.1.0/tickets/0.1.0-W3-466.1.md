### 逐則評估

#### TDD-04a

- **出處**：`test-object-catalogue.md`〈六〉「When 與 Then 僅描述規格宣告的觸發條件與可觀察結果」——「僅」已是正向判準：規格條目沒寫的內容不寫；句型「When {來源規格條目描述的觸發動作}」指明 When 取自來源規格條目。`phase2-test-design.md`〈場景設計原則〉「用業務語言描述，不用技術術語」。現行句把正向判準與「不得寫出……（回呼、事件監聽）……（如節點樹結構）」寫在同一句，讀者以禁止列舉為判準，列舉外的 app 旗標即放行（DOC-GPD-007 同型）。
- **草稿問題**：草稿以「是否為使用者可觀測的事實」為 When／Then 共同判準。When 描述的是規格宣告的觸發條件，常不是使用者可觀測的事實（題目正解「儲存請求回傳成功」、〈六〉範例一「前置資料解析完成」皆是），草稿會把正解判不合格。`chained-examples.md`「使用者可觀測的事實」在允許欄，是允許項不是唯一判準。
- **建議改文**（`test-object-catalogue.md`〈六〉，替換「**When／Then 的書寫邊界**：」起至「……具體方法名或選擇器語法」。」止）：「**When／Then 的書寫邊界**：When 只寫來源規格條目宣告的觸發條件（即句型中的 `{來源規格條目描述的觸發動作}`），Then 只寫來源規格條目宣告的可觀察結果；判準是內容是否出自來源規格條目，來源規格條目沒有寫出的內容一律不寫入 When／Then。觸發機制的具體實作方式（回呼、事件監聽）與框架內部表示方式（如節點樹結構）是常見的違反形態，不是完整的禁止清單。用語依 `references/phase2-test-design.md`〈場景設計原則〉「用業務語言描述，不用技術術語」；形態依 skill-design-guide `references/chained-examples.md`〈【驗證】段〉執行期行為形態允許／禁止表：允許「使用者可觀測的事實」，禁止「框架事件 handler 的具體命名」與「框架測試 API 的具體方法名或選擇器語法」。」其後的狀態轉換句不變。
- **逐詞推導**：規格列觸發條件只有「儲存請求回傳成功」。輪詢計時器與 isSaved 旗標都不在來源規格條目內，依「沒有寫出的內容一律不寫入」皆刪；(b) 依「只寫來源規格條目宣告的觸發條件」改為「儲存請求回傳成功」。r1、r2 保留旗標的路徑被「不是完整的禁止清單」與正向判準擋下；r2 把旗標當可觀測結果的路徑被「用語……不用技術術語」擋下。
- **判否反例**：狀態矩陣列「閒置 → 同步中｜觸發條件：使用者點選同步」，草擬 When「使用者點選同步，且本地快取超過五分鐘未更新」。後半句不是實作機制、不是框架表示、也不是旗標，但來源規格條目沒有寫，依改文判「不合格」。對照：When 只寫「使用者點選同步」判合格。反例不含計時器、旗標或儲存語境，與題幹不同構。
- **用戶偏好**：(1) When／Then 是否須逐字取自規格條目，或允許同義的業務語言改寫（改文目前寫「宣告的」，未要求逐字）。(2) 採本改文（正向判準＋例示標註），或依 W3-466 草稿備選改為列舉第三個禁止類別；後者會再次形成封閉列舉，本票不建議。

#### TDD-06a

- **出處**：`layered-test-strategy.md`〈終端回饋訊息的三類驗收（是否出現／內容／可讀性）〉表：是否出現的斷言對象為元件層日誌或元件樹節點，內容為「語系資源查表值、資源檔的靜態屬性、日誌的結構化欄位」、主要形態「單元測試或靜態讀檔；不比對散文字面」，可讀性為「渲染後的版面」、主要形態「widget 測試，含窄幕尺寸」；段末「驗收時三類並行檢查」；檢查清單「各有斷言形態，且未以其中一類的綠燈抵扣另一類」。`test-object-catalogue.md`〈二〉已路由到該節，但路由句與「不得拆成三行」同句相連，目錄列層與斷言層沒有分開。
- **建議改文**（`test-object-catalogue.md`〈二〉第三段「……違反來源唯一（C3）。」之後插入）：「「不得拆成三行」管的是目錄的列數，不管斷言：依同一節檢查清單「各有斷言形態，且未以其中一類的綠燈抵扣另一類」，三類在斷言層各自寫斷言，不合併為一條——該節表列三類的斷言對象與主要形態各不相同（內容為單元測試或靜態讀檔，可讀性為含窄幕尺寸的 widget 測試），合寫成一條斷言時至少一類落在其主要形態之外。」（C3 名稱依 W3-466 已落檔的改名同步，由 W3-466 落檔時核對。）
- **逐詞推導**：題幹 Then「出現提示／文字與語系檔一致／沒有被截斷」分屬是否出現、內容、可讀性三類，(a) 三類；(b) 依「不合併為一條」判否。r1 以「不得拆成三行」推出可合併的路徑，被「管的是目錄的列數，不管斷言」擋下。
- **判否反例**：Then「顯示文字等於該 key 依語系解析後的值，且句中帶入的數量參數等於事件回報的筆數」。兩個條件同屬「內容」一類、斷言對象同為語系資源查表值，依改文不構成跨類合併，判「否」（不違反）。反例只含一類、不含截斷或出現與否，與題幹三類齊備的結構不同。
- **用戶偏好**：三類各自的斷言可否放在同一個測試案例內（三條斷言、一個案例），或須分成不同測試案例。改文只禁止合併為一條斷言；主要形態不同（單元與 widget）暗示分檔，但 test-assertion-design〈問題類型表〉類型 9「一測試案例一行為面向」對三類是否屬同一行為面向沒有明文。

#### TDD-08b

- **出處**：`layered-test-strategy.md`〈分層之外的補位形態〉characterization test：「先對現有程式跑一次、把實際輸出記錄成預期值——斷言對象是「現在的行為」」。事件、串流是呼叫進入點後產生的實際輸出，依此定義屬該次呼叫記錄下的預期值。C2「每個可呼叫的公開進入點一條」決定條目單位；事件本身不能被呼叫。
- **建議改文**（`test-object-catalogue-starting-points.md` 起點 C 步驟 C2，接在「不另立條目。」之後）：「理由：依 `references/layered-test-strategy.md`〈分層之外的補位形態〉characterization test「先對現有程式跑一次、把實際輸出記錄成預期值」，這類輸出是呼叫進入點後記錄下來的預期值，屬該進入點條目；是否另立條目只看它本身是否為可呼叫的公開進入點。」
- **逐詞推導**：`start()` 是公開方法，一條；進度事件由呼叫 `start()` 產生，屬 `start()` 條目的預期值，不另立，共 1 條。r2 自設例外（持續送出、多次觸發、獨立驗收維度）被「只看它本身是否為可呼叫的公開進入點」擋下。改文未列舉 r2 的例外字面，避免與探針答案同構。
- **判否反例**：公開函式 `archive()` 呼叫時寫出一行完成紀錄並回傳檔案路徑。完成紀錄不是可呼叫的公開進入點，依改文「是否另立條目」判「否」。對照：同模組另有以函式實作的公開存取子回傳進度串流，該存取子本身可呼叫，依 C2 另立一條。反例為副作用紀錄加回傳值，不含類別、串流事件與 start 語境，與題幹不同構。
- **用戶偏好**：同一串流同時由公開存取子暴露、又由另一公開方法觸發送出時，串流上的事件記入哪一條（觸發它的方法，或暴露它的存取子，或兩條皆記）。C2 兩個子句在此情形都成立，現行條文與改文都沒有唯一答案。

- **逐詞推導**：題幹只有 Given 設置過長一項訊號成立（條件組合、邊界條件未超過門檻，步驟正確性由串接決定屬「留在整合測試」而非拆出動作）。依格內「本列與表中其他訊號同時成立時」不成立，後置條件不套用，(a) 直接依該列「考慮拆分 Module」；(b) 依「而非加測試」判否。r2 套用 Given 移除步驟的路徑被兩處射程句擋下。r3「若不過大則接受現設計」的分支：格內「Module 過大」是訊號成立後的判定，條文沒有「不過大」分支；改文未新增，理由見用戶偏好 (1)。
- **判否反例**：BDD 整合測試 Given 設置 8 行 Mock，Domain 層有 4 個條件組合的分支。Given 訊號未成立，只有 Domain 訊號一項，依段首射程句判「否」（不適用多訊號段），直接依 Domain 列拆為 Domain 單元測試，不進入拆分 Module 的判斷。對照：Given 15 行 Mock 且值物件 7 個邊界條件，兩項成立，適用本段。反例的單一訊號在 Domain 列而非 Given 列，與題幹不同構。
- **用戶偏好**：(1) 「考慮拆分 Module」是否保留「評估後不拆」的分支；若保留，須寫出不拆的判準，現行條文沒有。(2) 本段依據句「處方的第一順位都不是移動邊界」引自〈Sociable vs Solitary 選擇框架〉，該原則本身不限多訊號；單一 Given 訊號時是否也應先試不移動邊界的處方（例如該框架症狀 1 的「把替身設定集中到一個 test support 模組」），或維持訊號表直接「考慮拆分 Module」。改文採後者（依表），若用戶取前者，射程句要改寫。
