依 W3-417〈用戶裁示與 PM 定義裁決〉PM 定義 2、3：範例區塊外（含跨檔路由，須明文路由才算依據）的既有文字才算條文；「已有權威只欠路由」為階段 1，「條文根本不存在、須新造判準」為階段 2。

- **F-40**（`frontmatter-and-description.md`〈範例對照〉「壞（描述內部架構）」列）：`git grep` 全庫確認「內部架構」「版本號」相關判準只在本列出現，查無其他條文直接說明其壞因。但重讀〈結構公式〉（同檔〈Description 寫作〉節）「[做什麼] + [何時使用 / 觸發詞清單] + [可選：負面觸發]」，該壞例「統一 Ticket 系統 v1.0 — 整合 create / track / handoff / resume / migrate / generate 六大功能」通篇只有「做什麼」與版本號，完全沒有「何時使用」——與「壞（缺觸發）」列（`Creates sophisticated multi-page documentation systems.`）同一個病灶，只是外顯形式不同（內部功能列舉 vs. 泛泛陳述）。判定：階段 1，不是新判準，是既有〈結構公式〉的一次應用，之前只是沒寫出這個連結。
