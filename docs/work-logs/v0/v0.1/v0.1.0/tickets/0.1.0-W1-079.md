## Problem Analysis
<!-- Schema[IMP/Problem Analysis]: 選填（小型 IMP 可留 placeholder；大型 IMP 建議填寫）（.claude/pm-rules/ticket-body-schema.md） -->
### 問題根因

W2-008 驗收時發現 EmptyState.page 的 assert(actions.isNotEmpty) 與 SPEC-004 §4.21
無破洞例外衝突，當場加入 actionsOptedOut: bool（預設 false）。旗標對全體呼叫端
開放，任何未來呼叫端傳 true 即可繞過 FR-03，繞過的正當性無處可查；失效方向為
放行，放行後與本來不需要動作的畫面渲染上不可區分。

### 影響範圍

- lib/components/empty_state.dart（EmptyState 元件、assert 條件、旗標定義）
- lib/screens/gap_report/gap_report_screen.dart（唯一呼叫端，_NoGapsView）
- test/unit/components/empty_state_test.dart（slot 契約測試群）

### 相關 Error Pattern

無直接對應既有 error-pattern；屬 quality-baseline 規則 3「設計問題立即修正」的
延伸收斂，本票 decision_tree_path 已記錄根因與決策。

## Solution
<!-- Schema[IMP/Solution]: 選填（.claude/pm-rules/ticket-body-schema.md） -->
把 `actionsOptedOut: bool` 改為 `pageActionsException: EmptyStatePageActionsException`
（新 enum，成員 `none`（預設，斷言正常生效）/ `actionsRelocatedToHeader`——對應
SPEC-004 §4.21、SPEC-003 §2.7、`0.1.0-W3-335.37` R10 的唯一明列例外）。assert
條件由「呼叫端傳的布林」改為「非 none 即例外」：

```dart
assert(
  variant != EmptyStateVariant.page ||
      actions.isNotEmpty ||
      pageActionsException != EmptyStatePageActionsException.none,
  ...
)
```

新增例外需在 enum 新增具名成員並於文件註解引用對應 SPEC 條款，不可再以泛用布林
隱式放行——這把「有明確清單的例外」的清單本身變成型別系統的一部分。

呼叫端（gap_report_screen.dart `_NoGapsView`）改傳
`EmptyStatePageActionsException.actionsRelocatedToHeader`，渲染路徑與行為
完全未變（僅建構參數名稱與型別改變，元件內部 `_buildChildren()` 邏輯不變）。

### 自檢結果

- `fvm dart analyze lib test`：0 issues
- `fvm flutter test test/ --reporter compact`：1475 passed / 0 failed
- Phase 4 結論：不需重構。本次修改範圍限於單一元件的旗標型別收窄（bool → enum）
  與唯一呼叫端的參數名稱跟隨，無新增技術債務；程式碼品質 A（enum 註解已引用
  SPEC 條款，符合 quality-common 命名與註解規範）。
