### 2. 未生效與不下結論者的初判原因

### V3-B3（不下結論）——修補後仍分歧

s1/s2 判「類型1 計時硬門檻」（環境依賴 flaky 族），s3 判「類型5 非同步時序」（斷言設計族）。題目斷言 `expect(await timer.elapsed, lessThan(Duration(seconds: 2)))` 同時符合類型1（計時值對比絕對常數）與類型5（非同步操作）的特徵。SKILL.md 判斷軸段說明類型1-4 與5-6 歸屬差異，但對同時命中兩類型的斷言未給優先序。s1 引「計時差值對比 N ms 常數」（類型1 識別碼）；s3 引「斷言非同步操作尚未完成時的中間狀態」（類型5）。

### V3-C2（不下結論）——修補後仍分歧

s1 判「資料態（store 欄位驅動）」，s2/s3 傾向「互動瞬態（本地處理）」。模板 §4「來源」欄定義為「互動瞬態（輸入裝置驅動、本地處理）或資料態（store 欄位驅動）」，但「表單驗證結果推導」屬本地即時還是 store 欄位取決於架構決策，題目未指定，探針各自假設不同架構。
