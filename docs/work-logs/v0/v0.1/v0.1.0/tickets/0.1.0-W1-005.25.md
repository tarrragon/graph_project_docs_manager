## Problem Analysis
<!-- Schema[IMP/Problem Analysis]: 選填（小型 IMP 可留 placeholder；大型 IMP 建議填寫）（.claude/pm-rules/ticket-body-schema.md） -->
### 問題根因
建立元件 MissingSourceState（SPEC-004 4.22），承接節點詳情原始檔已消失狀態。

### 契約值不成立（已修正，記於 SPEC-004 變更歷史 1.10）
1. 狀態矩陣「顯示」欄原含 ButtonRow[重新整理, 返回]，與「互動反應」§3011
   及 slot 契約（僅 path/onRefresh/testKey，無 returnTo）不一致——後者明確
   指出返回鍵由頁面框架於 SplitRow.header 統一渲染，本元件動作列只放
   重新整理。已改狀態矩陣「顯示」「可用操作」「退出路徑」三欄對齊 §3011。
2. 內容政策原標 message 可換行 2 行、path 可換行 3 行，但兩者分別採用
   AppText.subtitle 與 AppText.mono，此二變體在 4.1（已核定）鎖定單行
   （AppText._isSingleLine：variant != body 恆單行）。已改內容政策為
   單行 + 末行截斷，與 AppText 實際契約行為一致。

## Solution
<!-- Schema[IMP/Solution]: 選填（.claude/pm-rules/ticket-body-schema.md） -->
### 實作
- `lib/components/missing_source_state.dart`：StatelessWidget，單一 default
  變體。slot：`path`（String）、`onRefresh`（VoidCallback）、`testKey`（Key）。
  結構：Container（testKey，置中）> ConstrainedBox（maxWidth
  LayoutSize.detailPaneWidth * 2）> Column（訊息 Semantics.liveRegion +
  AppText.subtitle、間距 Space.xs、路徑 AppText.mono secondary、間距
  Space.lg、ButtonRow.center[AppButton primary 重新整理，固定 Key
  action-nodeDetail-refresh]）。零裸值，全取 lib/tokens。
- `lib/components/components.dart`：新增一行 export，依字母序插入
  list_row 與 page_column 之間。

### SPEC-004 修正（見 Problem Analysis，版本 1.9 → 1.10）
- 4.22 狀態矩陣三欄對齊 §3011（移除 ButtonRow 內返回鍵）。
- 4.22 內容政策 message/path 改單行截斷，對齊 AppText 4.1 已核定行為。

### 自檢結果
- 契約十一欄位：用途／內容角色／何時不用／出現畫面／層級／變體／狀態矩陣／
  互動反應／操作機制／尺寸契約／內容政策／slot 契約／使用 design token／
  i18n／組合規則／無障礙，逐一比對 4.22 條目，實作與（修正後）契約一致。
- token：色彩經 AppText/AppButton；間距 Space.xs（訊息-路徑）、Space.lg
  （路徑-動作列）；無圓角、無裸值。
- i18n：sourceFileMissingMessage、lastKnownPathLabel、refreshAction 三個
  既有 key，皆透過 AppLocalizations.of(context) 取值，無硬編碼字串。
- 無障礙：訊息包 Semantics(liveRegion: true)；AppButton 自身已提供
  Semantics.button 與焦點裝飾，Tab 焦點路徑由 AppButton 內建 FocusNode
  承載，測試以 find Focus 祖先驗證 canRequestFocus。
- 尺寸契約：填滿父容器＋內容置中（Container alignment: center）；
  kMinWindowSize／kDesignSize 兩尺寸測試（testWidgetsAtEachSize）+
  SizedBox.expand 模擬填滿父容器情境，皆 expectNoOverflow。

### Phase 4 結論
程式碼品質 A（單一 StatelessWidget、零裸值、無分支邏輯、5 個 build 子節點
線性組裝），認知負擔低（無巢狀邏輯、無狀態管理）。無需重構，未發現額外
技術債務。
