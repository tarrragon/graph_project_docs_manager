### 逐則改文與反例

#### 風險 3
- **以哪句為準**：範本〈2〉「低風險＝伺服器拒絕並還原畫面後，不留下還原提示無法抵銷的外部後果」維持不變，判定點是還原完成當下的殘留狀態。
- **改文**（接在該句括號例示之後）：「伺服器拒絕只代表被拒的請求最終不成立，不保證操作處理途中未發出外部效果；還原完成當下仍存在的外部後果一律計入，不論發生於拒絕之前或之後。」
- **逐詞出處**：「不留下…外部後果」（範本〈2〉）；「回滾必須走失敗通知」「適合高成功率操作」（ux waiting-and-notification 感知效能段）。「不論前後」直接由「還原畫面後，不留下」的字面推出，因為判定的是狀態不是事件時點。
- **判否反例**：預約掛號操作送出後，伺服器先發簡訊通知陪診家屬，之後檢查名額時拒絕，畫面還原。簡訊已送達他人，還原提示無法抵銷，因此不是低風險，不允許樂觀更新。

#### 風險 5、6（一併裁決）
- **射程切分**：
  - 強制規則第 1、2 條（集中、禁散落）＋決策表第一題：射程是視覺 token，不看消費者數量。
  - 消費者範圍表＋決策表第二題：射程是視覺 token 以外的常數（含純業務常數）。
  - 強制規則第 3 條（跨層 import 禁令）：射程是全部 domain 常數，含純業務常數。
- **以哪句為準**：
  - 風險 5：以強制規則＋決策表第一題為準。出處有 4 處：方法論執行步驟 2「design token 層…集中管理」、component-contract-design SKILL.md「集中定義、程式碼只引用名字」、acceptance-criteria 方法論集中化驗收、同範本 frontmatter 用途把元件尺寸列入統一視覺規格。偏離的只有〈10〉首句「Design token 的程式碼配置位置依消費者數量決定」與表第一列範例。
  - 風險 6：以決策表第二題為準。「不在本規則範圍」的「本規則」收斂為前兩條集中規則。
- **改文**：
  - 〈10〉首句改為「視覺 token（色值、間距、圓角、陰影、字體、元件尺寸）一律集中於 design system 目錄，不看消費者數量；視覺 token 以外的常數，程式碼配置位置依**消費者數量**決定：」。
  - 消費者範圍表第一列範例改為「某 domain 專屬的業務列舉值」；第二列配置位置改為「`core/` 對應子目錄」，範例改為「多個 domain 共用的業務常數」。
  - 強制規則第 1 條括號補「元件尺寸」（出處：同範本 frontmatter 用途、§9 元件尺寸）。
  - 強制規則末條改為「純業務常數（如預設標籤名稱）不是 design token，不受前兩條集中規則約束；位置依下方判斷決策表第二題決定，跨層 import 禁令仍適用」。
- **判否反例**：
  - 風險 5：聊天氣泡最大寬度 280px 只有 messaging domain 使用，放在 `lib/domains/messaging/constants/`，判不合格。屬元件尺寸，應放 design system 目錄。
  - 風險 6：會員等級名稱列表被 membership 與 billing 兩個 domain 使用，放在 `lib/domains/membership/constants/`，判不合格，應放 `core/` 對應子目錄。
- **連帶**：第二列若保留「跨層使用」，決策表第二題要同步加「或被 domain 以外的層使用」，否則同一問題又分成兩說。落檔時二選一：兩處都加，或兩處都不加。

#### 風險 8
- **出處**：event-flow-load-arbitration 方法論〈8. 部分降級〉「降級不可靜默：回應或畫面必須攜帶降級標示」及其理由「沒有標示時降級回應與正常回應同形」；ux gate-fallback.md Degraded mode「呈現快取內容時須標示內容可能不是最新」。
- **射程**：只約束「收斂後表現與正常狀態同形」的情形。收斂為 error 等本來就與正常態不同的表現，不另加標示。
- **改文**（方法論〈降級不解除回饋義務〉Action 補一句，範本〈回饋契約〉降級段補同義路由）：「收斂後的可見表現與正常狀態同形時（使用者從畫面分辨不出已降級），表現須含降級標示；判準見 `event-flow-load-arbitration-methodology`〈8. 部分降級〉『降級不可靜默』列。」
- **判否反例**：匯率換算元件在匯率服務無回應時，改用上次快取的匯率算出結果，畫面與即時匯率時完全相同，沒有任何標示，判不合格。

#### 風險 10
- **出處**：
  - 範本〈無障礙〉標題「必填，不得填不適用」，引言「朗讀標籤與播報跨形態共用」。
  - 〈無障礙〉「狀態變化播報」列：資料態改變一律播報。
  - 方法論〈形態因素先決〉子表範例：各形態格都不含播報，但同段寫明桌機須提供播報替代。這表示承載處不在子表格內。
- **以哪句為準**：〈無障礙〉子節是播報的承載處。子表「播報替代不因該形態非觸控裝置而豁免」的射程是〈無障礙〉播報列不得以形態為由填不適用，不要求在子表格內列入播報。
- **改文**（接在「播報替代不因該形態非觸控裝置而豁免」之後）：「播報替代登記於第 4 章〈無障礙〉子節（跨形態共用），不填入本子表的格；本子表各格判定該形態的非播報通道。」
- **判否反例**：某 CLI 工具的清單元件在 CLI 欄「狀態變更提示」填「終端機輸出新行」，〈無障礙〉「狀態變化播報」列填「不適用：CLI 無螢幕閱讀器」，判不合格。該列必填，不得填不適用。
- **弱推導項**：方法論事件表定位提示列「輔助技術：焦點移入 + 播報」在〈無障礙〉沒有逐字對應列，只能推為歸「焦點順序與操作路徑」列，列入用戶偏好。

#### 風險 11
- **判定**：沒有出處，doc 內也沒有 `{…}` 的語意定義。本則是格式問題，不是新判準。DOC-20a 3/3 把佔位符讀作規則；DOC-19a 2/3 失敗主因是內距與鄰件間距的分界只在範例（W3-472 承接），不是大括號本身。
- **改文（方案 B）**：
  - 〈測試點〉該項去掉大括號，改為固定檢查項。
  - 〈組合規則〉「作為表格或列表的一欄時」列的規則移入引言：「作為表格或列表的一欄時，本列填欄比例或固定寬與欄內距，皆引用 token」，表格值欄只留 `{值}`。
  - 內距與間距的分界句由 W3-472 一併補，本則不代寫，避免兩票寫出兩種定義。
- **判否反例**：撰寫者把〈組合規則〉該列改寫為「寬 120px」，判不合格（未引用 token）。
- **方案 C**（備選）：範本檔頭補一句「表格格內 `{…}` 為填寫提示；提示內寫明的限制（引用 token、不得、須、一律）仍是規則」。
  - 利：一次涵蓋全範本同型格，包括〈無障礙〉「{判準：…}」與〈尺寸契約〉「{…引用 token}」。
  - 弊：需要讀者自己分辨提示與限制，歧義沒有消除。

#### 風險 13
- **出處**：chained-examples.md〈【產出】段〉「契約表｜欄位名加值的表格，欄位名取自受管詞彙」。

- **改文**：

#### 風險 14
- **以哪句為準**：方法論〈豁免三條件〉條件 1 的列舉以「或」收尾，為封閉清單。同條「可重用的『元件庫缺件』不得引用本條件——缺件的指定路徑是元件票」。範本〈7〉「主張封裝後仍無法達成…理由欄記錄」讓讀者以為還有第六條路，超出方法論。
- **改文**（範本〈7〉該句改寫）：「套件提供而由頁面直接使用的元件不屬此類，須先以元件庫元件封裝；封裝後仍無法達成契約要求的行為者，須依條件 1 其餘類別逐類主張（如效能豁免附 profiler 證據），理由欄記錄已嘗試的封裝路徑與失敗原因，只寫『套件限制』不成立；無一類成立者屬元件庫缺件，走元件票，不得豁免。」
- **連帶**：E-24 產出第一列「結構性無法收斂，可豁免」須補類別，或改判「無一類成立，走元件票」。
- **判否反例**：頁面直接使用圖表套件的圖例元件，封裝後仍無法套用色彩 token，理由欄記錄了封裝路徑，但不屬測試斷言、效能豁免、非視覺輔助結構件、一次性刻意破格任一類，判不得豁免，應建元件票。
