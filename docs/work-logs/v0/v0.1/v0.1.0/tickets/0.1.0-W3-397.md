## Problem Analysis
### 問題根因

Step 2 判準句「FR 描述含『畫面』『頁面』『元件』『介面』『UI』等關鍵字」的「等」字只給出五個字面詞，未定義五詞以外的涵蓋範圍。`examples/v02-walkthrough.md` 範例一的【產出】與【驗證】段自行引入「版面配置」與「可操作元件／按鈕」兩項判準，用來把「確認彈窗」FR（不含五詞字面）判為 UI 類。此判準只存在於範例——Step 2 本文、`references/step-rationale.md`〈Step 2 的 UI 前置檢查〉、Step 2 所引的 `component-library-bidirectional-constraint-methodology.md` 全文皆查無對應定義（該方法論的判準皆假設「已判定為 UI 類」之後的分層與元件契約規則，不涉及「是否為 UI 類」本身的判定）。

0.1.0-W3-336.13 三份獨立探針對範例一同題（V3-F3，終端輸出進度百分比）雖答對「非 UI 類」，但依據句皆為「不含五詞字面」的純字面比對，推理路徑與範例一「無版面配置、無互動元件」的延伸判準不同。若探針改答彈窗類 FR，純字面比對會判「非 UI 類」，與範例一的預期判定（UI 類）相反——代表此判準缺口目前只是尚未被題目命中，一旦命中會產生錯誤分類。

### 影響範圍

`.claude/skills/version-bootstrap/SKILL.md` Step 2、`references/step-rationale.md`〈Step 2 的 UI 前置檢查〉、`examples/v02-walkthrough.md` 範例一（三份檔案互相引用，同屬一個判準缺口）。

### 候選方案（本票不逕行定案，列供 PM／WRAP 選定）

新增判準會改變既有判定者的行為，依 0.1.0-W3-336.6 Solution〈矛盾類票的簽核流程〉精神，本票只列候選方向與各自的歸屬影響，停手交裁決。

**候選 A：雙要件析取（版面配置或可操作元件，逐字採用範例既有措辭）**

- 條文擬稿：「『等』涵蓋 FR 描述雖未出現五詞字面，但其產物具備版面配置（多個元素的相對排列）或可操作元件（使用者可觸發的按鈕／輸入／選項）任一者，仍判為 UI 類。」
- 歸屬變化：彈窗／對話框／浮動選單／內嵌提示等「有排版且可互動」但未用五詞字面描述的 FR，由現行字面比對的「非 UI 類」改判「UI 類」。若只採「版面配置」單一要件成立即算（不要求互動），純資訊呈現的排版（如唯讀清單畫面）也會被納入；範圍最廣，連帶把「非 UI 類」的邊界收得最窄。

**候選 B：限縮延伸範圍只到「頁面」語意（其餘四詞維持字面比對）**

- 條文擬稿：呼應範例一驗證段原文「屬『頁面』語意延伸」，只有「頁面」一詞取語意延伸，「畫面」「元件」「介面」「UI」四詞維持字面比對；具備完整版面配置與可操作元件、可視為「一個頁面的縮影」的產物（彈窗、對話框、可獨立導覽的浮動面板）納入「頁面」延伸範圍。
- 歸屬變化：只有「像頁面」的完整版面產物（彈窗/對話框/獨立面板）由非 UI 類改判 UI 類；單一按鈕、單一輸入框等不構成「頁面縮影」的零散互動元件仍維持字面比對結果（多半仍判非 UI 類）。範圍比候選 A 窄，但保留「語意延伸」需要讀者自行判斷邊界的模糊性。

**候選 C：以具名產物清單取代抽象「語意延伸」措辭**

- 條文擬稿：放棄「語意延伸範圍」這種需要讀者自行想像涵蓋邊界的描述，改列具名產物清單（例如：彈窗、對話框、選單、浮動提示、獨立面板），FR 描述的產物屬清單內任一具名類型即判 UI 類，不再要求判定者自行推論是否落入「語意延伸」。
- 歸屬變化：清單內具名產物的判定結果與候選 B 相近，但判定機制從「語意推論」換成「清單比對」，可被字面比對機械執行、不再需要語意層推理；清單外但實際上也具備版面配置與互動的新型態產物（清單未窮舉到者）不會被納入，需要人工升級清單，屬清單維護債務，長期需搭配一條「清單外個案交規則維護者評估是否補列」的路徑，否則此類產物退回候選前的字面比對結果（非 UI 類）。

**候選 D：不改條文，改範例——範例一輸入換成純關鍵字即可判定的 FR**

- 做法：不新增 Step 2 判準，把範例一兩個輸入 FR 改寫為單靠五詞字面（含「不含五詞」的反面情形）即可判定的案例，移除「彈窗」這種需要語意推論才能判定的輸入。
- 歸屬變化：條文與既有判定行為完全不變（無新增判準，字面比對範圍不擴大也不縮小）；範例庫因此失去「字面未命中五詞、但概念上仍屬 UI」這一類案例的教學示範，日後真的遇到彈窗類 FR 時，Step 2 條文仍無判準可依，agent 仍會依字面誤判為非 UI 類——這條路徑不解決缺口，只是把缺口從「範例引用條文查無依據句」的位置（本票已查到，未來可能再被查到），移到「條文本身缺判準」的位置（不會被〈驗證段機械檢查：依據句可溯性〉這類機械檢查攔到，因為範例不再涉及此判準）。
