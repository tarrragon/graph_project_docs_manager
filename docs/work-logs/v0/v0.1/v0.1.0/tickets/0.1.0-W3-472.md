  查證範圍：`component-library-spec-template.md`〈組合規則〉「與鄰件的間距不在此定義，由所在
  容器的排列不變式承載」＋ `component-library-bidirectional-constraint-methodology.md:65`
  組合規則列，兩處皆只排除「鄰件間距」不在此定義，未定義「內距」本身涵蓋的範圍；該定義原僅存在
  於已刪範例（commit 4aec4afc5 引入，後續風險 13 清理時移除，見〈組合規則「作為表格或列表一欄時」
  內距與「不得另定間距」的分界〉【驗證】段：「內距是元件邊界內部的空間，兩者不同」），現無 git
  grep -F 可命中的非範例出處。
- **觸發位置**：`component-library-spec-template.md`〈組合規則〉引言，緊接「與鄰件的間距不在此
  定義」之後。
- **影響**：DOC-19a 讀歪點未修，`b5-doc-2` 判定 21/22 中該題仍會因判準缺席而誤判（r2、r3 曾把
  佔位符「內距（引用 token）」讀成引言禁止的「鄰件間距」）。
- **建議補料**（草稿，供 PM／WRAP 裁決是否採用及如何落檔）：
  「內距是元件邊界內部的空間（如作為表格一欄時，欄內文字與欄邊界之間的留白）；與鄰件的間距，是
  本元件與相鄰其他元件之間的留白，屬容器排列不變式管轄，兩者不同。」
