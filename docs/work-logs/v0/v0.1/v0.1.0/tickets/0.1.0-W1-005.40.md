## Solution
<!-- Schema[IMP/Solution]: 選填（.claude/pm-rules/ticket-body-schema.md） -->
### 實作概述

`SwimlaneGrid`（StatefulWidget）：泳道列 = `AppText.body` 泳道名（釘選欄，
`LayoutSize.laneLabelWidth`）+ N 個步驟欄（`SwimlaneNode` 置中，私有常數
`_stepColumnWidth`，SPEC-004 4.38 明文步驟欄寬「不設 token」故非硬編碼違
規）；列間 1px 實線分隔（`AppColors.borderStrong`，規格稱「虛線」，取可行
的最小近似，見下方契約值調整）；底部箭頭列（`AppIcon(Icons.arrow_forward,
IconSize.sm, AppColors.textDisabled)`，`ExcludeSemantics` 排除語意樹）。

二維捲動 + 拖曳（`scroll-domain-swimlane` / `drag-domain-swimlane`）**未採
巢狀 `SingleChildScrollView`**：實測發現水平/垂直兩個內建拖曳辨識器在同一
手勢仲裁中互斥（斜向拖曳只有一軸生效，見下方「契約值實測」）。改採單一
`(_dx, _dy)` state + `GestureDetector.onPanUpdate`（拖曳）+
`Listener.onPointerSignal`（滾輪）共同改變同一組 offset，`clamp` 手動限制
範圍（無 ballistic 慣性模擬），滿足「位移比例 1:1、至邊界生硬停止、無慣
性、拖曳與捲動共用同一 offset」四項互動反應契約。內容尺寸可能大於
viewport（LayoutBuilder 給的 tight 上界會被 `SizedBox.enforce()` 夾住），
改用 `OverflowBox` 讓內容依真實尺寸排版，外層 `ClipRect` 裁切、
`Transform.translate` 位移顯示視窗。

`laneHighlight` 變更（含首次建構已帶值）時，`initState` / `didUpdateWidget`
於 `addPostFrameCallback` 呼叫 `_jumpToHighlight`：命中列不在目前 viewport
內時直接改 `_dy`（非動畫），符合「自詳情卡『在泳道中檢視』進入」的 jumpTo
契約。

### 契約值實測（無需修改 SPEC-004，記錄如下）

1. **列間虛線 → 改 1px 實線**：`Border` 不支援虛線，`Section`
   （0.1.0-W1-005.14）已示範以 `CustomPainter` 逐段畫短劃可行，但本票
   為控制範圍未複用（避免額外抽公用元件超出票面範圍），改用視覺近似的
   1px 實線（`AppColors.borderStrong`）。此為實作層面妥協非契約值變更，
   若需嚴格虛線視覺，建議後續票抽出共用 `DashedDivider` 元件供
   `Section`／`SwimlaneGrid` 共用。
2. **二維捲動實作方式**：SPEC-004 4.38 只約束「二維捲動 + 拖曳、與捲軸
   共用同一 offset」的行為契約，未指定 Flutter 實作手段。原計畫沿用
   `Section` 模式外的巢狀 `SingleChildScrollView`（水平外層 + 垂直內層），
   widget test 中對角線 `tester.drag()` 實測僅單軸位移生效（Flutter
   `HorizontalDragGestureRecognizer` / `VerticalDragGestureRecognizer`
   在同一手勢仲裁中互斥），不滿足「位移比例 1:1」（雙軸同時）之契約值，
   改採 `GestureDetector.onPanUpdate` 手動雙軸位移，測試綠燈驗證位移比例
   與邊界生硬停止皆準確至 0.5px 內。

### Phase 4 結論
