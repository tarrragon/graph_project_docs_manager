## Problem Analysis
### 問題根因

V4 讀者探針（只讀 skill 與 spec、禁讀 SPEC-004 與程式碼）在 9 個決策點上找不到可引用的條文，只能自擬規則；W3-335.36 將其歸為 E（skill 缺引導／缺範例）。根因分兩類：(1) 條文只寫正向或單一情境（path-A 可用操作只有「提到即存在」、判準 1 只列開關型二值、step-1 情況二預設三訊號可核對、〈失敗路徑覆蓋〉與〈掛載點〉第一層無條件性對「不經服務的事件」未交代交界）；(2) 畫面票 how 句型「狀態 X：容器 Z 第 N 格放元件 A 變體 a」只涵蓋「單一狀態、佔格位的元件」，覆蓋層、疊加態、格位起算、非狀態進入情境四種形態無寫法。

#### #2 格位起算（缺引導）

WRAP：W 三案——(a) 具名 slot 寫名、未具名依排列方向由 1 起算；(b) 一律數字、頁首類子件計格；(c) 一律具名、未具名者退回容器票補名。R：既有正例「第 1 格（側欄）」數字與名並用，(a) 與之相容；(b) 仍需另定「頁首算不算格」；(c) 對「逐格放 N 張清單卡」的同質容器強迫命名無意義。A：(a) 不改正例、不加新概念。P：容器契約的 slot 契約只寫數量上限未具名 → (a) 自動落到計數分支；絆腳索：畫面票出現容器契約查無的 slot 名，即缺件訊號。**定案 (a)**。

條文草稿：

> 格位的指稱以容器契約的 slot 契約為準。容器已具名 slot 者（如頁首、工具列、主區、側欄）寫 slot 名，不另行編號；容器以單一方向排列且未具名 slot 者，寫「第 N 格」，依排列方向由起點計數——垂直堆疊以最上方、水平並排以書寫方向起始側為第 1 格，每個直接子件佔一格。容器契約尚未寫出 slot 者，先補該容器的 slot 契約，不在畫面票內自訂編號。

範例草稿：

【輸入】
```
頁面框架容器的 slot 契約：頁首（1）、工具列（0..1）、內容（1），垂直堆疊
工具列容器的 slot 契約：未具名，子件依序為搜尋欄、篩選下拉 × 2，水平並排
清單容器的 slot 契約：未具名，清單卡 0..N，垂直堆疊
狀態「正常」：頁首放返回鍵；工具列放搜尋欄與兩個篩選下拉；內容放清單容器，逐筆放清單卡
```
【產出】決策表
```
how 寫法                                                   | 合格   | 理由
「頁面框架第 2 格放工具列容器」                             | 不合格 | 頁面框架已具名 slot，不另行編號
「頁面框架工具列 slot 放工具列容器，其第 1 格放搜尋欄、     | 合格   | 具名寫名；未具名依書寫方向由 1 起算；
 第 2、3 格放篩選下拉；內容 slot 放清單容器，逐格放清單卡   |        | 同質子件以「數量依資料筆數」標明
 變體 default，數量依資料筆數」                             |        |
```
【驗證】檢驗問句
```
Q 頁面框架的子件以 slot 名還是序號指稱？      預期：slot 名（依據：「容器已具名 slot 者寫 slot 名，不另行編號」）
Q 工具列容器中搜尋欄是第幾格？                預期：第 1 格（依據：「水平並排以書寫方向起始側為第 1 格」）
Q 頁面框架契約若未列 slot，畫面票可否自訂「第 2 格＝工具列」？
                                              預期：否（依據：「先補該容器的 slot 契約，不在畫面票內自訂編號」）
```

#### #3 覆蓋層（缺引導）

WRAP：W 三案——(a) 狀態列末以「覆蓋層：」子句列出、只列呼叫端觸發者；(b) 立虛擬「覆蓋層格」；(c) 不進 how、只在元件契約承載。R：(c) 使覆蓋層元件從 how 消失，acceptance「狀態矩陣每列都以契約內的元件組成」抓不到契約外的覆蓋層；(b) 把不佔版面的元件算進格位，與容器排列不變式的不重疊公式衝突。探針 G33 的兩個實例中，篩選選單屬下拉元件自帶、暫態提示由呼叫端觸發，兩者性質不同，須分開處置。A：(a) 只加一個子句。P：讀者分不清自帶與呼叫端觸發 → 依據 step-3〈關卡五〉既有問句「每條狀態邊的提示是元件自播還是呼叫端觸發」判定；絆腳索：同一覆蓋層在兩張畫面票一張列一張不列。**定案 (a)**。

條文草稿：

> 覆蓋層元件（疊於版面之上、不佔容器格位者，如選單、暫態提示、浮層、對話框）不寫進格位句。由呼叫端觸發者，於該狀態列末以「覆蓋層：元件 A 變體 a（觸發：可觀測事件；附著對象：觸發元件或視窗）」逐項列出，可在多個狀態觸發者每個狀態列各列一次；屬觸發元件自帶者（觸發器與其展開內容同屬一個元件契約）不列。覆蓋層的定位、尺寸與遮擋由該元件契約的尺寸契約與組合規則承載，畫面票不述。

範例草稿：

【輸入】
```
狀態「正常」：工具列放篩選下拉；篩選下拉的元件契約寫明選單屬本元件，展開時疊於版面之上
清單項刪除完成後出現附「復原」動作的暫態提示；暫態提示的元件契約回饋契約寫明由呼叫端觸發、
顯示位置為視窗底緣
```
【產出】決策表
```
覆蓋層             | 觸發者     | how 寫法
篩選下拉的選單     | 元件自帶   | 不列；格位句只寫「工具列 slot 放篩選下拉變體 default」
附動作暫態提示     | 呼叫端     | 狀態列末「覆蓋層：暫態提示變體 withAction（觸發：刪除完成；附著對象：視窗）」
```
【驗證】檢驗問句
```
Q 篩選下拉的選單是否出現在 how？           預期：否（依據：「屬觸發元件自帶者不列」）
Q 暫態提示是否佔工具列或內容的格位？       預期：否（依據：「不寫進格位句」）
Q 「視窗底緣」寫在 how 還是元件契約？      預期：元件契約（依據：「定位、尺寸與遮擋由該元件契約…承載，畫面票不述」）
```
