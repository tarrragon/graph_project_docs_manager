## Task Summary

裁決 7.2(3)「造成、設定或解除該狀態的動作」中「設定」的射程：改變一個進行中狀態的參數算不算設定該狀態

---

## Problem Analysis
### 問題根因

7.2(3) 第三句「狀態指示與造成、設定或解除該狀態的動作，代表的事物相同」以三個動詞共用一個受詞「該狀態」。造成與解除都只能指向該狀態成立與否，夾在中間的「設定」單獨看卻有第二個讀法——設定該狀態的某個參數。UX-T6a 子問 2 的動作（把灑水量由中量改為大量，且題幹明寫它既不會關掉灑水、也不會讓灑水開始）正落在兩個讀法的分岔上。

根因不是條文對這個分岔完全無字，而是**條文的其他各處已經選定了其中一個讀法，只有該句自己沒有把選擇寫出來**：

- 7.2(5) 明文封堵「同屬一個主題或功能領域、或共用同一個名詞」；「水量是灑水的一部分」正是同一主題的論證。
- 7.2(5) 另明文「同一個對象的兩個不同狀態，是兩個語意」；「本區正在灑水」與「本區灑水量為大量」是同一對象的兩個狀態。
- 同批答案鍵已有兩則同型判定採「設定的受詞必須是該狀態本身」的讀法並判違反：UX-N7c 子問 3（「開啟警報音量設定畫面」，該鍵逐字寫「設定的是音量，不是『有未讀警報』這個狀態」，並把「設定」二字標為誘餌）、UX-K1 子問 3（「開啟本 app 的設定畫面」）。

因此 UX-T6a 子問 2 的答案鍵與同批另外兩則答案鍵對同一個分岔採了相反讀法。四方（r1、r3、判定者 j1、j2）獨立推得「違反」，與 UX-N7c／UX-K1 兩鍵同向，與 T6a 該鍵反向。

### 實驗發現

**已驗證的事實**：

1. 同一批答案鍵對「動作設定的是某參數、另一端是狀態指示」這個分岔已有兩則判定，方向皆為**違反**（UX-N7c 子問 3、UX-K1 子問 3）；UX-T6a 子問 2 是第三則，方向相反。三則的條文依據是同一句。
2. UX-N7c 子問 3 的鍵不只判違反，還明文把題幹中的「設定」二字標為誘餌並寫出判準——「設定的是音量，不是那個狀態」。UX-T6a 的出題者踩的正是自己在另一檔標記過的誘餌。
3. r1 的作答已自行寫出正確的判準語言（「不涉及灑水這個狀態的改變（開/關），而是改灑水的參數」）。四位獨立讀者無一人採「設定該狀態的參數也算設定該狀態」。
4. b9 與 b12 的四題第 7 項題幹逐字相同，誤傷實驗代入 b12 即涵蓋 b9。
5. 「作用對象」這組詞已被 UX-T5c 子問 2 用作誘餌主張且其鍵明文扣分，草案不得使用。

**仍未驗證的假設**：讀者在射程句落檔後會依該句判。本檔對此形態尚無讀數；但該句所寫的判準已由四位讀者中的兩位自發使用（r1 明寫「開/關 vs 參數」），基本率優於前三次補句。
