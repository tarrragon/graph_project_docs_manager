## Problem Analysis
<!-- Schema[IMP/Problem Analysis]: 選填（小型 IMP 可留 placeholder；大型 IMP 建議填寫）（.claude/pm-rules/ticket-body-schema.md） -->
### 問題根因

W1-005 傘票落地期間，容器 slot（PageColumn header/content、ListRow
leading/trailing、Panel children、AppShell overlay、AppButton leading、
Toolbar filters、IssueMarker child、TwoColumnLayout main/detail 等）在
其契約指定的子件尚未存在時，依 AppButton 既有慣例暫以 Widget /
List<Widget> 承接。W1-065 對照表盤點出 8 個引用本票的偏離列。

### 盤點與逐項處置

依 W1-065 對照表逐列核對 SPEC-004 4 章 slot 契約欄與現行實作：

| SPEC-004 條目 | slot | 契約型別 | 處置 |
|---|---|---|---|
| 4.4 AppButton | leading | AppIcon? | 收窄（AppIcon 已於 W1-005 子票落地） |
| 4.27 AppShell | overlay | SwitcherOverlay? | 收窄（SwitcherOverlay 已落地） |
| 4.28 PageColumn | header | SplitRow.header（具名建構子，型別仍為 SplitRow） | 收窄 |
| 4.28 PageColumn | content | Panel / Panel.scrollable / TwoColumnLayout / EmptyState.page / BlockedState / LoadingState / LoadPrompt / MissingSourceState（8 型聯集） | 維持 Widget（契約本身即聯集，無單一具名型別可收窄，符合步驟 3「契約即 Widget」情形） |
| 4.30 Panel | children | 14 型具名聯集 | 維持 List<Widget>（同上，聯集） |
| 4.32 Toolbar | filters | List<FilterDropdown> | 收窄（FilterDropdown 已落地） |
| 4.6 IssueMarker | child（damagedEdge） | RelationItem | 實測不可行，見下 |
| 4.31 TwoColumnLayout | main / detail | Panel / Panel.scrollable | 維持 Widget，理由見下（非聯集本身不可收窄，而是既有測試耦合） |

### IssueMarker.child 收窄不可行的實測結果

嘗試將 IssueMarker.damagedEdge 的 child 參數與欄位型別從 Widget? 改為
RelationItem?，並將 issue_marker_test.dart 三處 Text 佔位改為真實
RelationItem 實例後執行 flutter test：「點擊 damagedEdge 呼叫 onTap
恰一次」測試失敗（Expected: <1>, Actual: <0>）。根因：RelationItem
自身持有可互動 InkWell（其 onTap 用於替換主欄／jump Domain 視圖），
巢狀於 IssueMarker.damagedEdge 自身的 InkWell（其 onTap 用於 jump 破洞
報告）內時，內層 InkWell 攔截 tap 命中測試，導致外層 onTap 不觸發——
Flutter 巢狀 GestureDetector/InkWell 的既知行為（內層優先取得 arena）。
收窄為 RelationItem 型別會破壞既有點擊行為契約，判定為實作上不可行，
依步驟 4 指示：不放寬契約、不改 SPEC-004，維持 Widget? 承接並在
issue_marker.dart 欄位註解記錄此衝突與判定依據。已 revert 相關測試
修改，issue_marker_test.dart 維持原有 Text 佔位寫法。

### TwoColumnLayout main/detail 維持 Widget 的判斷

契約型別（Panel / Panel.scrollable）本身可收窄（Panel.scrollable 是
Panel 的具名建構子，型別仍為 Panel）。但 two_column_layout_test.dart
既有測試多處以 tester.widget<material.ListView>(detailFinder) 直接對
detail slot 的具體型別斷言（驗證 ListView 的 controller 狀態），且
_buildMain() / _buildDetailCard() 佔位替身用 material.ListView 模擬
資料視圖捲動行為。改用 Panel.scrollable 包裝會使該類型別斷言編譯失敗，
需同步重寫多個測試案例的斷言方式（不僅是佔位替身），超出本票「收窄
Widget 型別」的最小變更範圍。判定為本票不處理，於 two_column_layout.dart
欄位註解記錄理由，未建額外追蹤票（契約本身未變、SPEC-004 未修改，未來
若 TwoColumnLayout 的具體 UC 畫面票落地時可一併處理，不需獨立票）。

## Solution

### 收窄的 slot（4 個）

| 檔案 | slot | 型別變更 |
|---|---|---|
| lib/components/app_button.dart | leading | Widget? → AppIcon? |

### 維持 Widget 的 slot（含判定理由，共 9 個既有欄位）

| 檔案 | slot | 判定 |
|---|---|---|
| lib/components/page_column.dart | content | 契約為 8 型聯集，非單一型別，維持 Widget |
| lib/components/panel.dart | children | 契約為 14 型聯集，維持 List<Widget> |
| lib/components/list_row.dart | leading / trailing | 契約各為多型聯集，維持 Widget? |
| lib/components/section.dart | header / items | 契約各為多型聯集，維持 Widget / List<Widget> |
| lib/components/split_row.dart | leading / trailing | 契約各為多型聯集，維持 Widget / Widget? |
| lib/components/app_table_row.dart | cells | 契約依變體為固定型別序列（混合型別），維持 List<Widget> |
| lib/components/issue_marker.dart | child | 契約單一型別（RelationItem）但實測不可行（巢狀 InkWell 攔截 tap），維持 Widget?（見 Problem Analysis） |
| lib/components/two_column_layout.dart | main / detail | 契約可收窄為 Panel，但既有測試耦合具體 ListView 型別斷言，超出本票最小變更範圍，維持 Widget（見 Problem Analysis） |
