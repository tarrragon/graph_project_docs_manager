### 問題根因

`oregano-data-miner` 的 `tools` 為 `Grep, LS, Read`（無 Write/Edit/Bash），但其三區塊要求它獨立完成「策略文件產出至 `docs/`」（允許產出）與「記錄至 Ticket 執行日誌」（禁止行為第 6 條）——兩者皆需 Write/Edit 或 Bash。這是結構性不可能，非措辭瑕疵：任何派發方式都無法讓它單獨完成一張 ANA/DOC 型 ticket。

### 影響範圍

**已驗證事實**：
- 本專案 `docs/` 對 `oregano-data-miner` 的 3 處命中（0.1.0-W3-141/143/144）皆為討論它的 ticket 本身，零實際派發引用。
- 本專案 `.claude/logs/agent-dispatch.jsonl` 對 `oregano` 命中 2 筆，皆為 143/144 本身（討論 oregano 的 ANA 派發），非派發 oregano 執行任務。
- `.claude/agents/registry.yaml` 將其標為「輔助代理人」且設 `conflict_avoidance: cannot_work_with: [oregano-data-miner]`——框架層面已預期它需與其他 agent 協作而非獨立運作。

**未驗證假設**：本機以外、未掛載於此環境的其他 consumer 專案是否有實際派發紀錄，無法從本環境驗證。

### 相關 Error Pattern

`ARCH-BAL-003`（白名單自訂納入判準但成員未同步）——其案例段已將 `oregano-data-miner` 列為「符合 `TICKET_EXEMPT_AGENT_TYPES`（唯讀 agent 豁免 Ticket ID 驗證）判準但未列入名單」的 5 個對象之一。查現行 `.claude/skills/ticket/hooks/agent-ticket-validation-hook.py`，`basil-writing-critic`／`linux` 已於 0.2.1-W3-010 補列，`oregano-data-miner`／`incident-responder`／`sumac-system-engineer` 仍未列入。此脫節與本票根因同源：框架已有「純諮詢型、免 Ticket ID」的分類機制，oregano 符合判準卻被錯置在「須獨立擁有 ANA/DOC ticket」的另一套期待下。
