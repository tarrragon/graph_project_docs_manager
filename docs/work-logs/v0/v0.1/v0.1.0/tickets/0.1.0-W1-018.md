### 執行時推翻本票自身的延後前提

本票 `when` 欄位原記「sync-pull 通道解封後（現在寫入 .claude/ 會擋住取得 hook 修復所需的 pull）」。執行時實讀 `.claude/scripts/sync-claude-pull.py` 的 `check_uncommitted_changes`（L371-398），其判斷依據為兩條命令：

    git diff --name-only -- .claude
    git diff --cached --name-only -- .claude

兩者都只列已追蹤檔案的修改，未追蹤新檔不在其中。實測（工作區同時存在 1 個已追蹤修改與 2 個未追蹤新檔）：

    diff(工作區)   : .claude/error-patterns/_project-registry.yaml   [1 行]
    diff --cached  :                                                  [0 行]

兩個未追蹤新檔落在判斷依據之外。**延後的前提從寫下當下就不成立**——建立一個新的 error-pattern 檔案從未擋住 pull。

該前提以事實語氣寫入本票的追加型欄位，因此後續讀者（含本 session）沒有理由去查。此事本身即本票要記錄的模式的第二個實例，已一併寫入 pattern 的「案例二」。原 `when` 欄位依追加型慣例不回改。
