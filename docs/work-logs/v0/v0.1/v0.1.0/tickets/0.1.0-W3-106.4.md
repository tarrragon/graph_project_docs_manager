## Problem Analysis
<!-- Schema[DOC/Problem Analysis]: 選填（若 DOC 起因於缺陷或盤點結論可填）（.claude/pm-rules/ticket-body-schema.md） -->
### 問題根因

同 0.1.0-W3-106.1／106.2／106.3：既有回饋契約語意正確、格式落後。本票
是父票 0.1.0-W3-106 四張子票的最後一段，額外承接一項判準：容器元件的
「自身互動」判別（PM 補充）——把資料整個抽掉，容器自己還有沒有互動？
依此問句將 16 個容器分成四類處置。

### 影響範圍

docs/spec/ui/SPEC-004-component-library.md §4.27–4.42（AppShell 至
SwitcherOverlay，容器元件段，條目數為四段之最）。逐條目分類：

- **完全委派子件（5 個）**：4.27 AppShell／4.28 PageColumn／4.31
  TwoColumnLayout／4.39 Tree／4.41 Section。抽掉資料後容器自身無任何
  互動（無點擊、無捲動）。掛載點寫「不適用」+ 委派清單。
- **自身互動屬操作路徑非服務三層（2 個）**：4.30 Panel／4.38
  SwimlaneGrid。自身互動限於捲動或拖曳，這類互動無等待/失敗概念，不
  落入 SPEC-003 §2.12 四類分類，另由〈捲動／拖曳操作路徑的不變式〉
  承載，「等待與結果」列標「不適用於服務三層模型」。
- **自身有第一層互動（2 個）**：4.35 TableRow（整列 pressed）／4.37
  MatrixGrid（列首格 pressed，容器內部互動區）。判定本地即時。
- **依變體分流（1 個）**：4.40 ListRow——`tree` 本地即時、`item` 短暫
  非同步（外部開啟，逐字命中 SPEC-003 §2.12 0.1 實例）、`sectionHeader`
  ／`meta`／`numbered` 三變體不適用（無互動）。
- **兼具承載他人某層與自身互動（2 個）**：4.36 DataTable／4.42
  SwitcherOverlay。比照 4.24 LoadingState 拆為「為誰承載」與「自身
  互動掛在哪一層」兩段書寫。4.42 處理前先 rg 實查全文「浮層開合由
  4.42 承載」的全部引用（命中 4.8／4.9／4.23 三處，非僅記憶中的清單），
  確認三處皆判定為本地即時，與本條目一致。
- **純佈局零互動（4 個，不需改動）**：4.29 SplitRow／4.32 Toolbar／
  4.33 BadgeRow／4.34 ButtonRow。既有「不適用（六類事件全部）」單列
  已是顯式呈現。

### 相關 Error Pattern

無新增；沿用父票引用的 ARCH-GPD-001 與 DOC-005。
