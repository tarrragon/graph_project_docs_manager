## Problem Analysis
<!-- Schema[IMP/Problem Analysis]: 選填（小型 IMP 可留 placeholder；大型 IMP 建議填寫）（.claude/pm-rules/ticket-body-schema.md） -->
### 問題根因
`0.1.0-W1-074` 已交出 `BlockedState.plain` 的 `onDegradedView` slot，但 `domain_view_screen.dart` 的
`_SchemaUnconsumableView` 未傳入該 callback，`action-domain-degraded-view` 因此無法渲染，
`state-domain-schema-unconsumable` 的降級退出路徑仍不可操作——`0.1.0-W1-035` 定案的「型別表缺席時
降級而非拒絕」在 UI 上未落地。

### 影響範圍
- `lib/screens/domain_view/domain_view_screen.dart`：`_SchemaUnconsumableView` 需接線 `onDegradedView`；
  新增版本閘門判斷（`.claude/VERSION` 高於內建型別表版本時不提供出口，SPEC-001 §1）。
- `test/unit/screens/domain_view_test.dart`：需補退出路徑操作後狀態確實改變的斷言（regression:
  `test-assertion-design` 規則要求斷言產物不同，非僅斷言按鈕存在）。

### 相關 Error Pattern
無新增；沿用 `0.1.0-W1-074` 的 `test-assertion-design` E1（傳與不傳對照組）精神，延伸至「操作後狀態
是否真的改變」的鑑別力要求（見本票 acceptance 第 3 項）。

### W（Widen）
候選方案：(a) 直接接線 `onDegradedView`，版本閘門用簡單逐段整數比較（採用）；(b) 引入
`package:pub_semver` 做版本比較（過重，專案未有此依賴，且版本字串格式非嚴格 semver）；
(c) 版本閘門邏輯移到 `domain_view_state.dart`（拒絕，狀態層不應含畫面決策邏輯，且會超出本票
`where.files` 範圍）。

### A（Attain distance）
機會成本：本票不處理常駐徽章（`badge-domain-degraded-schema`，依賴 `0.1.0-W2-009` 返回列容器）與
「build 內嵌型別表副本」的實際資產化（tracking_schema.json 讀入 App bundle）——兩者皆記於
NeedsContext，不在本票範圍內展開。

### P（Prepare to be wrong）
最可能失敗原因：版本閘門常數（`_builtinSchemaVersion`）目前為畫面層寫死值，未來若「build 內嵌型別表
副本」資產化落地，此常數需同步改為讀取實際內嵌檔案的 `schema_generated_at_framework_version`，
屆時本票寫死值會與真實資產不同步——已在程式碼註解標明「0.1 資產化本身不在本票範圍」，降低漂移風險。

## Solution
<!-- Schema[IMP/Solution]: 選填（.claude/pm-rules/ticket-body-schema.md） -->
### 修改內容
1. `lib/screens/domain_view/domain_view_screen.dart`
   - 新增私有常數 `_builtinSchemaVersion`（對應 `tracking_schema.json` 之
     `schema_generated_at_framework_version` 實際值 `2.40.3`，撰寫時查證）與比較函式
     `_isHigherThanBuiltinSchemaVersion`（逐段整數比較，段數不足補零，無法解析時安全預設回傳
     `true` 即拒絕提供出口，呼應 SPEC-001 §1 顯式關卡精神）。
   - `_SchemaUnconsumableView` 依 `state.version` 是否高於內建版本，條件式傳入 `onDegradedView`；
     按下後將 `domainViewStateProvider` 狀態轉為 `DomainReady(mode: matrix, isDegraded: true)`。
   - 更新檔頭與 `_SchemaUnconsumableView` 上方文件註解，移除「缺件」描述，標明徽章仍缺件並引用
     `0.1.0-W2-009`。
2. `test/unit/screens/domain_view_test.dart`：新增兩個測試——
   - 版本不高於內建版本：斷言按鈕存在、按下後 `container.read(domainViewStateProvider)` 為
     `DomainReady` 且 `isDegraded == true`，並斷言畫面確實渲染 `state-domain-matrix`（正向操作後
     狀態與畫面雙重驗證，非僅斷言按鈕存在）。
   - 版本高於內建版本（`9.99.9`）：斷言 `action-domain-degraded-view` 不存在，僅
     `action-domain-switch-project` 可用。

### 型別表資產化範圍說明
「以 build 內嵌的型別表副本解析」中「解析」步驟（讀取 established 邊、只渲染 12 條 established
邊）本身依賴 domain 視圖目前的假資料架構（`domainViewProviders.dart` 說明：全域 fixture 驅動，不接
真實資料夾與圖建置）。本票僅接線版本閘門與狀態轉換，未實作真實 JSON 資產內嵌與解析——此為既有
架構邊界（同檔頭「假資料驅動，不串真實資料」註記），非本票遺漏；待真實資料整合票落地時一併處理。
