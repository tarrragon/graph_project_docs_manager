### Task Reference
- 0.1.0-W3-143 what: 裁定 七個無有效寫入能力的 agent 定義，其 description 與 tools 各該修哪一邊

### Rationale Chain
- 0.1.0-W3-143 why: `0.1.0-W3-141` 找到的根因是 `saffron-system-analyst` 的 frontmatter 自相矛盾——`description` 明寫「檢視/**撰寫**需求文件」，`tools` 為 `Read, Grep, Glob, LS, Bash, mcp__serena__*` 不含 Write／Edit。建票者依 description 指派完全合理，卻必然卡住：serena 的寫入工具依 `tool-selection` 規則 1 禁用於 `.md`。該票只加派發前偵測，明示修法屬 agent 定義範疇、交 PM。

PM 實查 `.claude/agents/` 全部定義後確認**不只 saffron**。無有效寫入能力者七個，分兩種形態：

- **A 類（完全無寫入工具）**：`basil-writing-critic`、`incident-responder`、`linux`、`oregano-data-miner`、`sumac-system-engineer`
- **B 類（僅 `mcp__serena__*` 命名空間萬用字元，對 `.md` 依規則 1 禁用）**：`saffron-system-analyst`、`sassafras-data-administrator`

逐一對照 description 後，三個一致、兩個矛盾、兩個疑似：

| agent | description 承諾的產出 | 判定 |
|-------|---------------------|------|
| `basil-writing-critic` | 「產出審查報告，不修改文件」 | 一致——明示不寫 |
| `incident-responder` | 「開錯誤處理 Ticket」 | 一致——有 Bash 可呼叫 ticket CLI |
| `linux` | 架構決策與技術審查 | 一致——回報型 |
| `oregano-data-miner` | 「為執行代理人提供詳細的實作指引」 | **矛盾，且最嚴重**——無 Write 亦無 Bash，既不能寫檔也不能填 ticket body 或建票。依 quality-baseline 規則 5 情境表，這類 agent 在派發階段即不應被指派 ANA 型 ticket，但「策略規劃者」的定位本質上就是 ANA 型工作 |
| `saffron-system-analyst` | 「檢視/撰寫需求文件」 | **矛盾**——W3-141 的來源實例 |
| `sassafras-data-administrator` | 「設計資料儲存方式、設計資料遷移方案」 | 疑似——產出若須落為文件則同 saffron |
| `sumac-system-engineer` | 「規劃及建置系統執行環境、SERVER 安裝及設定」 | 疑似——有 Bash 可安裝，但改設定檔需 Edit |

**為何不能一律補 Write／Edit**：`saffron` 是 TDD 前置審查專家，賦予寫入權可能違反「審查者不修改被審對象」的設計意圖——`basil-writing-critic` 正是以「不修改文件」為明示約束的同型 agent，兩者的正確修法可能相反（一個改 description、一個維持現狀）。每個 agent 須分別判斷，不套用單一答案。

**擴散範圍**：`.claude/agents/` 是框架資產，經 sync 擴散至全部 consumer 專案。改動影響的不只本專案。
