> 於〈確定性斷言的基礎形態〉表後補一段：「結構驗證用於存在性判定時，斷言檢查該結構是否存在，不得改採等價於功能正確性的固定長度比對（如『長度為 0』）——內容政策定義的『不顯示』與『顯示但為空』是不同結構，後者的斷言方式會讓陣列仍存在時的情境被誤判為通過。邏輯不變式用於上界／下界關係時，斷言驗證該關係本身，不得改採功能正確性的固定值比對（如『筆數等於上限值』）——上界／下界屬可調整的業務政策，固定值斷言會在政策調整時無謂失敗，關係式不受影響。」

#### 反向框架結果（草稿需修正的兩處）

1. **草稿理由與既有條文相衝**：草稿以「上界屬可調整業務政策，固定值斷言會在政策調整時無謂失敗」作依據。SKILL.md〈確定性斷言的基礎形態〉表下既有句規定功能正確性的預期值取自 spec 條文；政策調整即 spec 變更，測試隨之改是預期行為，不是無謂失敗。以維護成本為判準會讓讀者推出「凡可能改的 spec 值都不寫固定值」，與功能正確性類型本身矛盾。
2. **真正的判別軸是宣告的語句形態，不是值會不會變**：「最多 20 筆」宣告的是上限關係 → 邏輯不變式；「不顯示清單容器」宣告的是存在與否 → 結構驗證的存在性；若規格寫「顯示前 20 筆」則宣告的是具體值 → 功能正確性比對 20。此軸可同時解釋範例兩半，兩條草稿規則合併為一條。
3. **殘留風險（P 階段）**：「筆數小於等於 20」在畫面顯示 0 筆時也成立，鑑別力弱。依〈斷言品質三問〉聚焦性一句宣告一面向，「顯示清單內容」由另一測試案例驗證，本條不處理；列為探針相反分支題候選，不擴大本票範圍。
