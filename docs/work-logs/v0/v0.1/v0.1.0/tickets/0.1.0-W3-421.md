**範圍確認**：W3-417 盤點表中 test-assertion-design 僅 1 項「條文查無」（D-24b），0 項「部分」。D-19～D-24a 已有依據句，不在本票處置範圍。

**查證**：`git grep -F` 搜尋本 skill 全文（SKILL.md／CHANGELOG.md／references/）與專案內 `.claude/rules/core/test-assertion-design-rules.md`、`.claude/methodologies/`，以「不斷言」「固定值」「上限」「無謂失敗」「存在性」等關鍵詞查找，命中位置僅在範例區塊內（該範例本身，含 v1.7.0 修正互斥的 And 句）；〈確定性斷言的基礎形態〉表（26-35 行）只定義「結構驗證」「邏輯不變式」兩類別是什麼（驗證欄位存在／型別／陣列長度；驗證數學關係 a<b），未明文規定「當存在性判定對應「不顯示」語意時不得改採長度斷言」或「當上界屬可調整業務政策時不得改採固定值比對」——這兩條是本判定實際依賴、但只在範例內成立的規則，屬新增判準而非既有文字的路由整理。

**判定：階段 2（需新增判準、會改變既有判定），只寫草稿，不改 SKILL.md**

**草稿**（供 WRAP 審閱，非用戶程式碼風格偏好，不上呈用戶）：

> 於〈確定性斷言的基礎形態〉表後補一段：「結構驗證用於存在性判定時，斷言檢查該結構是否存在，不得改採等價於功能正確性的固定長度比對（如『長度為 0』）——內容政策定義的『不顯示』與『顯示但為空』是不同結構，後者的斷言方式會讓陣列仍存在時的情境被誤判為通過。邏輯不變式用於上界／下界關係時，斷言驗證該關係本身，不得改採功能正確性的固定值比對（如『筆數等於上限值』）——上界／下界屬可調整的業務政策，固定值斷言會在政策調整時無謂失敗，關係式不受影響。」

**會改變哪些判定**：此草稿把目前只在單一範例（元件執行期行為）成立的兩條規則，提升為〈確定性斷言的基礎形態〉表的通用判準，適用範圍由「該範例的兩種狀態」擴大到「任何存在性判定／上下界判定」。可能影響讀者對「結構驗證」「邏輯不變式」與「功能正確性」三類別邊界的既有理解——目前表格僅以類型定義區分，草稿補上「何時不得改用功能正確性寫法」的排他句，等於新增一條跨類別的選用限制，非現有句子的引用或路由，故不逕行落檔，停手交 PM／WRAP 裁決是否採納、或另尋更輕量的表述。
