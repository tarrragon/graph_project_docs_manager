## 重現實驗結果

### 實驗方法

環境：macOS 26.5（Build 25F71）、Flutter 3.47.1 / Dart 3.13.1（FVM）、`macos/Runner/*.entitlements` `com.apple.security.app-sandbox = false`。
以裸 dart 程序（`fvm dart run`）執行 `Process.run('/usr/bin/open', args)`，對 scratchpad 內臨時建立的檔案／目錄各測一次，另測不存在路徑、無應用程式對應的副檔名（`.zzqq`）、`open -R`（Finder 顯示）與 `open -t`（強制文字編輯器）。`url_launcher` 依派發約束只評估不加依賴：讀 `~/.pub-cache/hosted/pub.dev/url_launcher_macos-3.2.5/.../UrlLauncherPlugin.swift`。

### 實驗執行

| 案例 | 指令 | exit | 耗時 | stderr |
|------|------|------|------|--------|
| 檔案 | `open <dir>/note.md` | 0 | 469 ms | （空） |
| 目錄（路徑含空白） | `open "<dir>/docs sub"` | 0 | 542 ms | （空） |
| Finder 顯示 | `open -R <dir>/note.md` | 0 | 480 ms | （空） |
| 不存在 | `open <dir>/nope.md` | 1 | 23 ms | `The file ... does not exist.` |
| 無應用程式對應 | `open <dir>/weird.zzqq` | 1 | 44 ms | `No application knows how to open URL ... kLSApplicationNotFoundErr` |
| 強制 TextEdit | `open -t <dir>/weird.zzqq` | 0 | 197 ms | （空） |

`url_launcher_macos` 3.2.5：`launchUrl` → `NSWorkspace.shared.open(URL)` 回傳 `Bool`；`canLaunchUrl` → `urlForApplication(toOpen:) != nil`。與 `open` 相比無額外資訊，且多一個依賴。

### 實驗發現

已驗證的事實：

1. 沙盒關閉下，`/usr/bin/open` 可開啟檔案與目錄（含路徑含空白），成功回傳 < 600 ms。
2. 失敗訊號可分辨：不存在 → exit 1 + 「does not exist」；無應用程式 → exit 1 + `kLSApplicationNotFoundErr`。
3. `open` 無行號參數；「定位至行號」無通用路徑（需編輯器專屬 scheme）。
4. `url_launcher` 不提供 `open` 沒有的能力。

仍未驗證的假設：

- A1：在 Developer ID 簽章 + notarization 的 `.app` 內 `Process.run('/usr/bin/open')` 行為與裸 dart 程序一致。依據：PROP-001 已在沙盒關閉的 app 內實測 `Process.run('/bin/echo')` exit 0，`open` 同為系統 binary，Hardened Runtime 不限制 spawn 系統程式；風險低但未親測，列為 `0.1.0-W1-068` 實機驗收項。

## Solution
<!-- Schema[ANA/Solution]: 必填（.claude/pm-rules/ticket-body-schema.md） -->
### WRAP 快速模式

**錨點**：客戶是使用本 App 追溯文件關係的維護者；0.1 核心目標是七畫面可導航。外部開啟是四處畫面的退出／前進動作，FR-06 要求形態明確，影響 W2 畫面票的元件承載，屬核心路徑上的決策。

**W（選項擴增，實質差異）**：

| 方案 | 內容 | 利 | 弊 |
|------|------|----|----|
| A 落地：`Process.run('/usr/bin/open')` + 可注入抽象 | 0 新依賴；失敗以 exit code 判定；fake 斷言 | 規格既有斷言方式（概述表「外部程序呼叫以 fake 呼叫紀錄斷言」）直接可用；不需回頭改四處 | 簽章 app 內未親測（A1）；行號定位無通用路徑 |
| B 落地：`url_launcher` | 官方套件 | 跨平台抽象 | 多一個依賴；能力與 A 等價（`NSWorkspace.open` 二值回傳）；目錄要組 `file://` URL |
| C 不落地：四處 `enabled: false` + 常駐說明 | FR-06 形態 (b) | 零實作 | 四處各需 disabledReason 文案與 i18n key；SPEC-001 §2 FR 驗收「提供開啟原始檔的動作」形同虛設；落地時再改四處，等於兩次改動 |
| D 不落地：不渲染（FR-06 形態 a） | 移除四處動作 | 最省 | 違反 SPEC-001 §2、§5、§6 的退出／可用操作宣告，需改 SPEC-001，超出本票 |
| E 落地但只 `open -R`（Finder 顯示） | 永不撞「無應用程式」 | 失敗面更小 | 使用者要的是開檔不是找檔；仍無行號 |

**R（基本率）**：macOS 桌面工具開外部檔案的常見解就是 `open` / `NSWorkspace.open`，成功率取決於 LaunchServices 綁定；「檔案不存在」「無應用程式」是僅有的兩類可預期失敗，實測皆有明確 exit 1 訊號。行號定位的基本率：只有編輯器專屬 scheme 可做，無通用解。

**A（機會成本）**：選 C/D 會把成本挪到 W2 畫面票與未來的重做；選 A 的額外成本是一張抽象實作票與一個 i18n key。落地不擠壓其他 0.1 目標。

**P（最可能失敗）**：簽章後 `.app` 內 `Process.run` 行為與裸 dart 不同（A1）。防護：W1-068 acceptance 明列實機驗證；若失敗，抽象層不變，實作改走 `url_launcher_macos`（方案 B）即可，四處規格不需再動。

**定案：方案 A，0.1 落地。** 行號定位收窄為「0.1 不做」並另立追蹤票。
