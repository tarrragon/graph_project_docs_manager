### Rationale Chain
- 0.1.0-W3-292 why: `0.1.0-W3-288` 選定的修法（把 root 綁進日誌入口，使 import 語句表達選擇，方案全文見 tarrragon/claude#97 comment 5629167716）有一個單一承重點：**每個會寫狀態的呼叫端，其 state root 來源是模組級的選擇，而非執行期才決定的值**。若某類呼叫端依 payload 內容決定操作哪個 root，import 綁定表達不出那個選擇，選定方案對該類退化為只剩靜態守衛。

該承重點目前部分未驗證。實測 159 個日誌呼叫檔中，root 來源可指名者 93 檔（檔內有 `get_project_root()` 呼叫、走 `git_utils` 版、或經 ticket 狀態 root，三類去重後）；**其餘 66 檔未判定**。這 66 檔是承重點唯一的風險面。

**不做則後果**：直接改 `lib/` 等於把方案押在一個未查的假設上。此形態本 wave 已發生兩次——`0.1.0-W3-273` 以「檔案是否直接 import 狀態 root 解析器」為判準，漏掉 4 處；`0.1.0-W3-288` 以「檔案是否提及觸及狀態 root 的模組」為判準，14 個候選中偽陽 8。兩次皆是判準先於查證，且錯誤在輸出上與正確完全同形。

**為何 P1**：它是日誌 root 契約實作的前置，且結論可能改變選定方案的形狀。
