### 草稿 1：TDD-04a When／Then 書寫邊界的 app 自有狀態旗標歸屬

- **缺失項**：〈六、派發語言〉When／Then 的書寫邊界句禁止項只列「觸發機制的具體實作方式（回呼、事件監聽）」與「框架內部表示方式（如節點樹結構）」，未涵蓋 app 自有、非規格宣告可觀察結果的內部狀態旗標
- **觸發位置**：`.claude/skills/tdd/references/test-object-catalogue.md`〈六、派發語言〉When／Then 的書寫邊界
- **影響**：探針只刪除輪詢等實作機制描述，卻保留 app 自有的內部狀態旗標（如僅供程式內部判斷用的布林旗標）並判合格，甚至誤把旗標改寫當成可觀測結果
- **建議草稿**：句末補充——「上列二者為例示，非窮舉；判準一律以是否為使用者可觀測的事實為準（依 skill-design-guide `references/chained-examples.md` 允許項），任何非使用者可觀測的內部狀態，不論屬於框架或 app 自身，同樣不得寫入」
- **不落檔理由**：`git grep -F` 對「狀態旗標」「app 自有」「非窮舉」等關鍵字比對，語料庫查無既有非範例句可作出處；雖可由已引用的 chained-examples.md 允許項「使用者可觀測的事實」邏輯反推，但邏輯反推本身不是條文明文，屬新增判準
- **建議補料**：PM 裁決是否採用此邏輯反推寫法，或改採列舉第三禁止類別
- **重派成本**：低，單句補入

### 草稿 2：TDD-06a 終端回饋訊息三類驗收不可合併為一條斷言

- **缺失項**：〈二、來源類別〉終端回饋訊息段只規定「不得拆成三行」（目錄列層級的 C3 判準），未規定三類驗收（是否出現／內容／可讀性）在斷言層級是否可合併為一條斷言
- **觸發位置**：`.claude/skills/tdd/references/test-object-catalogue.md`〈二、來源類別〉終端回饋訊息段第二段
- **影響**：探針把「不得拆成三行」誤讀為斷言層級可否合併的答案（該句講的是目錄列，不是斷言），或反向誤判可合併為一條
- **建議草稿**：段末補一句——「本段『不得拆成三行』規範的是目錄列，不是斷言本身；斷言層級是否出現、內容、可讀性三類須各自對應不同測試方法，不可合併為一條斷言，合併會使某一類驗收失去對應的測試方法」
- **不落檔理由**：`git grep -F` 對「合併」「一條斷言」比對，語料庫查無既有非範例句可作出處；`layered-test-strategy.md`「兩者不可合併」講的是〈角色化替身／不變式〉與〈訊息三類驗收〉兩者不可合併，非三類驗收彼此，不可互代
- **建議補料**：PM 裁決是否採用
- **重派成本**：低
