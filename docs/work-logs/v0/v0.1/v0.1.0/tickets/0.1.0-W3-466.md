**落檔內容**（`.claude/skills/tdd/references/bdd-behavior-testing.md`〈BDD→單元拆分標準〉，接在〈多訊號同時成立時〉段之後）：

> **判定不拆分 Module**（到達「考慮拆分 Module」時適用；不論是由單一 Given 訊號直接到達，或依〈多訊號同時成立時〉移除後仍 > 10 行 Mock 到達，皆同）：下列兩項條件都能從測試程式碼或題設逐項查證成立時，判定 Given 設置的長度來自受測 UseCase 串起的外部依賴、不是 Module 過大，不拆分 Module；任一條件不成立、或無法查證，依「Given 設置過長」列動作考慮拆分 Module：
>
> 1. 受測 Module 對外只有一個 UseCase 進入點：該 Module 的所有 BDD 場景，When 都呼叫同一個 UseCase 進入點。
> 2. 計入 Given 設置行數的每一行替身設置，都屬於該 UseCase 某個流程步驟會呼叫的外部依賴。沒有任何流程步驟呼叫的外部依賴時：建構受測對象不需要它，其設置行先刪除、不計入行數；建構受測對象需要它，本條件不成立。

**逐詞可推性**：條件 1 為機械可查——列出該 Module 全部 BDD 場景的 When 步驟，比對是否皆呼叫同一 UseCase 進入點。條件 2 為機械可查——逐行核對計入行數的替身設置，是否對應該 UseCase 某流程步驟會呼叫的外部依賴；無步驟呼叫者，依受測對象建構是否需要它二分（不需要則刪除不計、需要則條件不成立）。「串接列不構成依據」為射程澄清句，排除以訊號表既有列反向論證條件成立。

**判「否」反例**（不寫入條文，僅供本票驗證；避開 `probes/q/W3-417-b4-tdd-*.md` 命中詞「預約」「門診」「排班」「借閱」「借書」「續借」「稅務」「金流」「扣款」等，改用零命中的「退租結算」域）：退租結算 Module 只有一個 UseCase 進入點（條件 1 成立）；步驟呼叫租約儲存庫、押金金流閘道兩個外部依賴，但建構子另要求注入推薦獎金服務、沒有任何流程步驟呼叫它，Given 仍設置該依賴 3 行、其餘 9 行對應前兩個依賴，合計 12 行。依條件 2：推薦獎金服務的 3 行設置對應「沒有流程步驟呼叫的外部依賴」，但建構受測對象需要它（非殘留可刪），條件 2 不成立 → 判定「不適用不拆」，依訊號表動作考慮拆分 Module。
