評估 ux 判準第 2 項 2.11「同一圖形只承載一個語意」與 2.8 (b) 移出動作列的優先序（W3-474 草稿 A／B）

## Problem Analysis
### 問題根因

第 2 項 2.11「同一圖形在全畫面只承載一個語意」與 (a)(b) 判定互不引用，條文推不出 2.11 違反時第 2 項是否不合格（W3-474 NeedsContext）。根因是 2.11 從來源搬入時失去了「第二層問題」的定位：

- 來源：`cffdda1df`（框架導入，1.2.0 版「元件語意與版面」檢查層）單句「指示用明顯非按鈕形態（文字 chip、圓點）或移出動作列，同一圖形全畫面只承載一個語意。」該層取自 blog 案例 U.C18（`blog/content/ux-design/cases/status-icon-mistaken-for-button.md`，commit `29818cc0`）。
- U.C18 原本射程：〈判讀〉3「圖示語意撞名是第二層問題……同一個圖形承載兩個語意，即使解決了可點性、語意混淆仍在。圖示選擇要全畫面去重。」〈策略〉1（改形態／移出動作列）與〈策略〉2（圖示全畫面去重）分列兩條。撞名的「語意」指圖示代表的事物（「查書籍資料」vs「實體書」），不是可點與否。
- 演變：`054ee3f2a` → `0c21b9420` → `4244e912a` → `2250c6c37` 皆把此句留在 (a)(b) 句尾；`d992edf59`（W3-471）獨立為 2.11；`2bcd3bcb7`（W3-474）補 2.11(2) 圖形範圍。沒有任何一版寫過它與 (a)(b) 的關係。
- skill 內其他相關條文：`interaction-feedback-checklist.md`〈檢查清單〉「非互動指示與動作按鈕形態可區分、圖示無撞名？」——兩件事以頓號並列；反模式表「狀態圖示與動作按鈕同形混排」處置只列「改非按鈕形態、移出動作列」，沒有圖示去重。
- W3-457.5 #4 傾向 4-A 時曾寫「異列同形是另一種危害（外觀模仿），與 2.11 較接近」並標盲點「2.11 射程沒定義，D4 型畫面可能兩條都攔不下」；用戶裁示 4-A 時接受代價「與可點元素同形的指示放到別列就合格」。

### 影響範圍

- 已驗證：`interaction-feedback-component-semantics.md` 2.11 為唯一條文位置（`git grep -F "同一圖形"`）；09f 答案鍵計分點已寫「以 2.11 判不合格者不通過」。
- 已驗證：1.11.9 的 2.11(2) 把「圖形」限於圖示與純幾何形狀，09f「素食」是文字＋區塊，不在 2.11 射程內。所以 09f 在 1.11.9 對任何方案都無鑑別力，優先序問題只剩圖示與純幾何形狀會觸發。
- 未驗證：讀者實際採哪種讀法（需探針）。
