## Problem Analysis
### 問題根因

commit 3f12fa9e（W3-452）自述「不新增判準、只重排既有結構」，但其中兩處在條文加入了原本沒有的句子：
- FD-05b：〈權威缺席時〉「框架內確實無承接者」列的產物層，指明了「四種」是哪四種，並要求選「無」時必須符合〈判定「失效不存在」的理由〉。
- FD-13a：〈移植前置條件〉降級段新增「缺 ticket 系統時，把應建票的內容記入降級記錄，不套用形態 4」。

用戶常駐裁示：新判準須經 WRAP。本票對兩處各答三問：(a) 有無既有權威出處 (b) 有無改變既有讀法 (c) 判定本身對不對。

### 影響範圍

- 檔案：`.claude/skills/foundation-design/SKILL.md`。只讀，W3-453 正在修改同一 skill。
- 已驗證的事實：見〈重現實驗結果〉，全部以 `git grep -F` 與 `git show <commit>:<path>` 在 3f12fa9e 上查證。
- 未驗證的假設：第 3 批 FD 重建節錄檔後，新條文下的探針作答結果。本票不跑探針。

### 相關 Error Pattern

判準只寫在範例裡，或撰寫者自評「未新增判準」而實際擴充了內容：同 W3-417 讀者探針閘門的「依據只在範例內」系列。未另立 error-pattern。

### 實驗發現

**FD-05b（已驗證）**
- 「無」須符合〈判定「失效不存在」的理由〉：有條文出處（#4、#5），射程涵蓋形態 3 產物層。
- 「不含照預設」：可由條文推出（#3 seed 無預設產物，加上「照預設」列的何時使用）。但與 2310abdf 撰寫時「四種」的原意不同（#2：當時的四種含照預設、不含待定）。現行五種表下，舊句「四種」已經失去指涉，新列舉與 #5 一致，屬把失去指涉的數字重新錨定到現行條文。
- 讀歪風險：新句「不得僅因該物件目前不存在就代入」的「物件」，與〈判定「失效不存在」的理由〉的「對象」近義。依該節，「對象不存在」正是填「無」的合格理由（#6），讀者若把「物件」讀成「對象」，兩句會變成互相矛盾。本意是「產物（seeder）目前不存在」。

**FD-13a（已驗證）**
- 「步驟 4 與建票動作不成立」：有出處（前置條件第二項、降級段）。
- 「不套用形態 4」：由形態 4 的觸發條件「工作流自身引用的 skill 缺席」直接推出，與答案鍵一致。
- 「應建票的內容直接記入降級記錄」：無既有出處（#7、#8、#9）。它擴充了降級記錄必須記的內容（#10），屬新判準。
