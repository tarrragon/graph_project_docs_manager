### 併入的第二項：`ticket track phase` 的 frontmatter 變更不被 auto-commit 涵蓋（2026-09-10）

由 `0.1.0-W3-176` Phase 3a 的 worktree 代理人回報並寫入該票 NeedsContext，PM 已查證。

**三個限制疊起來形成靜默漏失**：

1. `ticket track phase` 改動票 frontmatter（`tdd_phase`），但**不觸發 ticket md auto-commit hook**。查證：`0.1.0-W3-176` 的 Phase 2 轉 Phase 3a 由 commit `ac475e87` 落地，其 message 為「docs(0.1.0-W3-176): Phase 2 測試設計完成，轉 Phase 3a」——是該代理人**手動**提交的，非 auto-commit 產物。
2. worktree 隔離的代理人無法以 `git -C <主 checkout>` 補提交（隔離的用意即在此）。
3. `ticket track commit` 因 `where.files` 範圍檢查拒收票檔——**即本票主文**。

**後果**：若某階段的最後一個動作是 `phase`，該 frontmatter 變更會**靜默停在工作區**——下一階段的代理人讀到的票仍是舊 phase，而全程零錯誤訊號。`0.1.0-W3-176` 本次未發生，僅因 `phase` 之後還有一筆 `append-log` 把它順帶掃入；換句話說，**它這次是被偶然救回來的，不是被機制保證的**。

**與本票主文的關係**：主文修好第 3 點（`ticket track commit` 接受自身 md）即給了代理人一條合法補救路徑，漏失不再無解；但**第 1 點是獨立缺陷**——即使有補救路徑，仍依賴代理人記得補提交。兩項一併修較完整，故併入本票而非另開。

**第二項的修法方向**：使 `phase` 與其他會改動票 md 的子命令走同一條 auto-commit 路徑。**先查證**目前哪些子命令有 auto-commit、`phase` 是刻意排除還是遺漏——若為刻意（例如避免階段轉換與內容變更混在同一 commit），則改為在 `phase` 完成後輸出明確提示要求提交，而非靜默。

> **本節原於 2026-09-10 誤寫入 `0.1.0-W3-248`（他人票），已於該票加更正說明並移除誤加的 acceptance。** 成因是建票後未查證實際配號，憑預期記錄票號。
