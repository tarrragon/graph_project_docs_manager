**兩項必須寫進規格的事實，來自 PM 覆核**：

1. **本專案有兩種接縫形態，不是一種。** `WorkspacePreferencesPort` 與 `WorkspaceDirectoryProbePort` 是 `abstract interface class` + private `_Default*` adapter 類別；`DirectoryPathPicker`（`lib/workspace/workspace_repository.dart:80`）是 `typedef` 函式型別，生產預設直接為 `getDirectoryPath`，無 adapter 類別。兩者的三個回饋點承擔者不同——前者的受理與結果由 adapter 承擔，後者三時刻全由呼叫端承擔。形態本身的約定歸 `0.1.0-W3-146`（寫進 `docs/tech-decisions.md`），本規格只描述各形態下回饋點由誰承載。

2. **`_DefaultWorkspaceDirectoryProbePort` 全無日誌。** PM 讀原始碼確認該 adapter 兩個方法（`exists` / `readFirstEntry`）皆為單行直呼 `dart:io`，無任何 `developer.log`。`0.1.0-W3-139` 記為「`exists()=false` 日誌缺失」，實際範圍比該描述更廣。規格須據實描述現況缺口，缺口的修補歸 `0.1.0-W3-135`。（來源已完成，結論見 Solution）
