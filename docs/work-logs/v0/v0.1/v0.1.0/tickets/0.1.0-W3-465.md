## NeedsContext
### 草稿 1：TDD-20b 列索引一般判準

- **缺失項**：〈GWT 種子與行為單元的分工邊界〉「列索引」只以名稱「場景」舉例，未給一般判準
- **觸發位置**：`.claude/skills/tdd/references/doc-handoff-uc-to-gwt-conversion.md`〈GWT 種子與行為單元的分工邊界〉第一段（含表頭範本「| 場景 | Given | When | Then | 來源 |」）
- **影響**：欄名換成其他標示列序用途的名稱時，r2／r3 分別往「計入四欄」「場景仍為固定欄位」兩個相反方向誤讀，皆源於此
- **建議草稿**：段末補一句——「表頭中只用來標示列序、不承載 Given/When/Then/來源以外任何內容的欄位，屬列索引，不計入四欄之列；此判準不限定於特定欄名，本範本以『場景』為其名稱」
- **不落檔理由**：`git grep -F` 對「不承載」「列序」「純索引」等關鍵字比對，本專案語料庫查無既有非範例句可作出處（唯一命中為診斷本缺口的 0.1.0-W3-417 工作日誌本身），屬真正新增判準
- **建議補料**：PM 裁決是否採用；採用後檢查 `test-object-catalogue.md` 是否需要同型態補充
- **重派成本**：低，單句補入

### 草稿 2：TDD-36a 值驗證／存在性驗證分類判準

- **缺失項**：Q_new3「值驗證」與「存在性驗證」二分缺分類語意判準，只以括號例示 API 名稱界定
- **觸發位置**：`.claude/skills/tdd/references/phase2/rules.md` Q_new3〈行動路徑〉第一句
- **影響**：換用非例示 API（如 `length` 大於零的數值比較）後，判定者因字面是數值比較誤歸為「值驗證」
- **建議草稿**：「存在性驗證（如 isNotNull, containsKey）」前補一句——「存在性驗證檢查的是『有沒有』（是否非空、是否存在、長度是否大於零等），不檢查『內容是什麼』；值驗證檢查的則是內容本身，判準依斷言檢查的語意而非特定 API 名稱」
- **一致性核對**：本草稿只新增「如何分類」，不改動同段既有「足夠」判定句（目標功能失效時該驗證會翻紅即為足夠，已由 0.1.0-W3-463 落檔）；分類發生於判斷足夠之前，兩者管不同步驟，採用後不衝突
- **不落檔理由**：`git grep -F` 對「存在性驗證」「值驗證」比對，語料庫查無「有沒有 vs 是什麼」同義既有非範例句
- **建議補料**：PM 裁決是否採用；採用後檢查 `test-object-catalogue.md` 是否有同型分類需求
- **重派成本**：低

### 草稿 3：TDD-37b Q_new4 無盲點時是否產出

- **缺失項**：Q_new4「建立對照表，空格代表測試盲點」未寫明無盲點（全數已覆蓋）時是否仍須產出此表
- **觸發位置**：`.claude/skills/tdd/references/phase2/rules.md` Q_new4〈行動路徑〉
- **影響**：全部異常路徑皆已覆蓋時，判定者以「建表用途是識別盲點」反推「無盲點不需要建表」
- **建議草稿**：「空格代表測試盲點」後補一句——「不論核對結果有無空格，此表都必須產出；建表是逐項核對每個異常路徑是否有對應失敗測試的手段，不是只在懷疑有漏洞時才需要的診斷動作」
- **不落檔理由**：`git grep -F` 對「無論是否」「空格代表」比對，語料庫查無同義既有非範例句可作此判準出處
- **建議補料**：PM 裁決是否採用
- **重派成本**：低

### 草稿 4：TDD-39a 前置條件類型表分類軸

- **缺失項**：〈前置條件驗證強制規則〉表混用物件命名（UI 元素存在）與狀態命名（操作可執行）兩軸，同一元素可能同時符合兩列，表格外觀卻像互斥分類
- **觸發位置**：`.claude/skills/tdd/references/phase2/rules.md`〈前置條件驗證強制規則〉表
- **影響**：按鈕「存在且已啟用」被合成一條前置條件並歸為單一類型，未依「操作可執行」列的驗證方式另外核對
- **建議草稿**：表後補一句——「上列四類型不互斥，同一元素可能同時符合多列（如按鈕同時屬『UI 元素存在』與『操作可執行』）；依〈行為鏈推演執行步驟〉步驟 2『列出完整前置清單』，逐列檢查所有適用類型，缺一即為前置條件未驗證完整」
- **出處查核**：步驟 2 既有句「列出完整前置清單」（非範例）只支持「前置條件可能不只一項」，不足以單獨支持「表格四類型應視為可疊加而非互斥」這個判準本身——後者是本草稿真正新增的部分，故轉 NeedsContext 而非落檔
- **建議補料**：PM 裁決是否採用；若採用建議同時檢視 `.claude/methodologies/bdd-testing-methodology.md` 的同型表格（〈權限具備〉列，命名不同但同型）是否同步修正
- **重派成本**：低，但需 PM 確認是否與 bdd-testing-methodology.md 同步
