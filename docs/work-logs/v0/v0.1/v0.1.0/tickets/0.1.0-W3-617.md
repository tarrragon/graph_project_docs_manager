### PM 裁決：本票兩件事一次做完（Step 4 定位 ＋ 規格修正）

#### 一、Step 4 二分定位

**定位的產出是「該改哪一句」，不是「哪一條改動有效」。** 二分只在必要時做——兩處失分都已指名到句，若讀數足以定位就直接給處置，不要為了走完流程而二分。

- **Q15-r1**（doc 第二列）：認列正確，卻把該列管轄欄**本輪未改動**的半句「作為表格或列表一欄時填在該列」讀成「填在所屬容器的格位」。**判斷為既有缺陷被新題暴露，不是本輪改動的回歸**——請先驗證此判斷再定位。
- **Q02-r3**（7.2(3-2)①乙）：結論正確但整份依據句只引同款前段的 (a)(b)(c)，**受測款次零套用**。只看判定欄會記成 3/3。

#### 二、規格修正（W3-616 回報六項，一併處理）

本票承辦者是規格的下一個執行者，會撞上同樣的問題，故由本票改：

1. **§7 第 11／12／13 項「交集為空」不可滿足**（MIN_LEN=5 下 17 題無一為空）。兩類受測步驟的題幹必然實例化條文字串：受測「某份逐項清單有沒有寫完」、受測「某個特定援引動作被禁止」。W3-616 改以三類命中分類判讀（指涉性字串／前置步驟既定事實／題幹等於判定語），只有第三類判紅——請評估並寫進規格，或給更好的判準。
2. **指名覆蓋題可與同票自列禁區衝突，而「零覆蓋清單為空」攔不下它**。W3-616 實測兩處（8.2(4) 全稱量詞句的唯一題材被 L18 列為禁區，屬真零覆蓋；doc 第五列承載者資格的指名題材正是禁區詞「頁面根堆疊」）。Step 1 須加一道檢查。
3. **§1.2「一題一步」與 §3.1 核心禁令的界線未寫**：前置步驟的結論**必須**交出、受測步驟的**不可**。W3-616 已自行定義並逐題登記，請收進規格。
4. **§5.7 未界定一題三輪算 1 次還是 3 次**。W3-616 取「一次派發的題數 ≤ 8」。
5. **新發現的出題側缺陷，最要緊的一項**：正解在同一款次內另有第二條充分理由時，覆蓋題可被旁路，而 §1–§4 四道關**無一擋得住**——它不是題材、不是槓桿、不是字面通路。請設計第五道關或改寫既有關。
6. **路徑字串在 prompt 裡人工複製，錯到一個碰巧存在的目錄時無訊號**（本輪實際發生：`graph_project_docs_manager` 底線版目錄確實存在且內有舊檔）。§5 須加一條：派發前對輸出目錄做寫入探測，或路徑由腳本產生而非手打。
