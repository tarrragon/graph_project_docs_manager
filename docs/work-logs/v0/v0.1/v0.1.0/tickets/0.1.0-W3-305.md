## Problem Analysis
<!-- Schema[DOC/Problem Analysis]: 選填（若 DOC 起因於缺陷或盤點結論可填）（.claude/pm-rules/ticket-body-schema.md） -->
### 派發前登記：skill-design-guide SKILL.md 的作者意圖清單（十項，B 批差集的分母）

1. 本檔整合官方 spec 與本專案慣例，聚焦「為什麼這樣設計」與「怎麼做」，不重述官方全文
2. Concise is Key：每段文字要過兩問（刪掉輸出會變嗎／值得 token 成本嗎），第一問問的是行為差異不是知識空缺
3. 三層載入的預算：第 1 層 description 250 字元、第 2 層 SKILL.md 全檔小於 5k tokens 且小於 500 行、第 3 層目錄總量無上限而單檔判準是讀取方式
4. 三個預算的適用對象各不相同，先認對象再量
5. token 估算要分段加總（非 ASCII 取 1.3、ASCII 取 4），不是全檔比例內插
6. 行數是官方合規項不是體量判準；兩個都量、取較嚴者
7. 第 2 層無 hook 執法，完全依賴撰寫者自查
8. 超標時外移什麼的判準在 splitting reference；分界是「讀者在選路之前還是之後用到它」，不是互斥性
9. 按需讀取六份 references 各有觸發條件；路由表的「涵蓋章節」欄要與目標檔的 `##` 標題逐字相同且雙向齊全
10. 發布前檢查清單分四組，其中觸發測試那一組目前無可執行程序、不是閘門

### 三批探針的派發參數

| 批 | 餵入範圍 | 份數 | 問題軸 |
|----|---------|------|-------|
| A | 只餵 `SKILL.md` | 3 | 理解正確性、第一個具體動作、路由涵蓋、指涉詞、歧義 |
| B | 只餵 `SKILL.md` | 3 | 重點涵蓋度差集、只能記住三件事、閱讀負擔、語氣 |
| C | 只餵 `references/splitting-an-existing-skill.md` | 3 | 位置感、缺料自覺、下一步、可執行性 |

指令沿用 component-contract-design 三輪所用的同一組題型，使兩個 skill 的量測可橫向對照（但**不與該 skill 的數字直接比大小**——受測對象不同，只比形態）。

### 本票已知的三類待補內容（與探針獨立，來自 0.1.0-W3-294／296／302 的判決）
