### 階段 2 草稿：A-21（splitting-an-existing-skill.md〈補範例後超標〉）

**範例位置**：`references/splitting-an-existing-skill.md`〈補範例後超標：觸發條件與處置順序〉「一則範例」【產出】決策表第 2 列。

**範例教的判定**：路徑 A、路徑 B 互斥、讀者抵達前已知屬於哪一條 → 各路徑外移獨立成檔，入口檔保留共用說明與路由。

**條文查證結果**：全檔 `grep -n "互斥\|各自\|獨立成檔"` 命中的「各路徑外移獨立成檔」字面只出現在該範例自身的【產出】code fence 內（第 55 行），範例區塊外查無此句。〈外移什麼、留什麼〉四問（本檔另一節）雖處理「內容該搬到哪個目標檔」，但問 3 明文限定「該列須在本次拆分之前即已存在——為本次拆分新造的列不算」；範例情境是原本合併於同一檔內的互斥路徑，拆分前並無個別路徑的既有列，字面上落在問 3 的排除範圍之外，四問未涵蓋「原本合併、因超標才首次拆成路徑各自獨立檔案」這個情境。

**判定為需新增判準（非單純補路由）的理由**：本skill查無其他章節或其他 skill 陳述「互斥路徑首次拆分時各自成檔」這條通則；若把範例的【產出】決策表字句直接提升為條文，等於新訂一條規則，且與問 3「拆分前即已存在的列才適用」字面相衝突（該規則預設目標檔案拆分前已存在，範例卻是拆分當下新造路徑檔）——需要 PM／WRAP 裁決如何協調兩者（例如：問 3 加一條例外，或另立通則涵蓋「原本合併、本次拆分首次成檔」的情境），非 thyme 可逕行代寫。

**候選草稿（供 WRAP 參考，未落地）**：於〈外移什麼、留什麼〉問 3 之後加一條例外句，例如：「互斥執行路徑原本合併於同一檔內、因超標首次拆分者，各路徑各自外移為獨立新檔，此類新檔不受『該列須在本次拆分之前即已存在』限制；入口檔保留共用說明、判斷條件與各路徑的路由列。」

**會改變的既有判定**：〈外移什麼、留什麼〉問 3 目前的判定範圍（不含拆分當下新造的列）將被此例外句部分推翻，凡「原本合併、因超標首次拆分」的情境會從「問 3 不適用」改判為「問 3 適用（例外）」；影響未來所有走本節四問判斷互斥內容外移對象的審查子票。

**處置**：本票依用戶裁示不上呈用戶（非程式碼風格偏好），交由 PM／WRAP 後續裁決是否採納、如何措辭；本票不改動 `splitting-an-existing-skill.md` 檔案內容。

### 階段 2 WRAP 評估：A-21（獨立評估者，依 wrap-decision skill）

**評估範圍**：`references/splitting-an-existing-skill.md`〈補範例後超標：觸發條件與處置順序〉「一則範例」【產出】第 2 列「各路徑外移獨立成檔」。本組同主題另含 A-28／C-11a（票粒度，合併為判準 G1，權威見 0.1.0-W3-424）與 A-11／A-12（0.1.0-W3-418）；A-21 與 G1 不重疊（對象是 skill 檔案結構，不是票）。

**反向框架結果**：範例結論不只「缺條文」，而是與同檔條文**方向相反**。〈外移什麼、留什麼〉首段明文「互斥性因此不進入判定」，範例卻以「路徑 A、B 互斥」為外移依據。thyme 草稿（問 3 加互斥路徑例外）等於把條文已排除的判準重新引入，且削弱問 3「為本次拆分新造的列不算」的防規避目的。

**選項表**

| 選項 | 內容 | 會改變的判定 | 評估 |
|---|---|---|---|
