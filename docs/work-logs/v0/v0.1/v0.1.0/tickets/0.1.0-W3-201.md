### 2026-09-11 獨立復核：語意複查與既有條目抽樣（thyme）

**獨立復核結論：同意 PM 的未抵達判定，未發現字面掃描的漏網。**

複查方式：不依賴四組關鍵字，改以語意等價詞逐一檢索 `.claude/skills/error-pattern/` 全樹（`SKILL.md` 步驟 1-8、`references/synonym-map.md`、`lib/*.py` docstring）：「應被排除的情形」「不適用範圍」「邊界」「豁免」「exclude」「exemption」「不算」「negative example」。命中的段落逐一核對語意，均與「撰寫判準句時附反例」無關——分別是 severity 不變式的建立/驗證分工（第一手來源 vs 鏡射欄位）、numbering freeze 的協議字串豁免、allocator/severity_audit 模組間的依賴邊界。`/error-pattern add` 步驟 2-6（症狀、根因、解決方案、預防措施、關聯 Ticket）與步驟 7-8（配號、README 同步）確認皆未要求反例。判定：撰寫流程本身沒有反例要求，PM 判定成立。

**既有條目抽樣（判定回填分界用）**

抽樣方式：分層抽樣而非全量，覆蓋三個時間層 + 一個量化交叉驗證：
1. 早期古典型（2026-03~04 建立）：PC-001、PC-042、IMP-008、ARCH-001
2. BAL 系列分析型（2026-07 建立）：DOC-BAL-001、ARCH-BAL-005
3. GPD 系列（2026-09 建立，含 0.1.0-W3-200 直接指名的兩則與其鄰近實例）：PC-GPD-009、PC-GPD-014、PC-GPD-015、PC-GPD-016、PC-GPD-022
4. 量化交叉驗證：對全樹 532 篇條目（不含 README/CHANGELOG）以排除語意關鍵字組（`不算本模式|不屬本模式|不是本模式|不歸此類|不落入本模式|前提不可省略|應排除|排除在外|不構成本模式|反例` 等）grep，命中 28 篇（5.3%），逐篇核對排除偽陽性後，確認集中在最近兩個月的 BAL/GPD 系列，早期條目幾乎零命中。

抽樣結果：

| 分層 | 條目 | 是否具「分類型判準句」 | 是否附排除情形/反例 |
|------|------|---------------------|-------------------|
| 早期古典型 | PC-001, PC-042, IMP-008, ARCH-001 | 否——症狀多為可直接觀測的機械事實（cwd 污染、檔案行數超標），非需要鑑別力測試的分類判準 | 不適用（判準類型不落入 0.1.0-W3-200 鎖定範圍） |
| BAL 分析型 | DOC-BAL-001, ARCH-BAL-005 | 是——各有明確的分類/裁決判準句 | 否——兩篇均未附「看似符合、實則應排除」的具體反例段落 |
| GPD 系列 | PC-GPD-015 | 是 | **是，且完整**——「與相鄰模式的分界」節「前提不可省略」段落明文給出反例（「一個完全正確的引用——回答的正是被問的問題——查證起來同樣『屬實』，照字面也會被判為本骨架」），並說明缺此前提會吞掉全部正確工作 |
| GPD 系列 | PC-GPD-014 | 是 | 部分——識別特徵句「Y 卻不是原因」隱含區分正確理由/錯誤理由，但無獨立段落明寫「一個看似符合實則應排除」的反例 |
| GPD 系列 | PC-GPD-009 | 是 | 否——「識別特徵」與「來源一/二」皆為正例枚舉，未見排除情形 |
| GPD 系列 | PC-GPD-016, PC-GPD-022 | 是 | 詞面命中「反例」，但用法是**引用** multi-round-review 的「對反例免疫」三題驗收機制或作為敘事內的實測反例，非條目自身判準句的排除情形段落 |

**結論**：0.1.0-W3-200 的 why field 稱「近期新增的兩則條目已在撰寫時實質滿足該要求」，經核對可判定為 PC-GPD-014、PC-GPD-015——但兩者程度不同：PC-GPD-015 完整滿足（獨立成段的反例 + 說明），PC-GPD-014 僅隱含於識別特徵的措辭結構、未獨立成段。「實質滿足」宜理解為「達成該要求的精神、尚未達成之後若正式入流程會要求的顯性段落格式」，不宜讀成「兩則已是可直接沿用的定版範本」——若上游閘門定案，PC-GPD-015 可作示範範本，PC-GPD-014 建議連同回填一併補一段獨立的反例陳述。

**回填分界建議**（供上游結論為「實作」時採用，本身不預先執行）：

1. **第一層排除——判準類型不適用者不回填**：早期古典型（症狀為可直接觀測的機械事實，如 cwd 污染、檔案行數）不具分類/裁決型判準句，不落入 0.1.0-W3-200 界定的要求範圍，回填無意義，應在流程說明中明寫「本要求只適用於含分類/裁決型判準句的條目」，避免執行者對全部 532 篇條目逐一比對。
2. **第二層——具判準句但未附反例的既有條目，不排程主動回填**：語料量體（532 篇，扣除第一層後仍有相當數量）使一次性回填成本過高，且與 0.1.0-W3-200 strategy 段已預告的「若數量過大則不在本票回填」一致。建議改為「附帶回填」——下次因其他理由（勘誤、關聯條目更新）編輯該檔時順便補一段，不另開專案 Ticket 追蹤。
3. **前瞻層——分界必須明文寫入流程說明**：無論上游採哪種第二層處置，都必須在 `/error-pattern add` 步驟或 README「文件格式」段明寫一句「本要求自 <抵達版本/日期> 起對新建立條目生效，既有條目不追溯，除非另行編輯」，避免下一位讀者（人或代理人）依「規則已生效」的字面推論，誤判既有條目已全數合規（同構於本 skill 現有 `severity` 不變式段落已示範過的「適用範圍：應然目標非存量現況」寫法，可比照複用）。

本項分界建議之標的是「上游閘門抵達後」的收尾動作，抵達本身仍待 issue 52 產生結論，不在本票自建。
