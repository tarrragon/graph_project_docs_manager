# Execution Log

## Task Summary

審查 foundation-design 與 version-bootstrap 地基波的需範例位置與實作引導缺口

---

## Problem Analysis
### 問題根因

foundation-design 與 version-bootstrap 以文字約束為主，已有範例（examples.md 五則、dimension-product-notes 兩則個案與事件流表、v02-walkthrough）皆無獨立【驗證】段，且數處文字約束彼此不一致（計數漂移、條款互相矛盾），讀者只能自行選邊。

### 影響範圍

掃描範圍（版控內全部 .md）：foundation-design/SKILL.md、references/{dimension-product-notes,examples,handoff-mode,troubleshooting}.md；version-bootstrap/SKILL.md、references/{step-rationale,version-shift-sop}.md、examples/v02-walkthrough.md。CHANGELOG 與 scripts/tests 不屬文字約束，排除。已驗證事實：下表每列皆有原文錨點；未驗證：被路由出去的權威（元件庫雙向約束方法論、data-layer-contract、tdd phase2 rules 等）不在本票範圍，其內部是否需範例未判。

### 相關 Error Pattern

判準類型對應 chained-examples〈「何處需要範例」判準〉五類無模糊詞分歧；計數漂移屬 reference-stability-rules 規則 10（可變計數寫死）的既有模式，本票不另立 error-pattern。

## 重現實驗結果
### 實驗方法

依 `.claude/skills/skill-design-guide/references/chained-examples.md` 機械步驟逐節掃描：先問決策點有無文字約束（無→缺引導），有則模擬兩位只讀文字約束的讀者對同一輸入各自推導，比對產出是否分岔；五類無模糊詞分歧類型逐節必查。

### 實驗執行

全文 Read 九份檔案；逐條款寫出甲乙兩讀者產出（見 Solution 表「分歧模擬」欄）。另以跨檔比對查計數與條款一致性（九步／六步、四塊／五塊、四種／五種合法答案、三項／兩項）。

### 實驗發現

命中 33 位置（缺範例 22、缺引導 11）；既有範例 10 則逐則判定；另發現 6 項文字不一致，屬缺引導前置（範例無法校準互相矛盾的約束）。

## Solution
### 結論

範圍內全部 SKILL.md 與 references（含 version-bootstrap/examples）已逐節掃描。命中位置見下表；既有範例逐則判定見次表；文字不一致見第三表（此類須先修文字約束，範例補不了）。依 W3-332.11 close_reason（ARCH-017，彙整改由父票承擔），**全部缺口列轉交父票 0.1.0-W3-332 彙整**，本票不就地修補、不建修補票。
