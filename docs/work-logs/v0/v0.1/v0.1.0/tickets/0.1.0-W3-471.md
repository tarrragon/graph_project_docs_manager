## NeedsContext
### 定稿全文（落檔前暫存，待 25 組推導驗證）

【待裁示】處已依用戶裁示（0.1.0-W3-417 Solution〈UX-09a 第五輪用戶裁示與 b3z／b5 派發〉）填入：#3=3-B、#4=4-A、#6=6-B、#7=7-a（新增 2.6(4)）。

2.1 前提
(1) 本項的「指示」指畫面上不可點的狀態指示，也就是按下去沒有任何反應的元素。
(2) 指示符合下列任一形態即合格：
  (a) 明顯非可點元素形態，依 2.2～2.7 判定；
  (b) 移出動作列，依 2.8 判定。
(3) (a) 的判定與指示是否和可點元素排在同一列無關：同列的指示只要屬 (a) 即合格。
(4) 畫面上沒有可點元素時，本項不適用。「不適用」只用於整項。2.3 每一軸的結果只有「不同」與「相同」兩種。

2.2 比較對象
(1) 可點元素指同一畫面上所有按下去會有反應的元素，含按鈕、可點 chip、文字連結，非窮舉。比較範圍是整個畫面，不限指示所在的列。
(2) 指示與每一個可點元素逐一比較。對每一個可點元素，指示都至少在 2.3 的一軸上「不同」，才屬 (a)。
(3) 只要對某一個可點元素兩軸都「相同」，指示就不屬 (a)。

2.3 兩軸
(1) 構成要素軸。構成要素有兩項：
  - 文字或圖示：文字與圖示算同一項；純幾何形狀不算圖示，界線見 (3)。
  - 區塊：底色或外框圍住文字或圖示的範圍。
  有區塊必定有文字或圖示，所以一方不會同時缺少又多出。判定方式：
  - 指示缺少對方具備的一項：不同。
  - 指示多出對方沒有的一項：依 2.4。
  - 兩者具備的項目相同：相同。
(2) 區塊高度軸。
  - 指示與對方都有區塊時才比較；達到 2.6 的門檻記為不同。
  - 以下情況記為相同：任一方沒有區塊（不比較）；專案沒有尺寸 token（不成立）；未達 2.6 的門檻。這裡的「相同」表示此軸不提供差異，判定只剩構成要素軸。
(3) 圖示與純幾何形狀的界線：純幾何形狀只有以下幾類：點、直線或直條、圓環、內部不含文字或圖示的純色圓形或方形。其他圖形一律算圖示，含勾號、箭頭、三角形。

2.4 多出規則
(1) 指示多出對方沒有的一項時，須同時滿足以下兩點，這一項才算不同；不滿足時，構成要素軸記為相同：
  - 畫面上另有一個可點元素具備該項；
  - 指示與那個可點元素至少在一軸上不同。
(2) (1) 的第二點依 2.3 判定，可以是任一軸。2.2(2) 本來就要求指示與每一個可點元素比較，所以這一點會在那一次比較中一併檢查。

2.5 徽章
附在可點元素熱區內、按下去觸發該可點元素本身的徽章，不是本項的指示，不做比較。

2.6 門檻與量測
(1) 區塊高度軸記為不同的門檻：在專案尺寸 token 階梯上，指示的區塊高度比對方至少低一階。
(2) 專案沒有尺寸 token 時，區塊高度軸不成立，記為相同，只看構成要素軸。
(3) 比較須在專案支援的所有字級、斷點、密度下都達到門檻；任一條件下未達門檻，此軸記為相同。
(4) 指示或可點元素的高度不在專案尺寸 token 階梯上時，視同專案沒有尺寸 token，此軸不成立，記為相同。

2.7 不可靠訊號
描邊或實心、圓角或直角、底色深淺，都不是可靠的可點性訊號，不作為比較依據。比較依據只有構成要素與區塊高度兩軸。

2.8 (b) 移出動作列
(1) 動作列指排有可點元素的列。移出動作列，指指示所在的列上沒有任何可點元素。
(2) (b) 只看指示所在的列，不與畫面其他位置的可點元素比較；全畫面比較只屬於 (a)。

2.9 例示
同一種指示形態，換了畫面上的可點元素，結果可能相反。以下例示須連同比較對象一起讀，不可單獨當成合格形態：
(1) 不加底色與外框的純文字：畫面上的可點元素全都帶區塊時，指示對每一個可點元素都缺少區塊，屬 (a)。畫面上只要有一個不帶區塊的可點元素，指示對它構成要素相同，區塊高度軸不比較、記為相同，不屬 (a)。
(2) 圓點：畫面上有一排可點的純色圓形色票（例如顏色選擇器）時，圓點與色票都沒有文字、圖示與區塊，構成要素相同；區塊高度軸不比較、記為相同，不屬 (a)。

2.10 理由
本條只適用於 (a)(b) 都沒有達成的指示：同列有可點元素時，使用者預設整列可點，按到指示時「沒反應」會被讀成壞掉。

2.11 同一圖形
同一圖形在全畫面只承載一個語意。
