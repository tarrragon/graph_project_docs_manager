## NeedsContext
### G9：再次可見時「無既有結果（上一輪被取消）」自動重新掃描

**缺失項**：SPEC-003 §3.5〈生命週期〉「再次可見」列——有既有結果時不重新掃描，
無既有結果（上一輪被取消，即 `GapReportScanning(isCancelling: true)` 殘留態）
時應自動進入 `state-gaps-scanning`。

**觸發位置**：`gap_report_provider.dart` `cancelScan()` 的延遲回呼只負責導覽，
不重置 `state`；`_completeScan()` 見 `isCancelling == true` 即提前 return，
狀態永久停在 `GapReportScanning(isCancelling: true)`，缺乏「使用者再次切回
本頁」的偵測點來觸發重掃。

**影響**：無法完成 G9 acceptance；此殘留態下再次進入畫面會顯示卡住的取消中
骨架，直到手動按 `action-gaps-rescan`。

**建議補料**：專案層級的「首次可見／再次可見」生命週期基礎設施
（`lib/app/router.dart` `firstVisibleProvider` 現僅用於路由層惰性載入判斷，
未提供「離開又切回」的訊號區分），需先設計是否擴充該 provider 或另建畫面
Notifier 訂閱 `selectedDestinationProvider` 變化的通用模式，再回填各畫面
（gap_report、trace、之後的 tickets／ucFlow）。建議建立獨立 ANA/IMP 追蹤。

**重派成本**：中——需先做跨畫面生命週期基礎設施設計決策（影響 W3-380/381
是否共用同一套機制），非單一畫面局部修復。
