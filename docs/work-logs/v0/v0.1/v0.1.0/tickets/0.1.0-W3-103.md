### 問題根因

盤點對象為頁面層（`lib/screens/`、`lib/app/shell.dart`）對元件 callback 的接線。W3-099 已驗證元件層 22 件 L1 全數齊備（Material InkWell/TextButton 提供），且元件把 L2（服務受理）與 L3（event 效果）正確委派給呼叫端——但「委派」不等於「承接方有做」。ARCH-GPD-001 的實際落點在頁面層，不在元件層。

分析範圍：`buildDestinationPage()` 中只有 `TraceabilityScreen` 與 `GapReportScreen` 是已實作頁面，其餘四項（domain、ucFlow、tickets、nodeDetail）為 `_DestinationPlaceholderPage`（純文字，無任何元件 callback 接線）。加上 `AppShell`（導覽殼）與 `ProjectSwitcherOverlay`（浮層），共 4 個已實作頁面 + 4 個佔位頁。

### 實驗發現

**已驗證事實**：

1. **21 條接線**分佈於 4 個已實作頁面 + 1 個背景控制器；4 個佔位頁（domain、ucFlow、tickets、nodeDetail）無任何元件 callback 接線。

3. **5 條為跨層呼叫**，依 L2/L3 完備性分為三組：
   - **兩層皆備（1 條）**：`LoadingState.onCancel → cancelScan()`
   - **L2 存在但無效（3 條）**：`rescan()` ×3（_NoGapsView + _FoundView + SnackBar action），LoadingState 骨架存在於程式碼但因 microtask 時序從未繪出——已由 W3-096 追蹤
   - **L2 缺失 + L3 失敗路徑不正確（1 條）**：`ListRow.item.onTap → _openItem()`

4. **W3-099 的 4 個檢查點在頁面層的狀態**：
   - `load_prompt.onStart`：佔位頁，未接線（Domain 視圖未實作）
   - `loading_state.onCancel`：已接線於 GapReportScreen._ScanningView，L2+L3 皆備
   - `missing_source_state.onRefresh`：佔位頁，未接線（節點詳情未實作）
   - `recent_project_item.onTap`：已接線於 ProjectSwitcherOverlay，但 0.1 為 fixture 驅動，`_selectProject` 只改 StateProvider + 關閉浮層，無服務呼叫——分類為「本地狀態」

5. **`_openItem` 的具體缺口**：
   - **L2**：`Process.run('open', [item.filePath])` 是 async await，期間無任何「處理中」指示（無 spinner、無「正在開啟...」SnackBar）。macOS `open` 命令通常 < 50ms 完成，實務影響極小，但嚴格來說 L2 缺失。
   - **L3 成功**：`AppSnackBar.show(context, message: l10n.openedExternallyMessage)` → 存在且正確。
   - **L3 失敗（Process.run 非零 exit code）**：`Process.run` 回傳 `ProcessResult` 但程式碼未檢查 `exitCode`，非零時仍顯示「已在外部開啟」成功 SnackBar → **L3 不正確（為失敗顯示成功訊息）**。
   - **L3 失敗（Process.run 拋例外）**：未 catch 的 async error → `runZonedGuarded` → `reportFatalError` → `fatalErrorNotifier` → `FatalErrorGate` 以 `BlockedState.plain` 取代整個 App → **L3 存在但不成比例**（單一檔案開啟失敗觸發全 App 阻擋態）。此路徑在 macOS 上極不可能觸發（`open` 命令恆存在），但 ARCH-GPD-001 要求降級後仍有可見表現——此處的表現是「全 App 被阻擋」而非「該操作失敗的提示」。
   - **已降級收斂的判定**：`Process.run` 非零 exit code 不屬降級收斂（沒有 catch 動作，只是忽略 exitCode）——屬遺漏而非刻意降級；拋例外路徑被全域錯誤攔截收斂為 `BlockedState`，該收斂**有可見表現**（BlockedState.plain 顯示錯誤訊息），不屬靜默失敗。

6. **附帶發現（非頁面層接線但與接線效果相關）**：`ScanNotificationController._evaluateCompletion` 中 `notifier.show()` 失敗時（MacosScanNotifier 內部 catch 了 PlatformException / MissingPluginException 後靜默回傳），呼叫端無從得知發送失敗，不觸發 SnackBar fallback → 使用者在非 gaps 頁面時不會收到掃描完成通知。此為背景通知系統韌性議題，非元件 callback 接線缺口，不在本票主要範圍但記錄供後續評估。
