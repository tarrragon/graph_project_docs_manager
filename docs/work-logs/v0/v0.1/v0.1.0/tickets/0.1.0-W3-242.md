### 前提重評（2026-09-10，B 組）：載體選擇需重新裁決，SPEC-003 §2.17 新增了另一個觀測點

本票建立於 09-09 23:41；`0.1.0-W3-243` 於 09-10 00:16 為 SPEC-003 新增 §2.17〈仲裁決策事件的定義與測試義務對照〉。**§2.17 的內容與本票要建的載體在同一件事上有重疊，建票時不存在。**

§2.17 定義的仲裁決策事件有三項與本票直接相關：

| §2.17 的性質 | 對本票的意義 |
|-------------|------------|
| 「決策（離開方式）」欄位的五個值之一是**「不顯示且留痕（承接 (c)）」** | 這正是本票 G3 缺口要記的那件事，已在通道層有欄位 |
| 該事件發生於**任何載體呼叫之前**，涵蓋全部三種載體 | 若判準在通道層評估，被判否的請求根本不會抵達 `AppSnackBar` |
| §2.17 明訂它與 `AppSnackBarLogSink` 是「同一請求生命週期的延伸，非另立事件線」 | 兩者不是可並存的兩套記錄，是同一條線的前後兩段 |

**因此本票的載體選擇成為未決問題，而非既定前提**：

- 若「因判準而不顯示」的判準在**通道層**（仲裁點）評估——請求不會呼叫 `AppSnackBar`，在 `AppSnackBar` 建一個事件值等於要求為了記錄一次不顯示而去呼叫它，載體錯了，本票應併入 `0.1.0-W3-207` 的仲裁決策事件。
- 若判準在**載體內部**（`AppSnackBar` 自身）評估——本票的載體正確，但須與 §2.17 的決策欄位對齊，避免同一事實兩處記錄。

**這個問題本票無法自己回答**：判準 T 的評估落點是 §2.13 與 `0.1.0-W3-207` 的範疇。**建議處置**：本票 `blockedBy 0.1.0-W3-207`，待仲裁器的評估落點確定後再定載體。

**原 P3 優先級的理由仍成立且更強**：§2.17 亦記載 0.1 落 (c) 的集合為空集合，本票建的是未來的載體而非修復當前缺陷；在落點未定前推進，會有一半機率建在錯的層。
