## Problem Analysis
<!-- Schema[DOC/Problem Analysis]: 選填（若 DOC 起因於缺陷或盤點結論可填）（.claude/pm-rules/ticket-body-schema.md） -->
### PM 裁決（2026-09-15）：先修文字對齊實況，hook 殘留另票處理

**查證**：`.claude/hooks/dart-style-guardian-hook.py` 的 `native_component_patterns` 確實存在，例如 `\bCard\(` 對應 `Use AppCard instead`。`scripts/style_checker.py` 沒有這組 pattern。W3-336.8 G21 當時只 grep 了 checker 腳本，漏看 hook 這個執法載體，四處文字因此寫錯方向。

**本票修正四處文字**，對齊兩個載體的實況：
- PostEdit hook 會攔下新增的原生元件直用。
- 批次掃描腳本不偵測原生元件直用。
- 「哪些算原生元件」「用什麼替代」的定義權威仍在 component-contract-design step-3〈原生元件禁用對照表〉。hook 的 pattern 屬於執法實作，不是定義權威。

這是事實更正，不改變任何判準。

**另立票處理**：hook 內替代名（App* 元件）與註解章節號是其他專案的殘留，也和本專案實際元件庫的命名未必相符。這屬於 hook 程式修改，由另一張 IMP 票承接。


### 查證記錄（thyme，2026-09-15）

- `grep -n "native_component_patterns" -A15 .claude/hooks/dart-style-guardian-hook.py`：確認 `native_component_patterns` 常數存在，含 8 個 pattern（`TextButton`／`ElevatedButton`／`Card`／`AlertDialog`／`showDialog`／`Divider`／`Chip`／`ChoiceChip`），於 `check_file_for_violations` 中被 PostEdit hook 逐行比對觸發。
- `grep -n "NativeComponent|native_component|原生元件" .claude/skills/dart-style-guardian/scripts/style_checker.py`：零命中，確認批次掃描腳本不含此偵測。
- `grep -rln "沒有偵測.*原生元件|原生元件.*沒有偵測|目前沒有偵測它的 pattern" .claude/`：僅命中 log 檔（無關）與本票範圍內的四個 SKILL/reference 檔，確認無第五處遺漏。

**裁決落地**：四處條文改寫為「PostEdit hook 含八個 pattern 攔下新增的原生元件直用，批次掃描腳本不偵測既有存量；定義與清點權威仍在 component-contract-design 的 step-3〈原生元件禁用對照表〉，hook 的 pattern 屬執法實作不是定義權威」。不改變任何判準，純事實更正對齊兩個執法載體實況。
