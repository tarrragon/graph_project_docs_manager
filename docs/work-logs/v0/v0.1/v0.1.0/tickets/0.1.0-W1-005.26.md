## Solution
<!-- Schema[IMP/Solution]: 選填（.claude/pm-rules/ticket-body-schema.md） -->
新增 `lib/components/blocked_state.dart`（`BlockedState.plain` / `BlockedState.withDetail`
兩個具名建構子，對應 SPEC-004 4.23 兩變體）與 barrel export `lib/components/components.dart`
一行；測試 `test/unit/components/blocked_state_test.dart`（35 支測試，覆蓋兩變體 ×
kMinWindowSize/kDesignSize、collapsed/expanded、zh/en i18n、切換專案／檢視詳情／Esc 收合
互動、最長測試文案不溢位）。

實作要點：
- 十一欄位（變體 2 + slot 9：message/explanation/version/appVersion/projectVersion/
  onSwitchProject/isDetailExpanded/onToggleDetail/testKey）全數依契約落地，皆非硬編碼。
- 展開／收合面板：`AnimatedSize` + `Motion.transition(context)`；面板容器色彩/圓角/間距皆取
  token（`AppColors.surfaceBase`/`borderStrong`、`Radius.md`、`Space.md`）。
- 詳情面板重用 `Section.static`（`header: SizedBox.shrink()`，本用法不需額外標題文字）承載
  `AppText.caption` × 2 + `AppText.mono` × 2（appVersion/projectVersion 標籤與值）。
- 動作列：`plain` 用 `ButtonRow`[切換專案 primary]（契約字面）；`withDetail` 需在「檢視詳情」
  鈕外包 `Semantics(expanded: isDetailExpanded)`，但 `ButtonRow.children` 型別限定
  `List<AppButton>` 無法容納包裹後節點——改以同構的 `Wrap`（相同 spacing/alignment token）
  承載兩顆按鈕，語意等價、契約值不變，僅容器類別替換。此為契約與既有 `ButtonRow` 元件型別
  簽章衝突下的唯一低成本解，已於 `_buildActions` dartdoc 註記理由。
- Esc 收合：`Focus(skipTraversal: true, onKeyEvent: ...)` 包裹 `withDetail` 整體；
  `skipTraversal: true`（而非 `canRequestFocus: false`）確認為讓 `onKeyEvent` 正確參與按鍵
  冒泡的必要設定——`canRequestFocus: false` 會使該 Focus 節點被排除在鍵盤事件冒泡鏈外
  （widget test 實測驗證，非規格臆測），且不影響 Tab 走訪順序（兩顆按鈕維持唯二可 Tab 停駐點）。

### Phase 4 結論

程式碼品質 A；無需重構。理由：函式皆 <= 15 行、單一職責（`_buildMessageBlock` /
`_buildActions` / `_buildDetailPanel` / `_handleKeyEvent` 各自獨立）、零硬編碼、既有元件
（`AppButton`/`AppText`/`Section`/`ButtonRow`）皆重用而非重造。發現一項技術債：
`ButtonRow.children` 型別為 `List<AppButton>`，任何需要對子按鈕額外包裹 `Semantics`/其他
wrapper 的呼叫端都會遇到同一限制（本票已用 `Wrap` 繞過）。此為既有元件設計限制，非本票
範圍可修改，未建額外 ticket（影響面小、繞過成本低、非阻塞）。
