### 問題根因

依 how.strategy 於 §2.6.4 三列既有『引用來源』欄補上 FR-11（破洞掃描完成列）、
FR-16／FR-17（開啟原始檔結果列）文字引用後，重跑

    python3 .claude/skills/spec/scripts/check_domain_coverage.py \
      docs/spec/ui/SPEC-003-interaction-response.md \
      --domain-map docs/domain-map.md --check-event-flow-labeling

`--check-event-flow-labeling` 仍回報 FR-11／FR-16／FR-17 三者缺標定，未歸零。

實測定位：`check_domain_coverage.py` 的 `CHANNEL_SECTION_TITLE_RE` 要求 domain-map
標題含字面「通道與協調圖」（`0.1.0-W3-224` 引入），但 `docs/domain-map.md` 的實際
標題是「## 2.6 注意力軸與通道」（`0.1.0-W3-203` 建立，早於檢核腳本存在）。以
`python3 -c` 直接呼叫 `extract_channel_section()` 驗證：`channel_section found: False`
——不論 §2.6.4 表格內容為何，此函式對本專案的 `docs/domain-map.md` 恆回傳 `None`，
下游 `extract_arrival_level_table()` 與 `check_event_flow_labeling()` 因此恆判定
「未見標定」，與表格內容是否含 FR token 無關。

依 `tool-output-trust-rules` 規則 6（驗證器 warning 與建立端定義衝突時先查建立端）：
`docs/domain-map.md` §2.6 標題建立於 `0.1.0-W3-203`，早於檢核腳本的
`0.1.0-W3-224`；建立端在先，腳本的標題假設在後且與建立端不符，判定為腳本缺陷，
非文件缺陷。故不將既有章節標題改寫成遷就腳本正則的字面巧合（那會是為了消除
警告而扭曲既有文件結構，且 thyme 禁止修改 `.py` 程式碼檔案）。

### 影響範圍

`--check-event-flow-labeling` 這一項提醒級檢核（非阻擋）對本專案永遠失準，
不限於 SPEC-003；任何 spec 命中事件流訊號詞的 FR，只要 domain-map 標題不是字面
「通道與協調圖」，該檢核都會誤報缺標定。

### 相關 Error Pattern

未新增獨立 error-pattern（單一腳本正則假設過窄，屬一次性缺陷，已用 IMP ticket
追蹤修正）。
