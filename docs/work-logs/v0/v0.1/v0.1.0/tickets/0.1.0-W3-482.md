## Problem Analysis
### 問題根因

b6-ux 兩位獨立判定者（j1 / j2）結論一致：16 題僅 7 題 3/3，9 題未通過，答案鍵誤 0、題目設計 0、餵料缺漏 0。九個失敗分屬兩種性質：

- 條文本身已寫定判準，讀者沒走到那一句——句子被放在例示區、放在另一節、或寫成省略式指涉。本票稱**甲類**。
- 條文沒有那一條判準，讀者的逃逸路徑在字面上成立。本票稱**乙類**。

**分類判別式**（本票採用，供後續票複用）：把該句補上後，是否有任何一組設計的判定結果由「合格／不違反」翻為「不合格／違反」。沒有翻轉即甲類——補句只縮小讀者的自由度，不動涵蓋範圍；有翻轉即乙類——改變判定涵蓋範圍，須 PM 逐項裁決。

最強訊號 UX-C8g 三輪全敗，根因是 8.2(2) 第一點的主問法自我抵銷：問法為「把畫面轉為灰階後，這些語意的呈現無法區分」，而灰階保留明度，任何明度不同的兩色轉灰階後都仍可區分，第一點因此近乎永遠不成立。條文備妥的兩處擋箭牌都在讀者走不到的位置——8.2(2) 的換色問法被寫成「無法實際轉灰階時」才啟用的 fallback（三輪無一啟用），8.5(1)「灰階後兩種標籤只剩明度差而無法區分」在例示區（三輪無一引用）。

### 影響範圍

**受影響檔案**：`.claude/skills/ux-design-evaluation/references/interaction-feedback-component-semantics.md`（269 行，八項判準全文）。九個失敗全部落在第 2、7、8 三項，第 1、3、4、5、6 項零失敗。

**已驗證的事實**（以 `git grep -F` 對 HEAD 逐句查證，命中數見 Solution 甲類表「HEAD 出處」欄，13 句全部命中）：

- 甲類六處的依據句在 HEAD 全部存在，非虛構。
- 8.5(1) 已把「只剩明度差」判為違反——排除明度不是新增立場，是把例示區的既有立場搬進判定條。
- 8.3(2)「本項與第 7 項各自判定」只寫在第 8 項，第 7 項無對等句（j2 記錄的 3 例讀出界同源於此）。
