## Solution
<!-- Schema[IMP/Solution]: 選填（.claude/pm-rules/ticket-body-schema.md） -->
依 SPEC-004 §4.16 十一欄位契約實作 `SwimlaneNode`（StatelessWidget，`lib/components/swimlane_node.dart`），僅兩個必填參數 `label` / `isActive`，無內部狀態。變體對映：`isActive=true` 底 `AppColors.accent`、字 `surfaceBase`；`isActive=false` 底 `AppColors.surfaceChip`、字 `textPrimary`。尺寸依 §4.0.3 chip 固有高公式，高度上限依 `LayoutSize.laneRowHeight - 2*Space.xs`；圓角 `Radius.md`；字級 `AppFontSize.body`；文字單行截斷。無互動（0.1 不可點不可拖，§4.0.1/§4.0.7 皆標「不適用」），故無 `InkWell`／`GestureDetector`，`Semantics(button:false, excludeSemantics:true)`，朗讀標籤為 `{label}，{laneNodeActive|laneNodeInactive}`（i18n key 已存在於 ARB，`0.1.0-W1-056` 已建）。`components.dart` barrel 依慣例追加一行 export（未重排既有行）。

契約值皆可由現有 token 直接取得，無需修改 SPEC-004 或 tokens。

### 自檢結果

- 十一欄位契約：用途／內容角色／何時不用／出現畫面／層級／變體／狀態矩陣／互動反應／操作機制／尺寸契約／內容政策／slot 契約／design token／i18n／組合規則／無障礙／測試點——全數對照 §4.16 逐項落實，無缺項。
- 狀態管理：純 StatelessWidget，傳值 + 無 callback（符合 §2「元件不 ref.watch」慣例，本元件無互動故無 callback 需求）。
- 測試：16 個測試涵蓋兩變體 × 兩尺寸不溢位、最長測試文案截斷、zh/en 資料值不溢位、點擊無反應（無 InkWell/ButtonStyleButton）、token 引用（色彩/圓角）、無障礙朗讀（含 en 語系、非 button）。
- i18n：`laneNodeActive`/`laneNodeInactive` 沿用既有 ARB key，未新增 key，未硬編碼 UI 字串。
- 常數：無魔法數字，色彩/間距/字級/圓角/尺寸皆取自 `lib/tokens/`。
- Package 導入：測試檔與元件檔皆用 `package:` / 相對路徑符合既有慣例（元件內部用相對路徑 `../l10n/`、`../tokens/`，與 `expander_icon.dart` 等既有元件一致）。

### Phase 4 結論

程式碼品質 A（單一 StatelessWidget、無分支邏輯、認知負擔低）；重構需要：否；技術債務：無發現。元件本身複雜度低（僅底色/字色二元切換 + 固有尺寸渲染），無重構空間。
