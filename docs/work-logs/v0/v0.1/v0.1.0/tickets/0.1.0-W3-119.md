**需求摘要**: 把「跨檔錨點該寫標題文字而非 URL fragment」這條判準記入 `DOC-V1-001`（或判定另建），核心是兩種錨點的失效**可偵測性**不同。

**目標檔現況（已驗證：`grep -n "^#"`，共 73 行）**

章節：症狀（L17）／根因（L29）／解決方案（L33）／預防措施（L39）／**第二實例：被命名端的同型失效（2026-08-18）**（L47）／與相關模式的關係（L59）／行為模式分析（L64）。

該檔已有「第二實例」章節先例，本次併入可沿用同一形態新增第三實例，不需重構既有結構。

**本則要記的判準（已驗證來源：`0.1.0-W3-114` 執行者的交接訊息，PM 採納並寫入 `0.1.0-W3-115` 的 Context Bundle 作為約束）**

| 錨點形態 | 目標標題被改時的行為 | 可偵測性 |
|---------|-------------------|---------|
| URL fragment（`file.md#port-回饋契約`） | 不報錯、不留痕跡，只是跳不到 | 靜默；且 anchor 生成規則由渲染器決定，各消費端不同（GitHub／本地 markdown 渲染器／純文字閱讀各一套），同一引用可能一處還能用、另一處已壞 |
| 標題文字（引用「Port 回饋契約」這串字） | 引用點仍在，指向的字串不再存在 | `rg -F "<標題文字>"` 找得到全部引用點 |

**可偵測性是本則的重點，不是穩定性。**兩種形態都會因標題改動而失效——差別在一種留下可被機械搜出的痕跡，另一種不留。寫作時容易把它論證成「fragment 比較脆弱」，那是失準的：fragment 不比較脆弱，是**壞掉時沒有人會知道**。

**實例（已驗證）**

`0.1.0-W3-114` 在 `.claude/methodologies/clean-architecture-implementation-methodology.md` 新增 `## Port 回饋契約`（commit `8db1f6d4`），交接時建議下游三處引用只寫標題文字。`0.1.0-W3-115` 據此執行（同儕 session 亦表態採納此判準）。

**歸屬判斷（執行者決定，以下為 PM 傾向而非結論）**

傾向併入 `DOC-V1-001` 而非另建：兩者根因同為「錨點綁定在一個會變、且變了不會報錯的東西上」——位置編號綁的是序位，fragment 綁的是渲染器的 anchor 演算法。若判定另建，於 Solution 說明不併入的理由（acceptance 第 4 條）。

**約束**

- 本檔屬按需讀取層，三明示（Why/Consequence/Action）可完整展開。
- 新增內容勿寫死實例計數（如「三個實例」），該檔既有的「第二實例」是章節標題不是計數敘述，沿用同形態即可（`.claude/references/reference-stability-rules.md` 規則 10）。
