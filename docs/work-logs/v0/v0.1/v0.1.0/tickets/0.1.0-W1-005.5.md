## Solution
<!-- Schema[IMP/Solution]: 選填（.claude/pm-rules/ticket-body-schema.md） -->
建立 `lib/components/page_title.dart`（`PageTitle`）與 `lib/components/components.dart`（barrel，僅一行 export）。

### 公開 API
```dart
class PageTitle extends StatelessWidget {
  const PageTitle({super.key, required this.title, this.subtitle});
  final String title;
  final String? subtitle;
}
```

依 SPEC-004 §4.11：title（畫面名，AppFontSize.subtitle / AppColors.textTitle、
Semantics.header）+ 可選 subtitle（AppFontSize.body / AppColors.textSecondary，
對應 AppText.body secondary 修飾），間距 Space.xxs，兩 slot 皆單行截斷不換行。

### AppText 依賴的處理
`AppText`（SPEC-004 4.1）由並行票 0.1.0-W1-005.1 實作，本分支 `lib/components/`
在動工時為空目錄，尚無 AppText 可引用。依票面約束選擇「直接依契約實作所需的
最小 AppText 子集並標明由並行票取代」：內部 `_PageTitleText` private widget
複刻 4.1 契約的 subtitle / body(secondary) 行為（單行、TextOverflow.ellipsis、
Semantics.header 依變體）。005.1 併入後應改 PageTitle 直接呼叫 AppText，
移除 `_PageTitleText`（已在檔案 doc comment 註記）。

### 契約修訂
無。SPEC-004 4.11 條目值全部可直接落實，未發現契約值實測不成立之處。

### Phase 4 結論
重構需要：否。技術債務：一項（`_PageTitleText` 待 AppText 併入後替換，已在
原始碼與本節記錄，非隱藏債務）。程式碼品質：A（單一職責、無裸值、token 全
引用、`dart analyze` 0 issues）。結論：目前實作為契約的最小正確落實，
待 AppText 併入後的替換屬既定計畫內收斂，不需額外重構動作。
