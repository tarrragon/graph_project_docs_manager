### 問題根因

依票面約束，先用 `.claude/skills/skill-design-guide/references/chained-examples.md`
〈驗證段機械檢查：依據句可溯性〉重新檢查 B9（來源：0.1.0-W3-332.7 Solution 需範例位置表）
再動筆，而非直接依 W3-332.7 已定的「缺口類型：缺範例」寫範例。

B9 對應條文：`version-shift-sop.md` 盤點步驟 1「對照移版提案的 checklist，逐項檢查是否觸及
`schema/*.schema.json`、`docs/spec/**/*.md` 的 DDL 章節、或其他跨版本共用契約檔案」（第 15 行）。
若要對「其他跨版本共用契約檔案」寫檢驗問句（設計產出物形態，依 chained-examples.md〈各段允許
與禁止內容〉判定），該問句必須能指回條文中一句界定「契約檔案」範圍的定義句。

逐一查證結果（`grep -rn "契約檔案\|契約 SOT\|SOT 檔案\|契約級" .claude/skills/version-bootstrap/
.claude/skills/foundation-design/`）：

- `version-shift-sop.md` 第 15 行：僅列舉兩個具名項（`schema/*.schema.json`、DDL 章節）與一個
  開放第三類「其他跨版本共用契約檔案」，未界定第三類的邊界。
- 第 9 行（動機段）：「契約 SOT 檔案（如 schema 定義）」——僅舉例，非定義句。
- 第 24-29 行（判斷準則表）：分級對象是「已被步驟 1 判定觸及」的項目，處理的是「觸及項算不算硬
  耦合」，不是「什麼算契約檔案」，無法回頭充當步驟 1 的邊界定義。
- 專案內唯一另一處「契約」相關模板 `.claude/skills/doc/templates/data-contract-template.md`
  定義的是「資料契約文件」這個 SPEC 文件類型本身（A/B 兩區結構），與本處「契約檔案＝觸及即需
  盤點的物件」是不同概念，不能借用。
- SKILL.md 第 92 行僅重複「schema／DDL／契約級的殘留耦合」，同樣未界定第三類開放項邊界。

**結論**：條文中「其他跨版本共用契約檔案」查無任何定義句可作為檢驗問句依據，依
〈「缺範例」與「缺引導」的分界〉判定順序（先問「這個決策點有沒有文字約束存在」）——本處雖有
「盤點觸及項」這個動作的文字約束，但對「第三類（其他契約檔案）的範圍」本身沒有文字約束，讀者
（例如 W3-332.7 甲乙兩讀者：一判僅 schema／DDL、一判含 API 路由表與 i18n key 清單）必須自行
發明範圍才能執行盤點。**此為缺引導，非缺範例**——與 W3-332.7 原判定不同；W3-332.7 判定時
chained-examples.md 尚無〈驗證段機械檢查：依據句可溯性〉一節（該節由 W3-332.12 之後定案），
故原判定未套用此機械檢查，屬規格演進後的重新分類，非 W3-332.7 誤判。

依〈「缺範例」與「缺引導」的分界〉Action：「缺引導的位置額外附上建議的文字約束草稿供 PM
裁決，不可直接以範例代替文字約束」，故不在 `version-shift-sop.md` 內自創定義或範例，草稿見
NeedsContext 章節。
