### 補料：本票建立後產生的 CLI 層實證（PM，2026-09-11）

**本票的核心問題是「剩餘缺口該由哪一層治」，而在本票建立之後、派發之前，同一個工作日內產生了一組該問題的直接實證。** 這組實證不在原 `why` 段內，補記於此。

**事件序**（皆已合併進 main 並經 PM 實測）：

1. **條文層先試過，且失敗了。** `0.1.0-W3-304` 於 `ticket-intake.md` 第 160 行加入 owner 識別行與範例格式，目的正是修「owner 未提供」。**該條文存在之後，PM 在 `0.1.0-W3-315` 與 `0.1.0-W3-319` 兩次派發仍漏填**——而該條文的讀者就是 PM 本人，且 PM 是它的作者。
2. **`0.1.0-W3-320`（CLI 層）修好了一半**：`validate_owner` 錨定專案前綴 + session uuid 前 8 碼。PM 實測 `graph-project-docs-manager-dcead428` 通過、舊短名／代理人角色名／他 consumer 值維持被擋。**但它修的是「值合不合法」，不是「值有沒有被帶上」**——漏填仍會發生，只是有了 exit 3。
3. **`0.1.0-W3-324`（CLI 層）消滅了漏填模式本身**：`init`／`add` 自行推導，`--owner` 降為覆寫。PM 實測 `resolve_write_owner(None)` 回 `graph-project-docs-manager-dcead428`，不符的 `--owner` 被擋並印三項診斷。**漏填這個動作在介面上不再存在**，不是「漏填會被發現」。
4. **效果可觀測**：`0.1.0-W3-323` 隨後在 `#95` 與 `#77` 各建立一則本專案擁有的區段（`graph-project-docs-manager-dcead428` 經 `gh api` 查得，#95 三處、#77 一處）。**這是本專案第一次擁有區段**，此前全數落在觀測流。

**對本票判準的意義（供判定參考，非預設結論）**：這組實證同時支持與限制候選 B。**支持**：同一缺口在條文層試過並失敗、在 CLI 層成功，且「消滅模式」與「加訊號」的差別在 320 與 324 之間被具體區分出來。**限制**：owner 是一個**可由環境唯一決定**的值，因此能被工具自行推導；`0.1.0-W3-306` 列的「未變」項（章節順序、`check` 七天觸發器、`dedup` 命中規模）**是否同樣具備這個性質，未經檢驗**——若不具備，本組實證的可推廣性受限，不得直接外推。

**本票應判定的正是這個外推是否成立**，而非因為 CLI 層在此例成功就結論「剩餘缺口交 CLI 層」。

### 實驗方法

本票的問題是層級判定，故「實驗」的對象不是條文的效果，而是**層級標籤本身可否被推翻**。為此先寫下一個可套用的判準（下稱 L 測），再對每一項需要標層級的發現套它；凡標籤依賴的機器事實，一律實跑取得，不引用前票的數字。

**L 測（四問，依序，首個成立者即為該項的層級）**：

| 問 | 成立則層級 | 推翻方式 |

| L1 正確值是否由環境唯一決定（存在一個純函式，全部輸入皆為機器可讀事實）？ | CLI 層可**消滅模式**（owner 型） | 舉出該純函式 |

### 實驗發現

**已驗證的事實**

1. **L1 在 owner 一例成立，在 `0.1.0-W3-306` 列的三項「未變」上全部不成立**（實驗 1／4／5）：章節順序無「值」可推導（它是編輯動作）；`check` 觸發器缺的是「以什麼為訊號」而非門檻數字，而門檻數字這條 CLI 路徑實測**早已走完**（`--stale-days`）；`dedup` 收斂缺的是「依什麼收斂」。三項中具備 L1 者 0 項。**外推不成立**（詳見 Solution 第二節）。
2. **`0.1.0-W3-307` 構造三的承重前提實測為假，而它在四問下仍全綠**（實驗 6／7）：該構造的修法是「於查重 SOP 的 `dedup` 命令區塊補上 `--all`／`--issue` 說明」，其「反例已試」答「是」的依據為「實跑 `dedup --help`，實測旗標存在」。本票實跑 `dedup --help`：**該旗標不在 `dedup`，在 `todo`**。也就是說該問答「是」時，被證偽的是「某處存在 `--all`」，不是「`dedup` 存在 `--all`」——而後者才是修法的承重前提。**這使「反例已試」無鑑別力這件事從『以構造推得』升級為『有一個實測反例』**。
3. **同一修法若被落地，失敗形態是靜默**（實驗 7）：`dedup --keywords x --all` rc=0 且把 `--all` 吃成關鍵字。照該說明操作的人得到一個看起來正常的查重結果，實際多了一個無意義關鍵字、範圍完全沒變。此為 `test-assertion-design-rules` 規則 E2 所述形態（失效與「本來就沒問題」同形），而兩份文件互指仍為 0／0（實驗 8）。
