## Solution
<!-- Schema[ANA/Solution]: 必填（.claude/pm-rules/ticket-body-schema.md） -->
### 結論（四句）

1. **「剩餘缺口交 CLI 層」不成立。** owner 一例的成功依賴一個窄性質——正確值由環境唯一決定，故工具能自行推導、漏填在介面上消失。`0.1.0-W3-306` 列的三項「未變」逐項檢驗後**具備該性質者 0 項**（實驗 1／4／5），其中 `check` 觸發器的 CLI 可調面（`--stale-days`）實測**早已存在而缺口未動**，這是外推不成立最直接的反證。
2. **條文層的邊際效益沒有到零，但它的位置可以指出來**：**事實更正與路由補全仍完全有效（7 項，可立即寫定）；凡會改變判定結果分佈者（新增或移除一條豁免路徑）一律不可當下寫定（15 項）**——這類修法的承重前提是「其他 consumer 的作答者會怎麼用它」，而該資料零觀測。`0.1.0-W3-307` 的兩處最小修補**全部落在後者**。
3. **條文的豁免閘門對「修改閘門自身」的修法會自我背書**，這是本票判定 307 兩處修補證據狀態時浮現的新結構：`escalation-flow.md` 在本 consumer 有機械訊號（`framework-issue/tests`）→ 擴散面第一檔 → 「使用者群已觀測」可填不適用 → 四問全綠 → 豁免。**用被修的規則為修它的動作背書，判定無效**，故兩處修補皆落待裁列，而非「證據不足所以再測一輪」。
4. **不需要第三輪。** 停止判準不是發現變少，是三個 frame 已涵蓋三個獨立軸（條文答不出／答得出但可被構造成錯／作者自身是否照做）；唯一未涵蓋的第四軸——**不知情的他方 consumer 實地作答**——換任何 frame 都測不到，因為缺的是讀取路徑不是視角。`0.1.0-W3-307` 方案 B 的停手條件與 `0.1.0-W3-308` 的樣本限制是同一件事。

### 一、層級標籤的判準與其推翻方式

層級以〈重現實驗結果〉的 L 測（L1 消滅模式／L2 加訊號／L3 判準語意／L4 缺觀測）指派，並在條文層內部再切一刀：

| 標籤 | 定義 | 推翻方式 |
|------|------|---------|
| **C0** | 條文層，可立即寫定：修法為事實更正或路由補全，**不新增也不移除任何判定路徑**，且其承重前提已由本票機械觀測 | 舉出該修法會翻轉某個既有判定的輸入 |
| **C1** | 條文層可治但須一次裁決：修法**會改變判定結果分佈**（增刪豁免路徑），或有互斥形狀二擇一；承重前提為作答者行為，零觀測 | 舉出一個不改變判定分佈、且無互斥選項的等效寫法 |
| **M2** | CLI／hook 層加訊號：存在一個 predicate，對同一輸入只輸出一個結果 | 舉出兩個相同輸入得相反輸出的案例 |
| **M1** | CLI 層消滅模式：正確值由環境唯一決定 | 舉出該值需要的任一非機器可讀輸入 |
| **X** | 不可由任何層寫字治：缺的是觀測本身 | 舉出該資料的現有讀取路徑 |

**C0／C1 這一刀為何劃在「是否改變判定分佈」**：因為第 3 點的自我背書迴圈使「依三問評估此修法」對凡動到閘門者一律回傳綠燈，該閘門無法用來區分這兩類。改變分佈者的承重前提落在消費端行為（零觀測），不改變分佈者的承重前提是可機械查核的檔案事實（本票已查核），這條線不依賴閘門即可判定。

### 二、外推判定：owner 的成功可否推廣到「未變」三項

| **具備 (a) 者** | — | 0 | 0 | 0 |

**最直接的反證在 `check`**：`DEFAULT_STALE_DAYS = 7` 且 `check` **早已有 `--stale-days` 參數**（實驗 4）。若這項缺口的層級是 CLI，則它早該被關掉；它沒有，因為缺的是「時間差作為代理指標本身錯」這件事的替代訊號定義——那是一次外生裁決（L3），不是一個工具能推導的值。**把它標成 CLI 層等於宣告一條已走完且無效的路徑仍可走。**

**外推的正確形狀**（而非全盤否定）：owner 的可推廣部分是**分類法**不是**結論**——`0.1.0-W3-320` 與 `324` 的差別（加訊號 vs 消滅模式）給出了 L1／L2 的操作定義，本票用它把剩餘缺口分成 C0／C1／M2／X 四堆。**可推廣的是尺，不是尺量出來的值。**

### 八、候選方案

**方案甲：分層併案（建議）**

- C0 七項合併為一次條文修訂（事實更正與路由補全，不改判定分佈）；C1 十五項全部寫進 `#81`／`#95` 的「待辦與來源」待裁列，其中 F5／N3／修補乙三項**綁為單一決定**；M2 五項各自獨立評估（`todo` 推送優先，有 `check` 的現成前例）。不做第三輪。
- 利：每一堆的處置與其層級一致；C0 可立即完成且零爭議；C1 不再被反覆重測。
- 弊：C1 十五項的裁決仍卡在同一面牆（跨 consumer 零觀測），待裁列可能長期不動——**這正是 `0.1.0-W3-306` G2 指出的「有查詢入口但無推送」的實際後果**，故 M2 的 `todo` 推送是本方案的實質前提。

**方案乙：先判第四軸的可行性（與甲不互斥，作為其補充）**

- 建一張可行性票：canonical repo 的公開面能否讀到他方 consumer 的三問作答實況。結果決定 C1 群是否有裁決依據，也同時解消 `307` 方案 B 的停手條件與 `308` 的樣本限制。
- 利：一次投入同時解開三處被同一面牆擋住的判定。
- 弊：可行性未知，可能得到否定結果；否定結果本身有價值（使「效果限定在本 consumer」成為明示宣告而非預設），但不產生任何修法。

**方案丙：直接落地候選 B 全形態（不採）**

- 依實驗 6 已被反證：作答者對四問全答綠而承重前提為假，提示強度無從改變答案內容。採此案會把 B2 的不可行帶進 B1 的可行部分。
