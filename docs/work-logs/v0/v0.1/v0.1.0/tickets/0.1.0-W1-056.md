## Solution
<!-- Schema[IMP/Solution]: 選填（.claude/pm-rules/ticket-body-schema.md） -->
補齊 SPEC-004 §4.0.6 新 key 總表宣告的 53 個 i18n key：

1. `lib/l10n/app_zh.arb` 新增 53 個 key（含 @ 描述，描述皆註明來源條目編號如「SPEC-004 §4.18」），`lib/l10n/app_en.arb` 同步新增對應英文翻譯（既有 flat 格式，不含 description）。
2. 執行 `fvm flutter gen-l10n` 重新產生 `lib/l10n/app_localizations.dart`、`app_localizations_zh.dart`、`app_localizations_en.dart` 並入庫。
3. SPEC-004 §4.0.6 逐條目 i18n 表移除「（新 key）」標記（原「新 key，呼叫端傳入」等複合標記改保留括號內其餘描述，去除「新 key」文字）；§4.0.6 引言段與 §4.0.9 待決清單結語改寫為「已建」狀態說明；新增變更歷史 1.6 版列記錄本次補齊範圍。
4. 未改動既有 key 值；帶 placeholder 的 key 依 ARB 既有慣例宣告型別（String/int）。

Phase 4 結論：本票純屬資料補齊（ARB key + 產生器產物 + 規格文件狀態同步），無自訂邏輯、無新增函式、無架構決策，不適用一般重構評估項目；品質為 A（結構與既有 ARB 慣例一致，53 個 key 逐一核對來源條目編號，無重複 key）。
