## Problem Analysis
<!-- Schema[ANA/Problem Analysis]: 必填（.claude/pm-rules/ticket-body-schema.md） -->
### 問題根因

`references/typography-system.md`〈Migration Guide〉的「Common Replacements」表把「精確命中 Type Scale 離散階的值」（10/12/14/16/18/20/24/28/32）與「非精確命中、需要取整判斷的值」（11/13/15/17/19）混在同一張表，且對後者僅用表後一句散文規則（「相鄰兩階等距時，一律取較小一階」）解出唯一答案，未依「這個值從哪裡來」分流；`0.1.0-W3-336.8` G26 對 spacing-system.md 的同型表格（Non-Standard Values）已認定「就地取近似套用在既有程式碼裸值上會改變畫面」與 `foundation-design references/handoff-mode.md`〈命名與收斂分兩步〉衝突，並改採方案 D（按值來源分流：設計來源指定／畫布雜訊／既有程式碼裸值／無設計來源新寫程式碼四類分開處置，見 `0.1.0-W3-336.12` 落地後的 `spacing-system.md`〈Non-Standard Values〉）。本票評估此衝突與分流需求是否同樣存在於 typography 的取整表。

### 影響範圍

檔案：`.claude/skills/dart-style-guardian/references/typography-system.md`〈Migration Guide〉（Common Replacements 表 + 表後散文規則）。連帶：`.claude/skills/dart-style-guardian/SKILL.md` 第 49 行〈交界表〉「字級」列觸發條件目前未提及「值不在 Type Scale 離散階上」，與已修正的「間距」列（第 48 行：「需要的值不在〈Spacing Scale〉的八階上，要判斷是該取近似值還是該加一階」）不對稱。

已驗證事實（見下方重現實驗結果）：typography 表目前 5 個平手列（11/13/15/17/19）已用單一明訂規則一致解出，無 spacing 修復前「6 列給單一候選卻無理由、10/14/20/28 列給兩候選卻無 tie-break 規則」式的內部不一致；但「就地取近似套在既有程式碼裸字級上」的衝突與 spacing 完全同構——本表未區分字級值的來源，直接套用會使既有程式碼的文字大小被悄悄改變。

未驗證假設：typography-system.md 是否有其他章節依賴現行「一律取較小一階」措辭（已用 grep 排除，僅表後一句散文引用此規則，無其他引用）。
