## Task Summary

評估 TDD-11b 單一 Given 訊號時是否保留「不拆 Module」分支並先試 Sociable「處方第一順位不是移動邊界」

## Problem Analysis
### 問題根因

`bdd-behavior-testing.md`〈BDD→單元拆分標準〉對「只有 Given 設置過長一項訊號成立」沒有獨立的處理規則，讀者各自補出三種讀法：

- 直接依表列動作「考慮拆分 Module」（答案鍵）
- 套用〈多訊號同時成立時〉的「移除 Given 設置」後置步驟（r2）
- 把「Module 過大」當成待評估的假設，另加「不過大則接受現設計」分支（r3）

`3afc5eec1` 把多訊號段的後置條件搬進表格同一格，但沒有帶上「多訊號同時成立」的射程，放大了第二種讀法。

另外，同檔有兩處既有條文與單一 Given 訊號相鄰，表格沒有交代它們的關係：

1. 〈分層 Mock 原則〉禁止 Mock Domain Entity、Value Object、UseCase 內部 Helper。Mock 行數可能含這類違規替身。
2. 〈常見挑戰速查〉「測試設置複雜：UseCase 需 Mock 多個外部依賴 → 建立 Test Helper / Builder Pattern 減少重複設置」。這是不移動邊界的處方，與表列「考慮拆分 Module」所處理的情境在字面上重疊。

### 影響範圍

- 檔案：`.claude/skills/tdd/references/bdd-behavior-testing.md`，範圍含〈BDD→單元拆分標準〉表格 Given 列、〈多訊號同時成立時〉段、〈常見挑戰速查〉表。
- 探針：W3-417 b4 tdd-1 的 TDD-11a、TDD-11b 題目與答案鍵。

已驗證（`git grep -F` 命中）：

- 「處方的第一順位都不是移動邊界」只出現在〈Sociable vs Solitary 選擇框架〉選擇準則句與多訊號段。
- 選擇準則句的主詞是「下面三個症狀」（責任搬動、紅燈定位、協作者拖慢）。「Given 設置過長」不在這三個症狀之列。
- `layered-test-strategy.md` 只有「只 Mock 外層依賴，使用真實 Domain Entity」，沒有 Given 長度或拆 Module 的條文。
- `test-assertion-design` SKILL 沒有設置長度相關條文。

未驗證：「> 10 行 Mock」的行數是否計入抽到 Helper 或 Builder 裡的行。條文沒有寫。

## Solution
### 結論

建議採 **A + B1**：

- **A**：沿用 W3-466.1 的射程改文。單一 Given 訊號直接依表列動作「考慮拆分 Module」，多訊號後置條件只在與其他訊號同時成立時適用。
- **B1**：Given 列的行數只計〈分層 Mock 原則〉允許 Mock 的外層依賴，違規替身先改真實物件，不計入。

不建議以下兩個方案：

- **B2**：單一訊號也先試 Test Helper／Builder。
- **C**：設「評估後不拆」分支。

兩者都需要新增判準，也都會改動答案鍵。「Builder 抽出的行是否計入」與「是否設不拆分支」交由用戶決定（見下方）。

- A ⊂ B1 ⊂ B2：B2 去掉 Builder 後即退化為 B1；B1 去掉計數限定後即退化為 A。

**反向框架**：若 Given 過長根本不代表 Module 過大（例如編排型 UseCase 本來就要串接多個外部服務），C 就成立。這個前提條文中沒有依據，列為用戶決定點 1。

### 建議改文（A + B1，不含例示）

1. 〈BDD→單元拆分標準〉表格「Given 設置過長」列，動作格整格替換為：
   「Module 過大，考慮拆分 Module 而非加測試。行數只計〈分層 Mock 原則〉允許 Mock 的外層依賴；替換 Domain Entity、Value Object 或 UseCase 內部 Helper 的設置，先依該原則改用真實物件，不計入行數。本列與表中其他訊號同時成立時，先依下方〈多訊號同時成立時〉套用不移動邊界的動作，移除僅服務已拆出邏輯的 Given 設置後仍 > 10 行 Mock，才考慮拆分 Module」
2. 〈多訊號同時成立時〉段首句改為：
   「**多訊號同時成立時**（本表兩項以上訊號同時成立；只有一項訊號成立時不適用本段，直接依該列動作）：」
   後文不變（沿用 W3-466.1）。
3. 取決於決定點 2：若採傾向 (a)，〈常見挑戰速查〉「測試設置複雜」列的對策欄接在原句後補：
   「；抽到 Helper／Builder 的替身設置仍計入〈BDD→單元拆分標準〉Given 設置過長的行數」
4. 取決於決定點 1：若採傾向 (ii)，第 1 項格內第一句後補：
   「本列成立即判定 Module 過大，不另設評估後不拆的分支。」
5. 探針配套：TDD-11a、TDD-11b 題幹補「Mock 皆替換外部依賴」，答案鍵不變。

### 需用戶決定之點與傾向

1. **是否保留「評估後不拆」分支**
   - 選項：(i) 維持「考慮」，不加句；(ii) 補否定句，明寫不設分支；(iii) 採 C，設不拆判準。
   - 傾向 (ii)。理由：r3 路徑已經重現；動作格的「Module 過大」本來就是診斷，不是待評估的條件；(iii) 沒有出處，而且會讓 11b 判不拆。
   - 盲點：編排型 UseCase 本來就要串接多個外部服務，這種情形下 (ii) 可能迫使不必要的拆分。
2. **抽到 Helper／Builder 的替身設置是否計入行數**
   - 選項：(a) 計入（訊號量的是單一測試需要的替身設置量，寫在哪裡不影響）；(b) 不計入（照「行」的字面）。
   - 傾向 (a)。理由：若採 (b)，任何 Given 過長都能靠 Builder 消去，訊號形同失效（見對照 Y）。
   - 盲點：(a) 讓〈常見挑戰速查〉的 Builder 對策與拆分訊號脫鉤，Builder 只剩減少重複的價值，讀者可能覺得兩處仍然矛盾。
3. **單一 Given 訊號是否套用 Sociable「處方第一順位不是移動邊界」**
   - 傾向否（即不採 B2）。理由：選擇準則的字面射程是三個症狀；擴大射程屬新判準，而且與決定點 2 (b) 的失效路徑相同。
