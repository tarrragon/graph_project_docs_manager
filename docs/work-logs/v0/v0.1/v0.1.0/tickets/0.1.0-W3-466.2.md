## Task Summary

評估 TDD-11b 單一 Given 訊號時是否保留「不拆 Module」分支並先試 Sociable「處方第一順位不是移動邊界」

---

## Problem Analysis
### 問題根因

`bdd-behavior-testing.md`〈BDD→單元拆分標準〉對「只有 Given 設置過長一項訊號成立」沒有獨立的處理規則，讀者各自補出三種讀法：

- 直接依表列動作「考慮拆分 Module」（答案鍵）
- 套用〈多訊號同時成立時〉的「移除 Given 設置」後置步驟（r2）
- 把「Module 過大」當成待評估的假設，另加「不過大則接受現設計」分支（r3）

`3afc5eec1` 把多訊號段的後置條件搬進表格同一格，但沒有帶上「多訊號同時成立」的射程，放大了第二種讀法。

另外，同檔有兩處既有條文與單一 Given 訊號相鄰，表格沒有交代它們的關係：

1. 〈分層 Mock 原則〉禁止 Mock Domain Entity、Value Object、UseCase 內部 Helper。Mock 行數可能含這類違規替身。
2. 〈常見挑戰速查〉「測試設置複雜：UseCase 需 Mock 多個外部依賴 → 建立 Test Helper / Builder Pattern 減少重複設置」。這是不移動邊界的處方，與表列「考慮拆分 Module」所處理的情境在字面上重疊。

### 影響範圍

- 檔案：`.claude/skills/tdd/references/bdd-behavior-testing.md`，範圍含〈BDD→單元拆分標準〉表格 Given 列、〈多訊號同時成立時〉段、〈常見挑戰速查〉表。
- 探針：W3-417 b4 tdd-1 的 TDD-11a、TDD-11b 題目與答案鍵。

已驗證（`git grep -F` 命中）：

- 「處方的第一順位都不是移動邊界」只出現在〈Sociable vs Solitary 選擇框架〉選擇準則句與多訊號段。
- 選擇準則句的主詞是「下面三個症狀」（責任搬動、紅燈定位、協作者拖慢）。「Given 設置過長」不在這三個症狀之列。
- `layered-test-strategy.md` 只有「只 Mock 外層依賴，使用真實 Domain Entity」，沒有 Given 長度或拆 Module 的條文。
- `test-assertion-design` SKILL 沒有設置長度相關條文。

未驗證：「> 10 行 Mock」的行數是否計入抽到 Helper 或 Builder 裡的行。條文沒有寫。

### 相關 Error Pattern

DOC-GPD-007 同型：判準只寫在相鄰段落或範例內，射程沒有明寫，讀者依字面擴大或縮小射程。沒有新的 error-pattern。
