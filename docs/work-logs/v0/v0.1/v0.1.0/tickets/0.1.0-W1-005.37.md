### 問題根因
SPEC-004 條目 4.35（TableRow）與 §5.9 排列不變式契約已齊（十一欄位 + 排列不變式表），依 component-contract-design skill 只需轉換為 Dart 實作，不需臨場設計。唯一缺口：欄首子件 `TableColumnHeader`（4.14）尚未建立於 `lib/components/`，`header` 變體 cells 改以 `Widget` 承接（與 `ListRow`/`AppButton` 既有記錄的契約差異同一慣例）。

### 影響範圍
新增 `lib/components/table_row.dart`（`TableRow` 容器 + `ColumnSpec` 欄規格）、`test/unit/components/table_row_test.dart`；`lib/components/components.dart` 追加一行 export。未修改其他元件檔、tokens、SPEC-004 其他條目。

### 相關 Error Pattern
無直接對應；派發階段已於 W1-055 補齊本票所需的固定寬欄 token（`ticketIdColumnWidth` 等），本票純消費既有 token。

### 命名衝突處理
類別名稱 `TableRow` 與 `package:flutter/widgets.dart` 內建 `TableRow`（`Table` widget 用）撞名。依 SegmentedControl 先例（該檔對 `Segment` 撞名的處理），本檔以 `import 'package:flutter/widgets.dart' hide TableRow;` 排除內建版本；呼叫端（含測試檔）若同檔匯入 `flutter_test`（其間接匯入 material），需一併 `hide TableRow`，否則 export 合併會使 `TableRow` 從命名空間靜默移除（Dart 語言行為：同名符號被兩個以上來源匯出且未消歧義時，該名稱不進入合併後的公開命名空間，非編譯錯誤，而是 `undefined_identifier`）。已在 dartdoc 檔頭記錄此偏離。

### 修正：撞名處理方式改為 App 前綴（PM 回饋）
原先以 `hide TableRow` 排除 Flutter 內建 `TableRow` 的做法會使所有同時 import `material.dart`（或 `flutter_test`，其間接 import material）與 `components.dart` 的呼叫端靜默失去 `TableRow` 這個名稱——Dart 對「同名符號被多個來源匯出且未消歧義」的處理是把該名稱整個移出合併後的命名空間，不是編譯錯誤，而是之後每個引用點各自報 `undefined_identifier`，接手畫面票的人不會直接看到「撞名」這個根因。

改依專案既有撞名慣例（`AppButton`／`AppText`／`AppSnackBar`）：類別更名 `TableRow` → `AppTableRow`，檔案更名 `lib/components/table_row.dart` → `lib/components/app_table_row.dart`（`git mv`），測試檔同步更名為 `test/unit/components/app_table_row_test.dart`，移除 `hide TableRow` 與相關 dartdoc 撞名說明段。契約仍為 SPEC-004 4.35 `TableRow`，本檔類別名為實作層命名偏離，不改 SPEC-004；契約名對照說明由後續 DOC 票回填（本票不建具體 ticket ID，避免框架檔案引用專案層級識別符觸發 reference-stability 規則 8 阻擋——此為一般性註記，不指定票號）。
## Solution
<!-- Schema[IMP/Solution]: 選填（.claude/pm-rules/ticket-body-schema.md） -->
新增 `lib/components/table_row.dart`：`TableRow` 容器（三具名建構子 `.header` / `.ticket` / `.step`）+ `ColumnSpec`（`fixed(LayoutSize.*)` / `flex(n)`，sealed class）。欄位設計依契約：

- `ticket`：id/title/status/priority/marker（marker 可 null，欄位保留但渲染 `SizedBox.shrink()`），欄寬 `ticketColumns`（ID 固定、標題填滿、狀態/優先/標記固定），整列 `InkWell` 可點（`onTap`/`testKey` 必填）。
- `step`：number/stepName/domain/events，欄寬 `stepColumns`（序號固定、步驟名與事件填滿等分、domain 固定），整列可點；domain 格（`RelationItem`）自身 `InkWell` 優先命中，符合測試點「點 domain 格不觸發列 onTap」。
- `header`：`columns`/`cells` 皆必填（呼叫端傳 `TableRow.ticketColumns` 或 `.stepColumns` 對齊資料列），cells 型別為 `Widget`（`TableColumnHeader` 4.14 尚未建立，見 Problem Analysis）。

排列不變式（5.9）落地：欄間距 `Space.md`（`SizedBox` 插入）、列水平內距 `Space.sm`、底邊框 `header`=`borderStrong`／`ticket`+`step`=`border`、序號欄置中其餘欄 `start` 對齊（`Align`/`Center`）。無障礙標籤依 4.35「各格文字依序串接」，`ticket` 串接 id/title/status.label/priority，`step` 串接 number/stepName/domain.id（events 因 `BadgeRow` 無單一文字聚合值，未列入串接，已於程式碼註解說明）。
