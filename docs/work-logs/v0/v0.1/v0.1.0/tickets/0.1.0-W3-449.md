變更摘要：逐題處置如下（皆為條文結構重排，未新增判準）。

- UX-09a（interaction-feedback-component-semantics.md 六項判準第 2 項）：讀歪點是例外句「兩者擇一即合格、與是否和按鈕同列無關」接在長句尾端，開頭的理由句「同列有按鈕時...」讀起來像適用所有形態。改法：把兩種合格形態與「與是否同列無關」的排除句移到句首，理由句移到後段。
- UX-26b（gate-fallback.md 每道 gate 的必答問題）：讀歪點是「列名寫出涵蓋的類型」未說清是逐一列出成員還是可用總稱概括，三份答案都寫出「永久拒絕」類總稱。改法：明文「須逐一列出涵蓋的每個成員類型」並排除總稱概括寫法，附例。
- UX-06a（input-mechanism.md 場景二：搜尋）：讀歪點是結論「適用『按送出』」被夾在雙重否定子句中段，讀者引對依據句仍判即時。改法：把結論句抽出、直接指向表格列名（「依上表對應『按送出』列，不對應『即時』列」）。
- UX-02b（input-mechanism.md Special keys 排列依據）：讀歪點是「有頻率資料時依頻率」與「無頻率時退回臨界路徑」兩條件的優先序不夠顯眼，讀者在題目已給頻率時仍依臨界路徑排列。改法：改寫為編號優先序 (1)(2)，並明寫「即使該鍵為必經鍵，只要有頻率資料仍依頻率、不因必經而提高順位」。
- UX-07a（input-mechanism.md IME 安全清單）：讀歪點是「不希望被記住」的理由被讀者從個人化學習泛化套用到自動校正與輸入建議。改法：兩處（表格前後）都改寫為「兩項控制分屬不同判準、互不影響」，明寫自動校正/建議的判準是自然語言與否、與 confidential 無關。
- UX-11a（interaction-feedback-waiting-and-notification.md 時間門檻與回饋策略）：讀歪點是時間帶邊界寫法（如「1-10s」）不夠明確，讀者把 p95=2.5s 誤歸到 >10s 帶。改法：表格改寫為顯式「下界含、上界不含」的區間敘述，並補一句提醒對照數值只需比較是否落在區間、不必參考鄰近段落的範例數字。
- UX-12b（同上檔 時間門檻表 + 畫面級回饋 + Spinner vs Skeleton）：讀歪點是「進度指示 + spinner」的「+」號被讀成「至少其中之一」，且「進度指示」被誤解為需要精確百分比才能使用。改法：補一句明文「+」代表組合非擇一，且「進度指示」不要求精確可計算的百分比，與「進度百分比」不同。
- UX-17a（screen-state-matrix-selection-prestate.md）：讀歪點一半屬題目設計（四個子問未編號），另一半是條文本身「四欄需完整填寫」與「退出路徑至少要有...」兩項並列要求擠在同一句，退出路徑要求容易被漏讀。改法：拆為編號 1、2 兩項。
- UX-10b：題目設計問題（計數器長度日後可能變長，與題幹「已完整顯示」的前提衝突），依票面裁示不改條文，僅記於此。
