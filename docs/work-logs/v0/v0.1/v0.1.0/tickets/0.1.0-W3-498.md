## Problem Analysis
<!-- Schema[ANA/Problem Analysis]: 必填（.claude/pm-rules/ticket-body-schema.md） -->
### 問題根因

7.2(3) 第三句授權的是**一對配對**：「狀態指示與造成、設定或解除該狀態的動作，代表的事物相同」。該句的兩端一端固定為狀態指示、另一端為動作，**兩個動作彼此之間沒有任何一句規範**。UX-N7c 子問 2 要判的正是兩個動作彼此（上鎖鈕 vs 解鎖鈕，兩者皆非狀態指示）。

固定值查證（`.claude/skills/ux-design-evaluation/references/interaction-feedback-component-semantics.md`，第 7 項全文）：

| grep 對象 | 命中數 |
|---|---|
| `傳遞` 或 `遞移` | 0 |
| `兩個動作` | 0 |
| `動作之間` | 0 |
| `彼此` | 0 |

答案鍵對子問 2 的預期判定「三個鎖頭承載的是同一件事」係由 A≡B 且 A≡C 推得 B≡C；7.2 從未宣告該關係為等價關係，7.2(2) 反而明定比較對象是畫面上所有圖形的**兩兩之間**。三輪探針一致取 7.2(3) 末句「語意不同指的是所指的事物或動作本身不同」判違反，該推論在條文字面內成立。

第二個缺口（子問 3，r2 逃逸 1/3）：7.2(3) 未給一般性的「兩個語意算不算同一件事」判準，讀者得以用「都涉及警報功能」這類**主題範疇**式讀法把兩個不同的事物併為同一語意。此缺口在 UX-K1 與 UX-K3 的答案鍵條文風險欄已被預告（「維修中」vs「設定」同屬設定範疇、「語音導覽」vs「現場演奏」同屬聲音範疇），本輪在 UX-N7c 子問 3 首次實際命中。

三段：

2. **失敗重現**：逐輪比對三位探針在 UX-N7c 子問 2 的判定與依據句，確認失敗點落在條文而非讀取（三輪皆引到 7.2(3) 該句、皆答對子問 1）。
3. **誤傷實驗**：把兩份判定報告各自草擬的措辭、以及本票草稿，逐一代入本批全部 12 題含判定題與 7.4／8.5 的 4 則例示，逐題判斷結論是否翻轉。完整逐題表見 Test Results。

第 3 段的關鍵發現（兩則，皆落在**判定報告自己的草擬措辭**上）：

- j1 措辭「同一個狀態或同一個對象的不同時態、方向、視角，屬語意相同」代入 **UX-M3 子問 3**：橘色進度條「逾期」與藍色進度條「進行中」是同一個工項對象的不同時態，依該句判語意相同，第 7 項**不命中**；現行答案鍵為命中，子問 4（兩項都命中記一項、以第 8 項為準）連帶失去前提。UX-M3 本輪 3/3，該措辭使其翻為錯。
- j1 措辭「共用一個名詞而所指的對象不同時，仍屬語意不同」與 j2 措辭「兩者是否作用於同一個被指涉的對象或狀態」代入 **7.4(2) 例示**：分享文章與分享相簿共用「分享」一詞、作用對象不同，依兩句皆判語意不同、違反 (1)；而 7.4(2) 明文為不違反。判準與自家例示直接互斥。

### 實驗發現

已驗證的事實：

1. 條文對兩個動作彼此無字（固定值 grep，4 項全 0 命中）。
2. UX-N7c 子問 2 的 0/3 不歸讀者——三輪都讀到並正確套用了 7.2(3)，失敗發生在該句推不到的地方。
3. 兩位判定者建議的措辭都有誤傷：j1 措辭翻轉 UX-M3（3/3 → 錯），j1 與 j2 措辭都與 7.4(2) 例示互斥。**這證實「補傳遞性」這個方向的措辭風險高於預期，且風險不在生僻邊界而在既有 3/3 題與自家例示上。**

仍未驗證的假設：三鎖頭並置的正確設計判定（不違反 vs 違反）——這是本票交 PM 的裁定項，Solution 列出兩個方向各自的涵蓋範圍變化供裁決。
