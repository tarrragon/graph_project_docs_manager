## Problem Analysis
<!-- Schema[ANA/Problem Analysis]: 必填（.claude/pm-rules/ticket-body-schema.md） -->
### 問題根因

7.2(3) 第三句授權的是**一對配對**：「狀態指示與造成、設定或解除該狀態的動作，代表的事物相同」。該句的兩端一端固定為狀態指示、另一端為動作，**兩個動作彼此之間沒有任何一句規範**。UX-N7c 子問 2 要判的正是兩個動作彼此（上鎖鈕 vs 解鎖鈕，兩者皆非狀態指示）。

固定值查證（`.claude/skills/ux-design-evaluation/references/interaction-feedback-component-semantics.md`，第 7 項全文）：

| grep 對象 | 命中數 |
|---|---|
| `傳遞` 或 `遞移` | 0 |
| `兩個動作` | 0 |
| `動作之間` | 0 |
| `彼此` | 0 |

答案鍵對子問 2 的預期判定「三個鎖頭承載的是同一件事」係由 A≡B 且 A≡C 推得 B≡C；7.2 從未宣告該關係為等價關係，7.2(2) 反而明定比較對象是畫面上所有圖形的**兩兩之間**。三輪探針一致取 7.2(3) 末句「語意不同指的是所指的事物或動作本身不同」判違反，該推論在條文字面內成立。

第二個缺口（子問 3，r2 逃逸 1/3）：7.2(3) 未給一般性的「兩個語意算不算同一件事」判準，讀者得以用「都涉及警報功能」這類**主題範疇**式讀法把兩個不同的事物併為同一語意。此缺口在 UX-K1 與 UX-K3 的答案鍵條文風險欄已被預告（「維修中」vs「設定」同屬設定範疇、「語音導覽」vs「現場演奏」同屬聲音範疇），本輪在 UX-N7c 子問 3 首次實際命中。

### 二、候選方案（W 階段，三類涵蓋）

| 代號 | 方案 | 類別 | 三鎖頭判定 | 新增條文量 |
|---|---|---|---|---|
| A | 補傳遞性句（j1／j2 方向）：同一狀態的造成、設定與解除動作彼此語意相同 | 改造既有 | 不違反 | 2 句（傳遞性＋一般性） |

**方案關聯性檢查**：B 在實務上退化為 C——B 的排除條件（同一狀態、方向相反、同時並置）在本 skill 的射程（單一畫面內的圖形比較）下幾乎恆成立，兩者判定結果同一而 B 的條文量三倍。實質選項為 A／C／D／E 四個。

**反向思考（若我相信的正好相反）**：若「三鎖頭不違反」才是正確設計意圖，則方案 A 成立而 C 錯。檢驗方式是問第 7 項要防的是什麼——7.2(1)「同一圖形在全畫面只承載一個語意」防的是使用者看到同一圖形卻要推斷不同意義。指示與動作配對時使用者按下去即可得知，故 7.2(3) 開例外；兩顆並置的互斥按鈕則要求使用者**在按下之前**選對一顆，同一圖形使該選擇無依據。例外的成立條件在動作對上不成立，故不傳遞。此檢驗支持 C。

### 三、必做 1：涵蓋範圍變化

### 方案 A（補傳遞性）

| 面向 | 內容 |
|---|---|
| 由違反移入不違反 | 同一狀態的造成／設定／解除動作彼此共用同一圖形的全部設計，含兩顆方向相反、同時並置、互斥的按鈕 |
| 放行的真缺陷 | 使用者無法從圖形分辨要按哪一顆。第 2 項治可點性形態、第 3 項治對比、第 8 項治顏色，**皆不承接**；第 7 項是唯一可能命中的判準，移出後為零覆蓋 |
| 會不會放行「同一圖形用於兩個無關動作」 | **會**——若一般性判準缺席，「同屬一個狀態」可被主題範疇式讀法擴張（r2 已示範「都涉及警報功能」），兩個實際無關的動作即被歸入同一狀態而放行 |

### 方案 C（不傳遞＋一般性判準，推薦）

| 面向 | 內容 |
|---|---|
| 由違反移入不違反 | 無 |
| 由不違反移入違反 | 無。三輪讀者已一致按此判，且其依據句是 7.2(3) 現有末句 |
| 會不會放行「同一圖形用於兩個無關動作」 | 不會——(6) 的結論是「依 (5) 判」，(5) 要求動作本身同一，兩個無關動作必不同一 |

### 四、必做 3：j1 與 j2 的分歧判定

| 主張 | 判定 | 理由 |
|---|---|---|
| j2「答案鍵推論超出條文」 | **為真**，且是操作面的主結論 | key 用 A≡B ∧ A≡C ⇒ B≡C。7.2 從未宣告該關係為等價關係；7.2(2) 明定比較對象是兩兩之間。條文側無一字支撐該推論 |
| j1「條文缺口」 | **部分為真** | 「條文對兩個動作彼此無明文」為真（固定值 grep 4 項全 0）；但 j1 由此推定缺的是**傳遞性**，這一步超出證據——三輪讀者用 7.2(3) 現有末句即得出結論，缺的是**不傳遞的明文**，不是傳遞性 |
| 兩者是否互斥 | 否，但處置不同且不可互相取代 | 改答案鍵（j2 處置）必做，否則同一題重出仍以錯誤標準計分；補條文（j1 處置）亦須做，否則作者側的等價讀法會再次發生。**但補的內容與 j1 建議的方向相反** |

**證據強度說明**：判定 j2 為真所依據的是條文文字本身（可 grep 驗證），不依賴對設計意圖的推測；判定 j1 方向為假所依據的是誤傷實驗（j1 措辭翻轉既有 3/3 題），亦為可複驗事實。方案 C 與 A 的選擇仍含一項設計意圖裁定（三鎖頭該不該違反），該裁定屬 PM，本票只提供上節的檢驗框架與推薦。

### 五、必做 4：一般性判準與傳遞性句是否缺一不可

| 組合 | 子問 2（三鎖頭） | 子問 3（兩鈴鐺） | 判定 |
|---|---|---|---|
| 只補一般性判準 (5) | 得解——動作本身不同，違反 | 得解——同屬一個主題不構成語意同一，違反 | **足夠** |
| 只補不傳遞句 (6) | 得解 | 未封，r2 的範疇路徑仍開 | 不足 |
| 只補 j1 傳遞性句 | 走向與讀者相反，且製造新缺口 | 未封 | 不足且有害 |
| j1 的兩句一起補 | 得解（走 A 方向） | 得解 | 在 A 方向下確實缺一不可，但另缺第三句承接被放行的缺陷 |

**結論**：j1「兩句缺一不可」的主張在其自身方案下成立，在推薦方案下不成立——(5) 單獨即足。(6) 仍建議同批落檔，理由是本案的誤讀實例發生在**答案鍵作者**身上而非讀者身上，(6) 封的是作者側；成本一句，且誤傷實驗證實零翻轉。

### 六、推薦草稿全文（方案 C）

在 `interaction-feedback-component-semantics.md` 的 7.2 判定節，(4) 之後追加兩項（既有 (1)～(4) 一字不動，編號不重排，以免 7.2(3)／7.2(4) 的既有引用失效）：

```
- (5) 本項所稱語意是否同一，只看圖形代表的那一個事物或動作本身是否同一：兩者同屬一個主題或功能領域、或共用同一個名詞，都不構成語意同一。同一個對象的兩個不同狀態，是兩個語意；同一個動作施加於不同對象，動作本身相同，屬語意同一。
- (6) (3) 授權的是狀態指示與動作之間的配對，這個配對不在兩個動作之間傳遞：兩個動作彼此之間一律依 (5) 判，不因各自與同一個狀態指示語意同一而彼此語意同一。造成某個狀態的動作與解除該狀態的動作，動作本身不同，是兩個語意。
```

**判否反例（供落檔票一併驗證，不入條文）**：兩顆可點按鈕都使用釘選圖示，一顆把本筆釘選、另一顆取消釘選，畫面另有「已釘選」的不可點指示。依 (3)，每顆按鈕各自與該指示語意同一；依 (6)，兩顆按鈕彼此不因此語意同一，動作本身不同，違反 7.2(1)，處置是更換其中一方的圖形。
