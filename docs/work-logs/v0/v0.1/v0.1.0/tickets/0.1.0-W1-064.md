## Problem Analysis
<!-- Schema[IMP/Problem Analysis]: 選填（小型 IMP 可留 placeholder；大型 IMP 建議填寫）（.claude/pm-rules/ticket-body-schema.md） -->
現況：三處元件繞過 AppText 直接建 Text 或以布林修飾推導語意色——
list_row.dart（sectionHeader 主色 accentStrong，AppText 僅 secondary 布林無法表達）、
recent_project_item.dart（name/summary/reason 依 enabled/isCurrent 狀態需 accentStrong/
textDisabled/textPrimary，同樣超出 secondary 布林覆蓋範圍）、nav_item.dart（label 色由
isSelected 推導 accentStrong/textPrimary）。

WAP：
W（候選方案）：(1) 為 AppText 新增 tone 語意色軸列舉，值限 AppColors 既有語意色名（採用）；
(2) 保留三處繞過並僅補註解說明理由（不採用，違反 ticket 目標）。
A（機會成本）：本票專注 AppText 契約補洞，未同時處理 recent_project_item.dart reason 欄位
2 行換行與 caption 單行的既有張力（本次以 body variant + maxLines:2 解，非 caption）。
P（最可能失敗點）：AppText body variant 預設無 maxLines 上限，若元件端忘記顯式傳入
maxLines:1 會由單行截斷退化為多行換行——已在 nav_item / recent_project_item 補上，並以
既有測試（longToken 不溢位）作為回歸防護。
