### Rationale Chain
- 0.1.0-W3-166 why: **用戶裁示（2026-09-09）**：「元件層內建回饋日誌應成為元件庫的通用契約條款。這些元件庫的回饋可以成為測試的判定依據，尤其這是最終使用者真正看到的資訊，**如果我們只驗邏輯，整個資訊鏈還是有可能中斷**。」

該裁示有一個當日的實證。`0.1.0-W3-078` 第二次實機驗證中，`0.1.0-W3-096` 附帶的診斷測試綠燈（`authorizationStatusCalls == 1`，程式邏輯正確），但實機上**沒有任何紀錄能回答「使用者看到了什麼」**——`denied` fallback 的 SnackBar 是否顯示，日誌上與靜默失敗完全同形，唯一分辨手段是人眼即時觀察，而 SnackBar 會自動消失。該項因此未取得。

**測試驗到了「程式做了對的事」，沒驗到「使用者收到了對的資訊」，而兩者之間還有一整段。** 元件層日誌記的不是「呼叫了顯示」，是「這個字串被顯示出來了」——這是資訊鏈最末端唯一可留存的證據。

**為何是條款而非個案**：`0.1.0-W3-165` 修的是 `AppSnackBar` 一個元件。條款層級的固化使後續新增的任何終端回饋元件自動受同一約束，不需要每次重新論證；同時讓元件層日誌取得**驗收依據**的正式地位，而非僅是除錯便利。

**與既有條文的關係**：`INV-FEEDBACK-001` 要求元件在每一次互動都發出第一層回饋，但該不變式**沒有觀測面**——違反時沒有任何東西會叫。本條款是它的觀測對偶：規範加上它自己的觀測面，才是完整的一組。（來源已完成，結論見 Solution）
