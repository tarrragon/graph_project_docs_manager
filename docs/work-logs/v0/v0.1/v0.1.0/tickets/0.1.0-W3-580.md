## Problem Analysis
### 問題根因

`0.1.0-W3-575` 以「本次改動新增字面」為差集基準，查出 `0.1.0-W3-536` 新增的 7.2(3-2) 以「漏斗」「音符」作例示，而兩詞逐字即 UX-C7v 與 UX-K3 的題材詞。本票把基準換成「條文全部例示」（不限本次改動），對三條線全掃，得到兩個結構性結論：

1. **同型破口不只兩例，且多數不是任何一次改動新增的**。UX-C8t（8.2(4) 括號舉例逐字含題幹的「長按提示」）、UX-C8p（8.4 的三項排除逐字即題幹甲、乙兩案）、UX-M2（8.5(2)「星號本身是橘色不構成違反」與子問 2 逐字同構）三題的來源條文句，自 `909a49c33`（2026-09-16 09:56）起未再改過。以差集法看，這三題的新增命中為零；以全文法看，三題各有一條完整通路。**兩法讀數不同不是誤差，是射程不同**——只查改動 diff 會系統性漏掉「條文早就寫著、出題時被採用」這一整類。
2. **破口有兩個方向，處置相反**。條文側（條文晚於題目，條文採用了題材詞）：C7v 的 7.2(3)／7.2(6) 例示於 `70059cd66` 09-16 11:31 落地，晚於 b6-ux-4 的 10:13；C7v／K3 的 7.2(3-2) 於 09-17 12:30 落地。題目側（條文早於題目，出題時採用了條文例示詞）：C8t／C8p／M2／R5／N2r 全屬此類。條文側不能靠出題時的檢查擋，題目側可以——而題目側的五題全部落在 b6／b9／b12 三批，那三批沒有 isocheck 工具。

### 影響範圍

- 受檢題目：`probes/q/` 140 份，拆為 723 個 `### <題號>` 區塊，其中 494 個區塊有可解析的餵入欄
- 受檢條文：被餵入的相異節錄 215 份（`probes/excerpt/` 的節錄檔，或餵入欄直接指向的 `.claude/` 原檔），涵蓋 ux／doc／tdd 三線與 foundation-design／version-bootstrap／component-contract-design／skill-design-guide／dart-style-guardian 各線
- 下游：本票判為「能」或「部分能」的七題（UX-C7v／K3／C8t／C8p／M2／R5／N2r）此後不得作為對應款次的可證偽讀數；`0.1.0-W3-575` 建議的「C7v／K3 自 7.2(3-2) 除名」經本票驗證為**範圍不足**，見 Solution 第三段

**已驗證的事實**：215 份條文的例示 span 切分與逐詞命中、七題的條文句與題幹逐字對照、每個例示詞首次進入條文的 commit 時間與對應題目檔的 mtime、四支既有 isocheck 工具的實際比對對象（逐檔讀原始碼）。
**仍未驗證的假設**：逐字比對是隔離的下界不是判準，語意同義（條文「匯出檔案」對題幹「匯出成檔案」）不在本法射程；結構對應軸由 `0.1.0-W3-581` 承接。

### 據實更正：票面 why 欄對現行工具的描述失準

票面 why 欄記「b17 manifest 的題材隔離檢查（`b17_ux_isocheck.py`）比對的是題目檔與題目檔之間，量不到『條文採用了題幹的題材詞』這個方向」。逐檔讀原始碼後更正前半句：

| 工具 | 實際比對對象 |
|---|---|
| `b14_ux_isocheck.py` | Column B：條文觸發句的內容詞 → 新題題幹。不讀 excerpt，無題材清單 |
| `b15_ux_isocheck.py` | Column B ＋ 題材檢查：新題題材詞 → excerpt（`ex.count(w)`）＋ 同批其他題目檔 |
| `b17_ux_isocheck.py` | 新題題材詞 → excerpt（`ex.count(w)`）＋ 全部既有題目檔 |
| `b18`／`b19_ux_isocheck.py` | 同 b17，另加禁用題材清單 |
| b6／b9／b12 批次 | **無 isocheck 工具** |

`b17_ux_isocheck.py` 的 `n_ex = ex.count(w)` 逐行確認存在，故「量不到條文」不成立。成立的是四點，見 Solution 第四段：方向單一、時點單一、詞表為人工清單、涵蓋批次不全。票面 why 欄的結論（現行工具對本破口零覆蓋）不受此更正影響——零覆蓋的成因是這四點，不是「不讀條文」。

### 相關 Error Pattern

`test-assertion-design-rules` 規則 E2（守衛的測試必須含正向對照輸入）為本票工具設計段的直接依據：現行 isocheck 每一批的 log 都是 `material hits=0`，而「題材確實不重疊」與「該詞根本不在人工清單裡」在 log 上同形。四個受影響題材詞（漏斗、音符、長按提示、色盲友善色票）從未進入任何一份 `MATERIAL` 清單，故從未有機會被報出。規則 E1（明示旗標必須有對照測試）為近鄰：條文例示與題幹題材重疊時，「讀者執行了判定步驟」與「讀者把條文的例示抄回去」在作答外觀上不可區分。
