## Problem Analysis
### 問題根因

`0.1.0-W3-575` 以「本次改動新增字面」為差集基準，查出 `0.1.0-W3-536` 新增的 7.2(3-2) 以「漏斗」「音符」作例示，而兩詞逐字即 UX-C7v 與 UX-K3 的題材詞。本票把基準換成「條文全部例示」（不限本次改動），對三條線全掃，得到兩個結構性結論：

1. **同型破口不只兩例，且多數不是任何一次改動新增的**。UX-C8t（8.2(4) 括號舉例逐字含題幹的「長按提示」）、UX-C8p（8.4 的三項排除逐字即題幹甲、乙兩案）、UX-M2（8.5(2)「星號本身是橘色不構成違反」與子問 2 逐字同構）三題的來源條文句，自 `909a49c33`（2026-09-16 09:56）起未再改過。以差集法看，這三題的新增命中為零；以全文法看，三題各有一條完整通路。**兩法讀數不同不是誤差，是射程不同**——只查改動 diff 會系統性漏掉「條文早就寫著、出題時被採用」這一整類。
2. **破口有兩個方向，處置相反**。條文側（條文晚於題目，條文採用了題材詞）：C7v 的 7.2(3)／7.2(6) 例示於 `70059cd66` 09-16 11:31 落地，晚於 b6-ux-4 的 10:13；C7v／K3 的 7.2(3-2) 於 09-17 12:30 落地。題目側（條文早於題目，出題時採用了條文例示詞）：C8t／C8p／M2／R5／N2r 全屬此類。條文側不能靠出題時的檢查擋，題目側可以——而題目側的五題全部落在 b6／b9／b12 三批，那三批沒有 isocheck 工具。

### 擴充設計：一支工具四種模式

三票（本票、`0.1.0-W3-549`、`0.1.0-W3-557`）指向同一組工具，建議收成 `tools/probe_isocheck.py`，四種模式共用同一組原語（題目區塊拆解、餵入欄解析、n-gram 極大命中、條文 span 切分）：

| 模式 | 比對的兩端 | 回答的問題 | 承接票 |
|---|---|---|---|
| `forward` | 新批題材詞 → 條文 ＋ 既有題目檔 | 這批新題有沒有踩到別人 | 現況（b15～b19 已有） |
| `reverse` | 條文例示 span → 全部在流通題幹 | 條文有沒有踩到既有題 | **本票** |
| `sweep` | 全部題目檔兩兩（不限新批） | 有沒有哪一批的隔離事後被破壞 | `0.1.0-W3-549` |
| `basis` | 答案鍵引文 → 該 key 宣告的基準 commit（非 HEAD） | 這條 FAIL 是條文改了還是器材壞了 | `0.1.0-W3-557` |

共用原語是收成一支的理由，也是它的收益：四種模式的輸出可互相解釋。`reverse` 報「條文採用了題材」、`sweep` 報「題目採用了別題題材」、`basis` 把「條文已改」從「器材損壞」裡分出來——三者對同一次條文改動會同時有輸出，分開的三支工具則各自只印自己那一格。

### `reverse` 模式的六項判準

1. **題材詞不再人工列舉**。取題幹全部長度 2–12 的連續 CJK 子字串，與條文例示 span 的同長度子字串取交集，只留極大命中。人工清單是缺口 3 的成因，換成自動推導即消除。
2. **例示 span 的定義取五種位置的聯集**（S1 引號詞／S2 標記後子句／S3 例示節／S4 括號／S5 頓號列舉）。S5 不可省：本票最強的一例（8.4 對 C8p）只落在 S5。
3. **每個命中附例示／規範的出現次數分解**。規範次數大於 0 者優先處理——條文既舉它為例、又規定讀者必須寫出它（漏斗即此類）。
4. **輸入是改動後的條文全文，不是 diff**。本票七題中的五題（C8t／C8p／M2／R5／N2r）不是任何一次改動新增的，只跑 diff 會全部漏掉。這也解釋了本票與 `0.1.0-W3-575` 讀數不同的原因：兩票射程不同，不是其中一票算錯。
5. **觸發時機由「出題時」擴為「出題時 ＋ 條文改動時」**。掛在條文改動的 commit 上，或作為下批出題 manifest 的前置關。
6. **輸出須逐題可定位**。報「詞 → 題號 → 檔案清單」，不報彙總計數；彙總計數與人工清單有同一個毛病，看不出漏了什麼。

### E2 正向對照輸入（已執行，見〈重現實驗結果〉第五節）

`experiment-0.1.0-W3-580-e2control.py`，exit code 0。四個控制詞（蜂箱／陶窯／藕塘／氣象站）取自在流通題幹，先驗證四者在現行條文出現次數皆為 0；負向半對未改動的條文跑 `reverse`，四詞回報為空；正向半把四詞植入 7.2(3-2)甲的句尾（僅記憶體副本），四詞全數回報並各自指到正確題號。

兩半缺一不可：只跑正向半無法排除「工具把每個詞都報出來」，只跑負向半無法排除「工具什麼都不報」。這正是 `test-assertion-design-rules` E2 所治的形態——現行 isocheck 每批的 `material hits=0` 從未附過任何正向對照輸入，故「題材確實不重疊」與「該詞不在清單裡」在 log 上一直是同形的。
