## Problem Analysis
### 問題根因

`0.1.0-W3-575` 以「本次改動新增字面」為差集基準，查出 `0.1.0-W3-536` 新增的 7.2(3-2) 以「漏斗」「音符」作例示，而兩詞逐字即 UX-C7v 與 UX-K3 的題材詞。本票把基準換成「條文全部例示」（不限本次改動），對三條線全掃，得到兩個結構性結論：

1. **同型破口不只兩例，且多數不是任何一次改動新增的**。UX-C8t（8.2(4) 括號舉例逐字含題幹的「長按提示」）、UX-C8p（8.4 的三項排除逐字即題幹甲、乙兩案）、UX-M2（8.5(2)「星號本身是橘色不構成違反」與子問 2 逐字同構）三題的來源條文句，自 `909a49c33`（2026-09-16 09:56）起未再改過。以差集法看，這三題的新增命中為零；以全文法看，三題各有一條完整通路。**兩法讀數不同不是誤差，是射程不同**——只查改動 diff 會系統性漏掉「條文早就寫著、出題時被採用」這一整類。
2. **破口有兩個方向，處置相反**。條文側（條文晚於題目，條文採用了題材詞）：C7v 的 7.2(3)／7.2(6) 例示於 `70059cd66` 09-16 11:31 落地，晚於 b6-ux-4 的 10:13；C7v／K3 的 7.2(3-2) 於 09-17 12:30 落地。題目側（條文早於題目，出題時採用了條文例示詞）：C8t／C8p／M2／R5／N2r 全屬此類。條文側不能靠出題時的檢查擋，題目側可以——而題目側的五題全部落在 b6／b9／b12 三批，那三批沒有 isocheck 工具。
