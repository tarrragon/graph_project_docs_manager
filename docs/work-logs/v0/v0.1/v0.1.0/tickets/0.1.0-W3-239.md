本票原範疇為第二條（同級別不得互相搶佔——排隊或合併）。但方法論的第三條現行文字為：

> 3. 低級別**排隊等待**，不得搶佔任何請求

「排隊等待」是 `0.1.0-W3-231` 的多輪審查 Round 1 加入的（commit `b50d3666`），初版（`92324657`）為「低級別**不得**搶佔任何請求」——**只禁搶佔，不規定被禁者做什麼**。加入後，第三條從一條禁令變成一條處置指派。

於是第三條與 `SPEC-003` §2.13 的現行決策同樣衝突：§2.13 明訂「排隊／延後／拒絕新的 `plain` 三者**皆不採用**，理由為三者皆在提示層為排程問題做視覺化緩衝，改以留痕滿足」。第二條與第三條指向同一個爭點——**0.1 是否引入任何形式的提示佇列**——分開裁決會產生兩個可能不一致的結論。本票一併裁決。

**二、`0.1.0-W3-205` 的 acceptance 已預設了本票的結論，須併同處置。**

`205` 的 acceptance 第二條為「截斷條件綁在級別上：低級別不得 hide、**同級別排隊**、僅高級別可截斷，三者各有測試」——**它已經假定採用排隊**，與 §2.13 的現行決策相反。該 acceptance 寫於 `184` 完成之時、方法論尚未產出，當時未察覺與 §2.13 的衝突。

## Solution
<!-- Schema[ANA/Solution]: 必填（.claude/pm-rules/ticket-body-schema.md） -->
### 裁決結論：維持留痕，正式記錄為具名例外

### 一、§2.13 拒絕理由的重新查證

§2.13 拒絕排隊/延後/拒絕新 plain 三者的理由為：

> 三者皆在提示層為排程問題做視覺化緩衝——症狀被吸收，而「同時發生了兩件都需要告知使用者的事」這個成因原封不動，且緩衝做得越好，成因越不可能被發現。

方法論產出後，仲裁點由 §2.13 定為「通道持有層」（方法論 §1「仲裁器落在通道的持有層，不落入任何 domain 內部」），不落在提示層元件內部。問：若排隊發生在仲裁器而非 AppSnackBar 內部，§2.13 的拒絕理由是否還指向同一件事？

逐字比對後的回答：是。理由仍然成立。

拒絕理由的核心是「在提示層為排程問題做視覺化緩衝」——這裡的「提示層」指的是從使用者可見角度看到的暫態提示通道本身（即 ScaffoldMessenger 管理的 SnackBar 佇列），不是特指 AppSnackBar 這個 Dart class。無論排隊邏輯放在 AppSnackBar.show() 內部還是放在一個獨立的仲裁器中，最終的可觀察效果相同——SnackBar 依序出現在同一個視覺位置，後到者延後 4-8 秒才被使用者看到，屆時已與觸發脈絡脫節。仲裁點的位置改變了職責歸屬，沒有改變可觀察效果。§2.13 的拒絕理由針對的是效果而非職責歸屬。

### 二、方法論自身支持維持留痕的三個依據

依據 1：方法論 §12 旁路的存在與可靠性——「單一使用者的桌面應用對注意力不夠沒有任何擴充選項，此時正確的答案是承認該通道的容量固定、把設計改成不產生超出它的請求」。本 App 是單一使用者的 macOS 桌面應用。方法論指出的正確方向是「不產生超出它的請求」（即 §2.13 的「密度過高的成因在事件流設計，不在提示層」），而非在通道上排隊。

依據 2：方法論 §6 卸載順序表——自發型/可棄格動作為「跳過，不補跑」；等待型/可棄為「拒絕加可重試資訊」。可棄事件在通道飽和時不排隊。九格表的具體動作覆蓋規則的一般敘述。

依據 3：方法論 §4 固定服務型通道——SnackBar 載體屬串行且服務時間固定者，佇列深度 >= 2 時第二則等待至少 4s，已超過 Motion.cancelDeadline（500ms），佇列代價與 §2.5 行為時限承諾直接衝突。

### 三、規則 2 與規則 3 的一併裁決

規則 2（同級別不得互搶——排隊或合併）：0.1 現況為無條件截斷加留痕，裁為具名例外。理由：方法論 §12（容量固定通道減少到達不排隊）、§4（固定服務型佇列等待與 cancelDeadline 衝突）、§6（可棄事件跳過不補跑）。

規則 3（低級別排隊等待）：0.1 同一載體上只有可棄級別，§2.15 已證跨級別時序互斥——規則 3 空成立，無需例外。

### 四、對 0.1.0-W3-205 acceptance 第二條的影響

205 第二條「截斷條件綁在級別上：低級別不得 hide、同級別排隊、僅高級別可截斷，三者各有測試」中「同級別排隊」與裁定矛盾。本票不改動 205 的 acceptance。

建議 PM 改為「截斷條件綁在級別上：低級別不得 hide、同級別截斷並留痕、僅高級別可截斷，三者各有測試」——與 §2.13 一致，且低級別不得 hide 和高級別可截斷仍由 205 負責實作。被截斷時日誌能回答被截斷的是哪一則（205 acceptance 第三條不受影響）。

### 五、規格條文需補記的位置與文字建議

本票不改 SPEC-003 任一條文（ANA 不寫規格正文）。建議：

位置 1：§2.13 重評 trigger 段後——補「0.1.0-W3-184 已完成（產出方法論 v1.7.0）；0.1.0-W3-239 覆核結論：維持留痕，規則 2 在本通道記為具名例外，理由見該票 Solution 三。」

位置 2：§2.15 同級別規則 2 驗收段後——補「0.1.0-W3-239 裁定此偏離為具名例外，非待修正項目；例外理由：方法論 §12 指出固定容量通道應減少到達而非排隊，§4 固定服務型通道的佇列等待與 §2.5 Motion.cancelDeadline 直接衝突。」
