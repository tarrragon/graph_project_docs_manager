### 重跑範圍與方法

逐條比對 SPEC-001 §1-7 每一列的「顯示」欄與「可用操作」欄文字，對照現行 28 個 ARB
key（`lib/l10n/app_zh.arb`），標記未被任何既有 key 覆蓋的文案。共確認 7 處缺口
（含 Context Bundle 已知的 3 處），逐一裁定如下。

### 裁定：操作欄字面是否納入

**結論：納入。** 理由：專案 `parsley-flutter-developer` 代理人定義明文「所有 UI 字串
必須透過 ARB/l10n 系統，禁止硬編碼」，未對「顯示欄」與「操作欄」做區分；SPEC-001
矩陣的四欄劃分（顯示／可用操作／進入條件／退出路徑）是 gate 三問文件格式的產物，
不是 i18n 覆蓋範圍的邊界宣告。因此三個載入型狀態的「取消載入」／「取消」按鈕字面
與 §7 展開狀態的「選擇其他」操作字面一併納入本次補齊。

### 新增 7 個 ARB key（zh/en 對稱）

| key | zh | 對應狀態 | 類型 |
|-----|-----|---------|------|
| `cancelLoadingAction` | 取消載入 | §1 Domain 載入中 + §4 Ticket 載入中（共用，文字逐字相同） | 操作欄 |
| `cancelScanAction` | 取消 | §5 破洞報告掃描中 | 操作欄 |
| `gapReportScanning` | 正在掃描破洞… | §5 破洞報告掃描中（骨架+進度，與 domainLoading/ticketsLoadingProgress 同型但前次歸類漏了此列） | 顯示欄 |

| `notFrameworkProjectExplanation` | 本 App 需要專案根目錄下含 docs/ 目錄，並依循框架文件慣例組織文件 | §1 不是框架專案的補充說明（原僅覆蓋標題句） | 顯示欄 |
| `ticketsUnassignedSection` | 未歸屬 | §4 正常·主題的未歸屬節標題（UC-05 acceptance 已明定此概念，非未決項） | 顯示欄 |
| `noGapsScanScope` | 已掃描全部節點與邊 | §5 無破洞的掃描範圍說明（原僅覆蓋「未偵測到破洞」句） | 顯示欄 |
