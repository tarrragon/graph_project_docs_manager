## Problem Analysis
### 問題根因

W3-457.3 第二版定義以兩軸判定「明顯非按鈕形態」：構成要素（文字或圖示／區塊）與區塊高度，比較對象是「同一畫面上實際的按鈕」。第三輪裁示（W3-417〈UX-09a 定義第三輪用戶裁示〉）定了 U4-B（理由句列出描邊 vs 實心、圓角、底色深淺為不可靠訊號，比較依據只看構成要素與區塊高度）與 U5（高度不設門檻），留下 U6（多出一個按鈕沒有的要素算不算不同）與 U7（矮的過、等高不過是否符合本意）。

第二版只以 4 個指定輸入加 5 個加推輸入驗證，全部是單列、單一按鈕種類、單一量測條件的靜態稿。定義中有 4 個詞在真實畫面上沒有唯一值：「每一種按鈕」的量詞與範圍、「按鈕」涵蓋哪些可點元件、「區塊高度」在哪個字級／斷點／密度量測、「低於」的量級。U4-B 的「只看」又把文字色、寬度、平台慣例這些使用者實際依賴的訊號排除在外。

## 重現實驗結果
### 實驗方法

premortem 前提：第二版定義（W3-457.3 Solution 一）已依 U4-B、U5 落檔半年，回推它在哪些真實畫面判錯。每個情境只拿定義字面逐詞推導，記錄四欄：輸入描述 → 逐詞推導 → 結果 → 是否符合意圖「使用者不會把指示誤認為可點按鈕」。

判定詞（沿用 W3-457.3）：E1 文字或圖示（同一項要素）；E2 區塊（底色或外框圍住文字或圖示）；X1 構成要素軸；X2 區塊高度軸（兩者都有區塊時，指示低於按鈕，U5 不設門檻）；規則「任一軸上與畫面上每一種按鈕都不同 → 屬 (a)」；U4-B 比較依據只看構成要素與區塊高度。

U6 兩案：
- U6-A（對稱）：指示缺少按鈕具備的一項，或多出按鈕沒有的一項，都算構成要素不同
- U6-B（只算缺少）：只有指示缺少按鈕具備的一項才算不同；多出的不算

結果分類：正確／假合格（判屬 (a) 但使用者會誤認）／假不合格（判不屬 (a) 但使用者不會誤認，代價是被迫移出動作列）／條件性（結果取決於定義沒指定的讀法或量測條件）。

例示同構檢查：情境未使用直條、檔案列、分享、相簿、SSH、訂單、退款。

### 實驗執行

逐情境推導（尺寸為構造值，單位 px）：

**S1 無按鈕畫面**
- 輸入：唯讀的個人檔案頁，只有 28 高填色「已驗證」chip，返回靠系統手勢，畫面上沒有按鈕
- 推導：比較對象集合為空。「與每一種按鈕都不同」可讀為空集合真值（屬 (a)），也可讀為無從比較（不可判）；U6 只作用在有比較對象時
- 結果：A、B 相同，字面兩讀
- 意圖：沒有按鈕即無同形混排，合格符合意圖；取空真值讀法不違意圖，但讀者會分歧

**S2 多種按鈕並存（量詞歧義）**
- 輸入：卡片底部列有 40 高填色「儲存」與不加底色外框的純文字「取消」，同列 28 高填色「草稿」chip
- 推導：vs 儲存：E1E2 同，X2 低於 → 高度軸不同。vs 取消：chip 有區塊、取消沒有
  - A：vs 取消構成要素軸不同。量詞讀法 R1「對每一種按鈕都至少在一軸不同」→ 屬 (a)；讀法 R2「存在單一軸對所有按鈕都不同」→ X1 對儲存相同、X2 對取消不適用 → 不屬 (a)
  - B：vs 取消未缺要素 → X1 同；X2 不適用 → 對取消兩軸皆同 → 不屬 (a)（兩種讀法皆然）
- 意圖：與 U1 同型（chip 比同列帶區塊按鈕矮），合格
- 結果：A 條件性（R1 正確、R2 假不合格）；B 假不合格

**S3 比較範圍（畫面他處的小按鈕）**
- 輸入：列表列內有 44 高填色「接受」與 32 高填色「待審」chip；同一畫面頁尾有 28 高填色小按鈕「回報問題」
- 推導：vs 接受：高度軸不同。vs 回報問題：E1E2 同，32 不低於 28 → 兩軸皆同 → 不屬 (a)。A、B 相同（無多出、無缺少）
- 意圖：使用者以同列的「接受」為參照，chip 明顯較矮，合格；定義字面「同一畫面」把遠處按鈕納入
- 結果：A、B 皆假不合格

**S4 純圖示按鈕與純圖示指示**
- 輸入：文字編輯器工具列，無底色的粗體、斜體、插入連結圖示按鈕；同列無底色「雲朵打勾」圖示表示已儲存
- 推導：兩者皆 E1 有（圖示）、E2 無 → X1 同；X2 不適用 → 不屬 (a)。A、B 相同
- 意圖：使用者會點雲朵以為是手動儲存，不合格符合意圖
- 結果：A、B 皆正確

**S5 文字與圖示合併為同一要素**
- 輸入：收件匣列尾有無底色垃圾桶圖示按鈕；同列灰色純文字「草稿」
- 推導：指示 E1 有（文字）E2 無；按鈕 E1 有（圖示）E2 無；文字或圖示屬同一要素 → X1 同；X2 不適用 → 不屬 (a)。A、B 相同
- 意圖：灰色字樣與圖示按鈕外觀類別不同，使用者不易把字樣當按鈕，合格
- 結果：A、B 皆假不合格（代價：被迫移出動作列）

**S6 附著於圖示按鈕的數字徽章（非選取類指示）**
- 輸入：導覽列無底色的聊天泡泡圖示按鈕，右上角紅色圓形底色包住數字「3」
- 推導：指示 E1 有（文字「3」）E2 有；按鈕 E1 有 E2 無
  - A：指示多出區塊 → X1 不同 → 屬 (a)
  - B：未缺要素 → X1 同；X2 不適用 → 不屬 (a)
- 意圖：徽章疊在按鈕熱區上，點下去觸發按鈕本身，不會出現「沒反應」；合格
- 結果：A 正確；B 假不合格。定義也沒寫疊在按鈕上的徽章是否算獨立指示

**S7 字級縮放**
- 輸入：預設字級 chip 24、填色按鈕固定 36；系統字級 200% 時 chip 隨字長到 40，按鈕仍 36（文字截斷）
- 推導：預設字級 X2 低於 → 屬 (a)；200% 字級 40 不低於 36 → 不屬 (a)。定義沒指定在哪個字級量測。A、B 相同
- 意圖：大字級下 chip 比按鈕高且同為填色區塊，會誤認，該字級下不合格才對；審查通常只看預設稿
- 結果：A、B 皆條件性（只看預設稿即審查時假合格）

**S8 響應式斷點**
- 輸入：窄幅按鈕放大到 44 觸控尺寸，chip 32；寬幅桌面版按鈕縮為 32，chip 仍 32
- 推導：窄幅屬 (a)；寬幅兩軸皆同 → 不屬 (a)。定義沒指定斷點。A、B 相同
- 意圖：寬幅同高時會誤認
- 結果：A、B 皆條件性（設計稿只交窄幅即假合格）

**S9 密度模式與微小高度差**
- 輸入：表格工具列緊湊密度下，填色按鈕 30、填色 chip 28；另一處描邊「已同步」標籤從按鈕同高縮為低 1px
- 推導：X2 只要求低於，U5 不設門檻 → 兩者皆屬 (a)。A、B 相同
- 意圖：1～2px 差肉眼不可辨，兩者同為文字加區塊，會誤認；U1 的判否反例「尺寸與按鈕相同」可藉縮 1px 規避
- 結果：A、B 皆假合格

**S10 只有純文字按鈕的畫面上的填色 chip**
- 輸入：對話框底部純文字「略過」「稍後提醒」按鈕（無區塊），同列 32 高填色「新功能」chip
- 推導：
  - A：chip 多出區塊 → X1 不同 → 屬 (a)
  - B：未缺要素 → X1 同；X2 不適用 → 不屬 (a)
- 意圖：列中唯一帶底色區塊的元素最像按鈕，會誤認，不合格才對
- 結果：A 假合格；B 正確。桌面 ghost 按鈕（靜止無底色、懸停才出底色）同型，且定義沒指定比較按鈕的哪個狀態

**S11 同列多指示**
- 輸入：列有 36 高填色「核准」按鈕、24 高填色「急件」chip、36 高描邊「已指派」標籤
- 推導：逐一判定：急件 X2 低於 → 屬 (a)；已指派兩軸皆同 → 不屬 (a)，在動作列 → 不合格。A、B 相同
- 意圖：已指派標籤與按鈕同尺寸會誤認；急件不會
- 結果：A、B 皆正確

**S12 可點 chip 與不可點 chip 並存（「按鈕」涵蓋範圍）**
- 輸入：篩選列有 28 高填色可點篩選 chip「本週」「本月」，右側 40 高填色「套用」；同列 28 高填色、不可點的「共 12 筆」chip
- 推導：篩選 chip 若不算「按鈕」→ 只比「套用」→ X2 低於 → 屬 (a)；若算 → 兩軸皆同 → 不屬 (a)。A、B 相同
- 意圖：外觀完全相同、一可點一不可點，必然誤認，不合格才對
- 結果：A、B 皆條件性（把「按鈕」讀成按鈕元件時假合格）

**S13 文字連結與純文字指示（文字色被排除）**
- 輸入：登入表單底部藍色純文字連結「忘記密碼」與 40 高填色「登入」，同列灰色純文字「已記住帳號」
- 推導：連結若算按鈕 → vs 連結兩軸皆同 → 不屬 (a)；不算 → vs 登入缺區塊 → 屬 (a)。U4-B「只看構成要素與區塊高度」排除文字色。A、B 相同
- 意圖：藍 vs 灰是使用者實際依賴的區分訊號，合格；但若連結也是灰色則會誤認
- 結果：A、B 皆條件性（連結算按鈕時對有色連結假不合格；定義無法區分有色與同色）

**S14 比按鈕高或寬的提示區塊**
- 輸入：表單底部列左側 44 高、佔半寬的淺底提示區塊「變更會自動儲存」，右側 36 高填色「完成」
- 推導：E1E2 同；44 不低於 36 → 兩軸皆同 → 不屬 (a)，在動作列 → 不合格。寬度不在比較依據內。A、B 相同
- 意圖：半寬、一整句說明的淺底區塊讀作提示框，不像按鈕，合格
- 結果：A、B 皆假不合格

**S15 平台慣例上可點的幾何指示**
- 輸入：下載列有 24 直徑進度環（純幾何、無文字），同列 36 高填色「開啟資料夾」按鈕
- 推導：進度環 E1 無（純幾何不算圖示）E2 無；按鈕 E1 有 → X1 不同（缺少，A、B 皆算）→ 屬 (a)
- 意圖：多個平台把進度環做成可點停止，使用者會點它，點了沒反應即被讀成壞掉
- 結果：A、B 皆假合格

## Solution
### 一、結論

第二版定義（依 U4-B、U5）在 15 個真實畫面情境中，U6-A 確定判錯 6、條件性 5；U6-B 確定判錯 7、條件性 4。兩案皆錯的有 9 個（確定 5、條件性 4），根源不在 U6，而在定義的 4 個未定詞與 U4-B 的封閉比較依據。U6 只改變 3 個情境的結果：A 錯 S10（假合格），B 錯 S2、S6（假不合格）。逐情境推導見〈重現實驗結果〉。

流程說明：premortem-workflow 步驟 2 為每個失敗原因派 subagent 深挖。本票執行者為被派發的代理人，且失敗原因是定義字面推導而非敘事，改為在〈重現實驗結果〉逐情境推導（輸入→推導→結果→意圖），步驟 3 綜合報告寫於下節。

### 二、premortem 綜合報告

| 節 | 內容 |
|---|---|
| 最可能的失敗 | S9：只要求「低於」且不設門檻，設計者把 chip 或描邊標籤縮 1～2px 即合格。理由：這是最低成本的通過方式，U1 的判否反例「尺寸與按鈕相同」因此形同虛設 |
| 最危險的失敗 | S12：可點篩選 chip 與不可點狀態 chip 外觀完全相同，把「按鈕」讀成按鈕元件時判合格。發生率低於 S9，但通過的正是最容易誤認的畫面 |
| 隱藏假設 | 審查輸入是單一靜態稿，畫面上的按鈕種類、字級、斷點、密度都只有一個值。S2、S3、S7、S8、S9、S12 全部建立在這個假設被打破之上 |
| 修訂計畫 | 見三、四兩節的條文修正選項；每個選項對應具體情境 |
| 落檔前檢查清單 | (1) 鏈式範例或驗證段補一題「同列有帶區塊與無區塊兩種按鈕」（S2）；(2) 補一題「可點 chip 與不可點 chip 同形」（S12）；(3) 若採量測條件選項，補一題字級放大後 chip 高於按鈕（S7）；(4) UX-09a 重跑答案鍵以 `git grep -F` 重核新定義引文；(5) 例示同構檢查延用本票排除清單 |

最嚴重的三個情境：S9（假合格，最可能）、S12（條件性假合格，最危險）、S7／S8（條件性假合格，審查只看預設稿即漏）。

### 三、U6 兩案後果對照

| 情境 | U6-A 對稱 | U6-B 只算缺少 | 意圖 |
|---|---|---|---|
| S2 帶區塊與純文字按鈕並存，旁有矮填色 chip | R1 讀法屬 (a)，R2 讀法不屬 | 不屬 (a)，假不合格 | 合格 |
| S6 圖示按鈕上的數字徽章 | 屬 (a)，正確 | 不屬 (a)，假不合格 | 合格 |
| S10 只有純文字按鈕的列上的填色 chip | 屬 (a)，假合格 | 不屬 (a)，正確 | 不合格 |
| 其餘 12 情境 | 與 B 相同 | 與 A 相同 | — |

後果比較：
- A 的錯誤是假合格（使用者被誤導，直接違反意圖），出現在按鈕全無區塊、指示是列中唯一帶區塊元素的畫面
- B 的錯誤是假不合格（被迫移出動作列），出現在畫面另有帶區塊按鈕作參照（S2），以及徽章（S6）這個普遍慣例
- S2 與 S10 結構相同（填色 chip 旁有純文字按鈕），差別只在畫面上是否另有比 chip 高的帶區塊按鈕。兩個純方案都無法同時判對

第三個選項 U6-C（改造既有，供用戶比較）：多出一個要素時，只有畫面上另有具備該要素的按鈕、且指示與該按鈕在任一軸上不同，才算不同。推導：S2 儲存帶區塊且 chip 較矮 → vs 取消的多出區塊算不同 → 屬 (a)，正確；S10 畫面無帶區塊按鈕 → 不算不同 → 不屬 (a)，正確；S6 導覽列無帶區塊按鈕 → 不屬 (a)，假不合格，須另加徽章條款（見四 O6）。代價：條文多一層條件，讀者須先盤點畫面上有哪些按鈕種類。

自我暴露偏好：我傾向 U6-C 加徽章條款。理由：它是 15 情境中唯一讓 S2、S6、S10 全部判對的組合，且錯誤方向不含假合格。可能漏掉的面向：條件層數增加會提高重跑讀歪率，這項只能由 UX-09a 重跑驗證；若用戶偏好條文簡短，A 的單一假合格情境（S10）可能是可接受代價。
