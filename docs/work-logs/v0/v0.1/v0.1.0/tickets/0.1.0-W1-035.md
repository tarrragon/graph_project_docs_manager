### 問題根因

SPEC-001 §1「無可消費的型別表」列的可用操作欄寫「（若支援降級）以純檔案模式檢視」，括號即未定案；CLAUDE.md §6 將其列為無 trigger 待決；SPEC-003 §3.1／§5 與 SPEC-004 BlockedState 只能以「0.1 不渲染」佔位。根因是 PROP-002 定案「讀專案內 `tracking_schema.json`」時，只把版本偏斜帶進「太新」一路，沒有回答「檔案根本不存在」（框架 < 2.41.0）時 App 要做什麼——而實測全機語料 94% 落在這一路（domain-map §9）。

### 影響範圍

- `docs/spec/ui/SPEC-001-screen-state-matrix.md` §1 該列 + 新註記；版本 1.4 → 1.5
- `docs/spec/ui/SPEC-003-interaction-response.md` §3.1 導航跳轉列、§4 第 7 列、§5 判讀註記；版本 1.6 → 1.7
- `CLAUDE.md` §6：待決項移除，改為已定案一段
- `docs/tech-decisions.md`：append-only 補記段「2026-09-03：型別表缺席時降級而非拒絕」
- 未動：SPEC-004（三處「待 W1-035」引用 → spawn DOC 票）、lib/、test/

已驗證的事實：三個缺檔語料的 frontmatter 欄位名與 2.43.1 型別表 `forward_field` 完全同名、ID 全部命中現行 `id_pattern`（見重現實驗結果）。仍未驗證的假設：舊語料中同名欄位的值型別是否與現行一致（例如 `relatedTo` 是否恆為 list）——本次掃描只檢查非空，未檢查型別，列為 tripwire。
