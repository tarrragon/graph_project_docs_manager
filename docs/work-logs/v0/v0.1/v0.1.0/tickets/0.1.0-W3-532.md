## Problem Analysis
<!-- Schema[ANA/Problem Analysis]: 必填（.claude/pm-rules/ticket-body-schema.md） -->
### 問題根因

〈容器亦為元件〉射程判定表第五列的管轄欄把表外的判別問句段當成子程序呼叫，但該段的回傳值不是一個管轄者，而是一個診斷：「該處缺一個容器元件」。

管轄欄現行措辭為「對共同上層重問一次本節判別問句，由該層承載；兩端各自的組合規則均不得另定這段間距」，語法上是「程序 + 單一結論」。讀者讀到「由該層承載」時已取得一個可填的管轄值，判別問句因此被讀成執行順序上的下一步，而非取值來源。當共同上層是頁面本身時，正確輸出應為「該處缺一個容器元件，須先補上該容器元件，由它承載」——這個輸出在本節任何一處都沒有以管轄值的形式出現。讀者必須自行把診斷翻譯回管轄答案，這一步無條文可依。

**這是承諾型別的落差，不是可見性落差**：三輪讀者全數逐字引用了判別問句（含「答案若是『頁面本身』，該處缺一個容器元件」），全數仍把承載層寫成頁面。路由已生效（第五列依據欄即指向該段），失效的是呼叫端對回傳值的期待。

**在計分上不可見，在用途上完全失效**：答案鍵現行門檻為「取用第五列並指出對共同上層重問判別問句、由該層承載」即通過，並明訂進一步推得缺容器者「亦記通過」（不強制）。故三輪皆記通過、b16 該題 3/3。但讀者的產出「這段間距由頁面管轄」，正是本節首段明文禁止的狀態——「頁面直接用原生佈局原語（水平或垂直堆疊、格線）排列元件，視同自製元件，適用工程端『禁自製元件』判準」。本節存在的理由是防止無人負責的排列造成重疊事故，而通過本題的讀者恰好產出了那個無人負責的排列。

### 實驗執行

**第一段：三輪把承載層停在頁面的原文（逐輪引用，含進入列）**

| 輪 | 判定欄逐字（承載層落點） | 是否引判別問句 | 從表的哪一列進入 |
|---|---|---|---|
| r1 | 「這段距離由『頁面』管轄。……答案若是『頁面本身』，該處缺一個容器元件，由該層（頁面）承載。」 | 是（全句） | 第五列（依據句為判別問句全句 + 第五列整行，無第一列） |
| r2 | 「此段距離由『頁面』（或共同上層）決定；判定步驟應重問判別問句『畫面上任兩個元件的相對位置是誰決定的？』」 | 是（全句） | 第五列（依據句為第五列管轄欄 + 判別問句全句） |
| r3 | 「這段距離由『共同上層』（頁面或框架容器）管轄。依條文應循『本節判別問句』判定。」 | 是（全句） | 第五列（依據句為第五列 + 判別問句全句） |

三輪的進入列一致為第五列，**無任一輪的依據句含第一列**。r1 最尖銳：同一句內先寫「該處缺一個容器元件」、再寫「由該層（頁面）承載」，兩者互相抵消。r2 把判別問句明寫為「判定步驟」，即只當程序不當取值來源。r3 最輕——「框架容器」是本節既有術語（「框架容器（頁面根堆疊、殼層）」），指的是頁面根堆疊這個容器元件，但該輪把它與「頁面」並列為兩個等價答案，仍未走到「缺一個容器元件」。

**第二段：兩位判定者的獨立記錄**

- j1 的絆腳索表：(i)（是否逐字引第一列）r1／r2／r3 **三輪皆否**；(ii)（是否把畫面／頁面當容器）r1／r2 記「是（弱）」、r3 記否。j1 的判讀原文：「收窄第一列對 (ii) 無效，因為 (ii) 的讀者並不會走到第一列，他直接把頁面填進第五列的『該層』。若要處理 (ii)，標的是第五列管轄欄或判別問句段，不是第一列。」
- j2 的絆腳索表：(i) 三輪皆否；(ii) 三輪皆否（判準較嚴，要求作答把頁面「稱為」容器元件才算命中）。j2 另起一節記：「三輪都把承載責任的落點停在『頁面／共同上層』這一層，只有 r1 進一步寫出『該處缺一個容器元件』」，並建議下批把「是否把判別問句的結論走到底」與「是否把頁面當容器」再分一層。
- j1 的結論表逐字列入一項條文讀歪點：「第五列管轄欄的『該層』與判別問句的『缺一個容器元件』之間缺一步銜接：條文未明寫『若該層是頁面本身，則該層尚不存在、須先補容器元件』。」

兩位對 (ii) 的計分口徑不同（j1 兩命中、j2 零命中），但**對缺口位置的認定一致**：不在第一列，在第五列管轄欄與判別問句段之間的銜接。

**第三段：收窄第一列已生效，故本缺口不可能由第一列承接**

- 絆腳索 (i) 三輪零命中——`0.1.0-W3-529` 的收窄（第一列由「一個元件 ↔ 另一個元件」改為「同一容器內的兩個子件」）在本批達成其預定效果，第一列不再對「兩個容器之間」給出假陽性。
- 第 9 項的誤傷觀測（19a(c)）亦零命中：三輪 (c) 皆判定正確，無一輪以「找不到容器」為由拒答或改判。收窄的已知代價未實現。

### 實驗發現

**已驗證的事實**

1. 三輪的承載層落點皆停在頁面或共同上層，無一輪輸出「須先補一個容器元件再由它承載」。
2. 三輪皆逐字引用判別問句——**該段的可見性與路由皆正常**，失效發生在讀者把該段的回傳值轉成管轄值的那一步。
3. 三輪皆從第五列進入，零輪引第一列——收窄已生效，本缺口與第一列無因果關係。
4. 現行答案鍵門檻對本現象不敏感：三輪皆記通過，b16 該題 3/3。

**仍未驗證的假設**

- 「改第五列管轄欄即可使讀者走到底」尚未被任何讀數支持——本票只證明缺口位置，未證明任一修法有效；驗證須待下一批探針。
- 本形態在真實撰寫者身上的發生率未知。
