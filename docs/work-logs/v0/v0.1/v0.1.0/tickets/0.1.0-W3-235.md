- 0.1.0-W3-231 why: 用戶裁示（2026-09-09）：新增的 skill 內容與方法論要作多輪審查。

前次審查（方法論定稿時）是三名代理人一輪並行，三個視角（架構、文字、高負載工程）各自獨立。依 multi-round-review 的判準，那一輪屬「跑臨時子集卻當成跑完整框架」——三個 frame 皆落在 Round 1（規範遵循）與 Round 3-B（steelman）之間，未跑 Round 2 的讀者旅程／冷讀／探針家族，也未跑 Round 3 的誤用梯度、共同前提、個案實跑。該 skill 明載一則實例：某份文件跑完三輪八個 reviewer 報「三輪全過」，一天後另一批審查在同一份文件找出五項嚴重缺陷，全部來自唯一沒有派人負責的維度。

本批另有兩項本身就構成高風險的性質：(1) 方法論的判準由單一實例（使用者注意力通道，樣本一個單機桌面 App）外推為資源無關通則，`DOC-GPD-008` 已記錄一次同型失效（例示沿用來源實例直覺、未回代判準鍵，導致仲裁申請訊息被歸入溢出即丟棄的類別）；(2) skill 的 worked-examples 三場景取自審查報告改寫，屬「教學層 case 引用」的高風險形態。
