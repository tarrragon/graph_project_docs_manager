## Problem Analysis
### 問題根因

閘門組（0.1.0-W3-335 系列）為修補審查子票（W3-332）指出的範例缺口，在多個 skill reference 檔案新增三段鏈式範例。範例補齊後，多檔 token 數超出 `skill-design-guide` 定義的第 2 層（SKILL.md 全檔 5k）與第 3 層（單檔 5k，依讀取方式適用於整份或最大單節）門檻。根因非「範例太多」，而是**原檔在通過門檻時就已採用過度精簡的規則文字（省略判斷條件的具體範例），補齊範例後才顯露出章節早該依讀者任務切分**——用戶裁示已明確排除以刪範例或壓規則文字回應此狀況。

### 影響範圍

**已驗證事實**（用 `skill-design-guide` SKILL.md〈Progressive Disclosure〉的分段估算指令逐檔實測，指令與數值見「重現實驗結果」）：

- 23 個 W3-335 觸碰過的 skill 檔案（6 個 SKILL.md + 17 個 references/templates/examples）全數量測完畢
- 6 個超標檔案（依各自適用的讀取方式判定，見重現實驗結果）：
  `component-contract-design/references/step-2-extract-components.md`、
  `component-contract-design/references/step-3-fill-contract.md`（W3-342 範圍）、
  `tdd/references/doc-handoff.md`、
  `tdd/references/test-object-catalogue.md`、
  `ux-design-evaluation/references/interaction-feedback.md`（W3-322 範圍）、
  `ux-design-evaluation/references/screen-state-matrix.md`
- 2 個檔案全檔量測超標，但適用讀取方式為「選段查閱」，以最大單節量測則未超標，判定不需拆分：
  `component-contract-design/references/appendix-examples.md`、
  `doc/examples/component-library-chained-examples.md`
- 1 個模板檔全檔超標，判定其消費方式為逐欄位選段填寫（非整份執行），以最大單節量測未超標，判定不需拆分：
  `doc/templates/component-library-spec-template.md`
- 3 個檔案接近門檻（>= 90% of 5000，全部為 SKILL.md 或 reference，皆未超標）：
  `ux-design-evaluation/references/gate-fallback.md`（4728/5000）、
  `ux-design-evaluation/references/input-mechanism.md`（4779/5000）、
  `skill-design-guide/references/chained-examples.md`（4682/5000）
- 其餘 11 個檔案（含全部 6 個 SKILL.md）在門檻內，無須處置

**仍未驗證的假設**：本票的重切方案為分析階段的 token 估算（依現有章節文字切分後加總），非實際搬移檔案後的複驗值；搬移會新增 H1、跨檔指標、路由表等結構開銷，實際落地後需依 `skill-design-guide` 同一量測指令重新量測，且需依 `splitting-an-existing-skill.md`〈拆分特有的必查項〉逐項核對節界／跨檔指涉／共置關係／外部引用／兄弟檔互指矩陣，並依〈兩種驗證，方法不同〉跑讀者探針驗證拆分可用性——這些驗證動作留給實作票執行，本票不動檔案。
