## Problem Analysis
### 問題根因

閘門組（0.1.0-W3-335 系列）為修補審查子票（W3-332）指出的範例缺口，在多個 skill reference 檔案新增三段鏈式範例。範例補齊後，多檔 token 數超出 `skill-design-guide` 定義的第 2 層（SKILL.md 全檔 5k）與第 3 層（單檔 5k，依讀取方式適用於整份或最大單節）門檻。根因非「範例太多」，而是**原檔在通過門檻時就已採用過度精簡的規則文字（省略判斷條件的具體範例），補齊範例後才顯露出章節早該依讀者任務切分**——用戶裁示已明確排除以刪範例或壓規則文字回應此狀況。

### 實驗發現

**已驗證的事實**：

1. 6 個檔案在其判定讀取方式下確實超標（見上表粗體列），超標幅度 14%-83%。
2. `component-contract-design/references/appendix-examples.md`、`doc/examples/component-library-chained-examples.md`、`doc/templates/component-library-spec-template.md` 三檔全檔超標但最大單節在門檻內，其消費模式（隨時查閱、缺範例位置對應、逐欄位填寫）不要求整份載入，判定不需拆分——此為本票新增的判定，未見於既有票（W3-322/W3-317/W3-342 僅對前兩類中的一檔位做過準判定，模板檔未被判定過）。
3. `tdd/references/doc-handoff.md` 與 `test-object-catalogue.md` 的〈相關文件〉H2 尾端各自內嵌完整版本紀錄（doc-handoff 7 條 Version、test-object-catalogue 5 條），量測顯示這段純版本敘事分別佔 1262 tokens 與 850 tokens，且與 `tdd` skill 自身 CHANGELOG.md v2.2.7 條目「版本紀錄搬到同目錄的 CHANGELOG.md……SKILL 是 runtime 整份載入的檔案，留在正文等於每次叫用都付一次無效讀取」的既有裁決矛盾——這兩份 reference 檔並非 SKILL.md 本體，但同一則「敘事不占正文預算」的理由對 `整份執行` 的 reference 檔同樣成立。此項外移不屬「刪範例」或「壓縮規則文字」，是清出非規則、非範例的維護敘事，最先執行。
4. `ux-design-evaluation/references/interaction-feedback.md` 的路由症狀列（SKILL.md〈觸發路由〉表對應列）本身已混雜兩種讀者任務的症狀關鍵字：「按鈕按了沒反應／重複提交／loading／spinner vs skeleton／通知該用 SnackBar 還是 Dialog」（時間門檻與通道群）與「切換鈕標籤被讀成現態／選中看不到字／文字被壓成省略號」（元件語意與版面群）。檔內〈反模式速查〉19 列與〈檢查清單〉四組已依這兩群清楚分組（無混雜列），是可machine-verify 的分割依據，非本票新造判準。
5. `component-contract-design/references/step-2-extract-components.md` 的〈路徑 A／B／C〉三節與 `test-object-catalogue.md`〈五、三種起點的推導程序〉的〈起點 A／B／C〉三節，皆對應各自 skill 已定義的「三種起點互斥」判定（`component-contract-design/SKILL.md`〈判定起點〉、`test-object-catalogue.md`〈五〉自身標題）——讀者在抵達這些節之前已由前置步驟判定屬於哪一條路徑，三節互斥、單一讀者只需其中一節。
