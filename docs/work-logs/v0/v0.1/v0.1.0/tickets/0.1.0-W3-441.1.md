| 核對句 | 命中位置 |

| 「catch 後 return 預設值 \| 必須記錄 warning 日誌（含錯誤訊息和元件名稱）」 | 同上表 |

| 「功能包含 catch/error handling 時必答。」 | `.claude/skills/tdd/references/phase1/rules.md` Q5 觸發條件 |
| 「純讀取操作的快取 miss -> 不需要日誌，靜默即可」 | 同檔 Q5 反面範例 |

### 實驗發現

- 已驗證：Q5 位於 `phase1/rules.md`（派發 prompt 寫 phase2，實際為 phase1，與父票一致）；全域無「何時可選靜默」條文，F-28 屬缺引導。
- 已驗證：Q5 三選項「日誌/通知/靜默」中，「日誌」對操作者、「通知」對使用者，「靜默」即兩者皆無；反面範例「不需要日誌，靜默即可」證實靜默含「不記日誌」。
- 已驗證：規則 1 對 catch 區塊不記日誌只留一個出口——註解說明原因；「catch 後 return 預設值」列要求 warning 日誌。草稿「可選擇不記錄日誌」未帶註解要求，與規則 1 部分衝突。
- 已驗證：`skill-design-guide/references/chained-examples.md` 無「O3」編號；以〈驗證段機械檢查：依據句可溯性〉第 3 項（判定詞逐詞對照）作為「逐詞可推」的判準。草稿判準詞「無副作用」「合法業務狀態」「其他機制」在【輸入】中無法逐字出現，照原文落檔後範例仍會判「橋接」。
