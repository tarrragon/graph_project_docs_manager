## NeedsContext
兩則需新判準，草稿如下，停手交 WRAP（依 W3-417〈修補分工〉階段 2：不是用戶程式碼風格偏好的，不上呈用戶）：

**F-02（SKILL.md〈判定起點〉「可拆成逐畫面」判準）**
- **草稿**：一張全域狀態清單「可拆成逐畫面」的判準為——清單含至少一欄可用來把列分組為各畫面的獨立集合（如「畫面」欄，或欄位語意等價者）；不含此欄、且無法僅憑既有欄位重建分組者，判無規格。
- **觸發位置**：`SKILL.md`〈判定起點〉起點表第一列，範例〈全域狀態清單是否算「可拆成逐畫面」〉。
- **影響**：此判準決定「有規格」起點是否成立，屬三起點互斥判定的分岔點，錯判的代價見同節「判錯的代價高」段——一旦寫入條文即拘束後續所有專案的分類。
- **未寫入條文的理由**：清單分組除「具名畫面欄」外，是否應涵蓋其他等價線索（如隱含於狀態列命名前綴的分組）未經評估，屬新增判準而非既有內容的補完。
- **建議補料**：WRAP 評估是否收斂為單一判準（僅認具名欄）或開放式判準（欄位語意等價亦可），並確認與 `step-1-pick-starting-point.md` 既有起點判定邏輯無衝突。

**F-05（`step-2-path-b-canvas-decomposition.md`〈視覺單元盤點〉「可獨立辨識」判準）**
- **草稿**：視覺單元「可獨立辨識」的判準為——於畫布圖層樹中為獨立子圖層，且與相鄰單元之間標有間距（不與相鄰單元共用外框、亦非無間距標註的緊貼排列）。
- **觸發位置**：同檔步驟 1「逐畫面框出每個可獨立辨識的區塊」（本票已補「容器子件關係留待步驟 4 判定」半句，「可獨立辨識」本身的判準仍缺）。
- **影響**：此判準若寫死，會把現行「不預設同型、各自先列」的寬鬆盤點原則收斂為硬性規則，可能排除同層但無間距標註、僅靠顏色分色塊等情形。
- **未寫入條文的理由**：僅有範例（單一案例：圖示、標題文字、按鈕三者皆為獨立子圖層且各有間距標註）支持，未評估反例（無間距標註但仍可辨識的情形）是否也該算，屬新增判準。
- **建議補料**：WRAP 評估判準的收放範圍，並確認與步驟 3〈同型歸併〉「語意相同者歸併」規則的銜接（可獨立辨識是否為歸併前必要條件）。

**重派成本**：兩則皆為條文草稿定案，估計各需 1 輪 WRAP 評估（無需重新盤點範例或重跑探針）。
