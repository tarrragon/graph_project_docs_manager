### 風險 6 選邊說明（兩處都不加）

消費者範圍表第二列原含「跨 2+ domain 或跨層使用」，決策表第二題只問「是否被 2+ domain 使用」，
兩處條件不對稱。選擇移除消費者範圍表的「或跨層使用」子句（兩處都不加「跨層使用」判準），理由：
本節章首已改為「視覺 token 一律集中，不看消費者數量」，「跨層使用」原本作為視覺 token 的替代
觸發條件已被無條件集中規則涵蓋；消費者範圍表現在僅管純業務常數，而純業務常數的「跨層使用」在
本專案沒有已知實例場景（業務常數一般不獨立於 domain 之外被其他層直接消費，若真有此情境，其正確
處置是「該常數其實是視覺 token 或應收斂為 domain 公開介面」，屬另一個問題）；若反向選擇兩處都加，
決策表需新增「或跨層使用」子問，但「跨層」的判定依據（依 `domain-map-template.md` 依賴方向 DAG）
已在強制規則第 3 條為 import 禁令定義過一次，若決策表再引入同一詞彙用於不同語意（消費者範圍 vs
import 方向），會製造第二個需要辨義的「跨層」，複雜度增加且無對應的收益。
