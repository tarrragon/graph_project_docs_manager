## Problem Analysis
<!-- Schema[IMP/Problem Analysis]: 選填（小型 IMP 可留 placeholder；大型 IMP 建議填寫）（.claude/pm-rules/ticket-body-schema.md） -->
### 票面前提與現況落差

本票建立於 2026-08-27，描述「shell.dart 對六個目的地共用同一份無 trailing
的 SplitRow.header」。實測（2026-09-21）：`lib/app/shell.dart` 第 128 行起
已有 `trailing: switch (item)`，`AppDestination.domain` 與 `AppDestination.tickets`
已各自接線 `DomainHeaderTrailing`／`TicketsHeaderTrailing`（W2-001、W2-003
陸續建立），其餘四個目的地維持 `null`。掛點本身已存在，本票的實質工作是
把仍暫置於畫面內容區的兩個按鈕（破洞報告重新掃描、節點詳情開啟原始檔）
遷移到既有掛點，而非「新增掛點」。

### SPEC-004 §3.7 核定記錄比對

- 第 18 項（§5 破洞報告）：無破洞列 `EmptyState.page`（**無動作**）＋
  重新掃描 `AppButton.secondary` 於 `SplitRow.header` 右側 `ButtonRow`；
  有破洞列同樣把重新掃描鈕放在 header（`0.1.0-W3-335.37` R10：本項「涵蓋
  無破洞與有破洞兩狀態」）。
- 第 17 項（§6 節點詳情）：返回與開啟原始檔的 `AppButton` 於
  `SplitRow.header` 右側 `ButtonRow`；返回鍵已由 `components.AppShell` 的
  `returnTo` 機制單一渲染（與 per-screen trailing 無關），本票只需遷移
  開啟原始檔鈕。

### acceptance 措辭與現況的落差

原 acceptance「SplitRow.header 支援 per-screen trailing」措辭已不符
現況——支援本身已存在，本票只是新增兩個 case 分支並遷移按鈕。依指示不
為勾選遷就措辭，依 SPEC 執行；acceptance 措辭調整回報 PM。

### 發現的元件不變式衝突（已修正）

`lib/components/empty_state.dart` 的 `EmptyState.page` 變體有硬編碼
`assert(variant != EmptyStateVariant.page || actions.isNotEmpty)`，與
SPEC-004 §4.21「page 列舉狀態；無破洞與 section 例外」及本票要落地的
第 18 項（無破洞列 EmptyState 無動作）直接衝突——若不修正，移除無破洞列
的內容區按鈕會在元件建構期直接 assert 崩潰。依 quality-baseline 規則 3
（設計問題立即修正，不可延後）當場修正：新增 `actionsOptedOut`
（預設 `false`，明式標示才可繞過必填斷言），呼叫端（`_NoGapsView`）顯式
傳 `true`。此為既有共用元件的最小相容擴充，不影響其餘呼叫端（預設值
不變）。
