### 探針派發前的預先登記（2026-09-11）

**為何預先登記**：重點涵蓋度探針的判準是「作者意圖清單與讀者回報清單的差集」——讀者不知道自己漏了什麼，所以直接問「你讀懂了嗎」問不出來。分母若在看到回報之後才寫，會事後遷就成「他們講到的就是我要講的」，差集恆為空、這一批探針的產出歸零。故先固定下列清單。

**SKILL.md 的作者意圖清單（十項，batch B 差集的分母）**

1. 產物是一份 L3 元件庫規格，目的是讓畫面票只剩「選件與排位」
2. 判準的權威不在本 skill 而在方法論；產物形狀在 doc skill 範本；本 skill 承載的是程序
3. 先判定三種起點之一，判錯的代價高且在後續步驟不會自我暴露
4. 有三項前置（design token 層／形態因素矩陣／互動反應規格），缺料一律建前置票，不在本規格票內補
5. 時序：在 version-bootstrap 地基波第 3 塊之後、第 4 塊之前
6. 產出檔案的作法是複製範本到專案 spec 目錄，不是就地編輯源檔
7. 七份 references 各有觸發條件，依所在步驟按需讀
8. 契約齊全有六條判準，且六條都是可機械執行的存在性檢查
9. 三條路徑（模式 C／矩陣待簽核／最小適用集）上六條不全部適用，各有替代判準
10. 契約先於實作指「改動先落在契約」，不指契約不可變

**派發前已量到的一項結構事實（與探針獨立，不進差集）**

## 重現實驗結果
### 實驗設計與可重現配方

本票的量測即實驗。三批探針的完整回報彙整與歸因在 Problem Analysis，此處只記可重現的配方與環境。

**配方**（依 multi-round-review 的 2-B4 frame）：

1. 派發前先把「作者意圖清單」寫進票面（本票 Problem Analysis〈探針派發前的預先登記〉）。分母必須在看到回報之前固定，否則差集會事後遷就成空集。
2. 每批 N 份低階 model（Haiku）實例，互不通訊，**批內指令逐字相同、餵入範圍逐字相同**。
3. 指令四項硬條件：不給審查框架（問「你讀到什麼」不問「這寫得好不好」）、明令標記不確定且禁止推測填平、問理解不問評價、判斷標準是份與份之間的分布不是任一份的結論。
4. 規則類文件另加一欄：「照這一節工作，我的第一個具體動作是什麼——寫出你會打開的檔案、會執行的命令，或會產生的第一個東西；找不到就直接說找不到。」
5. 批與批之間問法或範圍不同即為不同批，**不互相比對**。

**本次三批的參數**：A 批 4 份餵 `SKILL.md`（理解正確性、指涉詞、第一個具體動作、路由涵蓋）；B 批 3 份餵 `SKILL.md`（重點涵蓋度、只能記住三件事、閱讀負擔、語氣與讀者定位）；C 批 3 份餵 `references/modes-a-b.md`（可執行性、整體感知、缺料自覺、下一步）。

**歸因程序**（每一份回報都要跑，不可省）：先在原文 grep 該讀法對應的字串——找得到逐字對應即「文章自己這樣寫的」；找不到而現有材料足以推出該讀法即「表述有歧義」；材料足以排除該讀法才是「模型的問題」，且歸這一類必須把排除材料引出來。

**處置規則**：一份讀錯就是判決，收斂度只決定證據強度不決定要不要修。

### 觀測到的執行細節（供下次派同型探針參考）

- 十份中三份的回報超過訊息長度上限被截斷，需以 SendMessage 要求重送指定題號。**下次派發時應在指令中限制回報長度或分題派發**，例如指定「每題至多 N 項」。
- 明令「禁止推測填平」擋不住填平：「後四列」一題四份中三份填了答案，其中一份自造了原文不存在的分類理由。**這不是指令失效，是可用訊號**——三份獨立收斂到同一個錯誤答案，指出的是原表把兩種性質的列混在一起。
- 「第一個具體動作」欄的產出價值最高：其餘各欄 4/4 全對，唯此欄 3/4 回「找不到可打開的東西」。

## Solution
<!-- Schema[ANA/Solution]: 必填（.claude/pm-rules/ticket-body-schema.md） -->
### 結論

三批共十份低階 model 讀者探針全數回報，判決七項、待驗假設一項、重點涵蓋度差集一項。逐項歸因與依據見 Problem Analysis 的〈探針回報彙整與歸因〉表，此處不重述。

### 三項最強訊號（依證據強度排序）

1. **`modes-a-b.md` 的讀者看不到模式 C**——C 批 3/3 全體一致，且 grep 確認為文章自己這樣寫的（七份檔頭〈同目錄〉互指矩陣中唯一漏列的一格）。全體一致加原文可 grep，是本次證據強度最高的一項。
2. **分工句 3/3 全漏**——「判準權威在方法論／產物形狀在範本／本 skill 承載程序」無一份帶走；「只能記住三件事」的三份交集只有起點判錯的代價與契約齊全六條，**無一份帶走產物是什麼、放在哪**。此項靠差集才量得到——直接問「你讀懂了嗎」問不出來，因為讀者不知道自己漏了什麼。
3. **第 29 行例外段的兩批交會**——B 批 2/3 想跳過、A 批 1 份列為「不確定為什麼要出現在這裡」。兩批問法不同、批次不同，收斂到同一段落。

### 方法層面值得記的三點

- **歸因先於處置不可省。** 三份一致漏掉 mode-c 時，「讀者讀錯了」這個結論順到不需要查證，而查證成本只是一條 grep——grep 下去發現是文章自己這樣寫的。若跳過這一步，會把一個文件缺陷記成模型能力不足而結案。
- **禁止推測填平的指令擋不住填平。** 「後四列」一題，四份中三份填了答案且獨立地排除同一列，其中一份自造了原文不存在的分類理由（「addresses.md 為獨立的簡稱查詢工具」）。這反而是有用的訊號：三份獨立收斂到同一個錯誤答案，說明該表把兩種性質的列混在一起，只改數字解決不了。
- **規則類文件的「第一個具體動作」欄單獨產出最高價值 finding。** 其餘各欄（逐節在講什麼、其他檔案與觸發條件）4/4 全對，唯獨這一欄 3/4 回「找不到可打開的東西」、第 4 份給出完全不同的一組動作。讀懂與執行得出來是兩回事。
