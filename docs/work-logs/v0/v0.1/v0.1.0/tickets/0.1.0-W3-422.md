### 階段 2 草稿（D-12a、D-12b，草稿即停手，不改檔，非用戶程式碼風格偏好不上呈用戶）

來源：`doc-handoff.md`〈前置閘門〉「UC 主成功場景非空」「畫面狀態矩陣（涉及 UI 時）」兩檢查項，其判定細節目前只見於〈前置閘門判定範例〉的【產出】／【驗證】圍欄內（範例內圍欄依 W3-417 PM 定義裁決 2 第三款不算條文），條文本身（前置閘門表格列）未寫明。逐 grep 全 skill 確認 `doc-handoff-uc-to-gwt-conversion.md`、`doc-handoff-test-tier-assignment.md`、`bdd-behavior-testing.md` 均無同義判準，非漏找而是真缺口。

**D-12a 草稿判準**：UC 主成功場景步驟須同時具備「動作」（使用者或系統操作的描述）與「預期結果」（可觀察的回應或狀態變更）兩者，方視為完整場景步驟，計入前置閘門「至少 1 個完整場景步驟」；僅有動作或僅有結果、或整句籠統敘述而未拆出兩者的步驟，不計入。

**會改變哪些判定**：目前前置閘門表格只寫「UC 有至少 1 個完整場景步驟」，未定義「完整」的判準，執行者需自行推斷。草稿落地後會使部分現行判為「通過」的 UC（步驟僅隱含動作或結果、未逐句拆開）改判為「不通過」，回 doc 端補場景步驟——影響既有 UC 文件的前置閘門判定結果，屬新增判準而非既有條文引用。

**D-12b 草稿判準**：場景步驟只要包含使用者操作，即判定「涉及 UI」，觸發「畫面狀態矩陣（涉及 UI 時）」檢查項；不以「本次是否新增或改動畫面」作為排除或降低檢查等級的理由。

**會改變哪些判定**：目前「涉及 UI」檢查項的觸發時機無明文條件，執行者可能誤以為只有新增/改動畫面的功能才需要畫面狀態矩陣。草稿落地後，任何含使用者操作步驟的 UC（即使操作對象是既有畫面、未新增或改動畫面）都須補畫面狀態矩陣，可能新增此前被視為「不涉及 UI」而跳過此檢查的 UC 的補件負擔——屬新增判準，範圍擴大，非既有條文引用。

**處置**：兩則草稿均不改動 `doc-handoff.md` 或任何 skill 檔案，停手交後續 WRAP 評估是否採用、範圍是否需收斂（如是否排除純系統自動觸發、無使用者互動的步驟）。
