## Solution
<!-- Schema[IMP/Solution]: 選填（.claude/pm-rules/ticket-body-schema.md） -->
建立 `lib/tokens/` 三檔（colors.dart / spacing.dart / typography.dart），三層命名（原始值層 `_Palette` 私有 / 語意層 `AppColors` 公開 / 元件層留待後續票依 SPEC-002 定義）。

**顏色**：依 SPEC-002 分佈表萃取 17 個原始值，語意層 17 個名字逐一回溯。針對「四個表面層次色是否真需要四階」的既定疑問，逐色 grep 上下文確認：四色分別是側欄背景 `F4F6F5`、圖示容器底 `E0EFED`、徽章底 `E9EEED`、分段控制軌道底 `DCE4E2`——是四個互不相關的元件角色而非同一序列的四階明度，故四階皆保留但命名避開暗示線性層級的 `surface1/2/3/4`。

**間距／圓角**：實測 `design/*.dc.html` 得 padding/gap 原始值 15 種（1-10、12、14、16、18、20，非 SPEC-002 文件表列的 7 種），依集中程度歸納為 6 階（xxs=2/xs=4/sm=8/md=12/lg=16/xl=20），映射表記於檔頭 doc comment。圓角實測 8 種（4-9、11、12，非文件表列 3 種），歸納為 3 階（sm=6/md=8/lg=12）。

**字級**：實測 8 種（9-15、19，非文件表列 7 種），歸納為 4 階（caption=10/body=12/subtitle=14/title=19）。

**與 SPEC-002 文件的落差**：三個分佈表（顏色／字級／尺寸）皆與文件記載有出入（詳 NeedsContext），依 SPEC-002 自身的設計約束「兩者不符時以 artboard 為準並更新本規格」，token 定義採 artboard 實測值；文件回填另需 PM 處理（不在本票 where.files）。

**FR-01 驗證**：`lib/` 下除 `lib/tokens/`、`lib/l10n/`（生成產物）外，僅 `lib/main.dart:58` 有一處既有裸色碼（`colorSchemeSeed: const Color(0xFF2E6F6A)`），非本票 where.files 範圍，未修改，已記於 NeedsContext 供後續票處理。

**Phase 4（規則 2 強制）**：本票為純新增 token 定義，無既有邏輯可重構；三檔皆為常數宣告，無分支/巢狀/重複結構。結論：無需重構，程式碼品質 A（`dart analyze` 0 issues，命名遵循 SPEC-002 三層原則，每個裸值皆有 `color-exempt`/`magic-exempt` 標記並附出現次數註解）。
