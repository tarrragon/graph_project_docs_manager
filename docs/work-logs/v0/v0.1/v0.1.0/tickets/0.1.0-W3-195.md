### Task Reference

- 0.1.0-W3-194 what: 新增 acceptance-gate-hook 的 per-section 選填章節模板殘留 WARNING

### Rationale Chain
- 0.1.0-W3-137 why: `0.1.0-W3-087` 已讓 `dispatch-validate` 規則 4b 擋下 acceptance 的未填樣板，但**選填章節（Problem Analysis 等）留存樣板仍然完全無訊號**。

**實證**（記於 087 的 why 段）：`0.1.0-W3-082` 完成時 Problem Analysis 仍是未動的樣板，而執行代理人回報稱已在該處更正描述。兩者矛盾，但沒有任何機制會發聲——選填章節不受 acceptance-gate 檢查，樣板留存不產生訊號。

**「選填」的語意是「可以不填」，不是「可以留樣板」。**兩者現在無法區分：空白與樣板在 schema 檢查上同樣通過，但對讀者的意義完全相反——空白誠實地表示沒有內容，樣板則看起來像有內容。這與 087 修的 acceptance 樣板是同一個形態（`PC-GPD-008`：看起來像真的驗收條件，只有大括號洩漏），只是載體從逐項清單換成自由文字。

**與 087 的兩項差異，是本票獨立存在的理由**：

1. **檢查點不同**：acceptance 樣板擋在派發前（`dispatch-validate`，CLI）；選填章節樣板若要擋，時機在 complete 前（`acceptance-gate-hook`）。兩者是不同的執行時機與不同的承載體。
2. **判準難度不同**：acceptance 是逐項清單，可與建立端 `DEFAULT_ACCEPTANCE_CRITERIA` 逐字比對；選填章節是自由文字，樣板與真實內容的邊界模糊（部分填寫、改寫後保留樣板句式等中間態），逐字比對不足。

本票要評估的正是第 2 點——**判準是否存在、可靠度如何、誤報成本多少**，而非直接實作。
- 0.1.0-W3-194 why: `0.1.0-W3-137` 實測：**35% 的已完成 ticket 含選填章節模板殘留**（IMP 的 Problem Analysis 35%、DOC 的 Problem Analysis 56%、ANA 的 Test Results 50%）。

**留著樣板比留空更糟**：空白章節一眼可見沒填；留著「（選填：問題如何發現？直接原因是什麼？）」則在版面上與已填內容同形，讀者需逐字讀完才發現裡面沒有資訊。接手者掃過章節標題與段落結構後，會合理認為該處已有內容。

偵測基礎設施已就緒——`_is_section_empty` 的四層剝除能正確判定現有全部模板形態為空殼，缺口只在編排層沒有呼叫它。實作成本因此落在接線，不在偵測邏輯。

本票採 WARNING 不阻擋：選填章節本就允許不填，強制攔截會提高 complete 門檻而收益不明。目標是讓填了樣板等於沒填這件事在 complete 當下可見，由執行者自行判斷是刪掉樣板還是補內容。
