### V2a 的門檻檢討：漏答與誤讀被我綁在同一個標準，那是訂錯

形式上未達門檻（1/3 漏）。但趨勢與性質都變了：**讀反歸零、漏答從 3 降到 1**，由「無人帶走」變成「多數帶走且無人讀錯」。

那一份漏答的重點清單有十項且皆為實質內容——**清單有上限，滿額清單上漏一項不等於沒讀到**。誤讀是判決（讀者會照錯的做），漏答只是壓縮時的取捨；我訂門檻時把兩者綁成一個標準，使一個實質已解的項目被判成未生效。

**處置**：V2a 的文字不再改（已改三次，第三次讓 2/3 帶走且零誤讀）。門檻定義修正為往後這類量測**誤讀與漏答分開訂**——誤讀門檻 0/N 為硬條件，漏答只在「多數漏」時才視為訊號。此修正記入本票，供後續批次沿用。

### 疲勞點：搬離 token 估算區，落在 1.12.0 新增的段落

| 輪次 | 落點 |

三份理由高度一致：「層層推敲『何時拆檔案 vs 拆 skill』同一個概念，讀起來很密集」「文字緊密、句型反複在層級與拆分判準間往返，每句都帶新概念而前文未充分推導」「同時講為什麼不能某種拆法和應該怎樣拆，反向論述難以追蹤」。

那四段是 1.12.0 新增、1.12.1 補強的。**連續兩版都是修掉一個疲勞點、在新增的內容上長出新的。** 處置：四段散文改為一段加一張兩列對照表（什麼時候／做什麼／判錯的代價），交錯的正反論述收進表格欄位。

### 我又犯了自己同批新增的規則（第二次）

1.12.0 在必查項表新增「**用詞定義與用詞使用分屬兩檔**」一列。而我新增那張表時，把「**兄弟檔互指矩陣**」「**層級混疊**」兩個詞直接當列名用，**未就地定義**——C 批 2/3 有障礙（一份判「沒有定義，直接使用」，另一份說該列「需讀兩遍才懂」且「只描述現象無範例」）。

這與前一輪的〈位置性指涉〉同型：**補規則的那一次修改本身違反該規則**，已是第二次。機制相同——犯它的是編輯動作（新增列名時圖簡潔），而讀規則時想的是撰寫動作。處置：兩個詞在列名後就地加一句括號定義。
