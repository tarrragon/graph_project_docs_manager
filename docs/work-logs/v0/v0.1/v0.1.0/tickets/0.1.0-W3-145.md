### 條數判定：逐項問「既有 FR 是否涵蓋」與「能否合併」

§2.12 的規範主張拆為四項，逐項判定結果為**四項皆需新條、兩兩皆不可合併**，
另有一項既有條目已涵蓋不重複立。

| # | §2.12 的規範主張 | 既有 FR 是否涵蓋 | 判定 |
|---|-----------------|-----------------|------|
| A | 第一層回饋的無條件性（INV-FEEDBACK-001） | 否。FR-06 的驗收為「點擊皆產生狀態錨點改變／`IndexedStack` 索引改變／SnackBar／外部程序被呼叫之一」，四種結果全部預設服務會回應；服務永不受理的元件依 FR-06 會被判違反，但那是第二三層失落，第一層是否出現 FR-06 量不到。FR-07 管進度值誠實 | 新增 FR-12 |
| B | 逐服務類型的回饋形式 | 否。FR-01 管退出路徑錨點存在性，非依服務類型的回饋供給；FR-06 對短暫非同步無鑑別力——外部開啟只要「外部程序被呼叫」即滿足 FR-06 的四選一，即使完全不出 SnackBar 亦不違反，故失敗路徑（`externalOpenFailedMessage`）缺漏 FR-06 抓不到；FR-07 只在進度指示已出現時管其值 | 新增 FR-13 |
| C | 逐服務類型的輸入阻擋範圍 | 否。FR-02 的十條講取消錨點與目標態，不講載入態期間正常態元素是否仍可互動，亦不講導覽列必須不被擋 | 新增 FR-14 |
| D | 重複觸發防護的承擔者為服務 | 否。FR-05 管時間值具名（`Motion.searchDebounce` 已具名），不管誰消費它 | 新增 FR-15 |
| E | 阻擋頁面內容時必須同時提供取消 | 是。`0.1.0-W3-105` 已判定由 FR-02（§2.5 C1–C8 與 §2.8 L1–L2）滿足 | 不另立，標明歸屬 |

### 合併判定（為何不收斂為更少條）

| 候選合併 | 判定 | 依據 |
|---------|------|------|
| A + D（第一層無條件性 + 防抖承擔者） | 不合併 | 兩者可獨立失效：服務層外的第三方元件做防抖但仍給 ripple（A 過 D 敗）；服務做防抖但元件因 disabled 而無 ripple（D 過 A 敗）。且驗收的觀察形式不同——A 是行為斷言（注入替身後斷言 pressed 視覺），D 含靜態原始碼掃描（`lib/components/` 不出現 `Timer(`）。合併會使單一條目的驗收敘述橫跨兩種觀察形式，違反 §撰寫判準「可執行斷言」的粒度 |
| B + C（回饋形式 + 阻擋範圍） | 不合併 | `0.1.0-W3-105` 已明寫「提示是告知，阻擋是防止，兩者是兩件事」。可獨立失效：有載入態但不擋輸入；擋了輸入但無任何回饋。觀察量不同（回饋錨點存在性 vs 其他錨點的存在與 `enabled`） |
| B + C + D 合為一條「§2.12 政策對照表全部成立」 | 不合併 | FR-11 有「表格全部成立」的先例，但該表是**測試斷言表**（情境 \| 斷言）。§2.12 的政策對照表是**政策表**，格內是「不阻擋」「冪等」這類政策值而非斷言——直接委派會產生無法執行的驗收敘述（「冪等」要斷言什麼未被指定）。每一軸須各自給出斷言形態，故分立 |
