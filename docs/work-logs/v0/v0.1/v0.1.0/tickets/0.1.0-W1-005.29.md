## Problem Analysis

### 問題根因
SPEC-004 4.26 AppSnackBar 契約已齊，尚未建立實作。

### 影響範圍
`lib/components/app_snack_bar.dart`（新檔）、`lib/components/components.dart`（追加 export 一行）、`test/unit/components/app_snack_bar_test.dart`（新檔）。

### WRAP 三問
W（候選方案）：(1) 用 Material 內建 `SnackBar.action`（`SnackBarAction`）承接動作 slot；(2) 自組 `content` Row（文字 + 自訂動作按鈕）。採 (2)：`SnackBarAction` 的 `Text(label)` 無 `maxLines`/`overflow` 設定，無法承接契約「動作 label 超出處置：截斷」，實測 `TestCopy.longToken`（不可斷詞長 token）會使 Row 溢位 793px。
A（機會成本）：無其他票排隊，機會成本低。
P（最可能失敗點）：SnackBar 進出動畫的 widget test 計時斷言——`flutter_test` fake clock 對 Timer + AnimationController 驅動的元件，單次大跳躍 pump 無法可靠捕捉 Timer 觸發時機，需以 <=100ms 小步距反覆 pump（已驗證並實作 `_pumpBy` helper）。

## Solution
<!-- Schema[IMP/Solution]: 選填（.claude/pm-rules/ticket-body-schema.md） -->
### 實作摘要
`AppSnackBar` 為靜態入口類別（`abstract final class`），非渲染進 widget tree 的元件——依組合規則「不放入任何容器，經 ScaffoldMessenger 顯示於主區覆蓋層」，呼叫端以 `AppSnackBar.show(context, ...)` 觸發。

- `plain` / `withAction` 兩變體，停留時間分別引用 `Motion.snackBar` / `Motion.snackBarWithAction` token（非字面值）。
- `content` 自組 `Row`（`Flexible` 分配 message / 動作 slot 寬度），不使用 Material 內建 `SnackBarAction`——其 `Text(label)` 無 overflow 設定，無法承接「動作 label 單行、超出截斷」的內容政策；自訂 `_SnackBarActionLabel`（`InkWell` + 單行 `Text(overflow: ellipsis)`，`Semantics(button: true)`）補上此契約，並保留「動作只可觸發一次」的 Material 慣例。
- 動作點選：呼叫 `onAction()` 後手動 `messenger.hideCurrentSnackBar(reason: action)`，等同 Material 內建行為（`SnackBar 即時消失`）。
- 新的 SnackBar 呼叫 `show` 時先 `hideCurrentSnackBar()` 取代目前顯示者（狀態矩陣退出路徑）。
- 全部尺寸／間距／色彩／圓角取自 `lib/tokens/`，零裸值。

### 與契約的差異
無——十一欄位（用途、內容角色、何時不用、變體、狀態矩陣、互動反應、操作機制、尺寸契約、內容政策、slot 契約、token/i18n/組合規則/無障礙/測試點/反例）皆依 SPEC-004 4.26 原文實作，契約值實測皆成立，未修改 SPEC-004。
