## Problem Analysis
### 問題根因

W3-472 修 doc 第 5 批讀歪點時，DOC-19a（組合規則「作為表格或列表一欄時」可否填內距）因查無非範例出處未落檔，轉草稿交本票評估。

**事實更正（本票查證）**：W3-472 NeedsContext 記「該定義原僅存在於已刪範例（commit 4aec4afc5 引入，後續風險 13 清理時移除）」。實測 HEAD 該範例仍在，未被移除——`git grep -Fn "內距是元件邊界內部的空間" HEAD -- .claude` 命中 `.claude/skills/doc/examples/component-library-chained-examples.md:601`，節名〈組合規則「作為表格或列表一欄時」內距與「不得另定間距」的分界〉亦仍在（第 577 行），範本第 357 行的範例路由句指得到，非斷鏈。正確描述是 W3-417 既有的風險類別「依據只在範例內」，不是「依據已被刪除」。兩者處置相反：前者把既有依據提升為條文（範例留作示範），後者要重新起草依據。本票依前者辦理。

三份探針答案的形態（`probes/a/W3-417-b5-doc-2-r{1,2,3}.md`）：r2、r3 引 S3 判 (a) 不可；r1 判 (a) 可，但其「自行假設」欄自承「內距（padding）指欄內容與邊界之間的距離，與『與鄰件的間距』屬不同概念」——答對的那一份是靠自備分界，不是靠條文。

### 實驗發現

**已驗證事實**

1. 分界的兩個前提在非範例條文中都有出處：容器管的是兩個元件之間（S1、S2），內距無排列關係且歸子件組合規則或容器格位（S4、S5）。
2. 沒有任何一處把這兩個前提合寫成「內距 vs 鄰件間距」的分界句；唯一合寫的位置是範例檔（S8）。
3. DOC-19a 那一題的具體失敗結構（允許句只在佔位符內）已於 W3-469 消除：現行引言 S7 直接允許欄內距，探針只讀現行引言即可答 (a) 可。
4. W3-472 NeedsContext 的「已刪範例」為誤述，S8 於 HEAD 仍在。
5. S4 的句子主詞是「單一子件的包裝」，位在容器候選盤點步驟內；讀者為了填組合規則而翻方法論或範本時，不會走到該句。分界可推得，但推得它的前提散在三份檔案的三個不同用途段落。

**仍未驗證的假設**

- 改文後探針是否 3/3 通過——本票未重跑探針。
- 除表格欄外的其他內距情形（元件與容器邊緣、元件內部兩處內容之間）在實際填寫時的出現頻率，無資料。
