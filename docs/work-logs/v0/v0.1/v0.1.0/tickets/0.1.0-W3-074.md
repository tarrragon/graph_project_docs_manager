## Task Summary

決策 跨 app 邊界功能的驗證層：雙層測試策略是否加第三類，及各功能的驗證形態

---

## Problem Analysis
### 問題根因

五層分工表（`layered-test-strategy.md`）以架構層級為唯一軸，隱含假設為「每格指定的測試方法對該層所有功能有效」。跨 app 邊界的功能（MethodChannel 呼叫、外部 process 執行、系統資料夾選擇器）落在表上有位置（Layer 1 整合測試），但該格的方法做不到——`integration_test` 無頭執行觸不到系統權限對話框、通知中心、原生檔案選擇器、真實 process。表上有位置、方法無效、無條文說明此情形，讀者依表執行會得到「已覆蓋」的假象。

### 影響範圍

**框架層**：`layered-test-strategy.md`（121 行）、`doc-handoff.md` 的整合 vs 單元分工判斷原則（「自己決定或串接決定」二分，跨邊界屬第三種「平台決定」）。

**專案層**：三個呼叫點——
1. `lib/services/macos_scan_notifier.dart`：`UNUserNotificationCenter` MethodChannel，現有 fake only
2. `lib/workspace/workspace_repository.dart`：`file_selector` 系統資料夾選擇器 + `SharedPreferences` 持久化，現有 fake only
3. `lib/screens/gap_report/gap_report_screen.dart`：`Process.run('open', ...)` 外部開啟，現有 fake only

### 相關 Error Pattern

無直接相關的已知 error pattern。最接近的是 PC-165（false positive fix chain：測試綠燈不等於 runtime 正確），但該 pattern 聚焦 mock 替代真實依賴的遮蔽效應，本票聚焦的是分類表缺軸導致的系統性盲區。

## 重現實驗結果
### 實驗方法

本票為分類分析而非 bug 修復，「重現」的對象是分類表的缺口而非程式錯誤。方法：
1. 逐格檢視五層分工表，對每格問「這格指定的測試方法，對落在此層的所有功能都有效嗎？」
2. 對三個跨邊界呼叫點，嘗試以該格方法覆蓋，記錄哪些平台事實無法被自動化測試觸及
3. 檢視 `doc-handoff.md` 的分工判斷原則，驗證跨邊界功能是否被涵蓋

### 實驗執行

**五層分工表逐格檢查**：

| Layer | 測試方法 | 對跨邊界功能是否有效 | 原因 |
|-------|---------|-------------------|------|
| 1 UI/Presentation | 整合測試 | 部分有效 | `integration_test` 可驗證 UI 狀態轉換與 fake 注入，但觸不到真實平台 API |
| 2 Application/Behavior | 條件單元測試 | 有效 | 轉換邏輯可 fake 測試 |
| 3 UseCase | BDD 測試 | 有效 | 業務場景可 fake 測試 |
| 4 Interface | 不測試 | N/A | 介面定義 |
| 5 Domain | 單元測試 | 有效 | 業務規則可 fake 測試 |

結論：Layer 2-5 的方法對跨邊界功能有效（因為它們測的是 fake 注入後的應用邏輯）。缺口在 Layer 1：該格說「整合測試」，但真正的平台行為（權限對話框、通知中心、系統檔案選擇器、外部 process）在 `integration_test` 裡觸不到。

**doc-handoff 分工原則檢查**：
- 「自己決定」→ 單元測試：跨邊界功能的 App 端邏輯（如「granted 時發通知、denied 時走 fallback」）屬此類
- 「串接決定」→ 整合測試：跨邊界功能的 fake 注入後端到端流程屬此類
- **缺第三類**：「平台決定」——平台 API 本身是否可用、行為是否如預期，兩個分類都不涵蓋

**三個呼叫點的未驗證平台事實**：

| 呼叫點 | 可 fake 驗證的 | 不可 fake 驗證的平台事實 |
|--------|--------------|----------------------|
| `MacosScanNotifier` | 權限三路徑邏輯、發送/撤回呼叫次數、fallback 流程 | `UNUserNotificationCenter` 在沙盒關閉下的可用性、MethodChannel 實際能呼叫原生端、macOS `AppLifecycleState` 對應關係、撤回 API 行為 |
| `WorkspaceRepository` | 狀態轉換邏輯、路徑持久化邏輯 | `file_selector` 系統對話框能否彈出、`SharedPreferences` 跨啟動持久化、路徑是否可讀 |
| `GapReportScreen` | 外部開啟觸發邏輯、SnackBar 回饋 | `Process.run('/usr/bin/open', ...)` 的 exit code 語意、不存在路徑的 stderr 內容 |

### 實驗發現

1. **跨邊界不是表上的空位，而是表上每格都有但方法不完整的那一類**——Layer 1 有位置、Layer 2-5 各自有效的部分（App 端邏輯），但「平台端行為」在所有格都是盲區。
2. **doc-handoff 的二分判斷原則缺第三類「平台決定」**，此類的正確性既不由 App 自己決定，也不由 App 內部串接決定。
3. **三個呼叫點的驗證現狀完全一致**：App 端邏輯已有 fake 測試覆蓋，平台端行為零覆蓋。SPEC-003 §2.2 已明文標出四項平台事實待實機確認。
