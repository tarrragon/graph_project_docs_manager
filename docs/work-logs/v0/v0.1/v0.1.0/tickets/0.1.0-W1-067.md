TwoColumnLayout main/detail 收窄（AC1）：實作後 dart analyze 揭露 5 處呼叫點編譯失敗
（domain_view_screen.dart 1 處、uc_flow_screen.dart 3 處嵌套於 _UcSelectorPanel），
但深入排查發現 domain_view_screen.dart 的 _CellDetailPanel 存在架構性阻礙，非機械改
型別可解：

- _CellDetailPanel 目前是獨立 ConsumerWidget，其自身的 Key（依 domainId/ucId 動態產生，
  如 `panel-domain-cell-detail-A-B`）是 TwoColumnLayout 內 AnimatedSwitcher 判斷「換件觸發
  cross-fade」的識別鍵（Widget.canUpdate 比對 runtimeType + key）
- 該 widget build() 內部回傳的 Panel.scrollable 另有一個固定測試定址鍵
  `panel-domain-cell-detail`（test/unit/screens/domain_view_test.dart 多處 find.byKey 依此）
- 若將 detail 型別收窄為 Panel，_CellDetailPanel 必須被攤平為單一 Panel 物件，此時「換場
  觸發用的動態 Key」與「測試定址用的固定 Key」無法同時存在於同一個 widget 的單一 key 欄位
  ——攤平後若採固定鍵，換選格子時 AnimatedSwitcher 不再觸發 cross-fade（行為回歸）；若採
  動態鍵，既有測試的 find.byKey('panel-domain-cell-detail') 全數失效

此為需要架構決策的識別鍵設計問題（哪一層該承載換場語意、哪一層該承載測試定址語意），
非本票（Flutter 元件層收窄）範圍可單方裁決，且涉及檔案（domain_view_screen.dart、
uc_flow_screen.dart）不在 where.files 內。已將 main/detail 型別維持 Widget，於 dartdoc
記錄實測阻礙與具體位置，供後續票承接。
