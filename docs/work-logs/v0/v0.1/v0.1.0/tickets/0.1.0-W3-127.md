### 問題根因

`AppShell`（`lib/app/shell.dart`）已為六個導覽項各建一個 `PageColumn`（頁首
`SplitRow.header` + 內容 slot 由 `buildDestinationPage` 填），但
`TraceabilityScreen.build`（`lib/screens/trace/trace_screen.dart`）自己又回傳
一個 `PageColumn`，被塞進外層 `PageColumn` 的 content slot，形成巢狀，違反
SPEC-004 §4.28 slot 契約（`content` 只接受 `Panel` / `Panel.scrollable` /
`TwoColumnLayout` / `EmptyState.page` / `BlockedState` / `LoadingState` /
`LoadPrompt` / `MissingSourceState`，不含 `PageColumn`）。

### 修法

`TraceabilityScreen.build` 移除自建的 `PageColumn` 外殼，直接回傳 switch
表達式的結果（`_TraceTree`（Panel.scrollable）或
`EmptyState(variant: EmptyStateVariant.page, ...)`），與 `GapReportScreen`
同形態。頁首（`semanticLabel` / `header`）改由 `AppShell` 單一持有，畫面不再
自持這兩項。

### 補的紅燈斷言

`test/widget/app/shell_test.dart` 新增「AppShell 元件樹下 PageColumn 數量
等於導覽項數」：對象是**數量**（`find.byType(components.PageColumn,
skipOffstage: false)` 命中數 == `AppDestination.values.length`），不是某一
畫面的外觀——其他畫面日後若出現同型巢狀，此斷言同樣能攔截。修復前實測 7、
預期 6，紅燈；修復後綠燈。

### 內距疊加症狀確認

內距疊成 40（雙層 `Space.xl`）是雙頁首巢狀的症狀，非獨立缺陷。移除巢狀後
`0.1.0-W3-095` 既有的「六個畫面的頁首標題左緣與頁面容器左緣距離皆為
Space.xl」斷言直接綠燈，未另外調整內距程式碼，確認症狀隨根因修復自動消失。
