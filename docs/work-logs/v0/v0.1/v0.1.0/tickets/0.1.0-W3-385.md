修正 .claude/config/dart-style-guardian.json 的 tokens 四個類別名，改為與 lib/tokens/ 實際類別一致（AppColors/Space/AppFontSize/Radius），或確認命名差異是刻意設計並記錄理由

## Problem Analysis
<!-- Schema[IMP/Problem Analysis]: 選填（小型 IMP 可留 placeholder；大型 IMP 建議填寫）（.claude/pm-rules/ticket-body-schema.md） -->
Baseline（修正前）：`style_checker.py scan lib/` — Files scanned: 75, Total violations: 18，全數為 Color 類別（均在 lib/tokens/colors.dart，_Palette 定義區塊本身的 hex 常數，屬 token 定義檔本身，非誤用）。

實際類別名（以原始碼確認）：
- lib/tokens/colors.dart:86 `abstract final class AppColors`（config 原記 AppPalette，不符）
- lib/tokens/spacing.dart:29 `abstract final class Space`（config 原記 AppSpacing，不符）
- lib/tokens/spacing.dart:39 `abstract final class Radius`（config 原記 AppRadius，不符）
- lib/tokens/typography.dart:29 `abstract final class AppFontSize`（config 原記 AppTypography，不符）

build_exception_patterns 用 `re.escape(name) + r'\.'` 對整行做 re.search（無錨定），`Space.lg.w`／`Radius.md.r` 等 `.w`/`.h`/`.sp`/`.r` 尾綴用法皆可被含 `Token.` 子字串匹配命中，不需修改 checker。

## Solution
<!-- Schema[IMP/Solution]: 選填（.claude/pm-rules/ticket-body-schema.md） -->
修正 `.claude/config/dart-style-guardian.json` 的 `tokens` 四個類別名：color AppPalette→AppColors、spacing AppSpacing→Space、font_size AppTypography→AppFontSize、border_radius AppRadius→Radius。僅改 config，checker 程式與 lib/ 未動。

修正後（after）：`style_checker.py scan lib/` — Files scanned: 75, Total violations: 18（與 baseline 完全相同）。經逐一比對，本專案 lib/ 現有程式碼中所有 token 用法（`Space.md.w`、`Radius.md.r`、`AppFontSize.md.sp`、`AppColors.primary` 等）皆不含數字字面值，而各類別的違規正則（EdgeInsets/SizedBox/FontSize/BorderRadius）本身要求匹配 `\d+`，故 token 表達式在修正前後都不會落入任何違規正則、也不需要靠 exception pattern 排除——本次修正對現行 lib/ 的計數無影響，18 件違規（皆 lib/tokens/colors.dart 內 `_Palette` 定義區塊的 hex 常數，屬 token 定義檔本身）修正前後一致。

抽樣驗證改用合成輸入直接測試 `build_exception_patterns`／`should_skip_line`（因 lib/ 現況無「原本被報現在不報」的真實行可抽樣）：
- `EdgeInsets.symmetric(horizontal: Space.lg.w, vertical: 8)` → 修正後 `Space.` 匹配，該行被判定 exempt（should_skip_line=True）
- `AppColors.primary` → 修正後 `AppColors.` 匹配，exempt=True
- `BorderRadius.circular(Radius.md.r)` → 修正後 `Radius.` 匹配，exempt=True（`BorderRadius.` 子字串本身亦含 `Radius.`，但因該行確實使用 `Radius.md.r` token，非誤判）
- E2 對照（守衛仍能抓真違規）：`EdgeInsets.all(16)` → 不含任何 token 類別字串，should_skip_line=False，仍會被判定違規

修正前（AppPalette/AppSpacing/AppTypography/AppRadius）上述三個 token 用法皆不會被 exception pattern 匹配（因類別名不符），但因這些行本身也不含數字字面值故不影響 lib/ 的實際計數；差異僅在「若未來程式碼把 token 表達式與硬編碼字面值混在同一行」時才會顯現（exception pattern 命中會使整行豁免，含混入的硬編碼也一併豁免——此為既有機制的已知行為，非本票範圍）。
