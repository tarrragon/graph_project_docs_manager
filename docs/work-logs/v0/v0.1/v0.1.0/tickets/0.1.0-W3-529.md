**DOC-19a**（b6 版，狀態標籤元件放進工單清單作為清單列一欄，三段距離各自獨立判定）

- (b) 該欄占清單列寬度比例 2/12 → 同落第二列，可填同一列。**未涉及第一列，未翻面**。
- (c) 狀態標籤元件↔右側「負責人」元件的間距 → 落第一列。不可填組合規則，由清單列（容器）的排列不變式「最小間距」承載。新詞代入：題幹已明示清單列是容納兩者的排列結構（依〈容器亦為元件〉判準即為容器），狀態標籤與負責人皆為其子件，此步驟由題幹直接可推得，不需另行舉證。**結論與舊表相同，未翻面**（唯一的誤傷風險集中處，確認未誤傷）。

**DOC-19b**（b7 版，「作者」元件[非容器條目]由頭像+文字組成，放入「留言列」容器的一個格位）
- (a) 圓形頭像↔文字「陳小明」的水平間隔 → 落第四列「本元件的內容 ↔ 本元件的另一處內容」，登記於 `doc` 範本〈使用 design token〉章節「間距」列，不進組合規則。**未涉及第一列，未翻面**。

**DOC-19c**（b8/b13 版，食譜 App 畫面上直接並列兩個容器元件：食材清單容器、步驟清單容器，無再上一層容器）
- (a) 兩容器之間的垂直間隔，誰管轄、依什麼步驟判定？
  舊表：兩容器依〈容器亦為元件〉判準皆屬「元件」，字面上落入舊第一列「一個元件 ↔ 另一個元件」的射程，造成假陽性——誤判為可直接套用排列不變式「最小間距」，略過「兩容器是否有共同容器」的判別。
  新表：兩容器分屬各自獨立放置在畫面上，彼此不是同一容器的子件，不再落入新第一列「同一容器內的兩個子件」的字面射程，讀者被迫依序排除至第五列「皆非上列四種組合（如兩個容器之間）」：對共同上層重問一次判別問句——「畫面上任兩個元件的相對位置是誰決定的？答案若是頁面本身，該處缺一個容器元件」，正確結論為此處缺一個容器元件承載這段間隔。
  **翻面**（修復標的，如預期）。
- (b) 撰寫者主張「這段間隔改由食材清單容器自己的組合規則填」是否成立？
  依第五列「兩端各自的組合規則均不得另定這段間距」與末段「本元件對外的間距亦不進（第一、三、五列）」，容器對外間距不得由自身組合規則承載。
  判定：不成立。此結論新舊表相同（撰寫者主張本非任何一種可用第一列直接判定的情境，第一列措辭改變不影響其為錯誤主張）。**未翻面**。
