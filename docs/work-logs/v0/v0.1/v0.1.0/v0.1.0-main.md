## 前情提要

0.0.2 的訪談產出了 PROP×4 / SPEC-001 / UC×6 / 8 個 domain / EVT×9，
0.0.3 補完 markdown 渲染、編輯模型、git 變更記錄三項選型。到此為止
所有東西都在文件裡，沒有一個畫面存在。

本版把 SPEC-001 §1-7 的狀態矩陣變成可以看的東西。**驗收標準是狀態
覆蓋而非功能完成**：每個狀態都能渲染且不溢位、該捲動處能捲動、該換頁
處能換頁、該拖拉處能拖拉。與資料正確性解耦，後續接真實資料時這套
整合測試持續有效。

兩項刻意的限制：

- **假資料採真實 repo 快照，不用生成器**。0.0.3 的審查已證明想像的
  損壞形態可能整批是假的——當時撤回了一份「130 個 YAML 錯誤」的量測
  artifact，那些錯誤並不存在。生成器產的損壞形態同樣是想像的。
- **泳道本版只做靜態版型**。布局演算法是本專案唯一的差異化元件，
  後推至 Layout 接真實資料的版本，不在展示殼階段定案。

實作中撞到 SPEC-001 未預估的文件變體或畫面情況時，開 0.1.x 的票修正
並回填狀態表，不回頭改版本規劃。
