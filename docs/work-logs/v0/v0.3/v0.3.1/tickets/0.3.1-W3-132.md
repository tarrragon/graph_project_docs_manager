## Solution
<!-- Schema[IMP/Solution]: 選填（.claude/pm-rules/ticket-body-schema.md） -->
新增 `WorkspaceLogEvent` enum（31 個成員，逐一對應 `_log()` 的 31 個呼叫點），`WorkspaceLogSink` 簽章改為
`void Function(String message, {required WorkspaceLogEvent event, int? level, Object? error})`。`event` 為測試斷言應綁定的穩定契約，
`message` 維持人類可讀、可自由改寫的除錯文案（沿用既有 `i18n-exempt: 開發者 debug log` 標記）。

`chooseFolder()`／`openPath()` 共用的 `_persistAndInspect()` 與 `restore()` 各自有一次「偏好設定儲存已就緒」時刻，訊息文字
相同但屬不同流程——拆為 `persistPreferencesReady` 與 `restorePreferencesReady` 兩個獨立識別碼，兩者測試互不影響。

五則「呼叫發出」事件（`chooseFolderPanelOpening`／`persistIssuing`／`restoreIssuing`／`inspectExistsIssuing`／
`inspectReadIssuing`）措辭統一為「動詞片語 + 具名參數」，移除 `_persistAndInspect()` 原有的「準備」前綴
（`準備持久化，key=...,path=...` → `持久化，key=...,path=...`）。`WorkspaceLogSink` doc comment 寫明此措辭約定，
`WorkspaceLogEvent` doc comment 說明 event/message 的角色分工與 persist/restore 分開命名的理由。

測試（`workspace_repository_test.dart`）改造：`_LogEntry` 新增 `event` 欄位，`_LogRecorder` 新增 `containsEvent()`／
`indexOfEvent()`，取代原本的 `contains()`／`containsAll()`／`indexOfSubstring()`（三者已移除，全數呼叫點改用事件版本）。
順序斷言（G1-3／G2-1／G3-1／G4-1 等）改用 `indexOfEvent` 比較，INV-PORT-OBSERVE-001 的「呼叫發出→受理→結果」時序
約束未鬆綁，僅比對依據從文字子字串換成識別碼。少數斷言（G1-4／G1-5）仍檢查 `message` 內容（`workspace.path`、
`/tmp/ws`），因為那是驗證「key/path 有沒有被帶進日誌」的功能性檢查，非文案穩定性依賴，保留合理。

### Rationale Chain
- 0.1.0-W3-121 why: `lib/workspace/workspace_repository.dart` 有四個 driven port 呼叫點，依 `clean-architecture-implementation-methodology.md`〈Port 回饋契約〉的 INV-PORT-OBSERVE-001 全數不合規（PM 逐行實查）：

1. `chooseFolder()` 的 `getDirectoryPath()`（file_selector 平台通道）：無 try/catch、無日誌。MissingPluginException 或使用者環境異常時直接往上拋，呼叫端拿到的是未分類例外。
2. `chooseFolder()` 的 `SharedPreferences.getInstance()` / `setString(_pathKey, path)`：**回傳值完全未檢查**。`setString` 回傳 `Future<bool>`，寫入失敗時函式照樣往下走並回傳 `_inspect(path)`——使用者看到資料夾已選定，但下次 `restore()` 讀不到值會回 `WorkspaceUnset`。這是方法論「典型違反」的加重變體：連日誌都沒有，呼叫端與日誌兩個獨立義務同時缺席。
3. `restore()` 的 `getInstance()` / `getString()`：無失敗路徑。Phase 1 已修正本條的初始描述——`getString()` 是純記憶體查表無 I/O 失敗路徑，真正的讀取失敗集中在會拋例外的 `getInstance()`，兩者不可混為一談，詳見 Solution 裁決 B。
4. `_inspect()` 的 `Directory.exists()` 與 `dir.list().first`（dart:io 檔案系統）：現況只有 `FileSystemException` 分支有日誌，屬結果時刻的失敗分支；`exists()` 完全無記錄，兩處皆缺「呼叫發出」事件。本條由 Phase 1 的 SR-1 補入——PM 建票時盤點遺漏，非後續擴張。

四處皆缺「呼叫發出」事件，判準問句「把外部系統整個拔掉，呼叫端能否得知呼叫已發出但無回應」目前答案為否。
