## Problem Analysis
<!-- Schema[IMP/Problem Analysis]: 選填（小型 IMP 可留 placeholder；大型 IMP 建議填寫）（.claude/pm-rules/ticket-body-schema.md） -->
### 根因（PM 讀原始碼，2026-09-29）

`commands/track_commit.py` 的 `execute_commit` 以 `declared = set(write_files(ticket))` 作為唯一可提交範圍。ANA 票的 where.files 預設唯讀，`write_files()` 因此回傳空集合，命令走到「未宣告任何寫入路徑，拒絕提交」分支。票自身的 md 從未被納入範圍，任何型別都一樣；只是 IMP／DOC 通常宣告了其他寫入路徑，這一點才沒有暴露。

票自身 md 的路徑可由 `ticket_system/lib/paths.py` 的 `get_ticket_path(version, ticket_id)` 取得（絕對路徑，須轉為 repo-relative 後比對）。

### 預期變更

**修法方向**：
- 票自身 md 視為隱含可寫範圍。輸入檔全部落在「宣告寫入範圍 ∪ {票自身 md}」內即可放行。
- 「where.files 未宣告任何寫入路徑」這個判斷仍以**使用者宣告的集合**為準：宣告為空、且輸入含票自身 md 以外的檔案時，維持現行錯誤訊息，ANA 型時保留 `::write` 說明。
- 「ticket CLI 管理的附屬檔」語意不明，本票不納入，只處理票自身 md。

| 既有測試（`ticket_system/tests/test_track_commit.py`） | 預期 | 理由 |
|---|---|---|
| `test_rejects_when_where_files_declares_no_write_paths` | 不變（綠） | 輸入 `a/b.py` 不是票自身 md，宣告為空，照舊拒絕 |
| `test_rejects_when_ana_ticket_declares_only_read_paths` | 不變（綠） | 同上，訊息仍含「ANA 型」與 `::write` |
| `test_rejects_files_outside_declared_scope` 等範圍判定測試 | 不變（綠） | 非票面路徑的判定不變 |
| 其餘 | 不變 | — |

若實作選擇讓「未宣告」分支改為一律走 out-of-scope 分支，前兩個測試的訊息斷言會變紅。這不是本票期望的方向；若遇到，停手回報。

**新增測試**（E2）：
- ANA 票、where.files 全唯讀，輸入僅票自身 md（patch `get_ticket_path` 回傳 `/repo/docs/.../<id>.md`）。斷言呼叫 `commit_files_isolated`，rc=0。
- 同一張票，輸入為「票自身 md ＋ 一個非票面路徑」。斷言 rc=1 且不呼叫提交（正向對照）。

**驗收命令注意**：本檔測試位於 `.claude/skills/ticket/ticket_system/tests/`，不在 `.claude/skills/ticket/tests/` 之內，pytest 兩個目錄都要跑。
