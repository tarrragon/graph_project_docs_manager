### 決策脈絡（用戶裁決序列，2026-09-29）

1. 需求：minor 完成後把待修的 bug／issue 分到數個小 patch，不一律收斂；功能與格式變更推給下一個中版本或大版本。
2. WRAP 後定案模型 E：minor 完成後依 topic 定固定數量 patch（之後不增長）＋停放區＋例外閥（僅「契約行為或資料錯誤」可插進 active patch 並標 scope_blocker）；major 起始定 minor 清單。
3. 重評兩條舊規則：票號內嵌版本 → 1c 版本無關穩定 ID（框架，0.3.1-W1-090）；不預先登記未定版本 → 2c 廢除（0.3.1-W1-091 已完成）。
4. 停放區暫行載體：C1，登記 1.0.0（planned）承接。1c 落地前搬入即改名。
