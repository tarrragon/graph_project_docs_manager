## Problem Analysis
<!-- Schema[ANA/Problem Analysis]: 必填（.claude/pm-rules/ticket-body-schema.md） -->
### 現況量測（main 143661733，SPEC-001 v1.23 / SPEC-003 v1.47，2026-09-29）

以唯讀 python 解析 SPEC-001 §1–§7 各表「退出路徑」欄（40 列）與 SPEC-003 §4 表「SPEC-001 退出路徑」欄（40 列），依（畫面→節, 狀態名）配對逐字比對：

| 結果 | 列數 | 列 |
|------|-----|----|
| 逐字一致 | 33 | — |
| 不一致 | 5 | #7（S3 省略 SPEC-001 的「疊加降級型別表旗標」註記）、#12（S3 多出「前往 Ticket 清單（Ticket 未載入時）」，該資訊已在同列導航反應欄 `action-traceability-goto-tickets`）、#27（S1「—（此為靜止態，非阻擋態）」／S3「靜止態（SPEC-001 FR-01 唯一例外）」）、#30（S3 省略括號說明）、#32（S3 省略「含至 UC Flow 視圖選擇 UC」） |
| 狀態名不同無法直接配對 | 2 | #20「含損壞（疊加於 #17／#18）」vs S1「含損壞（疊加態）」、#31「已選格（疊加於 #3）」vs S1「已選格（疊加於正常 · 矩陣）」 |

觀察：
- 不一致的五列中，四列是 S3 作者的**編修性重述**（省略、改寫、補充），不是純粹抄錯；該欄從來就不是純複製，所以逐字比對型的腳本檢查會持續產生「刻意差異」與「真漂移」混在一起的輸出。
- #12 的多出內容已存在於同列「導航反應」欄——被比對欄承載的 S3 專屬資訊，本就屬於導航反應欄。
- 該欄對 §4 的核心用途（「40 個狀態無一遺漏，且各有導航反應」）不是必要輸入：同列「畫面」＋「狀態」兩欄已構成指向 SPEC-001 列的完整參照鍵；退出路徑欄只是把被參照列的一個欄位抄過來。

### 影響面盤點

- `docs/spec/ui/audit/matrix.py`：狀態矩陣的「S3§4」欄以狀態名是否出現在 §4 區段判定（`row_has`），不讀退出路徑欄——刪欄不影響。
- SPEC-001 概述「目標以 SPEC-003 §4 導航反應欄為準」：引用的是導航反應欄，不受影響。
- SPEC-003 §5 FR 驗收列：斷言「導航反應欄皆非空且皆含一個具名錨點」，不受影響。
- test/：`test/helpers/anchors.dart`、`state_injection_demo_test.dart` 註解以「§4 列」為單位引用，不讀欄位——不受影響。

### WRAP

- **W（擴大選項）**：另考慮過「反向，由 SPEC-001 引用 SPEC-003」——SPEC-001 是狀態的權威源，反向會讓權威源依賴下游，排除。
- **R（現實檢驗）**：量測顯示 5 列不一致中 4 列是作者刻意編修（見 Problem Analysis）。B 的逐字比對會把刻意編修與真漂移混在同一份輸出，每輪都要人工分辨，正是本票要消除的成本；若要讓 B 乾淨，得先把 5 列改回逐字複製，等於承認該欄只是抄寫。A 的參照文字與（畫面, 狀態）兩欄資訊完全重複，多一欄只是換一種寫法說同一件事。
- **A（拉開距離）**：§4 的驗收用途是「40 個狀態無一遺漏，且各有具名導航反應」。這兩個性質分別由（畫面, 狀態）集合相等與導航反應欄非空承載，都不需要退出路徑的文字。讀者若要看退出路徑原文，依（畫面, 狀態）到 SPEC-001 即得，且那是唯一正確版本。
- **P（準備犯錯）**：若刪欄後審查者反映 §4 難以單表判讀，可由稽核腳本產生「SPEC-001 退出路徑 × SPEC-003 導航反應」的 join 視圖（腳本輸出，非入庫文字），不必恢復複製欄。

### 定案：C（刪欄＋集合檢查）

**改法與受影響位置**（實作另建票，本票不改 §4）：
1. SPEC-003 §4 表：刪除「SPEC-001 退出路徑」欄（表頭與 40 列）；#12 多出的「前往 Ticket 清單」資訊已在同列導航反應欄，刪除不遺失。
2. SPEC-003 §4 引言：「將其退出路徑欄對應到本規格定義的導航反應」改為說明（畫面, 狀態）為指向 SPEC-001 列的參照鍵、退出路徑以 SPEC-001 為準。
3. #20、#31 的狀態名與 SPEC-001 對齊（S1 為「含損壞（疊加態）」「已選格（疊加於正常 · 矩陣）」），讓參照鍵可機械配對。
4. 不受影響（已核對）：`matrix.py` 狀態矩陣「S3§4」欄、SPEC-001 概述對「§4 導航反應欄」的引用、SPEC-003 §5 FR 驗收列、test/ 內以「§4 列」為單位的註解。

**檢查規則**（併入稽核腳本，建議由 0.3.3-W3-375 的 exit code 化一併承接或另票）：解析 SPEC-001 §1–§7 各表首欄狀態名與 SPEC-003 §4 的（畫面, 狀態）兩欄；狀態名正規化規則為去除 `**` 與全形括號內的疊加註記；兩集合對稱差非空即以非零 exit code 報出，輸出缺漏方向（S1 有 S3 無／S3 有 S1 無）與名稱。
