## Problem Analysis
<!-- Schema[DOC/Problem Analysis]: 選填（若 DOC 起因於缺陷或盤點結論可填）（.claude/pm-rules/ticket-body-schema.md） -->
### 預期變更（PM 前台執行，2026-09-29）
- 權威位置：step-3〈元件契約欄位填寫問句〉「尺寸契約」列的「常見空格與來源」格，補一條判別：
  - 最小尺寸沿每一軸 = 內容最小尺寸（含內容之間的間距）＋ 該軸兩側的自身內距。
  - 自身內距的 token 取本元件組合規則所填者，並在公式中指名。
  - 容器的最小間距與格位不計入。
- 依據句：方法論〈容器亦為元件〉「不得另定間距」射程判定表，「兩端都在本元件上：本元件內部的內容 ↔ 本元件自身的外緣（內距）」一列。
  - 內距的一端是元件自身外緣，所以元件外框尺寸必然包含內距。
  - 「本元件的內容 ↔ 本元件的另一處內容」一列屬內容本身，計入內容最小尺寸。
  - 「兩端分屬兩個元件」與「同一容器內的兩個子件」兩列屬容器，不計入。
- 容器上限公式段（〈容器元件另答排列不變式三項〉，一維、二維公式之後）補一句：公式中的子件最小尺寸取子件尺寸契約所填值，已含子件自身內距；子件之間的距離只透過最小間距項計入一次。
- 判否範例放在同節公式之後。以本專案 SPEC-004 導覽項缺陷去識別化：只算圖示、間距、文字，漏掉兩側內距；同時示範把低估值代入容器公式，會放行實際放不下的側欄。
- 行號與列序不作引用錨點：判定表的列以列名引用（規則 11）。
- CHANGELOG 3.12.0、SKILL.md metadata.version 3.12.0。step-3 行數需在 300 行門檻內，若超過另行說明。
