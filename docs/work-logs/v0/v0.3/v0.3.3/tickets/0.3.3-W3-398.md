## Task Summary

lib/app/shell.dart 啟動還原後，currentWorkspaceState 為 WorkspaceUnset 或 WorkspaceUnavailable 時將 domainViewStateProvider 改寫為 DomainUnset（渲染 state-domain-unset）；WorkspaceReady 維持 gate 偵測路徑

## Problem Analysis
<!-- Schema[IMP/Problem Analysis]: 選填（小型 IMP 可留 placeholder；大型 IMP 建議填寫）（.claude/pm-rules/ticket-body-schema.md） -->

### 問題根因

`AppShell._restoreWorkspaceAndDetect` 僅對 `WorkspaceReady` 呼叫 `detect()`；Unset／Unavailable 不改寫 `domainViewStateProvider`，停在預設 `DomainReady(matrix)`（fixture 矩陣）。

### 預期與實際（實作前列表；grep 盤點 `pumpApp`／`AppShell()`／`DocsManagerApp` 呼叫端與 `domainViewStateProvider` 引用）

判準：經 shell 啟動、restore 結果非 Ready，且斷言 Domain 視圖內容（預設 Ready 或以 override 注入的狀態）。未 override 的 repository 為真實 `WorkspaceRepository`，restore 得非 Ready，shell 於 restore 完成後改寫（會覆蓋 override）。

| 測試案例 | 檔案 | 預期 | 處理 | 實際 |
|---|---|---|---|---|
| 頁首模式切換 mode-domain-swimlane → 切至泳道… | test/unit/screens/domain_view_test.dart | 紅（預設 Ready 被改寫為 Unset，切換鈕消失） | 注入 Ready repository stub + 訊號探測替身（前提修正） | 修正後綠（已改注入 Ready 替身 + builtin 版本覆寫）；修正前未單獨跑紅（預測依據為 override 被啟動改寫覆蓋） |
| 降級旗標寫入端真實執行路徑（真實 App） | 同上 | 紅（override 的 SchemaUnconsumable 被改寫為 Unset） | 注入 Ready stub + 探測替身使 gate 判 SchemaUnconsumable('0.0.3') | 修正後綠（同上） |
| 未選專案等六列不渲染頁首模式切換 | 同上 | 綠（override Unset 與改寫結果同） | 不動 | 綠 |
| 其餘 pumpApp 呼叫端（gap_report／node_detail／ticket_list／project_switcher／scan_notification／external_opener 節點詳情／component_matrix_demo／widget shell_test 其餘） | 各檔 | 綠（斷言不涉 Domain 視圖內容；project_switcher 以 Ready 或選取後 detect 覆寫） | 不動 | 全套綠，無表外紅燈 |
| 新增：restore 回 WorkspaceUnset → state-domain-unset | test/widget/app/shell_test.dart | 修正前紅 | 新增 | 修正前紅（實測，DomainReady 非 DomainUnset），修正後綠 |
| 新增：restore 回 WorkspaceUnavailable → state-domain-unset | 同上 | 修正前紅 | 新增 | 修正前紅（實測），修正後綠 |
| 新增：restore 回 WorkspaceReady 仍走 gate（既有 DomainNotFramework 測試為對照） | 同上 | 綠 | 既有 | 綠（新增獨立對照測試，Ready→DomainNotFramework） |

表外紅燈即停手寫 NeedsContext。

### 預設值評估

不改 `domainViewStateProvider` 預設 `DomainReady(matrix)`。理由：(1) 大量畫面測試（pumpHarness 單畫面）依賴該預設直接渲染矩陣，改預設會擴大紅燈面到表外；(2) 預設值只在 restore 完成前的瞬間可見，restore 結果一律由 shell 改寫（Ready 走 gate、Unset／Unavailable 走本票），契約行為已由改寫承擔；(3) 改預設屬另一個決策，本票範圍為 shell 改寫。啟動到 restore 完成之間的一瞬仍為矩陣，未列入本票。

## Solution
<!-- Schema[IMP/Solution]: 選填（.claude/pm-rules/ticket-body-schema.md） -->

lib/app/shell.dart `_restoreWorkspaceAndDetect` 改為 switch：Ready 走 detect，Unset／Unavailable 寫 `DomainUnset`。測試：shell_test 新增 3 案（Unset／Unavailable／Ready 對照）；新增 test/helpers/stub_workspace_repository.dart；domain_view_test 兩案改注入 Ready 替身。

Phase 4：重構需要：否；技術債務：無（啟動到 restore 完成間的預設矩陣一瞬見預設值評估）；程式碼品質：A；結論：無需重構。
