## Solution
<!-- Schema[DOC/Solution]: 免填（DOC 類型以變更摘要取代）（.claude/pm-rules/ticket-body-schema.md） -->
SPEC-003 v1.48（commit d4fea7f18）：

- AC1：§2.10〈焦點裝飾（斷言方式，對照形）〉改為同一元件「取得焦點」與「焦點移走」兩態比對，指名比對屬性為祖先鏈 `DecoratedBox`／`Container.decoration` 上的 `BoxDecoration.border`：取得焦點時至少一個 border 邊色非透明，焦點移走時同位置 border 不存在或透明；兩態無差異即判紅。顏色不在 SPEC-003 規定（引 SPEC-004 §4.0.1）。
- AC2：反例為 `NavItem` 於 0.3.3-W1-006 修正前——內部 `BoxDecoration(color: null, borderRadius)` 與側欄容器使舊條文放行；新條文兩態皆無 border 判紅。
- AC3：與 W1-006 測試〈導覽項取得焦點時有 accent 外框，未取得時無（對照）〉一致（該測試以 `find.ancestor(of: nav-item key, DecoratedBox)` 取 `BoxDecoration.border.top.color == AppColors.accent`，並以未聚焦態與另一導覽項作對照）。grep `decoration != null`／「decoration 非 null」於 docs/spec、lib、test：SPEC-003 原條文（已改）；**SPEC-004 §4.0.1 互動瞬態表 focused 列**「元件祖先鏈存在 `decoration` 非 `null` 的 `DecoratedBox`（SPEC-003 §2.10 焦點裝飾斷言）」為同型存在性抄錄，不在本票 where.files，已回報 e1；test/ 與 lib/ 零命中。
