## Problem Analysis
<!-- Schema[DOC/Problem Analysis]: 選填（若 DOC 起因於缺陷或盤點結論可填）（.claude/pm-rules/ticket-body-schema.md） -->
### 預期變更（PM 前台執行，2026-09-29）
- 權威位置：step-4-verify-completeness.md 新增〈既有變體欄的差異判別〉一節，含射程、依據句、判別問句、三種結果、與反向漂移的分界，以及判是、判否範例各一。放在 step-4 的理由：沿用的既有變體不論來自路徑 C、接手的既有規格或盤點票，都會匯流到 step-4 驗收；step-3 的變體列問句只在新填時觸發。
- 第 1 條加一句路由：變體欄沿用既有值者，先過該節再核本條。
- 該節不列為第 7 條，六條仍是存在性檢查；該節是第 1 條「落成值」在變體欄的前置判定。
- step-2-path-c-code-extraction.md：步驟 1 盤點段與步驟 2「spec 的變體多於實作 → 反向漂移」一句後各加路由，不重述判準。
- 衝突處理：現行路徑 C 步驟 2 把「spec 有、程式碼無的變體」一律判為反向漂移，觸發實例正是此形。新節寫明分界：規格寫出差異而程式碼未實作的，才是反向漂移；規格只有名稱、指不出差異的，不構成變體，降為用途描述，不進漂移裁定。
- 依據句：step-3〈元件契約欄位填寫問句〉的變體列「同一語意有幾種行為不同的形態？各自的外觀與行為差在哪？」。判別問句由這兩句逐詞推出：變體即「行為不同的形態」，指不出差異的名稱不符合定義。
- 既有「變體只填 default」條目（step-4 範例判定表）不衝突：降級後只剩一種形態時，變體欄只填 default，正是該條目的落成值。
- CHANGELOG 3.9.11、SKILL.md metadata.version 3.9.11。
