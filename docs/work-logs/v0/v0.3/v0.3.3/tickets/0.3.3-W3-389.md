## Problem Analysis
<!-- Schema[IMP/Problem Analysis]: 選填（小型 IMP 可留 placeholder；大型 IMP 建議填寫）（.claude/pm-rules/ticket-body-schema.md） -->
### 現況（主線程，2026-09-29，main 35c65671d）

- 五畫面「專案未就緒」皆為 0.1 接線點層級：`lib/app/graph_status.dart` 的 `graphBuiltProvider` 固定 `true`（檔頭明寫「真實整合落地後改為依 workspace 狀態與 Domain 視圖建置進度計算」）；`TicketsProjectUnready(reason)`／`TraceabilityProjectUnready(reason)` 在 lib 內無建構點，只由測試注入。原因的「真實來源」本票不接（不在範圍）。
- `ProjectUnreadyReason` 有兩份重複 enum：`lib/screens/ticket_list/ticket_list_state.dart`、`lib/screens/trace/trace_state.dart`。
- 三畫面狀態類無 reason：`UcFlowProjectUnready()`、`GapReportProjectUnready()`、`NodeDetailProjectUnready()`；前兩者由 `graphBuiltProvider == false` 產生（`uc_flow_providers.dart`、`gap_report_provider.dart`；後者另於「尚未首次可見」時作靜態佔位），`node_detail_state.dart` 亦讀 `graphBuiltProvider`。

### 設計（主線程定，實作依此）

1. 共用 enum：`ProjectUnreadyReason { notSelected, loading, incompatible }` 移至 `lib/app/graph_status.dart`，刪除兩份重複定義，ticket_list／trace 改 import。
2. 接線點由 bool 改為帶原因：`graphBuiltProvider` → `projectUnreadyReasonProvider = Provider<ProjectUnreadyReason?>((ref) => null)`；`null` 表圖已建立（行為同現行預設 `true`），非 null 表未就緒及其原因。保留檔頭接線點說明並改寫為新語意。
3. 三畫面狀態類加 `reason` 欄位，由 provider 傳入；gap_report「尚未首次可見」的靜態佔位（使用者看不到的分支）使用 `ProjectUnreadyReason.notSelected` 並註明理由。
4. 共用呈現：抽一個 `ProjectUnreadyView`（依 reason 三選一 message + `gotoDomainViewAction` 動作，參數帶畫面錨點 `state-<screen>-project-unready`／`action-<screen>-goto-domain`），五畫面（含既有 ticket_list、trace）共用，消除五份重複。放置層：`lib/app/`（依賴 `navigateTo` 與 l10n，屬 App 層接線而非元件庫）。
5. 移除 ARB `projectUnreadyMessage`、`gotoDomainAction`（四處零引用後）；SPEC-004 §4.0.6 對應列由主線程於合併後處理，代理人不改 SPEC。
