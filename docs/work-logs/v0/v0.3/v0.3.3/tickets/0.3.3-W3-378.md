## Problem Analysis
<!-- Schema[ANA/Problem Analysis]: 必填（.claude/pm-rules/ticket-body-schema.md） -->
### 現行條文盤點（acceptance 1）

- SPEC-001 §1「未選專案」列：進入條件寫「App 首次啟動，無已存路徑」——**未涵蓋「有已存路徑但還原失敗」**。
- SPEC-003 §3.1〈生命週期〉只有兩列：「App 啟動且有已存路徑 → 直接進入 `state-domain-loading`」「App 啟動且無已存路徑 → 進入 `state-domain-unset`」——**無「有已存路徑但還原失敗」列**；§2.14 指派表列 15 的 `folderUnavailableMessage(reason)` 限「選定資料夾不可讀或不存在」（使用者當下選擇），不含啟動還原。
- SPEC-005：`restore()` 的失敗分支產出 `WorkspaceUnavailable`（`_reasonPreferencesUnavailable`、`_reasonFolderMissing`、`_reasonFolderUnreadable`），§2.2 回饋點表只規範 reason 進日誌與使用者投影不互相抵扣，**未規定畫面如何呈現**。
- 結論：三份規格皆無「啟動還原失敗須提示原因」的條文，也無「降級為未選專案」的條文——屬規格缺口，不是實作偏離。

### 現行行為（實測讀碼）

`lib/app/shell.dart` `_restoreWorkspaceAndDetect`：restore 回 `WorkspaceUnavailable` 時只寫入 `currentWorkspaceStateProvider`，不跑 gate 偵測、不改 `domainViewStateProvider`；後者預設為 `DomainReady(matrix)`（fixture）。因此還原失敗時使用者看到的是 **fixture 矩陣**，沒有任何失敗提示。附帶：無已存路徑的啟動（Unset）同樣停在 fixture 矩陣，與 SPEC-003 §3.1「無已存路徑 → `state-domain-unset`」不一致（0.x Domain 視圖為狀態注入設計，真實接線屬 0.5；另報 e1）。

過期註解兩處：`lib/workspace/workspace_types.dart`（`_WorkspaceBanner` 直接以 reason 顯示）、`test/unit/workspace/workspace_repository_test.dart`（使 `_WorkspaceBanner` 顯示例外型別名）；`_WorkspaceBanner` 已於 e67df26b8 移除。

## Solution

### 候選（交 e1 以 AUQ 詢問用戶）

| 候選 | 啟動還原失敗時的呈現 | 對使用者的影響 | 規格與 key |
|------|------------------|--------------|-----------|
| A 暫態提示 | 降級為 `state-domain-unset`，並顯示 SnackBar `workspaceUnavailable(reason)`「無法存取先前的資料夾：{reason}」 | 使用者知道上次的專案為何沒開；提示 4 秒後消失，剛啟動未注意即錯過 | SPEC-003 §3.1 生命週期補一列、§2.13／§2.14 補登；保留 key |
| B 常駐說明 | 降級為 `state-domain-unset`，未選專案畫面的說明區以常駐文字顯示「無法存取先前的資料夾：{reason}」（取代一般的授權說明），直到使用者選了資料夾 | 原因不會錯過，也不佔用暫態提示通道；畫面多一段條件式文字 | SPEC-001 §1 未選專案補進入條件與顯示、SPEC-003 §3.1 補列；保留 key |
| C 不提示 | 降級為 `state-domain-unset`，不說明原因（原因只進日誌） | 使用者只看到「請選擇資料夾」，不知道外接磁碟未掛載等原因，可能以為設定遺失 | SPEC-001／003 補「還原失敗視同無已存路徑」；移除 `workspaceUnavailable` key 與過期註解 |

三者都要先補「還原失敗 → `state-domain-unset`」這條降級（現況是停在 fixture 矩陣）。

建議：B。啟動還原失敗是使用者無法預期的狀態變化，原因（如外接磁碟未掛載）能直接決定下一步，常駐呈現不會錯過；且 `folderUnavailableMessage` 已用 SnackBar 處理「剛選的資料夾」，B 用常駐文字處理「上次的資料夾」，兩者時機與語意分開。

裁決後：補規格條文；另建實作票（shell 還原失敗時寫入 `DomainUnset`、依候選呈現 reason、兩處過期註解修正或移除 key）。

### 裁決與落地

- 裁決：候選 B（用戶，2026-09-29，經 e1 以 AUQ）——還原失敗降級為未選專案，說明區常駐「無法存取先前的資料夾：{reason}」直到選定資料夾，沿用 `workspaceUnavailable`。
- 規格（commit e667ba050）：SPEC-001 v1.24 §1 未選專案列補還原失敗進入條件與常駐文字；SPEC-003 v1.51 §3.1〈生命週期〉新增「有已存路徑但還原失敗」列；SPEC-004 v1.60 §4.0.6 登記 `workspaceUnavailable` 用途。
- 前置缺陷（本票分析發現）：Unset／Unavailable 啟動停在 fixture 矩陣 → 0.3.3-W3-398（IMP，P1，e1 裁決）。
- 實作票：0.3.3-W3-400（常駐原因文字 + 兩處過期 `_WorkspaceBanner` 註解修正，blockedBy 0.3.3-W3-398）。
