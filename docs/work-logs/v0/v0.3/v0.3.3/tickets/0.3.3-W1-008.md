## Problem Analysis
<!-- Schema[DOC/Problem Analysis]: 選填（若 DOC 起因於缺陷或盤點結論可填）（.claude/pm-rules/ticket-body-schema.md） -->
### 預期變更（PM 前台執行，2026-09-29）
- 權威位置：step-3-fill-contract.md 在〈元件契約欄位填寫問句〉表之後新增〈值對映參數〉一節，內容如下：
  - 四種形式（分類、極性、門檻、反向）：各寫定義與 slot 契約寫法（值域、對映表、方向）。
  - 上色判準：好壞可判定才用好壞色，好壞不明改用中性色盤；存量與流量的分界放在這條判準下。
  - 判是、判否範例各一。
- 變體列保留既有的判別問句（狀態集或值對映），「於 slot 契約寫明值域與對映」改為路由到新節；slot 契約列加一句路由。
- 範圍縮減：where.files 移除 step-3-fill-contract-conditional-cases.md。該檔只供路徑 C 與多形態專案讀者使用，值對映與這兩群讀者無關。
- 判準修正：票面寫「存量中性、流量上色」，但觸發回報的門檻例子（佔比 <25／25–50／≥50）本身是存量，兩者衝突。判準軸因此改為「好壞能否判定」：
  - 流量：正負即變化方向，可用極性上色。
  - 存量：預設中性；規格明訂目標或門檻時，才可用門檻上色，並於 slot 契約記錄出處。
  - 好壞不明：一律用中性色盤。
- 依據句：
  - 〈Anatomy of the KPI Card〉（Anastasiya Kuznetsova）："Use green for positive changes and red for negative ones. If you're unsure whether the change is good or bad, opt for a more neutral palette like blue-orange."
  - BoardUI Stat Cards：只有 delta pill 以 deltaColor（lime／rose／neutral）表示正負；數值不上色；圖示底色依分類取色，與表現好壞無關。
  - 兩則出處皆於 2026-09-29 以 WebFetch 讀取原文核對。
- 判否範例：「負債類別固定紅色」屬分類形式卻使用好壞色，對存量表達好壞但規格沒有門檻，查無佐證，改為中性。
- CHANGELOG 3.11.0、SKILL.md metadata.version 3.11.0；step-3 行數維持在 300 行門檻內。
