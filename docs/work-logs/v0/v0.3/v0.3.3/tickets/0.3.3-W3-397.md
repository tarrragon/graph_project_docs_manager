## Task Summary

移除 lib/components/matrix_grid.dart 的 Focus(autofocus: true)，使 Unset 與 DomainReady 兩種啟動情形皆不預設焦點、首次 Tab 落在專案切換入口（SPEC-003 §2.10 啟動焦點條文）；驗證點選矩陣格後按 Esc 仍清除選格

## Problem Analysis
<!-- Schema[IMP/Problem Analysis]: 選填（小型 IMP 可留 placeholder；大型 IMP 建議填寫）（.claude/pm-rules/ticket-body-schema.md） -->

### 問題根因

`MatrixGrid` 的 `Focus(autofocus: true)` 使 DomainReady 啟動即持有焦點，與 SPEC-003 §2.10「App 啟動」列（不預設焦點、首次 Tab 落在 project-switcher-entry）不符。

#### 預期與實際（實作前列出，以測試案例為單位）

盤點：grep `LogicalKeyboardKey.escape` 於 test/ 與 integration_test/，命中 domain_view_test、project_switcher_test、matrix_grid_test、blocked_state_test、switcher_overlay_test、filter_dropdown_test。後三者與 project_switcher 為浮層／篩選 Esc，不經 MatrixGrid 焦點；僅前三者涉矩陣。

## Solution
<!-- Schema[IMP/Solution]: 選填（.claude/pm-rules/ticket-body-schema.md） -->

移除 MatrixGrid autofocus；MatrixCell InkWell 掛自有 FocusNode，onTap 先取焦，已選格仍可聚焦（只跳過 onTap 回呼）；列首 onTap 以 Focus.of(context).requestFocus() 取得 MatrixGrid 焦點。測試：shell_test 兩則、matrix_cell_test 一則、matrix_grid_test 一則新增，兩則 Esc 測試前提改為先點選。

Phase 4 結論：重構需要=否；技術債務=無新增（取焦以現有 Focus 機制實作，無額外狀態）；程式碼品質=A；結論：無需重構。

## NeedsContext

- **缺失項**: 「點選矩陣格後 Esc 清除選格」的前提在實作上不成立，需裁決焦點取得方式。
- **觸發位置**: shell_test 新增測試「點選矩陣格後按 Esc 清除選取，焦點停在原格」於移除 autofocus 後為紅。根因：`MatrixCell` 的 `InkWell` 與列首 `InkWell` 點擊不會 requestFocus，點選後 primaryFocus 不在 `MatrixGrid` 的 `Focus` 內，Esc 不進 `_handleKey`。SPEC-003 §2.10 v1.50 寫的「點選矩陣格後 Esc 生效」因此不成立（以前 autofocus 遮蔽此缺口）。連帶 domain_view_test「Esc 清除選取」與 matrix_grid_test「Esc 有選格時...」轉紅。

- **建議補料**: PM 裁決其一：(a) MatrixGrid 於點擊時 requestFocus（例如 Focus 節點加 onTapDown／Listener 取焦，lib 變更超出本票字面範圍）並焦點落在原格則需 cell 端 requestFocus；(b) 修改 SPEC 條文為需 Tab 進入。
- **重派成本**: 小，決策後單檔加取焦邏輯與測試前提。

**已解決**：e1 裁決 (a)，本票併入取焦實作；以上缺口不再阻塞。
