## Problem Analysis
<!-- Schema[IMP/Problem Analysis]: 選填（小型 IMP 可留 placeholder；大型 IMP 建議填寫）（.claude/pm-rules/ticket-body-schema.md） -->
### 根因（PM 讀原始碼，2026-09-29）

三個命令都以**目標票所在版本**查找被引用的 ID，建在其他版本的 ID 一律查不到：

| 命令 | 查找位置 | 現行呼叫 |
|---|---|---|
| `set-blocked-by`／`set-related-to` | `commands/track_relations.py` 的 `_execute_set_relation_field` Step 2 | `validate_ticket_exists(version, ref_id)` → `load_ticket(version, ref_id)` |
| `create --blocked-by` | `lib/field_validators.py` 的 `validate_blocked_by_references` 驗證 1 | `load_ticket(version, bid)` |

同一檔已有跨版本的前例：`validate_source_ticket_arg` 以 `extract_version_from_ticket_id(args.source_ticket)` 取版本後再載入，`--source-ticket` 因此可以跨版本。修法與 0.3.1-W1-093 對 spawned 的修法同型。

### 預期變更（三命令部分）

**修法方向**：新增一個共用解析，三個命令共用：以被引用 ID 自身的版本前綴載入；取不到版本時，退回目標票版本；載入仍失敗才報找不到。目標票本身（`ticket_id` 引數）的載入不變。

| 既有測試 | 預期 | 理由 |
|---|---|---|
| `tests/test_track_relations_set_fields.py`、`tests/test_track_relations.py` | 不變（綠） | fixture 的被引用 ID 與目標票同版本，替身以 ID 為鍵 |
| `ticket_system/tests/test_track_relations_comma_misuse.py` 的兩個 `test_real_missing_id_shows_generic_not_found` | 不變（綠） | `0.2.1-W3-999` 取得版本 0.2.1 後仍查無，照舊報 TICKET_NOT_FOUND |
| `tests/test_create_blocking_duplicate.py`、`tests/test_create_source_ticket.py` | 不變（綠） | — |

**條件**：上表的「不變」成立的前提是，新的解析仍經由 `track_relations` 與 `field_validators` 兩個模組層級的 `load_ticket` 名稱呼叫，既有測試是 patch 這兩處。若把載入移進其他模組，這些替身會失效，上列測試會變紅。遇到這種情況，停手回報，不要改寫既有測試的 patch 點來遷就。

**不變（已知限制，本票不修）**：`validate_blocked_by_references` 的循環偵測用 `list_tickets(version)`，偵測不到跨版本的循環。

**新增測試**（E1／E2 對照，同一 fixture，替身以 `(version, id)` 為鍵）：
- `set-related-to`、`set-blocked-by`、`create --blocked-by`：各有一案被引用 ID 建在其他版本，斷言成功寫入；兩個方向都要測（舊版本引用新版本，新版本引用舊版本）。舊實作下這些案應為紅。
- 同一 fixture 下，被引用 ID 在其版本也不存在時，三個命令都仍報找不到（正向對照）。

|---|---|

### 預期變更（讀取端，0.3.2-W1-006.2）

**修法方向**：
- `blocker_resolution` 新增共用的 blocker 解析：map 查無時，以 blocker ID 的版本前綴載入；取不到版本或載入失敗，就維持「未解除」。
- `is_fully_unblocked` 與 `_unresolved_blockers` 改用這個解析，消除第二份實作的漂移空間。
- 反向解鎖要涵蓋其他版本中被擋的票。掃描範圍（全部版本目錄，或 todolist 中未完成的版本）由實作者擇一，並在 Solution 記錄理由與 complete 耗時的前後實測。

| 既有測試 | 預期 | 理由 |

| `ticket_system/tests/test_track_runqueue.py` 其餘 `_is_unblocked_pending` 案 | 不變（綠） | blocker 都在 map 內，不觸發載入 |

**不變（已知限制，本票不修）**：`validate_blocked_by_references` 的循環偵測只看單一版本。結案時寫進 #55 的完成觀測（e1 裁決）。

**新增測試**（E1／E2 對照，`ticket_system/tests/test_cross_version_blockers.py`）：
- blocker 在另一版本且 completed：`is_fully_unblocked` 與 `_unresolved_blockers` 皆判定為已解除。舊實作下為紅。

- complete 另一版本的 blocker 後，被擋的票由 blocked 轉 pending，並出現在解鎖訊息中。舊實作下為紅。
