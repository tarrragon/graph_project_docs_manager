### Task Reference
- 0.3.2-W3-253 what: 裁定 被動作觸發之再顯示所截斷的舊提示，其關閉事件應記什麼等級（來源已完成，結論見 Solution）

### Rationale Chain
- 0.3.2-W3-253 why: `0.1.0-W3-205` Phase 4a 的新發現，**不屬守衛失效而是行為判定**，故不併入 Phase 4b。

**形態**：`onAction` 同步再顯示時，舊的那一則其 `closed` 事件的 `reason` **恆為 `hide`**（Phase 4a 查 Flutter 3.47.1 原始碼證實為確定性行為，非競態：`TickerFuture._cancel` 只完成 secondary completer、primary 永不完成）。該事件因此走 `_resolveClosedLevel(hide, origin)`；若該呼叫點的 `origin` 為 `background`，**使用者自己按下動作造成的關閉會被記成 warning(900)**。

**這正是 `SPEC-003`〈截斷事件的日誌等級〉要避免的誤判方向**——把使用者發起的事件記成背景等級，等於在日誌裡製造一則不存在的異常。

**生產環境目前不可達**：`gap_report_screen.dart` 的 `onAction` 回傳未 await 的 Future，同步段不顯示 SnackBar，現況由 `0.1.0-W3-205` 的 T-205-12 鎖住。**但本票的來源票存在的理由，正是預先擋住這類形態**——留在審查報告裡等於沒有記錄。

**為何是 ANA 不是 IMP**：「這種關閉該記什麼等級」需要先有答案。`hide` 這個 `reason` 在此路徑上不代表「被低級別截斷」而是「使用者按了動作」，等級判定的輸入語意在此處與其他路徑不同——是否該引入第三種輸入、或由呼叫端顯式標記，屬設計決策，不能在重構票裡順手決定。（來源已完成，結論見 Solution）
