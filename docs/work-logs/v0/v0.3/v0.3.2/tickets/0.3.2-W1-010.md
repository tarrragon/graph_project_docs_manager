## Problem Analysis
<!-- Schema[IMP/Problem Analysis]: 選填（小型 IMP 可留 placeholder；大型 IMP 建議填寫）（.claude/pm-rules/ticket-body-schema.md） -->
### Context Bundle（PM 2026-09-29）

**現況**（main `77350fee5`，W1-008 已合併）：
- `WithdrawTrigger.projectSwitch` 列舉值已存在，目前沒有呼叫點，旁邊有註解寫明由本票承接。
- `_withdraw(trigger)` 已會記錄 `withdraw-trigger:<name>`，可用 `withdrawLogSink` 斷言。

**切換訊號**：
- `currentWorkspaceStateProvider`，型別為 `StateProvider<WorkspaceState>`，初值為 `WorkspaceUnset`。
- 啟動還原由 `shell.dart` 寫入。
- 浮層 `_handleChosenState` 在 `WorkspaceReady` 分支寫入。它的 `WorkspaceUnavailable` 分支**不會**寫入 provider，只顯示提示。

**轉換表（PM 依票面 how 展開，實作以此為準）**：

| previous | next | 撤回？ |
|---|---|---|
| `WorkspaceUnset` / 無 | 任何狀態 | 否（首次設定或啟動還原） |
| `WorkspaceReady(A)` | `WorkspaceReady(A)` | 否（同路徑重設） |
| `WorkspaceReady(A)` | `WorkspaceReady(B)`，B != A | **是**，記 `projectSwitch` |
| `WorkspaceReady(A)` | `WorkspaceUnset` 或 `WorkspaceUnavailable` | **是**，記 `projectSwitch` |
| 非 Ready | `WorkspaceReady(X)` | 否（沒有「上一個專案」的通知可屬） |

以上情況都要同時滿足「`_pendingWithdrawableState != null`」才撤回；沒有待撤回的通知時，一律不呼叫 `withdraw`。

## Solution
<!-- Schema[IMP/Solution]: 選填（.claude/pm-rules/ticket-body-schema.md） -->
在 `ScanNotificationController.start()` 以 `listenManual` 監聽 `currentWorkspaceStateProvider`，並於 `dispose()` 關閉。`_onWorkspaceChange` 依序判斷：
1. previous 不是 `WorkspaceReady` → 不撤回
2. next 是同一路徑的 `WorkspaceReady` → 不撤回
3. `_pendingWithdrawableState == null` → 不撤回
4. 其餘情況 → `_withdraw(WithdrawTrigger.projectSwitch)`

`projectSwitch` 列舉值旁那行「目前無呼叫點」的註解已移除。至此，SPEC-003 §2.2「不重複發送」列與 §3.5「切換專案」列要求的撤回，在執行期已可觸發：來源是浮層的真實選取器寫入 provider（0.2.0 起）。
