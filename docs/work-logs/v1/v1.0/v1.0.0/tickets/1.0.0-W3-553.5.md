### 初稿完成（1.0規劃，2026-11-10；未 commit，送主控審查）

產出三個檔：
- 新增 `docs/usecases/UC-08-revise-document-fields-in-app.md`：主線四步（開始編輯 → 修正欄位值 → 看到寫入結果 → 看到驗證狀態），替代與例外分支八條。兩個入口：節點詳情是主線，破洞報告是 `begin-from-gap-report` 分支。寫入結果三種：成功走主線；閘門阻擋分為外部已改與寫入未完成，IO 失敗併在寫入未完成。另含驗證的兩種非通過狀態、外部改動預警、快照分支、唯讀降級。traverses 依 domain 宣告字面填寫（edit、schema、corpus、graph、diagnostics、workspace），不列 observability，理由寫在檔內。
- `docs/app-use-cases.md`：登錄 UC-08。
- `docs/traceability.yaml`：mappings 加兩筆。SPEC-009×UC-08 的 tests 取自 SPEC-009-test-design；SPEC-001×UC-08 的 tests 為空，待 553.3 定稿後補。domain_bundle_tests 加 Edit（L3）。last_updated 改為 2026-11-10。

驗證：`doc validate UC-08` rc=0（traverses 宣告、branch_from 結構、主線順序皆通過）；`doc uc verify` 對 UC-08 與 app-use-cases 皆 rc=0；`doc test-map UC-08` 可解析；traceability schema 一致性測試 77 passed。

配號經過：`doc create usecase --title ...` 配到 UC-08，但產出的檔案標題未填、檔名為中文 slug（上游 #98「doc create --title 只寫索引」，由 1.0.0-W1-109 追蹤）。我刪掉這個產物，依既有 UC 慣例用英文 slug 自行撰寫。

交主控的兩個發現：
1. `ticket_refs` 為空：edit 實作票尚未建立，UC-08 在回填前會缺 `uc_ticket_refs` 必要邊而出現在破洞報告（與 UC-07 v1.2 的情況相同）。回填時點是 version-bootstrap 匯總建票之後。
2. EVT-CORPUS-002 與 SPEC-009 FR-06 不一致：FR-06 要 Edit 收到監看事件，但 EVT-CORPUS-002 的 consumers 只有 corpus，設計註記寫「domain 內部的觸發訊號，不跨界，對外只發 CorpusParsed」。所以 UC-08 的 `external-change-warning` 沒有填 consumes。Edit 是透過 CorpusParsed 得知，還是要改 EVT，需要裁定。

**等用戶**：無。等主控審查後 commit。
