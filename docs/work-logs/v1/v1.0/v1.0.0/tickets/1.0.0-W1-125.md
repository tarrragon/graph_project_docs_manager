## Task Summary

同一條線改名（L54-main → L54-編輯規格）後，先前派給該線的票 who.current 仍是舊標籤；/clear 後的新 session 以新名 --as complete，被 identity-guard 以身分不符擋下，需主控 set-who 改派

## Problem Analysis
<!-- Schema[ANA/Problem Analysis]: 必填（.claude/pm-rules/ticket-body-schema.md） -->
### 框架問題兩條 AND 判準

1. 抽象可攜：是。凡是會替線改名的 consumer（改名在 /clear 交接時很常見），先前派給該線、`who.current` 寫的是舊名的票，在新名的 session 以 `--as <新名>` 收尾時都會被身分檢查擋下。換掉專案名與線名後仍然成立。
2. 根源在 `.claude/` 通用資產：是。`.claude/skills/multi-session-orchestration/references/session-naming.md` 的改名程序沒有提到 `who` 與 `set-who`（grep 零命中），也沒有同步已派票 `who.current` 的步驟；ticket CLI 的 identity-guard 對 `--as` 與 `who.current` 做逐字比對，無法知道舊名與新名是同一條線。

### 查重

dedup 關鍵字：identity-guard、set-who、改名、who.current。#77（Multi-PM 並行架構）收多 session 協作協議，本題屬其中的線身分延續，關係為「引用」，以觀測附加。#47 談的是派發時寫入 who 弄髒 repo，與本題不同；#55 是 CLI 契約叢集，沒有涵蓋線改名。

### 是否拖慢專案

輕微。每遇到一次就要主控 set-who 一次，線端要多等一輪訊息。
