**待審問題（規格表定案前要先回答）**
- Q1：`unavailable(baselineNotReady)` 是時序條件，不是外部程序失敗。FR-07 規定「unavailable 為 external_process」，套在這個原因上不成立。提案：baselineNotReady 不帶 error_source。
- Q2：baseline 為 unavailable 時，寫入後判定直接沿用 baseline 的原因，不再量測（`_judge`）。如果 baselineMeasured(unavailable) 和 validationCompleted(unavailable) 都帶 external_process，同一次驗證器失敗會記兩筆。提案：只有在寫入後量測本身失敗時，validationCompleted 才帶 error_source；沿用 baseline 原因時不帶。
- Q3：hash-object 有兩種情況落在「結束碼／executableMissing／timedOut 三擇一」之外：(i) 結束碼為 0 但 stdout 不是合法 SHA；(ii) 等待結果時拋出例外（原 gitRunFailed）。提案：(i) 記結束碼 0；(ii) 歸入 executableMissing，與 validatorRunFailed 現況一致。另一個選項是在三擇一中新增一個原因值。
- Q4：tempDeleteFailed 發生在主要失敗已經記過一筆之後。它是另一個獨立失敗（會留下殘檔），不是同一次失敗的第二筆記錄。提案：以獨立事件列入 FR-07 表。
- Q5：FR-07 的 readIoFailed／writeIoFailed 欄位只有「路徑、errorCode」。現有 ioFailed 帶 operation，拆分之後會失去 writeTemp／syncTemp／setMode／rename 的區分。提案：fields 補 operation（IoOperation enum，不承載內容）。
