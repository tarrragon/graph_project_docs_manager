### 範圍候選的事實基礎（2026-11-10 實查）

- 編輯模型已於 0.0.3 選型（`docs/tech-decisions.md`〈markdown 編輯模型：直接改檔 + CLI 驗證（票 `0.0.3-W1-002`）〉）：frontmatter 與結構化區塊用結構化表單，欄位定義取自 `tracking_schema.json`；markdown 內文用 `re_editor`，關閉語法高亮（`re_highlight` 把 snake_case 底線誤判為強調）。
- `GRAPH_EDGE_TYPES` 共 19 條，established 13 條；其中 3 條有反向欄位：provenance（反向 `outputs`）、blood（反向 `children`）、spawn（反向 `spawned_tickets`）。改這三種邊要同時寫兩個檔案，閘門與快照要對兩個檔案各做一次。
- Ticket 另有 ticket CLI 寫入路徑（`ticket track` 變更型子命令 32 個，寫入後自動 commit）。App 若也直接改 ticket 檔，同一份檔案會有兩個寫入者。
- UC-06「找出並修復文件破洞」現行做法：在外部編輯器修改原始檔，監看偵測後重新解析（UC-06 第 61 行附近）。破洞報告的項目點選後交給外部開啟（`gap_report_screen._openItem`）。
- 1.0 整合測試（PROP-005 §1.0）：寫入後呼叫唯讀驗證器，索引不同步成為可偵測的紅燈。

### 盤點發現

1. **值域來源**：機器定義的列舉只有 PROP status（doc CLI）與 EVT category（tracking_schema）。SPEC／UC／EVT status、PROP source／priority、UC platform 等只寫在範本註解；evaluation_level 連範本都沒有。0.0.3 選型寫「欄位定義取自 `tracking_schema.json`」，但該檔目前只定義必填欄位與邊，沒有欄位值域。
2. **反向欄位**：13 條 established 邊中 provenance、blood、spawn 有反向欄位，改一條要寫兩個檔。
3. **Ticket status 是生命週期動作**：完成、關閉帶驗收閘門，不適合做成自由下拉。

### WRAP：輸入元件依欄位功能決定

**錨點**：讓使用者以最少操作選對值，編輯當下看得到可選範圍；同一概念在不同型別用同一元件。
**R 事實**：元件庫（SPEC-004）沒有表單輸入元件。現有選擇類元件三個，語意都不是表單：SegmentedControl（2～3 段，契約語意是畫面模式切換）、FilterDropdown（篩選）、AppCheckbox。值域大小：PROP 6、SPEC 8、UC 7、EVT 12、domain 8（加 edit 為 9）；ticket 單一版本即有數十張，全專案累計數千張。
**W 選項**：單選鈕組、下拉、可搜尋下拉、核取清單、chips 加搜尋、借用 SegmentedControl。
**A**：依當前選項數決定元件，值域從 4 長到 6 就得換元件，同一欄位的操作方式會變；改依功能分組，選項數只影響版面。
**P**：借用 SegmentedControl 當表單單選會混入第二種語意，違反元件契約的單一語意；表單元件另立。

| 功能 | 欄位 | 元件 | 理由 |
|---|---|---|---|
| 分類（互斥、值域小且固定、需並列比較） | EVT category；UC platform、extension_status、runtime_surface；SPEC has_functional_requirements | 單選鈕組（新元件） | 選項並列可直接比較，一次點選 |
| 等級（有序） | priority（PROP、Ticket） | 下拉 | 同一概念跨型別一致；Ticket 有 P0～P3 四值；值以 Badge 呈現，順序已知 |
| 生命週期（文件節點） | status | 下拉 | 值域 4～5 值，改動頻率低 |
| 生命週期（Ticket） | status | 動作按鈕 | 生命週期轉換帶驗收閘門，第一輪已裁定經 ticket CLI |
| 單一引用 | source_proposal（one）、supersedes、parent、target_version、SPEC domain、who、how.task_type | 可搜尋下拉 | 值域動態；parent 的候選是數千張票，需要搜尋；值域小時搜尋框不妨礙 |
| 多值引用（節點 ID） | 各 many 邊欄位、PROP outputs 三個清單、blockedBy、relatedTo、children、spawned_tickets | chips 加搜尋加入 | 已選值常駐可見，候選以搜尋加入 |
| 多值引用（domain） | depends_on_domains、producers、consumers、traverses | 核取清單（沿用 AppCheckbox） | domain 數量小，全部列出比搜尋快 |
| 自由文字 | title、name、canonical_name、proposed_by、primary_actor、subdomain、owner、scope_blocker | 單行 | — |
| 自由文字（段落） | what、why、how.strategy、payload | 多行 | — |
| 內文 | markdown 本文 | re_editor（關閉語法高亮） | 0.0.3 選型 |
| 字串清單 | secondary_actors、path_patterns、where.files | 可增刪的字串清單 | 沒有候選值 |
| 結構化區塊 | UC flow、PROP outputs | 表格列編輯 | 每列是一筆結構化資料 |

**後果**：1.x 需要一組新的表單元件（單選鈕組、下拉、可搜尋下拉、chips 多選、字串清單、表格列編輯、文字欄位），進 SPEC-004 前要走 component-contract-design；屬 version-bootstrap Step 4.5 地基波的元件契約。
