# Execution Log

## Task Summary

O3-1 setUpAll 只取 stdout+stderr 中 ERROR| 開頭行，不檢查 exitCode 也不保留原始輸出；analyzer 異常結束時 negative 得到空清單、positive 反而假綠。改為：negative 預期 exitCode==3 且至少一行 ERROR|；positive 預期 exitCode==0；兩者在斷言 reason 帶入 exitCode 與原始 stdout/stderr。P-9 的 _analyze 同型檢查。

---

## Problem Analysis
<!-- Schema[IMP/Problem Analysis]: 選填（小型 IMP 可留 placeholder；大型 IMP 建議填寫）（.claude/pm-rules/ticket-body-schema.md） -->
### Context Bundle（L56 記，用戶裁定 2026-11-12 經主控 AUQ）

- O3-1（test/observability_contract_test.dart）：negative 要求 exitCode == 3 且至少一行 `ERROR|`；positive 先實測正常 exitCode（有 warning 時可能為 2），再斷言等於該值。
- P-9（test/edit_contract_test.dart 的 `_analyze`）：同型檢查 exitCode。主要假綠風險在 positive 的 `isNot(contains('error'))`；negative 另斷言 `negative.dart:<行>:`，崩潰時會紅但看不出原因。
- 兩檔斷言失敗時 reason 帶 exitCode 與原始 stdout、stderr。斷言語意不變，fixture 不動。
- 驗收證據（兩檔都要）：正常全綠；正向對照——前景暫時把 analyze 命令換成會異常結束者，確認 negative 與 positive 都紅且訊息帶 exitCode 與原始輸出，確認後還原不 commit，紅燈摘要貼 Test Results。
- 過渡期規則（主控）：695.1 合併前，閘門只紅 O3-1 或 P-9 negative 且結果為空者，視為 695 已知症狀，重跑一次並記錄於 695。

## Solution
<!-- Schema[IMP/Solution]: 選填（.claude/pm-rules/ticket-body-schema.md） -->
修改：test/observability_contract_test.dart、test/edit_contract_test.dart（commit 1477a1398，fixture 與斷言語意不動）。
- O3-1：setUpAll 保留 ProcessResult；negative 斷言 exitCode==3 且至少一行 ERROR|；positive 斷言 exitCode==2（實測，scratch 副本含 UNUSED_IMPORT warning，非 0）且 0 個 ERROR 行；reason 帶 exitCode、stdout、stderr。
- P-9：_analyze 回傳 ProcessResult；negative 斷言 exitCode==3、positive 斷言 exitCode==0；reason 同上。
- 實測 exitCode：O3-1 positive=2、negative=3；P-9 positive=0、negative=3。

Phase 4 結論：重構需要=否；技術債務=無（positive 的 exitCode 2 取決於 scratch 副本的 warning，fixture 改動時須同步常數，已以註解標示）；程式碼品質=A；結論：維持現狀。
