# Execution Log

## Task Summary

設計全 domain 的 structured log 與錯誤分類：記錄格式與欄位、錯誤分類軸、落地位置（檔案路徑、輪替、保留期）、與既有 developer.log 的關係、與 C-2「只記識別不記內容」的界線、規格歸屬（橫切，現有 8 個 domain 無一以此為變更理由）；產出設計結論與實作票

---

## Problem Analysis
### 問題根因

〈2026-11-10〉子決策 3 解除 structured log 延後，但現況沒有任何「記錄載體」：所有日誌只經 `developer.log`（DevTools／終端），App 關閉即消失；`reportFatalError`（`lib/main.dart`）註解明寫「未預期例外不寫入 log 檔」。各 driven port 的 LogSink 由各票各自宣告，形狀未統一（W3-549 併入的問題）。

### 影響範圍

已驗證（2026-11-10，main HEAD 47a57fa6eb）：
- `developer.log` 呼叫 123 處、分布 43 檔；其中帶 `level: 900/1000` 86 處。
- LogSink typedef 8 個，形狀 4 種：
  - (event enum, Map fields, {level})：AttentionArbiter、AppSnackBar
  - (message, {event, payload Map, level})：Graph、History
  - (message, {event, level, error})：Workspace
  - 純字串：DomainView `(message,{level})`、StaleOpen `(name,message)`、Parse `(ParseLogLevel,message)`
- LogEvent enum 5 個：AttentionArbiter、Workspace、Graph、AppSnackBar、History。後三形狀中純字串三個無事件碼。
- 規格內有日誌事件契約者：SPEC-001、SPEC-003、SPEC-005、SPEC-007、graph domain-map。事件契約目前分散在各 SPEC。
- 全域三層攔截已建（〈2026-08-27〉裁決二），匯流至 `reportFatalError` 單一出口。

未驗證：Parse 路徑的診斷訊息是否夾帶原文行（C-2 風險來源 2）；本次未逐一讀 43 檔的訊息內容。

### 相關 Error Pattern

無直接對應。C-2 的兩個風險來源（手寫錯誤處理接入內容、解析器診斷引用原文）見〈2026-09-10〉C-2。
