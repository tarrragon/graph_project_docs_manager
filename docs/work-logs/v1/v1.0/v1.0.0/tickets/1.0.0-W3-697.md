### Context Bundle（L57，2026-11-13 派發前）

- 現況（.claude/project-integration/run_integration_tests.py）：TOTAL_TIMEOUT_SECONDS = 900；main() 建一個 deadline = monotonic() + 900，傳給每次 run_streaming(f, deadline)，因此 12 檔共用同一預算。TIMEOUT_MESSAGE 字面為「[ERROR] integration 逾時（{秒} 秒）」，檔頭第 7–9 行描述總逾時語意。run_streaming 已支援注入 clock。
- 套件總耗時（.claude/logs/worktree-merge.log）：正常負載 472.9s／622.0s／660.2s 跑完 12 檔；兩次逾時 900.1s（ffe408c4cc55，跑完 7 檔後卡在 history_real_git_scan_test 的 pub 解析）、900.4s（e9c8ebfc606f）。
- 單檔耗時依據來源：.claude/logs/merge-gate-failures/ 下的 bebcfabc933a-flutter-integration.log（21:42，12 檔全跑完的完整輸出）、ffe408c4cc55-flutter-integration.log；每檔以「== integration: <檔>」分段。單檔上限取觀測最大單檔耗時加足夠餘裕（考慮 swap 高時約加倍），依據寫入檔頭註解。
- 不變項：卡住時 killpg 終止整個程序群組、結束碼 3；訊息保留「integration 逾時」字面並加上檔名；merge-gate.yaml 的 failure 正規式不改（改前改後都以該正規式比對新訊息驗證）。

- 回報：單檔上限值與依據、改前後 failure 正規式比對結果、紅燈證據、自檢、Phase 4。代理人不改票檔。

## Solution
<!-- Schema[IMP/Solution]: 選填（.claude/pm-rules/ticket-body-schema.md） -->
代理人 commit 9bdc61572fe7（分支 worktree-agent-af06b47e52014a460），改 3 檔，皆在 .claude/project-integration/。

- run_integration_tests.py：TOTAL_TIMEOUT_SECONDS=900 改 FILE_TIMEOUT_SECONDS=300；新增 make_runner(stream, clock, limit)，每檔呼叫時才以 clock()+limit 起算 deadline，main() 改用 make_runner()。killpg 與結束碼 3 不變。TIMEOUT_MESSAGE 改為「[ERROR] integration 逾時（單檔 300 秒）」，run_all 仍附「，卡在 <檔名>」。檔頭寫明上限依據。
- merge-gate.yaml：只改 flutter-integration 註解（每檔各自 300 秒，非總預算）；failure 正規式未改。
- tests/test_run_integration_tests.py：新增 _FakeClock 與 2 測試——12 檔各 100 秒（合計 1200 秒，超過舊總預算）新行為回 0 且第二檔 deadline 自起算 300 秒；單檔 301 秒回 3、輸出含檔名與「integration 逾時」、後續檔不啟動（E2 正向對照），並以 merge-gate.yaml 實際宣告的正規式驗證訊息。

上限依據：兩份 log 中 flutter 輸出的單檔測試時間最大為 app_test 約 55 秒（含冷建置），其餘 0～28 秒；12 檔總耗時 473～660 秒，平均單檔含建置與 pub 解析約 40～55 秒；swap 高時約加倍，取 300 秒。log 無每檔牆鐘時間，屬推估，實測校正另建 1.1.0-W3-692。

正規式比對：'Unable to start the app|Error waiting for a debug connection|integration 逾時' 對改前「integration 逾時（900 秒），卡在 x」與改後「integration 逾時（單檔 300 秒），卡在 x」皆命中。

紅燈證據：HEAD 舊腳本配新測試檔，兩個新測試 FAILED（舊版無 make_runner）。代理人自評鑑別力偏弱：紅因是符號缺失而非行為差異；行為對照由新測試內的「舊總預算下會逾時的組合」承擔。
