## Solution
<!-- Schema[IMP/Solution]: 選填（.claude/pm-rules/ticket-body-schema.md） -->
發出即建列、結局回來更新同一列：
- lib/edit/session_write_list.dart：WriteListEntry 以 `result`（null=寫入中，Written／Blocked／IoFailed）與 `workspaceRoot`（所屬專案）取代 snapshotSha 欄位（snapshotSha 改為由 Written 推得）；`record` 拆為 `begin`（發出建列）與 `settle`（受理結果就地更新），各通知一次 changes。

- lib/app/write_list_providers.dart：失敗計數納入 result 為 Blocked／IoFailed 的列（原只計驗證 failed／unavailable）。
- lib/screens/write_log/write_log_panel.dart：writeStateOf 依 result 對應寫入中／blocked 三原因／ioFailed；專案名稱取列的 workspaceRoot；非目前專案（≠ WorkspaceReady.path）的列路徑不可點；非 written 列不帶取回說明。
- 舊測試「未受理的寫入不進清單」與 SPEC-001 §12 相悖，改為 blocked 成列。
- 未動：docs/spec/edit/SPEC-009（acceptance 4 等主控通知）、lib/app/edit_providers.dart、既有 developer.log；新程式碼無 developer.log、未新增 import 到被架構測試監管的方向。
