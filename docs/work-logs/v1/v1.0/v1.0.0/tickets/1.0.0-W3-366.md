## 重現實驗結果
### 實驗方法

2026-11-11 於 main（83fed5e166 之後）執行 `doc uc verify`（框架 v3.1.0），把回報按檔案與 token 分組；逐一讀建票時 5 處的上下文；對照 `doc uc list` 的合法清單（UC-01～UC-08）。

### 實驗執行

- 違規數由建票時的 5 處增為 **80 處**，分布在 22 個檔案（rc=1）。其中測試檔 18 個、lib 2 個、integration_test 2 個，tool、tech-decisions、PROP-005 各 1 個。
- token 分布：UC-UNSET 18、UC-09 9、UC-1 7、UC-99 6、UC-SELECTOR 4、UC-9／UC-10 各 4、UC-101 3、UC-0x.MD 7、其餘為 UC-A／UC-B／UC-77／UC-100／UC-00／UC-0／UC-LIST／UC-001 各 1～3。

建票時 5 處逐項判定：

| 位置 | 字串 | 判定 | 依據 |
|---|---|---|---|
| `docs/tech-decisions.md:626` | `UC-001` | 提及，非違規 | 原句是「`doc create usecase` 配出 `UC-001`，`doc uc verify` 拒絕它」，在描述工具缺陷。該檔 append-only，不可改 |
| `test/helpers/test_copy.dart:54` | `UC-09` | 提及（外部語料字面），非違規 | 註解標明取自 `book_overview_app` 語料的 UC 標題，是測試用的長文案樣本，不指涉本專案 UC |
| `test/unit/components/matrix_grid_test.dart:18` | `UC-0`（`'UC-0$i'` 插值前綴） | 測試資料，非違規 | 合成表頭標籤，掃描器把插值前綴當成編號 |
| `test/unit/components/matrix_grid_test.dart:70` | `UC-00` | 測試資料，非違規 | 斷言上一列合成標籤的渲染結果 |
| 同檔第三處（建票時計入） | `UC-0x` | 測試資料，非違規 | 同上 |

其餘 75 處形態相同：合成 fixture（UC-1／UC-9／UC-99／UC-A…）、程式識別字（`UC-UNSET`、`UC-LIST`、`UC-SELECTOR`，屬 testKey 或占位字面）、檔名被大寫化（`UC-01.MD`）。

### 實驗發現

已驗證：
1. 80 處之中，沒有一處是「以不存在的 UC 編號指涉本專案 UC」的真違規。全部是提及，或是刻意的非法測試資料。
2. 根因在驗證器：它無法區分提及與使用，屬框架資產 `.claude/skills/doc`。這個缺陷已收在 tarrragon/claude#98（open），且 PROP-005 已記錄「2026-11-10 實測 86 處，多數是提及」。本票的 5 處只是該缺陷在建票當時的樣本。
3. 違規數隨測試增加而單調成長（5 → 86 → 80）。在 #98 裁決前，全專案 `uc verify` 不可能轉綠，也不適合作為 CI 閘門。

## Solution
<!-- Schema[ANA/Solution]: 必填（.claude/pm-rules/ticket-body-schema.md） -->
### 結論

5 處（現擴為 80 處）都不是真違規，全部屬提及或刻意的測試資料。本專案這一側沒有任何檔案需要修改。

更正〈實驗發現〉第 3 點的措辭：違規數是隨程式與測試增減而浮動（5 → 86 → 80），不是單調成長。結論不變：在 #98 裁決前，全專案 `uc verify` 不會轉綠。

### 處置候選

| 候選 | 內容 | 利 | 弊 |
|---|---|---|---|
| A（採用） | 本專案不改檔；以本票盤點對 tarrragon/claude#98 附一則觀測（token 分類、0 真違規），由主控執行；本票關閉 | 修法在驗證器（框架資產），consumer 不修框架（CLAUDE.md §1） | 在 #98 裁決前，全專案 uc verify 維持紅燈 |
| B | 逐檔改寫 fixture 與識別字，避開 `UC-` 字面 | 能讓 uc verify 在本地轉綠 | 改 18 個測試檔與 lib 字面只為迎合誤報；`UC-UNSET` 等是規格指定的 testKey，改名會牽動規格；tech-decisions 是 append-only，改不了。新增測試仍會再觸發 |
| C | 在本專案加豁免清單 | 能讓紅燈只剩新增項 | 豁免機制屬 uc_registry（框架）；本地加會被 sync-pull 覆蓋，也正是 #98 所說「豁免以路徑代理」的反模式 |
