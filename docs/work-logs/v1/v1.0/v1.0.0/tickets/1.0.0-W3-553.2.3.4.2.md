### 閘門紅燈分析（incident-responder，2026-11-13）

- 分類：實作與凍結清單沒有同步，不是設計問題。
- 依據：docs/test-design/SPEC-010-test-design.md〈## 7. 凍結清單〉引言寫明「既有值不得改名或刪除」，新增值要同批更新 §7。O4-3 用逐字相等比對，所以新增值沒有同批寫入清單也會判紅。
- 修法：測試的 `_frozenGraph` 與 §7 表格 GraphLogEvent 列，兩處都在末尾附加 requiredEdgeSkipped、closedBySkipped。屬本票範圍，不開衍生票。
- 查證：.4.1（04c452a0a9）與 .4.3（a6952bc01a）都沒有改到五個凍結 enum 所在的檔案，不受 O4-3 影響。
- 已讓原 .4.2 代理人在同一個分支修正。

## Solution
<!-- Schema[IMP/Solution]: 選填（.claude/pm-rules/ticket-body-schema.md） -->
分支 worktree-agent-a36f15f1a6712a631，commit c38b021122（已含 origin/main）。

做法：各函式加選用具名參數 `logSink`，預設值為各 domain 的 final `defaultXxxLogSink`（比照 defaultGraphLogSink），不新增可變全域；shell 改用 `shellLogSinkProvider`。新增事件檔：schema_log_event、diagnostics_log_event、layout_log_event、shell_log_event。history 兩檔原本已走 sink，只修改提到 developer.log 的註解。gap_detector 移除 `_warnFlowReasonPrefixViolation` 與 `_reasonLogLimit`，負載不再帶路徑與 reason 前綴。

驗收核對（PM，git grep 該 commit）：8 檔剩 1 處命中，為 type_table_json_codec.dart 的 doc 註解「例外物件只進 `developer.log`」，不是呼叫。O4-2 守衛是否排除註解，由 1.0.0-W3-553.2.3.4.4 決定。

error_source 分類（供 .4.4 彙整 FR-02）：
| 事件（domain） | level | error_source |
|---|---|---|
| SchemaLogEvent.edgeTypeRejected／carrierPatternRejected／specificityRejected／idPatternRejected（schema） | warning | parse |
| GraphLogEvent.requiredEdgeSkipped／closedBySkipped（graph，新增） | debug | 無 |
| DiagnosticsLogEvent.flowReasonPrefixViolation | warning | internal |
| LayoutLogEvent.laneInvariantViolated | warning | internal |
| ShellLogEvent.firstFrameDomainState／workspaceRestored／lifecycleChanged | debug | 無 |

Phase 4：重構需要＝否；品質＝A；技術債 2 項：(1) 各 domain 的 defaultXxxLogSink 各自一份，尚未整併為單一注入點，屬 .4.4 範圍；(2) schema 4 個事件與 graph 2 個 debug 事件負載為空，除錯資訊只剩事件名。
