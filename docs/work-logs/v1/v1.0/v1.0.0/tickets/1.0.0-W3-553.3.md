已讀：SPEC-001 §6 節點詳情全節（7 列與判定順序表）；SPEC-003 §2.14 位置、§2.17 九格表第 3 項（等待型×不可棄目前空成立，1.23 版已寫明寫入被拒是下一個破口，加入時須重跑證據鏈）；0.1.0-W3-279 Solution〈裁定：不動不變式（路線 A）〉。
來源：SPEC-009（commit 5422601efd）的寫入結果 blocked／ioFailed、ValidationStatus、FR-01 唯讀降級、FR-02 快照回饋與取回說明、FR-06 外部已改預警、FR-08 session 寫入清單。
本票須新增的畫面狀態與元素（待設計）：
- 編輯入口有二：節點詳情、破洞報告（PROP-007 驗收第 4 條）。兩處各需編輯中、寫入中、外部已改（預警／阻擋）、寫入被拒（三種原因與 ioFailed）的狀態列與退出路徑。
- 驗證狀態（進行中／通過／失敗／無法驗證）與寫入結果分開呈現。
- 唯讀降級徽章（常駐，工作區層級）。
- 快照的可見回饋與取回說明（分有快照、無快照兩支）。
- session 寫入清單：每列附驗證狀態，離開該檔後仍可回顧，SPEC-003 §2.14 登記為須留痕（W3-187）。
- §2.14 加「等待型×不可棄」列，§2.17 重跑證據鏈，九格表該格改為適用並補測試條目。
需要裁決的設計題（多選一，屬畫面設計）：(1) 編輯的形式：在節點詳情內嵌欄位編輯，或另開編輯面板；(2) session 寫入清單的位置：側欄項、面板，或節點詳情內區塊；(3) 唯讀降級徽章的常駐位置；(4) 寫入被拒的載體（已確定不是 AppSnackBar，也不是三個阻擋狀態）：欄位旁的行內錯誤，或編輯區塊頂端的橫幅。
建議做法：開新 session，以 ux-design-evaluation（狀態矩陣、退出路徑）與 star-anise-system-designer 起草，四題送用戶裁決後再寫規格。
