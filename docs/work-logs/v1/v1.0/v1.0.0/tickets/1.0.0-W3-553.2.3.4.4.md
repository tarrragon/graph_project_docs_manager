### 前三片轉入的整併項（2026-11-13，L57）

1. 預設 sink 的形態不一致：.4.1 用 nullable 參數，用到時才呼叫 defaultEditLogSink()；.4.2 用 final defaultXxxLogSink 當參數預設值；.4.3 是 final 預設加 xxxLogSinkProvider，且與 `logSink ?? default` 並存。整併為單一注入點時須統一。
2. domain_view 同一 domain 有兩組 provider／事件 enum（lib/app/domain_view_loader.dart 的 DomainViewLogEvent，以及 lib/screens/domain_view/domain_view_screen_log_event.dart），須決定是否合併。
3. .4.2 在 type_table_json_codec.dart 留有一行提到 developer.log 的 doc 註解。O4-2 守衛要決定是否排除註解。
4. FR-02 分類表的來源：.4.1／.4.2／.4.3 各自 Solution 的 error_source 表。

### 整併項分流結果（2026-11-13，依主控 [4a1379] 指示，取代上一節第 1、2 項）

- 第 1 項（三片預設 sink 寫法不一致）：PM 查證三片分支（c38b021122、04c452a0a9、a6952bc01a）的所有預設都經 `defaultLogSink<E>(domain)`。這個 closure 每次被呼叫時才讀全域 `sharedLogWriter`，沒有任何一片自建 LogWriter，所以生產環境都會落到注入點，不影響本票 acceptance。形態統一屬改善，已建 1.1.0-W3-698。
- 第 2 項（domain_view 兩組 enum）：不影響 acceptance，已建 1.1.0-W3-699。
- 本票保留的約束：整併 writer 時必須保持「呼叫時才讀注入點」。若把 sharedLogWriter 改成在建立時就綁定的形態（例如 sink 建立時捕捉 writer 實例），三片的 final 預設會綁到舊實例而繞過注入點，等同第三條 acceptance 失敗。
- 第 3、4 項（type_table_json_codec 的註解、FR-02 表來源）仍屬本票。
- where.files 改為精確路徑（原為 test/unit/architecture/ 目錄級宣告）：lib/main.dart、lib/observability/log_sink.dart、test/observability_contract_test.dart（O4-2 與 O3-1／O4-1／O4-3 同檔）、test/unit/app/global_error_handling_test.dart（唯一引用 fatalLogWriter 的測試），共 4 檔，未超過 5 檔門檻。
### 派發約束（2026-11-13 23:0x，L57 接續 session，主控 [4a1379] 派工）
