### 派發前 context（1.0規劃，2026-11-10）

**範圍**：SPEC-009 FR-09 中「自」為 1.0 的欄位所用的輸入元件。依「現行元件」與「目標元件」兩欄合計，共五種：單行文字、多行文字（EVT payload）、下拉（列舉值，如 PROP status、priority）、可搜尋下拉（PROP target_version、SPEC domain）、單選鈕組（SPEC has_functional_requirements、UC platform 等、EVT category）。另加一個表單欄位容器（標籤＋輸入＋提示或錯誤＋唯讀呈現）的候選。chips、核取清單、字串清單、表格列編輯從 1.1 起才用，**不在本票**，在各自 minor 的規劃波補。

**起點判定（step 1）**：路徑 A（規格推導）。
- 命中訊號：SPEC-009 FR-09 逐欄位對照表，加上 PROP-007〈輸入元件依欄位功能決定〉。

#### 元件候選表

| 候選名 | 來源（FR-09 列） | 出現的畫面與狀態 | 與他候選總是共現 | 判定 | 理由 |
|---|---|---|---|---|---|
| 單行文字輸入 | 共通 title；PROP proposed_by；SPEC subdomain、owner；UC primary_actor；EVT name、canonical_name；過渡期無值域的列舉欄位（SPEC/UC/EVT status、PROP source/priority/evaluation_level、UC platform/extension_status/runtime_surface） | 編輯畫面（待 553.3）每個上列欄位 | 否 | 與多行合為 `AppTextInput`，變體 `singleLine` | 見「單行與多行」列 |
| 多行文字輸入 | EVT payload | 同上 | 否 | 與單行合併為 `AppTextInput.multiLine` | 單行與多行語意同為「自由文字值」（FR-09 同列「自由文字：單行；段落為多行」），退出路徑相同（皆經 `FieldBlock` 提交），差異只在 Enter 鍵行為與尺寸，屬變體 |
| 下拉（列舉） | PROP status（現行）；SPEC/UC/EVT status、PROP source/priority/evaluation_level（目標） | 同上 | 否 | 立特化元件 `AppDropdown`，不併入 4.13 `FilterDropdown` | 行為差異：`FilterDropdown` 首項固定「全部」並回傳 `null`（F3），表單欄位無「不篩選」值；`FilterDropdown` 的 active 態（框色 `accent`）表示「有篩選」，表單沒有此語意；表單須呈現值域外的既有值（檔案內手寫值），篩選不會遇到。內容角色差異：觸發器在篩選是「{label}：{value}」複合文字，表單的 label 由 `FieldBlock` 承載、觸發器只放值 |
| 可搜尋下拉（單一引用） | PROP target_version；SPEC domain | 同上 | 否 | 立特化元件 `ReferencePicker`，不併入 `AppDropdown` | 內容角色不同：引用值指名另一個對象（版本、DomainBundle），讀者據以辨認「是哪一個」，屬標題類；列舉值屬標籤類。行為不同：選項來自資料（數量隨專案增減，需捲動與文字過濾），列舉選項固定且少、全數展開不捲動。1.1 的「chips 加搜尋」（多值引用）是本元件的多值版，屆時另評 |
| 單選鈕組 | SPEC has_functional_requirements、EVT category（現行）；UC platform/extension_status/runtime_surface（目標） | 同上 | 否 | 立特化元件 `AppRadioGroup`，不併入 4.10 `SegmentedControl`、4.43 `AppCheckbox`、4.40 `ListRow.option` | `SegmentedControl`：FR-09 約束（W1-104 WRAP 的 P）已裁定借用會混入第二種語意——它是檢視模式與期間的常駐切換，套用為本地即時；表單單選的選取觸發寫入、受 FR-05 三時刻約束。`AppCheckbox`：布林單值，is 是／否 以兩個互斥選項呈現時需兩個可讀 label，FR-09 指定單選鈕組。`ListRow.option`：清單中的導覽式選取（選 UC），選項數隨資料增減，不是欄位值 |
| 唯讀值呈現 | 共通 id、created、updated、version；PROP proposed_date、confirmed_date；DomainBundle domain | 同上 | 總是與欄位 label 共現 | 不立新元件，以 4.1 `AppText` 放入 `FieldBlock` 的值格（`FieldBlock.readOnly` 變體） | 組合優先：既有 `AppText`（`body`／`mono`）可表達，無互動 |
| 欄位 label、提示或錯誤文字 | FR-09 每個欄位；FR-05 驗證狀態（呈現形式待 553.3） | 同上 | label 總是與輸入共現；提示／錯誤為有時 | 不立新元件，`AppText` 為 `FieldBlock` 的子件 | 組合優先 |

搜尋類既有元件 4.12 `SearchField` 的判定（與 `AppTextInput`、`ReferencePicker` 內部搜尋框）：不併入、不沿用。`SearchField` 的語意是對清單的即時過濾（每次輸入即 `onChanged`，結果是清單子集），退出路徑是清空；表單文字的輸入是待提交的欄位值，退出路徑是提交或還原。`ReferencePicker` 選單內的過濾框屬元件自帶子件（與 `FilterDropdown` 選單同理），不是容器格位，故不放 `SearchField`（其組合規則只允許 `Toolbar` 首格）。
