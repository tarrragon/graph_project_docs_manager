紀律規則

Rule 1: 0.1.0 凍結，不再新增

Batch 1-2 期間發現的問題，一律開到 0.1.1（品質）或 0.2.0（資料）。

判斷：不修復，畫面能渲染嗎？能 = 不在 0.1.0。

Rule 2: 批次內不逐票確認

同批票全數並行派發。整批完成後一次 merge + push，再啟動下一批。

Rule 3: 框架問題走 issue

create-time hard gate 已上線。框架問題 observe 到 canonical issue，不開本地票。

Rule 4: 發版後再 triage 溢出池

0.1.0 完成後，再把 75 張溢出票更新 version 欄位。先發版，再規劃 0.1.1。
